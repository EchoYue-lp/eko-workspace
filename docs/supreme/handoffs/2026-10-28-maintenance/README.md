# 2026-10-28 暂停迭代后的源码保存切点

用户要求暂时停止功能迭代，先提交已有代码、清理中间产物。平台 Goal 已暂停，原目标和未完成事项保留；本次不恢复新功能推进。

本目录保存四个源码范围的 Git 二进制补丁、精确 Git 基底和每个文件的 SHA／权限／软链接／删除状态。补丁以 gzip 压缩降低重复文本体积。三个产品仓库当前全部受控及非忽略未跟踪源码均纳入；顶层仅 README、原生切换设计与品牌草案。官网已存在的本地提交不重复打包。

每个范围都已实际从具名 Git HEAD 导出到独立 scratch，解压补丁并执行 git apply，逐文件核验所有字节、权限、链接和删除状态，再重读原工作区确认零漂移。manifest 保存实际结果；这使当前未提交源码具备受 Git 跟踪的完整恢复材料，后续缓存清理不依赖临时目录中的唯一副本。

这些是维护检查点，尚未通过的产品代码仍保持其真实资格。压缩补丁不会被自动编译、执行或合入生产。尚未合流的新候选另附工程包；未运行测试、待正式 SDK pin、项目语义资料缺口及外部校验阻塞继续开放。这里不声称功能交付完成，也不改变产品仓库 HEAD、索引、依赖、用户授权数据或顶层子仓指针。

恢复时先选择与 manifest 完全相同的仓库和 base_head，在独立空目录导出该 Git 基底；核验 working-tree.patch.gz 的 SHA 后解压并 git apply，再按 files 清单核验。不要直接向有未保存修改的现工作区应用补丁。原目录和证据未因本保存动作删除。

必要原始失败、构建日志、二进制及认证后数据继续在主开发根内保护，仅对已具名、无读者且具恢复凭据的可重建缓存或重复制品执行清理。未推送、未合并、未发布。
