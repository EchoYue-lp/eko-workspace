## C02 新建本地文件夹只用名称（建议第一个做，最独立）

**代码依据**：默认位置 = `~/.eko/workspaces/<规范化后的工作空间名>`；`WorkspaceLayout::base_dir()` → `user_data_path("workspaces")` → `~/.eko/workspaces`；`WorkspaceId::from_name` 保留字母数字与 `-` `_` `.`，其余字符替换为 `_`，超 64 字符截断，空名回落 `default`。前端提示文案：“留空使用默认位置”“创建后显示实际位置”。

**步骤**

1. 侧栏新建工作空间 → 选“新建本地文件夹”。
2. **只填名称**，例如 `case-c02-default`；父文件夹、新文件夹名称都留空。
3. 点创建。

**成功信号**

- 不弹目录选择器、不要求先浏览父目录即可创建；
- 创建成功后界面**显示实际位置**，且该位置应是 `~/.eko/workspaces/case-c02-default`；
- 侧栏出现该工作空间并切换到它；
- 用别的名字再试一次中文／带空格的名字（如 `测试 工作 区`），目录名应为 `测试_工作_区` 形态（非字母数字字符被替换）。

**缺陷长相（任一即是失败）**

- 只填名称时创建按钮不可点，或提示“请选择父文件夹”；
- 创建成功但位置显示为空、或显示的不是 `~/.eko/workspaces/...`；
- 中文名导致创建报错或目录名变成空／乱码。

**再验三小项**：① 自定义新文件夹名称 → 显式名称被采用；② 自选父文件夹 → 父目录被保留；③ 建一个与既有目录同名的 → 已有内容不被覆盖，且失败时草稿保留、给出具体错误。

## A06 设置表单（模型配置）

**代码依据**：`echo-agent-app-core/src/infra/llm.rs:131` 明确“temperature 不再是 EKO 产品配置或请求来源”；`factory.rs:855` 注释“产品不请求 temperature，显式 None 防止框架 builder 默认重新注入”；`infra/tests.rs:28` 断言 `get_temperature() == None`。

**步骤**

1. 打开设置 → 基础配置。
2. 切到模型 Provider / 模型选择分组。
3. 逐个展开模型表单，找“温度”字段。
4. 改一次推理深度／输出上限／上下文配置并保存，退出设置再进。
5. 保存时故意断网或填一个明显错误的 Base URL，看失败反馈。

**成功信号**

- 模型表单里**没有温度字段**（不是灰掉、不是隐藏后还能被旧值带回）；
- 推理深度、输出上限、上下文配置三项仍在且可改；
- 基础设置常显，不因折叠模型分组而消失；
- 重新进入设置，刚才保存的值仍在；
- QQ／飞书／个人微信有独立的 IM 渠道管理入口；
- 保存失败时草稿保留，错误提示具体（不是“保存失败”四个字）。

**缺陷长相**

- 温度输入框仍存在，或保存后日志/请求里仍带 temperature；
- 保存成功但重进设置值回退；
- 保存失败后表单被清空。

## C04 ubuntu SSH 重新进入与侧栏

**代码依据**：`terminal/project_ssh.rs:711` 仍会在连接未准备时返回 `project SSH connection has not been prepared`；前端 `NewTaskDialog.tsx:154/257/524` 已实现捕获该错误后提示“远程连接尚未准备，请在此重新连接；原工作空间和数据保留。”并保留项目记录、要求重新认证同一远程位置。

**步骤**

1. 侧栏查看已存在的 `ubuntu-ssh-test-20261102`，确认目标账号、主机、端口、目录显示正确。
2. 完成手头工作后，**退出 Eclip 并从新进程重新打开**（这一步是旧 c548 的失败点，必须真退出）。
3. 直接进入该工作空间。

**成功信号**

- 账号／主机／端口／目录与创建时一致；
- 没有现成连接时，弹出的是**原认证／目录验证弹窗**（要求重新输入密码/认证），而不是直接报错终止；
- 重新认证后能进入，且侧栏刷新成功；
- 原工作空间与数据仍在，项目绑定未被自动改写；
- 取消时：不切换、不新建工作空间；
- 密码只在 GUI 掩码框里输入（Agent 不读取、不落盘、不进日志）。

**缺陷长相**

- 新进程进入时直接抛 “project SSH connection has not been prepared” 且没有重连入口（即旧 c548 症状复现）；
- 重连后目录或主机被改写、或生成一个重复工作空间；
- 取消后仍发生切换或新建。

**需如实记录**：该目录是否为 Git 项目，以实际结果为准，不预设。

## B01 普通文字

**步骤**

1. 在任一工作空间发起普通对话，发送一句话（如“用三句话说明你在做什么”）。
2. 观察正文出现过程与结束状态。

**成功信号**

- 正文**逐步**出现（不是最后一次性蹦出来）；
- 最终内容完整、只发布一次（没有重复段落或闪现重来）；
- 运行中状态与结束后状态一致（结束后不再转圈、不残留“正在运行”）。

**缺陷长相**

- 整段最后一次性出现（流式失效）；
- 内容重复、或先出现后被整段替换；
- 结束后仍显示运行中，或运行中已显示完成。
