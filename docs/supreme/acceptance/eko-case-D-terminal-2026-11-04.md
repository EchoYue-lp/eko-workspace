> **历史归档（2026-11-04 至 11-06）**：下文前置、包与数据环境只属于原切点，不是今天的执行入口或验收结果。当前进度见 [协调交接](../handoffs/eko-current-handoff.md)，不要据本文恢复旧包或旧数据。

对应清单 **D01–D05**。清单里写着「远端命令结果及终端矩阵尚未取得」——这份用例把可做的五项写成具体步骤，两个不能做的写在末尾并说明原因。

**代码依据**

- `terminal.rs:6/123/154` 终端基于 `portable_pty`（真实 PTY，不是模拟输出）。
- `terminal.rs:176` 本地终端用 `CommandBuilder::new(<shell>)` 直接起 shell；`:178` SSH 终端用 `CommandBuilder::new("ssh")`。
- `terminal.rs:294` `resize(rows, cols)` 经 `validate_dimensions` 后调用 `master.resize(PtySize{..})`——**尺寸是送到 PTY 的**，全屏程序应能跟随。

## 前置

- 用验收入口当前指定的 `gui-unbounded-agent-App-20261106-r01/启动新版.command` 启动。
- 需要两个项目：一个**本地测试项目**（C01 用过的那类即可），一个就是 `ubuntu-ssh-test-20261102`。
- **重要**：上次在 ubuntu 终端里可能留有没回车的只读命令。进终端后先按 `Ctrl+C` 清掉当前输入行，再输入自己的命令。

## D01 本地终端

1. 在本地测试项目里打开内置终端；
2. 输入 `pwd` 回车。

预期：输出的是**当前项目目录**；不需要切到 full-auto 权限模式（用户主动打开终端不该被 agent 权限门控挡住）。

## D02 ubuntu 远端身份

1. 进 ubuntu 项目的终端，先 `Ctrl+C` 清行；
2. 依次执行：`id -un`、`pwd`、`git rev-parse --show-toplevel`、`git rev-parse HEAD`。

预期：

- `id -un` 是 **ubuntu**；
- `pwd` 与该项目配置的远端目录一致；
- 若该目录不是 Git 仓库，应显示**真实的 Git 错误**（如 `not a git repository`）——**不伪造仓库**。

## D03 中文与 emoji

1. 本地终端执行 `printf '中文🙂\n'`；
2. ubuntu 终端同样执行；
3. 再分别手动输入一段中文并回车。

预期：显示与回显都正常，无乱码、无半个字符被截断。

## D04 resize 与全屏程序

1. 拖动窗口改变宽度、再改变高度；
2. 运行 `top`（不改文件），观察布局，按 `q` 退出。

预期：行列跟随窗口变化；退出 `top` 后回到原 shell，提示符位置正常。

## D05 Ctrl-C、exit 与重新打开

1. 开两个终端（本地或 ubuntu）；
2. 在其中一个运行可中断命令（例如 `sleep 600`），按 `Ctrl+C`；
3. 执行 `exit` 关闭它；
4. 重新打开一个新终端。

预期：只影响这一个终端；另一个仍在且可用；关闭后重新打开能正常工作。

## 一个容易误判的地方

SSH 终端的行为**大部分由系统 ssh 与远端主机决定**，不是本产品的代码。所以：

- 远端 `pwd` 与预期不同 → 先看是不是远端目录本身如此，不要直接判缺陷；
- `git` 报错 → 可能是远端目录确实不是仓库，属**正确行为**。

**判断标准**：显示的信息是否**真实反映远端**，而不是是否符合你印象中的期望。
