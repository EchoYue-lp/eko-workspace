# 具名用例 L01：冷重开后历史完整

> **历史归档（2026-11-04 至 11-06）**：下文前置、包与数据环境只属于原切点，不是今天的执行入口或验收结果。当前进度见 [协调交接](../handoffs/eko-current-handoff.md)，不要据本文恢复旧包或旧数据。

对应清单 **L01**。选它作第四个可执行用例，因为**这个修复包的主题就是 warm continuation**，而 L01 是唯一不依赖模型、不依赖外网、又能直接打到该主题的一项。

**代码依据**

- `chat_event_log/event.rs:32` `REPLAY_BATCH_SIZE = 4096`＋`projection.rs:1-3` 注释：历史查询/追平**只读一个固定 journal 批次**，调用者可用 `Pending` 中的 cursor 续接。
- `projection.rs:4` `NATIVE_HISTORY_DIRECTORY = "native-publications"`：助手消息若带 blocks 或 `execution_status`，需要对应的发布记录才能还原。
- `runtime.rs:69-71`：`physically_final` 只由「原 owner 的最终发布」设置，**缺少 continuation 本身不能证明已结算**。
- 会话历史落盘为文件（不用 SQLite）。

---

## 前置

- 用验收入口当前指定的 `gui-unbounded-agent-App-20261106-r01/启动新版.command` 启动（沿用原 `isolated-runtime/data`）。
- 从 9 个既有会话里挑**一个带工具调用、且已有完整回答的**会话（列表里能看到工具卡片的那种）。不要挑最新的空会话。

## 步骤

1. 打开该会话，**滚到最底部**，记住最后一条回答的首句和最后一个工具卡片的名字。
2. 向上滚到顶，确认开头还在（记下第一句话）。
3. 正常退出 Eclip（⌘Q；确认 Dock 图标消失，不是关窗）。
4. 从 Finder 双击同一个 `启动新版.command`。
5. 重新打开同一个会话。
6. 先等两秒再判断——见下方「一个会误判的地方」。

## 成功信号

- 第一条、最后一条、工具卡片顺序都与退出前一致；
- 工具卡片显示**已完成**状态，不是转圈；
- 最后一条回答**只有一份**，没有出现两遍；
- 任务／Goal 历史仍在。

## 一个会误判的地方（重要）

历史是**每批 4096 条事件**追平的，带 `Pending` cursor 续接。

所以重开后**头一两秒内容偏少是正常的追平过程**，不等于历史丢失。

判断"丢失"之前：先等 2–3 秒、再滚一下，或切到别的会话再切回来。**只有等待后仍然缺，才算缺陷。**

## 缺陷长相

- 最后一条回答出现两份（重复 final）；
- 重开后工具卡片重新转圈／重新执行（重放旧副作用）；
- 等待后历史仍为空，或只剩最后几条；
- 重开后任务／Goal 历史消失。

## 与 C04 一起做（省一次重启）

L01 和 C04 都要「完全退出 → 新进程重开」。建议一次退出后连做：

1. 退出前：先做 L01 第 1–2 步（记住会话内容），再切到 `ubuntu-ssh-test-20261102` 工作空间（C04 第 1 步）；
2. 完全退出；
3. 重开 → 直接进 ubuntu 工作空间看是否弹重新认证（C04 第 3 步）；
4. 再切回刚才那个会话，核历史（L01 第 5–6 步）。
