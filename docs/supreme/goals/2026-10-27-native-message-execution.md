# 原生消息、统一执行终态与长任务进度：新 Goal

> 本文件仅保留原生消息子目标说明，已并入[本轮完整迭代总 Goal](eko-eclip-complete-iteration-2026-10-27.md)。它不能替代当前 Goal 的全部未完成项，也不是后续执行会话的总目标入口。

作为 EKO／Eclip 本轮改造的协调者，完成一次跨 Framework、EKO、SDK、示例和官网的完整切换：退役内置 `think`、`final_answer` 控制工具，以 provider 原生消息、实际工具调用及运行时确认的终态组成唯一执行路径。解决普通文字被误归为思考、回答结束依赖控制工具、长任务缺少稳定进度呈现三个问题。持续实施、验证和集成，不能以设计、候选、局部测试或交接代替完成。

## 一、先保护现场，再接管本次改造

唯一开发根为 `/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`，五仓仍独立维护。先读取适用 AGENTS、当前 Git／进程事实及唯一交接入口 `docs/supreme/handoffs/eko-current-handoff.md`，保全已有提交、未提交源码、候选、验证日志和恢复材料。各文件只有一名写入负责人，正在验证的源码及依赖保持冻结；不盲停编译、重启服务或清理别人的 target。

前一目标的未完成项和用户裁决继续在原交接中保留，本次优先完成原生执行切换。已实现的 Run／guidance 隔离、只读委派、完整原文恢复和工具历史恢复应检查后承接，不得覆盖或冒称全部验收。具名保留只读 dispatcher 结果缓存吞掉独立派发的问题，并以真实调用对照闭合；与本次无直接关系的分叉等工作保持可恢复，待新消息终态合同确定后续接。

## 二、统一消息语义，保留身份与原始顺序

在既有消息和事件体系中无损区分 provider reasoning／公开摘要、assistant 普通正文、实际 tool call/result、运行时 execution status。Reasoning 独立展示；普通进度、说明和回答始终为 assistant message，不能因同轮出现工具而改成 thinking。

保留 provider 的 `commentary`、`partial_answer`、`final_answer` 阶段；没有阶段时明确为未知，不根据中文措辞猜。每个块保留稳定身份、所属模型请求、provider 来源、顺序及增量状态。修正 Responses 多消息合并造成的身份、阶段和顺序丢失。流式和非流式归一化到相同语义事实，前端不再用 ThinkStart／ThinkEnd 切换后续 Token 的含义。

## 三、具名退役控制工具，保留原生能力

删除 ThinkTool、FinalAnswerTool、默认注册、曝光配置、特殊执行分支及“每次调用工具前输出分析思路”的强制提示；同步清理失效配置、测试、示例和文档。只退役这两个具名控制工具，不按文件名或关键字误删原生 reasoning、模型请求、最终回答事件／回调、校验、收尾或通用工具扩展 API。

保留 provider thinking 配置、签名、加密推理块与协议要求的历史回传。签名和加密内容按协议保留，不当作普通进度文字。新执行不能再调用 think／final_answer，也不能靠隐藏注册或第二套兼容执行分支维持运行。

## 四、由完整响应进入唯一执行和结束路径

复用现有 ReAct 主循环，不新增第二 executor。完整模型响应仍有待执行工具时，先执行并回填匹配结果，再继续请求模型；只有明确进度／部分回答时，保存展示并继续执行；明确最终回答且没有待执行工具时，进入最终候选校验。

无阶段、正常完成、有正文且无工具时，按对应 provider 的明确协议规则形成最终候选。Reasoning 本身不冒充最终回答。截断、异常断流、空响应进入原错误或有界重试。不能在单个消息块结束时提前结束，也不能使用同响应中早于工具的回答宣布完成。

所有最终候选共用结构化输出验证、已配置 Guard／Critic、Stop Hook、持久化和物理执行结算。Stop Hook 要求继续时继续同一执行；失败、取消、校验未通过或 owner 尚未结算时不发布成功终态。整段校验模式不得提前泄漏尚未通过的最终内容。成功终态和最终发布各自幂等，恢复／重试不得重复发布。

最终回答只是模型候选，执行完成由运行时确认；一次 Agent 执行结束与 EKO 整个 TaskRun 目标完成分别判定，不能用 final 消息替代 TaskRun 完成事实。

## 五、一次覆盖当前所有 provider

先枚举实际 provider／适配器及真实主路径，逐项归一化。Responses 保留消息身份、阶段、顺序与原生完成信号；Anthropic 保留内容块、tool use、停止原因及 thinking 签名；Chat Completions、DeepSeek、Qwen 和其它现存适配器按各自 content、reasoning、工具与停止原因处理。

不支持阶段信息的 provider 使用明确协议规则；不保留会把普通文字变思考的旧推断。各适配器流式／非流式同场景产生相同有序语义，无法验证的能力和真实服务资格单列，不以 mock 假称线上通过。

## 六、EKO 负责汇报策略和真实等待状态

首次工具操作前、关键发现、方案变化、阻塞和验证结果出现时，通过主模型简短汇报。默认超过 60 秒没有用户可见的自然语言汇报，在下一个模型请求安全边界提醒一次，汇报后重置。复用同一主循环，不为进度另起模型循环、不打断进行中的操作；工具记录和运行状态不能冒充自然语言发现。

长工具或模型请求未返回时，GUI 仍显示真实当前操作、耗时及最后收到事件的时间。没有新事件就如实等待，不能编造进度。GUI 按顺序展示正文、工具、后续正文及经确认的最终回答，Reasoning 独立折叠，保留附件、错误、HITL、Subagent、复制与必要操作，覆盖浅深主题、窄窗、键盘和焦点。

Subagent 复用同一消息／结束语义，保留原身份、层数、工具上界、投递与结果收集。IM、cron、SDK 消费同一框架事实，各自负责呈现，不新建结束判断或任务权威。

## 七、SDK、历史读取与恢复同批闭合

SDK 同步 Host、协议、TypeScript／Python／Java 和可执行示例，逐项核对 accepted contract 的新增、保留和具名退役，不以顶层 gitlink 替代 framework 精确 pin。独立 pin、依赖政策、来源、Host 行为与三语言消费分别实际验证，不继承 Framework／CLI 的资格。

新执行只产生新语义。旧日志保留原件，通过读取适配展示；无法区分的旧 thinking／工具前说明标为“历史执行说明”，不重新推断。旧断点的待执行控制工具只转换必要历史或最终候选，随后进入当前唯一恢复／校验路径；不注册旧工具、不另有调度／结束逻辑，不重放已完成副作用、不补成功结果、不重复发最终答案。

## 八、完整场景验收，最后只有一套执行路径

至少覆盖纯文字、纯工具、文字工具混合、独立进度、多消息、多工具并行、未知阶段、截断与异常断流；覆盖校验失败、Stop Hook 继续、取消、owner 未结算、崩溃恢复和重复发布负控制；覆盖 GUI 历史重载、Subagent、IM／cron、SDK 三语言、60 秒提醒和单操作长时间等待。

交付必须证明：新执行无 think／final_answer 调用；进度文字不进入 reasoning；进度消息不提前结束执行；待执行工具先结清；成功终态只发布一次；重载和恢复保留顺序、身份、原生协议数据与结果。旧注册、曝光、特殊完成分支和失效配置已清除，只有读取适配，没有第二套执行路径。

Framework 负责通用消息和执行机制，EKO 负责产品汇报策略／展示，provider 与 SDK 负责无损适配。先查全仓既有实现再扩展，在所属子仓记录中文 ADR／正式文档，更新可执行示例和官网；跨仓阶段设计／计划留顶层。代码按独立子仓依赖顺序验证、审查和保存本地里程碑。

## 九、工程边界与交付资格

最多同时 5 个 focused Cargo 批次，各用独立 target，jobs≤5、debug=0；完整重型矩阵和正式性能测量独占。低于 5GiB 不开新重构建。批次结束先保日志、真实出口、必要制品及哈希回读，成功确认无 reader 后再独立调用准确 cargo clean；任一步失败就停止后续清理，不补造前置证据。

所有提交显式关闭 GPG；保持非 main 开发和单一协调者集成。继续保留 Exa 本机提交、固定分支／pre-retirement tag、用户数据、原未提交成果及恢复包。不擅自 push、merge、关闭 Issue、发布包、部署官网或晋升未推送子提交的顶层 gitlink。

依赖按各仓真实用户裁决和精确 lock／consumer／source 合同验证，不扩风险或 ignore。既有 zstd 成果及 source 402 外部工具合同阻塞保留；不修复本轮已排除的 echo-semantic 合同、不造形式证据或扩大排除。正式 framework 来源／SDK pin 等前置未闭合时，明确保留交付缺口，不能冒充已合格。

保留当前已确认的 TaskRun→PlanTask→SubagentRun、文件持久化、CLI 不启用 SQLite、Eclip 品牌及技术标识边界。普通 Steer 由主模型结合历史理解并按需调整计划，不独立调用意图模型，不强制要求／计划／验收流水线；没有 Goal 时可由智能体初始化，已有 Goal 只允许用户显式改删。新消息切换不能越过这些已确认权威。

最终报告分别给出源码／ADR／示例、focused／完整矩阵、正式 source、真实原生／SSH／IM、SDK pin／三语言、main／CI、发布／部署资格。源码完成不代表旧窗口已加载，局部通过不代表整体完成。必要人工输入或外部授权确实缺失时，先完成其它可独立工作，再说明具体缺口；不缩小本 Goal 的完成标准。
