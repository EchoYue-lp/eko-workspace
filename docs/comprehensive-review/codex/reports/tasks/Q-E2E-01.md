## Question

Can representative Chat, Task, Subagent, Tool, HITL, attachment,
Browser/MCP, restart and large-output scenarios complete on every applicable
surface while preserving equivalent canonical facts?

## Answer

Not yet established dynamically. The static review proves that the surfaces
share substantial core execution paths, but it also proves material adapter
and lifecycle gaps. The user explicitly prohibited builds, tests and dynamic
fixtures during review, so each scenario/surface pair below has its own
immutable `not_run` report. No green E2E claim is inferred from static
reachability.

## Parity Contract

Equivalent does not mean identical presentation. Each applicable surface must
preserve the same conversation/turn/run/task/Subagent/call identities, effective
Tool input, ordered terminal outcome, typed failure/cancellation, complete
artifact reference and durable recovery facts. Text surfaces may summarize but
must retain a lossless continuation. Cron/background may return an explicit
interaction-required outcome instead of rendering HITL. Local user-driven
terminal/MCP/Browser actions must not inherit Agent automation permission gates.

## Static Result

- `PreparedUserTurn`, `drive_chat`, `AgentPool` and TaskRuntime provide genuine
  shared execution paths; a second E2E kernel is neither needed nor desirable.
- GUI, TUI, interactive CLI and channels do not currently preserve equivalent
  terminal, Tool, artifact, attachment, replay and cancellation facts.
- Cron/background use the canonical TaskRuntime but lifecycle/recovery and
  delivery gaps prevent a parity claim.
- A typed noninteractive one-shot surface does not exist, so V23 cannot be
  attempted until its thin adapter is implemented.
- Q-GUI/Q-WEB executable gates are also unexecuted, preventing any GUI E2E
  promotion independently of runtime findings.
