## Claim

Audit records describe actual completed tool outcomes with stable correlation,
and logging failures are observable.

## Method

```text
1. Trace builder.audit_logger into prepare/finalize/default tool pipeline.
2. Trace public AuditCallback through callback start/end/error hooks.
3. Compare start/result/error order for success, converted ToolResult failure,
   infrastructure error, and concurrent same-name tools.
4. Inspect logger error/poison/corrupt-query behavior.
```

## Expected Result

One call ID binds start to exactly one terminal result; success is recorded only
after success; failure cannot also appear successful; persistence loss returns a signal.

## Result

- Exit code: 0
- Duration: static lifecycle/correlation trace
- Summary: default AuditStage writes a successful ToolCall with empty output and
  zero duration before execution, never updates it on ordinary success, and adds
  a second failed row only on infrastructure failure. The callback END stage
  always calls `on_tool_end`, even for a failed ToolResult, so AuditCallback marks
  it successful. Concurrent same-tool completion is paired FIFO by tool name,
  not by call ID. AuditCallback discards every logger error; memory logger can
  also return success after a poisoned write dropped the row, and file query
  converts unreadable/corrupt records to absence.
- Log/artifact: this report

## Deviations

Direct prepare/finalize audit writes do log their errors, but this does not repair
tool terminal truth or the public callback backend.

## Conclusion

The audit truth/correlation/recovery invariant fails and supports F-OPS-01-P1-05.
