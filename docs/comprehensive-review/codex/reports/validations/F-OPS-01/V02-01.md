## Claim

An enabled cron occurrence inside the preceding poll window is selected exactly
once by SchedulerRunner.

## Method

```text
1. Follow SchedulerRunner::run_loop -> tick -> CronTask::next_run.
2. Compare the time reference used by tick with Schedule::upcoming(Utc).
3. Check last_fired and current unit/example coverage.
```

## Expected Result

The scheduler computes the occurrence at or before the tick time, compares it
with the previous poll boundary, and deduplicates that occurrence identity.

## Result

- Exit code: 0
- Duration: static control-flow proof
- Summary: `tick` captures `now` and a preceding 30-second window, but
  `next_run()` independently asks for the next occurrence after its own current
  time. That result is normally later than `tick`'s `now`, so `next <= now` is
  false and automatic execution is not selected. Tests assert only that a future
  occurrence exists; the example uses only manual `run_once`.
- Log/artifact: this report

## Deviations

directly established by the two time-reference definitions.
