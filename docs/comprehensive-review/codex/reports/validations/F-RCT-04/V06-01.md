## Claim

Outer batch timeout produces a paired batch terminal and durable outcome for
every announced call, including calls whose side effects may already have run.

## Method

```text
Trace the concurrent timeout branch through try_send_or, future drop, context,
checkpoint, ToolBatchEnd, and caller outcome. Compare ordinary and
timeout-exempt mixed batches and the per-tool timeout/retry layer.
```

## Expected Result

Timeout is a typed terminal transition with one result/error/unknown outcome per
announced call and a recovery-safe persistence point.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not measured
- Summary: timeout at `tools.rs:284-292` invokes `try_send_or!`; the macro at
  `stream_macros.rs:64-73` tries to enqueue one raw error and immediately returns
  `IterOutcome::Abandoned`. Dropping the local futures cancels polling. The path
  emits no ToolBatchEnd, synthesizes no per-call ToolError/unknown result, and
  saves no checkpoint. Any already emitted result remains partial. A single
  exempt tool disables the outer timeout for all peers, although ordinary peers
  still have ToolManager per-attempt timeouts.
- Log/artifact: this report

## Deviations

The raw error itself can also be lost if the primary channel is full; that
transport defect belongs to F-RCT-03-P1-02 and is not duplicated here.

## Conclusion

The claim fails. Timeout abandons the batch without a complete semantic or
durable projection, leaving consumers and recovery unable to classify peer
calls or possible side effects. Supports F-RCT-04-P1-05.
