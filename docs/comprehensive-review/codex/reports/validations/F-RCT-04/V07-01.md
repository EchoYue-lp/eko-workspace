## Claim

Per-tool retry distinguishes known side-effect risk and does not automatically
retry a streaming call after user-visible output.

## Method

```text
Inspect ToolManager non-stream/stream retry loops, ToolFailure automatic-retry
predicate, risk-derived side-effect classification, timeout scope, retry delay,
and stream output_forwarded guard.
```

## Expected Result

Only explicitly retryable failures are retried; possible side effects require
idempotency evidence, and streaming output suppresses replay.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not measured
- Summary: both loops retry only failures whose typed metadata allows automatic
  retry. Infrastructure errors derive `may_have_side_effects` from non-read-only
  risk; possible effects become verify-before-retry unless an idempotency key is
  present. Streaming retries additionally require `!output_forwarded` at
  `echo-execution/src/tools.rs:877-901`. Retry delay uses saturating arithmetic
  and caps at 30 seconds.
- Log/artifact: this report

## Deviations

Correctness depends on custom tools truthfully declaring risk/failure metadata.
ToolManager's generic cancellation gap is already F-EXT-01-P1-03. This check
does not validate batch recovery after a call has returned.

## Conclusion

Supports the local per-tool retry policy as conservative for classified side
effects and streamed output. It does not mitigate F-RCT-04-P1-01 or P1-05.
