## Claim

resolved component model or rejected before installation/enabling.

## Method

`validate_plugin_dir`, `install_local`, discovery and `resolve_components` for
all eight component families. Inventory existing component tests.

## Expected Result

Arrays are consumed in full or rejected for singular component families, and
installation validates declared paths before committing files/state.

## Result

- Exit code: 0 for static reads; source invariant failed.
- All component fields accept `StringOrArray`, and validation checks every path.
  Skills/agents/themes/output styles consume every path, but hooks, MCP, LSP and
  monitors call `first()` and silently ignore later valid declarations.
- Strict `validate_plugin_dir` exists, but `install_local` only parses and
  validates the manifest. It copies and persists an enabled plugin without
  resolving declared component paths. Discovery has the same deferred behavior.
- A recursive copy error can leave the destination directory behind before the
  registry entry exists; later install calls reject that partial directory as
  already installed.
- Existing resolution tests cover one hooks and one MCP path. They do not cover
  arrays in singular fields, missing components through install/scan, or partial
  copy cleanup.
