## Claim

Every public plugin integration/lifecycle surface has a production owner and
preserves the same source-scoped error contract as the canonical path.

## Method

Search both repositories, examples and bilingual documentation for
`NativePlugin`, `wire_skills`, `wire_hooks` and `wire_mcp`; compare their inputs,
outputs and registrations with `wire_all`/PluginLifecycleManager.

## Expected Result

Alternative public helpers are thin lossless adapters to one owned transaction;
legacy APIs without a host are removed under the project's no-compatibility rule.

## Result

- Exit code: 0 for static reads; source invariant failed.
- `wire_skills` calls generic directory loading without plugin source tags and
  silently drops errors. `wire_hooks` ignores the registration result.
  `wire_mcp` silently drops load failures and returns only server names. None
  returns a per-plugin reversible receipt.
- These helpers have no production caller but are explicitly recommended by the
  public bilingual plugin guide, so they are reachable misleading API rather
  than harmless private dead code.
- `NativePlugin` is exported and documented as the code-level extension path,
  but no registry/host stores or drives it. Its `init/shutdown` contract is
  disconnected from PluginLifecycleManager and it cannot inject any component.

## Deviations

A public option is not dead merely because EKO omits it. `NativePlugin` is
different: the framework itself has no execution host and its promised behavior
is unreachable. A real native host would also be valid if the capability is
required.

## Conclusion

Failed. Supports F-PLG-01-P2-09 and F-PLG-01-P2-10.

## Follow-Up

Delete/privatize the lossy helpers in favor of one source-owned transaction;
delete NativePlugin and stale docs or implement it through canonical lifecycle.
