## Claim

Uninstall and lifecycle callback errors leave registry, filesystem, callbacks
and live resources in one truthful terminal state.

## Method

Trace registry uninstall ordering, data deletion, state save, EKO uninstall,
PluginLifecycleManager flags, callback errors, reconcile, unregister and Drop.
Inventory existing lifecycle and uninstall tests.

## Expected Result

Destructive state changes commit atomically or return a typed partial outcome;
callback failures cannot be represented as clean inactive/unregistered state
without a documented compensation/indeterminate state.

## Result

- Exit code: 0 for static reads; source invariant failed.
- Registry uninstall removes plugin files and its in-memory entry, ignores data
  deletion errors, then saves state. If state save fails it returns Err after the
  destructive changes. EKO returns before lifecycle unregister, so callbacks
  remain registered while the plugin files/registry entry are gone.
- Lifecycle flags change only after callbacks return Ok. `init` or `activate`
  may have started partial resources and returned Err while manager reports them
  uninitialized/inactive; retry invokes the callback again. A failed deactivate
  leaves `active=true` even if it stopped a subset, and restore may skip needed
  compensation.
- `unregister` deliberately removes ownership before cleanup and returns Err;
  this permits re-registration but provides no retained handle/retry for leaked
  resources. Drop only logs the same best-effort failures.
- Existing tests cover successful transitions and failing unregister callback,
  but not partial init/activate/deactivate side effects, state-save failure after
  delete, data deletion error or EKO's early-return ordering.

## Deviations

The framework cannot make arbitrary callback internals atomic. It can represent
attempted/indeterminate state and require or execute an explicit compensation.

## Conclusion

Failed. Supports F-PLG-01-P1-07 and F-PLG-01-P2-08.

## Follow-Up

Use staged filesystem/state replacement and a typed uninstall outcome; model
lifecycle attempts explicitly and retain cleanup ownership until settled.
