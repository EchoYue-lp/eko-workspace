## Claim

`PluginIntegrator::wire_all` either commits a complete source-owned component
set or restores the previous Agent state, including MCP ownership collisions.

## Method

Trace dependency resolution, collection, skill/hook/MCP registration, failure
accumulation, `components_by_plugin`, `plugins_loaded`, MCP reconnect semantics,
and public teardown APIs. Compare EKO's application-level replacement wrapper.

## Expected Result

Framework wiring has a prepare/commit/rollback contract and receipts identify
the exact live component generation; a duplicate MCP identity is rejected
before replacing another plugin's connection.

## Result

- Exit code: 0 for static reads; source invariant failed.
- `wire_all` registers components sequentially and accumulates errors. A later
  hook/MCP/skill failure leaves every earlier success live. It returns receipts
  but provides no matching framework rollback/unwire transaction.
- EKO compensates by unloading the candidate and rewiring the previous complete
  set. Direct framework callers documented to call `wire_all` do not receive the
  same atomic contract.
- MCP manager identity is only server name. Connecting the same name first
  disconnects the prior client and removes its tools; PluginIntegrator then
  records that name under both plugin receipts. The earlier receipt no longer
  identifies the live connection, and unloading by either receipt can disconnect
  the other plugin's server.
- Missing servers after a multi-server load mark the plugin failed but any
  successfully connected subset remains live and recorded.
- Skill source tags and HookSource::Plugin are positive ownership controls; the
  defect is transaction/generation ownership, not their absence.

## Deviations

EKO's stronger whole-set compensation is acknowledged as positive application
behavior and is not counted as a separate application defect.

## Conclusion

Failed. Supports F-PLG-01-P1-04 and F-PLG-01-P1-05.

## Follow-Up

Add a framework prepare/commit/reversible receipt contract and reject duplicate
component identities before mutation. EKO should coordinate its product-owned
components around that generic transaction rather than reimplement ownership.
