## Claim

values; inspected runtime IDs and errors are UTF-8 safe.

```text
Search RuntimeDag/task executor production paths for unwrap/expect/panic,
unchecked indexing/string slicing, narrowing/overflow, float Duration creation,
attempt increment, and timeout conversion.
```

## Expected Result

No valid public TaskExecutorConfig can panic; counters saturate/check; strings
are not byte-sliced.

## Result

- Exit code: 0 for static searches; semantic claim failed
- Duration: under one second per search
- Summary: runtime attempt increments mostly saturate/check and no unsafe UTF-8
  slice was found. `retry_delay_for_attempt` accepts public
  `retry_backoff_factor: f64`; negative/NaN configurations can produce negative
  or NaN `secs`, and `Duration::from_secs_f64` panics. The exponent also narrows
  `u32 attempt as i32`, producing wrong exponent after `i32::MAX`.
- Log/artifact: this report

## Deviations

call this helper; framework TaskExecutor full-DAG does.

## Conclusion

The no-panic claim fails for the live framework controller's single-task retry
pipeline. Supports F-TSK-03-P2-04.
