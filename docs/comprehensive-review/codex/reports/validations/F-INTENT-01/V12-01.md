## Claim

`UserPromptSubmit` hooks execute exactly once per turn with the same semantics in
streaming and non-streaming entries.

## Method

Trace non-stream preparation, streaming preparation, Intent classification, and
the shared core `prepare_turn` hook invocation.

## Expected Result

One authoritative prepare phase executes the hook once and passes its typed
result to classification and core execution.

## Result

- Exit code: not-applicable (static inspection).
- Non-streaming `prepare_react_context` does not run the hook; shared
  `run_core_loop -> prepare_turn` runs it once.
- Streaming `prepare_stream_context[_with_message]` runs the hook before Intent
  classification, then its ordinary fallback enters the same `prepare_turn` and
  runs the hook again.
- The first result may directly activate/cache a skill. The second result can
  repeat injected messages or side effects, while its `activate_skill` field is
  not consumed by prepare_turn.

## Deviations

DirectAnswer exits before the core and therefore runs one hook; the duplicate is
the common streaming path that continues into ReAct.

## Conclusion

Failed. Supports F-INTENT-01-P1-07.

## Follow-Up

Move hook execution into one shared pre-classification phase and pass the same
typed result through routing and core preparation without re-execution.
