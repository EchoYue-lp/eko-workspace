## Claim

Provider adapters and the ReAct layer have one retry authority per logical LLM
request.

## Method

Trace OpenAI-compatible `post`/`stream_post`, Anthropic chat/stream and ReAct
trait/raw paths; compare default retry counts and nesting.

## Expected Result

Only one layer retries a network attempt, or the outer layer detects a provider
that already owns retry.

## Result

- Exit code: 0
- Duration: under one second
- Summary: provider HTTP functions use core default policy (initial plus three
  retries). ReAct independently defaults to initial plus three retries and wraps
  both custom-provider and raw HTTP calls. A persistently retryable provider
  error can therefore execute up to 4 x 4 = 16 HTTP attempts for one logical
  ReAct request.
- Log/artifact: none

## Deviations

The maximum is derived from explicit loop bounds and call nesting; no paid or
external provider request was made.

## Conclusion

Retry authority is duplicated and can multiply attempts/latency. This is an
independent P2 finding.

## Follow-Up

Select one attempt owner and pass attempt metadata/cancellation through the
provider boundary.
