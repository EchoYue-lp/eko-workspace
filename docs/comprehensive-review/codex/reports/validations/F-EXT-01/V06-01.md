## Claim

Every successful public `ToolResult` payload has a bounded model projection and
a complete recoverable artifact when it cannot be placed inline.

## Method

Compared every `ToolResult` payload field and constructor with
`TruncationStage`, `process_tool_output_for_call`, artifact persistence,
`read_artifact`, `AgentEvent::ToolResult`, and `Message::tool_result`. Inspected
default `AgentConfig` artifact settings and searched all binary-result reads and
writes.

## Expected Result

Text, structured, and binary payloads either reach the model within a bound or
produce a complete typed reference that the model can page to completion.

## Result

- Exit code: 0
- Duration: static inspection
- Summary: text output has a strong path: default 1 MiB spill, complete text
  artifact, SHA-256, bounded preview, and UTF-8 `read_artifact` pages.
  `success_json` also mirrors JSON into `output`. In contrast,
  `ToolResult::binary` deliberately sets `output` empty and stores bytes only in
  `bytes`; the pipeline spill/guard/truncation and both live model/event
  projections read only `output`. The public constructor therefore produces a
  successful empty model result and no complete binary artifact.
- Log/artifact: this report

## Deviations

No current builtin constructs `ToolResult::binary`; this is a broken public
framework capability for independent consumers, not evidence that a current
EKO builtin loses bytes today.

## Conclusion

The claim failed and supports F-EXT-01-P1-05. Preserve the working text artifact
authority, but make payload-kind projection exhaustive or remove the
unsupported binary contract.

## Follow-Up

Future validation should cover text, JSON, bytes/image, file reference, table,
diff, command output, spill failure, and complete recovery.
