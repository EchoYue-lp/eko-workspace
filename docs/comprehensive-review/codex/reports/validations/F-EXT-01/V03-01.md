## Claim

The JSON Schema advertised by each `Tool` is enforced before the same
parameters reach `execute`, including parameters modified by hooks.

## Method

Field-by-field static trace:

```text
Tool::parameters / Tool::validate_parameters
  -> ToolDefinition::from_tool
  -> ToolManager::validate_tool_parameters_async
  -> ParseValidateStage
  -> PreToolUseHookStage / PermissionStage
  -> ExecuteStage -> ToolManager::{normal,stream}_with_context
```

Repository-wide caller search was performed for `validate_parameters` and
`validate_tool_parameters_async`; macro-generated deserialization and manual
tool implementations were inspected separately.

## Expected Result

The registry validates tool schemas, every invocation is schema/typed-validated
immediately before execution, and argument rewrites are revalidated.

## Result

- Exit code: 0
- Duration: static inspection
- Summary: `ToolDefinition::from_tool` copies arbitrary schema JSON without
  validation. `ToolManager` exposes `validate_tool_parameters_async`, but its
  only repository caller is its own definition. Normal and streaming execution
  call `execute_with_context` directly. `ParseValidateStage` checks one field
  for only `read_file`, four write names, and `shell`; it never calls the tool
  contract. Pre-tool and permission hooks can replace `ctx.params` after this
  stage without a second validation. Non-object raw input is converted to an
  empty map.
- Log/artifact: this report

## Deviations

Macro-generated tools deserialize typed parameters inside `execute`, and many
manual builtins validate their own inputs. Those local defenses do not satisfy
the generic contract and are inconsistent by construction.

## Conclusion

The claim failed and supports F-EXT-01-P1-01. Schema publication,
`validate_parameters`, the ReAct name table, and per-tool execute checks are
parallel mechanisms rather than one enforced contract.

## Follow-Up

Future fix validation must cover manual and macro tools, non-object input,
unknown fields, schema-invalid registration, and hook-modified input.
