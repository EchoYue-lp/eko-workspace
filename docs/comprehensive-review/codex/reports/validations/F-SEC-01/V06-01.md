## Claim

## Method

Compare the two PathValidator algorithms and trace `validate_output_file` results into representative text/data file writes.

## Expected Result

The nearest existing ancestor is canonicalized and checked against canonical allowed/denied roots; security-sensitive writes avoid following a replaced symlink between validation and open where practical.

## Result

- Exit code: 0 for source inspections.

- `validate_output_file` instead normalizes lexically and checks lexical prefixes (`:345-398`). A symlink located inside an allowed root can point outside it while retaining an allowed lexical prefix.
