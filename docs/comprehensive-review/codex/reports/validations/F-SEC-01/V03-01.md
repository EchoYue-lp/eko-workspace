## Claim

An isolation or network limit evaluated as required is either enforced or rejected, never silently downgraded.

## Method

Trace `SandboxPolicy::evaluate*` through manager selection and executor invocation; inspect local EKO construction and K8s resource-limit projection.

## Expected Result

Required isolation is a lower bound. A caller may request a preferred level with explicit downgrade semantics, but the default does not reinterpret “required” as advisory.

## Result

- Exit code: 0 for source inspections.
- Default/strict policy evaluates to Container (`policy.rs:89-104,157-199`), while `auto_detect` and `with_configs` set `allow_fallback=true` (`manager.rs:173-211`). If no executor satisfies the result, selection returns the strongest lower executor and execution proceeds after only a warning (`manager.rs:290-403`). Existing tests encode successful fallback.
- EKO's `local_sandbox()` is a positive product adapter: it caps policy at local OS/process and sets fallback false (`manager.rs:228-241`); app-core checks platform availability before exposing `run_code`.
- K8s accepts `ResourceLimits.network=false`, warns that it cannot enforce it, and still starts a normal pod without a NetworkPolicy/isolated-network mechanism (`k8s.rs:194-267`).

## Deviations

This is not a recommendation for online-service permission gates. It concerns honoring an explicit framework execution contract chosen by the caller.
