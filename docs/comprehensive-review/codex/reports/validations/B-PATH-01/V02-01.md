## Claim

The live composition roots and service ownership transitions for GUI, TUI,
CLI, channel, cron, and background execution can be traced from current code.

## Method

Read `AgentRuntime::bootstrap`, `AppState::from_shared`, GUI `run_desktop`,
headless `run_tui_or_cli_entry`, `start_headless_services`, `run_cli_mode`,
`run_channels_mode`, `run_tui`, channel handler construction,
`AppState::start_task_service`, and `AppState::start_scheduler_with_store`.
Search all callers of those constructors across both repositories.

## Expected Result

Each process constructs the primary runtime once; mode-specific roots then
install the services required by their surfaces, with no hidden second process
entry.

## Result

- Exit code: not-applicable
- Duration: not-applicable
- Summary: both process trees call `AgentRuntime::bootstrap` exactly once.
  GUI subsequently owns a retained `Arc<AppState>`. Headless modes build a
  primary agent, TaskRuntime store, and AgentPool in `src/main.rs`; TUI and CLI
  additionally construct a temporary `AppState` through
  `start_headless_services`. Pure channel mode does not call that function and
  owns only `ChannelManager` plus per-sender handlers. Scheduler fires are
  adapted to `launch_cron_run`; background submissions use
  `BackgroundTaskService` and the same TaskRuntime store.
- Log/artifact: task report composition table
