# F-TSK-01 / V20-03 - Primary pause transition ownership

> Status: failed
> Executor: Codex primary reviewer
> Date: 2026-08-12
> Source commit: `echo-agent` `9b0e0faf74d35c9a432370b923acabfbb5f32d63`

## Claim

`TaskManager::pause_run` must actually store the valid transition it requests for every matching nonterminal task.

## Execution

Read-only line-numbered inspection of `echo-orchestration/src/tasks/manager.rs:444-463` and `echo-orchestration/src/tasks/runtime.rs:127-174`.

## Result

The claim failed. `TaskStatus::transition_to` is a pure validating function that returns the target value. `pause_run` calls it and discards the `Result` without assigning the returned `TaskStatus` to the task (`manager.rs:451`). Therefore a `Pending` or `Running` task remains unchanged. `resume_run`, by contrast, performs a direct assignment.

## Impact

The public framework API reports no error and performs no pause. Callers can continue dispatching work after believing a run has been paused.
