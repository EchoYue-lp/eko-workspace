## Claim

Cargo's normalized `packages[].targets[]` provides a complete and internally
consistent target/required-feature inventory for both workspaces.

## Method

Final counts were computed only from Cargo's target array and grouped by target
kind. Framework example files and explicit tables were counted solely as an
independent cross-check, not merged into the authoritative total.

```text
cargo metadata --no-deps --locked --format-version 1 | jq '{
  target_count:([.packages[].targets[]]|length),
  target_kind_counts:([.packages[].targets[].kind[]]|group_by(.)|
    map({kind:.[0],count:length})),
  required_feature_target_count:([.packages[].targets[]|
    select(((.["required-features"] // [])|length)>0)]|length),
  examples:([.packages[].targets[]|select(.kind|index("example"))]|length),
  gated_examples:([.packages[].targets[]|
    select((.kind|index("example")) and
      (((.["required-features"] // [])|length)>0))]|length)
}'
awk '/^\[\[example\]\]/{n++} END{print n+0}' Cargo.toml
find examples -maxdepth 1 -type f -name '*.rs' | wc -l
```

Environment: macOS, Cargo 1.97.1, Rust 1.97.1, Node 22.22.0, npm 10.9.4.

## Expected Result

Grouped kind counts sum to total targets, required-feature counts match the
detailed target records, and filesystem/manifest cross-checks explain rather
than alter Cargo's final target set.

## Deviations

This validation enumerates but does not execute targets. Explicit table count
is lower than final example count because Cargo auto-discovers examples not
given custom tables.

## Conclusion

The target inventory is internally reconciled and suitable for downstream test
matrix design. It does not establish that any target compiles or passes.
