## Claim

Every normal EKO exit explicitly closes the primary agent and shuts down its
pool before the Tokio runtime terminates.

## Method

Search definitions and callers of framework `Agent::close` /
`ReactAgent::shutdown` and EKO `AgentPool::shutdown`. Trace GUI, TUI, CLI, and
pure-channel cleanup blocks, including Drop fallback semantics.

```text
rg -n "pub async fn shutdown|fn close\(&self\)|impl Drop for ReactAgent|pool\.shutdown|browser_runtime.shutdown" echo-agent/src echo-agent-cli/src echo-agent-cli/echo-agent-app-core/src -g '*.rs'
```

## Expected Result

The composition owner first stops request producers, then awaits pool shutdown
and primary-agent close, and only then tears down process-level browser/runtime
resources. Framework Drop is a last-resort fallback, not the normal exit path.

## Result

- Exit code: `0`
- Duration: under 1 second
- Summary: `AgentPool::shutdown` cancels its cleanup monitor and clears all
  pooled agents (`agent_pool.rs:808-815`), but there are no production callers.
  Framework `ReactAgent::shutdown` fires a shutdown SessionEnd hook and awaits
  `Agent::close` (`echo-agent/src/agent/react/mod.rs:1998-2010`); `close` awaits
  all MCP closes (`:2994-3000`). No EKO entry calls either API. GUI and headless
  cleanup only shut down the separate BrowserRuntime and task hook dispatcher
  (`src/tauri/desktop.rs:260-268`; `src/main.rs:329-338,394-401,437-445`).
  `ReactAgent::drop` replaces the MCP manager and spawns detached close work
  (`react/mod.rs:2616-2632`), so immediate Tokio-runtime teardown cannot prove
  completion. Pool cleanup monitor likewise has a detached task and relies on
  an explicit but unused cancellation method.
- Log/artifact: none

## Deviations

ReAct turn finalization fires per-turn SessionEnd events on normal completion;
this does not close MCP clients or stop the pool monitor. This validation does
not duplicate the scheduler/background token issue already owned by
`B-PATH-01-P2-03`.

## Conclusion

The claim is false. This supports `A-BOOT-01-P1-04`: the implemented core-agent
and pool shutdown protocol is unreachable from real composition roots.

## Follow-Up

One application lifecycle owner should hold the pool and primary agent and
await their idempotent shutdown. A fix test must use instrumented MCP transport
and cleanup-monitor handles to assert completion before runtime return.
