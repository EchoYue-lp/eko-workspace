## Claim

Each live EKO composition root constructs one instance of every process-level
core service and retains the instance that becomes runtime authority.

## Method

From the repository root, search both source repositories for the definitions
and live calls of `AgentRuntime::bootstrap`, `AppState::from_shared`,
`TaskRuntimeStore::new`, `AgentPool::from_runtime`, `init_pool`,
`start_headless_services`, `run_cli_mode`, and `run_channels_mode`. Trace GUI,
TUI, CLI, pure-channel, and CLI-plus-channel branches from their binary entry
points through service construction. Inspect `TaskRuntimeStore` and
`FileTaskShadow` ownership rather than assuming two constructors share locks.

```text
rg -n "run_desktop_entry|run_tui_or_cli_entry|start_headless_services|run_cli_mode|run_channels_mode|AppState::from_shared|TaskRuntimeStore::new\(|AgentPool::from_runtime|init_pool" echo-agent-cli/src echo-agent-cli/echo-agent-app-core/src -g '*.rs'
```

## Expected Result

GUI and headless roots may use different adapters, but each process constructs
exactly one canonical TaskRuntime store, agent pool, webhook emitter, scheduler,
and background service; temporary construction does not perform discarded
initialization or recovery.

## Result

- Exit code: `0`
- Duration: under 1 second
- Summary: GUI constructs one `AppState`, retains its TaskRuntime store, then
  creates one pool and the two common services. Headless first creates and
  recovers a TaskRuntime store in `src/main.rs:35-56`, constructs the pool from
  it at `:183-200`, then `start_headless_services` constructs a full
  `AppState` at `src/cli/modes.rs:57`. `AppState::from_shared` creates another
  TaskRuntime store and calls recovery at `state.rs:544-566`; the headless
  adapter immediately overwrites it with the first store at `modes.rs:60` and
  drops the rest of the state after cloning two service handles. The discarded
  `AppState` also creates a webhook emitter, persistence/search/tool-execution
  objects, workspace registry, and skills hub. Each `TaskRuntimeStore::open`
  creates a distinct `FileTaskShadow` and therefore distinct per-run locks and
  sequence cache (`store.rs:176-186`, `file_shadow.rs:17-50`).
- Log/artifact: `/tmp/a_boot_constructor_search.txt`

## Deviations

The second TaskRuntime handle is discarded before normal task execution, so
this inspection does not prove a current concurrent-write corruption. It does
prove duplicate construction, duplicate crash recovery, and discarded startup
side effects on every TUI and CLI service boot.

## Conclusion

The claim is false. This supports `A-BOOT-01-P2-06`: headless composition uses
`AppState` as a side-effectful service factory and violates exactly-once
construction.

## Follow-Up

Replace the temporary `AppState` pattern with one retained application
lifecycle owner or side-effect-free service constructors. A regression test
should count TaskRuntime construction/recovery and assert one retained identity
per entry mode.
