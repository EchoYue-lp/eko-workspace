## Claim

In combined `--channels --cli` mode, leaving the CLI invokes
`ChannelManager::stop_all` and waits for channel transport shutdown.

## Method

Trace construction and ownership of the `run_channels_mode` future in the
combined branch, the REPL `/exit`/Ctrl-D terminal path, and the sole
`ChannelManager::stop_all` call.

```text
rg -n "channels_handle|run_channels_mode|shutdown_signal|stop_all|CommandResult::Exit|Signal::CtrlD" echo-agent-cli/src -g '*.rs'
```

## Expected Result

When the foreground CLI finishes normally, it signals the channel task, awaits
`run_channels_mode`, and therefore executes `manager.stop_all()` before common
runtime cleanup.

## Result

- Exit code: `0`
- Duration: under 1 second
- Summary: combined mode spawns `run_channels_mode` into `channels_handle`
  (`src/main.rs:365-371`), runs the REPL, then falls through without cancelling,
  aborting, or awaiting that handle (`:373-405,437-450`). The REPL returns on
  `/exit` or Ctrl-D (`src/cli/repl.rs:215-245`). `run_channels_mode` calls
  `manager.stop_all()` only after its independent process shutdown signal
  resolves (`src/cli/modes.rs:216-234`). Dropping a Tokio `JoinHandle` detaches
  rather than cancels the task, so the task remains blocked until the outer
  runtime is destroyed; its orderly channel stop block is bypassed.
- Log/artifact: none

## Deviations

Pure `--channels` awaits the handle and reaches `stop_all` after Ctrl-C; this
finding is specific to the live combined channel-plus-CLI branch.

## Conclusion

The claim is false. This supports `A-BOOT-01-P2-05`: normal CLI exit bypasses
the channel manager's only orderly transport shutdown path.

## Follow-Up

Give the combined mode a shared cancellation signal and retained handle. Add a
fake channel whose `stop` records completion, leave the REPL normally, and
assert the record is written before the entry future resolves.
