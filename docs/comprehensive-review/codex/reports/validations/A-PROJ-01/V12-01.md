## Claim

Project ignore matching is UTF-8 safe for arbitrary project-relative paths and
cannot panic at an invalid character boundary.

## Method

```text
Inspect GitIgnore::glob_matches, simple_glob, and globstar_match for every byte
offset used as a str slice; trace GitIgnore through ProjectContext construction
and search all internal callers of should_ignore_path/is_ignored. Inspect tests
for multibyte paths with a middle ** pattern.
```

## Expected Result

String scanning may operate on bytes for ASCII protocol tokens, but must never
slice arbitrary UTF-8 at an unvalidated byte offset.

## Result

- Exit code: 0
- Duration: static string-boundary inspection; not timed
- Summary: `globstar_match` iterates every integer byte offset from 0 through
  `remaining.len()` and evaluates `&remaining[j..]`; after a match it also
  slices at `j + part.len()` (`project/gitignore.rs:158-185`). With a Chinese or
  emoji path, most candidate offsets are not UTF-8 character boundaries and the
  first such slice panics. ProjectContext is constructed in the live CLI, but
  internal search found no production caller of `should_ignore_path`; current
  core execution therefore does not trigger it. Tests use ASCII only.
- Log/artifact: this report
