## Claim

Task, Subagent, and tool projections shown by TUI can be reconstructed from the
durable TaskRuntime/conversation authorities after restart or conversation
resume.

## Method

```text
Trace TUI startup/resume and 250 ms refresh reads; compare durable store APIs
and GUI loadByConversation hydration. Inspect Subagent broadcast capacity,
Lagged handling, event-to-view keys, conversation message restoration, and
TaskRuntime event/tool artifact replay.
```

## Expected Result

The TUI should rebuild the same run, task, Subagent outcome, tool terminal, and
artifact facts as GUI, then apply live events idempotently.

## Result

- Exit code: 0
- Duration: static inspection; not timed
- Summary: TUI refresh reads only latest run and plan (`events.rs:4920-4961`).
  It subscribes to a 128-entry live framework Subagent broadcast and ignores
  `try_recv` errors by ending the drain loop (`events.rs:562-572`;
  `echo-agent/src/agent/subagent/events.rs:10,342-375`). On resume it clears
  `subagent_runs` and restores stored tool messages only as generic
  `ToolResult { tool_name: "tool" }` (`events.rs:4818-4873`). It never reads the
  store's durable `list_events`/artifact APIs. GUI loads plan/todos/artifacts,
  replays all runtime events from sequence zero, and hydrates persisted tool
  executions (`web-frontend/src/stores/taskRuntimeStore.ts:219-264`).
- Log/artifact: this report

## Deviations

Framework inline Subagent executions without a TaskRun may lack the same durable
application ledger; that case increases uncertainty but does not negate the
demonstrated TaskRuntime replay gap.

## Conclusion

The claim fails and supports A-SRF-01-P1-02. A lag or restart can leave the TUI
Subagent/tool surface incomplete or stale even though durable EKO facts exist.

## Follow-Up

Replay persisted events before live subscription and explicitly surface/resync
on broadcast lag.
