## Claim

Streaming is semantically equivalent to non-streaming for text, thinking, tool
calls, usage, errors, cancellation, response identity, and structured output.

## Method

Trace bytes from both HTTP transports through SSE framing and provider event
decoding into `ChatChunk`, then through `create_llm_stream` reconstruction and
the ReAct stream processor. Compare with `chat`/`call_llm_with_retry` field use.

## Expected Result

Byte boundaries do not change Unicode, malformed events become errors,
cancellation wins promptly, provider block/candidate indices survive, and both
modes receive the same configured request controls.

## Result

- Exit code: not-applicable
- Duration: not recorded
- Summary: both transports decode each byte chunk with `from_utf8_lossy`; the
  shared SSE parser drops malformed JSON; cancellation is checked around, not
  while awaiting, bytes; Anthropic tool starts replace provider block index
  with map length; `ChatChunk` drops response/candidate identity; and canonical
  streaming hardcodes `response_format: None` while non-streaming forwards it.
- Log/artifact: none

## Deviations

Whether usage chunks are cumulative or delta is not documented by the neutral
trait; the runtime's last-usage policy therefore remains an explicit coverage
gap rather than a finding here.

## Conclusion

Streaming neutrality fails. This supports F-LLM-01-P1-01,
F-LLM-01-P1-02, F-LLM-01-P1-04, F-LLM-01-P1-07, and F-LLM-01-P2-08.
