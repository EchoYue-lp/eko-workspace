## Claim

Feishu long-poll framing is bounded for malformed peer input and its acknowledgement/dedup lifecycle preserves failed work.

## Method

Static Protobuf frame, fragment-cache, acknowledgement, dedup, spawned-handler, reconnect, and stop ownership inspection in `feishu/long_poll.rs` and `feishu/channel.rs`.

## Expected Result

Fragment counts and aggregate bytes are bounded before allocation; malformed frames return typed bounded failure; processing failure remains retryable or is durably represented; stop owns all tasks.

## Result

- Exit code: 0
- A peer-controlled signed `sum` greater than one is cast directly to `usize` and used by `vec![None; sum]` with no fragment/byte cap (`long_poll.rs:383-391,465-484`). A very large count can exhaust memory before TTL cleanup.
- The valid `seq` check prevents out-of-bounds assignment, but total reassembled bytes are also unbounded (`long_poll.rs:487-504`).
- The response frame is sent before parsing/processing; the message ID is inserted into dedup before spawning processing; async errors only log (`long_poll.rs:408-444`). A replay after failure is skipped.
- Per-event tasks and the Feishu send task are detached. `FeishuChannel::stop` aborts only the top receive/server handle and reports success without awaiting or draining send/event work (`channel.rs:207-226,251-306`).

## Conclusion

Failed. Malformed fragments can cause unbounded allocation, while successful acknowledgement can hide failed processing and shutdown does not own all work.
