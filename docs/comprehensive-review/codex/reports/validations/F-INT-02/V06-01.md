## Claim

Feishu Webhook verifies the actual signed wire payload and gives retry/dedup semantics that do not convert handler failure into permanent success.

## Method

Static request extraction, signature input, dedup ordering, response timing, and detached-task ownership inspection in `feishu/webhook.rs`.

## Expected Result

Signature verification consumes the raw request bytes; accepted events are either durably queued or remain retryable until processing succeeds; shutdown owns spawned event work.

## Result

- Exit code: 0
- Axum first parses the body into `serde_json::Value`, then signature verification serializes that value again (`webhook.rs:80-84,100-118`). JSON key order/whitespace/number spelling can change, so this is not the original signed body and valid signed requests can be rejected.
- The message ID is marked processed before payload validation and handler execution (`webhook.rs:141-160`).
- The endpoint returns success immediately and processing runs in a detached task; handler/reply failure only logs and the dedup entry remains (`webhook.rs:189-213`). A retry is therefore acknowledged and skipped for the TTL.
- The server task owns neither the per-event task handles nor a drain/cancel policy.

## Conclusion

Failed. Configured signature verification is not a faithful wire adapter, and delivery acknowledgement can make failed messages unrecoverable.
