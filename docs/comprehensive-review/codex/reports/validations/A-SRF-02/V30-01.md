## Claim

The delegated desktop/Tauri findings are supported by production source and the
locked Tauri API implementation, remain within the local EKO threat model, and
are distinct from generic shutdown and frontend-reducer reviews.

## Evidence Sampled

- `tauri-2.11.2/src/app.rs::Builder::setup` assigns `self.setup = Box::new(setup)`;
  it does not compose prior setup hooks. `src/tauri/mod.rs` calls it once for
  DevTools/Browser events and later again for shortcut/Subagent events.
- `src/tauri/terminal.rs::write_terminal` decodes every interactive input and
  logs its first 80 bytes as `preview`; GUI tracing persists application logs.
- `TerminalManager::create` separates `contains_key`, process/thread spawn, and
  `insert`, while `reader_loop` only emits exit and cannot remove/reap the
  manager-owned session.
- `TerminalManager::close_all` launches detached kill tasks and has no
  production caller; desktop teardown does not retain or invoke the manager.
- `src/tauri/commands/panels.rs` directly owns workflow IDs, in-memory CRUD,
  YAML/JSON parsing, framework Graph execution, and result DTO creation; no
  reusable app-core service or non-GUI surface caller exists.

## Result

All five findings are accepted. Terminal content logging is a P0 local secret
exposure and should be removed without adding an Agent automation permission
gate. The two setup calls definitively replace rather than accumulate. PTY
identity and teardown lack transactional ownership. Workflow policy belongs in
an EKO app-core service, while generic Graph remains in the framework.

No application launch, PTY process, build, test, fixture, network, or source
mutation was performed. CLI source was clean at
`b3b2e81f2b2d9fdb319ec604a561beec5f66fea5`; unrelated concurrent framework
worktree changes were excluded.
