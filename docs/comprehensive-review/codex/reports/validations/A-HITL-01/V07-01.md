## Claim

Direct user terminal, workspace file and MCP configuration remain independent of Agent automation permission mode and receive only local-product-appropriate validation.

## Method

Search direct Tauri commands and all `IpcAuth`/permission-mode consumers; inspect terminal consent and MCP URL/executable validation plus their current tests.

## Expected Result

No direct-user command consults Agent automation mode. Validation rejects malformed/obviously unsafe configuration without blocking the user's trusted local MCP server or custom launcher by online XSS/SSRF assumptions.

## Result

- Exit code: 0 for source inspections/searches.
- Positive: terminal, file and MCP command modules contain no live `permission_mode`/`IpcAuth` call. `IpcAuth` is currently dead except for its own definitions/comments. Terminal creation is explicitly ungated; file writes use workspace/revision checks; MCP connect states it is user-driven.
- Terminal still requires per-session consent before the first write, based on XSS reasoning (`terminal.rs:286-355`); the frontend invokes confirmation on first real terminal input, so the normal user flow remains reachable.

## Deviations

Light checks for empty commands, obvious shell metacharacters and URL scheme are within the product boundary. The finding is limited to capability-level executable/network-location blocking derived from an online threat model.
