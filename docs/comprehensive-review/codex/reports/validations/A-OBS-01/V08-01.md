## Claim

Prompt-module diagnostics shown for a historical run are derived from that
run's configuration/workspace identity rather than current process state.

## Method

```text
Trace PromptAssembly creation in AgentRuntime::bootstrap, storage in AppState,
Tauri get_run_diagnostics, CLI CommandContext, and load_run_diagnostics. Compare
PromptAssembly fields with Run/RunSummary identity and the frontend rendering.
Check config reload and workspace/model changes for a per-run snapshot or lookup.
```

## Expected Result

A historical diagnostic either displays a prompt snapshot/fingerprint captured
for that exact invocation or clearly marks prompt assembly unavailable.

## Result

- Exit code: 0
- Duration: static provenance inspection; not timed
- Summary: PromptAssembly is created once at primary-agent bootstrap and stored
  process-wide. Every GUI diagnostic request passes that current startup value
  into `load_run_diagnostics`, which attaches it unchanged to whichever
  diagnostic ID the user selected. CLI does the same; channels omit it. The
  report has module hashes/counts but no run/config/workspace/model identity.
  Thus old runs, pooled agents, or runs after configuration/workspace changes can
  be labeled with an unrelated prompt assembly while the UI presents it inside
  the selected run's details.
- Log/artifact: this report

## Deviations

The current config watcher documents that several domains require restart, but
historical runs across restarts remain in the durable store and are still paired
with the new process snapshot.

## Conclusion

The prompt diagnostic provenance invariant fails and supports
A-OBS-01-P1-06.

## Follow-Up

Persist a bounded prompt manifest/fingerprint with each invocation, or omit the
section unless a run-keyed snapshot is available. Do not create a second run
store.
