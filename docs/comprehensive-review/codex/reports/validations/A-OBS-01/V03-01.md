## Claim

Every webhook fact preserves enough event, configuration, conversation, run,
turn, execution, tool-call, attempt, and terminal identity to correlate it with
the canonical live lifecycle.

## Method

```text
Compare WebhookEvent/WebhookPayload fields with EventEnvelope::identity and the
identity constructed by drive_chat. Follow FinalAnswer, Error, Cancelled,
ToolCall/Result/Error, stream setup failure, and cron TaskRun settlement into
the webhook observer and event schema. Check whether completion derives from
the driver's semantic terminal or an intermediate payload.
```

## Expected Result

Webhook events carry stable correlation identity and exactly one terminal status
matching the driver/TaskRun outcome; tool start and terminal facts share call ID.

## Result

- Exit code: 0
- Duration: static field/call-path comparison; not timed
- Summary: `drive_chat` constructs conversation/run/turn identity, but
  `WebhookTurnObserver::observe` receives only `AgentEvent`, discarding the
  envelope. The schema contains none of those IDs, no config/workspace identity,
  no event/delivery ID, and no tool call ID. It has no cancellation event.
  `FinalAnswer` flips a Boolean and `finish` emits ChatCompleted even if a later
  Error/Cancelled fact was observed. This compounds, but does not re-own,
  A-CHAT-01-P1-01's canonical driver terminal defect. Cron completion correctly
  follows `launch_cron_run`'s TaskRun status check and was not misclassified.
- Log/artifact: this report

schema/observer is nevertheless unable to reject or correlate that sequence.
