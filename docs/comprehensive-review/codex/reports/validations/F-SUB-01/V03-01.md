## Claim

Registration updates instance, definition, factory, discovery, and execution
identity atomically and rejects duplicate-name ambiguity.

## Method

Field-by-field inspection of all async and sync registration, definition-only,
factory, lookup, instantiation, removal, and list operations in
`SubagentRegistry`, then trace through `ReactAgent::register_subagent_*` and EKO
default/plugin assembly. Lock order and return semantics were compared. No
concurrency fixture was executed.

## Expected Result

A successful registration exposes one coherent name-to-definition-to-runtime
record; failure changes nothing; replacement is explicit.

## Result

- Exit code: 0
- Duration: static concurrency inspection
- Summary: the registry stores instances, definitions, and factories under
  separate locks. Async registration releases the instance lock before updating
  the definition. `register_sync` returns true and emits `Registered` after the
  instance insert even if the definition lock fails. Definition-only updates do
  not clear an older instance/factory, and every insert silently replaces a
  same-name record. `get_agent` returns a cached instance without checking that
  it corresponds to the current definition.
- Log/artifact: this report

## Deviations

EKO normally performs default assembly while it exclusively owns the Agent,
but plugin registration/reload makes replacement a real live behavior. The
static review does not assign a probability to lock contention.

## Conclusion

The claim failed. The registry can permanently or transiently expose a catalog
identity that executes a different/missing runtime. Supports
F-SUB-01-P1-01.

## Follow-Up

Add contention, duplicate, definition-promotion, and concurrent lookup
regression scenarios after adopting one atomic record authority.
