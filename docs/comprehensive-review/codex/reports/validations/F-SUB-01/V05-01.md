## Claim

`SubagentDefinition.execution_mode` and `inherit_history` remain authoritative
when a model invokes builtin `agent_tool`.

## Method

Trace omitted and explicit `mode` from JSON parameters into
`DispatchRequest.mode_override`, parent-context construction, executor mode
selection, transfer policy, `ContextInheritance::from_parent`, and
`filter_history`. Compare all `None`/`Some(0)`/`Some(n)` semantics with field
documentation. No code was executed.

## Expected Result

Omitting `mode` uses the registered default; `Some(0)` inherits all eligible
parent turns; and `Some(n)` can select the documented last `n` turns.

## Result

- Exit code: 0
- Duration: static data-flow inspection
- Summary: builtin dispatch changes omitted/invalid mode to Sync and always
  sends `mode_override: Some(exec_mode)`, overriding the registered default
  except for isolation forcing Fork. Explicit Fork first builds a context with a
  hard-coded last-two-message preset, then applies the definition limit, so
  values above two cannot be honored. `SubagentContext::from_parent(Some(0))`
  returns zero messages while `filter_history(..., Some(0))` means unlimited.
- Log/artifact: this report

## Deviations

Direct programmatic `SubagentExecutor::dispatch` with `mode_override: None` does
use the definition. EKO defaults currently declare Fork, making the builtin
override directly observable.

## Conclusion

The claim failed. Model-facing delegation does not implement the public
definition semantics. Supports F-SUB-01-P1-03.

## Follow-Up

Preserve `None` as no override and compute one inheritance policy from the
effective definition before snapshotting parent state.
