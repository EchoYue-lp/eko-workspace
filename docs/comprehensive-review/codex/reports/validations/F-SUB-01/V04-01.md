## Claim

Every model-facing Subagent catalog is a complete, current, executable snapshot
of the shared registry.

## Method

Trace local `AgentDispatchTool.catalog`, `update_dispatch_catalog`,
`sync_subagent_dispatch_catalog`, definition-only registration, unregister, EKO
default child synchronization, plugin addition, plugin child construction, and
plugin unload. Compare catalog entry readiness with `get_agent`/factory lookup.
No code was executed.

## Expected Result

Schema names equal the executable registry set at the same revision for every
delegation-capable Agent, including reload and removal.

## Result

- Exit code: 0
- Duration: static state-flow inspection
- Summary: each Agent owns an independent vector projection. Sync only upserts
  provided definitions and never clears omitted entries. Registry events do not
  update other Agents. Definition-only roles are deliberately advertised before
  they are executable. EKO synchronizes built-in child catalogs once, but
  dynamic plugin registration updates only the primary Agent; plugin children
  are built with an empty local catalog, while unload removes only the primary
  projection. Existing child schemas can therefore omit live plugins or retain
  removed roles.
- Log/artifact: this report

## Deviations

The primary Agent's own register/unregister path does update its local vector and
sort entries deterministically.

## Conclusion

The claim failed. Catalog identity and registry readiness/revision are separate
authorities. Supports F-SUB-01-P1-02.

## Follow-Up

Make schema generation read one immutable executable registry snapshot or
broadcast revisioned replacement to every local projection.
