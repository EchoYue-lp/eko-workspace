## Claim

Builtin dispatch preserves the executor's terminal status and typed failure
category for completion, cancellation, timeout, malformed result, and runtime
error.

## Method

Trace pre-cancel, streaming `Cancelled`, timeout, `AgentEvent::Error`, executor
`SubagentOutcome`, dispatch events, `serialize_parent_result`, and both error
branches in `AgentDispatchTool`; compare against `ToolResult::error` and
`ToolFailureCategory`. No code was executed.

## Expected Result

Every terminal reaches the parent with one typed status/category; cancellation
and timeout are never represented as permanent failures.

## Result

- Exit code: 0
- Duration: static terminal trace
- Summary: completed and stream-cancelled `Ok(SubagentResult)` outcomes serialize
  their typed `SubagentOutcome`. Pre-cancel, timeout, stream error, missing Agent,
  depth failure, and background-start errors return `Err` from the executor;
  builtin dispatch converts every one to `ToolResult::error`, whose category is
  always Permanent and whose output contains no structured Subagent terminal.
  Thus the event bus may emit typed Cancelled/TimedOut while the parent model
  receives a permanent generic tool failure for the same execution.
- Log/artifact: this report

## Deviations

This finding is the Subagent adapter consequence of the accepted generic
`ToolFailure` boundary from F-CORE-01; it does not re-review generic Tool
execution.

## Conclusion

The claim failed. The model-facing adapter loses terminal semantics for common
error paths. Supports F-SUB-01-P1-05.

## Follow-Up

Map executor status/error types to one structured Subagent tool result and an
accurate `ToolFailureCategory`.
