## Claim

Subagent identity, definition, context, and result each have one authoritative
framework representation, with no overlapping public contract.

## Method

Static cross-repository symbol and semantic search for `SubagentDefinition`,
`SubagentContext`, `ContextBuilder`, `OutputSchema`, `SubagentOutput`,
`SubagentOutcome`, registration maps, prompt compilers, and result parsing. All
non-test references were classified as definition, projection, adapter, or live
consumer. No code was executed.

## Expected Result

One declaration drives execution; one context type has live consumers; and one
typed result contract reaches callers.

## Result

- Exit code: 0
- Duration: static inspection
- Summary: `SubagentDefinition` and `SubagentOutcome` are the intended live
  contracts, but several declaration fields have no runtime consumer.
  `ContextBuilder`, `MemoryScope`, `OutputSchema`, and `SubagentOutput` are
  publicly re-exported yet are referenced outside their defining module only by
  that re-export. `SubagentOutput` overlaps the live `SubagentOutcome` without
  reaching parsing, dispatch events, `agent_tool`, or EKO TaskRuntime.
- Log/artifact: this report

## Deviations

The application legitimately has an EKO source definition and immutable UI
catalog view; those are product adapters, not duplicate framework executors.

## Conclusion

The claim failed. Public dormant context/result APIs create a second apparent
contract, and the live definition is partly descriptive rather than enforced.
Supports F-SUB-01-P2-04 and F-SUB-01-P2-05.

## Follow-Up

Retain one framework context/result authority; validate real external users
before deleting public APIs.
