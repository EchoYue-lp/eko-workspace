## Claim

Role prompt, model, tool/permission selection, memory, iteration, token, and
delegation declarations are enforced consistently by registration and dispatch.

## Method

For every `SubagentDefinition` field, search production reads across both
repositories and trace construction of prebuilt/default/plugin Agents,
factories, `SubagentContext`, `AgentInvocationContext`, disabled tools, and
prompt compilers. No code was executed.

## Expected Result

Each behavior-bearing field either configures the executable Agent from one
factory or is validated against it before registration/dispatch.

## Result

- Exit code: 0
- Duration: static field matrix
- Summary: timeout and isolation are executor-enforced; history is only partly
  enforced. Model/system prompt/max iterations/token/can-delegate are separately
  baked into Agent instances by application factories, with no registry
  consistency check. `tool_filter` and `lightweight` have no production read.
  Definition `inherit_memory` selects no dispatch policy, and the captured
  `SubagentContext.store`/tool definitions are not passed to the executable
  Agent. Only invocation-specific `allowed_tools` disables Fork tools; Sync and
  Teammate do not consume it.
- Log/artifact: this report

## Deviations

EKO's default construction manually mirrors many fields correctly. This local
duplication reduces immediate mismatch for built-ins but does not satisfy the
public framework contract or plugin/custom callers.

## Conclusion

The claim failed. Definition and executable capability are two authorities, and
some advertised restrictions are inert. Supports F-SUB-01-P2-04.

## Follow-Up

Choose one factory-owned effective definition, validate it at registration, and
remove or implement inert framework fields rather than duplicating application
wiring.
