## Claim

The string-array namespace representation is injective and prefix enumeration
respects component boundaries in InMemoryStore, FileStore, and EmbeddingStore.

## Method

Inspect every namespace encoder/decoder/prefix comparison and compare the
representations for `['a/b','c']` versus `['a','b/c']`, plus prefix `['user']`
versus stored namespace `['user2','memory']`.

```text
rg -n 'join\("/"\)|split\("/"\)|starts_with\(' \
  echo-state/src/memory echo-core/src/memory --glob '*.rs'
```

Environment: static representation proof only; no dynamic fixture executed.

## Expected Result

Distinct component arrays map to distinct internal keys and prefix comparison
matches complete components only.

## Result

- Exit code: 0 for the search; claim failed
- Duration: not recorded
- Summary: both concrete stores encode namespaces with `join("/")`, decode
  with `split('/')`, and prefix-filter the flattened key using raw
  `starts_with` (`echo-state/src/memory/store.rs:44-45`, `:138-154`,
  `:399-415`). Thus the two example arrays collide, and prefix `user` includes
  `user2`. EmbeddingStore repeats the same flattened key at
  `embedding_store.rs:223`, `:342`, and `:378`, so semantic vectors share the
  same collision. The public trait and docs model namespaces as component
  arrays and promise isolation.
