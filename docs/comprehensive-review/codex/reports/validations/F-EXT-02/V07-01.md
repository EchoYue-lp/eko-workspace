## Claim

Git and worktree subprocesses do not block an async runtime indefinitely and
honor the owning ToolContext cancellation/timeout contract.

## Method

```text
1. Trace every Git Tool and worktree Tool subprocess call.
2. Search these implementations for tokio::process, spawn_blocking, timeout,
   CancellationToken consumption, kill_on_drop, process groups, and output caps.
3. Compare with ShellTool and RunCodeTool only as positive implementation
   references; do not repeat F-EXT-01's generic ToolManager finding.
```

## Expected Result

Async Tools use a cancellable bounded child-process primitive that reaps the
process tree and bounds captured output.

## Result

- Exit code: 0 for static searches
- Duration: approximately 4 minutes
- Summary: Git Tools execute synchronous `std::process::Command::output`
  directly inside async Tool futures. Worktree Tools call synchronous helpers
  the same way. Neither path reads ToolContext cancellation, applies a timeout,
  establishes process-tree cleanup, or caps buffered stdout/stderr. Git hooks,
  signing, credential helpers, or large diff/log output can therefore block a
  runtime thread or consume unbounded memory. Shell/RunCode contain substantial
  lifecycle controls, confirming a reusable implementation pattern exists.
- Log/artifact: `echo-tools/src/git.rs:421`, `echo-tools/src/git.rs:505`,
  `echo-tools/src/git.rs:571`, `echo-tools/src/git_worktree.rs:60`,
  `echo-tools/src/worktree_tool.rs:78`, `echo-tools/src/shell.rs:576`,
  `echo-tools/src/code.rs:358`.

## Deviations

F-EXT-01 already owns generic executor cancellation. This validation is limited
to specialized child-process propagation and cleanup.

## Conclusion

The Git/worktree execution path violates async cancellation and bounded process
lifecycle requirements. Supports `F-EXT-02-P1-03`.
