## Claim

The facade and seven split crates expose several duplicate public names, but
only the two concrete `DefaultAgentFactory` definitions represent the same
claimed capability with competing authority.

## Method

Search public structs, enums, traits, aliases and re-exports across all eight
framework library surfaces, then inspect definitions and live callers for the
duplicate names `AgentBuilder`, `CheckpointStore`, `MemoryScope`, `TaskState`,
JSON-RPC types and `DefaultAgentFactory`.

```text
rg -n 'pub (struct|enum|trait|type) ...|pub use ...' \
  src echo-core/src echo-execution/src echo-integration/src echo-tools/src \
  echo-state/src echo-orchestration/src
```

## Expected Result

Every duplicate is either a deliberate alias/distinct namespace or has one
clearly usable authority.

## Result

- Exit code: 0
- Duration: under one second
- Summary: the search found distinct MCP/LSP JSON-RPC contracts, distinct
  A2A/task/team states, distinct memory/subagent scopes, and distinct
  background/workflow checkpoint stores. `AgentBuilder` is an intentional
  facade alias for `ReactAgentBuilder`, with the core trait exposed as
  `AgentBuilderTrait`. Core and facade both define/re-export a concrete
  `DefaultAgentFactory`; the core implementation always returns an error.
- Log/artifact: none

## Deviations

Name equality alone does not prove semantic duplication; each candidate was
adjudicated from its definition and consumer namespace.

## Conclusion

This supports F-API-01-P2-06 and prevents unrelated same-name domain types from
being mislabeled as duplicate authorities. It does not assess their internal
runtime correctness.
