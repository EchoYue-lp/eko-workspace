## Claim

Code-based and file-based Skills both have reachable enable/disable/unload
cleanup that removes owned tools, prompt content, hooks and resources.

## Method

Trace `Skill::shutdown`, `ReactAgent::add_skill`, code-skill registry storage,
ToolManager removal, file descriptor removal, policy reconciliation and
source-scoped unregister APIs.

## Expected Result

The runtime retains a lifecycle owner per installed Skill and can reverse every
registration before calling `shutdown` exactly once.

## Result

- Exit code: 0
- Duration: not separately timed
- Summary: file Skills have descriptor removal, policy reconcile and plugin
  source unload that clear both registries, hooks and projections. Code Skills
  do not: `add_skill` consumes the boxed Skill, extracts tools/prompt and stores
  only `SkillInfo`; the object is dropped immediately, `Skill::shutdown` has no
  production caller, and there is no `remove_skill` that maps its tool names,
  prompt injection and shutdown together. Individual tool removal cannot undo
  appended prompt text or invoke the Skill lifecycle.
- Log/artifact: this report

## Deviations

Rust `Drop` may clean up a particular implementation, but that does not fulfill
the public `shutdown` contract or reverse Agent registrations.

## Conclusion

Fails code-Skill unload semantics and supports `F-SKL-01-P2-05`.

## Follow-Up

Retain an owned installed-Skill record with reversible registrations, or remove
the unreachable shutdown contract if code Skills are intentionally immutable.
