## Claim

All activation and resume paths update one authoritative Skill state consumed by
prompt projection, tool policy, resources, scripts and checkpoints.

## Method

Trace model `ActivateSkillTool`, programmatic/hook/intent
`ReactAgent::activate_skill`, `ToolRuntime::from_agent`, checkpoint save/resume,
and `ReadSkillResourceTool`/`RunSkillScriptTool` registry checks.

## Expected Result

One activation changes the same state observed by every current and future
invocation; resume restores that authority rather than only a projection.

## Result

- Exit code: 0
- Duration: not separately timed
- Summary: discovery copies descriptors into `tools.skill_registry` and
  `progressive_skill_registry`. Model activation mutates only the progressive
  registry and returns instructions as the tool result. Hook/intent/programmatic
  activation mutates only the catalog registry and writes a context projection.
  Snapshot merges both activation sets, but resource and script tools consult
  only the progressive registry. Checkpoint save snapshots the merged names;
  resume marks only the catalog registry. Thus a hook-activated or resumed Skill
  can appear active and restrict tools while its resource/script operations say
  it was never activated.
- Log/artifact: this report

## Deviations

Restored transcript messages may preserve prior instructions, but they do not
repair progressive registry state.

## Conclusion

Fails single-authority activation/recovery and supports `F-SKL-01-P1-01`.

## Follow-Up

Use one shared registry for descriptor and activation state; snapshots should
capture a generation/immutable view of that authority.
