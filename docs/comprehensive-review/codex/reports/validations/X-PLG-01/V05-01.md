## Claim

After plugin load, reload, disable or unload, Tool, Hook, Skill and Subagent
registrations should represent one current plugin generation in the primary
Agent, every existing pooled Agent and every future pooled Agent.

## Method

```text
1. Compare PluginRuntimeService state and mutation targets with
   AgentPool::SharedResources, from_runtime, refresh_skill_descriptors and
   create_agent.
2. Classify which registries are shared Arcs and which are per-Agent.
3. Search all callers of refresh_skill_descriptors and all plugin-runtime paths
   for AgentPool propagation.
4. Inspect removal behavior for descriptors absent from a replacement set and
   search pool construction for plugin Subagent registration.
```

## Expected Result

One application-owned generation update should reconcile source-owned
components in the primary Agent and all pool identities, including removal and
future construction.

## Result

- Exit code: 0
- Duration: static cross-owner trace; not timed
- Summary: the invariant fails. ToolManager and HookRegistry are shared Arcs and
  therefore see primary mutations. Pool Skill descriptors are a bootstrap
  snapshot; plugin runtime never calls pool refresh. The only production refresh
  caller is direct GUI Skill load/sync/enable, and its existing-Agent loop only
  registers the new list without removing absent descriptors. AgentPool neither
  shares nor reconstructs the primary SubagentRegistry, so plugin Subagents
  registered on the primary are absent from pooled Agents. Future pooled Agents
  continue to consume the pool's old descriptor snapshot.
- Log/artifact: this report
