## Claim

The single EKO plugin runtime is reachable from bootstrap and live mutation
surfaces, while its component targets can be traced to real Agent and service
consumers.

## Method

```text
Trace AgentRuntime::bootstrap -> PluginRuntimeService::new/reload, GUI and
headless AgentPool creation, scheduler binding, Tauri plugin commands and all
PluginRuntimeService mutation methods. Trace each prepared/wired component to
ReactAgent registries, shared ToolManager/HookRegistry, LspManager,
SchedulerRunner and presentation getters. Search AgentPool acquisition callers
in GUI chat, channels, scheduler, TaskRuntime and background services.
```

## Expected Result

Definitions should be registered once and mutation should affect every live
consumer that advertises the enabled plugin generation.

## Result

- Exit code: 0
- Duration: static call-graph inspection; not timed
- Summary: bootstrap loads plugins into the primary Agent before either GUI or
  headless pool construction. Tauri install/enable/disable/configure/reload/
  uninstall commands all call the same service. GUI conversations, channels,
  scheduler runs, TaskRuntime and background work acquire pooled Agents. The
  plugin service holds only the primary Agent handle, LSP handle, optional
  scheduler and registry state; it has no pool handle or pool update callback.
  Shared Tool/Hook mutations therefore propagate, while per-Agent Skill,
  Subagent and routing state does not share that reachability.
- Log/artifact: this report

## Deviations

This was a source reachability trace, not an executed surface scenario.

## Conclusion

Plugin lifecycle is live, not dead code, and its partial pool reach is a real
production boundary. This supports X-PLG-01-P1-01 and P1-02.
