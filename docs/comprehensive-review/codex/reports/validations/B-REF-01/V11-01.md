## Claim

Devin separates tool approval policy from OS sandbox enforcement and fails closed
when explicitly requested isolation cannot be established.

## Method

Read `https://docs.devin.ai/cli/reference/permissions.md` and
`https://docs.devin.ai/cli/sandbox.md`.

## Expected Result

Permission modes and sandbox roots/network filters are separate controls.

## Result

- Exit code: 0
- Summary: permission modes independently decide Auto/Prompt for read, fetch, shell,
  and edits; scoped allow/ask/deny rules apply precedence; `--sandbox` derives OS
  writable roots from workspace/grants, hides denied read paths, and refuses startup
  rather than silently running unsandboxed when sandbox resolution fails.
- Source URLs: `https://docs.devin.ai/cli/reference/permissions.md`, `https://docs.devin.ai/cli/sandbox.md`
- Access date: 2026-08-12

## Deviations

Devin explicitly labels sandbox network filtering unstable. Enterprise overrides and
cloud concerns are product-specific.

## Conclusion

Supports separate policy and enforcement layers, plus fail-closed behavior only when
the user/admin explicitly requested isolation. It does not justify gating unrelated
interactive desktop features.
