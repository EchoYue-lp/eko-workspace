## Claim

instead of retrying the whole deterministic orchestration by default.

## Method

sections of the official Workflow Execution documentation.

## Result

  the whole unchanged Workflow is discouraged; child execution start/result are explicit

- Source URLs: `https://docs.temporal.io/encyclopedia/retry-policies.md`, `https://docs.temporal.io/child-workflows.md`

## Deviations

Agent tool calls are not literally Temporal Activities. The supported inference is the
scope principle: retry the failure-prone operation/attempt and guard its committed output.

## Conclusion

Supports attempt identity, bounded retry policy, idempotence, and stale-attempt rejection
as generic mechanisms. It does not prescribe Temporal as an EKO dependency.
