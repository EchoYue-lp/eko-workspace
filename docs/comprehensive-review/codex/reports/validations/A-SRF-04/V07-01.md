## Claim

After a CLI or channel turn is admitted, its cancellation token remains
reachable from the surface until the turn settles.

## Method

```text
Trace cancellation token construction, clones, registries, user commands, and
turn await/spawn boundaries in CLI REPL and AppChannelMessageHandler. Inspect
ChannelHumanLoopProvider `/cancel` behavior separately from chat cancellation.
```

## Expected Result

Ctrl+C or a channel cancel command cancels the active Agent turn, propagates to
tools/Subagents/TaskRuntime, and yields one typed cancelled terminal.

## Result

- Exit code: not-applicable
- Duration: static inspection
- Summary: CLI creates the turn token inline in ChatResources at
  `src/cli/repl.rs:525-544` and then blocks rendering until the driver finishes;
  Reedline's Ctrl+C branch at `:239-241` is not active during that await.
  Channel creates a fresh token inside a detached producer at
  `src/cli/channels.rs:237-265` and stores no handle outside it. Channel
  `/cancel` is parsed only by `ChannelHumanLoopProvider` while a HITL request is
  pending (`echo-agent-app-core/src/hitl/channel_provider.rs:42-66,134`); with no
  pending request it is treated as a mode/chat input, not active-turn cancel.
- Log/artifact: this report

## Deviations

Formal TaskRuntime runs may later be cancellable by run ID through canonical
store APIs, but ordinary/Auto foreground turns and their pre-run tool work
still lose the surface cancellation handle.

## Conclusion

The claim fails and supports A-SRF-04-P1-03. This is an adapter ownership defect;
A-CHAT-01 remains canonical for what the driver/sinks do after cancellation.

## Follow-Up

Keep an active-turn registry keyed by full conversation/turn identity and add
CLI Ctrl+C plus channel cancel/disconnect races across chat/task/auto.
