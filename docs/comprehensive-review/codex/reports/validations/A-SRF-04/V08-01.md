## Claim

Headless startup retains all service cancellation owners and joins channel,
background, and scheduler loops before shared runtime teardown.

## Method

```text
1. Trace AppState task/scheduler tokens into services.
2. Trace what start_headless_services returns and what is dropped.
3. Search for task/scheduler cancel calls and join handles on every exit branch.
4. Inspect the combined --channels --cli branch and ChannelManager stop path.
5. Read SchedulerRunner from the clean HEAD blob because its worktree file was dirty.
```

## Expected Result

One process lifecycle owner cancels active work, awaits all service/channel
children, drains stores/hooks, then tears down pool/browser/runtime.

## Result

- Exit code: not-applicable
- Duration: static inspection
- Summary: `start_headless_services` creates a temporary AppState holding the
  root task/scheduler tokens, starts services, and returns only service Arcs
  (`src/cli/modes.rs:32-64`). AppState drops; no caller retains/cancels those
  root tokens. `BackgroundTaskService` exposes per-run cancel but no process
  shutdown/join; committed SchedulerRunner observes only its private token and
  returns no join handle. Main cleanup cancels the config watcher and shuts
  hooks/browser, but never cancels these service tokens. In combined
  `--channels --cli`, the channel JoinHandle is not awaited/aborted after REPL
  exit (`src/main.rs:365-405`), bypassing `run_channels_mode`'s
  `manager.stop_all` (`src/cli/modes.rs:228-232`).
- Log/artifact: this report

## Deviations

Channel-only Ctrl+C reaches `stop_all`, but still lacks background/scheduler
services. Runtime destruction will eventually abort Tokio tasks; that is not a
graceful, state-aware shutdown contract.

## Conclusion

The claim fails and supports A-SRF-04-P1-05. In-flight runs and channel sends can
be interrupted without ordered cancellation, terminal settlement, or resource
cleanup.

## Follow-Up

Introduce one headless lifecycle owner returning explicit cancel-and-join
handles; validate shutdown during chat, tool, HITL, cron fire, and background run.
