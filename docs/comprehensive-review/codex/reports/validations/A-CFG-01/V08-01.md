## Claim

Config persistence after a cwd/workspace transition can be executed in an
isolated fixture without accessing the real user-data config.

## Method

```text
env -u ECHO_AGENT_CONFIG CARGO_TARGET_DIR=/private/tmp/a-cfg-probe-target \
  cargo run --offline --quiet --manifest-path /private/tmp/a-cfg-probe/Cargo.toml -- \
  cwd-save /private/tmp/a-cfg-fixture-cwd-save
```

## Expected Result

Only files beneath the fixture should be considered.

## Result

- Exit code: 1
- Duration: less than 1 second
- Summary: `save_config` selected the already-existing real user-data config;
  sandboxing rejected the write with `Operation not permitted`.
- Log/artifact: none

## Deviations

The first probe process had not overridden the framework user-data root. No
real config was modified.

## Conclusion

This attempt is environmentally inconclusive, but it revealed that
`save_config` searches for any existing global file rather than retaining the
explicit startup source. The isolated retry is V08-02.
