## Claim

The framework production-module-to-test topology can be counted reproducibly
without treating raw test count as behavioral coverage.

## Method

```text
Enumerate committed `*.rs` blobs by package with `git ls-tree`; read each with
`git show`; count files, `#[test]`/`#[tokio::test]` attributes, cfg(test) files,
and root `tests/*.rs`. Separately inspect the two integration-test bodies.
```

The inventory identifies concentration and thin external seams while remaining
explicit that attribute counts are not runtime coverage.

## Deviations

Inline test attributes can include cfg-gated tests and say nothing about
assertion quality or actual CI execution. The count is topology, not coverage.

## Conclusion

The framework has substantial inline unit-test density but a very small
external integration layer. This supports the map and the sampling in V06; it
does not prove any test passes.

## Follow-Up

Use invariant-specific negative controls before crediting a count as coverage.
