## Expected

Events persisted before a Hook registry generation change should finish under
the old generation, or carry an explicit generation/snapshot. Reload must not
silently reinterpret already queued lifecycle events.

## Observed

The dispatcher queue preserves persisted event order, but each queued command
stores only an `EventTranslation`. On consumption its bridge reads the shared
HookRegistry at that later moment. Both config reload and plugin replacement can
clear/unregister/register Hooks in that shared registry without first calling
the already implemented `flush_hook_events`. The flush API is only exposed on
TaskRuntimeStore; production callers use shutdown at process exit.

An old persisted event can consequently execute a newly added Hook, skip a Hook
that was active when persisted, or observe a partially different plugin/user
generation. This supports `A-PLG-01-P1-03`. It does not claim event ordering
within one unchanged generation is broken; the single consumer preserves it.
