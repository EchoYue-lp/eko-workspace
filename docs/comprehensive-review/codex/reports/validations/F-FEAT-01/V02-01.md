## Claim

Facade features which gate examples also gate the corresponding public code or
dependency graph, and `full` includes every feature required by the package's
official examples.

## Method

From `echo-agent/`, inspect `src/lib.rs`, the facade adapters for memory,
sandbox, workflow, LLM providers, macros and multimodal wire types, and
normalized `packages[].targets[].required_features`. Compare dependency trees
for the six flags with `cargo tree -p echo_agent --no-default-features
--features <feature> -e features --depth 1`. Compute features and example
targets omitted from `full` using `jq` over Cargo metadata.

## Expected Result

Each example gate corresponds to a real capability gate, and `full` satisfies
all required-feature sets except any explicitly documented test-only target.

## Result

- Exit code: 0 for all inspection/tree commands
- Duration: about 1.3 seconds for the six tree comparisons
- Summary: all six feature dependency trees are identical; their APIs are
  already compiled without the flags (`src/lib.rs:54`, `:65`, `:111-117`,
  `src/llm.rs:105`, `src/memory.rs:42-47`). Ten examples are artificially gated
  by these flags. `full` omits seven flags (`macros`, `multimodal`,
  `provider-factory`, `sandbox`, `semantic-memory`, `testing`, `workflow`) and
  therefore does not satisfy 17 official example targets.
- Log/artifact: no external artifact.

## Deviations

`testing` has a real cfg effect and is not a no-op, but its omission still means
`full` cannot select six examples that declare it as required.

## Conclusion

The expected feature/example contract fails. This supports
`F-FEAT-01-P2-02` and `F-FEAT-01-P2-03`; compile-time selection is independently
confirmed by V18, V47 and V48.

## Follow-Up

Remove no-op gates or introduce actual capability isolation, then make `full`
semantics and example gates mechanically consistent.
