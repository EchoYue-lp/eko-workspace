## Claim

Every facade-owned optional dependency is used directly by facade code or
examples rather than redundantly mirroring an owner crate's feature dependency.

## Method

Read normalized optional dependency records and the root feature forwarding
map. Search `src/`, `examples/`, `tests/`, and `benches/` for direct Rust uses of
each optional crate, excluding references inside split crates. Compare each
zero-use dependency with the forwarded `echo_tools/<feature>` edge.

## Expected Result

An optional dependency enabled by a facade feature either has a direct facade
reference or is owned solely by the split crate implementing the capability.

## Result

- Exit code: 0
- Duration: under 1 second
- Summary: ten root optional dependencies have no direct facade-target Rust
  reference: `scraper`, `html2text`, `url`, `pdf-extract`, `lopdf`, `calamine`,
  `docx-rs`, `encoding_rs`, `polars`, and `sqlx`. Their root features also
  forward to `echo_tools`, whose own feature already enables the actual owner
  dependency. `rusqlite` is not in this set because `src/state/sqlite.rs` uses it
  directly.
- Log/artifact: no external artifact; manifest anchors are
  `Cargo.toml:81-89`, `:151-161` and `echo-tools/Cargo.toml:18-37`, `:56-76`.

## Deviations

Cargo unifies identical package versions, so this is redundant ownership and
feature coupling, not proof that two physical copies are always compiled.

## Conclusion

The claim fails for ten dependencies and supports `F-FEAT-01-P2-04`. The result
does not assess dependency advisories or version duplication outside this
feature boundary.

## Follow-Up

Retain only optional dependencies used by facade-owned code; owner crates should
remain authoritative for their implementation dependencies.
