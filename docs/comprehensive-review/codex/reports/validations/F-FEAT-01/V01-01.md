## Claim

Every declared framework feature has a corresponding cfg-controlled source
surface or dependency-forwarding effect, and every source cfg names a declared
feature in its owning package.

## Method

From `echo-agent/`, inspect normalized package feature maps with
`cargo metadata --no-deps --locked --format-version 1`, enumerate every
`feature = "..."` occurrence with `rg` under each package's Rust sources, and
compare declared names against cfg names package by package.

## Expected Result

No source cfg refers to an undeclared feature, and no non-meta public feature is
both dependency-empty and absent from source cfgs.

## Result

- Exit code: 0 for the inspection commands
- Duration: under 1 second per metadata/search invocation
- Summary: all cfg names are declared. Six facade features are empty and have
  zero Rust cfg references: `workflow`, `sandbox`, `semantic-memory`, `macros`,
  `provider-factory`, and `multimodal`. Cargo metadata reports 35 facade feature
  entries and 65 entries across all eight packages.
- Log/artifact: no external artifact; source anchors are `Cargo.toml:65-103`
  and `src/lib.rs:28-117`.

## Deviations

The six named features do not control source or dependencies. Meta-features
`default` and `full` were not treated as missing cfgs. Other empty facade
features do have source cfg effects and therefore are not classified as no-op.

## Conclusion

The reverse cfg-to-declaration mapping is sound, but the declared-to-effect
mapping fails for six facade flags. This supports `F-FEAT-01-P2-02`; it does not
prove runtime behavior of any feature-gated subsystem.
