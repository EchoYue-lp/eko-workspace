## Claim

Summary policies remain stable under repeated compression and retain recovery
facts and attachment identity, including empty or malformed LLM output.

## Method

```text
1. Trace Summary and IncrementalSummary partitions and second-pass inputs.
2. Inspect structured merge field semantics and natural-language fallback.
3. Trace empty successful LLM output through checkpoint and verifier.
4. Trace MessageContent::Parts attachments through prompts, summaries,
   verifier, eviction, and memory promotion.
```

## Expected Result

One canonical prior summary is updated rather than accumulated; empty summaries
fail closed; evicted attachments retain at least identity/retrieval metadata.

## Result

- Exit code: 0
- Duration: not recorded
- Summary: both summary compressors partition every system message out of the
  material being summarized. Their prior generated `[对话历史摘要]` is therefore
  retained forever and a new summary system message is appended each pass.
  IncrementalSummary additionally keeps private state, so its new merged summary
  coexists with all earlier summaries in the message buffer. A successful empty
  response becomes an empty checkpoint summary; verifier skips its
  `summary_not_empty` check. Old `Parts` attachments contribute only text parts
  to summary prompts and no file/image identity to verifier or promoter, so an
  evicted attachment can disappear without a recovery reference.
- Log/artifact: this report
