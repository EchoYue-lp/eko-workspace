# A-FE-03 / V04 / Attempt 01

> Status: failed/finding
> Validation date: 2026-08-13
> Executor: Codex primary reviewer

## Claim

Every frontend listener, timer, polling loop, and EventSource has one explicit
lifecycle owner and a paired cleanup or documented singleton contract.

## Method

Inventory all `setInterval`, `setTimeout`, and `addEventListener` sites and
sample task polling/EventSource, file/browser refresh, ChatInput focus hooks,
tool clocks, settings keyboard handling, and auth initialization.

## Expected Result

Repeated mount/unmount/module evaluation cannot duplicate background work, and
one subsystem is not polled independently by two owners.

## Result

- Exit code: 1 (invariant violated)
- Duration: static lifecycle inventory
- Most sampled component effects return cleanup: Task/EventSource, file/browser
  refresh, ChatInput focus listeners, settings Escape, and tool detail timers.
- Auth store import installs an anonymous focus listener and an interval with no
  retained handle/stop path. RequireAuth independently installs a second
  one-minute interval with its own lifecycle.
- This produces duplicate polling and an accumulation risk under module reload.

## Deviations

Short UI feedback timeouts were not upgraded to separate findings where they do
not retain external resources or subsystem authority.

## Conclusion

A-FE-03-P2-03 is confirmed; the broader lifecycle pattern is otherwise sound.

## Follow-Up

Create one root-owned, idempotent auth monitor with explicit stop and in-flight
coalescing.
