## Claim

Core overlays are named semantic dialogs, isolate/restore focus, label controls,
support keyboard operation, and fit narrow viewports.

## Method

Inspect command palette, settings, NewTaskDialog, and InterruptPromptDialog for
dialog/aria attributes, focus entry/trap/return, Tab/Escape handling, icon
labels, background inertness, and responsive width constraints. Search their
adjacent accessibility tests.

## Expected Result

Every overlay satisfies the same shared modal interaction contract and remains
fully usable at 320 CSS pixels and zoomed desktop sizes.

## Result

- Exit code: 1 (invariant violated)
- Duration: static accessibility/responsive inspection
- None of the four overlays declares `role=dialog`, `aria-modal`, or a named
  title association; none traps/restores focus or makes background content inert.
- CommandPalette focuses its input after an uncancelled timeout and handles
  keys only there. Settings handles global Escape only. NewTask and Interrupt
  implement no general keyboard modal lifecycle.
- Icon-only close controls lack accessible names in inspected paths.
- NewTaskDialog fixes width at 540px without a viewport max, causing narrow
  viewport overflow; Settings alone has an explicit small-screen layout.

## Deviations

No screen reader, accessibility engine, screenshot, or browser smoke test ran.

## Conclusion

A-FE-03-P1-04 is confirmed.
