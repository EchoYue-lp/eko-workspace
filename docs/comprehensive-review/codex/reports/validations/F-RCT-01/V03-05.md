## Claim

`AgentConfig.allowed_tools` applies uniformly to every tool registration surface, LLM schema, and execution path.

## Method

```text
Inspect AgentConfig allowed_tools contract (:54-55, :470-488), initial tool
registration in ReactAgent::new_inner, capabilities add_tool/add_tools/replace_tool,
Agent trait register_tool, builder custom-tool loop, AgentRunSnapshot filters, and
think::tools_for_request. Search every production read of config.allowed_tools.
```

## Expected Result

A nonempty allowlist is enforced at the request/execution choke point regardless of how a tool entered the registry.

## Result

- Exit code: 0.
- Duration: under one second per source slice.
- Summary: Only `add_tools(Vec)` reads the config allowlist. Initial core/builtin tools, `add_tool`, `replace_tool`, builder custom tools (which call `add_tool`), and trait `register_tool` bypass it. Snapshot LLM filtering includes disabled tools, skill allowlists, visibility, and plan mode, but not `AgentConfig.allowed_tools`; execution uses the same unfiltered manager.
- Log/artifact: this report.

## Deviations

Subagent invocation allowlists are a separate, functioning runtime policy and do not repair the root AgentConfig contract.

## Conclusion

Supports F-RCT-01-P1-03: the documented root allowlist cannot guarantee that only listed tools are exposed or called.

## Follow-Up

Centralize the root allowlist at snapshot/execution authority and delete registration-method-specific filtering.
