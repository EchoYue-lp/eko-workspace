## Expected Result

An injected memory store prevents only default-store creation; the resulting config still reports memory enabled because store, memory tools, promotion, and recall are live.

## Result

- Exit code: 0.
- Duration: under one second per search/slice.
- Summary: Builder first enables memory, then forcibly rewrites config to false to skip FileStore and injects the external store afterward. The resulting agent has memory tools/store and recall reads the store, but `config().is_memory_enabled()` is false. Existing builder test checks only store presence; the CLI config response exposes this false flag. App-core comments explicitly depend on this rewrite.
- Log/artifact: this report.

## Deviations

This is a state-truthfulness issue; automatic recall itself is store-driven and remains reachable.

## Conclusion

Supports F-RCT-01-P2-06: construction overloads one boolean with “create default store” and “memory capability enabled.”

## Follow-Up

Separate default-store policy from capability state and add a field-level construction assertion.
