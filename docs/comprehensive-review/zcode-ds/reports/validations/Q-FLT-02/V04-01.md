## Claim

A timed-out or cancelled Team dispatch must stop its members; a reported
failure must not coexist with live member execution. The current Team path
violates this: `TeamAgent::execute_with_usage` wraps `execute_inner` in
`tokio::time::timeout` (`echo-agent/src/agent/subagent/team/mod.rs:343-353`),
and `ManagerSubagentOrchestrator::execute_sub_tasks` spawns members with
`tokio::spawn` holding `JoinHandle`s in a local `Vec`
(`echo-agent/src/agent/subagent/team/manager_subagent.rs:277-284`) — on
timeout the outer future is dropped, the vec is dropped with it, and the
spawned member tasks keep running (detached). Timeout classification relies on
string matching (`executor.rs:1082-1084`).

## Method

Standalone tokio probe (`/tmp/qflt02-probe/src/bin/s4_team_timeout_detach.rs`)
that mirrors the exact pattern: 3 "member" tasks (1.5 s work, increments a
shared counter on completion) spawned via `tokio::spawn` with handles in a
local `Vec`, wrapped in `tokio::time::timeout(400 ms)` (CASE A — current Team
code). Contrast CASE B: the same members in a `JoinSet` with `abort_all()`
after 400 ms (what cancellation should do).

Static side: `team/mod.rs:343-353` timeout wrapper; `manager_subagent.rs:
277-284` spawn pattern; `executor.rs:1082-1084` string-match classification;
zero `CancellationToken` in `team/` (F-SUB-02 V01-01 grep).

## Expected Result

CASE A: the timeout reports failure at ~400 ms while all 3 members still
complete at ~1.5 s (detached execution). CASE B: abort_all stops members
immediately (0 completions).
