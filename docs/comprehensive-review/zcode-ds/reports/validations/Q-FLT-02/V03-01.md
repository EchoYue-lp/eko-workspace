## Claim

A pause issued while a wave is in flight must be durable and resumable; the
framework must not convert it into a permanent cancellation. The current code
violates this: the in-wave cancel branch hardcodes `Cancelled`
(`runtime_executor.rs:390-416, :416`), `interruption_outcome` is consulted
only at loop top / cancelled-task check / external-poll
(`runtime_executor.rs:207-209, 267-269, 278-281`), and EKO's
`finalize_cancelled_run_state` force-transitions the durably-Paused run to
Cancelled (`executor.rs:643-661`, legal per `types.rs:522`
`Paused => Running | Cancelled`).

## Method

Standalone probe (`/tmp/qflt02-probe/src/bin/s3_pause_cancel.rs`) driving the
real store: register the run-scoped driver token, transition Running, claim
t1, call `request_pause` while the task is in flight, then show (a) the pause
lands durably (run Paused, token cancelled — the exact signal the framework
in-wave branch reacts to), (b) the `Paused -> Cancelled` regression transition
is legal per the state machine, (c) the finalize write flips the task, (d)
replay preserves the Paused-then-Cancelled sequence, (e) resume is impossible
after the regression (`Cancelled` is hard-terminal).

Static side: framework wave-cancel branch and EKO outcome mapping
(`executor.rs:499-508` Cancelled branch -> `finalize_cancelled_run_state`).

## Expected Result

Either the run stays Paused and resumable (invariant), or the probe
demonstrates the deterministic regression chain with the exact legal
transition. Given the code under test, the latter is expected.
