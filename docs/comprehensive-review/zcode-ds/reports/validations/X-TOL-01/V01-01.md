## Claim

One tool invocation carries the same field set and identity through all four
layers — framework Tool schema/result (`echo-agent`), EKO execution projection
(`ToolExecutionRepository`), Rust/Tauri surface (commands and emitted
payloads), and TypeScript rendering (store + `InlineToolCall`) — field for
field, without loss or renaming.

- All `ToolExecutionSummary` fields (id, call_id, owner, conversation_id,
  run_id, name, args_preview, status, started_at, finished_at, duration_ms,
  detail_ref) appear identically in the TS `ToolExecution` interface.
- `ToolExecutionDetailManifest` (id, args_full, status, failure, metadata,
  truncated, output_bytes) and `ToolExecutionDetailPage` (chunks, next_cursor,
  complete) match 1:1.
- `call_id` survives from the LLM tool call through `execution_key` to the
  store row and renderer.
- `failure: Option<ToolFailure>` (framework type) is preserved in the manifest
  at layer 2 and 3, and the TS `ToolFailure` interface covers all seven
  `ToolFailureCategory` values plus recovery/side_effect/retry_after_ms/
  idempotency_key/postcondition.

## Deviations

- The collapsed GUI row and TUI header show only the 4-way `status`; the
  7-way `ToolFailureCategory` is visible only in the GUI expanded detail and
  the TUI metadata label. Recorded as an intentional projection, not a field
  loss — the taxonomy field itself survives (see V02-01 for the kill-path
  exceptions).
- `ToolExecutionDetailManifest.metadata` served to the frontend has
  `artifact_path` removed (tool_execution.rs:400-401) while the sha256/bytes
  keys survive; deliberate scoping, recorded in V03-01.
- Live-path identity keying by `detail_ref` instead of (owner, call_id) and
  the double producer are the canonical A-FE-02-P2-01 / A-SRF-02-P2-01
  defects (see V05-01); field names themselves map 1:1.

## Conclusion

This execution supports: the normal-path field mapping between the framework
Tool result/event schema, the EKO execution projection, the Tauri wire shape,
and the TypeScript store/renderer is 1:1 with stable identity (`call_id`) and
no renames or drops. It does not prove runtime behavior of the kill paths
(timeout/cancel/partial side effects) — those are the subject of V02-01 and
the canonical framework findings listed in V05-01.
