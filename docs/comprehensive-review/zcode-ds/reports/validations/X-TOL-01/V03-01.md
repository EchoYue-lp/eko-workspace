## Claim

Long tool output is spilled to a complete artifact with a SHA-256 checksum,
size, and retention at the framework layer; the checksum and size metadata
survive through the EKO execution projection to the frontend; and every
cursor-based read path (framework `read_artifact`, EKO detail paging) is
bounded, UTF-8-safe, and complete-flagged.

## Method

Static trace of the long-output path:

1. Framework spill: `echo-core/src/tools/artifact.rs` —
   `ToolOutputArtifactWriter` (`:145-293`) computes `Sha256` incrementally
   (`hasher`, `:152,184,241`), tracks `artifact_bytes` (raw with channel
   labels) and `payload_bytes` (content only), `finish()` renames
   `.partial` -> final and returns `ToolOutputArtifactRef {path,
   artifact_bytes, payload_bytes, sha256, retention}` (`:91-98,215-235`);
   `extend_metadata` inserts `artifact_kind/media_type/status/path/bytes/
   payload_bytes/sha256/retention` (`:100-119`); `from_metadata` round-trips
   (`:121-142`); threshold 1 MiB default (`:16`).
2. Framework insertion point: `src/agent/snapshot.rs:926-1060`
   `process_tool_output_for_call` (spill + bounded preview) and
   `TruncationStage` (`src/agent/react/run/pipeline.rs:716-749`);
   `ToolResult.metadata` then carries the artifact keys; GUI sink captures
   `result.metadata` at `ToolStreamEvent::Complete`
   (chat.rs:1254-1260; subagent path chat.rs:1040-1048).
3. EKO projection: `tool_execution.rs:292-358` `finish()` — reads
   `artifact_path` from metadata to decide not to duplicate the preview into
   the JSONL (`artifact_available`, `:312-330`); `read_output :413-450` reads
   the artifact file via `read_artifact_page :720-748` when the JSONL is
   empty; `detail_manifest :394-411` serves metadata with `artifact_path`
   REMOVED (`:401`) but sha256/bytes retained; `output_bytes` served from
   `manifest.output_bytes` (`:409`).
4. Cursor paging: `read_jsonl_output_page :677-718` (byte cursor at line
   boundaries, `next_cursor` = `stream_position()`, `complete` only when
   terminal), `read_artifact_page :720-748` (byte cursor, `utf8_page_prefix`
   `:750-768` drops up to 3 trailing bytes to stay on a char boundary),
   `parse_cursor :668-675` (invalid cursor -> `InvalidCursor` error).
   Tests: `artifact_pages_end_on_utf8_boundaries` (tool_execution.rs:956-978),
   `complete_output_is_read_in_pages` (`:851-887`).
5. Frontend: `InlineToolCall.tsx:61-118` paging loop (detail + readOutput,
   `next_cursor`, `complete`), `:244-258` "加载更多" button when not
   complete, `:204-207` `formatBytes(manifest.output_bytes)` +
   truncated marker; `types/api.ts:95-116` (`ToolExecutionDetailManifest`
   metadata/truncated/output_bytes; `ToolExecutionDetailPage` cursor/complete).
6. Framework cursor contract (model-facing): `read_artifact` tool +
   pagination cursor (F-EXT-01 V03-01, dependency report, re-read not needed)
   — fingerprint-bound opaque cursors; EKO byte-cursor is a separate surface.

## Expected Result

- The same SHA-256, byte counts, and retention string produced by the
  framework writer reach the EKO manifest and the frontend metadata display.
- The GUI's byte-count label (`输出 · N B`) reflects the artifact size for
  spilled outputs.
- Every page boundary falls on a UTF-8 character boundary; cursors are
  stable across pages; `complete` is accurate.

## Result

- Exit code: not-applicable (static trace; existing tests recorded below)
- Duration: not-applicable
- Summary:
  - Checksum survival: `artifact_sha256`, `artifact_bytes`,
    `artifact_payload_bytes`, `artifact_retention`, `artifact_status` are
    inserted into `ToolResult.metadata` by `extend_metadata`
    (artifact.rs:100-119), captured by the GUI sink
    (chat.rs:1254-1260 / chat.rs:1040-1048), persisted in the manifest
    metadata (tool_execution.rs:342), and served to the frontend
    (detail_manifest keeps all metadata except `artifact_path`,
    tool_execution.rs:400-401). The frontend renders the metadata verbatim
    (InlineToolCall.tsx:219-228). The checksum therefore survives all four
    layers unchanged.
  - Cursor integrity: byte-cursor paging is line-boundary based for JSONL
    (`next_cursor` after whole lines, tool_execution.rs:689-711) and
    char-boundary safe for artifact pages (`utf8_page_prefix`,
    tool_execution.rs:750-768); `complete` is only true when terminal and
    end reached; the frontend loop follows `next_cursor` and stops at
    `complete`. Existing tests pin UTF-8 boundaries (tool_execution.rs:956-978)
    and full read (tool_execution.rs:851-887); dependency reports record
    those suites green (A-TOOL-01 V04-01/02, F-EXT-01 V04).
  - Deviation 1 (finding X-TOL-01-P3-01): `ToolExecutionDetailManifest
    .output_bytes` is never updated from the artifact metadata. `finish()`
    only increments `output_bytes` when it appends the result to the JSONL
    (`!has_output && !artifact_available`, tool_execution.rs:316-330); when
    the artifact was spilled, `artifact_available` is true, so
    `output_bytes` stays 0 (or the streamed-bytes count). The GUI then shows
    "输出 · 0 B · Agent 上下文已截断" (InlineToolCall.tsx:204-207) for a
    multi-megabyte artifact, while `metadata.artifact_bytes` carries the
    true value. Content integrity itself holds (full artifact readable by
    paging), so this is a size-reporting honesty defect.
  - Deviation 2 (finding X-TOL-01-P3-02): for a FAILED tool that streamed
    output, the `result` argument of `finish()` (the `ToolError.error`
    text) is not persisted either — the append is skipped when
    `has_output` is true (tool_execution.rs:316). The detail file contains
    the streamed stdout/stderr but never the error message; the GUI shows
    only `failure.category · recovery` (InlineToolCall.tsx:214-218). The
    model-facing context does get "[Error] ..."
    (phases/tools.rs:252-256), so the loss is confined to the EKO GUI
    projection.
  - `artifact_path` removal from the served manifest (tool_execution.rs:401)
    is deliberate (absolute paths not exposed to page JS); the model-facing
    path survives via the framework context metadata. Recorded, not a
    finding.

## Deviations

- No dynamic end-to-end run of a real >1 MiB spill through the GUI was
  executed (read-only review; no fixture in source); the two deviations
  above are verified statically at the exact code sites.
- The framework `read_artifact` cursor contract was re-used from F-EXT-01
  V03-01 (dependency report) without re-inspection.

## Conclusion

This execution supports: checksum and artifact metadata survive all four
layers unchanged; cursor paging is bounded, UTF-8-safe, and complete-flagged;
two projection defects exist — `output_bytes` underreporting for spilled
artifacts (X-TOL-01-P3-01) and loss of the failure message text from the GUI
detail when the tool streamed output (X-TOL-01-P3-02).
