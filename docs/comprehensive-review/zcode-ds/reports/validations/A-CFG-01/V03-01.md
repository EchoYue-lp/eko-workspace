## Claim

The required invariant/edge-case families hold: (a) config precedence and
path map are consistent between inventory, loader, watcher, and docs;
(b) invalid/partial config degrades explicitly, not silently; (c) workspace
switch fully replaces workspace-scoped state; (d) restart-required vs live
reload is coherent across surfaces.

Static inspection of the exact code paths, cross-checked against existing
tests (test inventory for the modules below), plus the A-CFG-01 task-card
required fixtures. No process was launched; all behavior claims are traced
code chains (V04 runs the existing unit suites).

## Expected Result

(a) All four path authorities agree; (b) invalid config is reported and
partial config is unambiguous; (c) switch replaces every workspace-scoped
store and exit restores the global scope including CWD; (d) every
restart-required domain is documented consistently and no live path silently
claims to have applied a setting it did not.

## Result

- Exit code: not-applicable (static inspection; existing unit suites run in V04)
- Summary of observed deviations from the invariants:
  - (a) FAILS: inventory says global agent config is `~/.eko/echo-agent.yaml`
    (config_discovery.rs:221) while the loader reads `~/.eko/config.yaml`
    (config.rs:674 via user_data_path); docs claim `~/.echo-agent/config.yaml`
    and a nonexistent `./.echo-agent/echo-agent.yaml`
    (docs/configuration.md:8-10); inventory marks per-workspace
    `.workspace.json` as `ConfigScope::Global` (config_discovery.rs:374);
    inventory documents project hooks at `<project-root>/.eko/hooks.yaml`
    (config_discovery.rs:280) while loader and watcher use `<cwd>/.eko/hooks.yaml`
    (hook_config_loader.rs:184-185, config_watcher.rs:205-207).
  - (b) PARTIAL: malformed YAML on the explicit path falls back to
    `AppConfig::default()` with an error log (config.rs:733-737); on search
    paths it warns and continues (config.rs:748-750). Unknown/misspelled keys
    are silently ignored (`#[serde(default)]`, no `deny_unknown_fields`).
    No unit test covers the malformed-file fallback (existing tests:
    `test_load_config_no_file`, `test_load_config_honors_echo_agent_config_env`).
    `save_config` targets `./echo-agent.yaml` (cwd) when no file exists
    (config.rs:694-699) and every GUI persist call ignores the error
    (warn-only), while the UI reports "已保存" (ConfigPanel.tsx:68).
  - (c) FAILS: switch replaces conversations/memory/checkpoints but NOT the
    TaskRuntimeStore (global `~/.eko/tasks` shadow, file_shadow.rs:83-85) and
    NOT the hook registry or config watcher targets; `tasks_db_path`
    (state.rs:1197) is dead. exit_workspace never restores process CWD
    (state.rs:854 chdirs, :1053-1185 does not).
  - (d) PARTIAL: watcher scope doc (config_watcher.rs:5-11) matches watcher
    behavior (hooks/webhooks live; model/MCP not reloaded by the watcher),
    but the doc justification "wired into long-lived subsystems at agent
    construction" contradicts the live model application on GUI
    (providers.rs:113-115) and TUI (tui/events.rs:2721-2723). ConfigPanel
    max_iterations "sync" (ConfigPanel.tsx:52-66) is ineffective —
    `update_config` applies only system_prompt (config.rs:132-141) and
    `update_full_config` never applies max_iterations to the live agent or
    pool; pooled agents never receive ConfigPanel saves at all.
  - Window path (cross-check of F-CTX-01-P1-01): boot window = hardcoded
    396_000 (infra.rs:23, :215-219, :258-262); model-config inference
    (`effective_context_window`, model_config.rs:153-159) is GUI-view-only;
    GUI/TUI switch applies `context_window` → token_limit live
    (providers.rs:113-115, tui/events.rs:2721-2723) — same model gets 396K at
    boot and its configured window after a switch. `DEFAULT_CONTEXT_WINDOW`
    duplicated (infra.rs:23, model_config.rs:6).
