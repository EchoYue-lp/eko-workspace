## Claim

Reload/unload drops removed plugins exactly; the hook queue (task-runtime
`HookEventDispatcher`) has explicit flush/shutdown semantics; plugin lifecycle
events and user-hook reloads are coherent with unload; EKO skill enablement
is a coherent lifecycle authority over the runtime.

## Method

Static inspection of `fire_loaded_events`/`fire_plugin_disabled`
(plugin_runtime.rs:1048-1096, call sites :256/:337/:790), `unload_agent_components`
(:1157-1176), `HookEventDispatcher` (tasks/task_runtime/hook_event_dispatcher.rs:
1-130), shutdown call sites (main.rs:330/:395), user-hook reload surfaces
(hook_config_loader.rs, config_watcher.rs:227-278, tauri/commands/hooks.rs:
122-174, tui/events.rs:3500-3527, cmd_impls/hooks.rs), and the GUI/CLI skill
enable/disable surfaces (panels.rs:459-660, cmd_impls/skills.rs).

```text
1. reload() -> apply_candidate: dropped plugins are unloaded via
   unload_agent_components (previous set) but `PluginDisabled` is fired only
   from disable()/uninstall(); fire_loaded_events fires `PluginLoaded` for
   EVERY candidate plugin on EVERY successful apply.
2. HookEventDispatcher: bounded sync channel (cap 256), Flush = FIFO barrier,
   Shutdown = drains + stops consumer thread; store.flush_hook_events /
   store.shutdown_hook_events (store.rs:247/:261); session-end call sites
   main.rs:330/:395. Plugin lifecycle events (PluginLoaded/PluginDisabled/
   ConfigChange/SessionStart) are fired inline via run_lifecycle_hooks — no
   queue involvement.
3. Skill hub: enable_skill (panels.rs:592-632) loads skill_path.parent() into
   the agent + persists enabled-skills.json; disable_skill (panels.rs:635-660)
   persists only, returns requires_restart; CLI sync (skills.rs:61-71) and GUI
   sync (panels.rs:525-534) call load_skills_from_dir(hub root) after sync.
```

## Expected Result

Removed plugins trigger the same lifecycle notifications as disable/uninstall;
the hook queue flush/shutdown is explicit and idempotent; per-skill
enablement in the hub reflects runtime activation one-to-one and can be
reverted in-session.

## Result

- Exit code: not-applicable (static inspection; queue semantics dynamically
  covered by V04-03 `flush_and_shutdown_are_explicit_and_idempotent` +
  `bounded_queue_applies_backpressure_without_dropping`)
- Summary:
  - Reload/unload of registrations is exact (unload_agent_components keys
    symmetric with wire_all registration keys; V03-01).
  - Hook queue flush/shutdown: verified — bounded 256 queue, Flush is a FIFO
    barrier, Shutdown prevents new sends, drains prior events, idempotent;
    session-end callers in main.rs. Plugin lifecycle events are not queued
    (inline), which is consistent with their synchronous, mutation-scoped
    nature.
  - Deviations (promoted to findings):
    1. A reload that drops a plugin (deleted dir / invalid manifest) fires no
       `PluginDisabled` lifecycle hook, while every successful reload re-fires
       `PluginLoaded` for all candidate plugins (including unchanged ones) —
       duplicate notifications and missing drop notification — finding P3-01.
    2. GUI `enable_skill` loads the skill's PARENT directory, activating all
       sibling skills (flat layout: the whole `~/.eko/skills` root); GUI
       `disable_skill` has no in-session unload (restart-required, honest);
       re-enable after a content update is a silent no-op per F-SKL-01-P2-01 —
       hub enablement is not a reversible runtime lifecycle authority —
       finding P2-02.

## Conclusion

Supports: registration unload and the task hook queue are correct and tested;
the remaining lifecycle incoherences are event notification asymmetry
(P3-01) and the hub's non-reversible, directory-granular enablement (P2-02),
plus the workspace/plugin interplay (P1-01, V02-01/V03-01).
