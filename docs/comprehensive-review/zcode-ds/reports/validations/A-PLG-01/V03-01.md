## Claim

Prepare/activate ownership is clean (application prepares, framework activates,
no second state machine); real component registration reaches the live agent;
failed activation/wiring rolls back to the previous live set; EKO-owned
component preparation is validated before any live mutation.

## Method

Static inspection of `apply_candidate` (plugin_runtime.rs:551-802),
`replace_agent_components` (:804-909), `prepare_application_components`
(plugin_components.rs:96-222), `register_plugin_agents`
(plugin_components.rs:444-476), `validate_agent_collisions`
(plugin_runtime.rs:911-944), and `unload_agent_components` (:1157-1176),
plus the framework `wire_all` (echo-agent/src/plugin.rs:128-395) and the
dynamic tests in plugin_runtime.rs:1484-1883.

```text
1. Ownership split: prepare_application_components (EKO) parses agent/LSP/
   monitor/theme/style files and detects duplicates; wire_all (framework)
   loads skills/hooks/MCP; register_plugin_agents (EKO) registers subagent
   def+factory; lifecycle.activate_enabled (framework manager) runs after.
2. Ordering: resolve deps -> prepare (EKO) -> collision check -> prepare LSP
   (EKO, starts servers) -> deactivate_all -> replace monitors -> swap ->
   unload prev / wire candidate / register agents -> swap LSP -> activate.
3. Failure paths: deactivation fail (:575-588), monitor fail (:591-604),
   wiring fail (:822-842), agent-register fail (:844-867), activation fail
   (:655-719) — each restores the previous registry/framework/prepared set
   and reactivates the previous lifecycle.
4. Boot path: new_with_source (:144-178) runs reload() and warn-only on error.
```

## Expected Result

Each failure mode leaves the previous live components (skills/hooks/MCP/
subagents/monitors/LSP/theme/output-style) intact and restores lifecycle
callbacks; ownership is split exactly at framework-vs-application boundaries.

## Result

- Exit code: not-applicable (static inspection) — dynamic confirmation in
  V04-01 (8 plugin_runtime tests, incl. `activation_failure_restores_previous_components_and_lifecycle`,
  `failed_real_reload_restores_previous_live_components`,
  `real_plugin_load_disable_and_unload_are_live`).
- Summary:
  - Ownership split verified clean: EKO prepares application-owned components
    (agents/LSP/monitors/themes/styles) and registers subagents; framework
    wires skills/hooks/MCP; `PluginLifecycleManager` owns callback
    activate/deactivate. No second dependency resolver, no second state
    machine, no second validator in EKO.
  - Real component registration reaches the live agent: plugin skills tagged
    in both skill registries (capabilities.rs:719-730), hooks under
    `HookSource::Plugin`, subagent def+factory in the shared registry,
    monitors in the bound scheduler, LSP in the shared manager — asserted
    live in the dynamic tests.
  - Failed activation rollback is real and tested: a theme change + injected
    lifecycle failure restores the previous theme colors, previous LSP
    servers, and previous lifecycle counts (V04-01).
  - `validate_agent_collisions` runs before mutation; collision detection
    excludes the previous plugin set (own replacement allowed).
  - `unload_agent_components` swallows per-item errors (`let _`), but the
    underlying APIs return bool/Vec and their failure modes are benign
    not-found cases (unregister_subagent capabilities.rs:406-424,
    unregister_skills_by_source :915, disconnect_mcp :1315) — not promoted.
- Deviations (promoted to findings):
  1. Boot path: `new_with_source` treats ANY reload error as total plugin-set
     failure with warn-only logging — one broken enabled plugin silently
     disables ALL plugins at startup (no per-plugin isolation, no rollback
     target, no UI notice) — finding P2-01.
  2. Workspace switch never invokes any plugin-runtime path; project-scope
     plugin components remain live and LSP root stays boot-frozen — finding
     P1-01.
