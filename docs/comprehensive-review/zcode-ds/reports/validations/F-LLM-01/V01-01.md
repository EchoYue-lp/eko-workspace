## Claim

The provider-neutral LLM contract is fully inventoried: `LlmClient` method
list, `ChatRequest`/`ChatResponse`/`ChatChunk` field lists, tool
definition/call representation, thinking/reasoning representation, and the
serde behavior of each wire type (rename / skip_serializing_if / default /
custom impls) contain no unexamined loss path. A duplicate-search for
parallel semantic authorities is performed.

   ChatResponse, ChatChunk, SimpleChatOptions) in full.

## Expected Result

Single authoritative definition per concept; every serde attribute that can
lose information is identified; `extra`/dead-contract claims verified by
grep, not by reading.

## Result

- `LlmClient` methods (`echo-core/src/llm/mod.rs:53-107`): `chat`,
  `chat_stream`, `chat_simple`, `chat_simple_with_options`, `model_name`,
  `capabilities`.
- `ChatRequest` (`mod.rs:149-183`): messages, temperature, max_tokens,
  tools, tool_choice (raw String), response_format, thinking, cancel_token,
  user_id, cache_hints — all `Option` except messages.
- `ChatResponse` (`mod.rs:202-210`): message, finish_reason, raw
  (`ChatCompletionResponse`).
- `ChatChunk` (`mod.rs:233-241`): delta (DeltaMessage), finish_reason,
  usage (Option<Usage>).
- Tool representation: request side `ToolDefinition{type,function:
  FunctionSpec{name,description,parameters:Value}}` (`types.rs:583-601`);
  call side `ToolCall{id,type,function:FunctionCall{name,arguments}}`
  (`types.rs:450-469`); streaming deltas `DeltaToolCall{index,id,type,
  function{name,arguments}}` (`types.rs:850-874`).
- Thinking/reasoning: `ThinkingConfig{Disabled|Level|BudgetTokens}`
  (`thinking.rs:43-59`), `ThinkingLevel` (`:232-246`), `ThinkingProtocol`
  (9 variants, `:269-296`), request wire fields reasoning_effort /
  enable_thinking / thinking_budget / glm_thinking
  (`types.rs:548-566`), response side `reasoning_content`
  (`types.rs:250-251`, `DeltaMessage.reasoning_content` `:842-843`).
- Serde loss audit:
  - `MessageContent::deserialize` (`types.rs:69-88`): non-string,
    non-array JSON silently maps to `Empty`; an array containing an
    unsupported part type fails `from_value` and also maps to `Empty`
    (whole content lost, no error).
  - `Message` custom impl (`types.rs:254-315`): `content` omitted when
    Empty and no tool_calls (else `null`); round-trips. `Role::Custom`
    round-trips (`:189-200`).
  - `ChatCompletionResponse.extra` (`types.rs:635-637`): `#[serde(default,
    skip_serializing_if="Option::is_none")]` binds only a literal `"extra"`
    key; no `#[serde(flatten)]` catch-all; repo-wide grep shows zero
    readers/writers of `.extra` on this type. Unknown provider fields are
    dropped during `post()` deserialization (`client.rs:163-164`) despite
    `ChatResponse.raw` doc "Raw provider response for callers needing extra
    metadata" (`mod.rs:209`). → F-LLM-01-P2-01.
  - `ChatCompletionChunk` (`types.rs:788-799`): Deserialize-only, all fields
    defaulted; lacks `model`/`created` that `ChatCompletionResponse` has
    (minor asymmetry, no finding).
  - `Usage` normalization helpers (`types.rs:686-772`): effective_*/cached_*/
    cache_hit_rate with Anthropic-vs-OpenAI/DeepSeek detection by field
    presence; all `Option` + `#[serde(default)]` — no loss.
  - `ThinkingConfig` serde (`thinking.rs:43-59`): lowercase tag +
    `budget_tokens` rename; round-trip ok (no serde test, inferred).
  - `ToolChoice` (`mod.rs:114-125`): no serde derive (in-memory only) — no
    wire loss; wire value is the untyped `ChatRequest.tool_choice: String`.
- Duplicate/parallel search:
  - `ThinkingProtocol` (echo_core, drives `translate_thinking_openai_compat`
    via `ModelProfile::new`) vs `ThinkingProtocolPreference`
    (`echo-integration/src/providers/traits.rs:95-107`): two enums for the
    same concept. `ThinkingProtocolPreference` has zero uses outside
    traits.rs; `ProviderAdapter::thinking_protocol()` (:47-49) and
    `drops_temperature_on_thinking()` (:52-57) are never called by
    `AdapterClient` (adapter_client.rs:76-82,131-137 always call
    `translate_thinking_openai_compat`). → F-LLM-01-P2-03.
  - `ProviderAdapter`/`AdapterClient`: zero `impl ProviderAdapter` and zero
    `AdapterClient::new` call sites in `echo-agent` or `echo-agent-cli`
    (grep over both repos); re-exported as public API
    (`providers/mod.rs:10`, root `src/llm.rs:64-66`). Dead contract.
  - `cache_hints`: consumed only by the Anthropic adapter
    (`anthropic.rs:165-188` via `anthropic_cache.rs`); OpenAI-compatible
    adapters (openai.rs:292-310, adapter_client.rs:138-157) drop it at the
    boundary (used only for loop-side fingerprinting/logging).

## Deviations

`chat_simple`'s `unwrap_or_default()` on content (`mod.rs:93`) and the
`AgentEvent`-level usage accounting were verified as documented behavior,
not loss. No compile executed in this validation (V04 covers execution).

## Conclusion

Supports: complete inventory of the neutral contract; one dead/duplicate
provider contract (`traits.rs` + `adapter_client.rs`) with a parallel
thinking-protocol enum; one misleading "raw" API whose `extra` field is
never populated. Supports findings F-LLM-01-P2-01 and P2-03.

Does not prove: streaming behavior (V02), usage authority flow (V03),
or test behavior (V04).
