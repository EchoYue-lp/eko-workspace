## Claim

Usage/cache accounting has a single authority — provider-reported usage —
and the contract signals "provider did not report usage" explicitly
(`AgentEvent::LlmUsage.usage_reported = false`, per F-CORE-01 V01) on every
runtime path that consumes LLM responses.

## Method

1. Read `AgentEvent::LlmUsage` definition and doc
   (`echo-core/src/agent/mod.rs:157-177`): "When `usage_reported` is false,
   the provider or gateway did not return usage metadata; callers must treat
   cache fields as unknown instead of a zero-percent cache hit."
2. Traced all `AgentEvent::LlmUsage` construction sites (grep across
   `echo-agent/src`, `echo-core`, `echo-integration`, `echo-execution`):
   `src/agent/react/run/phases/think.rs:201`, `run/stream_channel.rs:466`,
   and consumer `src/agent/subagent/executor.rs:1253`.
3. Checked `usage_reported` derivation at each site:
   `think.rs:147` (`last_usage.is_some()`), `stream_channel.rs:427`
   (same), and the normalization used (`effective_prompt_tokens`,
   `cached_prompt_tokens`, `cache_creation_prompt_tokens`, types.rs:686-772).
4. Checked the non-streaming paths: `src/agent/react/run/react_loop.rs:100`
   (`call_llm_with_retry` returns `response.raw.usage`), `:763-813`
   (`direct_answer` — trace + token_tracker only), and
   `src/agent/react/run/context.rs:734` (`pre_compaction_flush` via
   `llm_client.chat`).
5. Cross-checked cache request-side authority: `ChatRequest.user_id`
   (KVCache isolation, mod.rs:176-179), `cache_hints`
   (mod.rs:180-182, consumed only by Anthropic adapter), `CachePolicy`
   (capabilities.rs:496-571).

## Expected Result

Every LLM call path that consumes provider usage surfaces it through
`AgentEvent::LlmUsage` with `usage_reported` reflecting presence/absence;
no path silently drops a reported usage.

## Result

- Authority is provider usage, normalized in `echo_core::llm::types::Usage`
  (types.rs:686-772) with provider-family detection by field presence
  (Anthropic cache fields vs OpenAI/DeepSeek inclusive totals). Consistent
  with MASTER-PLAN M9 ("provider usage 是记账权威").
- Streaming main path (think.rs) and DirectAnswer streaming path
  (stream_channel.rs) both emit `AgentEvent::LlmUsage` with
  `usage_reported = last_usage.is_some()` — contract honored.
- **Gap: `direct_answer` (`react_loop.rs:763-813`) and the structured-output
  path (`react_loop.rs:100-102`) record usage only into
  `RunEvent::LlmCall` trace + token_tracker; they never emit
  `AgentEvent::LlmUsage`.** Consumers that aggregate usage from events
  (subagent executor:1253 → `DispatchLlmUsage`, EKO chat surface) see zero
  usage for these turns even when the provider reported it, and cannot
  distinguish "provider didn't report" from "path doesn't emit".
  → F-LLM-01-P2-02.
- `pre_compaction_flush` (`context.rs:734`) also calls `llm_client.chat`
  and discards usage entirely (best-effort path; lower impact, same class).
- Reported-usage loss on malformed streaming input: a dropped usage chunk
  (client.rs:99-105) yields `usage_reported: false` despite the provider
  reporting usage — observability mis-signals; cross-referenced in
  F-LLM-01-P1-01.
- `usage_reported=false` semantics themselves are coherent: event carries
  zeros + flag false; consumers must treat cache fields as unknown
  (event doc mod.rs:157-161).

None.

## Conclusion

Supports: provider usage is the single normalization authority; the
`usage_reported` contract is honored on the streaming main paths and its
"unknown, not zero" semantics are documented; the authority diverges on the
non-streaming direct_answer/structured paths (P2-02), and malformed chunks
can flip a true report into `usage_reported: false` (P1-01).

Does not prove: provider-specific usage mapping fidelity (OpenAI = F-LLM-02,
Anthropic = F-LLM-03) or EKO-side usage aggregation (A-* tasks).
