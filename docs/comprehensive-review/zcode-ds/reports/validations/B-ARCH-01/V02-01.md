## Claim

The root `echo_agent` facade is a coherent composition of (a) real
implementations (agent engine, evolution, trace, context, state, notebook,
intent, event bus) and (b) explicit re-export facades over the split crates,
with every sub-crate re-export clearly marked "authoritative implementation
lives in <sub-crate>". No parallel second implementation exists for any
sub-crate-owned concept.

## Method

1. Read `src/lib.rs` in full (331 lines): module list, `prelude`, `advanced`,
   `workspace` alias module.
2. For each root module, classified it as re-export vs real implementation by
   reading its first lines and grepping for `pub use echo_<crate>::` /
   "re-export" markers.
3. Read all sub-crate `lib.rs` files (7) to confirm what each sub-crate owns.
4. Checked whether `crate::workspace` (facade-exposed sub-crates) is used in
   real code or only docs.

## Expected Result

- Root modules classified as thin re-exports: retry, error, llm, tokenizer,
  scheduler, human_loop, tasks, mcp, lsp, compression, audit, sandbox,
  skills, workflow, guard, plugin, memory, and tools (partially).
- Root modules with real code: agent, evolution, trace, context, state,
  notebook, intent, event_bus, memory_promoter, headless, config, paths.
- `workspace` alias used only in doc comments.

## Deviations

- `pub mod tasks;` in `src/lib.rs:96` is not feature-gated although the root
  manifest declares a `tasks = []` marker feature (`Cargo.toml:76`). The
  feature is therefore a no-op for the root crate; `subagent = ["tasks"]`
  (`Cargo.toml:80`) declares a dependency that the code does not require.
  Recorded as `B-ARCH-01-P3-02` (feature/facade inconsistency), not a
  deviation of this claim.

entry points.
