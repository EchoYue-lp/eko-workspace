## Claim

Claude Code's plan mode treats the plan as a **permission-restricted
exploration phase plus a Markdown file artifact**, with approval driven by a
permission gate — not by a runtime plan-approval state machine.

## Method

Lookup: GitHub repo `windy3f3f3f3f/how-claude-code-works`, file
`docs/10-plan-mode.md` (community reverse-engineering of Claude Code source,
with per-file source anchors), read in full via zread on 2026-08-12. Official
docs (`code.claude.com/docs/en/plan-mode`, `docs.anthropic.com/en/docs/
claude-code/plan-mode`) returned 404; official permission docs were not
fetchable in this session — noted as a limit.

## Expected Result

A concrete description of: plan artifact storage, Enter/ExitPlanMode tools,
approval flow, mode restoration, subagent restriction.

## Result

- **Plan artifact**: Markdown file `~/.claude/plans/<word-slug>.md` per
  session (`src/utils/plans.ts`, 398 lines); slug cached per session; fork
  gets a fresh slug to avoid overwrite; resume uses 5 layers (file → file
  snapshot in transcript → ExitPlanMode input → planContent → auto-compact
  attachment).
- **Entry**: `/plan` command or `EnterPlanMode` tool; both call
  `handlePlanModeTransition` + `prepareContextForPlanMode`; plan mode is a
  permission downgrade (read-only) recorded as `mode: 'plan'` with
  `prePlanMode` saved. Subagents **cannot** enter plan mode
  (`EnterPlanModeTool.ts:77-101` rejects `context.agentId`).
- **Exit/approval**: `ExitPlanMode` tool; `validateInput` rejects calls
  outside plan mode ("model amnesia" guard); `checkPermissions()` shows an
  "Exit plan mode?" dialog with Approve / Edit-then-approve / Reject;
  permission restoration reads `prePlanMode` with a circuit-breaker fallback
  (auto→default if the auto gate is off); four result-message types
  (teammate approval, subagent, empty plan, normal approval).
- **Instruction delivery**: mode instructions injected as **throttled
  attachments** (full every ~25 turns, sparse every 5) rather than a state
  machine.
- **Design insight documented**: plan mode is "the only mechanism where the
  model proactively lowers its own permissions to earn trust"; state
  transitions are symmetric (enter saves prePlanMode, exit restores it).

## Deviations

Official Anthropic docs were not reachable (404/network); the lookup uses a
community reverse-engineering document that cites concrete Claude Code
source files. The claim is supported for the source version the document
describes; version drift is possible.

## Conclusion

Supports: plan-as-artifact, permission-gated approval (no run-level
plan-approval state machine), subagents excluded from plan mode, editable
plan files — consistent with the review invariant "Plan is a versioned,
editable artifact; approval is permission/prompt driven".

Does not prove: current official-doc wording (unreachable) or behavior of
newer Claude Code versions.
