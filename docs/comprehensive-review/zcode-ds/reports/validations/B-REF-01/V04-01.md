## Claim

Cursor and Devin both implement plan-then-execute with the plan as a
**visible, editable, revisable artifact** and a user approval checkpoint
before autonomous execution; Devin additionally runs a **separate review
agent** after the writing agent; both support background/parallel agent
runs.

## Method

Lookup on 2026-08-12 via web search: dev.to comparison of Cursor/Devin
plans-vs-tasks, Federico Calò's Cursor plan-mode/background-agent deep-dive,
Cursor community forum orchestrator patterns, and Devin 2.0 plan-revision
coverage. Official Cursor/Devin docs were not fetched directly (limit
noted).

## Expected Result

Plan-as-artifact + approval gate + revision + separate review agent + background agents.

## Result

- **Cursor**: agent plan mode writes a detailed Markdown plan before
  touching code; workflow is describe → plan → user approves step-by-step →
  execution; planning is the human checkpoint before autonomous execution.
  Background agents run asynchronously while the user keeps coding and
  notify on completion or when approval is needed; multiple agents run in
  parallel; automations (2026) trigger agents from events (commits, Slack,
  PagerDuty).
- **Devin**: upfront planning with continuous revision — Devin inspects the
  repo, returns a step-by-step plan, waits for user modification before
  proceeding; Devin 2.0 makes plan revision central ("the plan changes a lot
  over time"); a **separate review agent** pressure-tests the implementation
  after the writing agent finishes.
- **Shared pattern**: plan-then-execute separation; visible/editable plans;
  approval gates before execution; task tracking during execution; plan
  revision as a feature (not a frozen approval state).
- Third-party orchestrators on Cursor implement `propose_plan →
  confirm_plan → execute_plan` — the same artifact+approval shape.

## Deviations

Official Cursor/Devin documentation was not fetched directly; claims rest on
secondary coverage (developer blogs/forums) of 2025-2026 product behavior.

## Conclusion

Supports: the cross-industry convergence that plans are editable artifacts
with a user approval gate, planning and execution are separable, and
background/parallel agents are first-class. Consistent with the review
invariant (plan as versioned artifact; no runtime plan-approval state
machine) and with EKO's review-agent pattern (A-TSK-06).

Does not prove: exact current UI/feature naming in Cursor/Devin.
