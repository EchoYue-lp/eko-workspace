## Claim

Temporal's durable-execution model uses **append-only event history per
workflow execution as the source of truth**, recovery by deterministic
**replay** (commands regenerated and compared against recorded events;
mismatch → `NondeterminismError`), non-deterministic effects wrapped in
`SideEffect` and recorded in history (not re-executed on replay), and
signals recorded server-side **before** delivery. "Safe point" is not a
first-class Temporal term; the closest analogues are event-history append
points and workflow-task completion.

## Expected Result

Event sourcing + replay determinism + side-effect recording + signal
ordering semantics, and an explicit statement that "safe point" is not a
Temporal term.

## Result

- Event sourcing: append-only event history per workflow execution; state
  recreated by replaying history.
- Determinism: workflow code must be deterministic; on recovery the worker
  re-executes code and compares generated commands against recorded events;
  mismatches raise `NondeterminismError`; time/randomness/external state/
  iteration order are the classic non-determinism sources; SDKs sandbox
  workflow code.
- Side effects: `SideEffect` runs non-deterministic code once, stores the
  result in event history; on replay it returns the recorded result without
  re-executing; `MutableSideEffect` variant exists.
- Signals: recorded server-side into history first, then delivered — replay
  sees signals at the exact same position.
- Activities: must be idempotent or accept at-least-once semantics; queries
  do not advance the workflow.
- Safe point: the exact term did not appear as a first-class concept; the
  closest analogues are event-history append points and workflow-task
  completion points.

## Conclusion

Supports: event-sourced recovery with replay determinism as the industry
model for durable execution; exactly-once is achieved via recorded history
plus idempotent activities, not via locking state machines. Directly
relevant to EKO's `events.jsonl` recovery authority and the claim/attempt
protocol review (A-TSK-04, F-TSK-03).

Does not prove: Temporal server internals beyond the architecture README.
