## Claim

The streaming handler preserves interleaved text/tool_use/thinking content
blocks in order: every tool_use block accumulates its `partial_json` deltas
against the correct block and emits exactly one `ChatChunk` with the
assembled `DeltaToolCall` at `content_block_stop`.

## Method

1. Read `chat_stream` in `echo-agent/echo-integration/src/providers/anthropic.rs:421-630`
   and the wire event types `AnthropicStreamEvent`/`ContentBlockStartBody`/
   `ContentDelta` (:1048-1098).
2. Trace the accumulator map lifecycle:
   - `ContentBlockStart` ToolUse arm (:520-528): `let idx = tool_call_args.len(); tool_call_args.insert(idx, (id, name, String::new()))` — key is the **map length**, while the event carries `index` bound to the ignored `_index` field (:1054-1058).
   - `ContentBlockDelta` (:532-553): `tool_call_args.get_mut(&index)` — lookup key is the **stream block index**.
   - `ContentBlockStop` (:554-583): `tool_call_args.remove(&index)` — key is the **stream block index**.
3. Check the downstream consumer of the emitted `DeltaToolCall.index`:
   `echo-agent/src/agent/react/run/processor.rs:60-80` keys its
   `tool_call_map` by `dc.index`.
4. Verify block-end signaling for text/thinking blocks: `ContentBlockStop`
   for non-tool_use indices removes nothing and yields nothing (:554-583);
   `ContentDelta` for thinking deltas (`{"type":"thinking_delta","thinking":...}`)
   has neither `text` nor `partial_json` set (:1088-1093) so the delta is
   silently ignored.

## Expected Result

Every tool_use block at stream index `i` must be accumulated and finalized
using key `i`; blocks preceding a tool_use (text at index 0, thinking at
index 0/1) must not break accumulation.

## Result

- Exit code: not-applicable
- Duration: not-applicable
- Summary:

The accumulator key is the map length at insert time (`tool_call_args.len()`),
while deltas and stops look up by the stream block `index`. These two
sequences diverge exactly when a non-tool_use block precedes the tool_use
block:

- **text-first case** (blocks = [text@0, tool_use@1]): tool_use inserted
  under key 0; `ContentBlockDelta{index:1}` and `ContentBlockStop{index:1}`
  miss → the tool call is silently dropped from the stream. The agent's
  ReAct loop never sees the tool call.
- **interleaved multi-tool case** (blocks = [text@0, tool_use@1,
  tool_use@2]): tool_use@1 → key 0, tool_use@2 → key 1; deltas for index 1
  are appended to key 1, which holds tool_use@2's id/name → **arguments of
  tool_use@1 are attached to tool_use@2**; deltas for index 2 miss; stop@1
  emits tool_use@2 with tool_use@1's args; stop@2 emits nothing.
- **tool_use-first case** (blocks = [tool_use@0, tool_use@1]): keys 0/1
  coincide with indices 0/1 → works by accident.
- With extended thinking enabled (thinking@0, text@1, tool_use@2): same
  divergence as text-first (thinking deltas are themselves ignored — no
  `reasoning_content` is ever emitted, and `processor.rs:18-36` thinking
  events never fire on Anthropic).

`ContentBlockStop` also serves as the only "block end" signal for tool
calls; there is no terminal signal for text blocks (not needed downstream).

Downstream consequence: `processor.rs` keys its tool_call_map by the
adapter-emitted `DeltaToolCall.index`, which is the (wrong) map key; when a
corrupted pair is emitted (case 2), the model receives the wrong tool with
the wrong arguments.

## Deviations

The preservation claim fails in the two interleaving cases above. No
streaming fixture test exists in the adapter (tests at anthropic.rs:1100-1279
cover convert_request/cache/attachments only), so the defect is invisible
to the current suite.

## Conclusion

Supports: the streaming tool-call assembly is correct only when the first
content block is a tool_use; interleaved text-first (or thinking-first)
streams lose or corrupt tool calls silently. This is the V02 finding
(F-LLM-03-P1-01). Does not prove: behavior against a real provider stream
(no live test).
