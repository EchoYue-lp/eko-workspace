## Claim

`AnthropicClient::convert_request` maps every `ChatRequest` field to the
Anthropic Messages API request body losslessly, and `convert_response` maps
every response content block to the neutral `ChatResponse` losslessly.

## Method

1. Read `echo-agent/echo-integration/src/providers/anthropic.rs` in full
   (convert_request :69-291, convert_response :293-364, wire types
   :637-1098).
2. Read the neutral contract `echo-agent/echo-core/src/llm/mod.rs`
   (`ChatRequest` :150-183, `ChatChunk` :233-241) and the wire types
   `echo-core/src/llm/types.rs` (`Message`/`MessageContent`/`Usage`,
   `Role` :156-168).
3. Grep for producers of each `ChatRequest` field in the core loop:
   `echo-agent/src/agent/react/run/phases/think.rs:312-328`,
   `src/agent/react/run/react_loop.rs:48-65`, and consumers of
   `reasoning_content`/`tool_choice` across both repositories.
4. Grep for `AnthropicClient` construction sites and `ProviderFactory`
   selection in `echo-integration/src/providers/config.rs`.
5. Grep `AnthropicCachePlan` helpers for live callers
   (`from_layout_or_default`, `default_plan`, `has`, `history_indices`,
   `has_history_last_stable`, `apply_conversation_cache_breakpoints`).

Response mapping (`convert_response`, anthropic.rs:293-364):

- `ContentBlock::Text` → content parts; `ToolUse` → ToolCall (:297-312);
  other block types (`thinking`, `redacted_thinking`, `document` in
  responses) are **unmodeled** — `ContentBlock` derives Deserialize with
  `#[serde(tag = "type")]` and no `#[serde(other)]` (:827-866), so a
  response containing a `thinking` block fails `resp.json()`
  (:410-413) with `LlmError::NetworkError("Response parse error")`.
- finish_reason mapping end_turn→stop / tool_use→tool_calls /
  max_tokens→length (:314-319).
- usage input/output → Usage.prompt/completion/total +
  cache_creation/read (:338-350).

Streaming response mapping (chat_stream, anthropic.rs:478-624): inline SSE
parser; `AnthropicStreamEvent` has `#[serde(other)]` (:1069-1070) so unknown
event types are ignored; tool-call accumulation keyed by map length instead
of block index (see V02 report).

Reachability: `AnthropicClient` constructed via
`ProviderFactory`/`LlmProvider::Anthropic` (`config.rs:305-311`),
re-exported at `src/llm.rs:80,100`; main-path producer `think.rs:312-328`
sets temperature/max_tokens/tools/tool_choice("none" on final_only,
:317-318)/thinking/cancel_token/user_id/cache_hints(empty breakpoints);
`react_loop.rs:48-65` (direct_answer path) additionally sets
`response_format` and `thinking`.

Dead-code inventory (grep): `AnthropicCachePlan::from_layout_or_default`,
`default_plan`, `has`, `history_indices`, `has_history_last_stable` have no
callers outside `anthropic_cache.rs` tests; `apply_conversation_cache_breakpoints`
(anthropic.rs:909-939) is unreachable from `convert_request` because
`cache_plan.breakpoints.is_empty()` (:243) can never be true when
`history_breakpoint_count() > 0` (:237); `AnthropicSystem::Text` (:668-671)
is never constructed; the `[DONE]` check (:507-509) is dead for Anthropic
(no `[DONE]` sentinel in the Messages SSE stream).

## Deviations

Deviations from the "lossless" claim: system-message collapse; tool_choice
and response_format silently dropped; thinking blocks unparsable in
non-streaming responses and dropped in streaming; dead code inventory
above. All recorded as findings or P3 items in the task report.

## Conclusion

Supports: request mapping is mostly lossless for the fields the core loop
sets today, with three confirmed silent-loss defects (system collapse,
tool_choice/response_format drop, thinking-response unmodeled) and one
dead-code inventory. Does not prove: wire acceptance by real providers
(no live-provider or request-fixture tests exist in the adapter; the 14
unit tests cover convert_request cache placement, metadata, and attachment
dispatch only).
