## Claim

`cache_control:{type:"ephemeral"}` breakpoints are injected at the planned
points (system block / last tool / conversation history) and every
cache_creation / cache_read token count is accounted into
`ChatChunk.usage` / `ChatResponse.raw.usage` with the same `usage_reported`
semantics as the neutral contract (F-LLM-01 V03).

## Method

1. Trace breakpoint injection in `echo-agent/echo-integration/src/providers/anthropic.rs`:
   - plan resolution from `cache_hints` breakpoints (:171-186) vs
     `PromptCacheLayout::from_messages` fallback (:197-201);
   - system block cache_control (:224-234), last-tool cache_control
     (:205-221), history breakpoints with 4-breakpoint cap
     (:236-268, `remaining_breakpoints = 4 - used`);
   - `AnthropicCachePlan::from_layout` (`anthropic_cache.rs:42-79`) and
     runtime-context exclusion (`is_runtime_context`, anthropic.rs:941-943).
2. Trace streaming usage accounting: `message_start` → input_tokens +
   cache_creation/read (:512-518); `message_delta` → output_tokens (:584-588);
   final chunk emits `Usage` when input>0 or output>0 (:594-617).
3. Trace non-streaming usage: `AnthropicResponse.usage` → `Usage`
   (:338-350) → `ChatResponse.raw.usage`.
4. Verify `usage_reported` semantics downstream:
   `echo-agent/src/agent/react/run/phases/think.rs:112-113,147`
   (`last_usage.is_some()`), `:183-211` (LlmUsage event + token tracker),
   `:171-180` (tokenizer calibration).
5. Cross-check the wire shape of `AnthropicUsage` (:1037-1046):
   `input_tokens: u32` and `output_tokens: u32` have NO `#[serde(default)]`;
   cache fields are optional.
6. Web-search verification of the Anthropic Messages API streaming usage
   shape (message_start carries `input_tokens` + cache fields;
   `message_delta.usage` carries **only** `output_tokens`).

## Expected Result

- Breakpoints placed at system/last-tool/75% history/last-stable per plan;
- final streaming chunk carries usage on every turn the provider reports it;
- `usage_reported` true iff usage is present; cache tokens reach
  `Usage.cache_creation_input_tokens`/`cache_read_input_tokens` and the
  `effective_*` normalizers (`types.rs:686-771`).

## Result

- Exit code: not-applicable
- Duration: not-applicable
- Summary:

Breakpoint injection: verified as designed. System block, last tool, and
history messages (max 4 total, runtime-context messages excluded) receive
`cache_control: {type:"ephemeral"}`; unit tests
(`conversation_cache_breakpoints_skip_trailing_runtime_context`,
`plan_*`, `cache_hints_with_empty_breakpoints_still_places_cache_control`)
pass (see V04).

Usage accounting: **fails on the real Anthropic wire shape.** The
deserializer for `message_delta.usage` requires `input_tokens`, but the
Anthropic Messages API emits `message_delta.usage = {"output_tokens": N}`
only (verified via web search; the code's own comment at anthropic.rs:586
"Capture output_tokens from message_delta" confirms the author expected
output_tokens-only). Serde therefore rejects the whole `message_delta`
event; `if let Ok(event)` (anthropic.rs:510) silently drops it. The final
chunk with `finish_reason` + usage (:607-616) is **never emitted** on real
Anthropic streams → `last_usage = None` → `usage_reported: false` on every
streaming turn; token tracker, tokenizer calibration (think.rs:171-180),
and cache-hit observability all see zero. Anthropic-compatible gateways
that include `input_tokens` in `message_delta` (e.g. some DeepSeek
endpoints) would parse fine — provider-dependent.

Non-streaming accounting: `resp.usage` → `ChatResponse.raw.usage` works
when the response parses (i.e. when no thinking blocks are present; see
V01 for the thinking-block parse failure).

`usage_reported` consistency with F-LLM-01: the `usage_reported` derivation
at think.rs:147 is provider-neutral and correct; the defect is that the
Anthropic adapter never delivers a usage chunk, making the flag
systematically false on real Anthropic streams — contradicting F-LLM-01
V03's assumption ("Anthropic usage mapping feeds ChatChunk.usage") and
F-LLM-01's M9 "provider/API usage 是记账权威" invariant on this path.

## Deviations

The streaming usage claim fails; root cause is the strict `AnthropicUsage`
struct combined with silent event dropping. Recorded as F-LLM-03-P1-02.

## Conclusion

Supports: breakpoint placement correctness; non-streaming usage mapping;
provider-neutral `usage_reported` semantics. Does NOT support: streaming
usage delivery on real Anthropic payloads — it is broken by a
deserialization shape mismatch that no fixture test covers.
