## Claim

The task's required invariants hold: (a) layer/precedence map of the
instruction + memory protocol is coherent; (b) instruction/hot-memory
projections survive repeated compression; (c) refresh triggers project
hot-layer changes immediately to primary and pooled agents; (d) duplication/
promotion and workspace-switch fixtures behave deterministically.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - (a) Layer/precedence map: coherent — five instruction tiers + hot memory,
    fixed concatenation order user→repository→project→learned→local
    (instruction_provider.rs:141-163), hot memory separate. One inconsistency
    arm: RulePromoter's write target is CWD-derived
    (`agents_instructions_path`, instruction_provider.rs:291-297) while the
    projected scope can be workspace/global — after exit_workspace the CWD
    stays in the exited workspace (state.rs:1053-1185, A-CFG-01-P1-02) so a
    promoted rule can land outside the active projection scope (P3-03).
  - (b) Compression survival: PASSES — projections are protected system
    messages; split/merge preserve them through every prepare; echo_state
    compression suite (69 tests incl. context_projection_* tests,
    mod.rs:1848-2075) green (V04-01). EKO rides F-CMP-01-P1-02 (summary
    accumulation) and F-CTX-01-P2-02 (canonical reinjection) machinery
    without adding EKO-specific exposure: projections are never summarized or
    truncated; the canonical reinjection at index 0 does not touch the
    boundary-placed projections.
  - (c) Refresh triggers: VIOLATED — every in-session hot-layer mutation
    (Dreaming promotion, GUI/TUI/CLI memory add/delete, remember tool,
    task memory bridge, budget demotion) fires the instruction projection
    refresh or nothing; the hot-memory projection stays stale until the next
    boot, workspace switch, or exit (P1-01). `refresh_hot_memory_projection`
    has zero production callers.
  - (d) Duplication/promotion: VIOLATED (minor) — a memory promoted to a
    rule (marker in content, stays in warm) is still eligible for Dreaming
    hot promotion (dreaming.rs has no marker check), so the same fact lands
    in both always-loaded projections (learned-rules.md + MEMORY.md);
    asymmetric: hot promotion deletes the warm entry so the reverse cannot
    happen (P3-02). Workspace-switch fixtures exist for the instruction
    projection replacement but NOT for hot-memory replacement across
    workspaces (hot memory is refreshed on switch via refresh_memory_projections,
    but no test pins it; also the stale-until-switch window is untested).
  - Cross-reference checks (F-CMP-01-P1-02, F-CTX-01-P2-02, F-EVO-01-P2-02):
    EKO's protocol relies on the same compression/store machinery without
    aggravating or mitigating it: (i) P1-02 summary accumulation applies to
    every EKO session (default "summary" strategy) — the instruction/hot
    projections are protected so they do not add to the accumulation, but
    they also do not cap it; (ii) F-CTX-01-P2-02 canonical reinjection and
    projection truncation (chars().take(2000) on rules) do not affect the EKO
    projection envelope (separate messages); (iii) F-EVO-01-P2-02 L3
    StoreMemoryPromoter writes (unrecorded, unscanned) feed the same warm
    store that EKO's RulePromoter scans — unaudited L3 content can be promoted
    into learned-rules.md (the rule text is security-scanned at promote time,
    rule_promoter.rs:184-193, so the guard arm holds); EKO neither aggravates
    nor mitigates the framework findings.
- Log/artifact: none
