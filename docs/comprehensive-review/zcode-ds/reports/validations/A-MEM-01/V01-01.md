## Claim

The instruction protocol (instruction tiers + hot-layer MEMORY.md), the memory
manager/evolution integration, and the Dreaming schedule each have a single
authoritative owner per repository layer, with no parallel implementation of
the same semantic across framework and application.

## Deviations

The `refresh_hot_memory_projection` dead helper and the two-reader MEMORY.md
parse are duplicates/divergences found by this search; they are recorded in
the task report (P1-01 evidence / coverage note), not as additional
authorities.

## Conclusion

Supports: single-authority claim for the instruction protocol, the memory
layer manager, the Dreaming driver, and rule promotion; three projection
helpers with one dead in production; MEMORY.md has two independent readers.
Does not prove runtime reachability — that is V02.
