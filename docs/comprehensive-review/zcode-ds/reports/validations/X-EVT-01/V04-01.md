## Claim

Duplicate or out-of-order terminal events cannot produce a second terminal,
a terminal-to-running regression, or a terminal that contradicts the
producer's outcome at any consumer layer (envelope, EKO Rust surfaces, TS
reducers).

## Method

executable store fixture run.

   `subagentRunStore.ts:450-460` (monotonic guard),
   `toolExecutionStore.ts:50-86` (merge rank) vs `:206-217` (live ingest).
5. Executable: `npx vitest run src/stores/subagentRunStore.test.ts

## Conclusion

The one-terminal invariant holds only at the envelope boundary and in the
subagent store; it fails at the GUI wire (two contradictory terminals per
error/cancel turn), in the live tool ingest (regressable, duplicate rows),
and for cancel/timeout class preservation. The subagent/TaskRuntime replay
paths are duplicate- and out-of-order-safe. This supports the task's
terminal-conformance verdict. It does not prove behavior under real
backpressure or real cancel timing (Q-FLT-01/Q-E2E-01 scope).
