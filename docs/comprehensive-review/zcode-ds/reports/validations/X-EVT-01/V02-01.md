## Claim

Every event variant the backend can emit on the chat and execution channels
has a covering TypeScript reducer arm, and every TS reducer arm corresponds to
a real wire variant — no unreachable reducer states and no unhandled wire
variants on the main chat path.

## Method

Static comparison of the Rust wire enums against the TS types and reducer
switches, plus a producer-side reachability check for each variant.

1. Rust wire enum `ChatEvent` (`src/tauri/commands/chat.rs:30-112`, 19
   variants) + injected fields (message_key, conversation_id, chat.rs:128-140).
2. TS union `ChatEvent` (`web-frontend/src/types/api.ts:125-177`) + dispatch
   switch `chatEventHandler.ts:25-220` (19 cases).
3. `ChatRunStatus` (`api.ts:38-52`) vs backend `run_status` value producers:
   `chat.rs:620/656/709` ("running"/"failed"/"cancelled"/"completed"),
   `chat.rs:1203` ("using_tool"), `agent_event_to_chat_event` ("thinking",
   chat.rs:1457-1467); whitelist `chatEventHandler.ts:163-173`.
4. Subagent channel: Rust producers `DispatchStarted/Completed/Failed/
   Cancelled` (`src/tauri/mod.rs:573-645`, event string = "started"/
   "completed"/status.as_str()/"cancelled") vs TS `STORED_SUBAGENT_EVENTS`
   (`subagentRunStore.ts:146-155`) and `statusFromEvent` (`:161-175`);
   replay mapping `runtimeTerminalEvent` (`:252-262`).
5. Tool channel: `emit_tool_execution_summary` (chat.rs:185-208) kinds
   "started"/"finished"/"cancelled" vs `toolExecutionStore.ingest`
   (`toolExecutionStore.ts:206-217`) and `recordToolStart`
   (`useTauriChat.ts:135-137`).
6. Per-variant producer reachability on the main ReactAgent path
   (F-RCT-03-P1-02 facts at the same commit).

## Expected Result

19/19 `ChatEvent` variants covered by TS type and reducer; all `run_status`
producer values in the TS whitelist; subagent/tool event kinds covered by
store ingest; any wire variant with zero live producers is flagged.

  src/stores/taskRuntimeStore.test.ts` — exit 0, 23 tests passed (see
  V03-01/V04-01 for the fixture detail)
- Summary:

    matching fields (verified field-for-field; A-FE-01 V03-01 independently
    confirmed the same 19/19 at the same commit).
  - `chatEventHandler` switch: 19/19 cases (token, thinking_start,
    thinking_end, llm_usage, context_compressed, tool_batch_start,
    tool_batch_end, chart, final_answer, approval_request, input_request,

- Deviations (dead variants — reducer arms with no live producer):

    main path. Filed as X-EVT-01-P3-01.
  - Subagent `timed_out`/`cancelled` statuses are reachable only via the

    classified `failed` (X-EVT-01-P1-01).

    `agent_event_to_chat_event` (chat.rs:1503-1510): `handle_tool_event`
    returns `Some` for every tool variant (chat.rs:1193-1331), so that arm
    is dead code in the GUI path.

## Conclusion

Variant exhaustiveness holds: the TS layer covers 100% of the wire variants
on all three channels, and the reducer states that are unreachable are
exactly those whose producer is missing in the framework (cancel) or whose
class is collapsed at the envelope (timeout). This supports the X-EVT-01
conclusion that the *consumer* vocabularies are complete and the *producer*
vocabularies are the deficit. It does not prove that every variant is
exercised dynamically (Q-E2E-01 scope).
