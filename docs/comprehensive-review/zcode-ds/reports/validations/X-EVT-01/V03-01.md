## Claim

Replaying the recorded EKO persistence (conversation messages, tool-execution
journal, TaskRuntime `events.jsonl`) reconstructs terminal state consistent
with what the live event stream produced, for every durable consumer.

## Method

Static trace of the three durable record families and their replay paths,
plus one executable store-level replay run.

1. **TaskRuntime**: write path `file_shadow.rs:92-145` (append-only
   `events.jsonl`, per-run seq, append lock) and `hook_event_dispatcher.rs`
   (single chokepoint); read/replay path `store.rs:1547-1583` (event
   rebuild) and frontend `taskRuntimeStore.loadByConversation`
   (`taskRuntimeStore.ts:219-283`) -> `listEvents(run_id, '0')` ->
   `ingestTaskRuntimeSubagentEvents` (subagentRunStore.ts:330-405) +
   `ingestTaskRuntimeToolExecutions` (toolExecutionStore.ts:241-254);
   durable subagent terminal status = `record_subagent_released.status`
   (`executor.rs:2337-2343`, `SubagentReleaseRecord`), replayed through
   `runtimeTerminalEvent` (subagentRunStore.ts:252-262).
2. **Tool journal**: durable `ToolExecutionSummary` per (owner, call_id)
   (`tool_execution.rs:40-130`, journal events); replay `list_tool_executions`
   -> `conversationStore.hydrateConversation` -> `mergeHydratedToolExecutions`
   (toolExecutionStore.ts:106-117) and `loadByConversation` merge
   (`taskRuntimeStore.ts:235-252`).
3. **Conversation**: `save_conversation`/`get_conversation`
   (`conversations.rs:392-470`) persist `SavedMessage[]` only (no turn

4. **Trace runs**: framework `JsonlRunStore` (trace/mod.rs:672-793) wired by
   EKO at `infra.rs:377`; terminal `RunStatus` persisted per turn.
5. Executable replay fixture check: `npx vitest run
   src/stores/subagentRunStore.test.ts src/stores/toolExecutionStore.test.ts
   src/stores/taskRuntimeStore.test.ts` (working dir
   `echo-agent-cli/web-frontend`).

## Expected Result

Replay yields the same terminal facts as the live stream for TaskRuntime
runs (status, subagent terminal, tool terminal); tool rows restore with
terminal status; conversation reload restores messages with the turn outcome
recoverable.

## Conclusion

Replay conformance holds for all three durable record families that carry a
terminal (TaskRuntime runs/subagents, tool journal, trace runs) — replayed
terminal states equal the persisted terminal facts and cannot regress via
stale events. The chat-turn path lacks a persisted terminal entirely
(X-EVT-01-P2-02). This supports the task's persistence-dimension verdict and
does not prove crash-point behavior (A-TSK-04/Q-FLT-02 own fault injection).
