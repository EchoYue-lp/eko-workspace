## Claim

There is exactly one streaming event producer authority for AgentEvent streams
(`run_stream_channel` → `run_core_loop`), no parallel streaming pipeline or
loop in either repository, and the definition/registration/live-caller status
of every streaming producer/consumer symbol is known.

## Method

Repository-wide search (both repositories, code + tests) for every candidate
streaming producer/consumer term, then classification:

```text
grep -rn "mpsc::channel" echo-agent/src/agent/react/           # producer channels
grep -rn "try_stream|BoxStream|ReceiverStream" echo-agent/src/agent/react/run/
grep -rn "execute_stream|chat_stream|run_stream_channel" echo-agent/src echo-agent-cli/echo-agent-app-core/src
grep -rn "stream_buffer_size" echo-agent/src
grep -rn "envelope_event_stream" echo-agent/src echo-agent/echo-core/src
grep -rn "cancel_aware_stream" echo-agent/src echo-agent/echo-core/src
grep -rn "GLOBAL_EVENT_BUS|EventBus" echo-agent/src
grep -rn "AgentEvent::Cancelled|AgentEvent::Error" echo-agent/src
grep -rn "process_stream_chunk|emit_content_tokens" echo-agent/src
grep -rn "yield_event_or|yield_final_event_or|try_send_or" echo-agent/src/agent/react/run
```

## Expected Result

- One producer: `run_stream_channel` (stream_channel.rs:41) with one loop body
  `run_core_loop`; the non-streaming wrapper (`react_loop.rs:686`) creates a
  private channel and drives the same loop; internal tool-pipeline channels
  (pipeline.rs:515,1642; tools.rs:141,319) carry `ToolStreamEvent`, not
  `AgentEvent`.
- No streaming implementation exists in `echo-agent-cli` (consumers only).
- No parallel `try_stream!` producer remains.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Single producer confirmed: `mpsc::channel::<Result<AgentEvent>>` created
    only at stream_channel.rs:41 (streaming) and react_loop.rs:686 (the
    non-streaming wrapper's private channel driving the same `run_core_loop`).
    Phase channels in tools.rs:141,319 and pipeline.rs:515,1642 carry tool
    stream events, not AgentEvents.
  - `BoxStream` produced only by `run_stream_channel` (stream_channel.rs:39,
    177,245,314); no `try_stream!` remains (module doc says channel-based
    replaced it).
  - `process_stream_chunk` has exactly one production caller (think.rs:122),
    always with `emit_content_tokens = false`; direct_answer_stream does not
    use it. No parallel chunk processor exists.
  - CLI has no streaming producer: `execute_stream_message_with_invocation_context`
    / `execute_stream_with_invocation_context` consumers only
    (chat_driver.rs:513, task_runtime/executor.rs:3119,3130,3734) plus the
    envelope wrapper (chat_driver.rs:538, executor.rs:3136,3743).
  - `cancel_aware_stream` (echo-core/src/agent/mod.rs:896-917) has exactly two
    callers, both default trait methods (mod.rs:567,626); ReactAgent overrides
    the four cancel-carrying streaming methods (react/mod.rs:2821-2933) and
    never calls it.
  - `envelope_event_stream` single authority in
    echo-core/src/agent/event_envelope.rs:112; consumers: chat_driver.rs:538,
    executor.rs:3136,3743, subagent/executor.rs:1182, a2a/server.rs:219.
  - `AgentEvent::Cancelled` producers: subagent/executor.rs:2013 and the
    default cancel wrapper only; zero producers on the ReactAgent main loop
    (react_loop.rs:737 is a consumer branch, not a producer).
  - `AgentEvent::Error` producers in react: stream_channel.rs:390
    (direct_answer_stream chunk error) only; other error terminals are
    `Err` items on the channel.
  - `GLOBAL_EVENT_BUS` / `EventBus` (src/event_bus.rs): zero publishers and
    zero subscribers outside event_bus.rs in `echo-agent/src` — the streaming
    path has no event-bus integration.
  - RwLockAgentWrapper (src/agent/handle.rs:95-149) re-streams events through
    an unbounded mpsc channel for `AgentHandle` users (unbounded = no
    backpressure, no drops); a transport wrapper, not a parallel loop.
- Log/artifact: none
