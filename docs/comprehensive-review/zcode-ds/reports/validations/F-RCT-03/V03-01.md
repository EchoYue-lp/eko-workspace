## Claim

The streaming event contract's invariants — ordered, lossless, bounded,
one-terminal, cancel-as-terminal, streaming/non-streaming conformance — are
either upheld by current code or covered by tests; every relevant edge case
has a known verdict and the test suite's coverage of each edge is known.

## Method

Invariant-by-invariant inspection of producer/consumer code against the
existing test suite (stream_channel.rs tests, phases tests, event_envelope
tests, processor tests, integration tests under `echo-agent/tests/`), plus
targeted searches for tests exercising each edge:

```text
grep -rn "buffer full|TrySendError|backpressure|dropping event" echo-agent/src echo-agent/echo-core/src   # backpressure tests
grep -rn "count|twice|duplicate|second" — FinalAnswer producers vs tests                                   # duplicate-terminal tests
grep -rn "conformance|non_streaming.*stream" echo-agent/src/agent/react                                     # conformance fixture
grep -rn "Cancelled" echo-agent/src/agent/react/run echo-agent/src/agent/react/mod.rs                       # cancel contract
git log --oneline -1 -- src/agent/react/run/processor.rs; git show 297fc54 --stat                            # origin of emit_content_tokens=false
```

## Expected Result

- Ordered: events on the channel follow send order (mpsc FIFO) — true by
  construction; producer order verified by reading each phase's send sequence.
- Lossless: no event dropped except receiver-closed (channel close).
- Bounded: buffer bounded at `stream_buffer_size` (256); loop bounded by
  `max_iterations` (0 = unlimited by EKO default).
- One terminal per turn on the raw stream.
- Cancel produces the documented terminal (`AgentEvent::Cancelled`).
- Tests cover: buffer-full/backpressure, channel close, duplicate terminal,
  streaming/non-streaming conformance.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - **Ordered:** mpsc is FIFO; per-phase send sequences verified. Ordering
    quirks exist in the think phase: `LlmUsage` is emitted (think.rs:199-211)
    before the end-of-stream content burst (think.rs:224-247); a mixed
    reasoning+content+tools turn emits `ThinkStart…ThinkEnd{0,0}` mid-stream
    and a second synthetic `ThinkStart…ThinkEnd{pt,ct}` after the stream ends
    (think.rs:213-247) — covered in finding P2-01.
  - **Lossless — VIOLATED (finding P1-01):** `yield_event_or!` uses `try_send`
    and drops the event on `TrySendError::Full` with only a `warn!`
    (stream_macros.rs:38-53). Droppable events include reasoning Token
    deltas, ThinkStart/ThinkEnd, LlmUsage, MemoryRecalled, ToolBatchStart,
    ToolCall, ToolResult, ToolError, ContextCompressed. Terminal `Err` items
    are also sent with `try_send`: finalize.rs:226 (NoResponse), finalize.rs:267
    (max-iterations), think.rs:47,65 (interventions), tools.rs:285-292 (batch
    timeout), stream_channel.rs:310 (wrapper forward) — a full buffer can drop
    the terminal error entirely, leaving a raw stream that ends with no
    terminal; the envelope then fabricates a generic Error
    (event_envelope.rs:180-191), losing the specific error. Blocking
    (`send().await`) is used only for FinalAnswer, ToolStream, ToolBatchEnd,
    BudgetDecision.
  - **Bounded:** channel bounded (256); loop bounded only by natural
    termination when `max_iterations = 0` (EKO default; LoopDetector dead per
    F-RCT-02-P2-02 — cross-reference, not re-filed). The RwLockAgentWrapper
    re-stream (handle.rs:95-149) uses an unbounded channel (memory-growth
    risk, no drop).
  - **One terminal — VIOLATED on the raw stream (finding P2-02):**
    Stop-hook continuation after `FinalAnswer` (finalize.rs:179-201) allows a
    second terminal; `envelope_event_stream` truncates at the first terminal
    (event_envelope.rs:174-177), so product consumers are shielded while the
    loop keeps running unobserved (hidden LLM call + possible tool side
    effects; trace already `Completed`).
  - **Cancel — VIOLATED (finding P1-02):** ReactAgent overrides the cancel
    streaming methods (react/mod.rs:2821-2933) without `cancel_aware_stream`;
    `AgentEvent::Cancelled` never emitted by the main loop. The cancel test
    `test_run_stream_cancelled_mid_llm_call` (stream_channel.rs:1971-2038)
    asserts only "no FinalAnswer", confirming no Cancelled assertion exists.
  - **Conformance — VIOLATED (finding P2-01):** the main loop passes
    `emit_content_tokens = false` (think.rs:122; processor.rs:51-53), so
    content deltas are never streamed; the whole response is emitted as one
    `Token` burst at stream end (think.rs:224-247). Introduced by commit
    297fc54 (2026-06-17, "fix(agent): unify HITL approval and thinking
    streams"); before it, per-delta content Tokens were emitted. Direct-answer
    streaming still emits per-delta (stream_channel.rs:405-414).
  - **Test coverage (gap):** zero tests for buffer-full/backpressure; zero
    duplicate-terminal tests on the loop (the only related test is the
    envelope-level `normalizes_missing_and_duplicate_terminals`,
    event_envelope.rs:352-396); zero streaming/non-streaming conformance
    fixture; no test asserts a Cancelled event; no test for the direct-answer
    mid-stream error path; no test for trace status on abandon. Tests present
    cover: guard block (single terminal), execution-mutex queueing, text/tool
    turn terminal, DeepSeek replay, checkpoint/resume, budget decisions,
    usage events, cancel-no-final-answer, tool drain on cancel, steer
    mid-LLM (stream_channel.rs tests, 23 total).
  - **direct_answer_stream error-status mismatch (finding P2-03):** verified
    statically — `Ok(partial)` on chunk error → trace `Completed` + empty
    assistant push (stream_channel.rs:385-396,219-242). No test covers it.
  - **Abandon trace leak (finding P2-04):** every abandon path returns
    without `finalize_run`; no test asserts trace status after consumer-close
    or tool-batch cancel.
- Log/artifact: none
