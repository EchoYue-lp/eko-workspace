## Claim

For the selected critical tests (usage_reported, terminal monotonicity, claim
protocol, batch ordering), a mutation/negative-control analysis can determine
whether the test would actually fail when the production invariant is
violated, and whether the mock reproduces the real wire shape
(F-TST-01-P1-01/02 core question).

## Method

Read-only thought experiments on verified production code: for each selected
test, enumerate concrete mutations of production behavior and ask "would the
suite still pass?" The mutations were NOT applied (review is read-only); the
analysis is anchored to the exact assertions read in V02 and the production
lines verified at the current commit.

## Expected Result

A per-invariant sensitivity table: which regressions the suite catches, which
it structurally cannot, and which the suite actively blocks (wrong-invariant
pins).
