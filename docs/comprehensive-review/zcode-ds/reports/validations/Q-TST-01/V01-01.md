## Claim

The production-module-to-test map for the key production modules (ReAct loop,
task runtime, LLM adapters, compression, frontend stores) can be stated with
per-module test counts and a has-tests / no-tests / restates-implementation
classification, verified by source inspection at the reviewed commits.

## Method

1. For each primary production module, count `#[test]` / `#[tokio::test]` /
   `#[test_case]` attributes inside the file (`grep -c`) and check for a
   `tests/` integration crate.
2. Classify test drivers: grep for `MockLlmClient` / `then_text` /
   `then_tool_call` / `MockAgent` inside each test module to determine whether
   a test drives the real loop or a mock at the Agent-trait level.
3. Frontend: list `web-frontend/src/**/*.test.ts(x)` files and map each store
   module to its test file.
4. Verify the two load-bearing mock anchors at the current commit
   (`src/testing/mock_llm.rs` single-chunk `chat_stream`; `phases/think.rs`
   usage capture) and the batch completion-order push (`phases/tools.rs`).

Commands (all run in the respective repository roots):

```text
grep -rn "#[cfg(test)]" --include="*.rs" <repo>/src <repo>/<crates> | wc -l
for f in <module list>; do grep -c "#\[test\]|#\[tokio::test\]" $f; done
grep -c "MockAgent|MockLlmClient|then_tool_call" src/agent/react/tests.rs
find echo-agent-cli/web-frontend/src -name "*.test.ts*" | sort
grep -rn "then_tool_calls" src | grep -v "fn then_tool_calls"
```

suite, has none, or has tests that only restate implementation details.
