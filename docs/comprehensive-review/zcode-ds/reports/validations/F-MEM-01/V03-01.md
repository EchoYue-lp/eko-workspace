## Claim

The `echo-agent-cli/docs/MASTER-PLAN.md` Iteration 3 statement — "File
writes use unique temp names, file fsync, atomic rename, Unix
parent-directory fsync, cleanup on failure, path-safe ids, and explicit
corrupt-JSON errors" — holds item by item for the migrated file backends,
and ID-derived filenames are path-safe in the file-backed memory
implementations.

## Method

1. Quoted the claim context: `echo-agent-cli/docs/MASTER-PLAN.md:70` (the
   claim names `FileRuntimeStateStore`, `FileConversationStore`,
   `restore_message(s)` as the migrated impls).
2. Verified each sub-claim in `FileConversationStore`
   (`echo-state/src/memory/file_conversation.rs`):
   - unique temp names: `atomic_write` :502-506 (uuid-suffixed `.{name}.{uuid}.tmp`)
   - file fsync: :510-511 (`f.sync_all()`)
   - atomic rename: :517
   - Unix parent-dir fsync: :521 + `sync_parent_directory` :525-528
   - cleanup on failure: :513-519 (write and rename failure both remove tmp)
   - path-safe ids: `safe_segment` :465-486 (rejects empty, `/`, `\`,
     `.`/`..`, control chars; allows `[A-Za-z0-9._:~\x2d]`); tests
     :772-779
   - explicit corrupt-JSON errors: :103-105, :153-157, :235-237
3. Spot-checked the sibling migrated impl `FileRuntimeStateStore`
   (`echo-agent/src/state/file.rs:206-241` — unique tmp + fsync + rename +

Path-safety details: `safe_segment` allows `:` and `~`
(file_conversation.rs:472) — legal on macOS/Linux (RFC3339-style ids such
as `2026-07-28T10:00:00Z` depend on `:`), but `:` is illegal in NTFS
filenames and introduces Alternate-Data-Stream semantics on Windows; EKO
ids are frontend-generated ASCII (`conv-<ts>-<rand>`) so no current
trigger. Rejections are `MemoryError::Unsupported` — no panic.

## Deviations

None beyond the documented table. The MASTER-PLAN claim itself is accurate
for the three migrated impls; FileStore predates Iteration 3 and was not
part of the claim, but it remains a framework file backend whose weaker
write protocol (fixed tmp name, no parent sync, partial cleanup) diverges
from the hardened pattern and is exposed to two EKO processes sharing the
scheduler-store path (desktop.rs:175 / modes.rs:47) — promoted to
F-MEM-01-P2-01.

## Conclusion

Supports: all seven MASTER-PLAN sub-claims TRUE for the migrated file
backends; FileStore's atomic-write protocol and corrupt handling are
materially weaker; path-safety is enforced on IDs in the file backends with
a Windows caveat for `:`. Does not cover crash-durability proofs (power-loss
testing is out of scope) or SqliteStore (F-MEM-02).
