No `unimplemented!()` / `todo!()` found in any implementation.

InMemoryStore vs FileStore alignment: put/get/search/delete/list/
list_namespaces/prune_expired/dedup_by_content bodies are line-for-line
equivalent (only FileStore adds flush-on-mutation); both use the same
`tokenize`/`value_relevance_score` search scoring; both leave
`search_with` at the trait default (semantic → `MemoryError::Unsupported`).

Deviations (anchored):

1. Namespace key encoding is not injective: `namespace.join("/")`
   (store.rs:59, 85, 98, 128; FileStore 318, 340, 352, 386) makes
   `["a/b"]` collide with `["a","b"]`; `list_namespaces` splits on "/"
   (store.rs:153) making the round-trip lossy; prefix filter uses string
   `starts_with` (store.rs:148-151) so prefix `["user1"]` also matches
   `["user10", ...]`. Identical in both implementations.
2. `get_messages` returns records in file/insertion order
   (file_conversation.rs:378-386) while the trait doc promises "sorted by
   id ASC" (conversation.rs:136-137). Normal flows assign ids in call
   order so the two coincide; externally supplied out-of-order ids (test
   `supplied_message_ids_advance_the_live_counter`,
   file_conversation.rs:753-769) break the contract.
3. `EmbeddingStore` keeps `prune_expired`/`dedup_by_content` at the
   default no-op even though its inner store implements them; a call on
   the wrapper silently does nothing. No callers of either method exist
   in framework or EKO today (grep over `echo-agent/src`,
   `echo-state/src`, `echo-core/src` — zero hits outside definitions).

Duplicate search: single authoritative definitions of Store/
ConversationStore/StoreItem/StoredMessage in `echo_core::memory`; single
implementations in `echo_state::memory`; `SqliteStore`/
`SqliteConversationStore` (F-MEM-02 scope); `RuntimeStateStore`/`FileRuntimeStateStore`
live in root `src/state/` (other task scope) — no parallel memory-store
authority found. `safe_segment` appears twice (file_conversation.rs:465 and
src/state/file.rs:253) with identical logic — cross-module duplication, not
a second authority.

## Deviations

The three deviations above. No nondeterminism or environmental constraints.
