## Claim

The five-entry field matrix is uniform; long/Unicode/empty inputs are handled
without byte slicing or loss; attachment identity survives the
persist -> message -> TaskRun -> subagent round trip; conversation deletion
cleans the artifacts it is supposed to; every truncation in the input pipeline
is UTF-8-safe.

## Method

Static inspection of all six `UserTurnInput` construction sites
(send/steer x GUI/TUI + REPL + channel), `PreparedUserTurn::build`/`to_message`,
`attachments.rs`, the deletion paths (GUI `delete_conversation`,
TUI `/delete-session`), and grep for byte-slice patterns and for uploads-dir
cleanup; test inspection of prepared_turn.rs::tests and attachments.rs::tests.

```text
grep -n '&[a-zA-Z_]*\[\.\.' <all input-path files>          # byte-slice search
grep -rn "uploads" echo-agent-cli/src echo-agent-cli/echo-agent-app-core | grep -i "remove|clean|delete"
```

## Result

- Exit code: 0 (grep invocations); not-applicable (static inspection)
- Summary:
  - Field matrix (all six sites pass text, attachments, mode_hint, spill_dir,
    conversation_id, turn_id): uniform. Differences are intentional:
    steer paths pass `mode_hint: None` (no re-fold on injected input) and
    TUI/GUI steer pass the active/expected turn id; CLI/channel pass the
    mode-hint string like the send paths.
  - Long inputs: `should_spill` (prepared_turn.rs:389-399) spills at >=32 KiB
    or >=4,000 estimated tokens; spilled text is replaced by a reference block
    (path + sha256 + preview <= 400 chars, `artifact_preview`
    prepared_turn.rs:582-590) and the artifact is written atomically
    (.partial -> rename, prepared_turn.rs:540-551). Tests cover
    byte-threshold, token-threshold, paste-source-always-spill, and tail-
    content-absent-from-message (prepared_turn.rs:677-949; 14 tests, see
    V04-01).
  - Unicode: all truncation is `chars().take(N)` — artifact preview
    (prepared_turn.rs:583), TUI queue preview `chars().take(60)` and title
    `chars().take(80)` (events.rs:1333, 1360), webhook args summary
    `chars().take(240)` (chat_driver.rs:124), REPL trace detail
    `chars().take(500)` (repl.rs:585), channel flush threshold
    `chars().count()` and char-based sentence split (channels.rs:520-570).
    Byte-slice grep over the eight input-path files: zero hits. CJK and emoji
    fixtures pass (V04-01).
  - Empty inputs: TUI and CLI REPL skip empty lines (events.rs:1322,
    repl.rs:221-223); GUI steer and TUI steer reject empty instructions
    (chat.rs:741, events.rs:4229); GUI send has no backend empty gate but the
    frontend blocks empty sends (web-frontend/src/components/chat/ChatInput.tsx
    :621-622, :765) — finding A-INP-01-P3-03; channel path builds the turn even
    for empty text (channels.rs:208).
  - Attachment round-trip: upload -> `save_attachment` (base64 decode,
    uuid-prefixed filename, path traversal rejected by `sanitize_name`
    attachments.rs:126-143) -> `AttachmentRef` (path+name+mime+source) ->
    `InputResourceRef` -> `ContentPart::ImageUrl`/`File` in `to_message`
    (prepared_turn.rs:335-353); TaskRun carries `inline_attachment_refs`
    (prepared_turn.rs:312-323) and subagents rebuild via
    `build_message_from_refs` (executor.rs:2913/3073); persistence round trip

## Deviations

channel surface has no empty-message gate. No other deviations from the
documented invariants.

## Conclusion

(no byte slicing found in the input pipeline); attachment identity preserved

consequences of the two mismatches above — those are registered as findings
