## Claim

User-input normalization (text + attachments -> prepared turn -> one framework
Message) has exactly one authoritative implementation across both
repositories, with no parallel "spill"/"mode-hint fold"/"message merge"
implementation at any entry point, and no duplicate user-input-artifact
mechanism in `echo-agent`.

## Method

Repository-wide grep (both repos, excluding `target/`) for definitions and
production call sites of: `PreparedUserTurn`, `UserTurnInput`,
`resolve_user_input_spill_dir`, `cleanup_user_input_scope`,
`cleanup_user_input_older_than`, `user-input` (directory), `spill`,
`[Mode:` fold, `build_message` / `match multimodal`, `ContentPart` builders,
`AttachmentRef`, `AttachmentData`, `AttachmentSource`, `path_component`.

```text
cd echo-agent-cli && grep -rn "<symbol>" --include="*.rs" . | grep -v target
cd echo-agent && grep -rn "user_input|spill" --include="*.rs" src echo-tools/src echo-core/src | grep -v target
```

## Expected Result

One production definition per concept in `echo-agent-app-core`; zero parallel
user-input normalization implementations; framework contains only the generic
tool-output artifact mechanism (distinct concept).

## Deviations

The TUI `/steer` failure branch re-queues raw `AttachmentRef`s that
`PreparedUserTurn::build` has already consumed (spilled and, for Paste
attachments, deleted the staged copy) — the adapter is not idempotent over the
same refs. Registered as finding A-INP-01-P1-01. The CLI REPL resolves the
spill dir from `config.project` while the agent's artifact root stays global —
registered as A-INP-01-P2-01.

## Conclusion

Supports: one authoritative normalization implementation, one merge point, no
parallel second implementation in either repository (the framework spill is a
different, generic tool-output mechanism). Does not prove runtime behavior;
reachability and field parity are covered by V02-01 and V03-01.
