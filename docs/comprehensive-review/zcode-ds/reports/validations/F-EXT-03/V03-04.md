## Claim

`research_remember` and `research_recall`
(`echo-tools/src/research/memory.rs`) are non-functional stubs: the remember
tool discards the submitted findings and reports success ("Research findings
stored successfully") without persisting anything, and the recall tool always
returns "No research findings found" regardless of prior input — while their
descriptions promise a persistent knowledge base "across research sessions".

## Method

Static inspection (read-only):

1. Read `echo-tools/src/research/memory.rs` in full (182 lines).
2. `ResearchRememberTool::execute` (lines 66-121): `_entry` is built at
   96-102 and never stored; success message at 106-119; comments at 90 and
   104-105 ("In production, this would persist to SQLite" / "For now, return
   success message").
3. `ResearchRecallTool::execute` (lines 159-180): always returns the
   "No research findings found" message (172-179); the `limit` parameter is
   parsed and discarded (`_limit`, 166-169).
4. Registration: `register_all_tools` and `register_readonly_tools` both
   register both tools (`registry.rs:174-175`, 398-399).
5. No other consumer: grep for `research_remember|research_recall` across
   `echo-agent-cli` returned zero hits; no persistence layer, store, or
   connector references these names.

## Expected Result

The tools must either persist and retrieve the submitted findings (matching
their description) or return an explicit error/not-implemented status; they
must not claim success while discarding data.

## Result

- Exit code: not applicable (static inspection)
- Summary:
  - `research_remember` returns `ToolResult::success` with
    "Research findings stored successfully." after building a local JSON
    `_entry` that is dropped at the end of the scope (no store, no file, no
    state anywhere).
  - `research_recall` returns success with "No research findings found for
    query: ..." unconditionally; it can never return anything stored.
  - Descriptions (memory.rs:26-28, 137-140) promise "persistent knowledge
    base across research sessions" / "Recall past research findings".
  - The `// In production, this would persist to SQLite` comment (memory.rs:90)
    is itself stale relative to AGENTS.md (echo-agent-cli does not use
    SQLite; this is a framework-crate tool with no persistence of any kind).
