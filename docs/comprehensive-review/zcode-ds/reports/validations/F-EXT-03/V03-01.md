## Claim

`detect_iqr_outliers` (`echo-tools/src/data_quality.rs:249-255`) computes the
IQR quantile indices as `q1 = sorted[n / 4.min(n - 1)]` and
`q3 = sorted[3 * n / 4.min(n - 1)]`; for `n = 4` (the minimum accepted by the
caller guard `values.len() < 4` at `data_quality.rs:232-235`) the q3 index is
out of bounds and the tool panics on valid input.

## Method

The caller guard admits `n >= 4`. A standalone Rust program replicating the
exact arithmetic (`let q1 = n / 4.min(n - 1); let q3 = 3 * n / 4.min(n - 1);`)
was compiled and run for `n = 4..=20`:

```text
cd /tmp/f-ext-03-v03 && rustc -O iqr.rs -o iqr && ./iqr
```

(`iqr.rs` replicates only the index arithmetic; the in-bounds check mirrors
`sorted[idx]` panicking when `idx >= n`.)

## Expected Result

The index expressions must be `< n` for every `n >= 4` (no panic reachable
from the documented input domain).

## Result

- Exit code: 0 (program ran to completion printing per-n bounds checks)
- Summary:
  - `n=4`: q1_idx=1 (in bounds), **q3_idx=4 (out of bounds; would panic at
    `sorted[4]`)**.
  - `n=5..=20`: all q1/q3 indices in bounds.
  - No other failure value in the tested range.
- Log/artifact: `/tmp/f-ext-03-v03/iqr.rs`, printed table in this report.

## Deviations

The observed out-of-bounds index for n=4 is the defect under test; no other
deviations.

## Conclusion

Supports: `outlier_detection` with a numeric column containing exactly 4
finite values (IQR method) reaches `sorted[4]` on a 4-element vector → panic
(index out of bounds) in both debug and release profiles; Vec indexing panics
are not profile-dependent. This is the evidence for F-EXT-03-P1-03. The
existing test (`data_quality.rs:563-579`) uses 9 values and does not cover
n=4. Does not prove the panic propagates identically through every hosting
runtime (no catch_unwind barrier was found in the F-EXT-01/02 traces), but a
tool panic is a core-path failure regardless of the enclosing barrier.

## Follow-Up

A regression test must exercise IQR outlier detection on a 4-value numeric
column and assert a successful result.
