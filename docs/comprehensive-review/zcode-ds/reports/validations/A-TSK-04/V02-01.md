## Claim

Claim identity (`{revision, attempt, spec_hash}` and the derived
`{run}:{task}:{revision}:{attempt}` execution id) is durably persisted in the
event log, survives an event-sourced rebuild round trip, is restored into the
framework snapshot, and is consumed by recovery — so a restart reconstructs
the exact same claim identity without re-derivation or loss.

## Method

Full static trace of the claim lifecycle:

```text
1. claim creation: store.rs:986-1029 claim_task -> append_task_status_event (store.rs:1123-1176)
   with claim serialized into the TaskStarted event payload (store.rs:1169 "claim": claim)
2. persistence: file_shadow.rs:118-178 append_event_line (seq + payload to events.jsonl)
3. rebuild: event_rebuild.rs:207-252 task-status branch restores t.claim from payload
   (event_rebuild.rs:229-231); PlanRevisionCommitted branch preserves execution+claim for
   surviving task ids (event_rebuild.rs:147-162); skipped/reset ids clear claim (:183-193)
4. projection: types.rs:1081-1089 PlanTask::execution() -> EkoTaskExecution.claim
   (types.rs:922-929) -> run-state.json; store.rs:718-724 maps claim back into framework
   TaskExecution.claim on load_revisioned_task_graph
5. recovery consumer: store.rs:1668-1672 recover_incomplete derives execution_id from the
   rebuilt claim; store.rs:2039-2078 recoverable_subagent_result matches durable
   SubagentReleased by that execution id (step_id)
6. guard consumer: set_claimed_task_status/requeue_claimed_task compare the full claim
   struct against the rebuilt projection (store.rs:1048, 1081)
7. entry points: GUI/TUI/CLI task_execute (register.rs:45-130; src/tauri/desktop.rs,
   src/main.rs) -> ExecuteTaskTool::execute (task_execute_tool.rs:236-417) ->
   execute_run (executor.rs:321-434) -> execute_runtime_plan (executor.rs:1622-1683) ->
   RuntimeDagExecutor (framework runtime_executor.rs:196-449) -> controller claim_task
```

## Expected Result

Every hop preserves the claim; no hop truncates or re-derives it; recovery
identity derives exclusively from the persisted claim.

## Result

- Exit code: not-applicable (static trace)
- Duration: ~15 min
- Summary:
  - Claim written exactly once per dispatch at `claim_task` (attempt =
    `retry_count + 1`, spec_hash = `TaskSpec::stable_hash`), persisted in the
    TaskStarted event payload; rebuilt verbatim at event_rebuild.rs:229-231;
    carried through `EkoTaskExecution.claim` into `run-state.json`; mapped
    back into framework `TaskExecution.claim` at store.rs:723. Round trip is
    lossless (serde of the same struct both ways).
  - `set_claimed_task_status` re-writes the same claim into the terminal
    event payload, so the last task-status event carries the current claim;
    `TodoUpdated` events that clear state (`requeue_claimed_task` store.rs:
    1097, recovery resets store.rs:980, `retry_blocked_task` store.rs:1265-1278)
    explicitly write `"claim": null`, which the rebuild honors.
  - Attempt identity `{run}:{task}:{revision}:{attempt}` (runtime.rs:221-223)
    is consumed by: durable-result reuse (executor.rs:1292-1295, store.rs:
    1668-1674), recovery blocker keys (store.rs:1596-1618), hook correlation
    (hook_event_dispatcher.rs:355-394), and the frontend event contract.
  - `recover_incomplete` (store.rs:1631-1776) reads the rebuilt claim from
    the task projection (store.rs:1665-1672); if the claim were lost in the
    rebuild, durable-result reuse and blocker identity would silently break
    (re-dispatch or false Blocked). The rebuild chain above is lossless, and
    the tests `boot_recovery_reuses_completed_subagent_without_redispatch`
    (store.rs:2738-2807) and `runtime_plan_reuses_durable_subagent_result_after_restart`
    (executor.rs:5459-5520) pin the end-to-end behavior green.
