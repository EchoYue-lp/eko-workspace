## Claim

There is exactly one live claim/execution-identity authority in the DAG
execution path (`echo_agent::tasks::TaskClaim` produced by
`echo_orchestration::tasks::RuntimeDagExecutor` via the EKO
`TaskRuntimeStore` CAS), no second claim/ledger/replay implementation is
reachable from production, and the event-log ("ledger") is a single
append-only authority with one rebuild consumer.

## Method

Repository-wide grep over `echo-agent/` and `echo-agent-cli/echo-agent-app-core/`
for claim, attempt, ledger, replay, and rebuild symbols, plus reachability
traces for each hit:

```text
1. grep -rn "TaskClaim" echo-agent/echo-orchestration/src echo-agent-cli/echo-agent-app-core/src
2. grep -rln "claim_task|set_claimed_task_status|requeue_claimed_task|task_claim_is_current|RuntimeTaskClaimOutcome|ClaimWriteOutcome" both repos
3. grep -rn "ManagedTaskDagController|TaskExecutor" echo-agent/echo-orchestration/src (legacy second controller)
4. grep -rn "rebuild_plan_from_events|RebuiltPlan|replay" echo-agent-cli/echo-agent-app-core/src
5. grep -rn "seq_cache|append_event_line|read_events|rewrite_plan" echo-agent-cli/echo-agent-app-core/src (ledger authority)
6. read echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime/{mod,ledger}.rs to classify what "ledger" names
```

## Expected Result

One live claim authority; `tasks/executor.rs` legacy claim machinery
(`TaskExecutor`/`ManagedTaskDagController`) production-unreachable; the
"ledger" concept in the task card maps to `events.jsonl`
(`file_shadow.rs`), not the progress-markdown export module `ledger.rs`;
one rebuild consumer (`rebuild_plan_from_events`) on the write path only.
