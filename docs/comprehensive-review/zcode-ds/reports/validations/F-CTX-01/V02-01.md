## Claim

`ContextManager::prepare` is the single runtime context-selection and budget
decision point for both streaming and non-streaming agent turns, and its
tokenizer/budget/protected-content wiring is registered on the main path.

## Method

Static call-graph trace, numbered inspection:

1. Streaming entry: `run_stream_channel` → `run_core_loop`
   (`src/agent/react/run/stream_channel.rs:307,494`).
2. Non-streaming entry: `run_react_loop` → `run_core_loop`
   (`src/agent/react/run/react_loop.rs:713`).
3. `run_core_loop` iteration calls `phases::compact::run_compact` which calls
   `context.prepare(None)` (`src/agent/react/run/phases/compact.rs:55-60`);
   prepared messages then flow into `phases::think::run_think`.
4. Construction wiring: `ReactAgent::new_inner`
   (`src/agent/react/mod.rs:336-356`) — `ContextManager::builder(config.token_limit)`,
   tokenizer `CalibratedTokenizer(HeuristicTokenizer)`, `budget(...)` when
   `token_budget_config.enabled`, SlidingWindow default when
   `token_limit < usize::MAX` or budget enabled, `set_canonical_context`
   (:360-382).
5. Budget decision inside `prepare`: `budget.allocate(0, 0, estimated_tokens)`
   (`echo-state/src/compression/mod.rs:1299-1315`), compression only when
   `allocation.needs_compression()`.
6. Token estimation: `estimate_tokens` iterates messages and calls
   `tokenizer.count_tokens` on `content.as_text()` only
   (`echo-state/src/compression/mod.rs:1541-1547`).
7. Protected content: projections (envelope) are protected
   (`is_protected` :679-691); canonical re-injection after compression
   (:877-929, call sites :1070-1072, :1143-1145, :1202-1204, :1528-1530).
8. Tool schema accounting: `tools_for_request` only logs
   `schema_stats_for` observability (`think.rs:395-414`); never feeds the
   budget.
9. Calibration feedback: `think.rs:171-179` calls
   `calibrated_tokenizer.calibrate(estimated, pt)` where `estimated` counts
   messages only and `pt` is provider prompt tokens (includes tool schema and
   cache components).
10. EKO path: `infra.rs:258-262` sets `token_limit` =
    `DEFAULT_CONTEXT_WINDOW` (396_000, `infra.rs:23`) when not configured;
    `agent_pool.rs:433-436` applies `runtime.context_window` to token_limit
    only when explicitly set; `model_config.rs:153-159` infers the window only
    for the GUI model list view.

## Expected Result

One decision point (`ContextManager::prepare`) with the budget, tokenizer, and
canonical/projection protection registered and reachable; tool schemas and
multimodal parts accounted or explicitly not accounted.

## Result

- Exit code: not-applicable (static trace)
- Summary:
  - Confirmed single decision point: both loop paths share `run_core_loop` →
    `run_compact` → `prepare`.
  - Confirmed registration: tokenizer, budget, compressor, canonical context,
    projections, and horizon compressor all wired in `new_inner`/builder.
  - Confirmed not-accounted: tool schemas are observability-only (`think.rs:403-411`);
    multimodal `MessageContent::Parts` without text parts are invisible to
    `estimate_tokens` (`as_text` returns `None`, `types.rs:92-117`);
    reserved output (`max_tokens`) never subtracted from the window.
  - Confirmed EKO window gap: inferred model windows never reach the runtime
    token_limit/budget in the EKO construction path.
- Log/artifact: none

None.
