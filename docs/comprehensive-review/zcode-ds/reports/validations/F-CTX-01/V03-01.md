## Claim

Budget arithmetic is overflow-safe, all truncation is UTF-8-safe, the
provider window is mapped into the effective limit, and protected/canonical
content survives compression deterministically — for mixed-language and
large-schema inputs.

## Method

Falsifiable checks, each against current code:

1. Overflow audit of every budget/estimate arithmetic site:
   - `TokenBudget::*_budget` `(total_window as f64 * pct) as usize`
     (`echo-core/src/budget.rs:65-86`); `conversation_budget` uses
     `(1.0 - allocated).max(0.0)` (:81-86); `allocate` sums with plain `+`
     (:106); `TokenAllocation` excess via `saturating_sub` (:103).
   - `ContextManager::prepare` `effective_limit` uses `saturating_sub`/`max`
     (`echo-state/src/compression/mod.rs:1299-1305`); `estimate_tokens`
     sums token counts (:1541-1547); `HeuristicTokenizer` weights sum
     (`echo-core/src/tokenizer.rs:55`); `tune_for_model` `w * 60 / 100`
     (`levels.rs:107-114`) with `w` clamped ≤ 10_000_000
     (`src/config.rs:103`).
   - `ContextAssembler` `token_est += t` (`src/context/mod.rs:209,235`) and
     `snapshot.rs` spill truncation uses `saturating_mul/sub` (:1029-1035).
2. UTF-8 safety of every truncation: `to_reinjection_messages`
   `rules.chars().take(2000)` (`echo-core/src/compression.rs:385`);
   `snapshot.rs` head/tail truncation `chars().take/rev` (:1033-1035);
   `context/mod.rs` memory truncation `chars().take` (:186-190);
   EKO `truncate_to_estimated_tokens` `chars().take_while` (`project/prompt.rs:370-385`).
3. Provider window mapping: `infer_context_window`
   (`capabilities.rs:197-217`) consumers — `src/config.rs:99-104`
   (framework YAML path), `model_config.rs:153-159` (EKO GUI view only);
   `AgentConfig::new` default `DEFAULT_TOKEN_LIMIT = 396_000`
   (`agent/config.rs:11-12,234`); builder path never consults the model name;
   EKO `infra.rs:215-219,258-262` uses hardcoded 396_000; `agent_pool.rs:433-436`
   applies `context_window` only when explicit. Known small window in the
   inference table: kimi k2.6/k2.7 = 256_000 (`capabilities.rs:210-211`).
4. Budget-bucket enforcement: `prepare` calls `budget.allocate(0, 0, tokens)`
   (`mod.rs:1300,1311`); `TokenAllocation::needs_compression` is
   `conversation_excess > 0` only (`budget.rs:181-184`); `system_fits`,
   `tool_defs_fit`, `output_fits` computed but never consumed by `prepare`;
   tool schemas logged, not budgeted (`think.rs:403-411`); reserved output
   `max_tokens` never subtracted.
5. Protected-content survival: canonical re-injection dedup and insertion
   (`mod.rs:877-929`); `to_reinjection_messages` emits only project_rules
   (truncated) and active skill names — `skill_injections` field is never
   populated (`react/mod.rs:379`; only writers are empty Vec initializers);
   `add_skill` mutates `config.system_prompt` + `ctx.update_system` but never
   the canonical context (`capabilities.rs:587-597`), whereas `set_working_dir`
   refreshes `canonical.system_prompt` (`react/mod.rs:939`).
6. Multimodal accounting: `estimate_tokens` uses `content.as_text()`
   (`mod.rs:1541-1547`) which returns `None` for `Parts` without text
   (`types.rs:92-117`); `token_breakdown` same (:978-987).
7. Calibration input symmetry: `think.rs:171-179` calibrates
   `(estimated_messages_only, pt_includes_tools+cache)`.
8. Mixed-language fixtures present in the suite:
   `echo_state` compression tests use CJK messages
   (`mod.rs:2261-2263`); EKO `project::prompt` test
   `optional_modules_use_mixed_language_token_budgets_without_prompt_noise`;
   `HeuristicTokenizer` CJK unit tests (`tokenizer.rs:369-387`).

## Expected Result

No overflow risk, no byte slicing, window mapped on all construction paths,
and protected content preserved without silent truncation or stale re-injection.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Overflow: none found — all budget arithmetic is saturating or bounded by
    clamped windows; f64 intermediate casts stay within `usize` range.
  - UTF-8: all truncation sites use `chars()` iterators; no byte slicing.
  - Window mapping gap (finding F-CTX-01-P1-01): builder default and EKO
    runtime use hardcoded 396_000; inferred windows never reach the runtime
    budget. kimi k2.x (256K real window) gets a 396K budget window.
  - Bucket enforcement gap (F-CTX-01-P2-01): only the conversation bucket
    (65%) is enforced; system/tool/output allocations are computed but never
    checked; total vs window never compared.
  - Protected-content issues (F-CTX-01-P2-02): canonical rules re-injection
    truncates to 2000 chars; `skill_injections` dead; `add_skill` leaves
    canonical system prompt stale → first compression re-inserts the pre-skill
    prompt at index 0.
  - Multimodal exclusion (F-CTX-01-P3-01), hardcoded protected counts in
    `direct_answer_stream` (F-CTX-01-P3-02), calibration asymmetry
    (F-CTX-01-P3-03), and `ContextAssembler` byte-based estimate + dead budget
    fields (F-CTX-01-P2-03) confirmed.
- Log/artifact: none
