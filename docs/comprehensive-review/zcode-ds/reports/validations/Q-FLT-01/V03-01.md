## Claim

Fault scenario 3 (huge tool output beyond `max_tool_output_tokens`): the model
never receives unbounded output — a 2 MiB CJK tool result is either spilled to
a complete artifact with a bounded preview (EKO/default config) or head/tail
truncated with an explicit notice (fallback), both UTF-8-safe; artifact
checksum and payload are intact.

## Method

Real code path (`process_tool_output_for_call`, snapshot.rs:926-1065) via a
real `Tool` returning `"好" × 2,000,000 + "TAIL_MARKER"` (6,000,011 bytes):

```text
cd /tmp/qflt01-probe && cargo build
./target/debug/scn3_huge
# (a) ToolOutputArtifactConfig threshold 32 KiB + max_tool_output_tokens=4000
# (b) artifact root points at an existing FILE → persist_tool_output fails →
#     spill_error → head/tail truncation fallback with 200-token budget
# (c) threshold_bytes=1 → spill everything; verify sha256 in the model note
#     matches the artifact file's real digest and payload identity
```

## Expected Result

(a) ToolResult carries only the 500-char preview + `read_artifact` note; the
artifact file at the noted path holds the complete 6,000,011 bytes; (b)
truncated head+notice+tail, valid UTF-8; (c) note sha256 == actual digest,
payload identical.

## Deviations

- Framework default (agent/config.rs:253) already enables
  `ToolOutputArtifactConfig::default()` (temp dir, 1h retention) — so even
  without explicit configuration, oversize results spill rather than
  truncate. The head/tail truncation fallback (snapshot.rs:1025-1064) fires
  only when the artifact write fails (spill_error). Noted, not a finding
  (F-EXT-01 already documents the spill authority).
- The ToolResult event itself carries no truncation metadata (truncation is
  only visible in the output text); the EKO-side `output_bytes` label defect
  for spilled results is canonical X-TOL-01-P3-01.

## Conclusion

Supports: the huge-output invariant survives — model-visible output is always
bounded, the complete artifact is retrievable at the noted path with a
matching sha256, and both spill and truncation are UTF-8-safe on CJK payloads.
Does not prove: retention/cleanup behavior (1h/30d configs are product
policy, F-EXT-01 scope) or the GUI size label (X-TOL-01-P3-01).
