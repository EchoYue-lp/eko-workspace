## Deviations

- (a) FAILS: a mid-stream disconnect yields no terminal event; the partial
  content is discarded; the trace stays `Running` (canonical F-RCT-03-P2-04
  class — dynamically confirmed with trace status).
- (b) FAILS the core invariant: a clean EOF with partial content is accepted
  as the final answer and the trace is marked `Completed` with the partial
  text as `final_output`. `finish_reason` is never consulted by the streaming
  loop (processor.rs / think.rs have no read; grep confirms only the
  non-streaming react_loop.rs reads it). This is the same defect as the
  truncated-stream case (V01-01 (d)) — finding Q-FLT-01-P1-01.
- (c) SURVIVES at the adapter boundary: the envelope truncates at the first
  terminal and fabricates a single `Error` for terminal-less ends
  (event_envelope.rs:174-191), so EKO sinks see one terminal — but the
  fabricated error erases the true cause (cancel vs timeout vs disconnect).

## Conclusion

Supports: disconnect/EOF is the scenario with the clearest invariant break —
partial provider output becomes a "complete" final answer (P1-01, trace
Completed) while hard mid-stream errors end the raw stream terminal-less with
the trace left Running (canonical). Does not prove: EKO's exact render of the
fabricated envelope error (A-CHAT-01 scope).
