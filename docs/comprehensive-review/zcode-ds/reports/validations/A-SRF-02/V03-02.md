## Claim

The Tauri event-emission contract is coherent: each frontend channel has a
live producer, each producer emits once, terminal signals are truthful, and
payload keys are stable.

## Method

Inventory of emitted channels and producers in `src/tauri/**` and the
frontend listeners:

```text
channel           producers                                   consumers
chat://event      emit_chat_event (chat.rs:114-143)            useTauriChat.ts
execution://event emit_execution_event (chat.rs:153-183),
                  emit_tauri_execution_event (chat.rs:1419-1446),
                  mod.rs:751-752 (bridge)                      subagentRunStore.ts, useTauriChat.ts
browser://event   mod.rs:58 (only)                             useBrowserEvents.ts:12
terminal-output   terminal.rs reader thread :154               Terminal.tsx
terminal-exit     terminal.rs reader thread :148/:165          Terminal.tsx
```

For each producer, traced definition -> registration -> live caller, and
checked duplicate emission for the same logical event.

## Expected Result

Every channel has a live producer; one logical event is emitted at most once
per channel; payload keys (`kind`, `event`, `subagent_run_id`, `call_id`) are
stable across producers.

## Result

- Exit code: not-applicable (static trace)
- Duration: ~40 min
- Summary:
  - `chat://event`: single producer (`emit_chat_event`); the turn stream ends
    with `TurnStatus` + `ChatEvent::Done` (chat.rs:1365-1388) emitted by the
    sink, plus a second `TurnStatus` from the spawned drive task
    (chat.rs:709-711) — the GUI lifecycle wrapper invents terminal signals
    decoupled from the agent-stream terminal (cross-verified A-CHAT-01-P1-01;
    error-terminated turns are labelled "completed", chat.rs:690-696).
  - `execution://event`: three producers. For subagent tool lifecycle, TWO
    producers fire for the same logical event in the GUI: the SubagentEventBus
    bridge (mod.rs:388-530: `DispatchToolStarted`/`DispatchToolCompleted` ->
    `tool_executions.start/finish` + `emit_tool_execution_summary`) and the
    task-runtime trace path (`ExecEvent::subagent(ToolStarted/ToolCompleted)`
    via the sink (chat_driver.rs:221 / task_tools.rs:985 / revisioned_adapter
    .rs:173) -> TauriChatSink (chat.rs:1361-1364) -> `TauriExecutionProjector`
    (chat.rs:957-1114)). The framework publishes `DispatchToolStarted` for
    every dispatched subagent (echo-agent/src/agent/subagent/executor.rs:
    1284-1296), so both paths observe the same call. `ToolExecutionRepository
    ::start` creates a fresh `detail_ref` and overwrites the summary map each
    call (tool_execution.rs:191-239) — double `start` = duplicate
    "started" summary events + orphaned first detail files; double `finish`/
    `cancel` is possible; the two paths keep independent `active_tool_ids`
    bookkeeping.
  - `browser://event`: producer is inside the overwritten first `.setup()`
    (V02-01) — channel has NO live producer; frontend listener can never
    fire; browser views are never created (browserStore.ts:114-131). Defect
    A-SRF-02-P1-01.
  - `terminal-output`/`terminal-exit`: emitted directly from the PTY reader
    thread (terminal.rs:148-166), no intermediate bridge — live and single.
  - Payload keys: `execution://event` uses `kind` in {"run","task","subagent",
    "tool"}; `subagent_run_id`/`run_id`/`event` stable across the three
    producers; bridge and projector emit the same `call_id` summaries for the
    duplicated case.

## Deviations

Duplicate emission for subagent tool events (see summary) violates
"one producer per logical event" — recorded as A-SRF-02-P2-01. The dead
`browser://event` channel violates "live producer per channel" — recorded as
A-SRF-02-P1-01. `ChatDriverEvent::Interrupt` has zero producers (A-CHAT-01-
P2-01, cross-verified: chat.rs:516-534 emits `ChatEvent::InterruptPrompt`
directly, bypassing the shared sink).

## Conclusion

Supports: `chat://event` and terminal channels are single-producer and live;
`execution://event` keying is stable. Establishes the two emission-contract
defects (dead browser channel; duplicated subagent tool emission). Static
proof only; event counts under a real run belong to Q-E2E-01.
