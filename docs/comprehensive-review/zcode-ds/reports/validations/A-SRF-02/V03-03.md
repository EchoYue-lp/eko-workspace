## Claim

Application shutdown kills every child process the GUI spawned (PTY sessions,
browser sidecar) and stops long-lived loops; per-window close is handled.

## Method

1. Shutdown trace: `desktop.rs:255-268` — after `build_tauri_app(...).run()`
   returns (all windows closed), the code cancels the config-watcher/MCP-
   health/Dreaming token, calls `store.shutdown_hook_events()`, then
   `browser_runtime.shutdown().await`.
2. Terminal lifecycle: `TerminalManager::close_all` (terminal.rs:256-266)
   callers (grep); `close_terminal` command (terminal.rs:402-413); PTY reader
   thread behavior on process exit.
3. Browser sidecar shutdown: `browser_runtime.shutdown()` (app-core browser/
   mod.rs) and its coverage of sessions/clients.
4. Scheduler/background-task tokens: `state.scheduler.cancel_token` /
   `state.tasks.cancel_token` (state.rs:542,546) cancel callers (grep).
5. Session-end review: `on_session_end` callers (grep) vs GUI exit path.

## Expected Result

Every spawned child and loop has a stop path exercised on GUI exit; PTY
children are explicitly killed; no loop survives window close.

## Result

- Exit code: not-applicable (static trace)
- Duration: ~30 min
- Summary:
  - `desktop.rs:260-268` cancels the shared boot token (config watcher, MCP
    health, Dreaming), shuts the task hook dispatcher, then the browser
    runtime (sidecar + sessions). `browser_runtime.shutdown()` is a real stop
    path (browser/mod.rs).
  - `TerminalManager::close_all` (terminal.rs:256-266) has ZERO callers;
    GUI exit never kills live PTY sessions — child shells are left to the
    kernel (PTY master fd close -> SIGHUP on the foreground process group,
    not guaranteed for daemonized/reparented children). Same finding as
    A-BOOT-01-P3-03 (cross-verified, canonical in A-BOOT-01).
  - `state.scheduler.cancel_token` / `state.tasks.cancel_token` are never
    cancelled on the GUI exit path (or any exit path) — cron runner and
    background-task loop run until process exit (A-BOOT-01-P3-02,
    cross-verified).
  - GUI exit never calls `review_integration.on_session_end()` — the
    session-end memory review is TUI/CLI-only (A-BOOT-01-P2-03, cross-verified;
    only callers are main.rs:306-327 and repl.rs:419/454).
  - Per-window close: no `on_window_event`/close handler; cleanup runs after
    `.run()` returns when the last window closes — adequate for a single-window
    app, but there is no in-process reset primitive (workspace switch is the
    only partial-reset path).

## Deviations

All four gaps above are cross-referenced to A-BOOT-01 (P2-03, P3-01, P3-02,
P3-03); none are re-filed here. PTY orphan behavior is inferred from PTY
semantics, not dynamically reproduced (Q-E2E-01 scope).

## Conclusion

Supports: browser sidecar shutdown is wired; boot-token loops stop on exit.
Establishes: the GUI exit path does not kill PTY sessions and does not cancel
scheduler/background tokens — the `close_all` API exists but is dead.
