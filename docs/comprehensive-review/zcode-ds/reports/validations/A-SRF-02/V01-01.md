## Claim

The Tauri command layer is a thin adapter surface: every command maps to one
app-core service, per-turn state (turn-busy registry, cancel-token registry,
tool states) is owned in app-core, and no business concept is implemented twice
inside the Tauri layer.

## Method

Repository-wide duplicate/definition search over `echo-agent-cli` (and the
framework where event-bus producers live). Terms searched:

```text
IpcAuth | require_full_auto | require_not_strict | IpcPermission
browser://event | BrowserEvent forwarders | execution://event producers
ChatDriverEvent | TauriChatSink | TauriExecutionProjector
subagent_trace_sink_for | framework_trace_sink_for | DispatchToolStarted consumers
run_git | git_repo_root | parse_worktree_list | validate_branch_name
default_worktree_path | validate_worktree_target | WorktreeInfo
create_terminal | TerminalManager | close_all | PtySession
PENDING_RESPONSES | active_chat_turns | cancel_token | tool_states | mcp_config
save_config | worker (terminology check in the Tauri layer)
```

Inspection: `grep -rn` over `src/tauri/**` and `echo-agent-app-core/src/**`;
full reads of `src/tauri/mod.rs`, `state.rs`, `desktop.rs`, `ipc.rs`,
`terminal.rs`, `error.rs`, `path_validator.rs`, `commands/{chat,conversations,
config,mcp,task_runtime,tasks,files,scheduler,session,tools,tool_executions,
hooks,memory}.rs`; structural reads of `panels.rs`, `workspace.rs`,
`providers.rs`, `plugins.rs`, `research.rs`, `analysis.rs`; app-core anchors
`state.rs` (SessionState), `tool_execution.rs` (ToolExecutionRepository),
`tasks/task_runtime/worktree.rs`; framework anchor
`echo-agent/src/agent/subagent/executor.rs` (SubagentEventBus producer).

## Expected Result

One definition per command concept; commands delegate to app-core; no
duplicate git parsing, no second projection authority, no `worker` terms.

## Result

- Exit code: not-applicable (static inspection)
- Duration: ~2 h
- Summary:
  - Command-to-service map (219 `#[tauri::command]` annotations; all 218-219
    handlers registered in the single `invoke_handler`, `tauri/mod.rs:69-310`):
    browser/config/workspace/session/files/tasks/task_runtime/memory/tools/
    tool_executions/mcp/plugins/hooks/providers/scheduler/conversations/chat/
    panels/research/analysis + terminal all delegate to app-core
    (`AppState`, `AgentHandle`, `BrowserRuntime`, `TerminalManager`); no
    command re-implements an app-core algorithm except the three exceptions
    below.
  - Per-turn state is app-core-owned: `active_chat_turns`, `cancel_token`,
    `tool_states` are fields of `AppState.session` (SessionState,
    `echo-agent-app-core/src/state.rs:347-352`), created at `state.rs:485-487`.
    Tauri commands only read/write them.
  - Duplicate authority found:
    1. `parse_worktree_list`/`run_git`/`git_repo_root`/`validate_branch_name`/
       `default_worktree_path`/`validate_worktree_target` implemented twice:
       `src/tauri/commands/panels.rs:1804-1930` AND public copies in
       `echo-agent-app-core/src/tasks/task_runtime/worktree.rs:149,194,202,
       218,245,272`. The panels.rs copy parses only `worktree`/`HEAD`/`branch`
       lines; the app-core copy additionally parses `locked`/`lock_reason`
       (app-core `WorktreeInfo` fields, worktree.rs:97-107, absent from the
       panels.rs struct at panels.rs:1788-1793).
    2. Subagent tool-execution projection has two live producers:
       `tauri/mod.rs:388-530` (SubagentEventBus bridge) and
       `commands/chat.rs:957-1114` (`TauriExecutionProjector::project_tool_event`,
       fed via `ChatDriverEvent::Execution` from the task-runtime trace sink,
       `chat_driver.rs:221` / `task_tools.rs:985` / `revisioned_adapter.rs:173`).
       Framework publishes `DispatchToolStarted` on the bus for every
       dispatched subagent (`echo-agent/src/agent/subagent/executor.rs:1284-1296`).
       `ToolExecutionRepository::start` is non-idempotent: fresh `detail_ref`
       per call and summary-map overwrite (`tool_execution.rs:191-239`).
  - `IpcAuth`/`IpcPermission` (`src/tauri/error.rs:15-70`): zero callers in
    either repository; dead gate machinery plus a stale "Phase 6.2" header
    (error.rs:3-10) describing it as active.
  - No `worker` terminology in the Tauri layer.

## Deviations

`TauriChatSink` (chat.rs:1148-1331) owns durable `ToolExecutionRepository`
projection state — a third projection-related authority in the adapter; its
authority classification is A-CHAT-01-P2-02 (cross-verified, canonical in the
A-CHAT-01 report, not re-filed). `conversations.rs:65-150`
(`project_saved_messages`) is an adapter-owned canonical-vs-UI merge
algorithm; its persistence authority is A-STATE-01 scope (cross-referenced,
not re-filed).

## Conclusion

Supports: commands are thin and state is consistently app-core-owned (the
task-question baseline holds). Establishes the two duplicate-authority
exceptions (worktree helpers, subagent tool projection) and the dead
`IpcAuth` machinery. Does not prove runtime behavior (see V02/V03).
