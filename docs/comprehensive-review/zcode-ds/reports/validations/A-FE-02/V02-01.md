## Claim

Every producer and consumer of the frontend task/subagent/tool projections is
registered and reachable at runtime, and the producer sets are exactly:
single producer for `execution://event kind=subagent` and for chat-owner tool
summaries; two producers for subagent tool summaries (the known A-SRF-02-P2-01
double projection); durable replay as the reload path.

## Expected Result

All listeners registered in `useTauriChat` (single mount site), all Tauri
commands registered in `invoke_handler`, kind=subagent emitted only by the
bridge, and the replay path restoring the same stores idempotently.

## Result

- Exit code: not applicable (static trace)
- Summary:
  - `kind=subagent` events: single live producer (bridge, mod.rs:353-768);
    the projector handles only tool events and cancels active tools on
    terminal (chat.rs:957-1114) — it does not emit kind=subagent events.
  - `kind=tool` subagent summaries: TWO live producers (bridge + projector)
    both call `tool_executions.start()` for the same (owner, call_id) —
    cross-confirmed A-SRF-02-P2-01 (fresh `detail_ref` per start,
    tool_execution.rs:191-239).
  - `kind=tool` chat summaries: single producer (sink/projector path).
  - Reload path: `loadByConversation` replays TaskRuntime events through the
    same stores with idempotent guards (terminal runs drop replayed events,
    subagentRunStore.ts:458-460); tool rows re-merged by (owner, call_id)
    identity (toolExecutionStore.ts:188-200).
  - Tool detail lazy-load chain reachable: InlineToolCall -> endpoints
    detail/readOutput -> registered commands.
  - Run-level artifact fetch (`listArtifacts`) reachable but backed by a
    backend projection with zero production writers (A-TSK-06-P2-01); the
    frontend `RuntimeArtifact[]` is always `[]` in production.
  - Non-TaskRuntime inline subagent runs have no durable replay source:
    `conversationStore.loadConversation` (conversationStore.ts:296-320)
    restores only tool summaries (`hydrateConversation`), not
    `subagentRunStore` (→ P3-02 evidence).

## Deviations

The double subagent-tool producer is known (A-SRF-02-P2-01) and intentionally
not re-validated end-to-end here; the frontend consumers and their reachability
are what this validation establishes. The missing subagent-run restore path
(P3-02) is a new observation recorded as a finding.

## Conclusion

Supports: the consumer/producer wiring is complete and live for chat://event,
execution://event, tool detail lazy-load, and TaskRuntime replay; the
duplicate subagent tool projection (A-SRF-02-P2-01) reaches the frontend as
two distinct rows per logical call (P2-01); the run-level artifact list is
dead-end-to-end (A-TSK-06-P2-01). Does not prove: event ordering under real
concurrency (fixtures in V03), or rendering behavior on screen (Q-E2E-01).
