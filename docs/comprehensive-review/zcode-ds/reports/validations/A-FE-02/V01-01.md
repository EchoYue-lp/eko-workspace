## Claim

Frontend task/subagent/tool projections have exactly one definition and one
authority per concept, the legacy parallel stores are deleted, and identity
helpers exist so reducers can key on the logical identity ((owner, call_id) for
tools; `{run_id}:{task_id}:{plan_revision}:{attempt}` execution id for subagent
runs; run_id/task_id for tasks) rather than producer-assigned ids.

## Method

Repository-wide definition/duplicate search over `echo-agent-cli/web-frontend`
and `echo-agent-cli/echo-agent-app-core` (and `echo-agent` where relevant):

```text
1. grep -rn "subagentTraceStore\|subagentStore" web-frontend/src   # legacy stores deleted?
2. grep -rn "executionIdentity\|toolExecutionOwnerKey\|subagentRunStoreKey\|latestSubagentRunsByTask" web-frontend/src
3. grep -rn "ToolExecution\|SubagentRun\|subagent_run_id" web-frontend/src/stores   # projection stores inventory
4. grep -rn "ResultFullView\|PlanEditor" web-frontend/src          # dead component check (excl. own files)
5. grep -rn "acceptance_criteria\|execution_checks\|required_artifacts" web-frontend/src (excl. generated/tests)
6. grep -rn "useWebSocket" web-frontend/src                       # second transport surface?
7. echo-agent: TaskClaim::execution_id format (echo-orchestration/src/tasks/runtime.rs:212-224)
8. echo-agent-cli: subagent_execution_id / subagent_run_id format (executor.rs:174-180, types.rs:1654-1668)
```

## Expected Result

One store per concept; zero `worker`/legacy `subagentTraceStore`/`subagentStore`
definitions; identity helpers present; no parallel projection implementation
that would create a second authority; the execution-id format
`{run_id}:{task_id}:{plan_revision}:{attempt}` confirmed on the backend so the
frontend can parse revision+attempt.

## Result

- Exit code: not applicable (grep/read-only inspection)
- Summary:
  - Legacy `subagentTraceStore`/`subagentStore` are gone; the only remaining
    mention is the deletion note in `subagentRunStore.ts:6-8` (Phase 4c).
  - Exactly four stores touch tool/subagent projections: `toolExecutionStore`,
    `subagentRunStore`, `taskRuntimeStore`, `conversationStore` (tool hydration
    only) — no parallel projection store exists.
  - Identity helpers exist: `toolExecutionOwnerKey`/`executionIdentity`
    (toolExecutionStore.ts:16-48, identity = owner+run_id+call_id),
    `subagentRunStoreKey` (subagentRunStore.ts:157-159), `executionAttempt`
    (subagentRunStore.ts:407-414, parses the trailing `:attempt` segment only),
    `latestSubagentRunsByTask` (:417-441), `traceRunForTodo`/
    `displayedTodoStatus` (TaskRuntimePanel.tsx:429-486).
  - Backend execution-id format confirmed: `TaskClaim::execution_id` =
    `{run_id}:{task_id}:{revision}:{attempt}` (echo-orchestration
    runtime.rs:221-223); `subagent_run_id` aligns (app-core types.rs:1657-1662).
  - Deviations found (became findings):
    - Live tool ingest stores rows keyed by the producer-assigned wire id
      (`tool.id` = `detail_ref`), not by the available (owner, call_id)
      identity (toolExecutionStore.ts:206-217 `ingest`); the identity-based
      merge exists only for hydration/replay paths (→ P2-01).
    - `latestSubagentRunsByTask` parses only the attempt segment and ignores
      `plan_revision` (→ P2-02, empirically reproduced in V03-02).
    - `acceptance_criteria`/`execution_checks`/`required_artifacts` exist in
      generated types and patch passthrough but have zero rendering or editing
      consumers in components (→ P2-03).
    - `ResultFullView` and `PlanEditor` have zero imports anywhere in `src/`
      (dead components; → P3-01).
    - `useWebSocket` no longer exists (removed; comment references only).
  - No `worker` terms introduced; subagent terminology consistent.

## Deviations

The deviations above are the point of this validation — they were recorded as
candidate findings and are expanded in V03-01/V03-02 (executable replays) and
the task report. No false positives were found in the dead-component grep
(no dynamic `import()` of `ResultFullView`/`PlanEditor` exists).

## Conclusion

Supports: single definition/authority per projection concept on the frontend;
identity helpers exist and match the backend execution-id format; the
`{run_id}:{task_id}:{plan_revision}:{attempt}` contract is confirmed. Does not
prove: runtime behavior of the reducers (covered by V03 fixture replays and
V04 test runs). The live-ingest identity gap (P2-01), revision-ignoring attempt
selector (P2-02), missing acceptance/check/artifact surface (P2-03), and dead
components (P3-01) are definition-level defects surfaced by this validation.
