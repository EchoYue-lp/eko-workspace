## Claim

`latestSubagentRunsByTask` (subagentRunStore.ts:417-441) selects the latest
attempt per PlanTask as documented ("defaults to the latest attempt when
rendering a task" — app MASTER-PLAN), including across plan revisions, where
the execution id is `{run_id}:{task_id}:{plan_revision}:{attempt}`.

## Method

Transient vitest file replaying the real reducer:

```text
npx vitest run src/__fe02_tmp__/fe02-revision.test.ts
```

Fixture: same run_id + task_id; store contains revision 4 attempt 3
(completed) and revision 5 attempt 1 (running, started later — plan was
revised and the task re-dispatched). Assertion records which record
`latestSubagentRunsByTask` returns.

## Expected Result

The selector must return the revision-5 attempt (the current plan's
execution); revision-4 attempt 3 is superseded.

## Result

- Exit code: 0
- Duration: 0.16 s
- Summary: the single test passed and documents the observed behavior —
  `latestSubagentRunsByTask` returns `run-1:task-1:4:3` (old revision,
  terminal `completed`) instead of `run-1:task-1:5:1` (current revision,
  running). Root cause confirmed statically: `executionAttempt`
  (subagentRunStore.ts:407-414) parses only the trailing `:attempt` segment
  (`Number('3') > Number('1')`), so `plan_revision` is ignored; the grouping
  key is `${runId}\u0000${taskId}` (revision-agnostic). Meanwhile
  `traceRunForTodo` (TaskRuntimePanel.tsx:429-433) sorts by `startedAt`, so
  the right rail picks the revision-5 attempt — the two "latest attempt"
  selectors diverge after a plan revision.
- Log/artifact: none kept (transient file deleted).

## Deviations

The observed behavior violates the claimed invariant — this is the expected
outcome of the validation and becomes finding A-FE-02-P2-02.

## Conclusion

Supports: the latest-attempt selection is revision-agnostic and empirically
returns the superseded revision's attempt after a plan revision; the right
rail and the inline chat view can disagree about which attempt is current.
Does not prove: how frequently plan revisions re-dispatch already-executed
tasks (backend behavior, A-TSK-01/A-TSK-04 scope), or the on-screen rendering
consequence (static reachability: `visibleSubagentRuns` →
`latestSubagentRunsByTask` → `SubagentStreamBlock`).
