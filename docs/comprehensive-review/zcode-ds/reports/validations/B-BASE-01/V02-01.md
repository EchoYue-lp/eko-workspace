## Claim

The declared feature-to-dependency graph is: root framework features forward to
owner sub-crates and optional deps; CLI features forward only to framework
features (`channels`, `telemetry`) plus local optional deps (`tui`, `gui`,
`devtools`); and neither CLI workspace member enables the framework `sqlite`
feature or any SQLite-carrying dependency.

## Method

1. Read all `[features]` sections of all 10 manifests (recorded in V01).
2. For each root framework feature, map it to either `dep:` optional
   dependencies, `echo_<crate>/<feature>` forwarding, or `[]` marker.
3. Extract the feature lists enabled by both CLI workspace members on
   `echo_agent` (Cargo.toml:50 and echo-agent-app-core/Cargo.toml:10-15).
4. Grep both CLI `Cargo.lock` files for SQLite-carrying crates
   (`rusqlite`, `libsqlite3-sys`, `sqlx-sqlite`, `sqlx`).

## Expected Result

- 35 root features on `echo_agent` (metadata), 13 of them empty markers;

- CLI root enables mcp/lsp/human-loop/subagent/tasks; app-core enables

- CLI lockfiles contain zero SQLite crates.
