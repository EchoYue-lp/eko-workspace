## Claim

For both workspaces: (a) every build script is enumerated and inspected;
(b) native (C/asm) dependencies and their pullers are identified with
link-in-graph status; (c) license metadata of all workspace crates and of the
third-party graph is checked for non-permissive/copyleft obligations.

## Method

```text
# 1. Build scripts:
find echo-agent echo-agent-cli -name build.rs (excl. target/, node_modules/)
cat echo-agent-cli/build.rs
# 2. Native/build-script crates in CLI lockfile + pullers:
grep -E '^name = "(tree-sitter|onig|onig_sys|openssl-sys|...)"' Cargo.lock
cargo tree --locked -i ring / onig_sys / tree-sitter / openssl-sys / webkit2gtk / wry
# 3. Registry source inspection:
cat ~/.cargo/registry/src/*/polars-ops-0.53.0/build.rs
ls ~/.cargo/registry/src/*/onig_sys-69.9.3/build.rs; grep cc:: onig_sys build.rs
# 4. Workspace license fields:
grep '^license' all 10 workspace Cargo.toml files
# 5. Third-party license scan (both lockfiles, ~/.cargo/registry/src/*/ Cargo.toml):
python3: license field per lockfile package; flag GPL/LGPL/MPL/CC*/Unlicense/BSL/AGPL/SSPL
```

Environment: cargo 1.97.1; registry mirror `rsproxy-sparse`; source crates
extracted under `~/.cargo/registry/src/rsproxy.cn-e3de039b2554c837/`.

## Expected Result

Few build scripts, all understood; native C dependencies are the standard
bundled set (tree-sitter grammars, oniguruma, ring/zstd) with a working
toolchain requirement; licenses are permissive with no strong copyleft.

## Result

- Exit code: 0 (all inspection commands; `cargo tree -i openssl-sys` reported
  "nothing to print", `webkit2gtk`/`wry` "did not match any packages" under
  default features — both are gui-only, lockfile-universe entries).
- Summary:
  - **Build scripts**: exactly one workspace build.rs —
    `echo-agent-cli/build.rs`: gates `tauri_build::build()` on
    `CARGO_FEATURE_GUI`; uses `unwrap_or_default()` (no panic); `tauri-build`
    remains an unconditional build-dependency (compiles with the default
    binary too). No build.rs in any framework crate.
  - **polars-ops 0.53.0 build.rs** (transitive, via polars): contains
    `version_check::Channel::read().unwrap()` — panics when rustc probing
    fails (restricted/cross/vendored build environments). The framework root
    `echo-agent/Cargo.toml:59-63` explicitly documents this class of failure
    ("polars-ops 0.46–0.53 has a build.rs that fails on some platforms",
    upstream fix unreleased) and **excludes `data` from the default feature
    set**; EKO re-enables `data` + `statistics` (`echo-agent-cli/
    echo-agent-app-core/Cargo.toml:13`), so the shipped CLI build depends on
    this fragile build script. No failure observed in this environment
    (workspace compiles; Q-STA-01 ran full all-feature clippy builds).
  - **Native C in the shipped default CLI binary** (each verified with its
    puller):
    - `tree-sitter` 0.26.11 + 6 grammar crates (rust/python/javascript/
      typescript/go/java), gated behind echo-tools' `files` feature, which
      EKO enables — C grammar sources compiled at build time.
    - `onig_sys` 69.9.3 → `onig` → `syntect 5.3.0` (TUI syntax highlighting,
      `regex-onig` feature): compiles the bundled oniguruma C library via
      `cc::Build` (build.rs:65-67).
    - `ring` 0.17.14 → `object_store` → polars stack: bundled C/asm crypto.
    - `zstd-sys`, `flate2` (zlib-rs): compression stack of polars.
    - macOS: `security-framework`/`native-tls` (native TLS, no OpenSSL);

  - **GUI-only natives** (linked only with the `gui` feature):
    `wry`/`webkit2gtk`/`gtk`/`objc2-app-kit` via tauri; `portable-pty`; not
    part of the default TUI/CLI binary.
  - **Licenses — workspace**: all 10 workspace crates declare `license =

    license field** (minor metadata gap).
  - **Licenses — third-party graph (both lockfiles, 1524 package entries)**:

- Log/artifact: none (all outputs short; scan script inline).

## Deviations

- License strings were read from registry-extracted `Cargo.toml` files; a
  package whose source is not in the local cache could not be classified
  (none found: every lockfile package resolved to a cached source).
- The license scan checks the declared `license` field, not file-level
  headers or vendored text; MPL-2.0 file-level obligations were not audited
  per file.

## Conclusion

The build-script and native-dependency surface is small and understood: one
workspace build.rs (safe), bundled C toolchains (tree-sitter grammars,
oniguruma, ring, zstd) that any desktop build must compile, and one
transitive build script (polars-ops) with a documented panic path that the
framework explicitly avoids by default but EKO re-enables via `data`/
`statistics`. Licenses are permissive throughout with no strong copyleft;
MPL-2.0 file-level notices are the only distribution obligation. These
observations feed findings Q-DEP-01-P3-04 (polars build fragility divergence)
and the licensing/metadata notes in the task report. It does not prove
build success on every target platform (only this environment was built).
