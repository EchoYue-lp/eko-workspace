## Claim

Duplicate crate versions in the resolved build graph of both workspaces are
enumerated (`cargo tree -d`), the notable splits (reqwest, crossterm) are
traced to their pullers, and every split is classified as linked-in-graph
versus lockfile-only.

## Method

```text
# 1. Resolved-graph duplicates (default features, --locked):
cd echo-agent        && cargo tree -d --locked > /tmp/qdep-v01-fw-tree.txt   (exit 0, 210 lines)
cd echo-agent-cli    && cargo tree -d --locked > /tmp/qdep-v01-cli-tree.txt  (exit 0, 1396 lines)
# 2. Lockfile-universe enumeration (all versions Cargo ever resolved):
python3 Cargo.lock parse: group by name, flag names with >1 version
# 3. Reverse-path traces for the notable splits (CLI workspace):
cargo tree --locked -i reqwest@0.13.3            # "did not match any packages"
cargo tree --locked --all-features -i reqwest@0.13.3   # "nothing to print"
cargo tree --locked --target all -i reqwest@0.13.3     # "did not match any packages"
cargo tree --locked -i reqwest@0.12.28           # direct via echo-agent/app-core/tauri-adjacent stack
cargo tree --locked -i crossterm@0.29.0          # comfy-table 7.2.2 -> polars-core 0.53.0 -> polars 0.53.0 -> echo_agent/echo_tools
cargo tree --locked -i crossterm@0.28.1          # echo-agent-cli direct + ratatui 0.29.0 + reedline 0.38.0
# 4. reqwest 0.13.3 puller identification in Cargo.lock (v4 format):
python3: packages whose dependency list references "reqwest" (version-qualified)
# 5. Framework feature wiring that pulls polars into the CLI graph:
grep polars echo-agent/Cargo.toml; grep features echo-agent-cli/echo-agent-app-core/Cargo.toml
```

Environment: cargo 1.97.1; crates.io registry replaced by the `rsproxy-sparse`
mirror (`~/.cargo/config.toml`); all commands offline against the local
registry cache except `--target all` which downloaded target-gated crates.

## Expected Result

Duplicate versions are predominantly transitive ecosystem splits; the two
previously filed splits (reqwest 0.12/0.13, crossterm 0.28/0.29, canonical ID
Q-STA-01-P3-03) are re-verified and their pullers pinned down; any new
directly-controllable duplicate is flagged.

## Result

- Exit code: 0 (all tree commands; the two `-i reqwest@0.13.3` queries exited 1 with "did not match any packages" — itself the finding below)
- Summary:
  - **echo-agent: 38 multi-version names in the lockfile**; in the
    default-feature resolved graph only 12 entries duplicate:
    `core-foundation` 0.9.4/0.10.1 (reqwest TLS stack: system-configuration vs
    security-framework), `getrandom` 0.3.4/0.4.2 (rand 0.9 vs uuid/tempfile),
    `hashbrown` 0.14.5/0.17.0 (dashmap vs indexmap), `itertools` 0.10.5/0.14.0
    (criterion dev-dep vs prost-derive), plus the serde_json/serde_core/memchr
    internal-split display artifacts. All are transitive; no duplicate in the
    framework's own `[dependencies]`.
  - **echo-agent-cli: 76 multi-version names in the lockfile**; in the
    default-feature graph the notable splits are:
    - **`crossterm` 0.28.1 + 0.29.0 — both LINKED in the shipped binary.**
      0.28.1: direct `echo-agent-cli` dep + `ratatui 0.29.0` + `reedline
      0.38.0` (the TUI input stack). 0.29.0: `comfy-table 7.2.2` →
      `polars-core 0.53.0` → `polars 0.53.0` → `echo_agent` + `echo_tools`.
      polars enters because EKO enables the framework `data`/`statistics`/
      `chart`/`research` features (`echo-agent-app-core/Cargo.toml:10-15`).
    - **`reqwest` 0.12.28 + 0.13.3 — NOT a real duplicate.** 0.13.3 is
      referenced in the lockfile only by `tauri 2.11.2`, whose reqwest
      dependency is declared under
      `[target.'cfg(any(target_os = "android", all(target_vendor = "apple",
      not(target_os = "macos"))))'.dependencies.reqwest]` (tauri-2.11.2
      Cargo.toml:321) — i.e. **mobile targets only**. No feature combination
      of the CLI workspace (`--all-features`, `--target all`) resolves it;
      no desktop build can link it. Lockfile-v4 records the whole universe
      (all targets/features), which is why the entry exists.
  - Other CLI duplicates (base64 0.21/0.22, bincode 1/2, toml 0.8/0.9/1.x,
    thiserror 1+2, syn 1+2, windows-sys 6 versions, rand 0.8/0.9/0.10,
    html5ever 3 versions, phf 3 versions, quick-xml 5 versions) are
    transitive ecosystem splits with no security-sensitive split version.
- Log/artifact: `/tmp/qdep-v01-fw-tree.txt`, `/tmp/qdep-v01-cli-tree.txt`
  (full `cargo tree -d` outputs).

## Deviations

- The `--target all` run triggered downloads of target-gated crates (x11rb
  etc.) from the rsproxy mirror and emitted "spurious network error" retry
  warnings; the query still completed and its negative result (reqwest 0.13.3
  absent) is valid because lockfile-v4 contains the full target universe.
- `cargo tree -i` traces were run under default features; framework feature
  combinations beyond those EKO enables were not each traced (the polars path
  was traced end to end, which is the only framework-feature puller of a
  notable split).

## Conclusion

Duplicate versions are widespread but benign in kind. The two previously
filed splits (Q-STA-01-P3-03) are re-verified with this refinement: the
reqwest 0.12/0.13 "split" never materializes in any desktop build (0.13.3 is
mobile-target-only via tauri) — it is a lockfile-universe entry, not a second
HTTP client in the shipped app; the crossterm 0.28/0.29 split is real and
linked (polars is the sole puller of 0.29). No new directly-controllable
duplicate found. This does not prove absence of security-relevant version
splits — that is the advisory scan's claim (V03).
