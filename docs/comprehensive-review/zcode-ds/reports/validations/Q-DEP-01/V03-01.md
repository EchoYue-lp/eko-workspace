## Claim

Both `Cargo.lock` files are scanned against the RustSec advisory database and
every advisory is classified as live (linked in the shipped default-feature
binary), build-time-only, or lockfile-universe-only (never linked), with the
puller traced for the live ones.

## Method

```text
# Environment: cargo-audit 0.22.2 installed via `cargo install cargo-audit
# --locked` (crates.io mirror rsproxy-sparse). github.com:443 is unreachable
# from this host (curl 000; `git ls-remote` RPC failed after 75 s), so the
# advisory DB was fetched from the reachable tarball endpoint:
curl -sL -o /tmp/advisory-db.tar.gz https://codeload.github.com/rustsec/advisory-db/tar.gz/refs/heads/main
mkdir /tmp/advisory-db && tar -xzf ... --strip-components=1
cd /tmp/advisory-db && git init -q && git -c user.name=review -c user.email=review@local add -A \
  && git -c user.name=review -c user.email=review@local -c commit.gpgsign=false commit -qm snapshot \
  && git remote add origin /tmp/advisory-db
# (local origin + --stale lets cargo-audit read the DB without network)
cargo-audit audit --db /tmp/advisory-db --stale      # in echo-agent/ and echo-agent-cli/
# Reachability of every flagged crate in the CLI workspace (default features):
cargo tree --locked -i <crate>@<version>             # live vs "nothing to print"
cargo tree --locked --target all -i <crate>@<version>
# Feature/registration proof for the live parsers:
grep PdfExtractTool/PdfInfoTool echo-agent/echo-tools/src/registry.rs
grep features echo-agent-cli/echo-agent-app-core/Cargo.toml   # media/research/data enabled
```

DB state: 1216 advisories loaded (snapshot of rustsec/advisory-db @ main,
2026-08-12). Advisory data is as of the snapshot; the date of each advisory is
in the output.

## Deviations

- cargo-audit's normal DB fetch (github.com git) is impossible here; the DB
  was snapshotted from the codeload tarball and served from a local git repo
  with a loopback `origin` + `--stale`. DB freshness is the snapshot date
  (2026-08-12), not a live fetch; new advisories published after the snapshot
  are not covered (e.g., anything newer than 2026-07-13 in this run).
- Reachability was determined under the CLI workspace's default features
  (`tui`); the `gui` binary adds tauri/wry/gtk but shares the same lockfile
  (its extra crates were classified; none adds a live advisory beyond the
  unmaintained gtk stack).
- "LIVE" means the crate is linked into the default binary and its vulnerable
  code path is plausibly reachable via EKO's registered tools
  (PdfExtractTool/PdfInfoTool registered at `echo-tools/src/registry.rs:97,
  312`; xlsx via `echo-tools/src/excel.rs`); it does not prove the exact
  vulnerable function is invoked by EKO's usage patterns.

## Conclusion

The advisory posture is understood: 6 distinct crates with live
vulnerabilities in the shipped EKO binary (lopdf, quick-xml ×4 live versions,
crossbeam-epoch), one build-time-only (quick-xml 0.38.4), two never linked
(quinn-proto, rsa — rsa exists only in the framework lockfile), plus live
informational warnings (lru via ratatui, anyhow, event-listener, memmap2,
bincode, fxhash).
