## Claim

Frontend stores/components form one dependency map without duplicate authorities: each store owns one domain concept; there is no parallel implementation of the same concept; dead components are identifiable; per-store subscription fan-out can be enumerated.

## Method

Static inventory over `echo-agent-cli/web-frontend/src` (grep + `wc -l` + import-graph tracing), both repositories checked for duplicate concepts:

```text
1. Line-count inventory: find src -type f \( -name '*.ts' -o -name '*.tsx' \) -exec wc -l {} + (files > 300 lines listed).
2. Store inventory: wc -l stores/*.ts; import graph of every store consumer (grep 'use[A-Z].*Store' across components/hooks).
3. Whole-store subscription inventory: grep 'useChatStore((s) => s.messages|state.messages', 'useSubagentRunStore((state) => state.runs|(s) => s.runs'.
4. Duplicate-concept search across both repos: MessageBubble, ParallelExecutionBlock, visibleSubagentRuns, lastAssistantMessageId, knownMessageIds, runStatus writers, MAX_MESSAGES, EventSource, setInterval/setTimeout/addEventListener inventory (full list captured below), role="dialog", aria-modal, worker (frontend), react-window/virtuoso in package.json and src.
5. Dead-component search: grep imports of TasksPanel, McpManagerPanel, PlanEditor, ResultFullView.
```
