contract ("context-aware transfer", `transfer_history`), and topology/handoff

## Expected Result

The documented contract holds: history transfer actually transfers messages; a
cancelled or failed handoff terminates deterministically; topology node types
reflect real identities; failure paths are exercised by tests.

## Result

- Exit code: not-applicable (static inspection; executable component in V04)
- Duration: ~20 min
- Summary (observed behavior vs expectation):
  - `transfer_history` on the LLM `handoff` tool path is a no-op: the tool builds
    `HandoffContext` with `messages: vec![]` and nothing ever fills it
    (`tool.rs:91`). On the programmatic path, history is flattened to text lines
    via `as_text_ref()`; messages whose content is not plain text (tool results,
    thinking, media) are silently dropped by `filter_map` (`mod.rs:236-239`).
  - `handoff_chain` re-synthesizes history by appending fabricated
    user/assistant messages (`mod.rs:317-323`); the next target receives a text
    rendering, not structured messages, and `Agent::execute` resets each target
    agent's own history per call (echo-core contract).
  - Cancellation: no token exists anywhere in the handoff path; a dropped/cancelled
    caller leaves the spawned `agent.execute` running (detach); a hung target
    blocks `rx.await` (`mod.rs:271-273`) with no handoff-layer timeout.
  - Result preservation: output is a raw `String`; `return_to_source` is a
    dead field always `false` (`mod.rs:285`); no structured status/artifacts/
    evidence — no `SubagentOutcome`-equivalent contract.
  - Topology failure handling: all RwLock poison cases silently no-op
    (add_node/record_call/stats/nodes/edges/clear) — no error surfaced, no test.
    No cancel concept exists (synchronous recorder; nothing to cancel).
  - Topology identity: auto-created nodes are typed by guess — source always
    `Subagent`, target always `Tool` (`topology.rs:199-201`); correctness of the
    graph depends on callers pre-registering nodes with the right type (demo24
    does this manually, masking the defect). The auto path (`TopologyCallback`)
    can only record agent→tool edges (no subagent-dispatch callback exists on
    `AgentCallback`); `agent_tool` dispatches appear as a Tool node and the real
    subagent name never enters the graph.
  - Fixtures: the task card's required "handoff result/context preservation" and
    "topology failure/cancel" fixtures do not exist as tests; the 11 unit tests
    cover happy paths only. Handoff tests: 4. Topology tests: 7.
  - Panic/UTF-8 safety: handoff uses `.ok_or_else` and no direct indexing;
    topology truncates labels with `chars().take(30)` (`topology.rs:312-314,
    365-367`) — no UTF-8 or panic violations found in either module.

## Conclusion

The claim is falsified. Context preservation is lossy (text flattening, silent
non-text drop) or non-functional on the tool path (history never populated);
result preservation is a raw string with a dead `return_to_source` field;
cancellation is absent and timeout is absent at the handoff layer; topology
auto-typing asserts identities the framework does not know, and no failure/cancel
fixtures exist in either module. Supports F-MAG-01-P1-01 (detached/cancelless
lifecycle), F-MAG-01-P2-01 (context/result preservation), F-MAG-01-P2-02
(identity classification + fixture gap). The 11 happy-path tests pass (V04-01,
V04-02); nothing here proves runtime concurrency behavior, which needs the
Q-FLT-02 fixtures.
