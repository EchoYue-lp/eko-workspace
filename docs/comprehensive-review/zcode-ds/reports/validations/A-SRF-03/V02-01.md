## Claim

Every `chat://event` and `execution://event` payload produced by the Tauri
backend reaches exactly one frontend store through a registered listener with
a message-scoped gate, and the `interrupt_prompt` early-return path of
`send_chat_message` produces no terminal event for the message_key the
frontend has already started a turn with.

## Method

Static trace (numbered inspection procedure):

1. Backend: `src/tauri/commands/chat.rs` — `emit_chat_event` (:137-149)
   serializes the `ChatEvent` enum and injects `message_key` +
   `conversation_id` into every payload; `app.emit("chat://event", ...)`.
2. Backend: `send_chat_message` (:443-733) — interrupt detection
   (:516-534) returns `Ok({"kind":"interrupt_prompt","run_id":...})` BEFORE
   registering `active_chat_turns` / `cancel_token` / sink; normal path
   registers the turn, builds `TauriChatSink`, calls `drive_chat` in a spawned
   task; terminal `TurnStatus{completed|failed|cancelled}` + `Done` are
   emitted after `drive_chat` resolves (:690-711).
3. Backend: `TauriChatSink::on_event` (:1343-1399) — agent events mapped via
   `agent_event_to_chat_event` (:1462-1545); tool events persisted +
   summarized on `execution://event` (:1218-1308); `TurnStatus != running`
   also triggers `Done` (:1383).
4. Frontend: `useTauriChat.ts:84-167` — registers `chat://event` and
   `execution://event` listeners once per mount with unmount-safe cleanup
   (`aborted` flag + `pendingCleanup`); `handleEvent` (:60-72) gates via
   `isCurrentRunEvent` (:50-58: message_key equality, else conversation_id,
   else accept) and dispatches `handleChatEvent`; `dispatchNextQueued` fires
   only on `done`.
5. Frontend: `chatEventHandler.ts` — each event type writes exactly one store
   (`chatStore`, `taskRuntimeStore` for `interrupt_prompt`, tool/subagent
   stores via `useTauriChat.ts:109-150`).
6. Backend: `steer_chat_message` (:735-803) requires an `active_chat_turns`
   entry ("no active chat turn" otherwise).

## Expected Result

Normal turns: user event → sink event → store, terminated by exactly one of
`final_answer`/`error`/`cancelled` plus `run_status` + `done`. Interrupt turns:
no terminal event of any kind for the started message_key.

## Result

- Exit code: not-applicable (static trace)

  - Normal-path flow verified end to end: `send_chat_message` → `drive_chat`
    → sink → `chat://event` (with message_key) → `handleEvent` gate →
    `handleChatEvent` → store transitions.
  - `execution://event` flow verified: `emit_tool_execution_summary` /
    `emit_tauri_execution_event` → listener (:109-150) → `toolExecutionStore`
    (kind=tool), `subagentRunStore` (kind=subagent), `taskRuntimeStore`

  - Interrupt path verified: backend returns before turn registration
    (chat.rs:516-534); frontend `dispatchMessage` (:184-233) has already set
    `currentMessageKeyRef` (:188) and created an assistant message (:189);

    (final_answer/error/cancelled/done) — none of which fire. `sendMessage`
    (:251-264) then queues every subsequent message behind the ghost key.
  - `cancel()` (:314-327) also does not clear `currentMessageKeyRef`.
