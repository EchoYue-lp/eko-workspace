## Claim

Reducer monotonicity and terminal semantics: (a) chat terminal transitions
never regress from a truthful terminal to a different/contradictory terminal;
(b) subagent-run terminal states are monotone against late/duplicate events;
(c) tool rows never lose identity.

## Method

Inspection of reducers + event handlers:

```text
web-frontend/src/stores/chatStore.ts            (finalizeAssistantMessage :354-362,
                                                 setRunStatus :391-397, markCancelled :399-416,
                                                 appendToken :241-249, error-path call sites)
web-frontend/src/hooks/chatEventHandler.ts      (error :140-150, cancelled :151-158,
                                                 run_status :159-180, done :206-219, final_answer :97-109)
web-frontend/src/hooks/useTauriChat.ts          (cancel :314-327)
web-frontend/src/stores/subagentRunStore.ts     (ingest :446-522 monotonic guard :458-460)
web-frontend/src/stores/toolExecutionStore.ts   (ingest :206-217, mergeToolExecution :58-86,
                                                 mergeHydratedToolExecutions :106-117)
```

Trace the exact store state after each handler for three scenarios:
(A) error-terminal turn with prior streamed tokens; (B) user cancel then
error event; (C) duplicate subagent `started`/`finished` summaries for one
logical call.

## Expected Result

(A) runStatus ends `failed`, partial content preserved; (B) ends `cancelled`;
(C) one row per logical (owner, call_id) execution.

## Result

- Exit code: not-applicable (static trace)
- Summary:
  - (A) FAILS: `error` handler calls `setRunStatus('failed')` then
    `finalizeAssistantMessage(id, '[Error] …')`, which unconditionally sets
    `runStatus: 'completed'` (chatStore.ts:358) and REPLACES the message
    `content` with the error text (chatStore.ts:359), discarding streamed
    tokens; `scheduleAutoSave` persists the wiped content. Final store state:
    runStatus `completed` (header renders "就绪" via `runStatusLabel`,
    ChatPanel.tsx:432-451), message body `[Error] …`. The backend's
    subsequent `run_status:'completed'` is suppressed by the
    `isCancelledRef` flag, so the store's own `completed` label is the last
    word. → A-SRF-03-P1-02.
  - (B) FAILS the same way: `markCancelled` sets `cancelled`, then the
    backend's fabricated Error event (F-RCT-03-P1-02) overwrites to `failed`
    then `completed`; `isCancelled` stays true so the panel renders both the
    "已停止响应" divider and the `[Error]` body with a "就绪" header. →
    A-SRF-03-P1-02 (same root cause).
  - (C) FAILS for the live path: `toolExecutionStore.ingest` keys by
    `tool.id` (= per-producer `detail_ref` UUID, tool_execution.rs:191-200),
    so two `started`/`finished` summary pairs for the same (owner, call_id)
    from the two live producers (A-SRF-02-P2-01) create two rows;
    `idsByOwner` carries both ids; `SubagentStreamBlock.tsx:46-49` renders
    "N 工具" with duplicated `InlineToolCall` rows. The identity-based
    dedupe (`executionIdentity`/`mergeToolExecution`,
    toolExecutionStore.ts:46-86) exists but is used only by the hydration
    path (:106-117) and the TaskRuntime boundary merge, not by `ingest`.
    `chatStore.toolExecution.test.ts` "ignores duplicate start events"
    only covers same-id duplicates, certifying the weaker invariant. →
    A-SRF-03-P2-01.
  - PASSES: `subagentRunStore.ingest` (:458-460) drops all events for a
    run whose status is no longer `running` — terminal subagent lifecycles
    are monotone against late/duplicate events (retries use new execution
    ids, so no legitimate reopen is lost).
  - PASSES: `final_answer`/`done` after `error`/`cancelled` cannot regress
    the message content — the refs are cleared by the error/cancelled
    handlers first (chatEventHandler.ts:146-148/153-155).

## Deviations

None.

## Conclusion

Supports: subagent-run terminal monotonicity holds; chat terminal monotonicity
is violated in two deterministic ways (error/cancel → `completed`, content
wipe); the live tool-ingest path is not idempotent by logical identity. Does
not prove: behavior under real runtime interleavings (static only).
