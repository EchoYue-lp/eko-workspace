## Claim

The generic Tool contract (`Tool` trait, `ToolContext`, `ToolResult`,
`ToolFailure`, `ToolParameters`, `ToolExecutionConfig`) is typed, cancellable,
and its schema/execute path converts deserialization failures into typed
`ToolError::InvalidParameter` without panics, with parameter paths free of
`unwrap`/`expect`/byte-slicing.

## Method

Static inspection with grep for panic-prone patterns plus full reads:

```text
1. Read echo-core/src/tools/mod.rs (Tool trait, ToolFailure, ToolResult,
   ToolParameters, ParamValue, ToolCallParams, ToolContext, ToolVisibilityState).
2. Read echo-macros/src/derive_tool.rs:330-415 and echo-macros/src/lib.rs:236-290
   (schema generation + serde deserialization error mapping).
3. Read echo-core/src/llm/types.rs:605-614 (ToolDefinition::from_tool projection).
4. Read echo-execution/src/tools.rs:618-728 (execute_tool_inner: timeout,
   retry gating, concurrency) and 754-912 (streaming execution).
5. Read src/agent/react/run/pipeline.rs:455-560 (ExecuteStage ToolContext
   construction) and src/agent/react/run/execution.rs:270-310 (plan_mode
   propagation into ToolExecutionContext).
6. grep -rn "unwrap(|expect(|\[\.\.|panic!|unreachable!" over the parameter
   handling paths of the contract files.
```

## Expected Result

- Tool trait exposes typed name/description/parameters/execute(-with-context)
  plus streaming, risk, permission, timeout-exemption hooks; `ToolContext`
  carries working_dir, ids, call_id, cancel token, output_artifacts config,
  visibility, trace_sink, delegation policy.
- LLM-facing schema is generated (schemars) and serialization failure degrades
  to a safe fallback, not a panic.
- Parameter deserialization failures map to `ToolError::InvalidParameter` with
  the failing field name; missing params to `ToolError::MissingParameter`.
- No panic-capable constructs on the parameter path.

    `execute_stream(_with_context)` with mandated terminal

  - `ToolContext` (`mod.rs:1000-1030`) carries: working_dir, conversation_id,
    run_id, turn_id, message_id, execution_id, call_id, output_artifacts
    (`ToolOutputArtifactConfig`), tool_visibility, cancel
    (`Arc<CancellationToken>`), trace_sink, delegation_policy. Live population
    verified at `pipeline.rs:495-512` (cancel = `snapshot.external_cancel`,
    artifacts = `snapshot.config.tool_output_artifacts`).
  - `ToolFailure` classification (`mod.rs:78-254`): category × recovery ×
    side-effect; `allows_automatic_retry()` (Mod:154-162) is deliberately
    narrower than "might recover" — requires recovery==Retry AND (no side
    effect OR idempotency key). `ToolFailure::from_error` (Mod:165-253)
    conservatively upgrades categories when side effects are possible.
  - Schema generation: derive macro `derive_tool.rs:362-365` and attribute
    macro `lib.rs:248-249` use `schemars::schema_for!` with
    `serde_json::to_value(...).unwrap_or_default()` (safe fallback, no panic).
    `ToolDefinition::from_tool` (`llm/types.rs:605-614`) is a plain projection
    of name/description/parameters.
  - Deserialization: `derive_tool.rs:394-410` / `lib.rs:273-289` map
    `serde_json::from_value` errors to `ToolError::InvalidParameter { name,
    message }` with a fragile-but-safe field extraction
    (`unwrap_or("(deserialization)")`); missing fields surface as
    `InvalidParameter` ("missing field `x`"). Missing-parameter errors from
    hand-written tools use `ToolError::MissingParameter` (e.g.
    `tools/builtin/memory.rs:89`).
  - Execution path: `execute_tool_inner` (`echo-execution/src/tools.rs:618-728`)
    wraps each attempt in `tokio::time::timeout` (drop-based cancellation on
    expiry) and gates retries on `ToolFailure::allows_automatic_retry`; a
    timed-out **write** tool is not auto-retried because `from_error` with
    `may_have_side_effects=true` converts Timeout to PartialSideEffect +
    VerifyThenRetry. Streaming retries stop once output was forwarded
    (`tools.rs:877-903`).
  - Panic scan of the parameter path: the only byte slicing found in scope is
    `spawn_task.rs:234` (`&bytes[..MAX_OUTPUT_LEN]`, guarded by
    `bytes.len() <= MAX_OUTPUT_LEN`), which cannot panic but cuts UTF-8 at a
    byte boundary (U+FFFD lossiness; P3-03). `permission.rs:274-285` slices
    only after `ends_with("*)")` / length guards — safe. No `unwrap`/`expect`
    on untrusted parameter data found in the contract files.
- Log/artifact: none (static).

## Deviations

- `Tool::execute`'s default constructs an empty `ToolContext`
  (`mod.rs:754-762`), so legacy `execute`-only tools cannot see ctx — by
  design (doc `:748-753`).
- `ToolManager` never polls `ctx.cancel` itself; cancellation is fully
  cooperative via the token handed to tools. Not a defect per se, but the
  manager's only enforced cancellation is the timeout drop.

## Conclusion

The contract is typed and cancellable (cooperative token + enforced timeout),
schema generation and serde failure handling are panic-safe, and error
classification is structured. Supports the claim; does not prove that
individual domain tools honor `ctx.cancel` (F-EXT-02/03 scope) nor that
timeout-drop cleans up OS resources.
