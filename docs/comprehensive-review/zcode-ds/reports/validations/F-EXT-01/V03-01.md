## Claim

Cursor pagination is opaque, versioned, query-bound, and size-bounded;
tool-output artifacts are spill-safe, sha256/identity-verified, path-confined,
and recoverable via `read_artifact`; all truncation on the artifact/pagination
path is UTF-8-safe per AGENTS.md.

## Expected Result

- Cursor: opaque to clients (hex-encoded envelope), version-checked, bound to
  query+limit+snapshot (fingerprint), page size clamped to [1, max], stale or
  tampered cursors produce typed `PageError`s, never panics (UTF-8/hex
  decode safe on multibyte input).
- Artifacts: complete output spilled after threshold (1 MiB default) with
  sha256; partial files dropped on failure; conversation-scoped cleanup
  deferred while writers active; `read_artifact` confined to artifact root,
  immune to symlink escape, and cursor-bound to file identity + sha256 so a
  changed artifact is detected; pages are token-bounded (max 3500) and
  UTF-8-safe.
- Bounded model output: inline truncation uses `chars()` head/tail; spill
  preview uses `chars().take(500)`.

## Deviations

- `PageRequest` fingerprint includes the full item list, so any result-set
  change invalidates the cursor (by design — CursorQueryMismatch); O(n)
  re-hash per page is acceptable at the current bounded result sizes
  (memory search caps at 20 items).
- `read_artifact` first-page hashing is O(file size) on the first page only;
  later pages reuse the cursor's sha256.
