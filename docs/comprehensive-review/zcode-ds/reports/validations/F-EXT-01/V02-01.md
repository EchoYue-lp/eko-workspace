## Claim

Tool registration is deterministic and duplicate tool names are either
impossible or handled observably; cross-agent registration on a shared
`ToolManager` (AgentPool pattern) keeps per-agent tool identities intact; no
unintended same-name collision exists between builtin (`src/tools/builtin/`)
and `echo_tools` tools.

## Method

```text
1. Extract every `fn name(&self) -> &str` literal across
   echo-tools/src/ and src/tools/builtin/; diff for duplicates.
2. Read ToolManager register/register_tools/unregister/get_openai_tools
   (echo-execution/src/tools.rs:280-301, 470-583).
3. Read memory tool registration branches
   (src/agent/react/mod.rs:593-604, 767-776, 1083-1110, 1146-1173).
4. Read AgentPool shared-ToolManager wiring
   (echo-agent-cli/echo-agent-app-core/src/agent_pool.rs:96, 127-140, 671-672,
   882-883, 923) and set_tool_manager (src/agent/react/mod.rs:1442-1445).
5. Read echo-tools/src/registry.rs register_all_tools / register_readonly_tools.
```

## Expected Result

- Registering the same name twice either errors/warns or is a documented
  replace; no silent cross-agent identity loss.
- The only same-name pairs are the intentional legacy/layered memory tools,
  registered in mutually exclusive branches.
- Deterministic, sorted tool definitions for provider prefix caching.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - `ToolManager::register` (`echo-execution/src/tools.rs:529-532`) inserts
    into a DashMap — a duplicate name **silently replaces** the previous tool
    (`tools.insert(name, tool)`); no warning, no error, and `register` returns
    `()`. `register_tools` (`:534-539`) has the same semantics. This is the
    mechanism the layered-memory "replace default tools" pattern relies on
    (`react/mod.rs:593-604` doc "Replace default memory tools").
  - Duplicate search across `echo-tools/src/` + `src/tools/builtin/`: exactly
    four same-name pairs, all memory tools — `remember`, `recall`, `forget`,
    `search_memory` — defined twice each in `src/tools/builtin/memory.rs`
    (legacy store-backed vs layered variants: lines 49/154, 262/531, 353/776,
    437/607). No other collisions (101 name() sites scanned).
  - **Cross-agent registration inconsistency (finding F-EXT-01-P1-02)**:
    AgentPool shares one `ToolManager` across all pooled agents
    (`agent_pool.rs:96,127-140`; `set_tool_manager` replaces wholesale at
    `react/mod.rs:1442-1445`, applied at `agent_pool.rs:882`). Each pool agent
    then re-registers the four memory tool names bound to **its own**
    `MemoryLayerManager` (per-agent evolution observer, `agent_pool.rs:650-657`
    and 915-923; `install_memory_store`/`install_memory_layer_manager` at
    `agent_pool.rs:671-672`, `react/mod.rs:1083-1110`). Because registration is
    silent-overwrite, the last agent to run wins and all pooled agents' memory
    tool calls route through one agent's layer manager; iteration order over
    the agent map is nondeterministic.
  - Determinism is otherwise correct: `get_openai_tools` sorts by name
    (`tools.rs:298`) with version-bumped lazy cache (`tools.rs:282-301,
    470-483`); `list_tools`/`get_tool_definitions` are sorted (test
    `test_tool_lists_are_deterministically_sorted`).
  - Engine core tools (`FinalAnswerTool`, task tools, think) have unique names
    verified against the echo_tools set; `tool_search`/`read_artifact`/`shell`
    single definitions.

## Deviations

- None beyond the two findings this report feeds (P1-02, P3-01).

## Conclusion

Registration is deterministic in ordering but duplicate-name handling is a
silent overwrite, which — combined with the AgentPool shared-registry pattern —
breaks per-agent memory-tool identity (P1-02). No unintended builtin-vs-
echo_tools collision exists today. Supports V02's claim with one defect
recorded.

## Follow-Up

Dynamic verification of P1-02 (a pooled multi-conversation run asserting each
conversation's memory tools route to its own layer manager) is the regression
validation for the finding.
