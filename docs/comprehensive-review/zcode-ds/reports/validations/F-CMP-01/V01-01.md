## Claim

Compression semantics (compressors, canonical-context reinjection, tool-call/result
pairing repair) have exactly one authoritative definition per semantic across both
repositories, with no parallel/duplicate implementation.

## Method

Repository-wide grep over `echo-agent` and `echo-agent-cli` (excluding `target/`):

```text
1. grep -rn "impl ContextCompressor for" echo-agent echo-agent-cli
2. grep -rn "sanitize_tool_call_pairing|ToolPairFix|tool_pair_fix" echo-agent echo-agent-cli
3. grep -rn "CanonicalContext|reinject_canonical|to_reinjection" echo-agent echo-agent-cli
4. grep -rn "SummaryCompressor|SlidingWindowCompressor|HybridCompressor|AdaptiveCompressor|IncrementalSummaryCompressor|VisibilityHorizonCompressor" echo-agent echo-agent-cli
5. grep -rn "current_query" echo-state/src/compression echo-core/src/compression.rs
```

## Expected Result

One `ContextCompressor` trait in `echo-core`; all compressor implementations in
`echo-state/src/compression`; one sanitizer; one `CanonicalContext`; no EKO-side
compressor or pairing-repair reimplementation; macro-generated compressor helper
may exist but must be an extension point, not a second authority.
