construction site.

## Expected Result

EKO agents reach a compressor (strategy default), prepare() is the single
compression decision point on the live turn path, and each strategy has a defined

## Result

- Exit code: not applicable (static trace)
- Summary:
  - Live path: every EKO agent is built via infra.rs with `token_limit`
    396K default (`DEFAULT_CONTEXT_WINDOW`) → `new_inner` installs
    `SlidingWindowCompressor::new(40)` (react/mod.rs:346-353), then
    `apply_compressor` (runtime.rs:114 / agent_pool.rs:948) overrides with
    `compress_strategy` default `"summary"` → `SummaryCompressor::new(llm, 20)`
    (config.rs:203-224). Compression is therefore always installed on the EKO
    path (also true when the user sets `token_limit: 0` — see V05 drift).
  - `prepare(None)` at compact.rs:60 is the only production `prepare` caller
    (grep-verified); it runs before each LLM call (run_compact is invoked from
    the ReAct loop), so the auto-compression + sanitizer + canonical
    reinjection chain is on the main turn path.
  - Opt-in strategies: `"hybrid"` → `HybridCompressor::summary_buffer`
    (config.rs:231); `"adaptive"` → `AdaptiveCompressor` (config.rs:270).
  - `IncrementalSummaryCompressor`: no production construction site in either
    repository (re-exported at echo-agent/src/lib.rs:184 only) — documented
    (docs/zh/04-compression.md) but dormant.
  - `VisibilityHorizonCompressor`: constructed only via
    `ReactAgentBuilder::visibility_horizon` (builder.rs:1045-1055); zero call
    sites of that builder method in framework or EKO — dormant.
  - Manual path: `/compress` and `/compact` CLI commands reach
    `force_compress_with_focus_and_hooks(focus, 6/12, "manual")` or
    `force_compress_context()` (echo-agent-cli/src/cli/cmd_impls/context.rs:110-182)
    → ContextManager::force_compress* — same sanitize + canonical chain.
