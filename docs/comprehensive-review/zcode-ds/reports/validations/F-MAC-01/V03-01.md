## Claim

Each macro's generated code matches the public trait/schema contract it targets,
handles hygiene (crate path resolution, renamed crates), and either honors or
rejects generic/borrowed/edge-case inputs with a correct diagnostic.

## Method

Static contract comparison and edge-case inspection:

1. Compare every generated impl signature in `echo-macros/src/lib.rs` and
   `echo-macros/src/derive_tool.rs` against its target trait:
   `Tool` (echo-core/src/tools/mod.rs:739-903), `ToolRunner` (:733-736),
   `AgentCallback` (echo-core/src/agent/mod.rs:920-990), `Guard`
   (echo-core/src/guard/mod.rs:62-73), `HumanLoopHandler`
   (echo-orchestration/src/human_loop/mod.rs:522-552),
   `ContextCompressor` (echo-core/src/compression.rs:446-454),
   `PermissionPolicy` (echo-core/src/tools/permission.rs:508-514),
   `AuditLogger` (echo-core/src/audit.rs:137-142).
2. Hygiene: `echo_agent_crate_path()` (lib.rs:43-51) and
   `resolve_echo_crate_path()` (derive_tool.rs:37-62) use `proc-macro-crate`
   with rename support; the derive tries `echo_core` before `echo_agent`;
   the attribute macros require `echo_agent` only.
3. Facade path audit: does `echo-agent/src/tools/mod.rs:109-114` re-export
   every type the generated code references (`ToolRunner`)?
4. Error-handling contract: `deserialize_params` field-name extraction
   heuristic in lib.rs:280-286 and derive_tool.rs:398-404.
5. Edge inputs: `&self` receiver (lib.rs:621-645 — only `FnArg::Typed`
   handled), generics/where-clauses/reference params (lib.rs:203-297 ignores
   `func.sig.generics`), fixed param-name contracts of `guard`/`compressor`/
   `permission_policy` (lib.rs:397-418, 496-514, 541-561), unit-struct derive
   (derive_tool.rs:419-495), tuple/enum derive rejection (derive_tool.rs:
   241-264), `risk_level` validation (derive_tool.rs:310-324).

## Expected Result

Generated signatures match traits; renamed crates resolve; the facade exports
everything generated code needs; unsupported inputs are either rejected with a
targeted diagnostic or compile with correct semantics.

## Result

- Exit code: not-applicable (static inspection; behavioral confirmation in
  V04-01/V04-02)
- Summary:
  - All 8 generated impl signatures match their trait contracts, including
    lifetime shapes (`&'a self`, `BoxFuture<'a, ...>`) and default-method
    handling (impl-block macros emit only user-defined methods; trait defaults
    fill the rest).
  - `ToolParameters = HashMap<String, serde_json::Value>`
    (echo-core/src/tools/mod.rs:554) — generated `deserialize_params` converts
    to `Value::Object` and uses `serde_json::from_value`; error mapping to
    `ToolError::InvalidParameter` present in both macros.
  - Renamed-crate resolution: attribute macro generates `::<renamed>::...`
    paths (V04-02 `renamed_attr` passed); derive prefers renamed `echo_core`
    (V04-02 `renamed_derive` passed).
  - FACADE GAP: the derive's generated `execute` references
    `<Self as <crate>::tools::ToolRunner<...>>::run` (derive_tool.rs:387), but
    the facade `echo_agent::tools` explicit re-export list
    (src/tools/mod.rs:109-114) omits `ToolRunner` (also absent from
    `echo_execution::tools::*`). For consumers depending only on `echo_agent`
    (the documented path), the generated code fails to resolve — reproduced in
    V04-02 `facade_derive`.
  - Edge inputs: `&self`/`&mut self` receivers are silently skipped by
    `extract_fn_params` (lib.rs:621-645 — `FnArg::Receiver` falls through with
    no error); generics/where-clauses are ignored and reference-typed params
    become lifetime-less struct fields (loud but confusing failures, V04-02
    `cf3`); `guard`/`compressor`/`permission_policy` fix their parameter names
    (`content`/`direction`, `input`, `tool_name`/`permissions`) without
    validating the user's signature (loud but confusing failures, V04-02
    `cf4`); tuple structs and enums are rejected with targeted messages
    (V04-02 `cf5`/`cf6`); invalid `risk_level` is rejected (V04-02 `cf9`).
  - Schema contract: `parameters()` builds `schemars::schema_for!` output;
    doc comments become `description`, `Option<T>` becomes nullable and is
    excluded from `required` (empirically verified in V04-01).
  - `to_pascal_case` (lib.rs:777-790) uses `chars()` — UTF-8 safe.

## Conclusion

The contract-matching and hygiene claims hold except for the facade `ToolRunner`
export gap (P1 finding) and the silent receiver drop (P2 finding); the
generics/borrowed-params and fixed-name cases fail loudly but with
low-diagnostic-quality errors (P3 findings). All behavioral confirmations were
re-run as executable checks in V04.
