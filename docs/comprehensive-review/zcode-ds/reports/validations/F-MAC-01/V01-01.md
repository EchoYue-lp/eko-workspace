## Claim

There is exactly one procedural-macro implementation generating Tool/Agent
support code in the framework; no parallel second macro system or duplicate
hand-written generation path exists, and the macro-generated Tool surface is
consistent with the single `Tool` trait authority.

## Method

Definition inventory and repository-wide duplicate search (static):

1. List every macro definition: `grep -n "proc_macro_derive|proc_macro_attribute|macro_export"` in `echo-agent/echo-macros/src/lib.rs` and `echo-agent/src/macros.rs`.
2. Search both repositories for macro usage sites: `grep -rn "#\[\(tool\|callback\|guard\|handler\|compressor\|permission_policy\|audit_logger\)("` and `grep -rn "derive(Tool)"` across `echo-agent` and `echo-agent-cli` (excluding `echo-macros/src`).
3. Search for a second Tool-generation mechanism: `ToolRunner`, `TypedTool`, `derive_tool`, any other `#[proc_macro_derive(Tool)`.
4. Compare the generated `Tool` impl shape against the single trait authority `echo-core/src/tools/mod.rs:739-903`.

## Expected Result

Exactly 8 proc macros defined in echo-macros and 6 `macro_export` declarative
macros in the root crate; zero competing macro implementations; the
`Tool`/`ToolRunner`/`AgentCallback`/`Guard`/`HumanLoopHandler`/`ContextCompressor`/
`PermissionPolicy`/`AuditLogger` trait authorities are each defined once.
