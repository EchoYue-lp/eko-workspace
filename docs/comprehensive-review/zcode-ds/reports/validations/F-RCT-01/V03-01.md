## Claim

The canonical system prompt is assembled once from deterministic sections
(core instructions, CoT guidance, model-profile suffix, project rules) with no
section injected twice, and `echo_core::project_rules` loading is the single
authority for project-instruction discovery.

## Method

Static inspection:

1. Read `ReactAgent::build_system_prompt` (src/agent/react/mod.rs:676-723):
   section order and gating.
2. Read canonical-context construction in `new_inner` (mod.rs:360-382) and the
   re-injection path in `echo-state/src/compression/mod.rs:877-929`
   (`reinject_canonical_context`, `to_reinjection_messages` consumers at
   :1071, :1144, :1203, :1525-1530) and `echo-core/src/compression.rs:376-401`.

   `InstructionResolver` (:57-126) — single authority, tested at
   :253-404.
4. Duplicate-search terms across both repositories: `inject_rules_with_root`,
   `rules_injection_with_root`, `rules_injection`, `load_project_rules`,
   `set_canonical_context`, `set_canonical_system_prompt`,
   `to_reinjection_messages`, `skill_injections`, `active_skill_names`,
   `replace_projection`, `SKILL_CATALOG_PROJECTION`.
5. Check `set_working_dir` refresh behavior (mod.rs:907-946) vs canonical
   `project_rules` staleness.

## Expected Result

Project rules appear exactly once in the final context; skill content uses
replaceable projections (no duplication); canonical re-injection preserves the
"prompt is not represented twice" contract (echo-core/src/compression.rs:
371-375).

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Section order in the base system message (mod.rs:676-723): project rules
    PREPENDED via `inject_rules_with_root` (echo-core/src/project_rules.rs:
    209-218), then user `system_prompt`, then `COT_INSTRUCTION` (only when
    `enable_tool && enable_cot`, mod.rs:683-691), then model-profile
    `prompt_suffix` (mod.rs:693-701). Deterministic for fixed inputs.
  - Skills: injected as replaceable context projections
    (`SKILL_CATALOG_PROJECTION` and `echo-agent:skill:{name}`, capabilities.rs:
    741-746, 969-989) — no duplication by design (comment at :738-740).
  - Subagent catalog: exposed only through the `agent_tool` schema
    (agent_dispatch.rs:74-75), not as a prompt section.
  - **Duplicate-injection path found (F-RCT-01-P2-02)**: the same project
    rules are stored twice at construction — embedded in the canonical system
    prompt (mod.rs:328, 360-382: `system_prompt: Some(sp_for_canonical)`) AND
    as `CanonicalContext.project_rules` (mod.rs:362-375). After the first
    compression that runs `reinject_canonical_context`
    (echo-state/src/compression/mod.rs:877-929), the rules text appears both
    inside the restored system message and as a separate
    `[Canonical context — project rules restored]:` message
    (echo-core/src/compression.rs:384-390). The exact-text dedup
    (echo-state/src/compression/mod.rs:912-921) cannot match the two because
    the re-injection message carries the prefix, so the duplicate survives;
    subsequent compressions are deduped against the first canonical copy.
  - **Stale-rules path**: `set_working_dir` (mod.rs:907-946) rebuilds the
    system prompt and updates `canonical.system_prompt` via
    `set_canonical_system_prompt` (:939) but never refreshes
    `canonical.project_rules` — after a workspace switch, the rules from the
    OLD working directory are re-injected on the next compression.
  - `CanonicalContext.skill_injections`/`active_skill_names` are initialized
    empty (mod.rs:379-380) and never updated by any activation path found
    (skills use projections instead) — canonical skill state is inert but
    harmless.
  - Project-rules discovery is a single authority
    (echo-core/src/project_rules.rs `InstructionResolver`, with boundary
    protection tests :253-404); both injection sites call it with the same
    working_dir/project_root.
  - UTF-8 safety: canonical rules re-injection truncates with `chars().take(2000)`
    (echo-core/src/compression.rs:385) — compliant with AGENTS.md.

Supports: deterministic single-assembly of the base system message; single

dynamic trigger (compression evicting the system message) was not executed
live, so confidence is medium-high.
