## Claim

Builder/agent construction produces exactly one tool registry per agent; the
`set_tool_manager` replacement path, the `register`/`add_tool` insertion paths,
and the shared AgentPool manager (F-EXT-01-P1-02) do not create a second,
divergent registry or silently drop registered tools on the standard paths.

## Expected Result

One authoritative `ToolManager` per agent at build time; `set_tool_manager` is
the only replacement path and is used by AgentPool before per-agent
registrations; any stale weak/strong references left behind by replacement are
handled; tool-definition ordering is deterministic.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Single registry: `ToolExecutionSubsystem.tool_manager` is the only
    registry field; `new_inner` builds exactly one manager (mod.rs:386) and
    registers final_answer + task tools (mod.rs:393-400), feature-gated tools
    (mod.rs:442-453, 454), memory tools (mod.rs:457), ToolSearchTool
    (mod.rs:461), AgentDispatchTool (mod.rs:478-497).
  - `set_tool_manager` fully replaces the field (mod.rs:1442-1444); AgentPool
    calls it before per-agent memory-tool re-registration, so no per-agent
    registrations are lost on the EKO path (agent_pool.rs:882 vs 671-672,923
    ordering).
  - `ToolSearchTool` holds `Weak<ToolManager>` (echo-execution/src/tools.rs:
    125-127); after `set_tool_manager` on a non-primary agent its original
    manager is dropped and the tool returns a graceful error
    ("Tool catalog is no longer available", :188-190) — no panic, no dangling
    execution. In the AgentPool layout the live shared manager contains the
    primary agent's ToolSearchTool which references the shared manager, so
    `tool_search` remains functional.
  - `task_revision_service` option replaces the default task tools via
    name-based silent `DashMap::insert` overwrite (src/tasks.rs:18-26; tools.rs:
    529-532) — no second API, but the replacement depends on the silent
    last-wins insert already flagged as F-EXT-01-P1-02 (silent overwrite
    class). Edge case: if `config.allowed_tools` (non-empty) is set, the
    `add_tools` filter (capabilities.rs:48-57) can silently skip the new task
    tools, leaving the default service in place — the builder option then
    silently no-ops; this is the only reachable "option declared but not
    effective" path found (combination requires direct AgentConfig mutation;
    see F-RCT-01-P2-01).
  - Determinism: tool definitions are name-sorted and version-cached
    (tools.rs:281-307), so identical inputs produce identical model-facing
    schemas regardless of DashMap iteration order.
  - Cross-reference: F-EXT-01-P1-02's shared-manager cross-agent contamination
    is confirmed consistent with this trace (shared registry + per-agent
    re-registration under identical names); it is owned by F-EXT-01 and not
    re-filed here.
