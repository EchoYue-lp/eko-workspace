## Claim

EKO's two projections (`eko:instruction-context`, `eko:hot-memory-context`)
survive repeated compression exactly once each (no loss, no duplication), and
repeated compression either converges within `token_limit` or reports the
bound — the stability half of the X-MEM-01 question.

## Method

Static anchor re-trace plus a dynamic probe crate built OUTSIDE the
repositories (path-dependencies on `echo_state`/`echo_core` only, no source
modification), plus the echo_state compression test suite:

```text
Static anchors:
- prepare() pipeline: echo-state/src/compression/mod.rs:1243-1539
  (split_protected :1336 -> compressor -> merge_protected :1353 -> sanitize
  :1451 -> verifier :1464-1523 -> reinject_canonical_context :1528;
  no post-compression token re-check; L3 promotion only on non-empty eviction
  :1358-1367; P0-fail fallback re-compresses ORIGINAL messages :1479-1514).
- is_protected (mod.rs:679-691) marks all projection messages protected;
  split/merge keep them out of the compressible set (:747-793).
- summary.rs:292-348 (system_msgs all partition-kept + one new summary
  appended per pass); sliding_window.rs:41-66 (early return when
  conv_msgs.len() <= window — no token check).
- react/mod.rs:346-353 (default SlidingWindow(40) when token_limit set).

Dynamic probe (procedure, run twice — once with window=3, once with window=6
to reach the early-return branch):
  ContextManager::builder(500).compressor(SlidingWindowCompressor::new(3))
  + replace_projection(INSTR/HOT) -> push 10 user/assistant turns ->
  4x prepare(None), asserting instr_copies == 1 && hot_copies == 1 each pass,
  has_projection both; then replace both projections with new content and
  assert old copies == 0, new == 1 each; then a second ContextManager with
  builder(100) + window 6, 3 long-payload turns, one prepare.
  Expected output recorded before running (see Result).

Test suite:
  cd echo-agent && cargo test -p echo_state --lib --locked compression::
```

## Expected Result

- Projection survival: instr_copies == 1 and hot_copies == 1 on every pass,
  replacement yields exactly one new copy and zero old copies.
- Compression convergence: with 6 long messages (~1,250 estimated tokens)
  against token_limit 100 and window 6, the compressor early-returns because
  `conv_msgs.len() <= window` and prepare reports the over-limit list — the
  stall behavior of canonical F-CMP-01-P1-01, expected to reproduce.
- Test suite: all 69 compression tests pass (exit 0).

## Result

- Exit code: 0 (both probe runs and the test suite)
- Duration: probe < 1 s; tests 0.04 s
- Summary:
  - Probe (window=3, token_limit 500): 22 messages before; passes 1-4 all
    show `messages=22 instr_copies=1 hot_copies=1 compressed=false`
    (compression not triggered — under limit); after replace:
    `old_copies=0 new_instr=1 new_hot=1` — all assertions passed.
  - Probe (window=6, token_limit 100): `compressed=true, after_messages=6` —
    compression fired (estimated tokens > limit) but the count-window early
    return (sliding_window.rs:48-66) left all 6 messages in place; no
    post-compression re-check (mod.rs:1531-1538). Over-limit context is sent
    to the LLM — canonical F-CMP-01-P1-01 reproduced dynamically.
  - `cargo test -p echo_state --lib --locked compression::`: 69 passed;
    0 failed; exit 0.
  - Static re-trace confirms: system summaries accumulate one immortal
    message per pass (summary.rs:292-296 partition-keep + :346-348 append) —
    canonical F-CMP-01-P1-02; the verifier's only token check is
    `after <= before` (verifier.rs:100-120), never `<= token_limit`.

## Deviations

The first probe run (window=3, 6 messages) did not reach the compression
branch (compressed=false) — expected, since 6 messages stayed under the 500
limit; the stall case requires tokens > limit with count <= window, which the
window=6 / limit=100 run produced. No other deviations.

## Conclusion

The projection-survival half of the claim holds: EKO projections survive
repeated `prepare` exactly once, and replacement is tombstone-clean —
verified dynamically. The convergence half does NOT hold on the count-window
path: over-limit context passes through unchanged (F-CMP-01-P1-01), and the
summary strategy accumulates system summaries without bound (F-CMP-01-P1-02).
Both are canonical framework findings, revalidated current at these commits
and directly relevant to the X-MEM-01 question ("memory/instruction layers
using generic compression without lost updates" — the layers are preserved,
but the surrounding pipeline does not guarantee a bounded context).
