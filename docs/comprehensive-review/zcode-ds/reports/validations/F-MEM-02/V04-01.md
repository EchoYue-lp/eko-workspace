## Claim

The semantic-search numerical path (vector serialization, cosine similarity,
score sorting) is panic-safe on numerical edge cases: dimension mismatch, empty
vectors, NaN/Inf, overflow, malformed blobs — and degrades gracefully or
errors explicitly.

## Method

Static inspection of the numerical paths:

```text
1. cosine_similarity (sqlite_store.rs:239-251): dimension mismatch, empty vec,
   zero norms, NaN/Inf inputs, overflow (f32 x*x -> Inf).
2. vec_to_bytes / bytes_to_vec (:221-236): empty vec, blob length not a
   multiple of 4 (chunks_exact remainder), NaN/Inf round-trip.
3. semantic_search_impl (:395-457): query vec empty, stored vec empty,
   dimension mismatch query vs stored, score sort at :451
   (partial_cmp unwrap_or(Equal)), candidate cap take(max_candidates())=10000,
   truncate(limit).
4. search_with Hybrid (:821-907): rrf_score with vector_weight out of range /
   NaN (echo-core/src/memory/store.rs:120-134), sort at :896-901.
5. Integer conversions: now_secs() as i64 (:476), row.get::<i64> as u64
   (:309-310, :804-805), limit as i64 (:646, :669), deleted as u64 (:926).
```

## Expected Result

No panic path exists: dimension mismatch -> explicit error or safe zero score;
NaN/Inf handled by partial_cmp; empty vectors filtered; malformed blob
remainder dropped; integer casts cannot panic.

## Result

- Exit code: not-applicable (read-only inspection; numerical functions also
  covered by passing tests test_cosine_similarity / test_vec_serialization,
  V03-01)
- Duration: ~10 min
- Summary of edge-case behavior:
  - Dimension mismatch: cosine_similarity returns 0.0 when `a.len() != b.len()`
    (:240-242) — no panic, but semantic_search_impl never checks dims
    explicitly, so a mismatched query (e.g., embedder model changed) yields
    all-zero scores and returns arbitrary DB-order items with score 0.0 —
    silent garbage instead of an explicit error (F-MEM-02-P3-04).
  - Empty vectors: stored empty vector filtered before scoring (:444-446);
    empty query vector -> all scores 0.0 (same silent-garbage path).
  - NaN/Inf: `partial_cmp(&a.0).unwrap_or(Ordering::Equal)` (:451, :896-901)
    never panics; NaN items rank arbitrarily. f32 arithmetic (x*x, sqrt,
    division) never panics on overflow — Inf propagates to NaN. Safe.
  - Malformed blob: bytes_to_vec uses chunks_exact(4) — a blob whose length is
    not a multiple of 4 silently drops the tail bytes (:233-235); no error.
  - Candidate cap: `take(10_000)` (:441) truncates the scanned set in
    arbitrary DB order before scoring — a silent quality cap, not a crash.
  - Hybrid rrf_score: vector_weight NaN/out-of-range yields NaN/negative
    contributions in echo-core (store.rs:120-134); final sort still safe via
    partial_cmp. Cosmetic ranking degradation only.
  - Integer casts: all `as` casts in the numerical/score path are between
    non-negative in-range values from DB rows or bounded indices; no overflow
    panic possible (Rust float/int casts never panic).
- Key behavioral defect found during this pass: `search()` and
  `semantic_search_impl()` return `fetch_items`/`fetch_items_with_scores`
  results in SQLite row order — `WHERE key IN (...)` has no ORDER BY — so the
  returned Vec is NOT sorted by relevance despite the trait contract
  ("sorted by relevance", echo-core/src/memory/store.rs:198-199); additionally
  semantic similarity values computed in `scored` are discarded and replaced
  by positional fallback scores `1/(i+1)` in fetch_items (sqlite_store.rs:300)
  because `fetch_items(..., None)` is called (:456). The existing tests never
  exercise multi-match ordering (test_fts5_search asserts a single match;
  test_fts5_search_multiple_keywords asserts a single match; test_with_embedder
  only checks score.is_some()). Filed as F-MEM-02-P2-03.
- Log/artifact: none created.

## Deviations

The claim "degrades gracefully or errors explicitly" does not hold for
dimension mismatch / empty query vectors — degradation is silent and returns
misleading results (no error). FTS5 query-syntax errors, if any ever occurred,
abort search with an Err instead of falling back to LIKE (:649).

## Conclusion

Supports: the numerical path is panic-safe on all inspected edge cases (NaN,
Inf, empty, mismatch, malformed blob, overflow). Does not support: graceful
explicit degradation on dimension mismatch (silent garbage), or relevance
ordering of results (contract violation, F-MEM-02-P2-03).
