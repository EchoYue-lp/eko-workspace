## Claim

The `sqlite` feature is correctly isolated: echo-state's `sqlite` feature maps
to `dep:rusqlite`; the root `sqlite` feature maps to `echo_state/sqlite` +
`dep:rusqlite`; with the feature off, the `SqliteStore`/`SqliteConversationStore`
types are not visible and no rusqlite code compiles.

## Method

```text
1. Read [features] of echo-state/Cargo.toml (sqlite = ["dep:rusqlite"]) and of
   root echo-agent/Cargo.toml (sqlite = ["echo_state/sqlite", "dep:rusqlite"];
   "sqlite" member of `full`).
2. Census all #[cfg(feature = "sqlite")] sites repo-wide
   (grep -rn 'cfg(feature = "sqlite")' --include=*.rs).
3. Verify every SqliteStore/SqliteConversationStore reference is either inside a
   cfg gate or inside an example whose required-features declares sqlite
   (grep -rn SqliteStore|SqliteConversationStore).
4. Verify rusqlite is only referenced by the two sqlite modules within echo-state
   (grep -rn rusqlite echo-state/src).
5. Execute: cd echo-agent && cargo check -p echo_state --no-default-features --locked
   (expect exit 0, no rusqlite/sqlite symbols needed).
```

## Expected Result

Echo-state compiles with no default features and zero rusqlite dependency; the
sqlite types are unreachable without the feature; the root `sqlite` feature
forwards to echo_state and keeps its own rusqlite dep for the root-level
SqliteRuntimeStateStore.
