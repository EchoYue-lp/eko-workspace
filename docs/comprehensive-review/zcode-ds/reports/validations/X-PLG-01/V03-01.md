## Claim

Every failure point in the load/activation cycle either rolls back to the
previous live state (in-session mutations) or degrades in a failure-safe way
(boot), and no failure path leaves partial candidate registrations live.

## Method

Static verification of each failure path in `apply_candidate` and its callers,
plus a targeted executable check:

```text
1. apply_candidate failure paths (plugin_runtime.rs:551-802):
   a. dependency resolution (:556-558) -> error before any mutation;
   b. prepare_application_components (:570-571) -> error before mutation;
   c. validate_agent_collisions (:572) -> error before mutation;
   d. lifecycle deactivate errors (:575-588) -> reactivate previous set + shutdown replacement LSP;
   e. monitor replacement error (:590-604) -> shutdown replacement LSP + reactivate previous lifecycle;
   f. replace_agent_components error (:622-648) -> restore previous registry/components/prepared,
      rollback monitors, shutdown replacement LSP, reactivate previous lifecycle;
   g. lifecycle activation error after swap (:655-719) -> deactivate candidate, rollback agent
      components to previous, rollback monitors, swap LSP back, reactivate previous set.
2. replace_agent_components failure handling (plugin_runtime.rs:804-909):
   wiring.errors non-empty -> unload candidate components + re-wire previous + re-register
   previous agents (:821-843); register_plugin_agents error -> same (:844-867).
3. wire_all per-plugin error collection (echo-agent/src/plugin.rs:155-395): failed_plugins
   set excludes plugins with errors from plugins_loaded; skill/hook/MCP per-component errors
   collected without aborting other plugins.
4. Caller-level rollback: enable/disable restore enabled state (plugin_runtime.rs:233-239,
   254-262), install rolls back the install (:278-284).
5. Boot path: new_with_source warn-only on reload error, continues with empty state
   (plugin_runtime.rs:174-176) -> canonical A-PLG-01-P2-01.
6. Activation-path failure: SkillRegistry::activate_dependencies recursion has no in-progress
   guard (echo-execution/src/skills/registry.rs:468-510) -> cyclic depends_on stack-overflows
   the process -> canonical F-SKL-01-P1-01 (empirically reproduced in F-SKL-01 V04-05, exit 134).
7. Executable check: cargo test -p echo-agent-app-core --lib --locked plugin_runtime
   (see V04-02 for the report) — 8/8 passed, including
   failed_real_reload_restores_previous_live_components and
   activation_failure_restores_previous_components_and_lifecycle.
```

## Expected Result

In-session mutation failures restore the previous live set (registry, components,
monitors, LSP, lifecycle); boot failures are either surfaced or degrade per-plugin
without silently disabling everything.

## Result

- Exit code: not-applicable for static steps; test suite exit 0 (V04-02)
- Summary:
  - All in-session mutation failure paths (a-g above) restore the previous set and
    reactivate the previous lifecycle; the rollback paths are dynamically tested
    (`failed_real_reload_restores_previous_live_components`,
    `activation_failure_restores_previous_components_and_lifecycle`, both passed).
  - `unload_agent_components` is invoked on every failure path that has already wired
    candidate components — no partial candidate stays live.
  - Monitor replacement has its own internal rollback (plugin_runtime.rs:1211-1234).
  - Boot failure is warn-only with an empty registry: the whole plugin set silently
    absent with no per-plugin degradation (canonical A-PLG-01-P2-01; static only).
  - Skill activation failure with cyclic dependencies aborts the process (canonical
    F-SKL-01-P1-01; empirical evidence in F-SKL-01 V04-05 at the same commits).
  - MCP connect failure inside wire_all marks the plugin failed (plugin.rs:348-358)
    but the failed server's earlier sibling connects are kept and unloaded together
    with the plugin's other components on rollback — consistent.

## Deviations

Two failure-safety violations exist but are already archived under canonical IDs:
boot all-or-nothing (A-PLG-01-P2-01) and activation stack overflow (F-SKL-01-P1-01).
No new failure-safety defect found beyond those.

## Conclusion

Supports: the in-session transactional rollback of the plugin seam is failure-safe
and dynamically verified. Does not prove: boot-path degradation (violated, canonical
A-PLG-01-P2-01) or activation-path robustness to malformed skill graphs (violated,
canonical F-SKL-01-P1-01).
