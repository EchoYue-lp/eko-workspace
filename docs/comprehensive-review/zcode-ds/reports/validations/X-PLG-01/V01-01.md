## Claim

For every component type (skills, hooks, Subagents, MCP servers, monitors, LSP,
themes, output styles, lifecycle callbacks, tools), the framework lifecycle
primitive and the EKO activation policy join through a registration key that has
a symmetric unregistration counterpart (source-scoped where sources exist), and
no second parallel authority exists on either side.

## Expected Result

One framework authority per component semantic with a symmetric removal key; EKO
adapter calls the framework primitives and owns no second registry/state machine;
each registration key carries source identity or is tracked per-plugin so unload
can be exact.

## Deviations

- MCP unload key is a bare server name shared with user-configured servers that
  connect into the same manager at boot (infra.rs:1069-1100, runtime.rs:110) and at
  runtime (`connect_mcp_server`, tauri/commands/mcp.rs:211). `McpManager::connect`
  is destructive last-wins (disconnect-old-then-connect-new, mcp/mod.rs:69-87).
  Promoted to finding X-PLG-01-P2-01.
- `unregister_skills_by_source` early-returns when the tracking registry finds no
  names, skipping the shared progressive registry (capabilities.rs:917-919).
  Promoted to finding X-PLG-01-P3-01.
- Pool agents copy skill descriptors with an additive-only refresh that is never
  invoked by plugin unload (agent_pool.rs:495-521; call sites only in panels.rs:536,
  :572, :624). Promoted to finding X-PLG-01-P3-02.

## Conclusion

Supports: the plugin seam is symmetric and source-scoped for skills, hooks,
Subagents, monitors, LSP, themes, and output styles, with one authority per
semantic; MCP is the exception (name-keyed, not source-scoped, destructive
replacement). Does not prove: behavior under failure (V03) or absence of stale
registrations under reload/switch sequences (V02/V04).
