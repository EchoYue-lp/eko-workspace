## Claim

The load/reload/unload cycle traverses the layers (surface -> PluginRuntimeService
-> framework primitives -> registries) with exact component replacement: reload
unloads the previous set before wiring the candidate, and every surface delegates
to the single runtime owner.

## Method

Cross-layer trace by inspection:

   apply_candidate), :110 (user MCP via infra::load_mcp_config).

## Expected Result

Each load entry point has a corresponding unload or replace path; reload is
unload-then-wire with the previous set restored on failure; a workspace switch
rebinds project-scoped components to the new workspace.

## Result

- Exit code: not-applicable (static trace; dynamic confirmation in V04-02)
- Summary:
  - Boot -> PluginRuntimeService -> apply_candidate: full chain verified; user MCP and
    plugin MCP share one McpManager namespace (runtime.rs:110 vs plugin.rs:332-347).
  - `/plugins reload`, enable, disable, install, uninstall all rebuild a candidate registry
    and run apply_candidate; disable additionally fires `PluginDisabled` (:256),
    uninstall unregisters lifecycle (:333).
  - `replace_agent_components` unloads the previous set (unload_agent_components :817) then
    wires the candidate — reload is a full teardown/rebuild, not incremental.
  - Deviation 1 (workspace): `switch_workspace`/`exit_workspace` never call the plugin
    runtime (grep: zero plugin_runtime references in either body, state.rs:844-1185), and
    `prepare_lsp` uses the boot-fixed `self.lsp.project_root` (plugin_runtime.rs:966),
    while `registry_for`/`scan` use `agent.working_dir()` at call time (:986-991). Previous
    workspace's project plugins stay live; new workspace's plugins absent until an explicit
    plugin command. Matches canonical A-PLG-01-P1-01.
  - Deviation 2 (hub): `enable_skill` loads the skill's parent directory (whole hub root for
    the flat layout, panels.rs:606-609); `disable_skill` has no runtime unload (returns
    requires_restart, :657-659); post-sync refresh `load_skills_from_dir` is a no-op for
    already-installed names (capabilities.rs:688-695). Matches canonical A-PLG-01-P2-02 /
    F-SKL-01-P2-01.
  - Deviation 3: `fire_loaded_events` fires for ALL candidate plugins on every successful
    reload (plugin_runtime.rs:790, :1048-1071); dropped plugins never receive
    `PluginDisabled` (only disable :256 / uninstall :337 call it). Matches canonical
    A-PLG-01-P3-01.

## Deviations

The three deviations above are re-anchored with current line numbers and folded
into the canonical findings (V05-01). No new defect class beyond those findings
was found in the load/reload/unload trace.

## Conclusion

Supports: single runtime owner across all surfaces; reload is teardown/rebuild;
the previous set is unloaded before the candidate is wired. Does not prove:
workspace-scoped lifecycle correctness (violated, canonical A-PLG-01-P1-01) or
hub lifecycle reversibility (violated, canonical A-PLG-01-P2-02).
