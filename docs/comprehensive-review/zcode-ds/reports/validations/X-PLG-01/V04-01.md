## Claim

No production registration point for a tool, Subagent, or hook lacks a matching
unload path, and no stale registration survives reload/unload/switch in the
verified component classes.

## Method

Repository-wide search for registration sites and their unload counterparts:

```text
1. Tools: grep register/unregister/replace_tool/remove_tool across
   echo-agent/echo-execution/src/tools.rs, echo-agent/echo-core/src/tools/mod.rs,
   capabilities.rs; grep add_skill/add_skills callers in both repositories.
2. Subagents: grep register_subagent_with_definition / register_subagent_factory /
   register_plugin_agents / unregister_subagent across both repositories.
3. Hooks: grep HookRegistry::register / register_plugin_hooks / register_user_hooks /
   unregister / clear_user_hooks / HookSource across both repositories.
4. MCP: grep McpManager::connect / disconnect / disconnect_mcp / connect_mcp_server.
5. Lifecycle: grep register_lifecycle / PluginLifecycleManager / deactivate_all / unregister.
6. Pool propagation: grep refresh_skill_descriptors / skill_descriptors in
   echo-agent-cli/echo-agent-app-core/src/agent_pool.rs, runtime.rs, panels.rs.
7. Stale-survival checks: reload drops plugin (scan skips invalid manifest) vs lifecycle
   entry; workspace switch vs plugin components; hub disable vs runtime registry.
```

## Expected Result

Every production registration has a symmetric removal; after a disable/reload/
switch, no tool, Subagent, hook, skill descriptor, or lifecycle entry from the
removed source remains reachable in any agent (primary or pool).

## Result

- Exit code: not-applicable (static search)
- Summary:
  - Tools: no plugin-specific direct tool registration exists; plugin tools arrive only
    via skills (removed by unregister_skills_by_source) and MCP (removed by
    disconnect_mcp). `ToolManager::unregister` exists (echo-execution/src/tools.rs:542).
    `add_skill` (code skills) registers tools with no removal API — zero production
    callers (only capabilities.rs:617 self-call and a test).
  - Subagents: `unregister_subagent` (capabilities.rs:406-424) removes instance,
    definition, factory, and dispatch catalog entry (subagent/registry.rs:275-293,
    capabilities.rs:409-421). Plugin Subagents registered only on the primary agent
    (plugin_runtime.rs:818). No stale Subagent registration found in the primary.
  - Hooks: all three sources have symmetric removal; skill hooks removed per removed
    name (capabilities.rs:925-928); plugin hooks by HookSource::Plugin
    (plugin_runtime.rs:1168-1170); user hooks by clear_user_hooks on boot and watcher
    reload (infra.rs:1935, config_watcher.rs:265).
  - Deviations found (each folded into a finding or a canonical ID):
    a. MCP connections are keyed by bare server name with destructive replacement
       (mcp/mod.rs:69-87) and plugin unload disconnects by name without restoring
       pre-plugin ownership -> X-PLG-01-P2-01.
    b. `unregister_skills_by_source` early-returns on the tracking registry's result
       and silently skips the shared progressive registry (capabilities.rs:917-919)
       -> X-PLG-01-P3-01.
    c. Pool agents copy skill descriptors additively; `refresh_skill_descriptors`
       (agent_pool.rs:495-521) never removes descriptors, and plugin unload never
       invokes it (call sites only in panels.rs:536/:572/:624) -> stale plugin skill
       descriptors survive in pool agents after plugin disable -> X-PLG-01-P3-02.
    d. Lifecycle manager entries survive a reload that drops a plugin (deactivate_all
       keeps entries, lifecycle.rs:137-147; invalid-manifest scan skips the plugin,
       plugin registry scan) -> canonical F-PLG-01-P3-02.
    e. Partial-wire facade entry points wire_skills/wire_hooks/wire_mcp have no unload
       counterpart and zero callers -> canonical F-PLG-01-P3-05.
    f. PluginLoaded re-fired for unchanged plugins on every reload; dropped plugins get
       no PluginDisabled -> canonical A-PLG-01-P3-01.
```

## Deviations

Items a-f above. None of them are silent stale *hooks* or *Subagents* on the
primary agent; the stale classes are MCP ownership, dual-registry divergence,
pool descriptor copies, and lifecycle entries.

## Conclusion

Supports: primary-agent tool/Subagent/hook unload is complete and symmetric.
Does not prove: pool-agent descriptor freshness after plugin lifecycle changes
(violated, X-PLG-01-P3-02), MCP ownership restoration (violated, X-PLG-01-P2-01),
or dual-registry consistency of unload (latent, X-PLG-01-P3-01).
