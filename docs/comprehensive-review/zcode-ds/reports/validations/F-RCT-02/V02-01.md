## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Entry chain verified as expected. EKO (`echo-agent-cli`) does not call the
    non-streaming entry: `chat_driver.rs:513` and `executor.rs:3119-3130` use
    `execute_stream_*`; the non-streaming path is framework public API
    (`Agent::chat/execute`, `StructuredAgent`).
  - FinalAnswer producers: guard block (stream_channel.rs:163), direct_answer_stream
    (stream_channel.rs:478), prepare_turn UserPromptSubmit block (prepare.rs:70),
    finalize_completed_run (finalize.rs:87), emit_final_text (finalize.rs:179).
    Err producers: think intervention cancel/block (think.rs:47,65), tool batch
    timeout (tools.rs:285-292), finalize_no_response (finalize.rs:226),
    finalize_max_iterations (finalize.rs:267). `AgentEvent::Error` only from
    direct_answer_stream chunk errors (stream_channel.rs:390).
  - **Error-forwarding asymmetry (finding P1-01):** the streaming wrapper
    forwards a loop error with `let _ = tx.try_send(Err(e))`
    (stream_channel.rs:306-311), but the non-streaming wrapper only logs
    `"Core loop error (already sent via channel)"` (react_loop.rs:711-727).
    Errors propagated via `?` out of `run_core_loop` without a preceding send —
    concretely `finalize_completed_run` intervention cancel/block
    (finalize.rs:40-53, `return Err(...)` without any `tx` write) — close the
    channel with no terminal; `rx.recv()` returns `None` and `run_react_loop`
    returns `Ok(answer)` with `answer == ""` (react_loop.rs:729-750). The
    comment at react_loop.rs:724 is false for this class of errors.
  - **Trace finalization (finding P2-01):** `finalize_run` call sites are
    finalize.rs:175 (text terminal), :216 (no-response), :261 (max-iterations),
    stream_channel.rs:226,235 (streaming direct answer), react_loop.rs:637,647
    (non-streaming direct answer). `finalize_completed_run` (finalize.rs:23-112,
    the tools-branch terminal) never calls `finalize_run` — trace status stays
    `Running`, `final_output`/`finished_at` never set, on every final_answer-
    tool-completed turn (both streaming and non-streaming).
  - Stop-hook continuation (finding P2-04): text terminal sends `FinalAnswer`
    (finalize.rs:179) BEFORE consulting the Stop hook; a `continue_reason`
    (hooks/types.rs:1087, set by hook scripts, hooks.rs:1429) makes
    `emit_final_text` return `ControlFlow::Continue` (finalize.rs:190-201) —
    the loop continues and can emit a second FinalAnswer; the non-streaming
    caller already broke on the first FinalAnswer (react_loop.rs:733-736), so
    the spawned task runs a hidden extra LLM request before abandoning on the
    first failed send. The tools branch pushes the note only and never
    continues (finalize.rs:95-105) — divergent Stop semantics between branches.
  - `AgentEvent::Cancelled` (react_loop.rs:737-740) is unreachable in the main
    loop (no producer; only subagent/executor.rs:2013).
  - UserPromptSubmit hook (finding P2-03): fired in `prepare_stream_context`
    (context.rs:544-546) AND in `prepare_turn` (prepare.rs:57-88, inside the
    shared loop) — twice per streaming turn, once per non-streaming turn
    (`prepare_react_context` react_loop.rs:508-591 never fires it).
