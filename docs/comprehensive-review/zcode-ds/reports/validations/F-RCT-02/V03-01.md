## Claim

Loop termination and max-step semantics hold under the declared invariants:
`max_iterations = 0` means unlimited; the loop always terminates in bounded
iterations otherwise; a terminal event is emitted exactly once per turn; loop
detection (duplicate/no-progress) is either wired or honestly absent; the
test suite covers these invariants.

## Method

Static invariant inspection against the loop body and the existing tests:

```text
read: stream_channel.rs :520-757 (loop bound, wind-down, budget, branch dispatch, post-loop)
read: phases/finalize.rs (max-iterations/no-response/text/tools terminals) + its tests
read: loop_detector.rs + its unit tests
grep test inventory: #[tokio::test]/#[test] in src/agent/react/run/ and loop_detector.rs
read: echo-agent-cli/echo-agent-app-core/src/profiles/types.rs:50-52 (EKO default max_iterations)
read: src/agent/react/run/phases/verify.rs (verifier retry cap)
```

## Expected Result

- `max_iterations == 0` → `usize::MAX` sentinel (stream_channel.rs:521-527);
  wind-down gated on `max_iterations > 0` (:540-548); exhaustion →
  `finalize_max_iterations` → `AgentError::MaxIterationsExceeded`.
- `LoopDetector` (exact duplicate Break, failure-streak Warn, no-progress Warn)
  either runs per iteration or has no runtime claim.
- Tests: loop-termination tests (text answer, tool cycle, empty response,
  cancellation, wind-down, budget) and a max-iteration-exhaustion test exist;
  loop-detector unit tests exist and are wired to the loop.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - `max_iterations = 0` → `usize::MAX` sentinel confirmed
    (stream_channel.rs:521-527); wind-down and final-only budget logic gated on
    `max_iterations > 0` (:540-548, :616-641); iteration loop is
    `for iteration in 0..max_iterations` (:528) and post-loop
    `finalize_max_iterations` (:754-756) is reachable only when the bound is
    finite. `finalize_max_iterations` sends
    `AgentError::MaxIterationsExceeded(snap.config.max_iterations)`
    (finalize.rs:267-269).
  - **Loop detection is dead (finding P2-02):** `LoopDetector` is never
    instantiated anywhere; the loop's only step limit is `max_iterations`.
    EKO's profile default is `max_iterations: 0` (unlimited,
    `echo-agent-cli/echo-agent-app-core/src/profiles/types.rs:50-52`), and EKO's
    main-agent builder passes it through (`infra.rs:290`); no `run_budget` is
    configured for the main agent (grep of infra.rs: no run_budget hit). So the
    default EKO main agent has no iteration cap and no duplicate/no-progress
    protection; the only runtime guards are per-tool/batch timeouts.
    `loop_detector.rs` tests (5) exercise the detector in isolation and pass,
    but no test exercises it inside the loop — consistent with no wiring.
  - Terminal-once invariant: text terminal can emit `FinalAnswer` then
    continue via Stop-hook `continue_reason` (finalize.rs:179 vs :190-201),
    allowing a second `FinalAnswer` in one turn (finding P2-04); no test covers
    a Stop hook with `continue_reason`.
  - No test drives a finite `max_iterations` to exhaustion through the loop
    asserting `MaxIterationsExceeded`; only the unit test of the phase itself
    exists (finalize.rs:336-361). No test covers: non-streaming error
    forwarding (P1-01), tools-branch trace finalization (P2-01), or
    UserPromptSubmit double-firing (P2-03).
  - Verifier retry cap confirmed: `retry_count >= verifier_max_retries`
    short-circuits to accept; critic errors fail open (verify.rs:35-41, 91-94).
  - NoResponse terminal confirmed: neither tool calls nor content →
    `finalize_no_response` sends `NoResponse` error and marks trace Failed
    (finalize.rs:211-231); test `run_core_loop_empty_llm_response_terminates_gracefully`
    (stream_channel.rs:1934-1965) covers the LLM-error variant.
