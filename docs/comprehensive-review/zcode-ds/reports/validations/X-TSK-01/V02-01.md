## Claim

There is exactly one revisioned TaskRun graph with exactly one live
validator, one live executor, and one store authority: the framework
`PlanValidator` + `RuntimeDagExecutor` + `TaskRevisionService`/`RevisionedTaskStore`
boundary, with EKO contributing only policy adapters. No second
validator/executor/store reaches production on either repository's live
paths.

## Method

Authority call-graph sweep over both repositories:

```text
1. Executor: grep "RuntimeDagExecutor::new" in echo-orchestration/src,
   echo-agent/src, echo-agent-cli (all crates).
2. Validator: grep "validate_task_snapshot|PlanValidator::default|PlanValidator::new"
   in both repos; classify each site production vs #[cfg(test)].

5. Legacy reachability: grep "TaskManager::new|TaskExecutor::new|execute_all|
   ManagedTaskDagController" and confirm test-only constructions.
```

- One production `RuntimeDagExecutor` construction (EKO `execute_runtime_plan`);
- one production validator call path (framework `finalize_and_validate` +
  executor safe point); all EKO `PlanValidator` sites `#[cfg(test)]`;
