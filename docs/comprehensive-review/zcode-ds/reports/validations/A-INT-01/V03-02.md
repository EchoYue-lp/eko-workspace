## Claim

Browser session cleanup and MCP state cleanup are complete and bounded: on
shutdown/interrupt all sidecar clients and sessions are closed; session
metadata does not accumulate without bound; MCP health/state is consistent
with the agent's live connection set.

## Method

Static inspection:

```text
1. Browser shutdown: mod.rs:194-204 (shutdown: cancel token, close_all,
   close both clients), mod.rs:185-192 (interrupt: close clients); TUI
   exit paths main.rs:334,399,443; GUI desktop.rs:263-267.
2. Session manager: session.rs:102-158 restore_metadata (all Closed on
   restore, fresh session on reuse), session.rs:504-521 close_all (status
   Closed + SessionClosed event + persist), session.rs:523-539 persist
   (JSON file per session id, never deleted on close or restore).
3. MCP state: disconnect_mcp_server/toggle remove mcp_health entries
   (mcp.rs:277-280, 363-366); run_mcp_health_check rebuilds the map from
   agent.list_mcp_servers() each cycle (state.rs:751-797).
4. Sidecar children: McpClient close() -> StdioTransport close (drop path,
   F-INT-01 P3-04 cross-ref); timeout-cancelled McpClient::new during GUI
   reconnect (15 s) or browser startup can abandon an un-initialized npx
   child (no kill-on-drop verified in stdio transport).
```

## Expected Result

- No browser process/session outlives app exit; session metadata does not
  grow unboundedly; health map never shows stale entries for disconnected
  servers.

## Result

- Exit code: not-applicable (static)
- Summary:
  - Browser: shutdown is wired on every entry point; sessions persisted as
    Closed; sidecar clients closed. Correct.
  - Session metadata files accumulate per conversation forever: `persist`
    writes `{session_id}.json` and neither `close_all`, `restore_metadata`,
    nor `lease_tab` ever deletes files; `restore_metadata` reloads ALL of
    them at every boot and re-persists. For long-lived installations with
    many conversations this is unbounded (small files, one per conversation
    ever created). Task report finding P3-01.
  - MCP health: consistent — rebuilt each cycle from the live agent list,
    removed on disconnect.
  - Cancelled startup can orphan a sidecar child: a GUI reconnect or browser
    startup that times out mid-`McpClient::new` drops the init future; the
    stdio transport child is not kill-on-drop (framework-side lifecycle,
    F-INT-01 P3-04 territory). Recorded as residual uncertainty, not a
    new finding (framework-owned).
- Log/artifact: none

## Deviations

- Unbounded session metadata files (P3-01) deviate from the expected result.

## Conclusion

Supports: browser session/sidecar cleanup on exit is complete; MCP health
state is consistent; session metadata accumulation is the only cleanup gap.
Does not prove child-process reaping behavior after a timed-out startup
dynamically.
