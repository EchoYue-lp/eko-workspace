## Claim

EKO-side browser, MCP, and LSP concepts have exactly one authoritative
implementation each across both repositories (no parallel client, transport,
session manager, or second config surface with independent authority); the
framework `echo-integration` MCP/LSP implementations are the sole protocol
implementations.

## Method

Repository-wide grep over `echo-agent-cli` (src, echo-agent-app-core, eval)
and `echo-agent`:

```text
1. MCP EKO files: grep -rn "connect_mcp_server|disconnect_mcp_server|connect_mcp|mcpServers|mcp_servers|McpServerInfo|McpTransportConfig|mcp.json|mcp__" echo-agent-cli --include="*.rs" -l
2. LSP EKO files: grep -rn "lsp|Lsp|LSP" echo-agent-cli/{echo-agent-app-core/src,src} --include="*.rs" -l
3. Browser EKO files: grep -rn "browser" echo-agent-cli/{echo-agent-app-core/src,src} --include="*.rs" -l
4. Parallel transport/client search: grep -rn "StdioTransport|SseTransport|HttpTransport|JsonRpcRequest|McpClient|McpManager|LspClient|StdioLspClient|LspManager|BrowserSession" echo-agent-cli --include="*.rs"
5. Second config surface: grep -rn "mcp_config|McpConfigFile|lsp.yaml|LspConfig" echo-agent-cli --include="*.rs"
6. fs writes of mcp config: grep -rn "mcp.json" echo-agent-cli/src echo-agent-cli/echo-agent-app-core/src
7. worker terminology check: grep -rn "Worker|worker" echo-agent-cli/echo-agent-app-core/src/browser echo-agent-cli/echo-agent-app-core/src | head
```

- No file write to `mcp.json` inside echo-agent-cli (checked as part of the

## Deviations

  (global) for the inventory/`config list` command, but the actual boot loader
  (`infra.rs:1091`) only reads `user_data_path("mcp.json")` plus CLI/env/YAML
  overrides — the discovered project `.mcp.json` is not loaded at boot by the
  runtime (inventory-only). Recorded as an observation (see task report
  P2-02 context and Coverage).
- The CLI `/mcp connect|disconnect` commands print but do not connect (see
  V02-01 / task report P2-01) — this is a stub, not a second implementation.
