## Claim

Every growth-sensitive allocation, lock, and task-lifecycle site on the key
paths (react loop, chat driver, TaskRuntime DAG executor, compression,
persistence, scheduler, frontend reducers) is identified, and each identified
site is classified as bounded or unbounded with an evidence anchor.

## Expected Result

A complete inventory of bounded vs unbounded growth points with per-site
anchors, so the task report can list the unbounded set (including new
findings) and cross-reference canonical findings.

## Result

- Exit code: not-applicable (static inspection)
- Duration: ~35 min
- Summary:

Bounded sites (verified):
- Framework ReAct stream channel: `mpsc::channel(buffer)` bounded
  (stream_channel.rs:41); buffer-full drops events (canonical F-RCT-03-P1-01).
- Framework RuntimeDagExecutor: `Semaphore(max_concurrent_subagents)` +
  `JoinSet` wave drain (runtime_executor.rs:201-366); no unbounded growth.
- EKO AgentPool: `max_agents` cap for conversation agents, RAII leases
  (tasks/service.rs:89-104), `release` on run driver (run_driver.rs:100) and
  cron (scheduler/runner.rs:106-109), 5-min idle cleanup monitor
  (agent_pool.rs:749-806).
- EKO HookEventDispatcher: bounded `sync_channel` with deliberate backpressure
  (hook_event_dispatcher.rs:88,127).
- EKO TaskRuntime projection compaction: per-field char caps
  (compact_context.rs:30-34).
- Frontend reducers: `MAX_MESSAGES=500` (chatStore.ts:104-111),
  `MAX_EVENTS=500` (taskRuntimeStore.ts:14,185), `MAX_EVENTS_PER_RUN=300`
  (subagentRunStore.ts:145,486).
- Tool artifacts: 1 MB spill threshold + 30-day max age cleanup
  (echo-core/src/tools/artifact.rs:16-17,271-272; infra.rs:33,71-73).
- Checkpoints: one file per conversation, overwritten atomically
  (src/state/file.rs:170-187).
- Run cancel-token registrations: removed on Drop
  (store.rs:141-159).
- EKO scheduler background runs: semaphore-bounded (tasks/service.rs:167).

Unbounded sites (verified, new findings in Q-PERF-01 report):
- `FileTaskShadow::rewrite_plan` re-reads the whole `events.jsonl` and
  rebuilds `plan.json` + `run-state.json` on every state-affecting event —
  O(N) per transition, O(N²) per run, under the per-run write lock on the DAG
  executor's critical path (file_shadow.rs:208-280, :362-379; 14 call sites
  in store.rs).
- EKO event fanout uses `mpsc::UnboundedSender` with zero backpressure:
  `ChannelChatSink` (chat_driver.rs:575-591; used at repl.rs:494,
  channels.rs:246, chat_driver.rs:1129) and eight `UnboundedSender<AgentEvent>`
  instances in TUI (src/tui/events.rs:1042,1225,1297,1344,1479,2022,2615).
- `FileConversationStore::save_messages` rewrites the full conversation record
  per save — O(N) per message, O(N²) per conversation; `list_conversations` /
  `search_conversations` read every record file (file_conversation.rs:350-376,
  :215-241).
- `JsonlRunStore` in-memory cache never evicts (trace/mod.rs:677-708,748);
  `FileTaskShadow` seq_cache and run_write_locks maps grow with total runs
  ever written (file_shadow.rs:26-34,185).
- ReAct loop: `max_iterations == 0` means unlimited
  (stream_channel.rs:521-527); EKO default is 0 (echo-agent config.rs:469)
  and EKO passes `run_budget: None` (chat_driver.rs:509), so the wind-down
  budget never fires; LoopDetector never consulted (canonical
  F-RCT-02-P2-02).
