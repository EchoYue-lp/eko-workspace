## Claim

The three representative large-input paths (large event stream, large
conversation compression, large file diff) have measurable, code-anchored
growth behavior: for the event stream this is measured against real on-disk
data under `~/.eko`; compression and diff growth are statically estimated
from verified code with concrete arithmetic.

## Method

```text
1. Real-data measurement (event stream):
   - ls -la ~/.eko/runs/*.jsonl; wc -l per file
   - python3 line-size analysis of the largest run file
     (run_e99256ec-750b-459b-ad69-e7271546f142.jsonl)
   - python3 event-kind/full_output analysis of the largest TaskRuntime
     events.jsonl (taskrun:3a89573f-...)
2. Static estimation (compression): verified SlidingWindowCompressor keeps
   window_size=40 messages by count only and never re-checks token limits
   (echo-state/src/compression/compressor/sliding_window.rs:48-75);
   summary compressor appends one system summary per pass
   (echo-state/src/compression/compressor/summary.rs, canonical
   F-CMP-01-P1-02); k passes => k summaries retained.
3. Static estimation (diff): src/cli/cmd_impls/diff_cmd.rs reads both files
   fully into memory (lines 148-160) and builds TextDiff::from_lines
   (diff.rs:76); `similar` patience diff is O(N+M) memory, roughly
   O(N log N) average time, O(N*M) worst.
4. Behavior confirmation: cargo test -p echo_agent --lib trace
   (29 passed, 0 failed) confirms the JsonlRunStore append/save semantics
   exercised in the measurement model.
```

## Expected Result

Real run files should show the O(N²) signature (line sizes growing with the
event index; total bytes far exceeding N × average event size), and
compression/diff estimates should bound growth in terms of conversation
length, pass count, and file size respectively.

## Result

- Exit code: 0 (cargo test); not-applicable for static parts
- Duration: ~15 min
- Summary:

1. Real event-stream data (`~/.eko/runs`, 8.4 MB total, 22 files):
   - Largest: `run_e99256ec...jsonl` = 2,166,731 bytes, 177 lines.
   - Line sizes: first = 1,140 B; last = 35,609 B; max = 106,641 B;
     cumulative sum = 2,166,731 B; ratio last/first = 31.2.
   - Linear (event-per-line) reference would be ~177 × ~1-2 KB ≈ 200-350 KB;
     the actual file is ~7-10× larger. Line sizes grow with event index —
     the O(N²) "full run per event" signature of `append_event` →
     `save` (trace/mod.rs:793-801, 733-750) confirmed in production data.
   - Two other files exceed 1 MB (1,587,384 B / 165 lines; 1,126,343 B /
     103 lines), i.e. multi-MB growth from ~100-event turns.
2. Real TaskRuntime events.jsonl (taskrun:3a89573f..., 140,402 B, 46 events):
   - Biggest single line = 33,863 B, event `subagent_released` carrying
     `full_output` (17,796 chars) + `result` (8,394 chars) + `summary`.
   - Confirms A-TSK-06-P3-02 mechanics: unbounded full_output inflates every
     line and, combined with the per-event full rebuild (Q-PERF-01-P2-01),
     drives per-transition read cost.
3. Compression static estimate: with window_size=40, after k compression
   passes the retained list holds ~40 conversation messages plus k summary
   messages (one immortal system summary per pass). For a long session that
   compresses once per ~40 messages, k ≈ turns/40; retained summary tokens
   grow linearly in k with no token-based eviction (F-CMP-01-P1-01/02), so
   prompt assembly grows without a token bound even though message count is
   capped.
4. Diff static estimate: two 10 MB files => ~40 MB peak (read strings +
   TextDiff line arrays + hunk copies); patience worst case O(N*M) on
   pathological inputs; the CLI command is user-invoked, so impact is local.

## Deviations

The `~/.eko` data is a single-machine sample from earlier development runs;
it is evidence of real growth behavior, not a controlled experiment.

## Conclusion

Supports the priority and impact statements of Q-PERF-01-P2-01 (measured
O(N²) TaskRuntime shadow rebuild combined with unbounded payloads),
Q-PERF-01-P3-01..03, and confirms canonical F-OPS-01-P2-02 and A-TSK-06-P3-02
against current on-disk behavior. Compression and diff paths show bounded
memory but token-unbounded prompt growth (canonical F-CMP-01).
