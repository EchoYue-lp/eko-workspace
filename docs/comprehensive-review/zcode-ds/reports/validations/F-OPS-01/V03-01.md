## Result

- Exit code: not applicable (inspection procedure)
- Duration: n/a
- Summary of violations:
  - (a) FAIL — tick predicate `next <= now` is unsatisfiable: cron `upcoming()`
    returns times strictly after its reference instant (≥ +1s). No task ever
    fires from `tick()`; only manual `run_once` works. Cancel is checked only
    between ticks; in-flight fires are never cancelled; fires are awaited
    serially with no timeout.
  - (b) FAIL — `HeadlessConfig.exit_on_error` is never read by `run_headless`
    (only demo/example and unit tests touch it); headless inherits the
    non-streaming `Ok("")` empty-success path (F-RCT-02-P1-01).
  - (c) PARTIAL — ToolCall args redacted via `new_tool_call`; ToolResult preview
    is post-guard (redacted output); BUT `Run.input` (raw user text),
    `final_output`, `run.error`, and `ToolError.message` are stored unredacted;
    args are not size-capped; `JsonlRunStore` rewrites the full run per event →
    quadratic file growth; no retention.
  - (d) PASS for disabled — both repos default to telemetry off; the CLI
    non-telemetry path is a plain local fmt layer. FAIL for enabled — framework
    `init_telemetry` has no idempotence guard (second call or pre-existing
    subscriber → `registry().init()` panic); EKO masks it with OnceLock and
    discards the init result.
  - (e) FAIL — audit events store raw tool args/output (AuditStage,
    AuditCallback); trace stores raw input/output/error; scheduler store keeps
    raw fire error text in `last_result`. EKO does not enable audit today, so
    audit exposure is conditional on a consumer opting in.
