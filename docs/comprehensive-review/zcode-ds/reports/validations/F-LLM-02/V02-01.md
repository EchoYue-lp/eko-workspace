## Claim

Streamed and non-streamed responses are mapped to the neutral contract without semantic loss: streaming chunks merge deltas, usage is delivered in both modes, and the F-LLM-01-P1-01 silent-drop path is the only streaming loss channel for the OpenAI adapter.

## Method

Trace the two response directions end to end.

## Expected Result

- Streaming: each `ChatCompletionChunk` → `ChatChunk { delta, finish_reason, usage }` with no field loss; usage-only final chunk preserved.
- Non-streaming: `ChatCompletionResponse` → `ChatResponse { message, finish_reason, raw }` with usage reachable via `raw.usage`.
- Malformed-chunk handling matches F-LLM-01-P1-01 (warn + drop, stream continues), with no additional adapter-side loss.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary:

Streaming mapping (openai.rs:366-375): `chunk.choices.first()` → `delta` (`unwrap_or_default`), `finish_reason`, `usage: chunk.usage.clone()`. For the standard `include_usage` final chunk (`choices: []`, `usage: {...}`), `delta`/`finish_reason` are defaulted and usage is preserved — no loss. Consumers: think.rs:110-114 (`last_usage`), think.rs:147/199-211 (`usage_reported` + `AgentEvent::LlmUsage`); stream_channel.rs:398-439 (same on direct-answer stream).

Non-streaming mapping (openai.rs:302-317): `raw.choices.first().ok_or(LlmError::EmptyResponse)?` → `ChatResponse { message, finish_reason, raw }`. Usage reachable only via `raw.usage` (react_loop.rs:100-102); `ChatResponse` has no `usage` field — consistent with F-LLM-01 (raw contract, P2-01).

Loss channels found:

1. `parse_sse_chunk` serde failure → `warn!` + `None` (client.rs:99-105) — F-LLM-01-P1-01, trigger surface confirmed for `OpenAiClient::chat_stream` / `DefaultLlmClient::chat_stream` (openai.rs:357, :445), i.e. every streaming call. A wrong-typed `usage` in the final chunk makes the whole turn `usage_reported: false`.
2. **Amplification (new detail)**: the `while let` chain at client.rs:317-319 exits the whole event loop on the first `None` from `parse_sse_chunk`; if the byte stream then ends, the final flush (client.rs:336-350) feeds the entire remaining buffer through `parse_sse_data` (which joins multiple `data:` lines with `\n` into one payload), so any already-buffered subsequent events are merged and dropped together. Common case (malformed chunk alone in buffer) behaves as F-LLM-01 describes; the multi-event tail loss is an extra severity multiplier, same root cause.
3. `[DONE]` is turned into `Some(Err(LlmError::NetworkError(sentinel)))` (client.rs:81-86) and matched by string containment (client.rs:329, :347) — F-LLM-01-P3-01; adapter has no alternative handling.

No usage loss beyond the two channels above: `stream_options.include_usage` is hardcoded on (openai.rs:346), so the final usage chunk is requested on every stream.

## Deviations

- `finish_reason` from streaming chunks is delivered in `ChatChunk.finish_reason` (openai.rs:371) and re-wrapped into `ChatCompletionChunk` (think.rs:339) but `process_stream_chunk` (processor.rs:16-88) never reads it; `ThinkOutput` (think.rs:249-257) carries no finish_reason. Adapter is faithful; the drop is framework-core side (F-RCT scope, recorded in V03).
