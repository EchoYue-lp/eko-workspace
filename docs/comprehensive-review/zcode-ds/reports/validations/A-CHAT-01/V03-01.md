## Claim

(a) No sink owns turn lifecycle, retry, or state-transition authority — sinks
only render/transport events (task question). (b) At the EKO boundary
(`drive_chat` + `ChatSink` + GUI wrapper) exactly one truthful terminal is
delivered per turn, and the product lifecycle terminal agrees with the agent
stream terminal. (c) The required stream error/cancel/steer fixtures exist.

## Method

Full reads of `chat_driver.rs` (1175 lines incl. tests), `chat_resources.rs`,
the three production sinks (`TuiChatSink` events.rs:2020-2210,
`TauriChatSink` chat.rs:1141-1417, `ChannelChatSink` chat_driver.rs:571-591),
the GUI wrapper (`send_chat_message` chat.rs:443-733), the REPL consumer
(repl.rs:477-849), the channel aggregator (channels.rs:515-654), the envelope
adapter (`echo-agent/echo-core/src/agent/event_envelope.rs:107-194`), and the
terminal definition (`echo-core/src/agent/mod.rs:331-336`:
`FinalAnswer | Cancelled | Error`). Fixture inventory: all tests in
`chat_driver.rs` `#[cfg(test)]` (9 tests), `surface_contract.rs`, and a grep
for cancel/error/steer tests at the driver level.

## Expected Result

Sinks are stateless renderers; every turn ends with exactly one terminal
envelope; the GUI's terminal status equals the agent terminal; tests cover
stream error, cancel, and steer at the driver boundary.

## Result

- Exit code: 0 (inspection completed)
- Summary:
  (a) Sink responsibility diff:
  - `TuiChatSink` (events.rs:2031-2209): pure event-to-event mapping into an
    unbounded mpsc; no state, no authority.
  - `ChannelChatSink` (chat_driver.rs:585-591): pure transport
    (`tx.send(event).is_ok()`).
  - `TauriChatSink` (chat.rs:1341-1417): maps events, emits Tauri events,
    AND owns durable tool-execution projection state — `ToolExecutionRepository`
    start/append_output/finish/cancel (chat.rs:1209-1316), `tool_completions`
    and `active_tool_ids` maps, `cancel_active_tools` on
    `Cancelled`/`Error`/non-running `TurnStatus` (:1325-1328, :1365-1368).
    This is surface projection state (GUI tool cards), not turn lifecycle
    authority; the sink never transitions the turn or retries. The asymmetry
    is where projection state lives (GUI inside the sink, TUI in `TuiApp`
    messages, channel in the aggregator buffer), not what it does.
  - No sink owns lifecycle/retry/state authority — task question holds with
    the caveat that `TauriChatSink` is not "thin" (carries durable projection
    state) and the GUI wrapper, not the driver, invents the product turn
    lifecycle (`TurnStatus`).
  (b) One-terminal invariant:
  - Envelope: exactly one terminal per stream — truncates at first terminal
    and fabricates `Error{"agent stream ended without a terminal event"}` on
    terminal-less ends (event_envelope.rs:173-191); never yields `Err`
    (raw `Err` items become `Error` payloads, :134-140). Verified by the
    envelope's own tests (`normalizes_missing_and_duplicate_terminals`,
    event_envelope.rs:352-396).
  - Driver: forwards envelopes until the first terminal, then the stream
    ends (chat_driver.rs:540-561); `Err` branch (:548-561) is unreachable
    with the current envelope. `drive_chat` returns `Ok(())` for every
    envelope-normalized outcome, INCLUDING `AgentEvent::Error` terminals and
    the fabricated terminal-less error.
  - GUI wrapper (chat.rs:690-696): `terminal_status = cancelled if
    cancel_for_status.is_cancelled() else completed if outcome.is_ok() else
    failed`. Because `outcome` is `Ok(())` for error-terminated turns, an
    error-terminal turn is reported `TurnStatus("completed")` + `Done` to the
    frontend while the `ChatEvent::Error` (e.g. "agent_stream: agent stream
    ended without a terminal event", or a NoResponse error) was already
    rendered — two contradictory terminal signals at the product boundary.
  - Cancelled turns (F-RCT-03-P1-02: main loop never emits `Cancelled`):
    cancel ends the stream as NoResponse Err or a terminal-less abandon; the
    envelope converts it to an `Error` payload; the GUI then reports
    `TurnStatus("cancelled")` but the user also sees the fabricated/derived
    error message; the TUI mitigates via `active_cancel.is_cancelled()`
    (events.rs:806-841 renders "Cancelled by user."), the GUI has no such
    masking (`agent_event_to_chat_event` maps Error -> `ChatEvent::Error`,
    chat.rs:1563-1565).
  - Channel aggregator depends on the terminal for the final flush
    (channels.rs:563-575: flush on FinalAnswer/Cancelled, Err on Error) — it
    gets a terminal because the envelope always yields one; on dropped
    terminal-Err (F-RCT-03-P1-01, buffer-full) the raw stream ends without a
    terminal and the envelope fabricates an Error, so the buffered partial
    text is flushed together with an error outbound message.
  (c) Fixture inventory (stream error / cancel / steer):
  - Existing: `drive_chat_streams_agent_events_via_sink`
    (one-terminal contract via `has_valid_contract`,
    chat_driver.rs:734-748,836-895), `task_mode_creates_formal_run_and_
    rejects_direct_fallback` (:758-833), projection-across-spawn (:897-996),
    mode-hint (:998-1064), tool exclusion (:1066-1122),
    `channel_chat_sink_forwards_events` (:1124-1174).
  - Missing: NO test drives a cancelled token through `drive_chat`; NO test
    with an `AgentEvent::Error` terminal or a terminal-less stream (the
    Ok(()) mislabeling is untested); NO sink-returns-false test; NO steer
    test at the driver level (steer is out-of-band via the framework mailbox,
    F-RCT-05-P1-02); `MockLlmClient` used by the tests emits content+usage in
    one chunk (F-TST-01-P1-01) so streaming order/loss defects cannot be
    reproduced at this level.

## Deviations

None beyond the recorded facts above (these are the findings, not procedural
deviations).

## Conclusion

Supports: drive_chat owns one application lifecycle; sinks render/transport
(with the GUI sink carrying durable tool-execution projection state); the
envelope boundary enforces one agent terminal per turn. Does not support: the
product lifecycle terminal agreeing with the agent terminal — the GUI's
terminal status is derived from `drive_chat`'s Result, which is `Ok(())` for
error-terminated and (non-token) cancelled turns (A-CHAT-01-P1-01). The
Interrupt wire variant is defined-and-consumed but never produced
(A-CHAT-01-P2-01). Fixture gaps: no driver-level error/cancel/steer tests.
