i.e., a per-surface inventory of missing event/tool/attachment/HITL paths can
be produced, each classified as (a) shared-core present, (b) surface-level

A-CHAT-01, A-HITL-01, A-INT-01, A-OUT-01, A-EVO-01 were used to classify
known gaps; anchors for newly discovered gaps were re-verified in source.

## Deviations

- Channels are NL-only by design (no slash command surface at all:
  `parse_channel_mode_command` + four NL special handlers). The rows
  classified "new" for channels (task management) reflect that no
  natural-language route exists either — the agent has no run-control tool
  (`task_execute` only), so a channel user cannot pause/cancel a run from
  the channel.
- REPL browser: browser *tools* are registered on the primary agent
  (infra.rs:454-455) and callable via chat; only the management surface is
  missing. Impact is therefore bounded (no sidecar status/restart path),
  unlike MCP CLI stubs which block a tool family's management entirely.

## Conclusion

The inventory supports the task-report conclusion: no surface is missing a
shared-core capability path (chat/task/subagent/tool/HITL/attachment all
reach the same core), but management and control surfaces are unevenly
distributed; three new gaps are filed (X-SRF-01-P2-01, P2-02, P3-01), all
other rows map to canonical IDs.
