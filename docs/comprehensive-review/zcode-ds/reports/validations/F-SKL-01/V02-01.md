## Expected Result

A single chain: discovery -> descriptors registered -> catalog projection + activate/read/run tools registered -> activation marks state -> enforcement at snapshot; EKO loads builtin/workspace/global/plugin skills on live startup/switch paths; disable/uninstall removes plugin skills.

## Result

- Exit code: not-applicable (inspection)
- Summary (verified chain with anchors):
  1. `ReactAgent::discover_skills` -> `discover_skills_inner` (`capabilities.rs:631-805`): loader parse, `SkillLoadPolicy` gate (:640-643), registers each descriptor into **two** registries (:715-718), registers frontmatter hooks (:702-711), replaces `activate_skill`/`read_skill_resource`/`run_skill_script` tools (:783-795), injects catalog via `replace_projection("echo-agent:skill-catalog")` (:741-746), fires `InstructionsLoaded` hook (:748-777).
  2. Dual registry: `tools.skill_registry` (tracking, `tool_exec.rs:34`) and `tools.progressive_skill_registry` (shared `Arc<RwLock<SkillRegistry>>` handed to the three tools, `capabilities.rs:660-677`). Both get identical descriptors; activation state is independent per registry (see finding F-SKL-01-P1-02).
  3. Activation entry points: model tool `ActivateSkillTool` (`activate_tool.rs:96-186`, marks shared registry via `activate_with_args`), hook action `ActivateSkill` -> `capabilities::activate_skill` (`context.rs:463-480`, tracking registry + projection), loop paths `react_loop.rs:674`, `stream_channel.rs:264`. Checkpoint resume marks only the tracking registry (`mod.rs:1703-1704`); snapshot save unions both registries' active names (`snapshot.rs:206-222`).
  4. Enforcement: `AgentRunSnapshot::from_agent` merges both registries' `active_skill_allowed_tools` and visibility (`snapshot.rs:206-254`); `tools_for_llm`/`is_skill_tool_allowed` filter (`snapshot.rs:269-299`).
  5. EKO live paths: builtin skills (`runtime.rs:148-168`), baseline injection (`runtime.rs:170-210`), workspace-curated on switch (`state.rs:994-1000`), global on reset (`state.rs:1143-1150`), agent pool (`agent_pool.rs:925-932`), tool_exposure test path (`tool_exposure.rs:303`), CLI `/skills sync` reload (`cmd_impls/skills.rs:61-71`).
  6. Unload: `unregister_skills_by_source` (`capabilities.rs:915-958`) called by plugin disable (`plugin_runtime.rs:1167`) — removes descriptors from both registries, hooks, projections, re-registers tools. `reconcile_skill_load_policy` (`capabilities.rs:809-877`) removes policy-rejected skills.
  7. Hooks: `HookRegistry` sources sorted deterministically (UserConfig < Plugin < Skill, `hooks.rs:711-722`); invoked from pipeline (`pipeline.rs:238,302`), react_loop (:328,465), hooks_bridge (session events), snapshot compact (:1109).

## Deviations

- `wire_skills` (`plugin.rs:398-410`) loads plugin skill dirs via `load_skills_from_dir` **without** source tagging, while `load_plugin_skills_from_dir` (:265) tags. The EKO plugin path uses `wire_all` (`plugin_runtime.rs:818-854`) which goes through the tagged path, so the untagged `wire_skills` variant is currently reachable only by direct framework consumers — recorded, not a finding (public API option).
- `activate_skill` tool takes any skill name; unknown names return a clean tool error (no crash).

## Conclusion

Supports: every component is registered and reachable on live paths; the two-registry arrangement and the resume asymmetry are verified chains (basis for F-SKL-01-P1-02); reload paths exist but re-discovery is a no-op for existing names (basis for F-SKL-01-P2-01). Does not prove: runtime behavior of the edge cases (V03-01/V03-02, V04 probes).
