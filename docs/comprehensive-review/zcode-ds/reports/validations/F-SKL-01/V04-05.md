## Claim

Activating a skill whose `depends_on` graph contains a cycle (including a two-skill mutual cycle) is handled gracefully: the loader's discovery-time cycle detection (`validate_and_sort_dependencies` / `detect_cycle`) is supposed to warn, and activation is documented to "handle" cycles ("they are handled at activation time", `loader.rs:489-491`).

## Method

Standalone probe linking the real `echo_execution` crate (no source modification in the repos):

```text
cd /tmp/fskl-probe && cargo build
./target/debug/fskl_probe a-cycle   # registers skills a<->b (mutual depends_on), calls SkillRegistry::activate("a")
```

Probe code registers two descriptors `a` (depends `b`) and `b` (depends `a`) with valid SKILL.md files, then calls `registry.activate("a")` on a `#[tokio::main]` runtime. Observed with a 25 s wall-clock watch: crash vs hang.

## Expected Result

Per the in-code documentation: a warning plus graceful error or no-op; the process must not crash or hang.

## Result

- Exit code: 134 (SIGABRT)
- Duration: crashed within seconds
- Summary:
  - `thread 'main' (…) has overflowed its stack`
  - `fatal runtime error: stack overflow, aborting`
- Root chain: `activate("a")` -> `activate_with_args` -> `activate_dependencies` (no in-progress guard; only the *completed* `activated` set is consulted, and the skill marks itself activated only *after* deps succeed, `registry.rs:441-444`) -> `activate("b")` -> `activate("a")` -> ... unbounded recursion until stack overflow. The loader's `detect_cycle` logs a warning but does not break the cycle edge (`loader.rs:527-551`), and `validate_and_sort_dependencies` is named "sort" but sorts nothing.
- Log: `/tmp/fskl-cycle-out.txt`

## Deviations

The documented "handled at activation time" contract is violated with a deterministic process abort.

## Conclusion

This execution **fails** the invariant and is the empirical basis for finding **F-SKL-01-P1-01** (circular or self-referential `depends_on` -> unbounded recursion -> stack overflow -> agent process abort; unrecoverable). Reachability: any EKO agent that loads builtin/workspace/global/plugin skills (runtime.rs:148-168, state.rs:994/1143) and has the model (or a hook `ActivateSkill` action) call `activate_skill` on such a skill.
