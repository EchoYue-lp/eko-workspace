## Claim

Concurrent fan-out state merge is consistent across all execution paths and
lossless with respect to the documented `SharedState` contract ("KV store
shared between nodes + structured message history", `mod.rs:12` and
`state.rs:9-12`).

## Method

Compare the four parallel-fan-out implementations in
`echo-orchestration/src/workflow/graph.rs` — `run` (`:686-706`),
`run_until_interrupt` (`:867-887`), `run_stream` (`:1320-1349`),
`resume` (`:1064-1081`) — against `SharedState::{fork, deep_merge, merge,
merge_overwrite}` (`state.rs:284-293, 324-408`) and the message-history
writer `node.rs:196` (`state.push_message`). Grep `push_message` readers
(`state.rs:240-245` `messages()`; in-engine consumers: none).

## Expected Result

All four paths use the same fork+deep_merge semantics; `deep_merge`
preserves every part of the state contract (values **and** messages).

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  1. `run`/`run_until_interrupt`/`run_stream` fork the state per branch
     (`state.fork()?`) and merge back with `state.deep_merge(&branch_state)`;
     `resume`'s parallel branch (`:1064-1081`) writes **directly to the
     shared state** with no fork and no merge — different semantics
     (no isolation, wholesale last-writer-wins on same keys, no recursive
     object merge) → F-WFL-01-P2-01.
  2. `deep_merge`/`merge`/`merge_overwrite` merge **only `values`**;
     `messages` are never merged (`state.rs:381-408, 324-355, 358-373`).
     `NodeAction::Agent` appends assistant messages to state
     (`node.rs:196`), so every message produced inside a parallel branch is
     silently dropped when the branch state is deep-merged back
     (`graph.rs:701, 882, 1344`). The `then` node and the final
     `GraphResult.state` (serialized by EKO `panels.rs:779-781` into the
     workflow response) never see branch message history →
     F-WFL-01-P2-02. In-engine nothing reads `messages()`; impact is
     limited to the returned/serialized state contract.
  3. Minor: `deep_merge` also does not merge `current_node`
     (`state.rs:134-137`) — cosmetic.

## Deviations

Both divergences above; `merge()` (`state.rs:324-336`) additionally
acquires and immediately drops two locks before re-locking (dead code,
F-WFL-01-P3-07).

## Conclusion

Supports: a genuine concurrent-state-merge inconsistency between resume
and the other three paths, and a message-history loss hole in the merge
contract. Does not prove: runtime manifestation (would need a fixture that
does not exist today — no test covers resume+parallel or message merge).
