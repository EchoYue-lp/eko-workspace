## Claim

`GraphBuilder::build` validates all structural references of the compiled
graph (nodes, edges, entry, finish, edge multiplicity), so misconfiguration
is rejected at build time rather than surfacing at runtime.

## Method

Read `echo-orchestration/src/workflow/graph.rs` `GraphBuilder::build`
(`:431-518`) and the runtime error sites `:650-655` (unknown node) and
`:1376-1385` (`resolve_next` "has no outgoing edges and is not a finish
node"). Cross-check each validator against the builder inputs
(`set_entry`/`add_edge`/`add_conditional_edge`/`add_parallel_edge`/
`set_finish` at `:334-395`) and the unit tests `:1658-1708`.

## Expected Result

Every structural reference (entry, edge from/to, parallel targets/then,
finish nodes, multiple outgoing edges) is checked at build; runtime errors
are unreachable for validated graphs.

## Result

- Exit code: not-applicable (static inspection)
- Summary: build validates entry existence (:438), edge from-node
  existence (:449), fixed/parallel target existence (:457-483), and
  rejects multiple ordinary outgoing edges per node (:493-505). **Missing
  validations**: (1) `finish_nodes` are never checked against the node map
  (they are only stored at `:512`); a typo'd finish name is silently
  ignored and surfaces only at runtime as "Node 'x' has no outgoing edges
  and is not a finish node" when the path is reached (:1380-1385); (2)
  conditional-edge targets are not validated at build — a condition
  returning an unknown node errors at runtime (:650-655), which is
  accepted design (LangGraph-style) but unvalidated; (3) `max_steps` is
  hardcoded to 100 at build (:513) and mutable only post-build.

## Deviations

Finish-node validation gap found (F-WFL-01-P3-04).

## Conclusion

Supports: the graph build gate is mostly complete; the finish-node gap is
