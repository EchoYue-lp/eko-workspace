## Claim

Checkpoint/resume preserves the exact execution that an uninterrupted run
would have performed: routing decisions (parallel fan-out, before-node
interrupts) are replayed faithfully after a resume, and approval outcomes
are distinguishable terminals.

## Method

Trace `run_until_interrupt` (`echo-orchestration/src/workflow/graph.rs:
738-906`) and `resume` (`:913-1092`) by hand:

1. AfterNode path: `should_interrupt_after(current)` → `resolve_next`
   → checkpoint with `current_node` = resolved next name — for a
   `NextStep::Parallel` the checkpoint stores only `then`
   (`:826-849`); for `Single(name)` it stores `name`.
2. Resume loop: `current` starts at `checkpoint.current_node`; the
   loop-top checks are cancel → max_steps → termination → execute
   (`:962-1010`); the BeforeNode check only exists in the
   `NextStep::Single` branch for the node **after** the executed one
   (`:1044-1061`).
3. Rejection path: `ApprovalDecision::Rejected/Deferred` returns
   `RunUntilInterruptResult::Completed(GraphResult{..})` (`:919-946`).
4. Existing fixtures: `test_resume_with_state_reuses_checkpoint_identity`
   (`:1883-1933`, BeforeNode + linear only);
   `test_checkpoint_*`/`test_file_store`
   (`checkpoint_store.rs:469-587`). Grep tests for `interrupt_after`:
   none combine interrupt_after with parallel edges or with a next node
   that itself has interrupt_before.

## Expected Result

Resuming from any checkpoint yields the same node sequence and state as a
fresh run; aborted runs are distinguishable from completed ones.

## Result

- Exit code: not-applicable (static trace of code + existing tests)
- Summary:
  1. **AfterNode checkpoint on a fan-out node loses the fan-out.**
     `interrupt_after(A)` with `A → parallel [b1,b2] → then` stores
     `current_node = then`; `resume` jumps straight to `then` and **b1/b2
     are never executed** (`:834-838` + `:981-1091`). The workflow
     completes with a different execution than an uninterrupted run —
     F-WFL-01-P1-01.
  2. **BeforeNode interrupt of the next node is skipped after an
     AfterNode resume.** `interrupt_after(A)` with next `B` storing
     `current_node = B`; `resume` executes B without the
     `should_interrupt_before(B)` check (that check only guards the node
     after B), silently bypassing a configured approval point — same root
     cause as 1, folded into F-WFL-01-P1-01.
  3. **Rejected/Deferred resume reports `Completed`.** The caller cannot
     distinguish "workflow aborted by rejection/deferral" from "workflow
     finished" (`:919-946`); no error, no abort variant, no flag on
     `GraphResult` — F-WFL-01-P2-03.
  4. No existing fixture covers interrupt_after + parallel, interrupt_after
     + next-before-interrupt, or the rejection path — the P1/P2-03
     behaviors are untested.

## Deviations

All three deviations above.

## Conclusion

Supports: the checkpoint/resume machinery has a recovery-correctness bug
(parallel stage skipped after an after-interrupt; next before-interrupt
bypassed) and an approval-terminus ambiguity. Confidence in the trace is
high; no runtime fixture exists to confirm empirically (read-only review
cannot add one — candidate for Q-FLT/Q-E2E phase).
