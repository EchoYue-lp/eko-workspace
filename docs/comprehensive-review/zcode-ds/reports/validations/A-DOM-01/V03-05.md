## Expected Result

Either the wrappers disclose the persistence side effect in their description, or the side effect is confined to explicit user-visible actions; the persistence root must equal the EKO workspace root used by the GUI.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary:
  - `AutoIngestResearchTool::description()` returns the inner framework description verbatim (`research_connectors.rs:298-300`); none of the four wrapped tools mention any persistence behavior. The model and the user see a read-only search tool.
  - On success the wrapper persists every parseable record into `research/sources/*.json` under `context.working_dir` (`:314-318`) and returns the original result unchanged; ingest failures are only `tracing::warn`ed (`:330-333`), so even persistence failure is invisible to the caller.
  - The persistence root is the agent working directory, not the workspace root from `state.app_state.workspace.current` used by the GUI/CLI commands (`src/tauri/commands/analysis.rs:17-25`, `research.rs:23-31`). For the primary agent these usually coincide; any divergence (launch cwd, future task-scoped working dirs) silently writes research records to a location the GUI cannot see — a second, divergent research-root authority.
  - The explicit `research_library` tool (description "Read and update EKO's file-backed research library", `research_tool.rs:31-33`) is honest about writing; the wrappers are not.

## Deviations

None. The behavior matches the module doc ("automatic search-result ingestion", `research_connectors.rs:1`) — the defect is the undisclosed LLM contract and the root ambiguity, not accidental wiring.

## Conclusion

Supports A-DOM-01-P2-01: hidden write side effect on four read-oriented search tools, undisclosed in descriptions and silently failed; persistence rooted at the agent working dir with a possible divergence from the app workspace root. The mechanism is fully reachable on the primary agent (V02-01).
