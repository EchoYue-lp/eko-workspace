## Claim

There is exactly one structural validator and one dependency analysis
(cycle detection / missing-node check / topological order / ready frontier)
for the dynamic task DAG across `echo-agent` and `echo-agent-cli`; no second
DFS, Kahn implementation, or ready-frontier computation is reachable in
production code of either repository.

## Method

Repository-wide grep over both trees, then definition-level inspection of
every match:

```text
# echo-agent
grep -rn "VisitState|visit_task|detect_cycle|topolog|indegree|ready_task|get_ready|frontier" echo-agent/echo-orchestration/src echo-agent/src --include="*.rs"
grep -rn "PlanValidator|validate_task_snapshot|validate_task_specs" echo-agent echo-agent-cli --include="*.rs"
grep -rn "cycle|topolog|dfs" echo-agent/echo-orchestration/src/tasks/{executor,events,hooks,background_task,composite}.rs
grep -rn "Skipped|execution_mode|parallel_group" echo-agent/echo-orchestration/src/tasks echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime --include="*.rs"

# echo-agent-cli task_runtime
grep -rn "cycle|topolog|indegree|VisitState|dfs|validate_task|ready_task|frontier|PlanValidator|dependency" echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime --include="*.rs"
```

## Expected Result

One authority per concern: `PlanValidator` (structural), `task_dependency_cycles`
+ `task_topology` (DFS/topo, sole), `DagExecutionState::ready_task_ids`
(ready frontier, sole production path). Any other match is either
test-only, a legacy surface with zero production callers, a distinct concept
(workflow engine, checkpoint nodes, agent topology), or a documented adapter
filter.

## Result

- Exit code: 0 (grep/diff-based inspection, no build)
- Duration: not-applicable
- Summary:
  - Sole DFS: `CycleVisitState` exists only in
    `echo-orchestration/src/planning/validator.rs:348-407`
    (`task_dependency_cycles` / `visit_task_cycles`); sorted-id iteration makes
    it deterministic. `task_topology` (validator.rs:297-346) uses a
    `BinaryHeap<Reverse<String>>` Kahn queue — the only topological-order
    implementation for task specs.
  - Sole structural validator: `PlanValidator` (validator.rs:184-294) is the
    only validator of task specs/snapshots. Callers: framework
    `TaskRevisionService::finalize_and_validate` (revisioned.rs:1007-1011),
    framework `RuntimeDagExecutor` safe point (runtime_executor.rs:214-219),
    EKO test-only helpers (echo-agent-cli store.rs:98-100, 921-923), and EKO
    `EkoTaskToolPolicy::validate_candidate` which delegates to
    `TaskCapabilityCatalog::validate_task_spec` — a capability/policy check
    (Subagent roles, allowed tools, task-control-tool ban,
    task_tools.rs:49-81), not a structural validator.
  - Sole production ready frontier: `DagExecutionState::ready_task_ids`
    (runtime.rs:438-458), consumed only by `RuntimeDagExecutor`
    (runtime_executor.rs:275, 318). EKO `select_ready_wave`
    (executor.rs:1265-1282) filters the framework-computed frontier via

    readiness.
  - Second-ready-loop candidates are legacy-only: `TaskManager::get_ready_tasks`
    / `wake_dependents` (manager.rs:241-256, 334-356) and
    `TaskExecutor::execute_ready_tasks` (executor.rs:570) have production

    surface, zero production construction).
  - Distinct concepts, not duplicates: `workflow/dag.rs` (own Kahn
    `topological_sort` + DFS `detect_cycle` for static workflow graphs —
    F-WFL-01 scope, never touches the task model); `src/topology.rs` (agent

    analysis).
  - EKO side: no cycle/DFS/indegree implementation anywhere in
    `echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime`; planner.rs:8-9

    `echo_orchestration::planning::PlanValidator`.

## Deviations

`get_dependency_chain_recursive` (manager.rs:384-403) remains a legacy chain
query reachable only through the production-unreachable `TaskManager`
(F-TSK-01-P3-01); it performs graph walking but no cycle/validation authority.
The EKO retry-unblock walk (store.rs:1287-1335) is a product recovery policy
traversal, not a validator or frontier (see F-TSK-02-P2-01). These are
classified, not counted as duplicate authorities.

## Conclusion

Supports: one structural validator and one dependency analysis (DFS + Kahn
topology) and one production ready frontier for the dynamic task model in both
repositories. Does not prove: absence of external framework consumers of the
legacy surface, nor correctness of the semantics inside the single analysis
(see V03-01 and findings P1-01/P2-02).
