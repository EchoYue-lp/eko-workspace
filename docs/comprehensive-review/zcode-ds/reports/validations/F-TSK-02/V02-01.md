## Claim

Every structural-validation and readiness decision on the live dynamic-task
path is registered and reachable through exactly one authority chain:
`task_create/task_update/task_list/task_execute` -> framework service -> one
`PlanValidator`; runtime execution reads one frontier
(`DagExecutionState::ready_task_ids`) and validates the snapshot at every safe
point.

## Expected Result

All entry points converge on the same validator and frontier; no parallel
registered validator/executor exists in either product.

## Result

- Exit code: 0 (static tracing)
- Duration: not-applicable
- Summary:
  - One registered tool family and one service (`TaskRevisionService`) in both
    framework and EKO (F-TSK-01 V02/V04 already verified registration; this
    trace confirms the validation hop inside it).
  - `RuntimeDagExecutor` re-validates every loaded snapshot at every safe
    point, so status-independent structural integrity is enforced on the
    runtime path even if a snapshot bypassed the commit validator.
  - EKO's outer drain loop (executor.rs:360-445) re-invokes the framework
    executor after a Completed outcome to catch appended tasks; it computes
    `unresolved_count` and completion blockers (product policy), never a ready
    frontier.
  - `select_ownership_safe_wave` (executor.rs:1127-1145) only filters the
    framework frontier; `validate_selected_wave` (runtime_executor.rs:467-492)
    rejects empty, non-ready, or duplicate selections.
  - EKO skip paths reach the framework patch engine (Skip op) and the runtime
    snapshot (Skipped status maps 1:1, types.rs:419), confirming the
    skip-with-dependents stall scenario is end-to-end reachable (P1-01).
