## Claim

The provider contract that F-RCT-04-P1-01 depends on is externally verified:
at least the Anthropic Messages API (and Gemini-style providers) require tool
result blocks to appear in the same order as the corresponding tool-use
blocks, and reject out-of-order results with HTTP 400.

```text
   the tool use parts"), qwen-code PR #8165 ("strict providers reject
   out-of-order shapes", validated against Kimi/GLM), Anthropic SDK example
   fix ("Each tool_result block must have a corresponding tool_use block in

   unpaired/reordered tool sequences).
```

## Expected Result

The ordering constraint is corroborated by at least two independent sources
describing the same API behavior.

## Result

- Exit code: not-applicable (external lookup)
- Duration: < 2 min
- Summary: confirmed. Sources:
  - RooCodeInc/Roo-Code issue #11804 — out-of-order tool_result blocks cause
    HTTP 400 on the Anthropic Messages API; ordering must match tool_use.
  - modelcontextprotocol.io SEP-1577 — Gemini (and other strict providers)
    require results in the exact order of the tool-use parts.
  - QwenLM/qwen-code PR #8165 — reorders tool_result before other content;
    live A/B tests against Kimi/GLM confirm strict providers reject
    out-of-order shapes.
  - anthropic-sdk-python PR #1052 — the API rejects a tool_result with no
    preceding tool_use and requires the result to follow the tool_use block.
  - LiteLLM #22946 — Anthropic-native pass-through rejects assistant
    `tool_use` without immediately following `tool_result`.
  - towardsai.net and zenvanriel.com articles restating the same rule
    ("tool_result blocks appear in the same order as their corresponding
    tool_use blocks").
  OpenAI's API matches results by `tool_call_id` and is order-insensitive;
  the ordering failure is provider-specific (Anthropic family, Gemini family).

## Conclusion

Supports: the framework's completion-order result insertion (verified in
V03-01) violates the documented provider contract on Anthropic/Gemini-family
endpoints whenever completion order differs from call order — the factual
basis of F-RCT-04-P1-01. Does not prove: that the failure manifests in this
project's live EKO deployment (depends on provider choice and tool timing).
