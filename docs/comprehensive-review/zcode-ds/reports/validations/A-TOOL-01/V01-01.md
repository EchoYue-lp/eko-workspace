## Claim

EKO has exactly one tool-registry/execution authority (the framework `ToolManager`
plus the framework `ToolExecutionPipeline`); there is no second EKO-side tool
executor, and the tool-exposure/terminal/sandbox concepts have exactly one
definition per concept across both repositories.

## Method

Repository-wide grep over `echo-agent-cli` and `echo-agent`:

```text
1. consumers of tool_exposure: grep -rn "initial_visible_tools|disabled_tools_for_mode|rollout_for_mode|record_mode_schema_budget" echo-agent-cli --include="*.rs"
2. registration: grep -rn "register_all_tools|register_readonly_tools" echo-agent-cli
3. ToolManager construction/execution in CLI: grep -rn "ToolManager::new|tool_manager" echo-agent-cli/{echo-agent-app-core/src,src}
4. second executor search: execute_tool* call sites in echo-agent-cli (analysis.rs, panels.rs, tasks)
5. terminal: single definition search "TerminalManager|PtySession|create_terminal" in echo-agent-cli
6. sandbox: "has_local_os_sandbox|SandboxManager|bare" in echo-agent and echo-agent-cli
7. permission gates: "permission_mode|require_full_auto|full_auto|IpcAuth" in echo-agent-cli
```

## Expected Result

- One definition each for `tool_exposure`, `terminal.rs`, `ToolExecutionRepository`.
- EKO executes tools only through the agent's framework `ToolManager` (via
  `execute_stream_*`/`execute_tool_with_context`); no parallel executor.
- `require_full_auto`/`IpcAuth` has zero live call sites (gates removed per
  AGENTS.md historical lesson).

## Result

- Exit code: not-applicable (inspection)
- Duration: about 15 minutes
- Summary:
  - `initial_visible_tools`/`disabled_tools_for_mode`: one definition
    (`tool_exposure.rs`), four consumer sites: `chat_driver.rs:465-470`,
    `tasks/task_runtime/executor.rs:3084-3109`, `executor.rs:3686-3703`.
  - `register_all_tools` is only referenced by a comment
    (`infra.rs:901`); tools are registered by the framework
    `ReactAgentBuilder::enable_tools()`/`readonly_tools()`.
  - `ToolManager::new()` in production code: only `analysis.rs:382-420`
    (reuses the agent's manager via `agent.tool_manager().clone()` and calls
    `execute_tool_with_context("run_code", ...)` — a caller, not a second
    executor); `analysis.rs:1084/1149/1161` are test-only.
  - `terminal.rs` (PtySession/TerminalManager + 6 Tauri commands) is the only
    terminal implementation; commands registered in `src/tauri/mod.rs:303-308`.
  - Sandbox: framework `SandboxManager` (echo-execution/src/sandbox); EKO
    probes `has_local_os_sandbox` (`infra.rs:269`) and removes `run_code`
    (`configure_run_code_capability`, `infra.rs:533-543`); framework `run_code`
    has a hard `IsolationLevel::OsSandbox` floor (`echo-tools/src/code.rs:313,
    324`) and `SandboxManager::local_sandbox()` sets `allow_fallback: false`
    (echo-execution/src/sandbox/manager.rs:250). Bare-execution text exists
    only in framework skill `run_script_tool`/`prompt_exec` (outside EKO tool
    exposure scope).
  - `IpcAuth`/`IpcPermission`/`require_full_auto`/`require_not_strict`:
    definition only in `src/tauri/error.rs`; zero call sites in `src/` and
    `echo-agent-app-core/src/` (grep exit 1).

## Conclusion

Supports: single tool-exposure authority, single tool-execution authority
(framework ToolManager; analysis.rs reuses it), single terminal implementation,
fail-closed sandbox contract, and the absence of any live `require_full_auto`
gate. Does not prove that the exposed tool surfaces per role/mode are correct —
that is V02/V03 territory.
