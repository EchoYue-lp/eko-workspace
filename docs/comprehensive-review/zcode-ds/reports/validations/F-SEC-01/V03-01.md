## Claim

The sandbox selection/fallback chain can never silently execute below a command's `minimum_isolation` on the production path: `run_code` (echo-tools/src/code.rs:313) requires `IsolationLevel::OsSandbox` minimum, and degradation (Docker/K8s unavailable, local OS sandbox missing) either fails closed or still meets the floor.

## Method

1. Read the policy floor computation: `echo-execution/src/sandbox/policy.rs:147-199` (`evaluate_with_limits` folds `command.minimum_isolation` via `required.max(policy_level)`; trusted-mode test at :305-310).
2. Read the manager fallback paths: `manager.rs:291-336` (`execute_at_level`: `actual < required && !allow_fallback` → error; else `warn!` + proceed), `manager.rs:344-403` (`select_executor` best-available fallback), `manager.rs:215-242` (`local_only`/`local_sandbox` constructors, `allow_fallback: false`), `manager.rs:175-196` (`auto_detect`, `allow_fallback: true`).
3. Read `run_code` pre-checks: `echo-tools/src/code.rs:313` (`with_minimum_isolation(OsSandbox)`), `:319-323` (no sandbox → fail closed), `:324-330` (declared level < OsSandbox → fail closed), `:340-345` (availability check), `:347-355` (limits: network=false, working_dir writable).
4. Read EKO wiring: `echo-agent-cli/echo-agent-app-core/src/infra.rs:265-271` (`SandboxManager::local_sandbox()`, `run_code_available = has_local_os_sandbox()`).
5. Checked the only production `with_minimum_isolation` callers (grep: `code.rs:313` + tests only).

## Expected Result

On the EKO path (local_sandbox, fallback disabled, pre-checks): run_code either runs at >= OsSandbox or fails closed. On the generic framework path (`auto_detect`, `allow_fallback=true`), a below-minimum execution is structurally possible but cannot occur for the only production minimum (OsSandbox) unless the local backend is Process-only and Docker/K8s are absent.

## Result

- Exit code: not-applicable (static inspection; supported by unit tests `manager.rs:490-496` `command_minimum_isolation_blocks_process_only_manager`, `:508-524` limits-aware policy, `policy.rs:305-310` trusted-mode floor)
- Summary:
  - EKO path: `local_sandbox()` → policy `local_os()` (max OsSandbox) + `allow_fallback=false`. `run_code` command: required = max(policy_level, OsSandbox) = OsSandbox (mac/linux); `select_executor` picks Local (OsSandbox >= OsSandbox) or errors. Pre-checks at `code.rs:324` and `infra.rs:269` additionally fail closed. On Windows: local declares Process → `run_code` gate fails closed (`code.rs:324`); Docker would be required for any code execution. Verified: no silent below-minimum path on the EKO production path.
  - Generic path (`auto_detect`, `allow_fallback=true`): if required = Container (default Strict policy) or OsSandbox and the only available executor is Process-level local (e.g., Windows without Docker), execution proceeds with `warn!` (`manager.rs:313-319`) below `minimum_isolation`. This is the API-level design gap — the manager does not treat `minimum_isolation` as a hard floor independently of `allow_fallback`; it is only folded into the policy `required`. No production caller is affected today (only `code.rs:313` sets a floor, and its caller-side pre-checks + EKO's pinned config close it) — finding F-SEC-01-P3-02.
  - Fallback to Local when Docker is configured-but-unavailable (daemon died after startup probe, `DOCKER_CHECK_CACHE` TTL 30s at `docker.rs:50-129`): local (OsSandbox on mac/linux) still meets the OsSandbox floor; only the policy `required` (Container) is undercut, with `warn!` and `result.sandbox_type` exposing the actual backend.
  - `execute_stream` path (`manager.rs:73-136`) applies the same floor logic (`policy.evaluate` at :78, `actual < required && !allow_fallback` check at :81-87).

## Deviations

The `warn!`-level degradation is by design and visible (log + `sandbox_type` in `ExecutionResult`, `echo-core/src/sandbox.rs:260`), so degradation is not silent in observability terms; only the guarantee is weaker than the field name suggests.

## Conclusion

Supports: "run_code 的最小隔离（IsolationLevel::OsSandbox）" holds on the EKO production path with fail-closed behavior (B-DOC-01's claim about code.rs:313 confirmed and extended to the whole chain). Identifies the framework-API gap (minimum not a hard floor when `allow_fallback=true`) as finding F-SEC-01-P3-02.
