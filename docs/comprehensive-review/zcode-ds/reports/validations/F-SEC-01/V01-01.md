## Claim

Each protection mechanism (guard system, sandbox, secret scan, URL/SSRF validation, shell command classification) defends a threat that is real under EKO's local threat model, and no mechanism over-gates a user-interactive or default feature path; in particular the interactive terminal and the agent `run_code` path are distinguished.

## Method

Static classification with per-mechanism source anchors:

1. Guard system: read `echo-core/src/guard/mod.rs`, `content.rs`, `llm.rs`, `rule.rs`, root `src/guard/{mod,llm,rule}.rs`; checked feature gating and EKO wiring (`grep -rn "GuardManager|ContentGuard|RuleGuard" echo-agent-cli`).
2. Sandbox: read `echo-core/src/sandbox.rs`, `echo-execution/src/sandbox/{mod,policy,manager,local,docker,k8s}.rs`; checked EKO wiring (`echo-agent-cli/echo-agent-app-core/src/infra.rs`).
3. Secret scan: read `echo-agent/src/security.rs`; enumerated call sites (V02).
4. URL validation: read `echo-tools/src/security.rs` SSRF section and `echo-tools/src/web/fetch.rs` execution path.
5. Shell classification: read `echo-tools/src/shell.rs` (ALLOWED / REQUIRE_APPROVAL / DANGEROUS lists, `check_command_safety`).
6. Interactive-vs-agent distinction: `grep -rn "require_full_auto|IpcAuth::" echo-agent-cli/src echo-agent-cli/echo-agent-app-core/src`; read `echo-agent-cli/src/tauri/error.rs` and `src/tauri/terminal.rs:281-295`.

## Expected Result

- Guards are opt-in framework capability, not a default EKO gate.
- Sandbox is applied to the agent `run_code`/`shell` path and fails closed; the user-interactive terminal carries no permission gate (AGENTS.md historical lesson).
- Shell classification gates only the agent tool path, not user-interactive execution.
- URL/SSRF validation is a generic framework default; its local-model justification and any over-gating are recorded.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Guards: `echo_core` default features = `[]`; guard module behind `#[cfg(feature = "guard")]` (`echo-core/src/guard/mod.rs:3-8`); root re-exports behind `content-guard` (`src/guard/mod.rs:35-45`); zero GuardManager/ContentGuard/RuleGuard wiring in `echo-agent-cli` (grep: no hits). Guards are opt-in, no default over-gating.
  - Sandbox: EKO builds `SandboxManager::local_sandbox()` (`echo-agent-cli/echo-agent-app-core/src/infra.rs:265`), `allow_fallback: false` (`echo-execution/src/sandbox/manager.rs:229-242`); `run_code` requires a configured executor with `isolation_level() >= OsSandbox` and fails closed otherwise (`echo-tools/src/code.rs:319-330`, `:340-345`); OS-sandbox availability disables run_code (`infra.rs:269-271`).
  - Terminal: `create_terminal` has no permission gate; comment documents the local-model rationale (`echo-agent-cli/src/tauri/terminal.rs:281-295`). `grep require_full_auto` → definition only at `src/tauri/error.rs:45`, zero callers.
  - Shell: strict-mode default whitelist + metacharacter rejection applies to the agent tool path only (`echo-tools/src/shell.rs:34-72`, `:207-280`); `RequiresApproval`/`Dangerous` verdicts return tool failures, they never gate user terminal.
  - URL validation: `web_fetch` uses `ssrf_safe_get` unconditionally (`echo-tools/src/web/fetch.rs:199-201`); `validate_url_with_addrs` rejects all loopback/RFC1918/link-local/CGNAT/TEST-NET addresses with no opt-out (`echo-tools/src/security.rs:529-570`, `:615-663`).
  - Threat mapping: guards → content safety/prompt-injection (opt-in, user-extensible); sandbox → framework-bug containment + code-execution isolation (local-model justified: run_code is the agent auto path); secret scan → "不把密钥打进日志/事件" (explicitly required by AGENTS.md); SSRF → agent accidental internal-service fetch (generic default; see over-gating note below); shell classification → agent-auto approval separation (B-REF-01 V05: sandbox/approval separation convergent).

Recorded as finding F-SEC-01-P3-03.

Does not prove: the SSRF default is wrong for EKO (judgment call, finding P3-03).
