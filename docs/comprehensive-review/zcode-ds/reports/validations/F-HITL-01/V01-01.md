## Claim

Approval/permission concepts have exactly one live decision authority and no
unacknowledged parallel implementation in either repository; the legacy
`HumanGate` concept is gone from code (AGENTS.md cleanup promise), and any
duplicate decision/probe implementations are identified and classified as
live or dead.

## Method

Repository-wide grep over `echo-agent` and `echo-agent-cli` (excluding
`target/`, `node_modules/`), for the following term families:

```text
HumanGate | human_gate
PermissionPolicy | DefaultPermissionPolicy | permission_policy
tool_needs_approval | check_tool_approval | request_human_approval
handle_ask_decision | would_request_human_for_permissions
take_modified_args | flush_pending_permission_rules | pending_permission_rules
timeout_strategy | enable_classifier | PermissionServiceBuilder
PermissionMode::Bubble | PermissionMode::Auto | PermissionMode::DontAsk
approval | Approval (file inventory, both repos incl. web-frontend)
```

Each hit was classified as definition, registration, live caller, dead
caller, test, or documentation.

## Expected Result

Either zero parallel approval implementations, or explicit evidence that
parallel implementations exist and which are live versus dead. `HumanGate`
expected to be absent from production code.

## Conclusion

Supports: (a) the AGENTS.md HumanGate cleanup promise is fulfilled in code
(only an example doc-comment retains the legacy name); (b) there is one live
decision authority (`PermissionService` + the echo-core permission types),
but several parallel/divergent implementations exist and are dead or
half-dead: `run/approval.rs` (whole ReactAgent approval file), the
`PermissionPolicy` menu API, `PermissionServiceBuilder`, two scope-converting
handler bridges (`DynProviderHandler` service.rs:855-908 vs
`DefaultPermissionRequestHandler` permission.rs:643-689), and two
`tool_needs_approval` implementations that intentionally diverge on rule
flushing (documented at snapshot.rs:1145-1150).

Does not prove: runtime behavior of the live path (see V02, V03).
