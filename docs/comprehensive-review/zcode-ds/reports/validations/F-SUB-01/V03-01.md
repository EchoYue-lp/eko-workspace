## Claim

Prompt envelope/cardinality, history inheritance, and tool/permission
selection obey their documented invariants: (a) one result contract with
exactly one parsed section; (b) `SubagentDefinition.inherit_history`
semantics (`None` = no inheritance, `Some(0)` = all, `Some(n)` = last n);
(c) a declared tool restriction actually restricts; (d) UTF-8 safety of all
text slicing.

## Expected Result

- `Some(0)`/`None` limit semantics as documented per field doc
  (`types.rs:149-151`: `None` = don't inherit, `Some(0)` = inherit all,
  `Some(n)` = last n).
- A `tool_filter` on the definition restricts the dispatched agent's tools.
- No panic on multi-byte text in any parse/split/bound path.

## Result

- Exit code: not applicable (static inspection; complemented by V04 tests)
- Duration: ~20 min
- Summary:
  - Cardinality: system prompt is one string envelope built by
    `compile_system` (EKO app composes named sections incl.
    `render_result_contract()` at the end, `subagent_prompt.rs:177-235`);
    invocation is one task text; parse takes the first `## Result` section
    and the first ```` ```json ```` fence. Consistent.
  - `inherit_history` doc violation (F-SUB-01-P2-02): on the LLM
    `agent_tool` fork path the parent context is pre-sliced to the last 2
    raw messages by `fork_default` (`context.rs:74-81` +
    `agent_dispatch.rs:269-274`); the definition's `inherit_history` is
    then applied only as the *limit* (`executor.rs:1123-1144`,
    `prompt.rs:182-186`). Consequently `None` (doc: "don't inherit")
    inherits up to 2 messages, `Some(10)` is capped at 2, `Some(0)` and
    `Some(1)` behave as documented. EKO always registers
    `inherit_history=Some(2)` (`infra.rs:689` fork_mode,
    `plugin_components.rs:498`), so EKO is unaffected; framework
    consumers get silent scope/history leakage.
  - Tool/permission selection (F-SUB-01-P1-01): `tool_filter`
    (`types.rs:144`) has no consumer; `SubagentContext.allowed_tools` is
    honored only in `dispatch_fork` (`executor.rs:1672-1676, 1744-1745`)
    and only reachable via programmatic delegation helpers
    (`react/mod.rs:2370-2377, 2517-2518`); the LLM-facing `agent_tool`
    exposes no tool-restriction parameter and its parent-context factory
    never populates `allowed_tools`. So a definition-level tool
    restriction cannot be expressed on the primary dispatch surface.
  - `SubagentContext.allowed_tools` doc ("overrides inheritance",
    `context.rs:184`) holds only for Fork; Sync/Teammate/Team invocations
    ignore it (currently unreachable since all production callers use
    Fork).
  - UTF-8 safety: `bounded_text`/`split_subagent_output`/`normalize_outcome`
    use `chars().take()` and `get()`-based slicing only; no byte-slice
    panic path found (tests in V04 confirm incl. 600-char Chinese payloads).
  - Result terminal ownership: model-provided status ignored
    (`types.rs:401-417, 464-465` filter on contract_version), caller
    status wins; reported verification demoted to `Reported`
    (`types.rs:481-485`); runtime-observed evidence replaces same-check
    reported entries (`executor.rs:229-254`).
  - Cancelled path: pre-cancelled dispatch returns without any
    `SubagentEvent`/hooks (`executor.rs:417-423`) — event-contract gap
    (F-SUB-01-P3-02); cancelled run output/remaining_work set at
    `executor.rs:1410-1412, 1443-1445`.

## Deviations

`filter_history` drops any message whose text starts with
`[runtime_context:`; the `[workspace]`/`[constraints]` blocks appended by
the executor/compiler use different bracket tags and are not dropped —
consistent, no deviation found.

## Conclusion

Supports: prompt envelope/cardinality invariant holds; UTF-8 safety holds;
result terminal-ownership invariant holds; two documented invariants are
violated — definition-level tool restriction is unimplemented
(F-SUB-01-P1-01) and `inherit_history` `None`/`>2` semantics are capped
and leaky on the LLM fork path (F-SUB-01-P2-02). Does not prove dynamic
end-to-end behavior beyond the executed tests in V04.
