## Claim

Every registered subagent definition is reachable from dispatch, the
model-facing dispatch catalog routes exactly to registry entries, and the
definition fields the executor relies on are consumed at runtime.

## Method

Static call-graph trace with source anchors:

1. Registration paths: `capabilities.rs:305-325`
   (`register_subagent_with_definition` → `registry.register_sync` +
   `update_dispatch_catalog`), `:360-401` (factory → catalog),
   `:342-356` (definition-only → catalog), `:406-424`
   (`unregister_subagent` → catalog retain), `:434-438`
   (`sync_subagent_dispatch_catalog` reconciliation).
2. EKO composition: `echo-agent-cli/.../infra.rs:687-746` (builder wiring),
   `:846-872` (registration on primary agent + catalog sync),
   `echo-agent-cli/.../plugin_components.rs:470-510` (plugin registration).
3. Dispatch routing: `executor.rs:407-781` (`dispatch` → mode match),
   `:1469-1551` (`dispatch_sync`), `:1554-1888` (`dispatch_fork`),
   `:871-980` (`dispatch_teammate`), `:992-1113` (`dispatch_team`),
   `agent_dispatch.rs:180-355` (tool → `dispatch`/`dispatch_background`).
4. Catalog schema projection: `agent_dispatch.rs:388-416` (`parameters()`
   reads `catalog` RwLock; enum when non-empty) and `execute` → registry
   lookup via `executor.registry().get(agent_name)` (`:246-252`).
5. Definition field consumption audit: which `SubagentDefinition` fields
   appear in the executor/dispatch-tool production code.

## Expected Result

- `agent_tool.parameters()` enum = registered definition names; executing an
  unregistered name fails cleanly at the executor with "Subagent 'x' not
  found" (no panic).
- Mode forcing for isolation roles works (worktree/workspace roles dispatch
  as Fork).
- Fields consumed: `execution_mode`, `inherit_history`, `timeout_secs`,
  `isolate_worktree`, `isolate_workspace`, `team`, `is_background`, `name`,
  `description`, `tags`; fields `tool_filter`, `model`, `system_prompt`,
  `max_iterations`, `token_limit`, `inherit_memory`, `can_delegate`,
  `lightweight` have no runtime consumer.

## Result

- Exit code: not applicable (static inspection)
- Duration: ~30 min
- Summary:
  - Registration → catalog: every agent-level registration path updates the
    catalog (name + description, sorted, deduped by name); direct shared-
    registry registration does not touch agent-local catalogs, but the
    documented reconciliation API (`sync_subagent_dispatch_catalog`) exists
    and EKO calls it (`infra.rs:813, 864-872`). Catalog is a projection;
    the registry is the authority.
  - Route validation: `execute` never validates `agent_name` against the
    schema enum; validation happens at dispatch via
    `registry.get()` → `ReactError::Other("Subagent 'x' not found")`
    (`executor.rs:445-447`), surfaced by the tool as a `ToolResult::error`.
    Definition-only entries (no instance, no factory) fail at execution in
    `isolated_dispatch_agent` (`executor.rs:1455-1466`) — documented,
    intentional.
  - Mode forcing: `agent_dispatch.rs:244-252` — a role declaring
    `isolate_worktree`/`isolate_workspace` is forced to Fork; background
    flag propagated (`:253`).
  - Reachability of consumed fields confirmed at anchors above (e.g.
    `timeout_secs` at `executor.rs:1475-1478, 1569-1573, 891-895`;
    `inherit_history` passed into `compile_invocation` at
    `:1481-1485, 1580-1584`; isolation at `:1603-1636, 1706-1735`;
    `team` at `:1001-1069`; `is_background` at `agent_dispatch.rs:251`).
  - Dead fields (see V01) have no production reader on any dispatch path;
    the tool-restriction fields reachable in production are
    `SubagentContext.allowed_tools` (set only by the programmatic
    delegation helpers `react/mod.rs:2370-2377, 2517-2518`, consumed only
    in `dispatch_fork` via `invocation_disabled_tools`,
    `executor.rs:1672-1676, 1744-1745`) and EKO's build-time
    readonly/writer split (`infra.rs:639-677`).

## Deviations

`dispatch_fork`'s tool allowlist is honored via `AgentInvocationContext.
disabled_tools`; Sync/Teammate/Team invocations carry no `disabled_tools`,
so an allowlist expressed in `SubagentContext` is silently ignored for those
modes (all production callers of the delegation helpers use Fork, so the gap
is currently unreachable in practice).

## Conclusion

Supports: definition-to-registration-to-dispatch trace is complete for the
fields the executor actually consumes; catalog routing is coherent (schema
projection + registry-authoritative validation); the definition's
tool/permission surface is not wired (basis for F-SUB-01-P1-01 and
F-SUB-01-P2-01). Does not prove event-timing behavior (V03/V04 touch parts
of it).
