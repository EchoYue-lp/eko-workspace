## Claim

Malformed or hostile input from the language server (framing, JSON,
oversized lengths) is handled without panic, without unbounded allocation,
and without wedging the reader task.

## Method

Static trace of `echo-integration/src/lsp/client.rs:125-199` (read_loop),
`jsonrpc.rs` (framing helpers + tests), and `echo-core/src/lsp/types.rs`.

## Expected Result

Content-Length is capped or validated before allocation; JSON parse
failures are skipped without losing the pending map; malformed frames do
not hang `read_exact`.

## Result

- `read_loop` (client.rs:125-199): header parse via
  `jsonrpc::parse_content_length` (jsonrpc.rs:90-97 — byte-slice
  `line["content-length:".len()..]` is UTF-8-safe because the
  case-insensitive ASCII prefix check guarantees an ASCII boundary);
  EOF/read errors clear `pending` and return.
- **Unbounded allocation**: `let mut body = vec![0u8; len]` (client.rs:164)
  with `len` taken verbatim from the server's `Content-Length` header — a
  misbehaving server can advertise a multi-GB frame and abort the process
  (allocation failure). No cap, no checked allocation. Finding
  F-INT-02-P2-02.
- Malformed JSON body: `serde_json::from_slice` failure → `continue`
  (client.rs:171-173) — skipped silently, reader survives.
- Frame with wrong length: `read_exact` blocks until the bytes arrive or
  EOF — with no timeout this can wedge the reader indefinitely if the
  server advertises a larger length than it sends (same class as
  F-INT-02-P1-01).
- `LspConfig::from_yaml`/`discover` parse errors are surfaced as `Err`
  (config.rs:74-80) and EKO logs them warn-only (runtime.rs:522-549) —
  malformed user config degrades gracefully.
- `parse_content_length` returns `None` for missing/zero-value lengths;
  read_loop then `continue`s (client.rs:159-161) — no hang, no panic.

## Deviations

Unbounded `vec![0u8; len]` allocation (finding F-INT-02-P2-02);
length/JSON read paths have no timeout (finding F-INT-02-P1-01).

## Conclusion

Supports: parse-failure handling is non-panicking and reader-preserving.
Does not prove: boundedness under adversarial framing (fails — P2-02) or
timely completion under wrong-length frames (fails — P1-01).
