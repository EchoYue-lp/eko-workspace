## Claim

A2A wire names (`tasks/send`, `tasks/sendSubscribe`, camelCase/kebab-case
JSON fields) are confined to the adapter boundary, and the internal model
does not introduce worker terminology or a second task authority.

## Method

1. `grep -rni "worker"` over `src/a2a` — zero hits.
2. Inspect `src/a2a/types.rs` wire constants (METHOD_*, ERROR_CODE_*,
   `#[serde(rename_all = "camelCase"/"kebab-case")]`) and
   `src/a2a/server.rs`/`client.rs` usage.
3. Compare against the framework task model (`echo-orchestration` task
   types) for parallel-authority overlap.

## Expected Result

Wire names at the boundary only; `TaskState`/`A2ATask` are protocol
artifacts (external fixed protocol exception), not framework task
objects; no worker naming.

## Result

- Wire constants (`METHOD_SEND` etc., types.rs:14-35) and serde renames
  are confined to `src/a2a`; the root facade (`src/lib.rs:69-71,306-311`)
  exposes them under the `a2a` module only.
- `TaskState` (types.rs:338-378) is the A2A-spec kebab-case state enum
  with `is_terminal`/`can_transition_to` — a wire-protocol type, not the
  framework `TaskStatus`/task model; the A2A server dispatches directly to
  the `dyn Agent` (`execute`/`execute_stream`) rather than claiming to be
  a task executor. No second task-authority is created (the A2A task
  registry is a protocol cache, not an execution authority).
- `EventIdentity` reuse (server.rs:211-217) ties streaming events into the
  framework envelope contract (run_id/turn_id = task_id) — internal
  conversion is present and lossless.
- No worker terminology anywhere in the module.
- SSRF-adjacent note (not a naming issue): `A2AClient` fetches arbitrary
  caller-supplied URLs; per the AGENTS.md local threat model this is the
  caller's responsibility, recorded here as an observation only.

## Deviations

None.

## Conclusion

Supports: compliant external-protocol isolation; wire names at boundary;
no worker naming; no parallel task authority.
