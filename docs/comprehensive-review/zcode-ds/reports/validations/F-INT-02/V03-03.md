## Claim

LSP requests support retry and cancellation: cancelled request futures
release their bookkeeping, timed-out requests surface `LspError::Timeout`,
and retries are bounded by a configured policy (`max_restarts`).

## Method

Static trace of `send_request`/`send_notification` (client.rs:201-256),
`pending` map lifecycle, `shutdown`, and `grep` of `LspError::Timeout`,
`max_restarts`, `restart_count`, `restart_server` across echo-agent.

## Expected Result

On cancel (future dropped): pending entry removed or provably reclaimed.
On no response: `LspError::Timeout` after a bounded wait. On restart:
bounded by `max_restarts`.

## Result

- `send_request` (client.rs:202-236): inserts the `oneshot::Sender` into
  `pending` at :214-218, then sends to the writer. If the caller's future
  is dropped (cancellation — e.g., React tool timeout at
  react_loop.rs:316 firing), the pending entry is **not removed**; it is
  reclaimed only when the server eventually responds (then `tx.send`
  fails silently, entry removed) or the reader task exits. A hung server +
  repeated cancelled calls → unbounded `pending` growth. Finding
  F-INT-02-P1-01 (part).
- If `writer_tx.send` fails after insertion (:220-223), the entry leaks
  until the reader exits.
- No retry exists anywhere in the LSP client; `LspError::Timeout` is never
  constructed (no timeouts at all in the request path).
- `max_restarts` / `restart_count` / `restart_server` are inert (see
  V02-01) — the documented bounded-restart policy is absent. Finding
  F-INT-02-P2-01.
- `shutdown` ignores all request errors (`let _ =` at client.rs:315-317)
  but still kills the child (:320-322) — cancel of the *process* works;
  cancel of *in-flight requests* has no dedicated path (writer channel
  drop is the only mechanism, and only the manager's `stop` drops it).

## Deviations

None beyond the findings.

## Conclusion

Supports: process-level termination exists. Fails: request-level
cancellation cleanup, timeouts, retry, and restart bounds — none
implemented; the `Timeout` variant and `max_restarts` field are dead
contracts.
