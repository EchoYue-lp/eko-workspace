## Claim

IM channel connections and sends have a defined retry/cancel story: token
refresh retries, gateway/long-poll reconnection is bounded and
backoff-driven, and message sends recover or fail explicitly.

## Method

Static trace of `qq/api.rs` (TokenManager), `qq/channel.rs` (reconnect
loop), `qq/gateway.rs` (heartbeat/reconnect ops), `feishu/api.rs`
(TokenManager), `feishu/long_poll.rs` (backoff loop), `feishu/channel.rs`
(send loop), `feishu/webhook.rs` (dedup on retries).

## Expected Result

Reconnect with backoff; single-flight token refresh; duplicate webhook
retries deduplicated; send failures at least reported.

## Result

- Token managers (qq/api.rs:38-179, feishu/api.rs:186-291): cached tokens
  with refresh 5 minutes early, single-flight refresh via
  `refresh_lock` + double-check — correct retry-concurrency behavior.
- QQ gateway reconnect (qq/channel.rs:136-190): exponential backoff 1-60s,
  reset after 60s stable; heartbeat task aborts on connection end; no
  RESUME (re-IDENTIFY only, `OP_RESUME` is `#[allow(dead_code)]` at
  gateway.rs:27) — acceptable but full re-auth on every reconnect.
- Feishu long-poll reconnect (long_poll.rs:134-192): backoff with jitter
  (1s step jitter at :195-208), `reconnect_count` from server config
  (-1 = unlimited default), capped at 300s.
- Feishu webhook dedup: message_id marked processed before async handling
  and TTL-cleaned (webhook.rs:144-160) — Feishu timeout-retries do not
  double-process.
- **Send retry is absent**: QQ send task drops a message on any
  `send_qq_message` error (qq/channel.rs:118-129, warn+continue); Feishu
  likewise (feishu/channel.rs:227-238). No retry, no dead-letter, no
  at-least-once — a transient network error silently loses the user's
  reply. Finding F-INT-02-P3-04.
- Cancel: channels have no in-flight message cancellation; `stop()` is the
  only cancel, and its QQ teardown defect is covered by F-INT-02-P1-02.

## Deviations

No send retry/queue (finding F-INT-02-P3-04); QQ teardown defect
(P1-02) doubles as the cancel story for the send path.

## Conclusion

Supports: reconnection and token-refresh retry semantics are well-formed
with backoff and single-flight. Fails: message-send retry is non-existent.
