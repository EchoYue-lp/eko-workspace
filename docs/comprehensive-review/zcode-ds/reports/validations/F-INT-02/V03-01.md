## Claim

LSP lifecycle `new → initialize → [did_open/did_change/did_save]* →
shutdown` (documented at `echo-core/src/lsp/client.rs:39-43`) is
terminating: every request completes or fails, every `stop` returns, and
processes are reaped.

## Method

Static trace of `echo-integration/src/lsp/client.rs` (full),
`manager.rs` (full), `config.rs` (full), `echo-core/src/lsp/client.rs`
(full), and `echo-agent/src/tools/lsp.rs`.

## Expected Result

`shutdown()` sends shutdown/exit and kills the child; a hung-but-alive
server cannot block `stop`; restart bookkeeping (`max_restarts`,
`restart_count`) drives a bounded restart policy.

## Result

- `spawn_process` (client.rs:67-122) sets `kill_on_drop(true)` and stores
  the child; `shutdown` (client.rs:311-329) awaits `send_request("shutdown")`
  — `rx.await` at :225-227 has **no timeout**; a server that is alive but
  not answering blocks `shutdown` (and therefore `LspManager::stop_server`,
  `restart_server`, `shutdown_all`) forever. A dead server is fine
  (read_loop clears `pending` at :139-146, oneshot senders drop).
- `LspError::Timeout` (`echo-core/src/lsp/client.rs:15`) is never
  constructed; the only timeout in the stack is `LspManager::start_server`
  15s wrap around `initialize` (manager.rs:76-82), and the React tool-level
  timeout (echo-agent/src/agent/react/run/react_loop.rs:316) that bounds
  agent turns but not the client internals.
- Re-initializing an already-running `StdioLspClient` spawns a second
  process without killing the first (client.rs:272-309) — reachable only
  through direct API use, since the manager always builds a fresh client.
- `restart_count` (client.rs:40,60,528) is never incremented;
  `max_restarts` (types.rs:143-149) is never read; `restart_server`
  (manager.rs:105-108) has no production caller. `LspServerStatus` always
  reports `restart_count: 0`.
- EKO plugin reload awaits `shutdown_all()` on the live manager
  (echo-agent-cli/echo-agent-app-core/src/plugin_runtime.rs:583-975); a
  hung server blocks the reload path.

## Deviations

See findings F-INT-02-P1-01 (no request timeout; shutdown hang; pending-map
leak on cancelled requests) and F-INT-02-P2-01 (dead restart contract).

## Conclusion

Supports: process reaping via `kill_on_drop` and kill-on-shutdown is
present; lifecycle is NOT fully terminating — hung servers block shutdown,
and the documented restart/retry contract is inert.
