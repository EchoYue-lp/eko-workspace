## Claim

Channels are live-reachable: EKO CLI `channels` mode registers QQ/Feishu
channels, starts them through `ChannelManager::start_all`, drives messages
through `SessionHandler` → `AppChannelMessageHandler` → AgentPool, and
stops them via `stop_all` on the shutdown signal.

## Method

1. Read `echo-agent-cli/src/cli/modes.rs:110-255` (`run_channels_mode`).
2. Read `echo-agent-cli/src/cli/channels.rs` (AppChannelMessageHandler,
   `handle`/`handle_stream` at :78-230).
3. Read `echo-agent/echo-integration/src/channels/manager.rs` (start_all/
   stop_all/Drop), `session.rs` (SessionHandler), `channels/qq/channel.rs`,
   `channels/feishu/channel.rs` (start/stop).
4. `grep -rn "ChannelManager|SessionHandler"` in echo-agent-cli.

## Expected Result

One composition: CLI channel mode registers both platforms from
`echo-agent.yaml`, starts all, waits for SIGINT/SIGTERM, then
`manager.stop_all()`; messages flow framework-trait → EKO handler → pool.

## Result

- EKO channel mode (`modes.rs:122-247`): registers `QqChannel` and/or
  `FeishuChannel` per config, `start_all(handler_factory)` where the
  factory produces one `SessionHandler` per channel whose inner factory
  produces `AppChannelMessageHandler` (per-sender pool key
  `channel:{channel_id}:{sender_id}`), then awaits
  `infra::shutdown_signal()` and calls `manager.stop_all()`.
- `AppChannelMessageHandler` implements framework `MessageHandler`
  (`cli/channels.rs:78`), routes through `AgentPool::acquire` and the
  shared `drive_chat`; complex-task store is threaded through for feature
  parity.
- QQ `start` (`qq/channel.rs:83-196`): token manager + detached send task
  (JoinHandle discarded, `let _send_task = tokio::spawn(...)` at :108) +
  gateway reconnect loop (exponential backoff 1-60s). `stop` (:198-208)
  aborts only `gateway_handle`, drops `send_tx`.
- Feishu `start` (`feishu/channel.rs:194-300`): token verify, detached
  send task (`while let` at :218), long-poll `WsClient` or webhook task;
  `stop` (:302-312) aborts `task_handle`, drops `send_tx`.
- `ChannelManager::drop` (:131-141) only logs; it does not stop channels
  (doc at :14-15 claims "Auto-stop all channels on Drop").

## Deviations

QQ send task cannot terminate: `loop { if let Some(msg) = rx.recv() }`
spins when the channel closes after `stop()` (finding F-INT-02-P1-02).
ChannelManager Drop does not stop channels (finding F-INT-02-P2-05).

## Conclusion

Supports: channels are a live EKO surface with a single composition and
framework-trait bridging. Does not prove: clean teardown semantics (see
findings) or protocol behavior under faults (V03).
