## Claim

Malformed input from IM platforms (QQ gateway JSON, Feishu protobuf
frames/JSON events, webhook bodies, YAML config) is handled without panic
and without unbounded allocation.

## Method

Static trace of `qq/gateway.rs` (event parse), `qq/api.rs` (token/gateway
JSON), `feishu/long_poll.rs` (`handle_binary_frame`, `combine_fragments`,
`process_event_async`), `feishu/webhook.rs`, `feishu/proto.rs`, and
`feishu/api.rs`.

## Expected Result

Parse failures degrade per-event (skip or reconnect); no allocation is
driven by untrusted lengths; UTF-8 truncation uses char boundaries.

## Result

- QQ gateway: `serde_json::from_str` failure → `ChannelError::Other` →
  connection error → reconnect loop (gateway.rs:115-117, channel.rs:164-179).
  Malformed events cost a reconnect, never a panic. Debug logs truncate
  with `chars().take(200)` (gateway.rs:107-113) — UTF-8 safe.
- Feishu long poll: protobuf decode failure → `ConnectionError` → reconnect
  (long_poll.rs:332-334). Event JSON parse failure → warn (process_event_async
  :513-516). `String::from_utf8_lossy` for payloads (:401) — non-panicking.
- **Unbounded allocation**: `combine_fragments` builds
  `vec![None; sum as usize]` (long_poll.rs:482-484) where `sum` comes from
  the server-controlled `sum` header (`get_header_int(HEADER_SUM)`,
  :383). A malformed/hostile frame with a huge `sum` aborts the process on
  allocation failure; no cap. Finding F-INT-02-P2-06.
- Fragment slot write is guarded (`seq >= 0 && seq < sum`, :490-492) —
  indexing is safe.
- Feishu webhook: JSON extract rejection (axum) → 4xx, no panic; challenge
  and signature verification handled before processing; dedup map TTL 300s.
- QQ/Feishu message content parsing uses `serde_json::Value` access with
  defaults — safe for malformed content (qq/gateway.rs:258-317,
  feishu/long_poll.rs:593-604).

## Deviations

Unbounded `sum`-driven allocation (finding F-INT-02-P2-06); otherwise
malformed-input handling is non-panicking.

## Conclusion

Supports: panics absent; per-event degradation present. Fails: bounded
allocation under hostile frame headers (P2-06).
