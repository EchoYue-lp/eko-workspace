## Claim

Entry-point option handling (config, model, project, resume, logging,
conversation identity, shell env, panic hook) is consistent across TUI/GUI/CLI
entries, apart from deliberately documented differences.

## Method

Side-by-side inspection of `src/cli/args.rs`, `run_tui_or_cli_entry`
(src/main.rs:94-451) and `run_desktop` (src/tauri/desktop.rs:124-271).

```text
1. Args schema: args.rs:12-68 (tui, no_alt_screen, web, cli, port, host,
   model, project, mcp_config, config, channels, continue, resume, verbose)
2. GUI argv: desktop.rs:132 cli::Args::parse_from(["echo-agent-tauri"])
3. Conversation id: headless main.rs:128-150 (--resume/--continue/latest/fresh
   uuid); GUI desktop.rs:142-157 params.conversation_id=None ->
   bootstrap default (runtime.rs:89-91)
4. Logging target: main.rs:114-124 (TUI file vs stderr), desktop.rs:139 (stderr)
5. Shell env: desktop.rs:130 load_shell_env (macOS), not in headless
6. Panic hook: desktop.rs:74 install_panic_hook, not in headless
7. Working dir / project: headless passes project=args.project,
   working_dir=None (main.rs:153-165); GUI passes both None (desktop.rs:142-157)
```

## Expected Result

Same effective config chain (config file -> env overrides -> CLI flags) and
the same working-directory semantics on every surface; differences are either
by design (TUI file logging, GUI shell-env/panic-hook) or documented.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Config chain identical: `config::load_config(args.config.as_deref())` +
    `apply_env_overrides` in both entries (main.rs:100-101, desktop.rs:133-134);
    `--verbose` debug override only honored in headless (main.rs:104-106).
  - GUI entry parses a hard-coded single argv (desktop.rs:132) — `--config`,
    `--model`, `--project`, `--resume`, `--verbose` are silently ignored in
    GUI (already recorded as B-PATH-01-P3-02; not re-findable here).
  - Conversation identity: headless derives a persisted id from resume flags
    or a fresh uuid (main.rs:128-150); GUI always gets a fresh
    `primary-<uuid>` from bootstrap (runtime.rs:89-91). Consistent per
    surface; GUI restores per-conversation state via frontend IPC instead.
  - Working directory: both entries pass `working_dir=None` and
    `project=Some/None`; effective project root for subagents/memory is
    resolved identically inside `create_agent_with_diagnostics`
    (infra.rs:235-240: project -> working_dir -> cwd discovery) and
    `resolve_memory_store_paths` (infra.rs:1288-1313: workspace root -> cwd
    project discovery -> global). TUI project file scan uses process cwd
    (tui/mod.rs:1962); workspace switching changes process cwd (state.rs:854).
    No divergence found between entries.
  - Logging: TUI writes to project-scoped `tui.log` (infra.rs:1503-1505,
    1625-1649); CLI/channels/GUI to stderr + `~/.eko/logs/app.log`
    (infra.rs:1592-1617). GUI's stderr is lost in a packaged .app but the
    file mirror + crash log covers it (documented at infra.rs:1593-1597).
  - Shell env loading (GUI-only, macOS Dock launches) and panic hook
    (GUI-only crash log) are deliberate GUI adaptations with comments
    (desktop.rs:11-64, 128-131); not parity violations.
  - Reload behavior: config watcher identical in both entries
    (main.rs:230-237, desktop.rs:163-171) — hooks + webhook endpoints hot-
    reload; model/MCP/runtime topology requires restart (documented in
    config_watcher.rs:1-14).
- Historical reference: `MASTER-PLAN.md` Iteration 2 claim ("one
  Arc<WebhookEmitter> shared by chat, scheduler, and the active surface")
  is consistent with desktop.rs:196 and modes.rs:58 overrides.

## Deviations

GUI cannot honor `--config`/`--model`/`--project`/`--resume` at all
(B-PATH-01-P3-02); this is recorded there and referenced, not re-findable.

## Conclusion

only the documented GUI deviations; reload scope is identical. Contributes to
A-BOOT-01-P3-02/03 evidence where relevant. Does not cover startup-failure
