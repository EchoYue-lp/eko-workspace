## Claim

The composition-root constructors and service helpers have one authoritative
definition per concept across both repositories (no parallel implementations),
and their production construction sites are enumerable so "constructed exactly
once per entry" can be judged per entry point.

## Method

Repository-wide grep (both repos, excluding `target/`) for the definitions and
production call sites of: `AgentRuntime::bootstrap`, `AppState::from_shared`,
`start_headless_services`, `run_channels_mode`, `TaskRuntimeStore::new`,
`TaskRuntimeStore::new_in_memory`, `recover_incomplete`,
`register_task_tools_on_agent`, `bind_task_execute_to_pool`,
`spawn_config_watcher`, `spawn_dreaming_task`, `spawn_mcp_health_check`,
`init_logging`, `init_logging_for_tui`, `on_session_end`, `into_app_state`,
`close_all` (TerminalManager), `sqlite`.

```text
cd echo-agent-cli && grep -rn "<symbol>" --include="*.rs" . | grep -v target/
```

## Expected Result

One production definition per concept; construction sites countable; no
second authority in `echo-agent` for the EKO composition roots.

## Deviations

`AppState::from_shared` runs in a third context (modes.rs:57) whose state is
discarded — this is a production duplicate-construction site, not a test.
`WebhookEmitter::from_config` inside `from_shared` (state.rs:469) is
constructed and then immediately replaced at both entries (desktop.rs:196,
modes.rs:58).

## Conclusion

Supports: one authoritative definition per composition concept; the two-entry
(bootstrap, watcher, task-store, pool, task-service, scheduler) ownership map
holds, plus a channels-only gap and a discarded temporary-AppState
construction (findings A-BOOT-01-P2-01, A-BOOT-01-P2-02). Does not prove
runtime behavior; reachability is covered by V02.
