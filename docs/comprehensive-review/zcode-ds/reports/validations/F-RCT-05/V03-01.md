## Claim

AgentCheckpoint save → restore is a lossless field round-trip for the fields
that exist, and the round-trip is covered by tests that exercise the pairing
validator.

## Method

Field-by-field comparison of the save site and the restore site:

- Save: `save_runtime_checkpoint` (snapshot.rs:570-631) constructs
  `AgentCheckpoint { conversation_id, messages_json, current_plan, active_skills,
  blocked_reason, working_dir, timestamp }` from `ctx.messages()`,
  `plan_state`, `tools.active_skill_names`, the passed `blocked_reason`, and
  `config.working_dir`.
- Type: `AgentCheckpoint` (state/mod.rs:117-135) — 7 fields, all
  `Serialize`/`Deserialize`.
- Restore: `resume_from_state_store` (react/mod.rs:1680-1752) reads
  `messages_json` (via `restore_messages`, state/mod.rs:157-168), `current_plan`
  (:1697-1700), `active_skills` (:1703-1705), `working_dir` (:1718-1721),
  `blocked_reason` (:1724-1729), `timestamp` (trace event :1732-1737).
- File impl: `FileRuntimeStateStore::save_checkpoint`/`get_checkpoint`
  (state/file.rs:151-187) — serde_json round-trip with atomic_write
  (unique-uuid tmp + fsync + rename, file.rs:210-219).
- Tests: `state::checkpoint_tests` (state/mod.rs:298-360) —
  `checkpoint_restores_paired_tool_history` (round-trip + completed ids),
  `checkpoint_rejects_unpaired_or_duplicate_tool_results`;
  stream_channel.rs:1600-1632 (`completed_tool_batch_is_checkpointed_before_next_model_call`),
  :1634-1711 (`resume_records_checkpoint_origin_and_completed_tools_in_trace`);
  V04-01 executed both checkpoint tests (exit 0).

## Expected Result

Every saved field is restored with identical value; message history round-trips
through JSON; unpaired tool calls are rejected with a typed error.

## Result

- Exit code: not-applicable (static inspection plus V04-01 test runs)
- Duration: ~15 min
- Summary:
  - All 7 fields have a matching restore site; no field is dropped or
    fabricated. `working_dir`/`blocked_reason` are `Option` with
    `#[serde(default, skip_serializing_if = "Option::is_none")]` on
    `working_dir` (state/mod.rs:130) — backward-compatible serde defaults.
  - Round-trip of messages is not symmetric by design: `restore_messages`
    VALIDATES pairing (state/mod.rs:166, 186-231) and errors on:
    duplicate in-flight call ids, tool result without call, orphan/duplicate
    result, name mismatch, and pending (result-less) calls. So the round-trip
    is lossless for well-formed checkpoints and rejecting for malformed ones.
  - `completed_tool_call_ids` (state/mod.rs:171-183) correctly extracts
    Tool-role message ids in message order (unit-tested, state/mod.rs:332).

## Deviations

The validation asymmetry is a design property, not a deviation: a checkpoint
containing any result-less tool call is rejected wholesale (see V03-02 for the
"completed-tool skip" consequence and V03-04 for the fallback behavior).

## Conclusion

Supports: snapshot field round-trip invariant holds for well-formed
checkpoints; the pairing validator is the single gate that makes a checkpoint
resumable. Does not support any claim about checkpoints that contain in-flight
calls at save time — those are saved by the cancel/error arms (V03-03) and
rejected on restore (V03-04).
