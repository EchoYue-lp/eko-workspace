## Claim

The steer / snapshot / checkpoint / resume / safe-point concepts have exactly one
authoritative definition and one live implementation per semantic across
`echo-agent` and `echo-agent-cli`; no parallel second authority exists for
same-turn steering, runtime checkpointing, or resume.

## Method

Repository-wide grep (both repositories, production sources, excluding test
modules where noted) for the concept families:

```text
steer|Steer            (echo-agent/src, echo-agent-cli/echo-agent-app-core/src, echo-agent-cli/src)
checkpoint|Checkpoint
resume|restore|Restore|Resume
AgentCheckpoint|RuntimeCheckpoint|struct Checkpoint
save_runtime_checkpoint|resume_from_state_store|save_runtime_state|save_checkpoint|restore
interrupt|Interrupt
```

Each hit classified as: definition / registration / live caller / dead code /
test-only. Full hit lists recorded in the analysis notes; representative
anchors below.

## Expected Result

One `TurnSteerMailbox` definition, one `AgentCheckpoint` type, one
`RuntimeStateStore` trait with two impls (file default, sqlite feature), one
resume entry (`resume_from_state_store`), and checkpoint call sites confined to
the shared loop phases; no EKO-side duplicate runtime.

## Result

- Exit code: not-applicable (static inspection)
- Duration: ~20 min
- Summary:
  - Steer: single authority — `TurnSteerMailbox` (echo-agent/src/agent/steer.rs:44),
    lease `ActiveTurnLease` (steer.rs:132), public entry `ReactAgent::steer_input`
    (react/mod.rs:271-276) and `AgentHandle::steer_input` (handle.rs:187-194),
    consumption only in `drain_steer_into_context` (stream_channel.rs:328-349)
    called from the shared loop (stream_channel.rs:538, 663, 709). No duplicate
    mailbox in either repository. EKO surfaces (`steer_chat_message`
    src/tauri/commands/chat.rs:735, `/steer` src/tui/events.rs:1438) are thin
    callers of the framework API.
  - Checkpoint: single `AgentCheckpoint` (src/state/mod.rs:117-135); trait
    `RuntimeStateStore` (state/mod.rs:244-283) with default
    `FileRuntimeStateStore` (state/file.rs) and `sqlite`-feature
    `SqliteRuntimeStateStore` (state/sqlite.rs) — the SQLite impl is a valid
    framework option (F-MEM-02 scope), not a duplicate authority. Checkpoint
    writes all go through `AgentRunSnapshot::save_runtime_checkpoint`
    (snapshot.rs:570-631), called only from loop phases: compact.rs:35,
    tools.rs:203/258/296/309/336/414/419/429/439, finalize.rs:79/164/251, and
    the user-facing `force_checkpoint` (react/mod.rs:1758-1763).
  - Resume: single entry `ReactAgent::resume_from_state_store`
    (react/mod.rs:1680-1752), called only from `restore_thread_context`
    (run/context.rs:230-261), which is called at turn start in
    StreamMode::Execute (context.rs:502, 571; direct.rs:11). EKO does not
    duplicate resume; it restores conversation history via `load_messages`
    (conversations.rs:712, main.rs:215, session.rs:140) — a different
    mechanism (conversation-store projection, A-STATE-01 scope), not a second
    runtime checkpoint authority.
  - TaskNode/hydration: `hydrate_running_nodes` (snapshot.rs:763-791) single
    implementation.
  - No `interrupt`-named framework API; interrupt is expressed as
    cancellation tokens + the cancel arms in `run_tools` (single batch
    authority, F-RCT-04) and `ThinkOutcome::Cancelled` (think.rs:50).
  - No parallel snapshot implementation: `AgentRunSnapshot` (snapshot.rs:329)
    is the only run snapshot; the legacy `AgentSnapshot` clone mentioned in the
    module doc no longer exists.
  - EKO-side: `infra.rs:126` `state_store` field, `runtime.rs:80-86` wiring,
    `state.rs:924/1090` workspace-switch store reset — thin construction, no
    second runtime.

## Deviations

None. One note: `restore_thread_context` is reachable at every Execute-mode
turn start (not only at process start), which changes the blast radius of a
bad checkpoint (see V03-04 and finding F-RCT-05-P1-01).

## Conclusion

Single-authority claim holds: one steering mailbox, one checkpoint type, one
resume entry, one live batch-cancel authority. Supports the layering
classification (all generic mechanisms in `echo-agent`, EKO adds only thin
callers). Does not by itself establish behavioral correctness — that is V02,
V03, V04.
