## Claim

The resume, checkpoint, and steer paths are reachable from the EKO main
turn path with the identities used in production, and the drain/mark/restore
keying matches between producer and consumer on every path.

## Method

Static call-graph trace, following these chains in the source:

1. EKO turn entry: `chat_driver.rs:490-514` builds `AgentInvocationContext`
   with `runtime.run_id` (Task mode: `formal_run_id_for_turn(turn_id)` =
   `format!("taskrun:{turn_id}")`, task_tools.rs:178-180; Chat/Auto: `None`)
   and `runtime.turn_id = Some(turn_id)` → `execute_stream_message_with_invocation_context`
   (react/mod.rs:2913-2925) → `run_stream_message_entry(message,
   StreamMode::Execute, Some(invocation))` → `run_stream_channel`
   (stream_channel.rs:35-316).
2. Steer producer/consumer keying: lease `begin(turn_id)` with
   `turn_id = runtime.turn_id.or(runtime.run_id).or(agent.current_run_id).or(uuid)`
   (stream_channel.rs:111-122); drain key `self.current_run_id`
   (stream_channel.rs:333) with `current_run_id = runtime.run_id` for
   invocation paths (snapshot.rs:461-469). Compare the two values per EKO mode.
3. Resume chain: Execute mode → `restore_thread_context` (context.rs:502/571,
   direct.rs:11) → `resume_from_state_store` (react/mod.rs:1680-1752) →
   `AgentCheckpoint::restore_messages` → `validate_tool_message_pairing`
   (state/mod.rs:157-168, 186-231) → context `set_messages` / plan /
   `skill_registry.mark_activated` / `hydrate_running_nodes` / working_dir.
4. Checkpoint producers: `save_runtime_checkpoint` (snapshot.rs:570-631) call
   sites at compact.rs:35, tools.rs:203/258/296/309/336/414/419/429/439,
   finalize.rs:79/164/251, force_checkpoint (react/mod.rs:1758-1763).
5. Skill activation save/restore/read divergence (F-SKL-01-P1-02 independent
   verification): save = `ToolRuntime::from_agent` union of tracking +
   progressive registries (snapshot.rs:206-222); restore = `mark_activated`
   on tracking registry only (react/mod.rs:1703-1704); tools read the shared
   progressive registry (`is_activated`, resource_tool.rs:98-103,
   activate_tool.rs:150/191, run_script_tool.rs:191); tool construction passes
   the shared registry (capabilities.rs:857-865).

## Expected Result

Steer drain key equals lease key on every reachable path; resume restores
checkpoints that `validate_tool_message_pairing` accepts; the same skills are
marked activated on the registry the skill tools consult.

## Result

- Exit code: not-applicable (static trace)
- Duration: ~25 min
- Summary:
  - Steer keying: lease key = `turn_id`; drain key = `current_run_id` =
    `runtime.run_id`.
    - EKO Chat/Auto: `run_id = None` → `drain_steer_into_context` returns 0
      at stream_channel.rs:333-335 → steer never drained.
    - EKO Task mode: `run_id = "taskrun:{turn_id}"` ≠ `turn_id` →
      `mailbox.drain("taskrun:...")` finds no active turn (active id =
      `turn_id`, steer.rs:117-119) → never drained.
    - Framework non-invocation paths: lease key and `current_run_id` both
      derive from `agent.current_run_id` (stream_channel.rs:115-121 vs
      snapshot.rs:461-469; react_loop.rs:614-619 vs 688-692) → match.
    - The only steer integration test sets `run_id == turn_id ==
      "turn-steer-1"` (stream_channel.rs:2106-2107) and therefore passes —
      it cannot observe the EKO mismatch.
  - Resume reachability: every EKO turn (GUI/TUI/CLI chat and Task executor)
    runs in StreamMode::Execute with `conversation_id` set (chat_driver.rs:492-505)
    and a `FileRuntimeStateStore` configured (runtime.rs:80-86, infra.rs:126)
    → `restore_thread_context` → `resume_from_state_store` runs at the start of
    every turn, in-process and after restart.
  - Skill divergence: confirmed exactly as F-SKL-01-P1-02 described —
    save is a union over both registries (snapshot.rs:206-222), restore marks
    only `self.tools.skill_registry` (react/mod.rs:1703-1704), and
    `ReadSkillResourceTool`/`RunSkillScriptTool`/`ActivateSkillTool` consult
    the shared registry (capabilities.rs:857-865 → resource_tool.rs:98-103,
    run_script_tool.rs:191, activate_tool.rs:150/191). After a fresh-process
    resume the shared registry is never marked, so the tools return "Skill 'X'
    has not been activated"; re-activation by the model then injects the
    instructions a second time.

## Deviations

None for the traced chains. The steer mismatch is a behavior deviation from
the documented contract (see finding F-RCT-05-P1-02 and V05-01).

## Conclusion

Supports: (a) F-RCT-05-P1-01 (resume/checkpoint poison path reachable on the
EKO main path), (b) F-RCT-05-P1-02 (steer drain mismatch on invocation
paths), (c) F-RCT-05-P1-03 (skill activation divergence, confirming
F-SKL-01-P1-02 independently). Does not prove the checkpoint content itself is
poisoned at cancel time — that is V04-04 (dynamic probe).
