## Claim

Non-GUI/TUI triggers preserve identity, noninteractive event output, and
cancel/shutdown/recovery semantics equivalent to TUI/GUI: (a) turn/run/
conversation identity propagates into the shared driver and durable stores;
(b) terminal/error events reach noninteractive consumers; (c) every surface
can cancel an in-flight chat turn and shut down gracefully; (d) interrupted
runs have a recovery surface on every surface.

## Expected Result

Turns on every surface are cancellable; shutdown stops scheduler/background
loops; every interrupted run (background or cron) has a resume surface on the
surface that owns it; identity is consistent per trigger.

## Result

- Exit code: 0 (static; commands listed in method)
- Duration: n/a
- Summary — observed violations:
  (a) REPL/channel chat turns are not cancellable: the `CancellationToken`
      at repl.rs:533 / channels.rs:244 has zero producers (never fired); the
      REPL input loop is blocked for the whole turn (repl.rs:234); in CLI
      mode no Ctrl+C/SIGTERM handler exists (only channels mode installs
      `shutdown_signal` at modes.rs:228), so mid-turn Ctrl+C terminates the
      process with default SIGINT disposition, skipping `shutdown_hook_events`
      (main.rs:438-442) and graceful store shutdown. TUI (events.rs:1939)
      and GUI (chat.rs:807-826) both cancel in-flight turns.
  (b) `scheduler.cancel_token`/`tasks.cancel_token` (state.rs:662/692/699)
      are never cancelled anywhere — scheduler and background loops are
      process-lifetime with no graceful stop (cross-check of
      A-BOOT-01-P3-03).
  (c) Interrupted cron runs: `recover_incomplete` (store.rs:1631-1776) turns
      them Paused at boot, but `resume_pending` (service.rs:556) filters
      `conversation_id.starts_with("background:")`, and CLI `/tasks resume`
      (service.rs:469-489) rejects non-background runs — a Paused cron run
      is unresumable from the CLI (TUI events.rs:4710 / GUI task_runtime.rs
      resume bypass the filter). In channels-only mode no resume surface
      exists at all.
  (d) Channels-only mode never runs `resume_pending` (no BackgroundTaskService
      — V02) and never starts the scheduler — background runs stay Paused
      after restart and cron never fires on that surface.
  (e) Identity propagation is consistent: conversation_id per trigger family
      (channel:..., cron:..., background:..., boot uuid for REPL) reaches
      drive_chat / TaskRuntime run creation and the pool key; turn_id is a
      fresh uuid per turn (REPL channels.rs:202 / repl.rs:495); Task-mode
      formal run derived as taskrun:<turn_id>. Cron/background runs carry
      empty root_message_id (executor.rs:3587) — turn_id None in the
      ExternalRunContext for unattended runs (by design).
  (f) Noninteractive event output exists via durable run store + webhook
      (CronTaskCompleted, drive_chat webhook observers); the REPL has no
      single-shot noninteractive mode (interactive-only surface; no
      --exec/--print flag in args.rs).

## Deviations

All conclusions are static; no live LLM turn or IM traffic was executed.
The "Ctrl+C terminates the process" consequence follows from the absence of
any signal handler on the CLI path (verified by grep) and default SIGINT
disposition, not from a live reproduction.
