## Claim

The local developer tools (shell, run_code, files, git, worktree) handle
paths (relative/absolute/Chinese/emoji/space/special chars), UTF-8
truncation, and containment correctly — no byte-level slicing of possibly
multibyte strings, and no panic reachable from path/parameter input.

## Method

1. Full read of `echo-tools/src/files/mod.rs` (resolve_path/normalize_path),
   `files/files.rs`, `files/edit.rs`, `files/grep.rs`, `files/glob.rs`,
   `files/diff.rs`, `files/code_search.rs`, `files/repo_map.rs`,
   `files/artifact.rs`, `shell.rs`, `code.rs`, `git.rs`, `git_worktree.rs`,
   `worktree_tool.rs`, `security.rs` (PathValidator section), `registry.rs`.
2. Panic/UTF-8 audit of every `[..]` slice, `unwrap`, `expect`, and index in
   the above files.
3. Empirical check (scratch program at /tmp/f-ext-02-check/check.rs,
   replicating `find_occurrence_lines` from edit.rs:260-270 and
   `glob_with_doublestar` from glob.rs:240-284) compiled with rustc and run:
   empty-needle on ASCII and on Chinese haystack; non-empty needle on Chinese;
   doublestar globs on realistic paths.

## Expected Result

- All `[..]` slices on `String`/`&str` must be provably char-boundary-safe or
  the tool must reject the input first (AGENTS.md rule).
- Doublestar globs (`**/*.rs`, `src/**/*.rs`) should match real files.
- resolve_path must confine absolute/relative paths and reject `..`/symlink
  escapes; non-existent-output parents canonicalized.

## Result

- Exit code: 0 (scratch program; panics captured via catch_unwind and printed)
- Duration: <1 s
- Summary:
  - **PANIC CONFIRMED**: `find_occurrence_lines("abc", "")` panics
    ("start byte index 4 is out of bounds for string of length 3");
    `find_occurrence_lines("中文", "")` panics ("byte index 1 is not a char
    boundary; it is inside '中'"). Non-empty needle on multibyte content is
    safe (returns [1, 2]).
  - **DOUBLESTAR CONFIRMED BROKEN**: `glob_with_doublestar("**/*.rs",
    "/a/b/main.rs")` = false; `src/**/*.rs` on `/repo/src/x/main.rs` = false;
    only a file literally named `*.rs` matches (ends_with of raw pattern text).
  - Static audit: shell.rs (IncrementalUtf8Decoder, split_stream_chunks,
    RetainedOutput) is UTF-8-safe and panic-free; files.rs read_file
    (from_utf8 → GBK fallback, char/line iteration, saturating math) is safe;
    glob.rs glob_match_advanced is char-index safe (explicit fix comment at
    glob.rs:304-308 with regression tests); artifact.rs token_bounded_prefix
    uses chars().take binary search; grep.rs/diff.rs/code_search.rs/repo_map.rs
    safe (no byte slicing); git.rs/worktree tools use argv + to_string_lossy
    only.
  - resolve_path (files/mod.rs:35-132): confines to effective base
    (base_dir else working_dir), canonicalizes, canonicalizes parent for
    not-yet-existing files, rejects `..` escapes; deep-nonexistent-parent
    fallback returns textual path (residual symlink gap, see task report
    P3-04 note / F-SEC-01-P3-06 relation).
  - PathValidator (security.rs:272-343) `validate_within_base` has zero
    callers (grep both repos); file/git tools use resolve_path, NOT
    PathValidator — confirms F-SEC-01 P3-06 handoff.

## Deviations

- `files/mod.rs:24-27` doc claims "when only working_dir is set ... no
  confinement check", but code (mod.rs:45-70) confines to working_dir — doc
  stale, behavior stricter (see task finding F-EXT-02-P3-04).
- The /tmp scratch program replicates two helper functions verbatim; it does
  not exercise the full `edit_file`/`GlobTool` execute paths end-to-end.

## Conclusion

Supports: UTF-8 handling across shell/files is exemplary and mostly
compliant; two defects found — (1) `edit_file` with `old_content=""` panics
(byte-slice out of bounds / non-char-boundary), violating the AGENTS.md
no-panic rule (finding F-EXT-02-P1-01); (2) glob `**` patterns never match
real files (finding F-EXT-02-P2-01). Does not prove: end-to-end tool-call
behavior (covered by V05 unit tests).
