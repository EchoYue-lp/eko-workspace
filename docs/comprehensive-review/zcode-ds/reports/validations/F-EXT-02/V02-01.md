## Claim

Shell and run_code child-process cleanup is complete on cancellation,
timeout, and stream drop (kill_on_drop / process-group kill / sandbox
cancellation), and the F-EXT-01 ToolContext cancel contract is honored where
the tool owns a process.

## Method

1. Read `echo-tools/src/shell.rs` execution paths: `start_direct_stream`
   (564-605), `run_direct_child` (674-810), `cleanup_direct_child` (845-856),
   `start_sandbox_stream` (607-672); `echo-tools/src/code.rs` execute path
   (248-378).
2. Read sandbox executor child cleanup in
   `echo-execution/src/sandbox/local.rs` (grep kill_on_drop/process_group/
   kill: lines 406, 419, 589, 607) and `echo-core/src/tools/mod.rs`
   (ToolContext.cancel field, line 985).
3. Cross-reference F-EXT-01 V01 (cancel is cooperative-only at manager
   level; timeout drop is the enforced bound) and F-SEC-01 V03 (run_code
   fail-closed isolation chain).
4. Confirm no `catch_unwind` barrier around tool execution
   (`echo-execution/src/tools.rs:686-698` awaits the tool future inline).

## Expected Result

- Direct shell path: child killed on timeout, on stream drop (tx.closed),
  and on read errors; process group (negative pid SIGKILL) covers
  descendants; kill_on_drop as last resort.
- Sandbox path: cleanup delegated to SandboxExecutor, which kills on drop /
  cancellation.
- run_code: `ctx.cancel` pre-checked before startup and passed into
  `execute_with_limits_and_cancel`.
- git.rs / git_worktree.rs / git_checkpoint.rs: synchronous std Command —
  expected to be non-cancellable (documented deviation).

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - shell direct path: `kill_on_drop(true)` (shell.rs:576),
    `process_group(0)` on unix (shell.rs:578), `cleanup_direct_child` sends
    `kill -KILL -{pid}` to the whole group and reaps (shell.rs:845-856);
    called on tx.closed (700-703), deadline (704-716), send errors
    (728-730, 743-745, 763-765), wait errors (790-793). Timeout result uses
    ToolFailureCategory::Timeout + ToolSideEffect::Possible postcondition
    (1049-1055). Killing is covered by the green test
    `dropping_shell_stream_kills_and_reaps_child` (shell.rs:1661-1707).
  - shell sandbox path: on tx.closed the spawned loop returns and drops the
    executor stream; the local executor itself sets kill_on_drop + process
    group + explicit kill (local.rs:406,589,607) — cleanup is delegated and
    present.
  - run_code: pre-start cancel check (code.rs:331-339, Cancelled category
    with Possible side effect), and `ctx.cancel.clone()` passed to the
    executor (code.rs:358); cancelled/timed-out results map to
    Cancelled/Timeout categories (code.rs:435-457).
  - git.rs `run_git` (598-608), git_worktree.rs (all), git_checkpoint.rs
    (13-42, 51-56, 66-83): synchronous `std::process::Command::output()`,
    no kill_on_drop, no ctx.cancel consultation — blocking and
    non-cancellable (finding F-EXT-02-P3-01). git_checkpoint is invoked
    synchronously from async file-tool paths (files.rs:289, edit.rs:216).
  - No panic barrier: a panic in any tool future propagates into the agent
    run (finding F-EXT-02-P1-01 impact).

## Deviations

- Shell tool never consults `ctx.cancel` directly; cancellation is expressed
  by dropping the stream / closing tx. This matches the F-EXT-01-recorded
  contract (cancel cooperative-only at manager level), so it is compliant,
  not a deviation from the contract — recorded for completeness.

## Conclusion

Supports: shell direct path and run_code have complete, tested child-process
cleanup (kill on timeout/drop/cancel); sandbox path delegates to a
kill-capable executor. Supports: git-family tools are blocking and
