## Claim

git_worktree / worktree_tool create, reuse, merge, and clean up worktrees
correctly, confining paths to `.worktrees/`, and failures do not produce
silent partial side effects (worktree left behind, branch deleted
unverified, changes discarded).

## Method

1. Full read of `echo-tools/src/git_worktree.rs` (create_worktree 37-112,
   remove_worktree 115-147, list_worktrees 150-190, merge_worktree 193-232,
   find_git_root 234-248) and `echo-tools/src/worktree_tool.rs`
   (EnterWorktreeTool 78-128, ExitWorktreeTool 175-240, ListWorktreesTool
   278-316).
2. Trace each failure path: what state is left and whether the tool reports
   success.

## Expected Result

- `enter_worktree`: `path_suffix` confined under `git_root/.worktrees/`;
  absolute or `..` suffixes rejected.
- `exit_worktree`: removal errors surface as failures; destructive actions
  (`git worktree remove --force`, `git branch -D`) only target worktrees
  verified to belong to this repo; success message implies the worktree was
  actually removed.
- `merge_worktree`: on conflict the error is returned and the repo state
  (checked-out target branch) is acknowledged.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - create_worktree: `worktree_dir = git_root.join(".worktrees").join(suffix)`
    (git_worktree.rs:44-51) — `PathBuf::join` with an absolute `suffix`
    replaces the base and `..` escapes upward; only the branch-derived
    DEFAULT name is sanitized (47-50), `path_suffix` is raw.
    → finding F-EXT-02-P2-03 (worktrees/checkouts can be created outside
    the repo). Branch reuse path: "already exists" stderr match retries
    without `-b` (83-105); on failure the error is returned.
  - remove_worktree: `git worktree remove --force` failure is IGNORED
    (falls into `let _ = ... prune`), prune errors ignored, `git branch -D`
    errors ignored (130-146), function always returns Ok(()) — success is
    reported even when nothing was removed.
    → finding F-EXT-02-P2-02 (silent partial side effects).
  - ExitWorktreeTool fallback (worktree_tool.rs:195-210): when the supplied
    `worktree_path` does not string-match any listed worktree (e.g. trailing
    slash, different normalization), the path is "treated as managed" with
    branch = file_name → `git branch -D <file_name>` and `remove --force`
    run against an unverified target.
    → finding F-EXT-02-P2-02.
  - `remove --force` discards uncommitted/untracked worktree content without
    a warning message; with `merge_to` unset the branch tip work is deleted
    via `-D` after removal — destructive with no confirmation and no
    error-path acknowledgment (risk_level Dangerous is the only signal).
  - merge_worktree: checkout failure and merge conflict are returned as
    errors (208-214, 224-229) — good; after a merge conflict the repo is
    left on the target branch with a merge in progress and the worktree
    still present (partial state acknowledged only implicitly via the error
    text).
  - list_worktrees parsing of `--porcelain` is correct; `managed: false` for
    listed entries (correct — only created-by-us worktrees are managed).

## Deviations

- None observed beyond the findings above.
