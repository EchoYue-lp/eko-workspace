## Expected Result

A live index with mtime-based invalidation; one diff authority with standard hunk headers; switch/exit fully rebinds cwd-derived state; bounded walkers and revision-guarded writes.

## Result

- Exit code: not applicable (static inspection + replicas, see V04-04 for replica exit codes)
- Summary:
  - **(A) Index lifecycle — violated.** `ProjectIndex` (index.rs) has no `refresh`, no invalidation, no mtime comparison, no watcher; `built_at` (:60, :87-92) and `modified` (:22, :182-186) are written but never read for staleness; and the type is dead anyway (V01-01). The only live index, TUI `project_files`, is a boot-only snapshot (mod.rs:1966) never rebuilt — files created/deleted during a session are missing/stale in `@`-completion (finding P2-02).
  - **(B) Diff source-of-truth — violated.** Three live diff engines with divergent semantics (V01-01). GUI `diff_file` groups ALL changes of a file into ONE hunk whose header counts only changed lines, not hunk content (files.rs:322-372; replica: 10-line file with one change → `@@ -1,1 +1,1 @@`, hunk holds all 11 lines, V04-04). App-core `diff.rs` groups with `grouped_ops(context)` and trims trailing newlines (diff.rs:83, :102/:112/:121) — different rendering than the GUI path for the same file. Framework `DiffTool` uses `similar::udiff::unified_diff`. Large-repository consequence: a big file with a one-line change renders the entire file as one hunk in the GUI (finding P2-03).
  - **(C) Workspace switch — mostly compliant with two capture-at-boot gaps.** `switch_workspace` refreshes the project-context projection with the new workspace root (state.rs:883) and `get_workspace_root` follows `current_workspace()` at call time (files.rs:451-457) — no stale project binding after switch. `exit_workspace` clears the projection (state.rs:1072) but never restores the process CWD (state.rs:1053-1185, cross-ref A-CFG-01-P1-02); after exit, `discover_project_root(None)` (infra.rs:240) and REPL-style cwd discovery resolve to the exited workspace. REPL `CodingLoop` root (repl.rs:183-189) and TUI `project_files` (mod.rs:1966) are captured at boot and never rebound — stale-by-design snapshots (findings P2-02/P2-04; REPL/TUI have no switch surface, A-CFG-01-P1-03).
  - **(D) Large-repo and conflicting-file behavior — bounded on read, correct on write.** Walker caps: 1 MB/file and no total cap in dead `ProjectIndex.build`; 10 000-entry cap in TUI `collect_project_files` (blocking sync walk at boot); depth-3 / ~80-entry file-tree summary (context.rs:124-179); GUI write path is atomic (temp + rename, files.rs:196-205) with a revision check ("File changed on disk", files.rs:182-187) mirrored by the frontend conflict banner (fileStore.ts:220-225) and the 2.5 s disk-revision poll (fileStore.ts:38-45). `GitIgnore.globstar_match` panics on multibyte paths and mishandles `**` patterns — latent only (no production callers, finding P3-01).
