## Claim

Event envelope producers and consumers are reachable end-to-end: the
framework produces `EventEnvelope` streams in the React engine, subagent
executor, and A2A server; EKO consumes them in `chat_driver`,
`surface_contract`, and channels. Identity is constructed at each production
site with stable ids on the EKO main path.

## Method

1. `grep -rln "envelope_event_stream"` across both repositories.
2. `grep -rn "EventIdentity\|from_invocation"` at each production site.
3. Read `echo-agent-cli/echo-agent-app-core/src/chat_driver.rs:478-545`
   (identity + invocation construction + envelope wrapping).
4. Read `echo-agent/src/agent/subagent/executor.rs:1166-1185` (subagent
   envelope usage).
5. Grepped `EventEnvelope` consumers in app-core (`chat_driver.rs`,
   `surface_contract.rs`, `src/cli/channels.rs`).

## Expected Result

Framework: root `src/lib.rs`, `src/a2a/server.rs`, `src/agent/mod.rs`
(re-export), `src/agent/subagent/executor.rs`, `echo-core` internal. EKO:
chat_driver + surface_contract + channels.

## Result

- Producers (framework): `echo-agent/src/lib.rs` (prelude re-export),
  `echo-agent/src/a2a/server.rs`, `echo-agent/src/agent/subagent/executor.rs`
  (`:1168` `EventIdentity::from_invocation`), `echo-core/src/agent/mod.rs`
  (re-export), `echo-core/src/agent/event_envelope.rs` (definition).
  The root React engine (src/agent/react) does not call
  `envelope_event_stream` directly — wrapping happens at the
  invocation-boundary (subagent executor) and at EKO's `drive_chat`
  (chat_driver:538).
- Consumers (EKO): `chat_driver.rs` (wraps raw stream with
  `envelope_event_stream`, `:538`; constructs `EventIdentity` directly with
  conversation/run/turn ids, `:483-488`; forwards to sinks as
  `ChatDriverEvent::Agent(Box<EventEnvelope>)`, `:526-527`),
  `surface_contract.rs` (event contract tests incl. parent_event_id and
  run_id projection, `:156-299`), `src/cli/channels.rs` (channel event
  consumption).
- Identity stability on the EKO main path: chat_driver builds
  `ExternalRunContext` with conversation_id + run_id (active_run_id) +
  turn_id (`:492-500`), so `EventIdentity` is deterministic per turn.
- Subagent path: `EventIdentity::from_invocation(&invocation)`
  (executor.rs:1168) — identity inherits whatever the invocation's
  ExternalRunContext carries; fallbacks apply when fields are None (V03).

## Deviations

None.

## Conclusion

Supports: end-to-end producer/consumer reachability; EKO's main chat path
provides stable identity; the subagent path inherits invocation identity.

Does not prove: that every consumer preserves envelope invariants
(X-EVT-01), or the edge-case behavior of identity fallbacks (V03).
