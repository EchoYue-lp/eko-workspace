## Claim

The default/full-auto mode matrix is coherent end to end: EKO surfaces expose
exactly the modes the framework implements, the mode reaches the decision
pipeline on the live path, protected paths deny in every mode, and
mode changes propagate to existing and future agents.

## Method

Static trace of mode string -> framework `PermissionMode` -> decision
behavior, and of mode propagation on each surface.

1. EKO surface normalization (four user-facing modes):
   - GUI `set_permissions_mode`: `echo-agent-cli/src/tauri/commands/panels.rs:43-80`
   - TUI `/permission`: `echo-agent-cli/src/tui/events.rs:3578-3605`
   - CLI `/permission`: `echo-agent-cli/src/cli/cmd_impls/coding.rs:645-685`
2. Mode -> `PermissionMode` mapping and service propagation:
   `echo-agent/src/agent/react/mod.rs:2047-2081` (`set_permission_mode`:
   full-auto -> BypassPermissions with loud warn, auto-edit -> AcceptEdits,
   strict -> StrictConfirm, default -> Default; cache cleared on switch),
   `echo-agent/src/agent/config.rs:1042-1058`, `normalize_permission_mode`.
3. Decision dispatch per mode:
   `echo-orchestration/src/human_loop/service.rs:484-681`
   (`check_with_permissions_in_mode`: protected path first, bypass, plan,
   rules, cache, denial tracker, handler check, mode dispatch),
   `service.rs:167-182` (confirmation-required sets),
   `service.rs:250-256` (`has_real_handler`), `service.rs:568-575`
   (no-handler -> RequireApproval, never silent allow).
4. EKO wiring: `runtime.rs:130-141` (primary: dispatcher + service),
   `agent_pool.rs:467-483` (`apply_permission_mode` propagates to existing
   pool agents) and `:928-932` (shared service + mode on new agents),
   test `agent_pool.rs:1445-1464`.
5. Pool/background default: empty `HitlDispatcher` (fail-closed rejection,
   `agent_pool.rs:955-975`).

## Expected Result

- default: ask for Write|Execute|Network|Sensitive via handler.
- full-auto: BypassPermissions allows all tool automation, protected paths
  still deny, and the enable is logged loudly.
- auto-edit / strict behave per their confirmation-required sets.
- Mode changes reach the shared `PermissionService` (mode switch clears the
  approval cache) and future pool agents.

## Deviations

The mode matrix is coherent for primary/pool agents but does not reach
TaskRuntime subagent automation (P1-01) and does not propagate in the CLI
path (P3-01). No other deviation.

## Conclusion

Supports: default/full-auto/auto-edit/strict behave as documented on the
primary and pool-agent paths, protected paths deny even in full-auto, and
mode switches clear the approval cache. Does NOT support: that the matrix
governs subagent automation (P1-01) or that CLI surface propagation matches
GUI/TUI (P3-01).
