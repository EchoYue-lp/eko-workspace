## Claim

TUI reducer terminal handling is symmetric across FinalAnswer/Cancelled/
Error, the parallel task strip is populated by live events, the TurnStatus
arm has a producer in the TUI path, and terminal event fixtures exist for
the TUI reducer (task card: "terminal event fixtures").

## Method

Source inspection of the TUI reducer (inline `match` in
`run_event_loop`, `src/tui/events.rs:602-908`), the sink mapping
(events.rs:2031-2210), the queued-turn dispatcher (events.rs:1476-1484),
the Esc/cancel handler (events.rs:1937-1958), the task-strip state
(`mod.rs:201-218,334,830`; `widgets/task_strip.rs`; `ui.rs:38`), the HITL

`markdown.rs:526+`).

## Expected Result

Cancelled terminal drains queued turns like FinalAnswer and Error; the task
strip receives live task/subagent events; the TurnStatus arm is reachable;
terminal events (FinalAnswer/Error/Cancelled/ToolCall/ToolComplete/
ToolResult/TurnStatus) are replayed through a testable reducer fixture.

## Result

- Exit code: 0 (inspection)
- Summary — observed behavior:
  - Asymmetric terminal handling: `FinalAnswer` (events.rs:657-660) and
    `Error` (:805-843) call `dispatch_next_queued`; `Cancelled`
    (:661-675) does **not** — queued turns stall until the next manual
    Enter after a Cancelled terminal. Currently masked because the
    framework's cancel path never emits `Cancelled` (F-RCT-03-P1-02:
    ReactAgent overrides `cancel_aware_stream`; cancel ends as NoResponse
    Err → Error arm fires → queue drains). Latent P2 (P2-03).
  - Error arm distinguishes user cancel via `active_cancel.is_cancelled()`
    (:805-841): cancelled turns render "Cancelled by user." and never show
    the fabricated envelope error — the TUI does **not** mislabel
    error/cancel terminals the way the GUI does (A-CHAT-01-P1-01 does not
    apply to TUI).
  - `parallel_tasks` (task strip) has zero population sites repository-wide
    (V01-01): dead UI scaffold. `TaskProgressEntry` (mod.rs:201) is never
    constructed. P3 (P3-01).
  - TurnStatus reducer arm (events.rs:880-886) has no producer in the TUI
    path — `ChatDriverEvent::TurnStatus` is constructed only by the GUI
    wrapper (chat.rs:620/656/709) and tests (surface_contract.rs:191).
    Dead arm. P3 (P3-02). Same for the `ChatDriverEvent::Interrupt` arm of
    `TuiChatSink` (events.rs:2045-2053, zero producers — A-CHAT-01-P2-01
    cross-check).
  - Terminal event fixtures: the TUI reducer is an inline `match` inside
    `run_event_loop` (events.rs:602-908); it is not factored into a
    testable function. Existing tests cover helper functions only
    (`parse_interaction_mode`, `handle_esc`, `update_subagent_runs`,
    tool-rendering helpers, markdown). The one event fixture present is
    `subagent_events_update_live_projection` (events.rs:5666-5746), which
    replays SubagentEvent DispatchStarted/ToolStarted/Completed through the
    SubagentRuntimeView projection. No fixture replays AgentEvent terminals
    (FinalAnswer/Error/Cancelled/ToolCall/ToolComplete/ToolResult/TurnStatus)
    through TUI state transitions. P3 (P3-03).
  - HITL: TUI provider is registered (main.rs:250-257), REPL provider
    unregistered in TUI mode — A-HITL-01-P1-02 (REPL EOF auto-approve /
    blocking read) does **not** apply to the TUI path; the TUI provider
    waits for real keys with a 300 s timeout that resolves to
    `HumanLoopResponse::Timeout` (tui_provider.rs:206-222), fail-closed.
    The 'a' approve-all key maps to `ApprovedWithScope { SessionAllTools }`
    (events.rs:242-244) — TUI is one of the four SessionAllTools producers
    of A-HITL-01-P1-03 (cross-check, not re-filed).
  - Pause: /task-pause → `store.request_pause` (events.rs:4345-4355) — the
    same API whose pause-during-wave path silently cancels the run
    (A-TSK-03-P1-01). TUI exposes the identical broken flow (cross-check,
    not re-filed).
