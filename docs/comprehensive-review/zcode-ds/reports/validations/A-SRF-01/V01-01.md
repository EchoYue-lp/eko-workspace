## Claim

TUI capability concepts (drive_chat wiring, ChatSink implementation, reducer,
slash-command surface, task/Subagent projections, parallel task strip,
workspace surface, worker terminology) have exactly one definition each in
the EKO application, and the TUI-vs-GUI capability difference set is
enumerable from definitions alone.

## Method

Repository-wide grep over `echo-agent-cli` (both `src/` and
`echo-agent-app-core/src/`) and `echo-agent`:

```text
# 1. drive_chat call sites
grep -rn "drive_chat" src/ echo-agent-app-core/src/
# 2. ChatSink implementations
grep -rn "impl.*ChatSink for" src/ echo-agent-app-core/src/
# 3. worker terminology in src/tui
grep -rni "worker" src/tui/
# 4. SlashCommand variants defined vs handled
grep -o "SlashCommand::[A-Za-z]*" src/tui/commands.rs | sort -u > all; grep -o "SlashCommand::[A-Za-z]*" src/tui/events.rs | sort -u > handled; comm -23 all handled
# 5. parallel_tasks population sites
grep -rn "parallel_tasks" src/; grep -rn "parallel_tasks.push\|TaskProgressEntry {" src/
# 6. workspace surface in TUI vs GUI
grep -rn "workspace" src/tui/*.rs; grep -n "pub async fn\|pub fn" src/tauri/commands/workspace.rs
# 7. TurnStatus producers
grep -rn "ChatDriverEvent::TurnStatus" echo-agent-app-core/src/ src/
# 8. GUI-only command groups (research/export/task-detail)
grep -rn "export_conversation\|restore_conversation" src/ web-frontend/src -l
grep -rln "list_task_events\|list_task_todos\|list_task_artifacts\|list_task_reviews" src/
```

## Expected Result

One `drive_chat` definition with four live call sites; three production
`ChatSink` impls; zero `worker` terms in TUI; all defined SlashCommand
variants handled; `parallel_tasks` either populated or provably dead;
workspace surface either present or absent in TUI; TurnStatus producers
identified.

## Result

- Exit code: 0 (all greps succeeded)
- Summary:
  - `drive_chat`: one definition (`chat_driver.rs:202`), four live call
    sites — TUI `src/tui/events.rs:2226`, GUI `src/tauri/commands/chat.rs:688`,
    REPL `src/cli/repl.rs:543`, channel `src/cli/channels.rs:262`.
  - `ChatSink` impls: three production (`TuiChatSink` events.rs:2031,
    `TauriChatSink` chat.rs:1341, `ChannelChatSink` chat_driver.rs:585) plus
    one test mock (chat_driver.rs:692). No parallel sink.
  - `worker`: zero hits in `src/tui/`.
  - SlashCommand: all 66 defined variants have a handler arm in events.rs;
    only strum-derived names (`complete`, `iter`) appear unmatched.
  - `parallel_tasks`: referenced only by the layout (`events.rs:586`), the
    state struct (`mod.rs:334`, init `mod.rs:830`) and widgets
    (`ui.rs:38`, `widgets/task_strip.rs:25,31`); **zero push/insertion sites
    in the entire repository** — the task strip projection is never
    populated (dead UI).
  - Workspace: TUI has no workspace surface — no SlashCommand variant
    (commands.rs:58-136), no handler; three TUI comments explicitly state
    "TUI has no workspace concept" (`events.rs:1368`, `:2526`, `:3266`, and
    `:2544` for uploads). GUI has a full command set
    (`src/tauri/commands/workspace.rs:9-235`: list/create/switch/delete/
    link/migrations).
  - `ChatDriverEvent::TurnStatus`: produced only by the GUI wrapper
    (`chat.rs:620,656,709`) and a test (`surface_contract.rs:191`);
    `drive_chat` never emits it, so the TUI's TurnStatus reducer arm
    (events.rs:880-886) is unreachable in the TUI path.
  - GUI-only command groups: conversation export/restore
    (`src/tauri/commands/conversations.rs`, frontend `endpoints.ts`) and
    task detail browsing (`list_task_todos/events/artifacts/reviews`,
    `src/tauri/commands/task_runtime.rs`) have no TUI consumer; research
    workbench commands (`src/tauri/commands/research.rs`, REPL
    `src/cli/cmd_impls/research.rs`) have no TUI equivalent.

## Deviations

None (all expected facts confirmed; the dead `parallel_tasks` strip and the
workspace absence were confirmed as gaps rather than false positives).

## Conclusion

Supports: TUI uses the single shared chat driver and one TuiChatSink; no
second TUI-side chat/task authority exists; TUI is free of `worker`
terminology; the TUI capability gap vs GUI is enumerable (workspace surface,
task-detail browsing, research workbench, conversation export). Supports the
P1-01 workspace finding, the P2 task-introspection and research-workbench
findings, and the P3 dead-strip / dead-TurnStatus-arm findings.
