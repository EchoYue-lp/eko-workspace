## Claim

The TUI entry path registers and reaches the same core services as the GUI:
task tools on the primary agent, AgentPool with the TaskRuntime store,
TaskRuntime execute_run for /task-resume, drive_chat for chat turns, the
TUI HITL provider on the shared dispatcher, and conversation resume.

## Expected Result

TUI boot wires: TaskRuntime store + task tools + pool + HITL provider +
browser runtime + conversation store/id; every chat turn goes through the
shared `drive_chat`; task control flows reach the same `TaskRuntimeStore`
APIs the GUI uses.

## Result

- Exit code: 0 (inspection complete, no commands executed)
- Summary:
  - TUI is the default entry (`main.rs:1-29` module doc, `is_tui_entry`
    default true at main.rs:99-101); headless modes always build a
    TaskRuntime store with boot recovery (main.rs:47-76) and register the
    same task tools as GUI (main.rs:63-84).
  - `dispatch_turn` (events.rs:1341-1436) builds `PreparedUserTurn` via the
    shared `prepared_turn` path (attachments + mode hint + conversation id +
    turn id) and constructs `ChatResources` with pool/store/sink/
    conversation id/attachments/cancel/mode/layer_manager, then
    `send_to_agent` (events.rs:2212-2230) spawns `drive_chat` — same driver
    as GUI (chat.rs:688).
  - Task controls: /task-cancel, /task-pause, /task-resume, /task-recovery,
    /task-retry, /task-skip all reach the shared `TaskRuntimeStore`
    (events.rs:4305-4507); /task-resume additionally re-drives
    `execute_run` (events.rs:4696-4755) with a fresh cancel token registered
    via `store.register_run_cancellation`.
  - Subagent: event-loop subscription to the agent's subagent event bus
    (events.rs:562-564) → `update_subagent_runs` projection (events.rs:5343).
  - HITL: REPL provider is unregistered and the TUI provider registered in
    TUI mode (main.rs:250-257); approval keys y/n/m/a/Enter/Esc handled
    (events.rs:36-260); 'a' maps to `ApprovedWithScope { SessionAllTools }`
    (events.rs:242-244).
  - Resume/attachments/browser/MCP: /resume + /sessions + /fork + startup
    `--resume/--continue` (main.rs:96-147, events.rs:2974-3070, 4818-4918);
    /attach + Ctrl+V paste staging (events.rs:3261-3300, 1510-1597);
    /browser status|managed|chrome on the shared `BrowserRuntime`
    (events.rs:4551-4615); /mcp list|load|disconnect on the agent
    (events.rs:3425-3477).

## Deviations

The TUI has no workspace switching anywhere in the boot or command path
(cross-check of A-CFG-01-P1-03); the GUI's workspace.rs command set has no
TUI counterpart.

## Conclusion

Supports: TUI is a full-surface entry that reaches the same application
services as the GUI — shared drive_chat, TaskRuntime store/tools/execute_run,
HITL dispatcher, browser runtime, conversation persistence; the pause path
is the same `request_pause` API (so A-TSK-03-P1-01 applies to TUI), and the
approval 'a' key is one of the SessionAllTools producers (A-HITL-01-P1-03).
Supports all findings' reachability claims.
