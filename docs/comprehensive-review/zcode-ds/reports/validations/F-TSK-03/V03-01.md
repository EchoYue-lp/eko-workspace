Scenario-by-scenario analysis:

1. **Stale claim / stale attempt**: EKO `claim_task` requires revision +
   Pending + exact spec (`store.rs:996-1009`); `set_claimed_task_status`
   and `requeue_claimed_task` require Running + exact claim else
   `Superseded` (`store.rs:1048, 1081`); `task_claim_is_current`
   (`1107-1122`) guards the completion path (`executor.rs:1458, 1518`);
   framework maps `Superseded` to a no-op (`runtime_executor.rs:423-426`)
   so a late/stale write can never overwrite a newer state. Attempt
   identity: `claim.attempt = retry_count + 1`; execution id
   `{run}:{task}:{rev}:{attempt}` (`executor.rs:174-179`) separates
   durable results per attempt (`store.rs:2039-2079`).
2. **Cancellation**: loop-top check (runtime_executor.rs:207-209);
   in-wave biased select with `cancellation_grace_period` then
   `abort_all` + drain (390-412); completed siblings resolved before the
   run returns Cancelled (416-447) — no replayed siblings after resume;
   EKO `interruption_outcome` returns Paused when run status is Paused
   (executor.rs:1595-1613); run-cancel finalizes all unfinished todos to
   Cancelled (`finalize_cancelled_run_state` 643-660). Gap found: a
   non-cooperative dispatch aborted after the grace period is never
   resolved — its claim stays Running (part of P2-01's family; EKO boot
   recovery `store.rs:1631-1774` is the only reset).
3. **Failure propagation**: `blocked_by_failures`
   (runtime.rs:461-478) -> `block_task("blocked: upstream task failed")`
   (runtime_executor.rs:239-244); EKO retry-unblock walks dependents by
   matching that exact string (`store.rs:1292`) — string-literal
   cross-repo contract confirmed identical (F-TSK-02-P2-01). A single
   `Cancelled` resolution sets the run outcome to Cancelled
   (runtime_executor.rs:435-439) and any Cancelled task in a snapshot
   aborts the run (267-269) — run-level semantics that contradict EKO's
   per-task-cancel comment (P2-02).
4. **Revision reload**: safe-point revalidation
   (runtime_executor.rs:211-230); claim conflicts return
   `ReloadSnapshot` (not failure) and the task re-enters the frontier
   (356-358); mid-run plan append handled (`insert_after` test);
   EKO test `claim_reloads_when_task_update_wins_revision_race`
   (store.rs:3060) verifies the same CAS.
5. **Stall**: ready empty + in_flight empty + no Blocked task ->
   `note_stalled` + `Failed("<none>", "DAG stalled ...")`
   (runtime_executor.rs:287-313). No unit test hits this branch; the
   mid-DAG skip case (F-TSK-02-P1-01) lands here
   (`ready_task_ids` requires `completed` deps, runtime.rs:449-455);
   `from_tasks` leaves `Paused` unclassified (runtime.rs:353-391), so a
   Paused snapshot would also stall with the misleading message (P3-02).
6. **Per-task controller fault mid-wave**: closure `?` on permit/claim
   (runtime_executor.rs:348-354) -> `return Err` at 379-381 aborts the
   run, dropping the JoinSet (aborting sibling dispatches) with their

   (executor.rs:537-541); a same-process retry then polls externally
   forever (`runtime.rs:359-363` in_flight + runtime_executor.rs:276-285)
   — only boot recovery resets (P2-01).
7. **F-TSK-02 cross-checks**: P1-01 (skip stall) re-verified via
