## Claim

The intent router is registered on the agent and is reachable from both ReAct
entry points (streaming and non-streaming), and EKO wires a live classifier
into the primary agent used by `drive_chat`.

## Method

Static call-graph trace (read-only inspection). Steps:

```text

2. builder.rs:1037-1039 build() -> agent.intent_router = Some(router)
3. react/mod.rs:226 field intent_router; :1489-1492 set_intent_router
4. react_loop.rs:622-682  run_react_loop: classify() before run_core_loop spawn

```

## Expected Result

Registration chain `builder -> ReactAgent.intent_router -> both run entries`;
EKO main agent carries both the router and a pre-model projector.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - Registration: confirmed at all anchors in step list.
  - Reachability: both `run_react_loop` (non-streaming, via `direct.rs:23,42`
    `ReactAgent::run`/`chat`) and `run_stream_channel` (streaming, via
    `react/mod.rs:1839,1860`) call `router.classify(...)` on every turn when
    `intent_router` is `Some`. Actions: `DirectAnswer` + shortcut enabled
    (`allows_direct_answer_shortcut()`), `SkillRequired` ->
    `activate_skill` (`capabilities.rs:964-997`), `Fallback` -> ReAct.
  - EKO: `runtime.rs:294-356` builds `KeywordClassifier` from skill
    descriptors (`agent_handle.read(skill_descriptors())`), optional
    `LlmIntentClassifier` from the agent LLM client, `TriggerSupervisor` with
    the agent's `hook_activation_cache` slot, wrapped in `IntentRouter`
    (threshold 0.7, both shortcuts enabled), set on the same `AgentHandle`
    used by `drive_chat`. EKO chat turns therefore execute the classifier.
  - EKO main agent always has a pre-model projector (`infra.rs:446-450`), so
    `allows_direct_answer_shortcut()` is always `false` there: the
    DirectAnswer ACTION arm is unreachable in EKO; `SkillRequired` and
    `Fallback` arms are live.
  - Subagents and agent-pool agents do not receive a router (no callers).
