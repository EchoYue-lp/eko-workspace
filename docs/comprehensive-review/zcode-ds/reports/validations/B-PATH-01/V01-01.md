## Claim

The live entry points are exactly: (1) `echo-agent-cli` binary via
`src/main.rs` (TUI by default, CLI and channels as flags), (2)
`echo-agent-tauri` binary via `src-tauri/src/main.rs` (gui feature) and (3)
the same desktop runtime reached from `src/main.rs` in a gui-only build —
all of which assemble shared services through
`AgentRuntime::bootstrap`, with no other reachable `fn main` or startup
constructor.

## Method

1. Read `src/main.rs` (571 lines) in full; read `src-tauri/src/main.rs`;
   read `src/tauri/desktop.rs` (271 lines) in full.
2. Traced feature-based dispatch in `main`:
   `gui+no-tui` → desktop; `tui` → `run_tui_or_cli_entry`; `channels+no-gui+
   no-tui` → `run_tui_or_cli_entry`; none → `compile_error!`.
3. Traced the mode selection inside `run_tui_or_cli_entry`
   (`is_tui_entry = args.tui || (!args.web && !args.cli && !args.channels)`),
   `--cli` → `run_cli_mode`, `--channels` → `run_channels_mode`,
   `--web` → hard exit with removal message.
4. Confirmed `run_tui_or_cli_entry` calls
   `AgentRuntime::bootstrap` (main.rs:167-168) and `run_desktop` calls the
   same (`desktop.rs:159-160`).
5. Grepped both binary roots and `src-tauri` for any second `fn main`.

## Expected Result

- Two binaries; one desktop runtime shared by both; single shared bootstrap;
  three interactive modes (TUI/CLI/channels) + one desktop mode.
- `compile_error!` when no mode feature is enabled.
