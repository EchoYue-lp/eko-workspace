## Claim

Composition roots: `AgentRuntime::bootstrap` (app-core runtime.rs) is the
single shared agent-initialization path; `AppState::from_shared` is the GUI
state root; `start_headless_services` (cli/modes.rs) is the TUI/CLI
background-services root; `run_channels_mode` is the IM root. TaskRuntime
store construction and task-tool registration happen post-bootstrap in each
entry (documented in bootstrap's own comment).

## Method

1. Read `echo-agent-app-core/src/runtime.rs` in full (728 lines) —
   `AgentRuntime::bootstrap` steps 0-13 and `init_pool`.
2. Read `echo-agent-app-core/src/state.rs:419-719` — `AppState` fields,
   `from_shared`, `start_scheduler_with_store`, `start_task_service`.
3. Read `src/cli/modes.rs:32-80` (`start_headless_services`) and
   `:107-205` (`run_channels_mode`).
4. Traced every service constructor and its entry-point call sites.

## Expected Result

- bootstrap builds: runtime state store, browser runtime, primary agent +
  prompt assembly, MCP config, compressor, AgentHandle, HITL dispatcher

## Deviations

The TaskRuntimeStore fallback+recover logic and the task-tool registration
pair are duplicated across entries (three files: main.rs, state.rs via
AppState, desktop.rs). This is recorded as `B-PATH-01-P2-02` (divergence
risk), not a deviation of the inventory claim.

## Conclusion
