## Expected Result

All four modes reachable via `agent_tool` (LLM) and via programmatic delegation
(TaskRuntime); EKO injects all three factories; team definitions reachable from
EKO frontmatter and plugins; isolation paths consumed only by Fork.

## Result

- Exit code: not-applicable (static trace)
- Duration: n/a
- Summary:
  1. `agent_tool` is registered by EKO on the main agent (`infra.rs:288`) and
     plugin agents (`:930, :1008`, `plugin_runtime.rs:1471`); its schema exposes
     `mode` enum `["sync","fork","teammate","team"]` (`agent_dispatch.rs:414-418`).
  2. All four `DispatchRequest` paths flow into the single `dispatch()` loop,
     which owns `DispatchStarted`, terminal `DispatchCompleted/DispatchFailed/
     DispatchCancelled`, retry/delegation, and hooks for every mode.
  3. Sync/Fork/Teammate derive a child cancellation token from `req.cancel`
     (`executor.rs:1486, 1671, 879`) and race cancel-vs-timeout-vs-execution
     with a biased `select!` (cancel checked first). Team (`dispatch_team`)
     passes no token to `TeamAgent` and never checks `req.cancel`.
  4. Timeout sources: Sync/Fork/Teammate = `definition.timeout_secs > 0 ? def :
     executor.default_timeout_secs` (`executor.rs:1475-1478, 1569-1573, 891-895`);
     Team = `TeamConfig.default_timeout_secs` from the `TeamSpec` (EKO always
     `TeamConfig::default()`, 600 s) with a 60 s floor at `team/mod.rs:345`.
  5. Worktree/workspace isolation is consumed only by `dispatch_fork`
     (documented in `types.rs:181-210` and enforced by the mode-forcing at
     `agent_dispatch.rs:244-252`); Team members run as shared registry
     singletons (`ArcAgentBox`, `executor.rs:1020-1068`) with no isolation.
  6. `dispatch_team` builds `TeamAgent` with `run_id` + `runtime_state_store`
     (`executor.rs:1038-1043`) — EKO supplies a `FileRuntimeStateStore`
     (`infra.rs:434-437`) so checkpoint/resume is production-reachable.
  7. Team-mode definitions are production-reachable via EKO subagent frontmatter
     (`subagent_loader.rs:454-487`) and plugin definitions
     (`plugin_components.rs:481-514`).
- Log/artifact: none.

## Deviations

- Team mode is the only mode without cancellation wiring (P1-01) and without
  the executor/definition timeout knobs (P2-01).
- `max_concurrent_forks` semaphore is consumed only by Fork
  (`executor.rs:1555-1560`); Teammate/Sync/Team never acquire it.

## Conclusion

Supports: one unified dispatch lifecycle with four reachable mode routers;
EKO production wiring is complete for all modes including Team; isolation
factories are genuinely consumed; the reachability claims in the P1/P2 findings
hold. Does not prove lifecycle behavior under cancel/timeout/failure — covered
by V03.
