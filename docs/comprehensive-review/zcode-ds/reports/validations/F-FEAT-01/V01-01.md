## Claim

For every feature declared in the eight framework manifests, all `#[cfg(feature = "...")]` / `#[cfg_attr(docsrs, doc(cfg(feature = "...")))]` code references are enumerated; no cfg references an undeclared feature; the set of declared-but-zero-code-reference features is exactly identified (including the 13 marker features).

## Method

1. Read all eight manifests' `[features]` sections (root `echo-agent/Cargo.toml:65-103`; `echo-core/Cargo.toml:21-28`; `echo-execution/Cargo.toml:21-24`; `echo-integration/Cargo.toml:21-25`; `echo-tools/Cargo.toml:15-37`; `echo-state/Cargo.toml:21-22`; `echo-orchestration/Cargo.toml:21-23`; `echo-macros/Cargo.toml` — no features section).
2. Per crate, collect distinct `feature = "..."` strings from every `cfg(...)` / `cfg_attr(...)` attribute in `src`, `tests`, `examples`, `benches`:
   `grep -rhoE 'feature\s*=\s*"[a-z0-9-]+"' <dirs> --include='*.rs' | sort -u`
   plus targeted greps for `cfg(feature`, `cfg_attr(feature`, `cfg!(feature`.
3. Diff each crate's referenced set against its declared set (undeclared-reference check).
4. For each of the 13 marker features (handoff/topology/tasks/project-rules/eval/improve/testing/sandbox/semantic-memory/macros/provider-factory/workflow/multimodal), grep the whole repository for `feature = "<name>"` in `.rs` files and for manifest references (`required-features`, `[features]` edges, docs.rs metadata).
5. Inspect `echo-agent/src/lib.rs` module declarations to determine which marker modules are gated vs always compiled.

## Expected Result

- Every referenced feature exists in the referencing crate's own `[features]`; zero undeclared references.
- The 13 markers split into: (a) markers with real code gates despite `= []` manifests, (b) markers with zero code references anywhere.
- No `cfg!(feature = ...)` runtime checks and no `CARGO_FEATURE_*` env usage in the framework.
