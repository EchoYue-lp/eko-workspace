## Claim

Every optional dependency (`dep:xxx`) is referenced only by code gated by the feature that enables it (or by an always-compiled module whose feature is forced on); no code compiles references to an optional crate when its enabling feature is off (no missing-gate leakage).

## Method

1. For each optional dependency in each manifest, collect the enabling feature(s) and grep the owning crate's `src` for crate-name usage.
2. Verify each usage site is inside a `#[cfg(feature = "<enabler>")]`-gated module or a gated `cfg` block.
3. Specifically checked: root optional deps (axum, jsonwebtoken, opentelemetry\*, rusqlite, sqlx, polars, scraper, html2text, url, pdf-extract, lopdf, calamine, docx-rs, encoding_rs); echo_core (reqwest, regex, globset); echo_tools (scraper, html2text, url, async-trait, pdf-extract, lopdf, calamine, chrono, rust_xlsxwriter, docx-rs, encoding_rs, tree-sitter\*, polars, sqlx, quick-xml, uuid); echo_integration (tokio-tungstenite, axum); echo_state (rusqlite); echo_orchestration (tokio-tungstenite).

## Expected Result

All optional-crate usage is confined to the gating feature's code. No optional crate is referenced by ungated code in a way that would fail compilation when the feature is disabled.

## Result

- Root: axum/jsonwebtoken only in `src/a2a/` (module gated at `src/lib.rs:69-71`); opentelemetry crates only in `src/telemetry.rs` (gated `src/lib.rs:98-100`); rusqlite only in `src/state/sqlite.rs` (module gated at `src/state/mod.rs:291-296`); scraper/html2text/url/polars/sqlx/pdf-extract/lopdf/calamine/docx-rs/encoding_rs have ZERO usage in root code (the root features still declare them as `dep:` — redundant with the same deps declared in echo_tools, see V02/P3-03).
- echo_core: regex only in `guard/{content,llm,rule}.rs` (gated `guard/mod.rs:3-7`); globset only in `tools/permission.rs:262-264` (gated at :262); reqwest only at `error.rs:396-398` (gated). Ungated `pub mod guard;` (`echo-core/src/lib.rs:27`) compiles without regex because the gated submodules are the only regex users.
- echo_tools: chrono only in `excel.rs:608` (media-gated); async-trait only in `web/` (`web/search.rs:249,276`, `web/providers/*`); url only in `web/`; uuid only in `rag.rs`; tree-sitter only in `files/repo_map.rs` (files-gated); quick-xml only in `research/`; polars only in `data.rs`/`statistics.rs`/`data_quality.rs`; sqlx only in `database.rs`; all per-module gates verified in `echo-tools/src/lib.rs:20-65`.
- echo_integration: axum only in `channels/channels/feishu/webhook.rs` (channels-gated); tokio-tungstenite in `channels/channels/qq/gateway.rs`, `channels/channels/feishu/long_poll.rs` (channels) and `mcp/server.rs` (mcp) — all within feature-gated modules (`echo-integration/src/lib.rs:16-26`).
- echo_orchestration: tokio-tungstenite only in `human_loop/websocket.rs` (gated `human_loop/mod.rs:61,84`).
- echo_state: rusqlite only in `memory/sqlite_conversation.rs`, `memory/sqlite_store.rs` (gated `memory/mod.rs:23,47-49`), `util.rs:3,23` (gated).
- Special case — root `src/tools/mod.rs` ungated re-exports `pub mod files { pub use echo_tools::files::*; }` (:58-59) and `pub mod shell { pub use echo_tools::shell::*; }` (:78-79): these compile only because echo_tools' files/shell features are forced on by echo_execution's defaults (V05). This is not a missing gate on an optional dep; it is an always-on feature invariant (finding F-FEAT-01-P2-01).
- `src/tools/builtin/spawn_task.rs:262-264` correctly falls back to an inline classifier when `shell` is off (:270+), so `tasks` without `shell` compiles.

None.

## Conclusion

Supports: no optional-dependency leakage — every optional crate is referenced only inside its enabling feature's code. The only leak-like pattern is the reverse direction: gated features (`files`/`shell`) whose code is always compiled because of echo_execution defaults and ungated facade re-exports.
