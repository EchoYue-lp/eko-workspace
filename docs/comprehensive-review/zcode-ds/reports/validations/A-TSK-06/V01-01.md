## Claim

Review, acceptance/check, artifact, summary, compact-context, and memory-bridge
concepts have exactly one live definition each across both repositories — no
parallel authority — and every production definition is distinguished from
registered-but-unreachable lookalikes.

## Method

Repository-wide `grep -rn` over both `echo-agent` and `echo-agent-cli` for the
following terms (searched by name and by neighboring naming style), then
classification of each hit as production-caller / test-only / dead:

- Review: `review_task`, `requires_review`, `circuit_breaker_action`,
  `build_fix_task`, `run_review_gate`, `ReviewResult`, `ReviewGateOutcome`,
  `reviewer_llm`, `list_reviews`, `LlmCritic`, `set_critic`, `verifier`.
- Acceptance/check: `acceptance_criteria`, `execution_checks`,
  `required_artifacts`, `assess_task_execution`, `verification_matches`,
  `artifact_matches`, `SubagentVerification`, `Observed`.
- Summary: `TaskExecutionSummary`, `put_summary`, `get_summary`,
  `collect_dependency_summaries`, `format_execution_summary`, `Summarize`,
  `dependency_summaries`, `summary_chain`.
- Compact context: `TaskRuntimeContextProjector`, `PreModelContextProjector`,
  `task_runtime_projection_registry`, `install_task_context_protection`,
  `RUNTIME_RECOVERY_MARKER`, `TASK_CONTEXT_MARKER`.
- Memory bridge: `write_memory_candidate`, `MemoryEvent`, `MemoryPolicy`,
  `MemoryLayerManager`.
- Artifacts: `Artifact`, `ArtifactProduced`, `add_artifact`, `list_artifacts`,
  `SubagentArtifact`, `observed_artifacts`, `ToolOutputArtifactRef`,

- Thinking: `ThinkingDelta`, `reasoning_content`, `in_thinking`, `ThinkStart`.

## Expected Result

One live review gate (EKO `review.rs` consumed by `executor.rs`), one summary
authority (`TaskExecutionSummary` + `put_summary`/`get_summary`), one capsule
projector (EKO `compact_context.rs`), one memory chokepoint
(`MemoryLayerManager` via `memory_bridge.rs`), and a clean framework/EKO
boundary where the framework supplies primitives (`TaskSpec` carries
`execution_checks`/`acceptance_criteria` as data; `SubagentResult`/`SubagentOutcome`
carry result/verification/artifacts) while EKO applies policy.
