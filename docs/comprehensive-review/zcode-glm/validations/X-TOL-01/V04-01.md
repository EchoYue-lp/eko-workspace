## Claim

cancellation, and partial side effect — has at least one end-to-end test
that drives a tool result of that classification through the full
framework → `AgentEvent` → EKO projection → frontend store path, so that
a regression in field preservation, terminal-reason mapping, or
projection identity is caught. Failing that, each family has at least a
unit test at every individual layer that asserts the field-level
contract, with the gap between layers explicitly documented.

## Conclusion

Fails V04. The four edge-case families are covered at the framework batch
layer (F-RCT-04) and partially at the EKO TaskRuntime store layer
(`tool_failure_boundary_persists_recovery_contract`, with a single-field
assertion only), but no end-to-end fixture drives any of them through
the full framework → EKO → frontend projection. The `PartialSideEffect`
case — the most safety-critical because it carries the
`verify_before_retry` semantic — has the weakest assertion coverage:
the only persistence test checks `failure.category` and ignores
`recovery`, `side_effect`, and `postcondition`. This is filed as
X-TOL-01-P2-03.

The validation does NOT refute the field-preservation claims of V01/V02:
static inspection shows the fields are forwarded losslessly on the
failure path. The defect is the absence of a regression-catching test,
not an observed field loss.
