## Claim

The TypeScript contract for IPC DTOs is guarded by either (a) ts-rs
generation directly from the Rust serde model, or (b) a fixture /
snapshot / round-trip test that fails when the wire shape and the TS
type drift. The set of generated types is internally consistent
(no orphaned or shadowed files).

## Deviations

The combination of (1) orphaned generated files, (2) shadowed nominal
types where the manual and generated disagree, and (3) no contract
tests, means the V01 drift (specifically `ToolInfo.parameters` vs
`tool.input_schema`) went undetected at compile time on both sides and
at test time on either side. The ts-rs setup creates the *illusion* of
a compiler-checked contract for the types it exports, but the contract
is real only for the task-runtime family (which is the only place the
frontend actually consumes `generated/` directly — `endpoints.ts:49-59`
imports `TaskRun/TaskPlan/...` from `generated`).

## Conclusion

Supports the V04 claim with caveats: ts-rs generation exists and is
correct for the task-runtime types that are consumed via `generated/`,
but the wider contract is manual-only and unguarded. Five orphaned
generated files (notably `SubagentRun`) are dead weight, and three
shadowed nominal types create a trap where importing the wrong module
silently produces the wrong shape. No regression test would catch
another `parameters`/`input_schema`-class drift.
