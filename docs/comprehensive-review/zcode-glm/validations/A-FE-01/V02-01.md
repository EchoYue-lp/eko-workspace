## Claim

Every Rust enum variant that crosses the IPC boundary has a
corresponding TypeScript string-literal (or object-literal discriminant)
variant. No enum variant is silently dropped, renamed, or invented on
either side; tag/discriminator conventions (`#[serde(tag = ...)]`,
`rename_all = "snake_case"`) line up between Rust and TS.

    A-FE-01-P3-05.**

## Deviations

The drift in `SubagentRunEventKind` is benign at runtime (the dead
`artifact` branch in the reducer is unreachable, so no incorrect
state transition occurs), but it is undocumented contract drift — a
future backend change that emits `event: "artifact"` would land in an
untested code path. The `McpConnectionStatus` drift is masked because
the manual TS is the live contract.

## Conclusion

Supports the V02 claim with two caveats: enum coverage is complete for
all ts-rs-generated task-runtime types and for the manual `ChatEvent` /
`ToolExecution*` / `Evidence*` types, but the manual
`SubagentRunEventKind` carries a dead `artifact` variant, and the
generated `McpConnectionStatus` (along with `SkillInfo`/`McpServerInfo`)
misrepresents the wire because the corresponding Rust structs are
unused by the Tauri command path.
