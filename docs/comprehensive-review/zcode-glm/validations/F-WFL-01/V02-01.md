## Claim

`Graph::build()` performs meaningful structural validation at build time
(missing entry, unknown edge endpoints, duplicate outgoing edges, parallel
targets/then existence) and `DagWorkflow::build()` additionally performs
cycle detection; however `Graph` **intentionally does not** detect cycles
(loops are a feature) and **does not** validate conditional-edge targets
(opaque closures returning arbitrary node names at runtime). These two gaps
are documented/observable but the conditional-target gap is a real
validation hole for declarative workflows.

## Method

Static inspection of both builders' `build()` paths plus the runtime
node-resolution path, cross-checked against the unit tests.

```text
Read echo-agent/echo-orchestration/src/workflow/graph.rs (lines 430-526 build(),
         595-725 run(), 1372-1416 resolve_next(), 1428-1933 tests)
Read echo-agent/echo-orchestration/src/workflow/dag.rs (lines 255-297 build(),
         334-431 topological_sort + detect_cycle)
Read echo-agent/src/workflow/loader.rs (lines 179-281 build_graph, 236-267 edge loop)
```

## Expected Result

- `Graph::build()` rejects: missing entry, unknown entry, unknown edge
  `to` (non-`__end__`), unknown parallel targets/then, and multiple
  outgoing edges from one node.
- `Graph::build()` does NOT detect cycles (by design — `test_loop_graph`
  exercises a cycle).
- `Graph::build()` does NOT and cannot validate conditional-edge return
  values (they are `Box<dyn ConditionFn>` returning `String` at runtime).
- `DagWorkflow::build()` DOES detect cycles (it is a DAG).
- A declarative YAML workflow with a condition pointing at a typo'd node
  builds successfully and fails only at runtime.

      (`:1686-1708`) locks this.
    - Three more build-time tests lock missing entry, unknown entry,
      unknown edge target (`:1658-1683`).
  - **`EdgeKind::Conditional` is NOT validated at build time**
    (`:457-485`, the `_ => {}` arm at `:484` skips it). The condition is a
    `Box<dyn ConditionFn>` whose `evaluate(&SharedState) -> String` returns
    an arbitrary node name only at runtime. `resolve_next` then does
    `NextStep::Single(target)` and `run()` looks up
    `self.nodes.get(&current).ok_or_else(... Node not found ...)`
    (`:650-655`). So a condition returning an unregistered name fails at
    runtime with `Node 'X' not found in graph`, not at build.
  - **Declarative impact confirmed** (`loader.rs:236-267`): the YAML/JSON
    loader turns an `edge.condition.then` / `else_node` pair into a
    conditional-edge closure that returns whatever strings the YAML
    author wrote. `GraphBuilder::build()` cannot see inside the closure.
    A typo in `then: fnalize` (instead of `finalize`) passes build and
    fails mid-run. This is the practical hole.
  - **No cycle detection in `Graph`** — by design. `test_loop_graph`
    (`:1529-1569`) builds `increment -> increment` via a conditional edge
    and asserts the loop runs to completion, bounded only by `max_steps`
    (default 100, `:513`; `set_max_steps` at `:569-572`;
    `MaxIterationsExceeded` at `:613-622`). Cycles are a first-class
    feature (conditional loops power `writing_pipeline`'s revise loop,
    `writing_pipeline.rs:369-408`).
  - **`DagWorkflow::build()` DOES enforce acyclicity** (`dag.rs:255-297`):
    unknown edge endpoints rejected (`:258-275`);
    `detect_cycle` (DFS, `:372-431`) + `topological_sort` (Kahn's,
    `:334-369`) both run; a cycle surfaces as a typed
    `AgentError::InitializationFailed`. Tests `test_cycle_detection` and

    sort already detects cycles when `order.len() != nodes.len()`
    (`:360-366`), so cycles are detected twice. Minor inefficiency.
  - **Asymmetry:** `Graph` (cycles allowed, conditional targets unchecked)
    vs `DagWorkflow` (cycles forbidden, no conditional edges at all — the
    DAG builder exposes only `edge(from, to)`, `dag.rs:246-252`). The
    asymmetry is consistent with each flavor's contract but is not called
    out in the module docs.

## Deviations

None. All claimed validations are present; both gaps (no cycle detection

## Conclusion

`Graph::build()` validates the statically-knowable structure (entry,
endpoints, fan-out targets, single outgoing edge). Two intentional gaps
remain: (1) no cycle detection — a feature, bounded by `max_steps`; (2)
conditional-edge targets are opaque and unchecked until runtime — a real
validation hole for declarative workflows, where a typo'd `then`/`else`
node name passes build and fails mid-execution. `DagWorkflow::build()` is
stricter (enforces acyclicity) but supports no conditional edges.

Supports findings F-WFL-01-P2-01 (two graph flavors with asymmetric
validation) and F-WFL-01-P2-03 (conditional-edge target not validated).
