## Claim

The workflow engine (`echo-orchestration::workflow`) is a **static, ahead-of-time
pipeline/graph orchestration API** that is semantically distinct from the
dynamic, agent-driven, revisioned task system (`echo-orchestration::tasks`,
audited in F-TSK-01). There is no overlap in mutation authority, store
contract, or tool surface, and no workflow code references the task model.

## Method

Repository-wide structural inventory of both subsystems plus a one-way
reference search (workflow → task) to confirm the absence of coupling.

```text
Read echo-agent/echo-orchestration/src/workflow/mod.rs (engine surface)
Read echo-agent/echo-orchestration/src/tasks/revisioned.rs (task authority, via F-TSK-01)
grep -rn "TaskRevision\|TaskSpec\|RevisionedTaskGraph\|task_create\|task_update\|task_list" \
    --include="*.rs" echo-agent/echo-orchestration/src/workflow/
grep -rn "register_workflow\|WorkflowTool\|workflow_tool\|GraphBuilder::\|run_data_pipeline\|run_writing_pipeline" \
    --include="*.rs" echo-agent/ echo-agent-cli/  (registration + live callers)
```

## Expected Result

- Workflow module exports only static topology types (`Graph`,
  `SequentialWorkflow`, `ConcurrentWorkflow`, `DagWorkflow`, prebuilt
  pipelines, checkpoints, `SharedState`).
- Zero references from workflow code to `TaskRevisionService` /
  `RevisionedTaskStore` / `TaskSpec` / `task_create|update|list`.
- Workflow is not registered as an agent tool (it is a programmatic API +
  declarative YAML/JSON loader, not a runtime agent-callable CRUD).
- The two subsystems are clearly distinct in layering and authority.

## Deviations

None for the workflow-vs-task claim. The two subsystems are cleanly
distinct in authority, store contract, and tool surface.

One observation that does not affect the claim: the workflow module
internally hosts two parallel graph implementations (`Graph` +
`DagWorkflow`); their coherence is evaluated under V02/V03, not here.

## Conclusion

The workflow engine is a coherent **static orchestration** API and is
semantically distinct from the **dynamic task** system. There is no shared
mutation authority, no store coupling, and zero code references from
workflow to task. The framework layering is clean at this boundary:
workflow = embedder-defined topology executed by the framework; tasks =
agent-created revisioned plan. Supports the task report's primary positive
conclusion (distinct APIs) and feeds the internal-coherence findings
F-WFL-01-P2-01 (two graph flavors) and F-WFL-01-P2-02 (parallelism
asymmetry).
