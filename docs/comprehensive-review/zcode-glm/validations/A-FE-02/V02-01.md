## Claim

The projection reducers handle duplicate events, out-of-order events,
and old-attempt completion correctly — with one exception
(tool-execution live ingest, A-SRF-03-P2-01 confirmed). Specifically:
(a) the subagent terminal lock drops late/duplicate terminals and a
late `started` cannot reopen a terminal; (b) old-attempt completion
is structurally isolated by the per-attempt key and cannot corrupt
the current attempt; (c) task-runtime generation counters suppress
stale loads/refreshes; (d) tool-execution live ingest is a direct
overwrite with no status-rank guard (the exception, untested via the
live entry point).

## Expected Result

- Subagent `ingest`: after a terminal status (`completed` / `failed`
  / `timed_out` / `cancelled`), any subsequent event for the same
  `storeKey` is dropped (`if (prev && prev.status !== 'running')
  return s`). A late `started` after terminal cannot reopen. A
  duplicate terminal is a no-op. Old attempt completion lands on the
  old attempt's key (already terminal) and is dropped; the current
  attempt is untouched.
- `latestSubagentRunsByTask`: for a given `(runId, taskId)`, the
  highest attempt number wins. A late terminal for a lower attempt
  does not change the selection (the higher attempt is still higher).
- TaskRuntime `refresh` / `loadByConversation`: a `set` whose
  captured generation != current generation is suppressed. Polling
  overlap is prevented by `refreshInFlight`.
- Tool-execution live `ingest`: direct overwrite by `tool.id`. NO
  status-rank guard — the exception.

## Deviations

One finding:

The tool-execution live `ingest` overwrite (A-SRF-03-P2-01) is
confirmed from the projection-identity angle. The V01 dual-identity
analysis explains WHY: the live path keys by `tool.id` (a single
slot per id) and overwrites unconditionally, while the merge path
dedupes by `executionIdentity` and applies status-rank. When a live
`started` arrives after a terminal for the same `tool.id`, the
terminal is clobbered. The merge path would prevent this
(`mergeToolExecution` returns the terminal when ranks differ), but
the live path does not call it.

The test gap (A-FE-02-P3-03) means this regression is not caught by
the current suite. The merge-path tests are sometimes mistaken for
live-path coverage because they test the same monotonicity property,
but they exercise a different entry point.
