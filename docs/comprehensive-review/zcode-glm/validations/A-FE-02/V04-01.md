## Deviations

The claim is falsified in three ways (the three findings):

1. **A-FE-02-P2-01**: `listReviews` is never called. The reviewer's
   detailed verdict (issues, severity, reasoning) is invisible in
   the GUI. A user staring at a `blocked` task with "评审未通过"

2. **A-FE-02-P3-01**: `execution_checks` / `acceptance_criteria` are
   never displayed for existing tasks. The user cannot see what
   hard-evidence checks or acceptance criteria were declared for a

3. **A-FE-02-P3-02**: Verification `source` (observed/reported) is
   rendered as a raw technical label. The evidence-strength
   distinction that the backend's two-gate design centers on is
   under-exposed.

## Conclusion

The claim is NOT supported. The backend two-gate separation
(A-TSK-06 V02: hard-evidence `execution_checks` first, reviewer-judged
`acceptance_criteria` second, disjoint fields, strictly ordered) is
only PARTIALLY projected to the frontend:

- The binary OUTCOME of the acceptance gate (did the task pass
  review?) surfaces via the persisted todo status and the
  `todoStatusDescription` label ("评审未通过"). This is correct and
  the persisted status is authoritative.
- The EVIDENCE behind the gate (what the reviewer found, which
  issues, what severity) is never fetched (`listReviews` has zero
  callers). The `ReviewResult` type is dead weight in the frontend.
- The DECLARED checks/criteria on PlanTask are never displayed.
- The per-check evidence STRENGTH (observed vs reported) is rendered
  without semantic distinction.

For the EKO positioning (a supervised local task system), this means
a user deciding whether to retry a blocked task cannot see the review
issues — they must act blind or dig into the raw
`~/.eko/tasks/{run_id}/events.jsonl`. The hard-evidence gate's
results ARE partially visible (via `SubagentResultView.verification`),
but even there the observed/reported distinction is not interpreted.

Findings that use this validation:

- A-FE-02-P2-01 (reviewer verdict never fetched) — V04 is the
  primary evidence.
- A-FE-02-P3-01 (declared checks/criteria never displayed) — V04
  confirms zero component readers.
- A-FE-02-P3-02 (verification source under-exposed) — V04 confirms
  the raw-label rendering.
