## Expected Result

- `InlineToolCall` renders only a one-line summary when collapsed.
  Detail (manifest + output chunks) is fetched ONLY when expanded.
- Output is paginated via `readOutput(detail_ref, cursor)` returning
  `{chunks, next_cursor, complete}`. The component accumulates
  chunks and stops when `complete === true`.
- While running and expanded, auto-refresh every 500 ms fetches the
  next page, PAUSING when accumulated text >= 256 KiB
  (`LIVE_DETAIL_AUTOLOAD_CHARS`). A notice explains the pause.
- On terminal status change (expanded), a one-shot refetch retrieves
  the final page.
- A manual "load more" button is available when not complete and
  (running is false OR live-loading is paused).
- The output container is `max-h-96 overflow-auto`, bounding the
  rendered DOM height.
- `manifest.truncated` surfaces an "Agent 上下文已截断" label.
- Subagent and task-runtime event logs are capped (300/run, 500
  total) to prevent unbounded memory growth on long-running tasks.
- `SubagentResultView` lists are bounded by backend caps (no
  frontend pagination needed).

## Deviations

None. The lazy-output design is coherent and well-bounded.

<50) and is A-FE-03 territory (frontend performance), not a
projection-correctness issue.
