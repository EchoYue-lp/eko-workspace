## Claim

The subagent system prompt and invocation are assembled by a single prompt
compiler with bounded, cache-stable sections; parent context inheritance is
explicit, filtered, and bounded. The registration-time `compile_system` and
the dispatch-time `compile_invocation` are both wired into the live path.

## Method

implementation, and the executor's call sites. Cross-checked against the
`ContextInheritance` presets and the `ParentContextFactory` to determine
how much parent context reaches the subagent.

## Expected Result

(1) `compile_invocation` is called on every dispatch mode (Sync/Fork/Teammate/Team).
(2) `compile_system` is called at registration or first dispatch to produce
    the subagent's role system prompt.
(3) History inheritance is bounded by a numeric cap and filters out
    tool/reasoning turns.

## Result

- Exit code: not-applicable (static inspection)
- Summary:

### Dispatch-time invocation compiler — LIVE

`SubagentExecutor::compile_invocation` (`executor.rs:1117-1145`) is the single
funnel. It selects `ContextTransferPolicy::InheritStructured` only when
`mode == Fork` AND `parent_context.messages` is non-empty; otherwise `Fresh`.
It then calls `self.config.prompt_compiler.compile_invocation(...)` passing
`agent_name`, `task`, `mode`, `transfer_policy`, `parent_context`,
`inherit_history`, `payload`, and `constraints`.

Call sites:
- `dispatch_sync` (`executor.rs:1485`) — always called.
- `dispatch_fork` (`executor.rs:1580`) — always called.
- `dispatch_teammate` (`executor.rs:881`) — always called.
- `dispatch_team` (`executor.rs:1073`) — always called.

All four modes route through `compile_invocation`. The default compiler
(`DefaultSubagentPromptCompiler`, prompt.rs:107-147) produces:
- `task_input`: the raw task, or task + `[constraints]...[/constraints]` block
  when constraints are present.
- `history`: `filter_history(context.messages, inherit_history)` when
  `InheritStructured`, else empty.

### Registration-time system prompt compiler — DEAD

`compile_system` is declared on `SubagentPromptCompiler` (`prompt.rs:97-99`)
and implemented by `DefaultSubagentPromptCompiler` (`prompt.rs:108-118`, which
returns `input.role_prompt` verbatim). **Grep across the whole `echo-agent`
workspace returns zero production callers** — only the trait declaration, the
default impl, and a test stub (`executor.rs:1920`). The subagent's actual
system prompt is whatever the pre-built `Box<dyn Agent>` instance carries in
its own `AgentConfig.system_prompt`; the definition's `system_prompt` field
and the compiler's registration-time output never reach the agent.

The supporting types `SubagentSystemPromptInput` (`prompt.rs:47-61`) and
`CompiledSubagentSystemPrompt` (`prompt.rs:64-68`) are likewise unused outside
the trait/default/test surface.

### History filter — bounded and provider-safe

`filter_history` (`prompt.rs:149-187`) drops:
- context-projection messages (`is_context_projection_message`);
- tool-call messages (`tool_call_id` set or non-empty `tool_calls`);
- reasoning-content messages (non-empty `reasoning_content`);
- non-User/Assistant roles;
- empty text and `[runtime_context:`-prefixed runtime injection.

The numeric cap: `Some(n)` with `n > 0` keeps the last `n` messages after
filtering (`prompt.rs:182-186`); `None` keeps all filtered; `Some(0)` is
treated as "no limit" (filtered out by `.filter(|max| *max > 0)`).

### How much parent context is inherited

Two filtering passes occur for Fork mode:

1. **`ParentContextFactory::build`** (`agent_dispatch.rs:51-54`) calls
   `SubagentContext::from_parent(...)` with `ContextInheritance::fork_default()`
   (`context.rs:74-81`): `inherit_history = Some(2)`, `inherit_memory = true`.
   `from_parent` (`context.rs:254-260`) slices `all_messages` to the last `n`
   via `saturating_sub(n)`.
2. **`compile_invocation`** (executor.rs:1117-1145) then calls the compiler's
   `compile_invocation`, which runs `filter_history(context.messages, ...)`
   on the already-sliced set. The definition's `inherit_history` (not the
   mode preset) is passed here (`executor.rs:1481-1485`).

Net effect: Fork inherits at most the last 2 parent turns (mode preset cap),
further narrowed by the definition's `inherit_history` if smaller, and always
sanitized of tool/reasoning/projection turns. Sync/Teammate/Team default to
`Fresh` — zero inherited messages, but `parent_goal` (latest real user
request) is still extracted by `from_parent` (`context.rs:297-311`) so the
subagent sees the user's intent without the transcript.

The transfer is bounded: no unbounded history, no system-prompt transfer as
user text (the `from_parent` doc explicitly notes "Parent system prompts are
never transferred as user text," `context.rs:26-27`), and memory inheritance
is a boolean flag (full store reference or none — no partial filtering).

### `Some(0)` semantics mismatch

The two consumers of `inherit_history` interpret `Some(0)` differently:
- `filter_history` (`prompt.rs:182`): `Some(0)` = no limit (inherit all).
- `SubagentContext::from_parent` (`context.rs:254-260`): `Some(0)` =
  `saturating_sub(0)` = len → `get(len..)` = empty (inherit nothing).
- `SubagentDefinition.inherit_history` doc (`types.rs:150`): claims
  `Some(0)` = inherit all (matches `filter_history`, NOT `from_parent`).

The definition's field is consumed by `filter_history` on the live path, so
the doc is correct for the executor path; but the same-named
`ContextInheritance.inherit_history` field (which feeds `from_parent`) has
the opposite `Some(0)` behavior and no doc noting the difference.

- Log/artifact: none.

## Deviations

1. `compile_system` being dead means the `SubagentSystemPromptInput.environment`
   field (intended for "OS/arch facts that do not change per dispatch,"
   `prompt.rs:55-60`) is also dead — no caller populates it and no consumer
   reads it. This was clearly designed for product compilers to inject static
   grounding; the design is sound but unwired.
2. The double-filtering of history (mode preset in `from_parent`, then
   definition field in `filter_history`) is redundant for Fork but not
   harmful — the mode preset's `Some(2)` is the tighter bound, so the
   definition's value can only narrow further or match. A definition with
   `inherit_history = Some(10)` still gets only 2 (the mode preset wins at
   pass 1).

## Conclusion

The claim is **partially supported**. `compile_invocation` is fully wired and
the history envelope is bounded and provider-safe. **`compile_system` is
dead** — the registration-time system-prompt compilation path (trait method,
input/output structs, default implementation) has zero production callers.
This feeds F-SUB-01-P2-02. The `Some(0)` semantics mismatch feeds
F-SUB-01-P3-02.
