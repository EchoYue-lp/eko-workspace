## Claim

Subagent results flow back to the parent as a single structured message: one
JSON `SubagentOutcome` carrying a runtime-owned terminal status, bounded
fields, and hydrated artifact integrity facts. The model cannot lie about
completion, and all string fields are UTF-8-safe bounded. Lifecycle events
carry the same outcome to observers.

## Expected Result

(1) `parse_subagent_outcome` ignores any model-reported `status` and uses the
    runtime-supplied status exclusively.
(2) All variable-length fields are char-bounded (no byte truncation).
(3) Artifact paths are hydrated with bytes + sha256 when the file exists,
    flagged `available: false` when not.
(4) The synchronous dispatch returns one `ToolResult::success(json)` to the
    parent — single message.
(5) `DispatchCompleted`/`Failed`/`Cancelled` carry the same `SubagentOutcome`.

## Result

- Exit code: 0 (all five tests pass)
- Duration: ~0.05s
- Summary:

### Runtime owns terminal status

`parse_subagent_outcome` (`types.rs:456-532`) accepts the terminal `status`
as a parameter (`SubagentStatus`, supplied by the executor). The model's
reported `status` field is parsed into `ReportedSubagentOutcome.status`
(`types.rs:401-417`) but annotated `#[allow(dead_code)]` and **never read** —
the returned `SubagentOutcome.status` is always the runtime-supplied value
(`types.rs:470`). Verified by
`structured_result_ignores_model_status_and_hydrates_artifact`: a model JSON
claiming `"status":"completed"` with runtime `SubagentStatus::TimedOut`
yields `outcome.status == TimedOut`.

### Verification source is downgraded

Any model-claimed `source: "observed"` is rewritten to `Reported`
(`types.rs:478-486`). Only runtime-observed tool events may create
`Observed` evidence — the model cannot self-certify. Verified by the same
test (`outcome.verification.first().source == Reported`).

### UTF-8-safe bounding

All variable-length fields use `chars().take(N)` (`bounded_text`,
`types.rs:552-554`), never byte slicing:
- `summary`: `DEFAULT_SUMMARY_CHARS = 1200` (`types.rs:245, 564, 475`).
- `remaining_work` / `verification.check` / `details`: `MAX_DETAIL_CHARS = 500`.
- `artifacts[].path`: `MAX_PATH_CHARS = 2048`.
- `artifacts[].kind`: `MAX_KIND_CHARS = 80`.
- Every list: `MAX_RESULT_ITEMS = 64` via `keep_latest` (drain from front)
  or `bounded_unique` (dedupe + cap).

Verified by `structured_result_bounds_utf8_evidence`: 70 Chinese-string
items collapse to 64, each ≤ 500 chars; a 3600-char Chinese summary
collapses to exactly 1200 chars. `split_output_truncates_utf8_safely_without_heading`
confirms the fallback path is also UTF-8-safe.

### Artifact hydration

`hydrate_artifacts` (`types.rs:600-632`) resolves each path against
`working_dir`, stats the file, and sets:
- `bytes` from `metadata.len()` when it is a regular file;
- `sha256` via streaming hash (`hash_file`, `types.rs:634-647`, 64 KiB buffer);
- `available = sha256.is_some()`;
- `producer_execution_id` stamped from the execution id.
Non-existent / non-file paths get `available = false`, `bytes = None`,
`sha256 = None`. Verified by the hydration test (sha256 len == 64,
`available == true`, `producer_execution_id == "task-1:1"`).

### Single-message parent return

`serialize_parent_result` (`agent_dispatch.rs:13-17`) is
`serde_json::to_string(outcome)`. The synchronous dispatch success arm
(`agent_dispatch.rs:336-344`) returns `ToolResult::success(json_string)` —
exactly one tool-result message to the parent LLM. Background dispatch
returns a different one-message shape (`{status, execution_id, agent_name}`,
`agent_dispatch.rs:309-316`) and delivers the full outcome later via the
`DispatchCompleted` event.

`render_result_contract` (`types.rs:386-399`) documents the model-facing
envelope: `## Result` heading + fenced JSON with the exact shape. The
round-trip test confirms a rendered contract parses back to
`contract_version == 1`.

### Event coherence

`DispatchCompleted` (`events.rs:64-83`) carries `result: SubagentOutcome`;
`DispatchFailed` (`events.rs:85-100`) carries `result: SubagentOutcome` with
a terminal status and remaining work; `DispatchCancelled`
(`events.rs:102-113`) carries the cancelled outcome. All three share the
same `SubagentOutcome` shape the parent receives via the tool result — one
contract, three terminal channels. The executor emits exactly one terminal
event per `DispatchStarted` (`executor.rs:584-608` for completed/cancelled,
`:767` for failed), with `output` (full text) alongside `result`
(structured) so observers can render either.

## Deviations

1. The legacy fallback path (`contract_version == 0`, `types.rs:505-526`)
   fires when the model did not emit a valid `## Result` JSON block. It
   falls back to `split_subagent_output` (markdown `## Summary` / `## Artifacts`
   extraction, or UTF-8-safe 1200-char truncation). This is correct but
   means a subagent that ignores the result-contract prompt still produces a
   parent-facing summary — graceful degradation, not a bug.
2. `SubagentResult` (`types.rs:662-687`) wraps `SubagentOutcome` plus
   `output` (full text), `duration`, `iterations`, `tokens_used`,
   `was_truncated`, `mode`, `isolation_observed`, `usage`. This is the
   executor-internal record; only `outcome` is serialized to the parent
   tool result. The full `output` reaches observers only via the
   `DispatchCompleted.output` event field. This is intentional (the parent
   LLM gets the bounded contract; the UI gets the full text) but means the
   parent tool result and the event payload are not field-identical.

## Conclusion

The claim is **supported**. The result protocol is a single-message
structured JSON return with runtime-owned status, UTF-8-safe bounded fields,
hydrated artifact integrity, and model self-certification blocked. The
event channel carries the same outcome shape. This matches the Claude Code
single-tool/single-message-return pattern well.
