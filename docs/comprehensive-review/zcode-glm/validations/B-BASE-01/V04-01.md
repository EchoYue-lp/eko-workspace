## Claim

CI workflows in both repositories enforce the mandatory submission gates
described in AGENTS.md, but do NOT run the conditional matrices (feature,
GUI, frontend).

## Method

Read-only comparison of both `.github/workflows/rust-ci.yml` files against
the AGENTS.md "提交前门禁" and "条件矩阵" sections.

```text
1. Read echo-agent/.github/workflows/rust-ci.yml in full
2. Read echo-agent-cli/.github/workflows/rust-ci.yml in full
3. Read AGENTS.md sections "提交前门禁" (echo-agent + echo-agent-cli)
4. Read AGENTS.md sections "条件矩阵"
5. Map each CI step to the corresponding AGENTS.md gate
6. Identify gates present in AGENTS.md but absent from CI
```

## Expected Result

CI should run at minimum the mandatory pre-commit gate for each repo.
Conditional matrices are documented as "CI/专项审计兜底" backstops — they
may be absent from CI but their absence is a coverage gap.

## Result

- Exit code: 0
- Summary: Both CIs run the mandatory gate (fmt, clippy, test, no-default
  check). Neither CI runs any conditional matrix. Frontend is entirely
  uncovered in echo-agent-cli CI.

### echo-agent CI (`rust-ci.yml`)

| CI Job | Steps | AGENTS.md equivalent |
|---|---|---|
| lint | `cargo clippy --workspace --all-targets --all-features --locked -D warnings` | ✓ mandatory gate |
| test (8-matrix) | `cargo test -p <pkg> --lib --tests --all-features --locked` | ⚠ uses `--lib --tests`, not `--all-targets` (finding P3-01) |
| minimal | `cargo check -p echo_core --no-default-features --locked` | ✓ (partial: only echo_core, not all crates) |

**Missing from CI**: per-feature standalone compile loop (`for feature in sqlite
subagent ...`), doctest execution.

### echo-agent-cli CI (`rust-ci.yml`)

| CI Job | Steps | AGENTS.md equivalent |
|---|---|---|
| ci | `cargo fmt --all -- --check` | ✓ |
| | `cargo clippy --workspace --all-targets --all-features --locked -D warnings` | ✓ |
| | `cargo test --workspace --all-features --locked` | ✓ |
| | `cargo check -p echo-agent-app-core --no-default-features --locked` | ✓ |

**Missing from CI**:
- GUI matrix: `cargo check --no-default-features --features gui --bin echo-agent-tauri`
- GUI tests: `cargo test --no-default-features --features gui`
- Frontend: `npx prettier --check`, `npm test`, `npm run build`
- SQLite absence verification: `grep -rn "sqlite" echo-agent-cli/*/Cargo.toml`
- Panic-safety Clippy: the `-D clippy::unwrap_used` lint configuration

### CI platform coverage

Both CIs run on `ubuntu-latest` only. The product targets macOS (Tauri).
macOS-specific `rustflags` in `.cargo/config.toml` are unexercised (finding P3-03).

## Deviations

1. The echo-agent test job uses `--lib --tests` per-package instead of
   `--all-targets`. Examples and benches are compiled by the lint job (clippy)
   but their `#[test]` functions are not executed.
2. echo-agent-cli CI installs Tauri system dependencies (lines 23-30) but
   never builds the GUI target. This is wasted CI setup.
3. No `Cargo.lock` freshness check beyond `--locked` (which fails if the lock
   file doesn't match the manifest, but doesn't verify it's committed).

## Conclusion

Both CIs enforce the mandatory non-conditional submission gate. The conditional
matrices documented in AGENTS.md ("条件矩阵") are entirely absent from CI,
creating a coverage gap where feature-isolation, GUI, and frontend regressions
can merge undetected. This is documented as finding B-BASE-01-P2-04.

The `Q-FW-02`, `Q-GUI-01`, and `Q-WEB-01` tasks must exercise these matrices
locally since CI does not.
