## Claim

Every `[features]` definition in both repositories can be mapped to the
optional dependencies, `cfg`-gated sub-crate features, and `dep:` activations
it enables. The CLI never enables the framework `sqlite` feature, satisfying
the `AGENTS.md` "echo-agent-cli 不需要 SQLite" invariant. The frontend
`package.json` exposes the documented scripts and key dependencies.

## Method

Read-only extraction of `[features]` and `[dependencies]` blocks from all 10
`Cargo.toml` files plus `echo-agent-cli/web-frontend/package.json`. Feature
lists produced with `awk '/^\[features\]/{f=1;next} /^\[/{f=0} f && /^[a-zA-Z]/'`.

```text
1. For each Cargo.toml, extract [features] and optional deps (entries with `optional = true`).
2. Map each feature to its activated `dep:` and `<crate>/<feature>` entries.
3. Confirm which features echo-agent-cli enables on echo-agent (grep 'echo-agent/' in cli manifests).
4. Read web-frontend/package.json in full.
```

## Deviations

Three observations that are not failures for this validation but are
recorded for downstream tasks:

1. **`@tailwindcss/vite` appears in both `dependencies` and `devDependencies`**
   (`package.json:16` and `package.json:32`) with different version specifiers
   (`^4.1.4` vs `^4.1.8`). This is a duplicate entry; npm will pick one.
   Forwarded as finding `B-BASE-01-P3-02`.
2. **`full` includes `data` but `[package.metadata.docs.rs]` excludes it**
   with a documented polars nightly incompatibility
   (`echo-agent/Cargo.toml:59-63`). `data` is a known-fragile feature on
   nightly toolchains. Relevant to `Q-FW-02` / `F-FEAT-01`.
3. **`echo_core` `reqwest` and `permission` features are hard-enabled by the
   root `echo_agent` dependency declaration** (`Cargo.toml:106`), not by the
   `default` feature. So `echo_core` is never actually built with a truly
   empty feature set inside this workspace. `F-FEAT-01` should recheck
   `echo_core` standalone isolation.
