## Claim

`ProviderCapabilities` lets every provider express the same protocol-level
feature set, and the streaming path is neutral: a `BoxStream<'static,
Result<ChatChunk>>` carries content, reasoning, tool-call deltas, finish
reason, and usage uniformly across OpenAI-compatible, Anthropic, and Ollama
providers, with a single cancellation hook.

## Method

Static inspection of `echo-core/src/llm/capabilities.rs` (full file) plus the
two streaming implementations and the shared transport.

```text
Read echo-agent/echo-core/src/llm/capabilities.rs (lines 1-778)
Read echo-agent/echo-integration/src/providers/client.rs (stream_post, lines 179-260)
Inspect OpenAi/Anthropic chat_stream bodies for chunk assembly + cancel handling
```

## Expected Result

All capability fields populated for each preset; streaming chunks assembled to
the same `ChatChunk` shape; cancellation observed on both provider paths.

## Result

- Duration: n/a
- Summary:

    populated for each preset — `streaming_tool_calls`, `named_sse_events`,
    `reasoning_content`, `image_input`, `system_as_top_level`,
    `ndjson_streaming`, `tool_support`, `structured_output`,
    `requires_version_header`, `supports_parallel_tool_calls`,
    `supports_tool_choice_none`, `tokenizer_name: Option<&'static str>`.
  - **Three presets**:
    - `openai_compatible()` (`:76-91`): streaming tool calls, bare SSE, reasoning,
      images, parallel tools, tool_choice_none.
    - `anthropic()` (`:94-109`): no streaming-tool-call deltas (uses block
      events), named SSE events, `system_as_top_level`, version header,
      `supports_tool_choice_none: false`, `structured_output: false`,
      `reasoning_content: false` (comment: "not mapped in this implementation").
    - `ollama()` (`:112-127`): NDJSON streaming, no images, no structured
      output, no parallel tools.
  - **`from_provider_name`** (`:130-136`): routes `anthropic`/`ollama`, defaults
    everything else to `openai_compatible()`.
  - **Streaming neutrality** — both providers converge on `ChatChunk`:
    - OpenAI (`openai.rs:325-375`): wraps `ChatCompletionChunk`, maps each
      `ChunkChoice` to `ChatChunk { delta, finish_reason, usage }`. Usage rides
      the final usage-only chunk (parsed because of the `null`-delta deserializer).
    - Anthropic (`anthropic.rs:424-626`): consumes named SSE events
      (`MessageStart`, `ContentBlockStart`, `ContentBlockDelta`,
      `ContentBlockStop`, `MessageDelta`) and emits the same `ChatChunk` shape,
      accumulating tool-call args and emitting them on `ContentBlockStop`;
      final `MessageDelta` carries accumulated usage. Input/cache tokens
      captured at `MessageStart` (`:512-518`), output tokens at `MessageDelta`
      (`:584-588`).
  - **Cancellation**: single field `ChatRequest::cancel_token:
    Option<CancellationToken>` (`mod.rs:175`). Shared transport `stream_post`
    checks `ct.is_cancelled()` between SSE chunks (`client.rs:252-254`) and
    breaks iteration. Anthropic also checks inline in its own loop
    (`anthropic.rs:482-484`) because it does not use `stream_post`. Both paths
    terminate cleanly on cancel.
  - **`ModelProfile` + resolver** (`:144-373`): higher-level wrapper that
    combines capabilities with model-specific knowledge (context window,
    max output tokens, thinking protocol, tokenizer). `ModelProfileResolver`
    supports provider-default and exact-model overrides; tested at `:724-776`.

## Deviations

- **Anthropic reasoning output is not surfaced** (`capabilities.rs:98`,
  `reasoning_content: false`). In the streaming path, every Anthropic
  `ChatChunk.delta.reasoning_content` is `None`
  (`anthropic.rs:541,566,611`), and in the non-streaming path the response
  `Message.reasoning_content` is `None` (`anthropic.rs:335`). The contract
  type can carry it; the adapter does not populate it. The Anthropic
  `ContentBlock` enum (`anthropic.rs:829-862`) has no `Thinking` variant, so
  thinking content blocks hit the `_ => {}` catch-all (`:308`) and are
  silently dropped. This is primarily an adapter implementation gap
  (deferred to F-LLM-03), but it means the streaming contract is observably
  non-uniform today: an OpenAI reasoning model streams `reasoning_content`
  deltas, an Anthropic model does not. See finding F-LLM-01-P2-01.
- `supports_tool_choice_none` is `false` for Anthropic and Ollama
  (`:107,124`). The contract still accepts `tool_choice` on the request;
  providers that do not support `none` must drop it themselves. No framework
  guard rejects it up front — acceptable for a thin contract but worth noting.

## Conclusion

Capability negotiation is complete and uniformly typed; the streaming chunk
contract is identical in shape across providers and cancellation is wired
through one neutral field checked on both transport paths. The one material
non-uniformity is that Anthropic does not emit `reasoning_content` even though
the contract supports it — this is an adapter-level gap that downstream task
F-LLM-03 must close, but it is surfaced here because the task asks whether
providers *can* preserve thinking losslessly, and today the Anthropic path
demonstrates observable loss.
