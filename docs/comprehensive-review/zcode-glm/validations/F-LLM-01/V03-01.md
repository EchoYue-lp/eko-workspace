## Claim

The thinking-config contract lets every provider translate the same semantic
knob to its native wire format, and the usage/cache contract has a single
normalization authority: `Usage` methods compute effective tokens, cached
tokens, and cache hit rate consistently across OpenAI, Anthropic, and
DeepSeek response shapes.

`echo-core/src/llm/cache/` (mod, layout, diagnostic), and the `Usage` block in
`types.rs`. Cross-checked the translation functions against the

      `GlmReasoningEffort`. `emits_field()` (`:301-312`) returns false for

    - Documented depth-knob reality (`thinking.rs:18-22`): GLM-4.5/4.6 and Kimi
      only have on/off; a user picking "high" is faithfully translated but has
      no extra effect. This asymmetry is documented, not hidden.
  - **Usage authority** — single normalization site (`types.rs:686-771`):
    - `effective_prompt_tokens()` (`:693-702`): adds back Anthropic
      `cache_read` + `cache_creation` when either is present, because Anthropic
      `input_tokens` excludes them; OpenAI/DeepSeek `prompt_tokens` already
      includes cached tokens so no adjustment.
    - `effective_total_tokens()` (`:705-715`): recomputes from
      `effective_prompt_tokens + completion_tokens` when Anthropic fields are
      present, otherwise trusts provider `total_tokens`.
    - `cached_prompt_tokens()` (`:724-736`): priority chain
      `prompt_tokens_details.cached_tokens` → `input_tokens_details.cached_tokens`
      → `cache_read_input_tokens` (Anthropic) → `prompt_cache_hit_tokens`
      (DeepSeek). Returns 0 when none present.
    - `cache_creation_prompt_tokens()` (`:739-750`): same chain for writes.
    - `cache_hit_rate()` (`:764-771`): `cached / effective_prompt_tokens`,

## Deviations

- `Message::reasoning_content: Option<String>` is the response-side thinking
  channel. It carries the reasoning *text* but cannot carry Anthropic's
  per-block encrypted `signature` (`thinking.signature`), which Anthropic
  requires to be replayed unchanged in a subsequent turn's request when
  interleaving thinking with tool use. The contract therefore supports
  thinking *observation* universally but not thinking *round-trip* for
  Anthropic. See finding F-LLM-01-P2-02.
- `ChatPolicy`/`CachePolicy.recommended_stable_prefix_tokens` values
  (`capabilities.rs:513,536,547,558`) are provider presets; there is no
  per-model override hook on `CachePolicy` (unlike `ModelProfileOverride`
  which covers capability fields). Minor; not a correctness issue.

## Conclusion

Thinking translation is a clean single-knob → multi-protocol design with
faithful per-vendor translators and accurate capability gating. Usage
normalization is the single authority and is well tested for all three cache
reporting conventions. The one contract-level limitation is that
`reasoning_content: Option<String>` cannot represent Anthropic's signed
thinking blocks for round-tripping — observable as a P2 finding.
