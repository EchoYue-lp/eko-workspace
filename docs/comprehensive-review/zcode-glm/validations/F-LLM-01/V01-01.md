## Claim

The provider-neutral LLM contract (`LlmClient`, `ChatRequest`, `ChatResponse`,
`ChatChunk`, `Message`, `ContentPart`, `ToolDefinition`, `Usage`, streaming
types) is defined once in `echo-core/src/llm`, carries typed fields for every
contract dimension (messages, tools, thinking, usage, caching, streaming,
cancellation, errors), and has no duplicate public definition of the same
semantics elsewhere in the workspace.

## Method

Static inspection. Read `echo-core/src/llm/mod.rs` and `echo-core/src/llm/types.rs`
in full, enumerated every public type and field, then grepped both repositories
for duplicate definitions of the core contract types.

```text
Read echo-agent/echo-core/src/llm/mod.rs (lines 1-242)
Read echo-agent/echo-core/src/llm/types.rs (lines 1-1280)
grep -rn "trait LlmClient"   echo-agent/ echo-agent-cli/ --include=*.rs
grep -rn "struct ChatRequest" echo-agent/ echo-agent-cli/ --include=*.rs
grep -rn "^pub struct Message " echo-agent/ echo-agent-cli/ --include=*.rs
```

## Deviations

- `ChatRequest::tool_choice` is `Option<String>` (`mod.rs:162`), not
  `Option<ToolChoice>`. The typed `ToolChoice` enum (`mod.rs:114-146`) exists
  for safe construction and converts via `to_openai_value()`, but the request
  itself stores the OpenAI wire string. The contract is therefore
  OpenAI-wire-shaped for this field; Anthropic translates it in its own request
  builder. See finding F-LLM-01-P3-01.
- `Message::reasoning_content` is a flat `Option<String>` (`types.rs:251`).
  It cannot carry Anthropic's per-block encrypted `signature` needed to replay
  thinking blocks in later turns. See finding F-LLM-01-P2-02.

## Conclusion

The neutral contract is singly defined, typed, and covers every dimension the
task asks about: messages (`Message`/`MessageContent`/`ContentPart`), tools
(`ToolDefinition`/`ToolCall`/`ToolChoice`), thinking (`ThinkingConfig` on the
request + `reasoning_content` on response/delta), usage (`Usage` with 9 fields
and normalization helpers), caching (`CacheHints`/`CachePolicy`), streaming
(`chat_stream` returning `'static` `BoxStream` of `ChatChunk`), cancellation
(`cancel_token`), and errors (`LlmError`). No duplicate definition exists.
Supports V02, V03, V04. Used by findings F-LLM-01-P3-01 (stringly-typed
tool_choice) and F-LLM-01-P2-02 (reasoning_content cannot carry signature).
