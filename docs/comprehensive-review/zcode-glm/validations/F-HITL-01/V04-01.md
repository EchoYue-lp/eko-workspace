## Claim

protected-path primitives without imposing EKO interaction policy. The
generic-vs-EKO boundary is clean: every policy decision that is
specific to the local-assistant product (which providers exist, how
they arbitrate, what the UI looks like) lives in `echo-agent-cli`; the
framework defines only the typed model, the composing service, the
extension traits, and universally-safe defaults (protected paths).

## Conclusion

Supports the task's primary answer: **yes, the framework provides
generic automated-action approval and protected-path primitives without
imposing EKO interaction policy, and the boundary is clean.**

Layering classification:

| Component | Layer | Rationale |
|---|---|---|
| `ToolPermission`, `PermissionMode`, `PermissionDecision`, `RuleRegistry` (deny-first), `PermissionPolicy` trait | framework (`echo-core`) | Typed model any consumer needs; referenced from Claude Code (B-REF-01). No product coupling. |
| `PermissionService`, `PermissionServiceConfig`, `SessionApprovalCache`, `ProtectedPathChecker`, `Classifier` trait, `RuleClassifier`/`LlmClassifier` | framework (`echo-orchestration`) | Composing service + extension points + universally-safe defaults. Configurable (mode, rules, cache TTL, protected patterns, classifier). No EKO coupling. |
| `HumanLoopProvider` trait, `HumanLoopManager`, `PermissionRequestHandler` trait, `DynProviderHandler` | framework (`echo-orchestration`) | Extension seams. `DynProviderHandler` is a thin, lossless `HumanLoopResponse`↔`PermissionResponse` bridge with no state authority. |
| `HitlDispatcher`, `ReplHumanLoopProvider`, `TuiHumanLoopProvider`, `channel_provider`, Tauri provider | application (`echo-agent-cli`) | EKO product policy: which providers exist, how they arbitrate (parallel first-responder-wins), the 5-min deadline, the fail-closed UX. Implements the framework trait; owns no permission decision. |
| React `ApprovalCard`, `permissionModes`, `chatEventHandler` | application (`echo-agent-cli/web-frontend`) | UI rendering of approval requests emitted by the application provider. |

The one boundary observation (not a defect): `ProtectedPathChecker`
ships default patterns in the framework. This is correct layering under
AGENTS.md — preventing unintended loss of `.git`/secrets is
"本地也成立的通用安全", the checker is configurable, and the behavior
matches Claude Code (B-REF-01 C4). It does not impose an EKO
*interaction* policy.

AGENTS.md security-boundary compliance:

- The threat model is local (no multi-tenant/公网 exposure); the
  framework does not apply a web-service threat model. No
  `require_full_auto` gate remains on user-interactive tools.
- `PermissionMode` governs agent automated paths; interactive terminal
  / file picker bypass it (they are not tool-pipeline calls).
- User-extensible capabilities (MCP, skills) are wired through the same
  provider trait; the framework does not second-guess user config.
