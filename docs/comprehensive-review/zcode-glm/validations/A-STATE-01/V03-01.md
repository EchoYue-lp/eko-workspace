## Claim

A conversation saved via Tauri `save_conversation` and reloaded via
`get_conversation` / `restore_conversation` round-trips all
event types (text, tool calls, tool results, thinking segments,
attachments) without loss, AND the save sequence is safe under two
concurrent calls.

The "inconclusive" verdict applies to the round-trip half (executable
confirmation needed) and the "failed" half applies to the concurrency
claim.

## Expected Result

- All four canonical roles (system/user/assistant/tool) round-trip with
  text, tool calls, tool results, reasoning_content, name, and
  tool_call_id preserved.
- UI metadata (`thinking_segments`, `execution_steps`, `execution_rounds`,
  `attachments`, `message_id`) is preserved across save/load on the
  frontend projection path.
- Two concurrent `save_conversation` calls for the same id both persist
  their messages.

## Result

- Exit code: 0
- Duration: ~10 min code + test read
- Summary:
  - **Canonical projection is lossless** for the four canonical roles.
    Framework `project_message`/`restore_message`
    (`echo-state/src/memory/conversation.rs`) preserves role, text
    content, structured `MessageContent::Parts`, `reasoning_content`,
    `name`, `tool_call_id`, and `tool_calls` (`tool_calls_json`) /
    tool-role `tool_call_id`+`name` (`tool_result_json`). The
    `projection_round_trips_empty_content_and_message_identity` test
    (conversation.rs:206-219) and F-MEM-01 V04-01's
    `round_trip_messages_via_project_and_restore`
    (file_conversation.rs:654) confirm.
  - **Tauri `get_conversation` returns the UI metadata intact**
    (`src/tauri/commands/conversations.rs:473-531`). It calls framework
    `get_messages` then extracts `message_id`/`display_content`/
    `thinking_segments`/`execution_steps`/`execution_rounds`/`attachments`
    via `AttachmentsPayload::parse`, which accepts both the modern object
    form and the legacy plain-array form (persistence.rs:127-145).
    Frontend sees the same fields it saved.
  - **Tauri `restore_conversation` does NOT restore UI-only fields to the
    agent runtime** (`src/tauri/commands/conversations.rs:680-724`).
    Framework `restore_messages` only reads canonical fields +
    `_echo_message_version` envelope (`conversation.rs:169-191`). On the
    very first save of a turn where no canonical transcript exists yet,
    `project_saved_messages` writes a non-canonical record
    (`has_canonical_transcript = false`) and the UI fields
    (`thinking_segments`, `execution_rounds`) are not readable by
    `restore_message`. The agent's `Message.reasoning_content` ends up
    empty after restore even though the frontend still shows the thinking
    text. This is finding P3-02.
  - **Concurrency**: the Tauri save path is `get_conversation` →
    `update_conversation` → `get_messages` → `project_saved_messages` →
    `save_messages`, with each framework call independently acquiring the
    in-process `Mutex<StoreMeta>`. There is no per-conversation
    application-level lock spanning the sequence. Two concurrent
    `save_conversation` calls for the same id race: both read the same
    baseline, both call `save_messages`, and the framework replaces
    `record.messages` wholesale on each call
    (`file_conversation.rs:370`), so the second writer silently wins.
    This is finding P3-01. No executable test pins the concurrent
    behavior in either direction.

## Deviations

- The framework `Mutex<StoreMeta>` only guarantees each individual
  `ConversationStore` operation is atomic, not multi-operation
  transactions. The Tauri command treats the non-atomic sequence as if
  it were transactional.
- The frontend typically serializes saves itself, so the race is latent
  rather than frequently hit; this is why P3-01 is P3 and not P1.

## Conclusion

- **Round-trip half (inconclusive — needs executable confirmation).**
  Static evidence says the canonical projection is lossless and the UI
  metadata is preserved for the frontend; the gap is that UI-only
  reasoning does not reach the agent runtime on `restore_conversation`
  (P3-02). An executable test should pin the no-canonical-transcript
  branch end-to-end (save → reload → restore_messages → assert
  `reasoning_content`).
- **Concurrency half (failed).** Two concurrent saves of the same
  conversation silently drop one batch of messages because the framework
  replaces `record.messages` wholesale. The frontend happens to
  serialize today, so impact is low; recorded as P3-01.

Supports findings: P3-01 (Tauri save_conversation non-atomicity),
P3-02 (UI-only reasoning lost on agent restore).
