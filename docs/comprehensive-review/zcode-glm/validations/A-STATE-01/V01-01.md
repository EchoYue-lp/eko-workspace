## Claim

The conversation persistence format is a single framework-owned JSON-per-
conversation authority; the application's `Persistence` and
`SessionSearchEngine` types are constructed but never invoked in
production, indicating dead duplicate authority.

## Expected Result

Two parallel storage authorities (`Persistence`, `SessionSearchEngine`)
overlap with the framework `FileConversationStore`. The framework is the
authority actually called by every Tauri/TUI persistence operation. The
application types should have zero production callers if they are dead
code.

## Result

- Exit code: 0
- Duration: <2s for greps, ~10 min for full code read
- Summary:
  - **Framework authority is the only live path.**
    `infra.rs:1215-1231 create_conversation_store` builds
    `FileConversationStore` rooted at `~/.eko/`. `state.rs:363, 494` stores
    it in `StorageState.conversation_store: RwLock<Option<Arc<dyn ConversationStore>>>`.
    All eight Tauri commands and TUI `/rename`, `/delete-session`,
    `/search` acquire this `Arc`.
  - **On-disk format** (`file_conversation.rs:42-46, 168-175, 494-523`):
    one JSON file per conversation at
    `<base>/conversations/<safe_id>.json` containing
    `{conversation, messages}`, plus `_meta.json` id counter. `atomic_write`
    uses uuid-suffixed temp + fsync + rename + parent-dir fsync.
  - **`Persistence` is dead.** Public methods `save_session` (persistence.rs:211),
    `load_session` (242), `list_sessions` (247), `export_conversation_markdown`
    (286), `load_conversation` (321) — grep across `echo-agent-cli/src` and
    `echo-agent-app-core/src` returns hits only inside `persistence.rs`
    itself and inside tests. The struct is instantiated in `state.rs:495, 894, 1058`
    (workspace switch) but no method is ever invoked. The Markdown export
    used by the Tauri `export_conversation` command is built inline in
    `src/tauri/commands/conversations.rs:643-677` and does not call
    `Persistence::export_conversation_markdown`.
  - **`SessionSearchEngine` is dead.** `state.rs:496-506` constructs it and
    calls `reindex_all()` once. Grep for
    `app_state.storage.search_engine`, `storage.search_engine`,
    `state.search_engine` returns **zero hits**. The only `index_session`/
    `remove_session` callers are inside `conversation_file.rs` itself
    (`reindex_all` at line 161 + tests at lines 209, 215, 221). Tauri
    `search_conversations` (`src/tauri/commands/conversations.rs:727-747`)
    and TUI (`src/tui/events.rs:2990`) call framework
    `FileConversationStore::search_conversations` directly.
- Re-export layering is clean for the live path:
  `echo-agent/src/lib.rs:201-202` re-exports `FileConversationStore`;
  `echo-agent-app-core` consumes it via `echo_agent::memory::`.

## Deviations

None for the framework authority. The two application types were expected
to be "secondary helpers" but turned out to have zero production callers,
which is stronger evidence than expected for P2-01.

## Conclusion

The framework `FileConversationStore` is the single conversation storage
authority for EKO. `Persistence` and `SessionSearchEngine` are constructed
but unused in production — they constitute dead duplicate authority that
should be deleted or resurrected (finding P2-01).
