## Claim

Deleting a conversation cascades to (a) the conversation JSON file,
(b) the application tool-execution index and detail artifacts, (c) the
framework tool-output artifact subtree, and (d) the user-input spill
directory — on both Tauri and TUI surfaces — and the search index
reflects the deletion.

## Expected Result

Both surfaces run the same cascade. After `delete_conversation(id)`:
1. `<base>/conversations/<safe_id>.json` is removed.
2. `ToolExecutionRepository.summaries` no longer contains rows for `id`.
3. Per-conversation tool-execution detail files are tombstoned and removed.
4. Framework tool-output artifacts under `<artifact_root>/<conv>/` are removed.
5. User-input artifacts under `<spill_dir>/<conv>/` are removed.
6. Search results no longer include the conversation.

## Result

- Exit code: 0
- Duration: ~5 min code + grep
- Summary:
  - **Tauri `delete_conversation`** (`src/tauri/commands/conversations.rs:586-640`)
    performs steps 1, 2, 3, 4, 5:
    1. `store.delete_conversation(&id)` (file_conversation.rs:338-348 —
       `fs::remove_file`, missing-file is a no-op).
    2. `state.app_state.storage.tool_executions.remove_conversation(&id)`
       (tool_execution.rs:464-506 — moves the per-conversation subtree to
       `.trash/<scope>-<uuid>`, drops matching `summaries`/`details`/`active`
       rows, spawns a thread to `remove_dir_all` the tombstone).
    3. (Same call as 2 — the index rows ARE the tool-execution summaries.)
    4. `echo_agent::tools::artifact::cleanup_tool_output_scope(&config, &id, None)`
       inside a `tokio::task::spawn_blocking` (lines 618-625).
    5. `prepared_turn::cleanup_user_input_scope(&user_input_spill_dir, &id)`
       inside the same `spawn_blocking` (lines 626-635).
  - **TUI `/delete-session`** (`src/tui/events.rs:3067-3102`) performs steps
    1, 4, 5 only:
    1. `store.delete_conversation(id)` (line 3071-3074).
    4. `cleanup_tool_output_scope(&config, id, None)` (line 3080-3084).
    5. `cleanup_user_input_scope(&spill_dir, id)` (line 3086-3090).
    **Steps 2 and 3 are missing** — grep across `echo-agent-cli/src/tui`
    for `tool_executions\.` returns zero hits. The TUI never touches the
    `ToolExecutionRepository`. This is finding P2-02.
  - **Search index (step 6)**:
    - The `SessionSearchEngine` is never called on delete (no
      `search_engine.remove_session` callers anywhere outside its own
      tests). But the engine is dead code per V01-01, so this is moot.
    - The live search path is `FileConversationStore::search_conversations`
      which scans on-disk files (`file_conversation.rs:398-440`). Because
      step 1 removes the file, the next search naturally excludes the
      deleted conversation. Search correctness is preserved on the live
      path.
  - **`_meta.json` counter** is intentionally not decremented on delete
    (it is a monotonic id generator). This is correct — ids must stay
    unique. Not a finding.
  - **`ToolExecutionRepository::remove_conversation`** uses `fs::rename`
    to `.trash/<scope>-<uuid>` then `std::thread::spawn` to
    `remove_dir_all` the tombstone (tool_execution.rs:473-504). If the
    rename succeeds but the process exits before the spawned thread
    completes, the tombstone remains in `.trash/` indefinitely. Low
    impact; documented in passing, not promoted to a finding.

## Deviations

- The TUI/GUI parity gap (steps 2+3 missing on TUI) is exactly the kind
  of "X 模式 doesn't use Y" gap that AGENTS.md warns against treating as
  product intent — it is a missing-feature, not a deliberate omission.

## Conclusion

The Tauri `delete_conversation` cascade is complete and correct on the
conversation-store side, the tool-execution index side, and both
artifact sides. The TUI `/delete-session` cascade is **incomplete**:
it does not call `tool_executions.remove_conversation`, leaving
summaries, detail manifests, and event journals orphaned for the
deleted conversation (finding P2-02). Search behavior is correct on
the live framework path because it scans files; the dead application
`SessionSearchEngine` is irrelevant.

Supports findings: P2-02 (TUI/GUI deletion-cascade parity gap).
