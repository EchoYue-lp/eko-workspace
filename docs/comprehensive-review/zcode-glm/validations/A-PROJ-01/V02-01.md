## Claim

The diff source-of-truth is single and on-disk. There is no second diff
authority in production:

1. `/diff` derives its output from `git diff` (git is the authority for
   unstaged/staged changes) or from comparing two files on disk
   (`similar::TextDiff` over fresh `tokio::fs::read_to_string` reads).
2. `/review` derives its output from `git diff HEAD`; it falls back to
   `CodingLoop.diff_summary()` only when `git diff HEAD` fails.
3. `FileChangeTracker` / `CodingLoop.diff_summary()` is a *nominal*
   second "what changed" authority, but it is never populated —
   `record_file_write` / `record_file_delete` have zero callers outside
   the `project/` module — so its `diff_summary()` always returns
   `"No file changes"`. It is inert, not a real second authority.

## Deviations

None. The `/diff --html` git path (`diff_cmd.rs:247`) calls
`parse_unified_diff("git diff", &diff_text)` then `render_diff_html` —
i.e. it round-trips git's unified diff through the Rust parser/renderer
before display. This is a rendering choice, not a second diff *authority*:
the underlying bytes still come from `git diff` (single authority).

## Conclusion

The diff source-of-truth is single and derived from current files: `git
diff` for repository changes (git is the authority) and `similar` over
fresh on-disk reads for file-vs-file / file-vs-backup comparison. The
`FileChangeTracker` exposed on `CodingLoop` is a nominal second "what
changed" surface, but it has no writer in any live path (file tools do
not report into it; no CLI/Tauri/IPC caller invokes `record_file_*`), so
it is permanently empty. This validates the V02 sub-question
positively for the live path and feeds finding A-PROJ-01-P2-02
(`FileChangeTracker` is an inert second authority and a deletion
candidate). Also confirms there is no second diff renderer hidden in the
GUI.
