## Claim

Workspace switch behaves differently on the two surfaces, and the
project/gitignore module has a latent UTF-8 panic:

1. **GUI path** (`src/tauri/commands/workspace.rs:131`) calls
   `AppState::switch_workspace`, which rebuilds project context fresh
   from the new root via `refresh_dynamic_context`
   (`state.rs:883` → `infra.rs:530` → `prompt.rs:352`). There is no
   index to rebuild (the live path is cache-less per V01); the diff
   has no cache to refresh (per V02).
2. **CLI path** (`src/cli/cmd_impls/workspace.rs:114` `ws_switch`)
   does NOT call `AppState::switch_workspace`. It opens the registry
   (`registry.open_by_name`) and prints info. Nothing about the live
   session changes: no CWD, no agent `working_dir`, no persistence /
   conversation / memory / runtime-state swap, no project-context
   refresh.
3. `gitignore::globstar_match` byte-slices `&remaining[j..]` over a
   UTF-8 string, which panics when `j` lands inside a multibyte char.
   The bug is currently latent (`should_ignore_path` has no live
   caller), but it is a real panic on Chinese paths + `**` patterns
   and violates AGENTS.md's UTF-8 rule.

### Standalone reproduction (globstar_match byte-slice panic)

A faithful extraction of `project/gitignore.rs::globstar_match`
(`simple_glob` reduced to `==` / `starts_with`, preserving the
byte-slicing control flow):

```rust
fn simple_glob(pattern: &str, path: &str) -> bool {
    pattern == path || path.starts_with(pattern)
}

fn globstar_match(pattern: &str, path: &str) -> bool {
    let parts: Vec<&str> = pattern.split("**").collect();
    if parts.len() == 1 { return simple_glob(pattern, path); }
    let mut remaining = path;
    for (i, part) in parts.iter().enumerate() {
        if part.is_empty() { continue; }
        let is_last = i == parts.len() - 1;
        if is_last {
            return simple_glob(part, remaining) || remaining.ends_with(part);
        } else {
            let mut found = false;
            for j in 0..=remaining.len() {
                let candidate = &remaining[j..];   // <-- byte slice
                if simple_glob(part, candidate) {
                    remaining = &remaining[j + part.len()..];
                    found = true;
                    break;
                }
            }
            if !found { return false; }
        }
    }
    true
}

fn main() {
    for (pattern, path) in [
        ("z**", "中文模块"),
        ("a-**/x", "b-中文/x"),
        ("src/**/z", "src/中文/不匹配"),
    ] {
        let r = std::panic::catch_unwind(|| globstar_match(pattern, path));
        match r {
            Ok(b) => println!("pattern={:?} path={:?} -> {}", pattern, path, b),
            Err(_) => println!("pattern={:?} path={:?} -> PANICKED", pattern, path),
        }
    }
}
```

## Deviations

The reproduction uses a *reduced* `simple_glob` (the real one is a
byte-indexed backtracking matcher at `gitignore.rs:125-156`). The
reduction preserves the byte-slicing control flow that causes the panic
(`&remaining[j..]` for `j in 0..=remaining.len()`), so the panic
evidence is faithful; the full `simple_glob` would also produce the
same panic at the same line for the same inputs (the panic happens
before `simple_glob` is even called for the offending `j`). The
production reachability caveat stands: no live caller of
`should_ignore_path` today.

## Conclusion

Workspace switch on the GUI path rebuilds the project context fresh
(`refresh_dynamic_context` → `refresh_project_context_projection`) and
swaps all storage/memory surfaces; there is no index or diff cache to
stale. On the CLI path, `/workspace switch` performs none of this — it
is a registry viewer, not a state switch (P1-01). Separately, the
gitignore glob matcher has a real UTF-8 byte-slice panic that is
currently latent but reachable the moment any caller consults
`should_ignore_path` with a `**` pattern + a non-ASCII path (P2-03).
Feeds findings A-PROJ-01-P1-01 (CLI switch parity gap) and
A-PROJ-01-P2-03 (gitignore UTF-8 panic).
