## Claim

Large-repository and conflicting-file handling is bounded on the live
path, and the workspace registry's crash-safety surface is the one
weakness worth flagging:

1. **Large-repo indexing**: the live project-context builder
   (`generate_file_tree_summary` / `collect_dir_entries`) caps depth at
   3 and total entries at 80, and skips `target`/`node_modules`/`.git`/
   `dist`/`build`/... via `SKIP_DIRS`. `load_git_context` delegates to
   `git status --short` + `git diff --stat`, which are O(changes) not
   O(repo). `/diff` delegates entirely to `git diff`, which handles large
   repos natively. The dead `ProjectIndex::walk` additionally caps
   individual files at 1 MiB and skips the same build artifacts, but it
   is never reached (V01).
2. **Conflicting file fixtures**: the diff command operates on at most
   two on-disk files at a time (`show_file_diff`) or one file + one
   `.bak`; there is no in-memory file set that could conflict with disk.
   The single source of truth is whatever is on disk at call time.
3. **Crash safety**: `RegistryIndex::save` and the workspace manifest
   write both use non-atomic `fs::write` (truncate-then-write). A crash
   mid-write corrupts `registry.json`; `RegistryIndex::load` then
   silently falls back to `Self::default()`, making all workspaces
   invisible on the next launch with no surfaced error. Same class of
   defect as F-EXT-02-P1-02 (non-atomic writes in framework file tools).

## Conclusion

On the live path, large-repository handling is bounded (explicit caps in
`collect_dir_entries`; git-backed `status`/`diff`/`stat` for everything
that scales with change volume) and conflicting file fixtures cannot
arise (the diff command reads at most two disk paths per invocation and
has no parallel in-memory file set). The one weakness is crash safety:
the workspace registry's central `registry.json` and the per-workspace
manifest are written non-atomically, and a corrupt `registry.json` is
silently loaded as an empty registry (all workspaces disappear). This
matches the F-EXT-02-P1-02 finding for the framework file tools and is
the same fix (a shared `atomic_write` helper). Feeds finding
A-PROJ-01-P3-02.
