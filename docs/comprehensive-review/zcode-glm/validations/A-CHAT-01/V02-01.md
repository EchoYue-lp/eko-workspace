## Claim

Every `ChatSink` implementation only renders or transports events (no
durable state authority, no business logic). If any sink owns a
repository or mutates a store, that falsifies the "sinks only
render/transport" half of the A-CHAT-01 question and becomes a finding.

## Method

Static classification of every `ChatSink` implementor. Working
directory: `/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`.

```text
1. Enumerate every ChatSink implementor:
   grep -rn "impl ChatSink for\|impl.*ChatSink for" \
       echo-agent-cli --include="*.rs"

2. For each production sink, read on_event and classify every side
   effect as RENDER (UI event / mpsc forward) or BUSINESS (repository
   mutation / durable store write / state authority).

3. Cross-check tool-execution persistence asymmetry: does the TUI sink
   touch ToolExecutionRepository?
   grep -rn "ToolExecutionRepository\|tool_executions\|tool_execution::" \
       echo-agent-cli/src/tui --include="*.rs"

4. Confirm the correct layering precedent (WebhookTurnObserver is in the
   driver, not a sink):
   grep -n "WebhookTurnObserver\|webhook_observer" \
       echo-agent-cli/echo-agent-app-core/src/chat_driver.rs
```

## Expected Result

- Three production sinks (`ChannelChatSink`, `TuiChatSink`,
  `TauriChatSink`) plus one test sink (`MockChatSink`).
- All production sinks perform only RENDER/TRANSPORT side effects.
- The cross-cutting webhook observer lives in `drive_chat_inner`, not
  in a sink.

## Deviations

The validation's claim ("all sinks only render/transport") is falsified
by `TauriChatSink`. This is itself the finding (A-CHAT-01-P2-01), not
an environmental deviation.

## Conclusion

Supports A-CHAT-01's sink-responsibility diff (task report Current Path
"Sink responsibility diff" and Handoff item 4). Two of three production
sinks (`ChannelChatSink`, `TuiChatSink`) are pure render/transport; the
third (`TauriChatSink`) owns `ToolExecutionRepository` persistence
authority, breaking the "sinks only render/transport" invariant and the
multi-mode parity rule. The `WebhookTurnObserver` precedent confirms the
correct layering (driver-level observer) that the tool-execution
persistence should follow. This validation is the sole evidence for
A-CHAT-01-P2-01.
