## Claim

`drive_chat` is the single chat-turn lifecycle owner: it has exactly one
definition, every chat turn (TUI / REPL / Tauri / channels) enters it
exactly once, and no sibling chat-streaming path bypasses it. The
task-run half (`drive_run_async` / `drive_agent_run`) is a separate,
intentionally-decoupled lifecycle and does not count as a parallel chat
driver.
