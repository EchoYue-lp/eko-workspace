## Claim

`drive_chat` delivers exactly one terminal `AgentEvent` to the sink per
call across the happy, stream-setup-error, mid-stream-error, and cancel
paths. The guarantee is provided by `envelope_event_stream`, which
`drive_chat_inner` wraps around the raw framework stream; the stream-
setup error path synthesizes its own terminal.

## Expected Result

- `envelope_event_stream` (a) normalizes raw `Err` into `AgentEvent::Error`,
  (b) breaks after the first `is_terminal()` payload, (c) synthesizes
  one `AgentEvent::Error` if the stream ends without a terminal — and
  only ever `yield Ok(..)`.
- `drive_chat_inner`'s stream-setup error path (`:517-536`) forwards a
  synthetic `AgentEvent::Error { source: "chat_driver" }` to the sink.
- `drive_chat_inner`'s mid-stream `Err(e)` arm (`:548-560`) is
  unreachable (envelope never yields `Err`).
- The happy-path test asserts `terminal_count == 1` and exits 0.

## Result

- Exit code: 0 (step 5); not-applicable (steps 1-4, static)
- Duration: ~3s for the test run (incremental cache)
- Summary: claim confirmed.

  Step 1 — `envelope_event_stream_after`
  (`event_envelope.rs:123-194`):

## Deviations

None on the happy path. The mid-stream `Err(e)` arm being unreachable
(A-CHAT-01-P3-01) is a dead-code observation, not a terminal-invariant
violation — the invariant holds today because the arm cannot fire. The
cancel path's terminal is a synthesized `Error` (not `Cancelled`),
which is a semantic downgrade inherited from F-RCT-03-P2-02, not a
deviation from this validation's claim (one terminal is still
delivered).

## Conclusion

Supports A-CHAT-01's one-terminal conclusion (task report Current Path
"One-terminal invariant" and Handoff item 2). `drive_chat` delivers
exactly one terminal per call on all four paths (happy / setup-error /
mid-stream-error / cancel) because (a) the stream-setup path
synthesizes its own `Error` terminal, and (b) every other path is
normalized by `envelope_event_stream`, which guarantees one terminal
(real or synthesized) and never yields `Err`. The happy-path
"exactly one terminal" assertion is regression-guarded by
`drive_chat_streams_agent_events_via_sink`; the non-happy paths are not
(yet) guarded at the app level — see V04-01 and A-CHAT-01-P3-02.
