Intent classification degrades safely: an errored or hung LLM call falls
back to `Intent::Fallback`, and the hook-activation handoff is scoped to
exactly one turn.

## Expected Result

- LLM error → `Intent::Fallback` (safe).
- A hung LLM call is bounded by an intent-layer timeout that returns
  `Fallback` promptly.
- The hook activation slot is consumed or cleared each turn; no stale
  value can leak to a later turn.

## Result

- Exit code: not-applicable (static inspection)
- Duration: n/a
- Summary: claim **failed** on two counts. The LLM *error* → Fallback
  path is correct, but (a) there is no intent-layer timeout, so a *hung*
  call stalls turn entry for the full provider HTTP timeout (~120 s),
  and (b) the hook activation slot is never cleared at turn start and is
  not taken on the keyword fast path, so a stale value can leak across
  turns.
- Log/artifact: none

### Sub-check A — LLM error → Fallback (PASS)

`src/intent/classifier.rs:409-419`:

```rust
Box::pin(async move {
    let messages = vec![Message::user(prompt)];
    match llm.chat_simple(messages).await {
        Ok(response) => Self::parse_response(&response),
        Err(e) => {
            tracing::warn!(error = %e, "LLM intent classification failed, falling back");
            Intent::Fallback
        }
    }
})
```

A returned `Err` is logged and mapped to `Intent::Fallback`. `parse_response`
additionally maps any unparseable/invalid JSON to `Fallback`
(classifier.rs:393-396). The KeywordClassifier is synchronous and
infallible (returns `Intent` directly, no `Result`). So the *error*
fallback is robust.

### Sub-check B — No intent-layer timeout (FAIL → F-INTENT-01-P3-02)

- `grep -rn "timeout\|tokio::time" src/intent/` → **zero matches**. No
  timeout anywhere in the intent module.
- `IntentRouter::classify` (mod.rs:124-153) awaits
  `self.classifier.classify(...)` with no wrapping timeout.
- `echo-core/src/llm/mod.rs:20-50` — `SimpleChatOptions` has only
  `temperature` and `max_tokens`; no timeout field, and `LlmClient::
  chat_simple` (mod.rs:74) takes no timeout.
- The only bound is the provider's HTTP client:
  `echo-integration/src/providers/openai.rs:256-258` builds the reqwest
  client with `.timeout(Duration::from_secs(120))`.
- Classification runs at the top of `run_chat_direct`/`run_stream_channel`
  (react_loop.rs:625, stream_channel.rs:187), **before** the core loop and
  its budgets, so no turn-level budget bounds it.

Consequence: a provider stall (network hang, unresponsive endpoint) makes
the turn entry block for up to 120 s before the error surfaces and maps
to Fallback. The error fallback is correct; the latency bound is absent
and non-uniform across providers. Recorded as F-INTENT-01-P3-02.

### Sub-check C — Hook activation slot staleness (FAIL → F-INTENT-01-P3-01)

Lifecycle trace of the shared slot
`ReactAgent::hook_activation_cache: Arc<Mutex<Option<(String, String)>>>`
(mod.rs:253-257):

| Step | Site | Behaviour |
|---|---|---|
| Hook fires | `context.rs:545, 613` | `fire_lifecycle_hook(UserPromptSubmit, input)` |
| Hook activates skill directly | `context.rs:466-481` | on `Ok` → `result.activate_skill = None` (line 474); on `Err` → left in `result` (line 478) for supervisor retry |
| Slot **write** | `context.rs:548-552, 615-619` | `if hook_result.activate_skill.is_some() { *cache = hook_result.activate_skill }` — written **only** on hook-activation failure |
| Slot **read/take** | `trigger_supervisor.rs:87-91` | `hook_activation_slot.lock().ok().and_then(|mut guard| guard.take())` — consumed only when the fuse step is reached |
| Keyword fast path | `trigger_supervisor.rs:76-78` | `if kw.confidence() >= 0.7 { return kw; }` — returns **before** the take |

The defect: the slot is write-on-failure, take-on-fuse, and **never
cleared at turn start**. Two failure modes follow:

1. Turn N: hook-activation fails → slot = `(A, reason)`. Same turn the
   keyword fast path fires (different skill B, confidence ≥ 0.7) → returns
   B at trigger_supervisor.rs:78 **without taking the slot**. Slot still
   = `(A, reason)`.
2. Turn N+1: hook either succeeds (slot not overwritten, stays `(A)`) or
   has no ActivateSkill request (slot not overwritten, stays `(A)`).
   Turn N+1's classification reaches the fuse step (keyword low, LLM low)
   → takes the stale slot → activates skill A for turn N+1's input, which
   had nothing to do with A.

No `*cache = None` exists in either prepare path before the hook fires.
Recorded as F-INTENT-01-P3-01 (P3, medium confidence — the trigger is
narrow because it requires a failed hook activation on the same turn as a
keyword fast-path match, but the code defect is unambiguous).

### Sub-check D — Keyword/DirectAnswer no-match fallback (PASS)

keyword matches, `classify_inner` returns `Intent::Fallback`

demotes sub-threshold confidences to Fallback (mod.rs:127-152). Safe.
