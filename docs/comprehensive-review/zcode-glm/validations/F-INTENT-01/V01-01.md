## Claim

Intent classifiers and the `IntentRouter` have a single canonical
definition site each, are registered through one path, and are reachable
from the agent loop entry points.

## Method

Repository-wide static inspection of definition, registration, and
reachability. Working directory
`/Users/ls/MyWork/code/ylp_agent_learn/lp-agent/echo-agent` at commit
`9b0e0fa`.

```text
1. Definition search (grep across both repos, excluding target/):
   grep -rn "pub enum Intent\b\|pub trait IntentClassifier\|pub struct IntentRouter\|pub struct KeywordClassifier\|pub struct LlmIntentClassifier\|pub struct ChainedClassifier\|pub struct TriggerSupervisor" --include="*.rs"
   → expect exactly one definition site per symbol.

2. Registration search:
   grep -rn "intent_router\|set_intent_router\|IntentRouter::new\|TriggerSupervisor::new" --include="*.rs"
   → trace how the router reaches ReactAgent.

3. Reachability search (who calls router.classify at runtime):
   grep -rn "router.classify\|self.intent_router" --include="*.rs" src/agent/react/run/
   → expect exactly two live call sites (run_chat_direct + run_stream_channel).

4. Module wiring:
   read src/intent/mod.rs (module root, re-exports, submodules).
```

## Expected Result

- Each of `Intent`, `IntentClassifier`, `IntentRouter`, `KeywordClassifier`,
  `LlmIntentClassifier`, `ChainedClassifier`, `TriggerSupervisor` defined
  exactly once.
- The router reaches `ReactAgent` via either
  `ReactAgentBuilder::intent_router()` → `build()` direct write, or
  `agent.set_intent_router(...)`.
- `router.classify(...)` is called from the two converged loop entry points
  (`run_chat_direct`, `run_stream_channel`) before the core ReAct loop.

### Registration paths (two, both legitimate)

1. **Builder path** — `ReactAgentBuilder::intent_router(router)`
   (`src/agent/react/builder.rs:630-632`) stores into the builder field
   (`builder.rs:103-104`); `build()` writes directly to the agent:
   `agent.intent_router = Some(router)` (`builder.rs:1038-1040`). This is
   a Category-C bypass (no `AgentConfig` field) per F-RCT-01-P3-03 —
   benign here because `new_inner` initialises `intent_router: None`
   (`mod.rs:571`), so the assignment cannot clobber state.
2. **Runtime setter** — `ReactAgent::set_intent_router(router)`
   (`mod.rs:1490-1492`). Used by EKO bootstrap after the agent handle is
   constructed (`runtime.rs:348-354`).

Both paths terminate on the same field
(`ReactAgent::intent_router: Option<IntentRouter>`, `mod.rs:226`).
No parallel field or shadow registry exists.

### Reachability (two converged loop entry points)

| Entry point | File:line | Guard | Action on each Intent |
|---|---|---|---|
| `run_chat_direct` (non-streaming) | `react_loop.rs:623-682` | `if let Some(ref router) = self.intent_router` | DirectAnswer(+shortcut)→`direct_answer`; SkillRequired→`activate_skill`; Fallback→fall through |
| `run_stream_channel` (streaming) | `stream_channel.rs:185-280` | `if let Some(ref router) = self.intent_router` | identical match structure (comment "converged with run_react_loop") |

Both call `router.classify(message, &messages).await` **before** the
core ReAct loop spawns (`react_loop.rs:711`, `stream_channel.rs:302`).
When `intent_router` is `None` (e.g. `ReactAgent::new` minimal config,
`mod.rs:509-571`), the gate is skipped and the plain ReAct loop runs —
verified by the `agent_with_mock_llm` test fixture
(`stream_channel.rs:1072-1078`) which builds without a router.

The streaming-router call sites at `stream_channel.rs:1081, 1243` are
inside `#[cfg(test)]` fixtures, not production code; production
registration is `runtime.rs:340-354`.

## Deviations

One benign structural note (not a failure of this claim): the
`intent_router` builder option bypasses `AgentConfig` and writes directly
to the agent field (`builder.rs:1038-1040`). This is the same Category-C
pattern F-RCT-01-P3-03 flagged for five builder options; for the router
it is harmless (the target field defaults to `None` and the setter is
idempotent), but it means `agent.config()` does not describe the router's
presence. Recorded for completeness; no new finding raised here (covered
by F-RCT-01-P3-03).

## Conclusion

Supports: the definition/registration/reachability claim is fully
confirmed. There is exactly one definition site per intent symbol; two
registration paths that terminate on the same field; and two converged
loop entry points that classify before the core ReAct loop. The router is
optional (`Option<IntentRouter>`) and its absence is the clean default.

Does not prove: the *correctness* of the classification decision
(V02), the *timeout/fallback* behaviour (V03), or the *parity* of the
two call sites' side effects (V04). The Category-C builder bypass is
benign for the router but is owned by F-RCT-01-P3-03.

Findings using this validation: none directly (V01 is the foundation;
the findings P2-01/P3-01/P3-02/P3-03 rest on V02/V03/V04).
