### Part A — authority and convergence (static, PASS)

**Single skill-activation authority.** `grep` shows exactly one
`activate_skill` definition:
`src/agent/react/capabilities.rs:964 pub async fn activate_skill(&self, skill_name: &str) -> Result<()>`.
It routes through the single
`ToolExecutionSubsystem::skill_registry: SkillRegistry`
(`src/agent/react/subsystems/tool_exec.rs:34`, constructed once at
`mod.rs:509`). Both router arms call it:

- non-streaming: `react_loop.rs:674 self.activate_skill(&skill_name).await`
- streaming: `stream_channel.rs:264 self.activate_skill(&skill_name).await`

This is the **same** method the hook system calls
(`context.rs:467 self.activate_skill(skill).await`) and the product
runtime calls directly. No parallel skill registry, no parallel
activation path.

**No subagent/task authority in the router.**
`grep -rn "SubagentRegistry\|TaskRun\|spawn_subagent\|task_create" src/intent/`
→ **zero matches**. The intent module imports only `Intent`, `Message`,
and its own classifiers; it cannot spawn subagents, create tasks, or
mutate `TaskRun`/`PlanTask`/`SubagentRun`. The router is a pure pre-loop
hint layer.

**SkillRequired side effect.** `activate_skill`
(capabilities.rs:964-997) injects the skill body as a *replaceable
context projection* with marker `echo-agent:skill:{skill_name}`
(capabilities.rs:969, 983-989) and then **falls through** to the normal
ReAct loop (react_loop.rs:677 / stream_channel.rs:272 comment "Fall
through to run_core_loop"). So SkillRequired never bypasses the loop —
it only prepends instructions.

**DirectAnswer projector-gate convergence.** Both gates consult
`allows_direct_answer_shortcut()` (mod.rs:624-629: true iff
`pre_model_context_projector` is `None`):

- `react_loop.rs:627-663` —
  `DirectAnswer { confidence } if self.allows_direct_answer_shortcut() =>`
  shortcuts to `direct_answer`; the bare `DirectAnswer { confidence }`
  arm (line 657) logs "routed through ReAct for pre-model projection" and
  falls through.
- `stream_channel.rs:189-253` — identical structure: guarded arm shortcuts
  (line 219 `direct_answer_stream`); bare arm (line 247) logs and falls
  through.

So when a product installs a context projector (EKO does, for task
context), `DirectAnswer` is never shortcuted — it falls through to the
loop where the projector runs. This is the safety mechanism that
prevents the router from answering "directly" in a context where task
projections are required.

**Fallback arm.** Both gates' `Fallback` arm (react_loop.rs:678,
stream_channel.rs:273) log and fall through to the core loop. No side
effect.

the gated path, but the shortcut-path divergence is untested and is the
subject of the P2 finding.
