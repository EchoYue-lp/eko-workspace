### Intent label set (bounded)

| Variant | Fields | Routing effect |
|---|---|---|

| `SkillRequired` | `skill_name: String, confidence: f32` | activate skill, fall through to ReAct |

Accessors `confidence()` (mod.rs:46-52) and `skill_name()` (mod.rs:55-60)

### Decision mechanism per classifier

| Classifier | Mechanism | Cost | Decision function |
|---|---|---|---|
| `KeywordClassifier` | rule/weighted-score | 0 tokens | `classify_inner` (classifier.rs:102-160): per-skill score accumulation; confidence = `0.5 + score*0.1` (capped 0.95) minus an ambiguity penalty when the runner-up gap < 0.3; emits `SkillRequired` only if confidence ≥ 0.7, else falls to DirectAnswer-keyword or Fallback. CJK triggers require ≥2 chars; ASCII triggers require word-boundary match (`match_weight`, classifier.rs:170-202). |
| `LlmIntentClassifier` | LLM (JSON) | ~500 tokens | `build_prompt` (classifier.rs:308-352) asks for `{"intent","skill","confidence"}` with the rule "only return DIRECT or SKILL if confidence >= 0.7"; `parse_response` (classifier.rs:355-397) strips markdown fences and maps DIRECT/SKILL/FALLBACK, defaulting to Fallback on any parse failure. |
| `ChainedClassifier` | ordered first-non-Fallback | sum of children | `classify` (classifier.rs:447-464): iterates classifiers, returns first non-Fallback, else Fallback. |
| `TriggerSupervisor` | 3-source fusion | 0 or ~500 tokens | `classify` (trigger_supervisor.rs:66-95): keyword first; if ≥0.7 fast-path return; else LLM; then take hook slot; `fuse` (lines 48-62) priority: kw≥0.7 → llm≥0.7 → hook → Fallback. |

The fusion priority is documented in the docstring
(trigger_supervisor.rs:42-47) and matches the implementation exactly,
verified by the 5 fusion unit tests (lines 102-156):
`keyword_high_confidence_takes_priority`, `llm_wins_when_keyword_low`,
`hook_adopted_when_both_low`, `all_low_returns_fallback`,
`keyword_beats_llm_even_when_both_high`.

### Outer gating layer

`IntentRouter::classify` (mod.rs:124-153) wraps the inner classifier and
demotes any `DirectAnswer`/`SkillRequired` whose confidence falls below
`IntentRouterConfig::confidence_threshold` (default 0.7) to `Fallback`,
and honours the `enable_direct_answer` / `enable_skill_routing` flags.
So the router is a second threshold gate on top of each classifier's own
threshold — defence in depth.

### Shipped-keyword claim (confirmed: zero hardcoded keywords)

- `KeywordClassifier::default()` (classifier.rs:53-61) constructs empty

- The only populated keyword tables in `classifier.rs` are inside

### Explainability (partial — finding F-INTENT-01-P3-03)

| Path | Explainable? | Evidence |
|---|---|---|
| Keyword | yes | `match_weight` and `classify_inner` are a deterministic scorer; the confidence formula is documented inline (classifier.rs:124-137). A mis-classification can be traced by re-running the scorer. |
| LLM | no | the prompt (classifier.rs:330-352) requests only `intent`/`skill`/`confidence`; no `reason` field. `parse_response` extracts only those three and discards everything else; on parse failure it returns Fallback with no diagnostic. |
| Hook fusion | no | `fuse` destructures the hook activation as `(skill_name, _reason)` (trigger_supervisor.rs:55) — the `reason` string the hook system populated (context.rs:466 `(ref skill, ref reason)`) is discarded. |
| Runtime log | partial | the loop logs `skill = %skill_name, confidence = confidence` on SkillRequired (react_loop.rs:668-673) but never the rationale. |

This is the basis for finding F-INTENT-01-P3-03 (P3, observability gap,
no correctness impact).

## Deviations

None for the claim as stated. The explainability shortfall is recorded
as a finding (F-INTENT-01-P3-03) rather than a deviation from this
validation's expectation, because the claim only requires the decision
mechanism to be *identifiable* (which it is) and explainability to be
*at least partial* (which the keyword path provides).

One additional observation (not a deviation): the keyword scorer uses
`partial_cmp(...).unwrap_or(Ordering::Equal)` (classifier.rs:119) on
`f32` scores — safe (the `unwrap_or` absorbs NaN), and the surrounding
arithmetic uses `min`/`max`/saturating-style caps, so there is no panic
path and no NaN-propagation hazard. This respects the AGENTS.md no-panic
rule.
