## Claim

Secrets (API keys, tokens, passwords, private keys, password-in-URL) are
detected and redacted before reaching logs, traces, snapshots, and tool
output flows in the framework's main runtime paths.

## Method

Grep-based caller trace + redaction-correctness inspection of
`echo-agent/src/security.rs` and `echo-agent/src/evolution/security.rs`.

```text
cd /Users/ls/MyWork/code/ylp_agent_learn/lp-agent
grep -rn "scan_secrets\|redact_secrets\|contains_secrets" \
  echo-agent/src echo-agent/echo-core/src echo-agent/echo-execution/src \
  echo-agent/echo-state/src echo-agent/echo-orchestration/src \
  echo-agent/echo-tools/src echo-agent/echo-integration/src \
  echo-agent-cli/ \
  | grep -v "test"

# Plus read security.rs in full (lines 1-241) and evolution/security.rs
# head (lines 1-50) + the contains_secrets impl context.
```

Inspection targets:
1. Pattern coverage at `security.rs:33-77` (19 secret kinds).
2. UTF-8 boundary safety at `security.rs:113-125`.
3. Overlap deduplication at `security.rs:88-93`.
4. Live caller paths into the ReAct loop, trace, snapshot, spawn_task.

## Expected Result

- `redact_secrets` callers cover all four main runtime surfaces: tool output,
  trace, snapshot, ReAct execution loop.
- `redact_secrets` does not panic on multi-byte (Chinese/emoji) input.
- Overlapping matches (e.g. `Bearer <JWT>` matched by both Bearer and JWT
  rules) are deduplicated so redaction is stable.
- Fast-path `contains_secrets` gates the heavier `redact_secrets` to avoid
  running 19 regexes on clean output.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - **Coverage is correct on the four main surfaces**:
    - `tools/builtin/spawn_task.rs:171,175` — `redact_secrets` on stdout/stderr
      of spawned tasks.
    - `trace/mod.rs:434` — `redact_secrets` on trace strings.
    - `agent/snapshot.rs:885-886` — `contains_secrets` + `redact_secrets` on
      tool output (snapshot path).
    - `agent/react/run/execution.rs:229-230` — same on the ReAct loop's
      `check_tool_output_guard` path.
  - **UTF-8 boundary safety is defensive and correct**: `security.rs:113-125`
    checks `result.is_char_boundary(m.position)` AND `result.is_char_boundary(end)`
    before `replace_range`, bails with `tracing::warn!` and skips redaction if
    not on a boundary. Will not panic on Chinese/emoji content.
  - **Overlap dedup works**: `security.rs:88-93` skips any match whose range
    overlaps an already-recorded (higher-priority) match, so e.g.
    `Bearer eyJ...` only produces one redaction (Bearer wins as it appears
    earlier in `SECRET_PATTERNS`).
  - **Fast-path is used consistently**: all four live callers do
    `if contains_secrets(output) { let r = redact_secrets(output); ... }`
    or call `redact_secrets` unconditionally on small known-risky strings.
    Pattern compilation is `LazyLock`-cached (`security.rs:33`).
  - **Documented gaps**:
    - `security.rs:3-12` TODO acknowledges the `://[^:]+:[^@]+@` (Password in
      URL) pattern produces false positives on docs/comment lines. See finding
      F-SEC-01-P2-02.
    - `echo-agent/src/evolution/security.rs` is a parallel scanner with its
      own `SECRET_PATTERNS` list (19 patterns, slightly different from root's
      19). Used only by the evolution/memory-persistence path, not the main
      runtime. See finding F-SEC-01-P3-02.

- Log/artifact: none created.

## Deviations

- The root `security.rs` and `evolution/security.rs` pattern lists diverge
  (e.g. evolution has `gho_` GitHub OAuth and a stricter `sk-ant-apiXX-_…`
  Anthropic pattern; root does not). Both compile and redact correctly in
  isolation, but the divergence is a maintenance hazard, not a runtime
  defect.

## Conclusion

and overlap deduplication. The framework satisfies AGENTS.md's
