## Claim

Path-traversal / injection, UTF-8 safety, and panic safety in guard and
sandbox code comply with AGENTS.md's hard Rust constraints (no byte slicing
on unicode, no `unwrap`/`expect`/`panic!` on untrusted input, validated
paths).

## Expected Result

- No byte slicing (`&s[..n]`, `s[n..]`) on potentially-unicode text.
- No `unwrap`/`expect`/`panic` in non-test guard/sandbox code on untrusted
  input paths.
- Seatbelt profile paths validated against S-expression / comment / null
  injection.
- Length-based guards use `chars().count()`, not byte length.
- UTF-8 truncation splits on char boundaries.

## Result

- Exit code: not-applicable (static inspection)
- Summary:
  - **Panic safety PASS**: zero matches for `unwrap()`/`expect()`/`panic!`/
    `unreachable!`/`todo!` in non-test guard/sandbox code. All error paths
    use `?`, `unwrap_or`, `unwrap_or_default`, or `Result` returns.
    `GuardManager::check_all` (mod.rs:156-158) converts a panicked guard
    task (`handle.await` JoinError) into `ReactError::Other(...)` —
    defensive against guard implementation bugs.
  - **Path-injection prevention PASS**: `local.rs:458-469`
    `validate_sandbox_path` rejects `(`, `)`, `\n`, `\0`, `;`, `#`, `"`.
    `append_seatbelt_subpath_rule`/`deny` (471-490) call it and silently
    skip invalid paths. Test at 1456-1475 confirms injection like
    `/tmp/bad")\n(allow file-write* (subpath "/"` produces an empty profile
    rather than a compromised one. This is correct framework-bug-prevention
    per AGENTS.md scope.
  - **UTF-8 truncation PASS**: `retain_utf8_prefix` (sandbox.rs:309-322)
    iterates `chars()` and accumulates `len_utf8()` bytes, never slicing
    mid-character. Test at 424-431 confirms `"中文"` (6 bytes) under a 7-byte
    cap is preserved fully while `"abc"` stderr is truncated to `"a"`.
  - **Streaming UTF-8 decoder PASS**: `IncrementalUtf8Decoder`
    (local.rs:828-880) buffers partial multibyte sequences across pipe reads
    using `std::str::from_utf8` + `error.valid_up_to()`. Test at 1143-1168
    confirms `printf '\342'; sleep; printf '\202'; sleep; printf '\254'`
    streams as a single `€` rather than panicking on invalid intermediate
    bytes. Output chunks split via `split_stream_chunks` (local.rs:777-795)
    also iterate `chars()` to avoid breaking multibyte chars at the
    `STREAM_CHUNK_BYTES` boundary.
  - **Secret redaction boundary safety PASS**: `security.rs:113-125`
    explicitly checks `is_char_boundary(position)` and `is_char_boundary(end)`
    before `replace_range`, logs warn and skips on failure.
  - **ContentGuard redaction - minor concern**: `content.rs:114`
    `result.replace_range(m.start..m.end, replacement)` does NOT call
    `is_char_boundary`. In practice this is safe because (a) the `regex`
    crate's default unicode mode always returns matches on UTF-8 char
    boundaries, and (b) matches are processed in `rev()` order so earlier
    positions remain valid. Still, it lacks the defensive check that
    `security.rs` has — minor inconsistency.
  - **FINDING: `RuleGuard` length check uses bytes, not chars**:
    `rule.rs:51-55` does `content.len() > max_len` and reports byte length
    in the block reason. AGENTS.md mandates `chars().count()` for length
    checks on potentially non-ASCII text. For CJK content this means
    `max_length(10)` blocks just 4 Chinese characters (10 bytes / 3 bytes
    per char). See finding F-SEC-01-P3-01.
  - **FINDING: ContentGuard Redact mode is no-op through GuardManager**:
    `content.rs:222-232` — when `ContentGuard` is wired via
    `with_content_guard(ContentGuardMode::Redact)` (builder.rs:760), the
    `GuardResult::Warn` path DISCARDS the redacted text. The inline comment
    at content.rs:223-227 acknowledges this. A user expecting pipeline-level
    PII redaction gets only a warning. See finding F-SEC-01-P2-01.

- Log/artifact: none created.

## Deviations

- `content.rs:114` lacks the `is_char_boundary` defensive check that the
  sibling `security.rs:113-125` has. Not a defect in practice (regex
  guarantees boundary alignment), but inconsistent defense-in-depth.
