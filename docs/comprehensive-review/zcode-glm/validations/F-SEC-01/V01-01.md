## Claim

The framework's guard/sandbox/security modules' protection scope matches the
AGENTS.md local-desktop threat model: only user-data-loss prevention,
framework-bug prevention, and local-universal safety (no secrets in logs) are
in-scope; web-service threats (XSS, SSRF, multi-tenant) are not implemented as
permission gates.

## Method

Read AGENTS.md "产品定位与安全边界" section and classified each protection
found in the primary paths:

1. `echo-agent/src/security.rs` — secret scanner (241 lines, read in full).
2. `echo-agent/src/guard/{mod,llm,rule}.rs` — guard façades (read in full).
3. `echo-agent/echo-core/src/guard/{mod,content,llm,rule}.rs` — guard core
   (read in full).
4. `echo-agent/echo-core/src/sandbox.rs` + `echo-execution/src/sandbox/*.rs`
   — sandbox trait, manager, policy, local backend (read in full).

For each protection, classify: (a) local-universal, (b) framework-bug
prevention, (c) user-data-loss prevention, or (d) overreach (web-service
threat model misapplied).

```text
Inspection procedure (manual):
- AGENTS.md lines: threat-model bullet list (local, not web-service).
- For each guard/sandbox/security symbol, ask:
  * Does it gate an interactive user tool behind an "agent auto-permission"
    mode? (overreach per AGENTS.md historical lesson)
  * Does it model multi-tenant isolation? (out-of-scope)
  * Does it prevent a framework bug or local-universal risk? (in-scope)
- Grep for `require_full_auto` / `full_auto` gates in primary paths.
```

- No multi-tenant / cross-user isolation logic.
- Secret redaction present (local-universal: no secrets in logs).
- Path-injection validation present (framework-bug prevention).
- Fail-closed LLM guard parsing (framework robustness).
