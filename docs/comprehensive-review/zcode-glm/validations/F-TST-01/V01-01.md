## Claim

The four framework mocks (`MockLlmClient`, `MockAgent` +
`FailingMockAgent`, `MockTool`, `MockEmbedder`) each implement their
production trait (`LlmClient`, `Agent`, `Tool`, `Embedder`) using the real
request/response types. They are singly defined in `echo-agent/src/testing/`
with no parallel/sibling mock surface. They model a documented subset of
production behaviour: streaming is single-chunk, tool results are
text-only success/error, agent streams are single-`FinalAnswer`, and
`FailingMockAgent` emits one error variant. This is a faithful
*type-level* contract but an incomplete *behaviour-level* contract.

## Deviations

The `LlmError` variety coverage is slightly narrower than the matrix
header suggests: the mock directly constructs `NetworkError`,
`ApiError { status: 429 }`, and `EmptyResponse` (the last implicitly when
the queue is empty). `Timeout`, `AuthError`, and `ContentFilter` are not
directly constructible via a builder, though `with_error(ReactError)`
accepts any `ReactError` so a test can hand-roll them. This narrows the
"typed LlmError" coverage to "convenient builders for 3 variants,
manual construction for the rest" — noted here for completeness; not a
finding because the `with_error` escape hatch keeps the full variant
space reachable.

## Conclusion

The claim is supported. The mocks are singly defined and trait-faithful at

establishes the matrix that V02 (scripting), V03 (feature isolation), and
