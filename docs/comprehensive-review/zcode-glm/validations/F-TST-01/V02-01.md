## Claim

The mocks support rich **call-level** scripting (a sequence of responses
consumed one-per-call, including interleaved success / tool-call / error
and multi-turn ReAct ordering), but they do NOT support **stream-level**
scripting (a sequence of chunks within a single `chat_stream` call) or
**agent-stream-level** scripting (a sequence of `AgentEvent`s within one
`execute_stream`). Errors and cancellation are modelled only at the
pre-stream/pre-emit seam, never mid-stream. The mocks therefore cannot
reproduce the multi-chunk streaming, fragmented tool-call assembly,
DeepSeek argument-repair, mid-stream-error, or mid-stream-cancellation
conditions that the production runtime actually defends against.

## Expected Result

- Call-level scripting: YES. The `VecDeque<MockLlmResponse>` queue drains
  one entry per `chat`/`chat_stream` call, in FIFO order, across an
  arbitrary number of calls. Interleaving `with_response`,
  `then_tool_call`, `with_error` scripts a precise multi-turn sequence.
- Stream-level (chunk-level) scripting: NO. Each queued response becomes
  exactly one `ChatChunk` via `stream::once`.
- Agent-stream-level scripting: NO. `MockAgent::execute_stream` emits
  exactly one `AgentEvent::FinalAnswer`.
- Errors: modelled only as the pre-stream `pop_response()?` Err path or
  the `with_delay` + cancel `select!` before stream creation.
- Mid-stream cancellation: NO. The cancel token is checked only before
  the stream is created (`mock_llm.rs:400-408`); the stream body has no
  cancel reference.

### Call-level scripting (positive)

The response queue is `Arc<Mutex<VecDeque<MockLlmResponse>>>`
(`mock_llm.rs:57`). Each builder appends to the back; `pop_response()`
(`mock_llm.rs:308-322`) pops from the front. So a test can script a
multi-turn ReAct sequence precisely:

```text
MockLlmClient::new()
    .then_tool_call("call_1", "calc", r#"{"x":6}"#)   // turn 1: tool request
    .with_error(ReactError::Llm(Box::new(LlmError::ApiError { status: 500, ... })))  // turn 2: server error
    .with_response("final answer")                      // turn 3: recovery
```

This is exercised by `run_core_loop_tool_call_cycle_completes`
(`stream_channel.rs:1441-1467`) and `deepseek_tool_turn_replays_complete_assistant_message`
(`stream_channel.rs:1469-1534`), both of which script a two-turn
(tool-call → final-answer) sequence. Confirmed: call-level ordering is
rich and faithful.

When the queue is empty, `pop_response()` returns
`Err(ReactError::Llm(Box::new(LlmError::EmptyResponse)))`
(`mock_llm.rs:320`). This is the "empty queue" error condition exercised
by `run_core_loop_empty_llm_response_terminates_gracefully`
(`stream_channel.rs:1933-1965`).

### Stream-level scripting (negative)

`chat_stream` (`mock_llm.rs:380-461`):

```text
match self.pop_response()? {
    PopResult::Content(text, usage) => {
        let stream = futures::stream::once(async move {
            Ok(ChatChunk { delta: DeltaMessage { role, content: Some(text), reasoning_content: None, tool_calls: None }, finish_reason: Some("stop"), usage })
        });
        Ok(Box::pin(stream))
    }
    PopResult::ToolCalls(message, usage) => {
        // build complete DeltaToolCall vec, then:
        let stream = futures::stream::once(async move {
            Ok(ChatChunk { delta: DeltaMessage { ... tool_calls: Some(delta_calls) }, finish_reason: Some("tool_calls"), usage })
        });
        Ok(Box::pin(stream))
    }
}
```

Both branches use `stream::once` — exactly one `ChatChunk`. Grep for
alternative builders:

```text

→ (no hits)
```

There is no public or private API to queue a `Vec<ChatChunk>` for a single
`chat_stream` call. Consequently:

- The consumer's accumulation loop
  (`think.rs:110-125` `while let Some(cr) = llm_stream.next().await`)
  executes exactly once per mock turn.
- The `tool_call_map` keyed by `dc.index` (`processor.rs:64-83`) always

  the multi-fragment assembly path is dead for mock-driven tests.

  (`processor.rs:104-135`) is unreachable through the mock (only the

### Errors and cancellation (partially modelled)

`chat_stream` error/cancel path (`mock_llm.rs:399-422`):

```text
if let Some(d) = self.delay {
    let token = request.cancel_token.unwrap_or_default();
    tokio::select! {
        _ = token.cancelled() => return Err(ReactError::Other("mock LLM stream cancelled".into())),
        _ = tokio::time::sleep(d) => {}
    }
}
match self.pop_response()? { ... }   // Err here propagates as a pre-stream error
```

Both error mechanisms fire BEFORE the stream is constructed:

1. `with_delay` + cancel → returns `Err(...)` from the `chat_stream`
   future itself (the consumer never gets a stream).
2. `with_error(...)` / empty queue → `pop_response()?` returns `Err`,
   propagated as `Err(...)` from the `chat_stream` future.

Once the stream is created, it emits exactly one `Ok(ChatChunk)` and
ends. There is no `Err` inside the stream body and no cancel-token
reference inside it. Therefore:

- Mid-stream error (N good chunks then `Err`) — not producible.
- Mid-stream cancellation (cancel after some chunks emitted) — not
  producible. The existing cancel test
  (`test_run_stream_cancelled_mid_llm_call`, `stream_channel.rs:1972-2038`)
  cancels during the 30s pre-stream `with_delay` sleep, not after any
  chunk emission (there are no chunks to emit before).

## Conclusion

The claim is supported. Call-level scripting is rich and faithfully
models multi-turn ReAct ordering. Stream-level scripting (chunk
sequences), agent-stream-level scripting (event sequences), mid-stream
errors, and mid-stream cancellation are absent. This means the
mock-driven test suite cannot reproduce the conditions that exercise
`run_think`'s accumulation loop, `process_stream_chunk`'s fragmented-
tool-call assembler, `parse_tool_args`'s DeepSeek repair, the chunk-loop
error-forwarding path (`try_send_or!` at `think.rs:111`), or real
mid-stream cancellation. These coverage gaps feed F-TST-01-P2-01 and
F-TST-01-P2-02; the corresponding regression validations (multi-chunk
content stream, fragmented tool-call assembly, DeepSeek-style repair,
mid-stream error, mid-stream cancel) cannot be written against the
current mock.
