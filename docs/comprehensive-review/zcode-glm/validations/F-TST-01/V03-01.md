## Claim

The `testing` feature properly gates test-only code: the `src/testing/`
module and its `prelude` re-export are compiled only under
`cfg(any(test, feature = "testing"))`. The feature is empty (unlock-only,
no implementation dependencies), is absent from both `default` and `full`,
and is scoped to `[dev-dependencies]` in the downstream CLI. No
production code path (in `echo-agent` or `echo-agent-cli`) depends on the
`testing` feature being enabled; all in-crate mock consumption is inside
`#[cfg(test)] mod tests` blocks. The feature does not leak into
production.

## Method

Static inspection of feature definitions and gates across both repos,
plus a compile check confirming the crate builds without the testing
module. Working directory
`/Users/ls/MyWork/code/ylp_agent_learn/lp-agent/echo-agent`.

```text
1. Inspect echo-agent/Cargo.toml feature table:
   sed -n '65,97p' Cargo.toml  → default=[], full=[...], testing=[]
   Confirm "testing" is NOT in default or full.
2. Inspect the cfg gate on the testing module:
   sed -n '59,60p;274,275p' src/lib.rs
   → #[cfg(any(test, feature = "testing"))] pub mod testing;
   → #[cfg(any(test, feature = "testing"))] pub use crate::testing::{...};
3. Enumerate [[example]] required-features referencing testing:
   grep -n "required-features = \[\"testing\"\]" Cargo.toml
4. Enumerate in-crate mock usage and confirm each is inside #[cfg(test)]:
   grep -rn "use crate::testing\|crate::testing::" --include="*.rs" src/
   For each hit, locate the enclosing #[cfg(test)] mod tests { ... }.
5. Inspect downstream CLI wiring:
   read echo-agent-cli/echo-agent-app-core/Cargo.toml lines 9-15 (prod deps)
   and 58-59 (dev-deps).
   grep -rn "testing" echo-agent-cli/Cargo.toml \
     echo-agent-cli/echo-agent-app-core/Cargo.toml \
     echo-agent-cli/echo-agent-eval/Cargo.toml \
     echo-agent-cli/src-tauri/Cargo.toml
6. Compile check (production gate):
   cargo check -p echo_agent --no-default-features --locked
   → must succeed (testing module cfg'd out; no production dep on it).
```

## Expected Result

- `testing = []` in the feature table; not a member of `default` or `full`.
- The gate `#[cfg(any(test, feature = "testing"))]` on both the module
  declaration and the prelude re-export.
- Exactly seven `[[example]]` entries with `required-features = ["testing"]`
  (examples are not production code).
- Every in-crate mock usage inside a `#[cfg(test)] mod tests` block.
- Downstream CLI: production `[dependencies]` do NOT enable `testing`;

- `cargo check -p echo_agent --no-default-features --locked` exits 0.

### Downstream CLI wiring (positive)

`echo-agent-cli/echo-agent-app-core/Cargo.toml`:

This is the canonical Cargo pattern: production builds use only the
`[dependencies]` features (no `testing`); test/example/bench builds unify
the `[dev-dependencies]` features, enabling `testing`. So a
`cargo build` of `echo-agent-app-core` does NOT compile the testing
module, while `cargo test` does.

Root `echo-agent-cli/Cargo.toml:50` declares the production echo-agent
dep with `features = ["mcp", "lsp", "human-loop", "subagent", "tasks"]`
— no `testing`. The `echo-agent-eval` and `src-tauri` manifests have no
`echo-agent` dependency that enables `testing` (grep-confirmed).
