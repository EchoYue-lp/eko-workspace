production runtime actually defends against. Specifically, no mock-driven

mock-driven suite therefore gives false confidence on those paths: green

### Unreachable production paths (consolidated)

Cross-referencing F-LLM-01 / F-LLM-02 / F-RCT-03, these production
behaviours are live but not mock-exercised:

1. **Multi-chunk SSE streaming** — `stream_post` (`client.rs:317-333`)
   yields one chunk per SSE event; a single turn emits many. The mock
   emits one chunk per turn (`stream::once`). The `run_think` accumulation
   loop (`think.rs:110-125`) runs once. → F-TST-01-P2-01.

2. **Fragmented tool-call delta assembly** — real providers stream a
   tool call across multiple `DeltaToolCall` deltas keyed by `index`,
   with `id`, `name`, and `arguments` arriving in separate fragments.
   The mock emits one complete delta per call. The
   `tool_call_map.entry(dc.index).or_insert_with(...)` accumulation
   (`processor.rs:64-83`) is exercised with at most one delta per index.
   → F-TST-01-P2-01.

3. **DeepSeek "fake-stream" argument repair** — `parse_tool_args`
   (`processor.rs:104-135`) strips trailing `}` / `]` / `,` to repair
   the corrupted argument fragments some providers emit (vLLM #42878).
   Only the unit tests at `processor.rs:185-271` (hand-crafted JSON
   strings) exercise this; no end-to-end streaming test reaches it
   through the assembler. → F-TST-01-P2-01.

4. **Mid-stream error forwarding** — the consumer's chunk loop
   (`let chunk = try_send_or!(tx, cr, ThinkOutcome::Abandoned)` at
   `think.rs:111`) handles `Result<ChatChunk>` per chunk. An `Err` chunk
   mid-stream is a real case (network drop, server error after SSE start,
   the `[DONE]`-sentinel edges noted in F-LLM-02). The mock cannot emit
   `Err` from inside the stream. → F-TST-01-P2-02.

5. **Mid-stream cancellation** — the real transport polls
   `is_cancelled()` between chunks (`client.rs:252-254`,
   `anthropic.rs:482-484`). The mock checks the token only before the
   stream is created. The existing cancel test cancels during the
   pre-stream `with_delay` sleep. → F-TST-01-P2-02.

6. **Structured `ToolFailure` routing** — the F-EXT-01 contract routes
   tool failures by `category → recovery` (e.g.
   `PartialSideEffect → VerifyThenRetry`). `MockTool` produces only
   `ToolResult::success(text)` / `ToolResult::error(msg)` (text-only,
   `failure: None`). No mock-driven test exercises the structured-
   failure routing. → F-TST-01-P2-03.

7. **Backpressure-drop conditions** — F-RCT-03-P1-01 / P2-01 established
   that intermediate events are dropped on `Full` and error terminals are
   droppable. The mock emits one chunk per turn, so the 256-slot buffer
   can never fill from the LLM side. The drop paths are structurally
   invisible to the mock-driven suite. → cross-reference F-RCT-03; not a
   new finding here, but the mock cannot regression-test any fix.

## Conclusion

The claim is supported. The mock-driven suite is green (7/7 on the
representative subset), but the green result does not imply coverage of
the hard streaming/tool/error/cancellation paths. Seven categories of
live production behaviour are structurally unreachable through the mocks.
This feeds findings F-TST-01-P2-01, F-TST-01-P2-02, and F-TST-01-P2-03,
and cross-references F-RCT-03-P1-01 / P2-01 (the backpressure defects
that the mock cannot reproduce). The positive side: usage recording
(`react_stream_records_real_usage_in_run_trace`,
`value_scoped_direct_answer_records_usage_in_child_trace`) and the
multi-turn ReAct cycle (`run_core_loop_tool_call_cycle_completes`,
`deepseek_tool_turn_replays_complete_assistant_message`) ARE faithfully
exercised, because those paths depend on call-level scripting (which the
mock does well), not on stream-level chunk shape (which it does not).

The practical takeaway for downstream tasks: a green mock-driven test
run is necessary but not sufficient evidence that streaming, structured
tool failure, mid-stream error/cancel, or backpressure paths work. Those
paths need either the mock-fidelity enhancements (F-TST-01-P2-01/P2-02/
P2-03 directions) or integration-level fixtures (recorded real-provider
SSE traces replayed through the consumer).
