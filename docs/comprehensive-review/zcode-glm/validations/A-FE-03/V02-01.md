## Claim

All in-component `useEffect` listeners and timers return proper
cleanup functions (no memory leak, no stale-closure accumulation
on unmount). Three module-scope singletons (`authStore` interval +
focus listener, `chatStore` autoSave timer) are never cleaned up
— a dev-only leak under HMR. The `TasksPanel` SSE `useEffect`
re-runs on every `tasks` update and its cleanup closes-and-leaves
rather than closes-and-deletes, so the re-open guard short-circuits
and SSE progress events stop after the first poll.

## Method

Static inspection of every `setInterval`, `setTimeout`,
`addEventListener`, and Tauri `listen(` call in
`echo-agent-cli/web-frontend/src/` (excluding `generated/`,
`*.test.*`), with each site checked for the matching cleanup
return.

```text
1. Inventory every timer / listener registration:
   grep -rn "setInterval\|setTimeout\|addEventListener\|listen<\|listen(" \
     echo-agent-cli/web-frontend/src \
     --include="*.ts" --include="*.tsx" \
     | grep -v node_modules | grep -v generated | grep -v "\.test\."

2. For each hit, open the surrounding useEffect and verify the
   return statement clears / removes / unlistens the same handle.

3. For module-scope registrations (outside useEffect), confirm
   absence of any dispose / import.meta.hot cleanup.

4. For TasksPanel SSE specifically, trace the close-and-reopen
   logic across two setTasks invocations:
   - read TasksPanel.tsx:51 (useState)
   - read TasksPanel.tsx:107-187 (SSE effect + cleanup)
   - trace eventSourcesRef.current lifecycle across setTasks
```

## Expected Result

- ~15-18 in-component sites, all returning a cleanup function.
- Module-scope singletons in `authStore` and `chatStore` lacking
  any dispose hook.
- `TasksPanel` SSE effect: cleanup closes all `EventSource`s but
  does not delete entries from `eventSourcesRef.current`, so
  the re-open guard `if (eventSourcesRef.current[task.id])
  return` skips re-opening.
