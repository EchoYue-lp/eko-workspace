## Claim

The chat message list has no virtualization (no library installed,
no manual windowing). It is bounded at `MAX_MESSAGES = 500` via
`trimToMax` on every grow path. All 500 bubbles render in the DOM
via `.map`. `MessageBubble` is `memo`'d but subscribes to
`chatStore.messages` directly, so on every `appendToken` reducer
every bubble re-renders (Zustand bypasses React's `memo`). Event
logs and tool output are bounded (A-FE-02 V03) and the chat log
region has `aria-live="polite"`.

## Method

Static inspection of the chat rendering path plus whole-tree
greps for virtualization libraries and bounds.

```text
1. Check package.json + imports for any virtualization library:
   grep -E "react-window|react-virtual|react-virtualized|@tanstack/virtual|virtuoso" \
     echo-agent-cli/web-frontend/package.json
   grep -rn "react-window|react-virtual|@tanstack/virtual|virtuoso" \
     echo-agent-cli/web-frontend/src

2. Locate the message list render and check for windowing:
   grep -n "messages\.map\|slice\|windowing\|virtualiz" \
     echo-agent-cli/web-frontend/src/components/chat/ChatPanel.tsx

3. Inspect MessageBubble subscriptions and memo wrapping:
   sed -n '153,220p' \
     echo-agent-cli/web-frontend/src/components/chat/MessageBubble.tsx

4. Confirm the messages-array reducer returns a new reference on
   every token (Zustand equality check default Object.is):
   sed -n '241,260p' \
     echo-agent-cli/web-frontend/src/stores/chatStore.ts

5. Inventory bounds already audited by A-FE-02 V03:
   grep -n "MAX_EVENTS\|MAX_EVENTS_PER_RUN\|LIVE_DETAIL_AUTOLOAD_CHARS\|MAX_MESSAGES" \
     echo-agent-cli/web-frontend/src/stores/*.ts \
     echo-agent-cli/web-frontend/src/components/chat/InlineToolCall.tsx \
     | grep -v test
```

## Expected Result

- Zero hits for any virtualization library in package.json.
- Zero hits for any virtualization import in src/.
- A single `.map` over the full `messages` array in `ChatPanel`.
- `MessageBubble` is `memo`'d AND subscribes to `chatStore.messages`
  directly.
- `chatStore.appendToken` returns a new messages array reference
  (so the Zustand selector reports a change on every token).
- Bounded event logs (`MAX_EVENTS=500`, `MAX_EVENTS_PER_RUN=300`)
  and a 256 KiB live-load cap on tool output.

    via `useMemo([chatMessages])`. Both caches invalidate on
    every `chatMessages` reference change.
  - **`chatStore.ts:241-249`** `appendToken` reducer:
    ```ts
    set((s) => {
      const idx = s.messages.findIndex((m) => m.id === id);
      if (idx === -1) return { messages: s.messages };
      const updated = [...s.messages];
      updated[idx] = { ...updated[idx], content: updated[idx].content + token };
      return { messages: updated };
    });
    ```
    Returns a new `messages` array on every token (the
    `[...s.messages]` spread). Zustand's default `Object.is`
    equality on `state.messages` therefore reports a change on
    every token → every `MessageBubble` subscriber re-renders
    (regardless of `memo`, which only blocks parent-driven
    re-renders).

    - `chatStore.ts:104` `MAX_MESSAGES = 500` (applied via
      `trimToMax` to every grow path: `addUserMessage`,

## Conclusion

Supports A-FE-03 V03's four sub-claims: (1) no virtualization
library installed; (2) `MAX_MESSAGES=500` bounds the in-memory
list but every bubble renders in DOM; (3) `MessageBubble`'s
internal `chatStore.messages` subscription bypasses `memo` and
re-renders every bubble on every token (A-FE-03-P2-01); (4) event
logs and tool output are bounded (A-FE-02 V03 confirmed). The
chat log region itself is accessible (`role="log"` +
`aria-live="polite"`). The rendering hot path is the single
highest-impact perf concern.
