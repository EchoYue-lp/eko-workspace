## Claim

The frontend has partial accessibility coverage. The chat log
has good `aria-live` and `Toggle` is exemplary, but the
`InterruptPromptDialog` modal lacks role, focus, Escape, and
backdrop-click semantics; `CommandPalette` and `SettingsDialog`
are partial (keyboard works, role/focus-trap missing); the
primary chat textarea is unlabeled; the mobile sidebar overlay
is not keyboard-dismissable; and ESLint (with react-hooks +
jsx-a11y enforcement) is configured but not installed or run.

## Method

Static inspection of every modal, the chat input, the layout
overlay, and the tooling baseline. Whole-tree greps for a11y
primitives.

```text
1. Inventory a11y primitives across all tsx:
   grep -rn "aria-\|role=" --include="*.tsx" \
     echo-agent-cli/web-frontend/src | wc -l
   grep -rn "<button" --include="*.tsx" \
     echo-agent-cli/web-frontend/src | wc -l
   grep -rn "tabIndex\|alt=" --include="*.tsx" \
     echo-agent-cli/web-frontend/src | wc -l

2. Inspect each modal for role/aria-modal/Escape/autofocus/focus
   trap/backdrop-click:
   sed -n '850,922p' \
     echo-agent-cli/web-frontend/src/components/task/TaskRuntimePanel.tsx
   cat echo-agent-cli/web-frontend/src/components/common/CommandPalette.tsx
   sed -n '330,360p' \
     echo-agent-cli/web-frontend/src/components/layout/SettingsDialog.tsx

3. Inspect the primary chat input for label:
   sed -n '855,875p' \
     echo-agent-cli/web-frontend/src/components/chat/ChatInput.tsx

4. Inspect the mobile sidebar overlay for keyboard dismissal:
   cat echo-agent-cli/web-frontend/src/components/layout/AppLayout.tsx

5. Inspect Toggle as the baseline-good example:
   cat echo-agent-cli/web-frontend/src/components/common/Toggle.tsx

6. Inspect the tooling baseline:
   cat echo-agent-cli/web-frontend/eslint.config.js
   cat echo-agent-cli/web-frontend/package.json | grep -E "eslint|scripts"
   cd echo-agent-cli/web-frontend && npm ls eslint
```

## Expected Result

- ARIA / role coverage: well under 50% of buttons (the codebase
  relies on native `<button>` semantics for most interactions).
- `InterruptPromptDialog`: missing role, aria-modal, Escape,
  autofocus, focus trap, backdrop click.
- `CommandPalette`: has keyboard nav + autofocus; missing role,
  aria-modal, focus trap.
- `SettingsDialog`: has Escape + backdrop click; missing role,
  aria-modal, focus trap.
- Chat textarea: no aria-label.
- Mobile sidebar overlay: onClick only, no Escape.
- `Toggle`: role="switch" + aria-checked + sr-only label.
- ESLint: config file present, ESLint not in devDependencies, no
  lint script, jsx-a11y not configured.

## Conclusion

Supports A-FE-03 V04's claims: the codebase has a partial a11y
baseline (good `Toggle`, good `aria-live` chat log, decent
CommandPalette keyboard nav) but three real gaps: (1)
`InterruptPromptDialog` is a non-interactive modal
(A-FE-03-P2-02); (2) the primary chat textarea is unlabeled
(A-FE-03-P3-05); (3) the mobile sidebar overlay is not
keyboard-dismissable (A-FE-03-P3-06). The deeper enabler is the
dead ESLint config (A-FE-03-P3-04): no automated check enforces
react-hooks or a11y rules, so these gaps were not caught at
authoring time and will not be caught at CI time.
