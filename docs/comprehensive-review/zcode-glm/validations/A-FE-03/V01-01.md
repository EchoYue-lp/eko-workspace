## Claim

The frontend has 13 non-test Zustand stores organized around
stable domain facts with no monolithic accidental owner. There is
exactly one runtime circular import (`chatStore ↔
conversationStore`) and exactly one store→component import
inversion (`subagentRunStore` → `components/compress/`).

## Method

Static inspection of every store under
`echo-agent-cli/web-frontend/src/stores/` and the dependency
edges between them, cross-referenced with the in-component
`getState()` call sites.

```text
1. List every non-test store file in src/stores/:
   ls echo-agent-cli/web-frontend/src/stores/*.ts | grep -v test

2. For each store, extract the import edges to sibling stores and
   to anything under components/:
   grep -nE "^import.*from '\./|from '\.\./components" \
     echo-agent-cli/web-frontend/src/stores/*.ts

3. For each cross-store import, find the runtime call sites:
   grep -n "useChatStore\|useConversationStore\|useSubagentRunStore" \
     echo-agent-cli/web-frontend/src/stores/*.ts

4. Confirm there is no parallel chat transport or sink:
   grep -rn "useWebSocket\|createChatStore\b\|subagentStore\b" \
     echo-agent-cli/web-frontend/src
```

## Expected Result

- 13 non-test store files (one per domain fact).
- Largest store ≤ ~600 lines; no single store exceeds ~1000 lines
  (the monolithic threshold).
- Exactly one bidirectional edge: `chatStore ↔ conversationStore`.
- Exactly one store→component import: `subagentRunStore` →
  `components/compress/subagentUsage`.
- Zero hits for `useWebSocket` (A-SRF-03 confirmed removal).
