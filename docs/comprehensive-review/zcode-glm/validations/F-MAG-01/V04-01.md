## Claim

Three robustness defects hold:

1. `TopologyTracker` silently swallows every internal `RwLock` error
   (poisoning, contention) — `add_node`, `record_call_with_duration`,
   `nodes`, `edges`, `stats`, and `clear` all use
   `if let Ok(...) = lock.write()` / `.unwrap_or_default()`, so a wedged
   lock produces an arbitrarily wrong graph with no log.
2. `TopologyCallback::on_tool_start` hardcodes the agent as
   `NodeType::Subagent` and the tool as `NodeType::Tool`
   (topology.rs:491-496); `record_call_with_duration` auto-creates nodes
   with the same hardcoded defaults (topology.rs:200-201). Orchestrator,
   Planner, and External nodes can never be produced via the callback or
   the convenience recorder.
3. `HandoffManager::handoff` spawns the agent execution via
   `tokio::spawn({ agent.execute(...); tx.send(result) })`
   (mod.rs:265-269) and awaits the result through a oneshot channel. If
   the caller drops the `handoff()` future (cancel, timeout, parent
   panic), the spawned task is **detached** — it continues running to
   completion, burning LLM and tool budget, exactly the anti-pattern
   F-SUB-02-P1-02 flagged for Team mode. The inline comment
   ("Use spawn to avoid holding the lock") is misleading —
   `HandoffManager.agents` is a plain `HashMap`, not a locked map, so
   there is no lock being released.

The handoff and topology test suites continue to pass (they do not
exercise failure injection, so the silent-swallow and detach behaviours
are not contradicted by green tests).

Node-misclassification evidence:

- `topology.rs:491-496` (`on_tool_start`):
  ```rust
  self.tracker.add_node(TopologyNode::new(agent, NodeType::Subagent));
  self.tracker.add_node(TopologyNode::new(tool, NodeType::Tool));
  self.tracker.record_call(agent, tool, "call");
  ```
  Every agent observed by the callback is labelled `Subagent`, even if it
  is the orchestrator or an external A2A service. Every target is labelled
  `Tool`, even if it is another agent (e.g. when the agent invokes
  `agent_tool` to dispatch a child).
- `topology.rs:200-201` (`record_call_with_duration`):
  ```rust
  self.ensure_node(from, NodeType::Subagent);
  self.ensure_node(to, NodeType::Tool);
  ```
  Convenience callers inherit the same hardcoded defaults. The five-variant
  `NodeType` enum (Orchestrator / Subagent / Planner / External / Tool)
  is only ever produced by `TopologyNode::new` when an explicit caller
  passes a different variant — and the only such callers are
  `demo24_topology.rs` and the topology unit tests.

Cancellation/timeout census for handoff:

- `grep -n "cancel\|timeout\|abort\|CancellationToken" echo-agent/src/handoff/mod.rs echo-agent/src/handoff/tool.rs` → **zero hits**.
- The `tokio::spawn` at `mod.rs:265-269` produces a `JoinHandle` that is
  dropped immediately (only the `tx`/`rx` oneshot is observed). On
  caller-side drop of the `handoff()` future:
  1. `rx.await` returns `Err(RecvError)` → mapped to
     `ReactError::Other("Handoff task failed to complete")` (mod.rs:271-273).
  2. The spawned task continues running — its `agent.execute(&full_prompt)`
     future is not cancelled, the LLM call completes, and `tx.send(result)`
     hits a dropped receiver (`let _ = tx.send(result)` ignores it,
     mod.rs:268).
- Misleading comment at `mod.rs:261`:
  `"Use spawn to avoid holding the lock and blocking other handoff requests during execute"`.
  `HandoffManager.agents` is `HashMap<String, Arc<dyn Agent>>` (mod.rs:145)
  — not a `RwLock`/`Mutex`. The lookup at mod.rs:195 holds a plain
  `&Arc<dyn Agent>` reference, cloned at mod.rs:262 before the spawn. There
  is no lock to release; the comment justifies the detach with a
  non-existent constraint. (The actual reason the spawn "works" is that
  `agent.execute(&'a str)` borrows `self` for the duration of the future;
  spawning moves ownership of the cloned `Arc` into the task so the borrow
  does not tie up `&self`. That is achievable without detaching from the
  caller's cancellation domain — e.g. by `.await`ing the future directly
  after the clone.)

Topological sibling concern: topology has no integration with

## Conclusion

Supports: TopologyTracker swallows every internal lock error silently;
TopologyCallback and the convenience recorder hardcode
`NodeType::{Subagent, Tool}` and therefore cannot produce the other
three node types via the callback path; `HandoffManager::handoff`
detaches from the caller's cancellation domain via `tokio::spawn` with
no cancel/timeout/abort propagation, and the inline comment's "lock"
justification is stale (the underlying map is not locked).

Does NOT support any claim that topology integrates with the subagent
lifecycle, or that handoff is cancellable. The two are siloed from the
subagent event bus and from the cancellation-token propagation pattern
that Sync/Fork/Teammate (and, after the F-SUB-02 fixes, potentially
Team) modes use.

Findings using this validation: F-MAG-01-P2-02 (handoff spawn-detach),
F-MAG-01-P3-02 (topology silent swallow), F-MAG-01-P3-03 (topology
misclassification), F-MAG-01-P3-04 (no SubagentEvent integration).
