## Claim

`HandoffResult` is an unstructured plain-string result that diverges from
the `SubagentOutcome` contract on every dimension that F-SUB-01 established
as load-bearing (status, artifacts, verification, touched_files, UTF-8
bounding). Handoff context preservation is shallow: the full
`Vec<Message>` history is flattened into a free-text
`[Conversation history]` section in the prompt, with no working_dir, no
tool surface inheritance, no run_id continuity, and no `SubagentEvent`
emission. `HandoffResult.return_to_source` is hardcoded to `false` and has
no path that ever sets it differently.

## Expected Result

- HandoffResult has no status, no artifacts, no verification, no
  touched_files. `output` is `String` with no length bounding.
- SubagentEvent is not imported or emitted by handoff/mod.rs.
- `return_to_source` is set in exactly one place, always to `false`.
- Context transfer carries only: source_agent name, free-text history,
  and a flat `HashMap<String,String>` metadata. No working_dir, no tool
  surface, no run_id.

`return_to_source` census:
- `grep -n "return_to_source" echo-agent/src/handoff/mod.rs` returns:
  - `mod.rs:138` — field declaration (`pub return_to_source: bool`)
  - `mod.rs:285` — `return_to_source: false,` (the only assignment site)
- The field is part of the public `HandoffResult` API, documented as
  "Whether to suggest returning control to the source agent" (mod.rs:138),
  but the producing code never sets it to `true`. It is dead within the
  producing path.

`handoff_chain` context update (mod.rs:293-339):
- Between steps, the chain shoves the previous step's `output` into
  `metadata["previous_output"]` (mod.rs:330) — a single-slot rolling
  buffer. Step N-2's output is overwritten when step N-1 runs. The chain
  does not preserve a structured transcript beyond the rolling metadata
  entry plus the appended `[user, assistant]` message pair
  (mod.rs:317-322).
- The chain forces `transfer_history = true` on every step
  (mod.rs:301-304), so each step receives the running history blob — but
  the blob is the flat-text concatenation, not the structured
  `Vec<Message>` that `SubagentContext` preserves.

- Log/artifact: none (static inspection).

## Deviations

The chain's `metadata["previous_output"]` rolling-overwrite behaviour is
an additional finding (the chain loses step N-2 output when step N-1
runs), but it has no production consumer (V02 confirmed `handoff_chain`
has zero callers), so it is folded into the dead-API framing of
F-MAG-01-P2-01 rather than filed separately.

## Conclusion

Supports: HandoffResult diverges from the SubagentOutcome contract on
every load-bearing dimension (status, artifacts, verification,
remaining_work, touched_files, schema versioning, UTF-8 bounding).
Handoff context preservation is shallow (free-text history, no tool
surface, no working_dir, no run_id, no events) compared to
`SubagentContext::from_parent`. `return_to_source` is dead within the
producing path.

Does NOT support any claim that handoff preserves context in a form
comparable to the subagent stack. The two stacks have incompatible
context models; a framework consumer switching a delegation call from
`AgentDispatchTool` to `HandoffManager` would lose all structured
context and the entire event stream.

Findings using this validation: F-MAG-01-P2-03 (result contract
divergence + dead `return_to_source` field).
