## Claim

The Shell, file, code, and Git tools handle paths and Unicode safely:
path-traversal and symlink-bypass attempts are confined by `resolve_path`,
no production panic-prone APIs or unsafe byte slicing of multibyte strings
exist in the inspected code, and streaming shell output decodes split UTF-8
sequences without corruption or panic.

## Expected Result

- Every file-tool entry point uses `resolve_path`; the path-confine +
  canonicalize chain rejects `..`, absolute-escape, and symlink bypass.
- Zero production `.unwrap()` / `.expect(` / `panic!` / `unreachable!`.
- No byte slicing of `str` that could land inside a multibyte character.
- Shell streaming recovers full Unicode code points from arbitrary
  pipe-read boundaries.

## Result

- Exit code: 0
- Summary:

1. **Path traversal confinement — passed.**
   `echo-tools/src/files/mod.rs:35-132` implements:
   - `normalize_path` (line 135) collapses `.` and `..` textually so the
     `starts_with(base)` containment check at line 59 cannot be bypassed by
     `../`-prefixed relative paths.
   - For existing targets, `std::fs::canonicalize(&normalized)` is called
     (line 74) and the canonicalized path is re-checked against the
     canonicalized base (line 82). Symlinks pointing outside the base are
     rejected with `"Path resolves via symlink to location outside allowed scope"`.
   - For write targets that do not yet exist, the *parent* directory is
     canonicalized and checked (line 96-113), preventing a write to a path
     whose parent is a symlink escaping the base.
   - When neither `base_dir` nor `working_dir` is set, behavior falls back to
     raw normalize + best-effort canonicalize (line 119-128) — no
     confinement, matching the documented contract.

2. **Equivalent confinement in code tools — passed.**
   `code.rs::validate_script_path` (line 89-141) rejects absolute paths and
   any `ParentDir`/`RootDir`/`Prefix` component (line 99-111), then
   canonicalizes both `base` and `resolved` and checks `starts_with` (line
   133). The Unix-only test at `code.rs:783` confirms a symlink inside the
   working dir pointing outside is rejected.

3. **Production panic-prone API scan — passed.**
   The `awk` filter that excludes `#[cfg(test)]` / `mod tests` /
   `*_tests` blocks returned no matches across all inspected files. All
   `.unwrap()` / `.expect(` occurrences are inside `#[cfg(test)]` modules.
   The two production mutex lock recoveries (`shell.rs:187`, `:211`, `:391`,
   `:442`; `code.rs:175`, `:244`, `:257`) all use the
   `unwrap_or_else(|poisoned| poisoned.into_inner())` pattern, which is
   panic-free and is the documented way to keep serving after a panic in
   another thread (deliberate, non-violating).

4. **Byte slicing — borderline-safe, no panic risk.**
   The only `&str` byte slices found outside test code are in
   `files/edit.rs:263` and `:265`:
   ```text
   while let Some(pos) = haystack[search_from..].find(needle) {
       let abs_pos = search_from + pos;
       let line_num = haystack[..abs_pos].lines().count() + 1;
       search_from = abs_pos + needle.len().max(1);
   }
   ```
   All three offsets (`search_from`, `abs_pos`, `search_from + needle.len()`)
   are derived from `str::find()`, which by contract returns byte offsets on
   UTF-8 boundaries; `needle.len()` is the byte length of a valid `&str`,
   also boundary-aligned. The slicing therefore cannot split a multibyte
   character and cannot panic. (See finding F-EXT-02-P3-02 for a
   documentation/restyle note; this is not a defect.)

   `files/edit.rs:281` truncates with the AGENTS.md-preferred
   `first_line.chars().take(30).collect()` form. `files/mod.rs:112` uses
   `file_name().unwrap_or_default()` (OsStr default, panic-free).
   `shell.rs` splits streams with `chars()` + `len_utf8()` at line 831-833.

5. **Streaming UTF-8 decoding — passed.**
   `IncrementalUtf8Decoder` (shell.rs:968-1020) buffers trailing incomplete
   bytes from each pipe read, emits valid prefixes, replaces invalid bytes
   with U+FFFD, and flushes any leftover bytes on `finish()` via
   `String::from_utf8_lossy`. The test `shell_stream_preserves_unicode_split_across_pipe_reads`
   (shell.rs:1511) verifies a single `€` (3-byte sequence) split across three
   separate reads is reassembled correctly.

## Conclusion

The path/Unicode edge-case claim is supported. The framework's file and code
tools enforce path confinement and symlink defense consistently through
`resolve_path` and `validate_script_path`; no production panic-prone APIs are
present in the inspected code; streaming shell output is UTF-8-safe under
arbitrary pipe-read boundaries. The two `&str[..]` slices in `edit.rs` are
safe by construction (find-derived offsets) but technically deviate from the
AGENTS.md "禁止字节截断" guidance — recorded as F-EXT-02-P3-02 for cosmetic
cleanup, not a correctness defect.

Supports findings: F-EXT-02-P3-02. Does not by itself address the worktree
path-injection concern (V04) or atomic-write concern (V03), which are
separate claims.
