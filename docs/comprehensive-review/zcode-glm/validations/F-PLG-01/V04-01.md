## Claim

Plugins can be reloaded, disabled, and uninstalled repeatedly. On each
operation, all live components (skills, hooks, MCP servers, Subagents, LSP
servers, monitors, themes, output styles) are removed from the runtime, and a
fresh reload re-registers them. The lifecycle callbacks (init/activate/
deactivate/shutdown) fire exactly the expected number of times across a
load→disable→enable→uninstall cycle. No component survives uninstall.

Live test run of the full-cycle integration test plus static inspection of the
disable/uninstall paths.

## Expected Result

- After `reload()`: 1 plugin loaded with 1 Subagent, 1 LSP language, 1 monitor,
  1 theme, 1 output style.
- After `disable()`: Subagent gone, themes empty, output styles empty,
  scheduler tasks empty, LSP servers empty, output-style projection cleared.
- After `enable()`: Subagent back, scheduler task restored.
- After `uninstall()`: plugin directory removed, registry empty, Subagent gone,
  scheduler tasks empty.
- Lifecycle across reload→configure→uninstall: init=1, activate=3,
  deactivate=2 (before uninstall), then deactivate=3 + shutdown=1 after
  uninstall.
- Preferences (active theme, active output style) survive a runtime drop +
  recreate.

  **`native_lifecycle_brackets_reload_configure_and_unregisters_on_uninstall`**
  — registers a counting lifecycle, reloads, configures, uninstalls, then
  re-scaffolds + re-registers. Counts confirmed: init=1, activate=3,

  **`theme_and_output_style_preferences_survive_runtime_restart`** — activates
  a theme + output style, drops the runtime, recreates it, asserts
  preferences persisted and the output-style projection is re-injected.

  **Steady-state unload paths inspected:**
  - `disable(name)` (`plugin_runtime.rs:242`): scans fresh candidate,
    `candidate.disable(name)`, `apply_candidate` swaps state (previous
    components unloaded, candidate without the plugin wired), fires
    `PluginDisabled` hook. On apply error, `restore_enabled_state` rolls back
    the registry flag.
  - `uninstall(name, keep_data)` (`plugin_runtime.rs:287`): if enabled, calls
    `disable(name)` first (which unwires components); then
    `state.registry.uninstall(name, keep_data)` removes the directory +
    in-memory entry + optional data dir; then `state.lifecycle.unregister(name)`
    runs deactivate+shutdown. The registry `uninstall`
    (`registry.rs:411`) removes the directory BEFORE the in-memory entry, so a
    failed delete leaves the live registry truthful (test
    `test_uninstall_keeps_registry_entry_when_directory_delete_fails`,
    registry.rs:1222).
  - `reload()` (`plugin_runtime.rs:201`): builds a fresh candidate registry,
    scans, `apply_candidate`. Because `apply_candidate` does a full
    unload-previous/wire-candidate (not a diff), a reload with no manifest
    changes produces an equivalent live state; repeated reloads are idempotent
    (init once, activate/deactivate cycle).

  **Component coverage on unload** (`unload_agent_components`,
  `plugin_runtime.rs:1157`):
  - Subagents: `unregister_subagent(name)` per agent.
  - Skills: `unregister_skills_by_source("plugin:{name}")`.
  - Hooks: `hook_registry.unregister(&HookSource::Plugin(name))`.
  - MCP: `disconnect_mcp(server)` per server (also removes adapted tools).
  - LSP: replaced wholesale via `std::mem::replace` + `shutdown_all` on the
    old manager (`plugin_runtime.rs:650-653`).
  - Monitors: `replace_plugin_monitors` removes previous + adds candidate.
  - Themes/output styles: replaced via `state.prepared` swap (no live agent
    registration to clean; projection cleared if active style no longer
    present).

## Deviations

None. One observation (not a deviation): MCP `load_mcp_config`
(`capabilities.rs:1251`) returns `Ok(clients)` even when some servers in a
config fail to connect — `wire_all` (`plugin.rs:348-358`) compensates by
comparing `expected_servers` vs connected and marking the plugin failed if any
are missing, which triggers full rollback. Partially-connected servers are
disconnected during rollback. No leak.
