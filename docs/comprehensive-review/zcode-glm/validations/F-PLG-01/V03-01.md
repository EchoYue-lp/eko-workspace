## Claim

If a plugin reload/activation fails midway (lifecycle deactivation failure,
monitor replacement failure, agent-component wiring failure, or lifecycle
activation failure), previously-registered components from the prior state are
restored. No partial candidate state leaks into the live runtime. The
`PluginLifecycleManager` removes a stale registration before running cleanup
callbacks so a failed cleanup cannot block re-registration.

## Expected Result

- `apply_candidate` detects failure at four checkpoints and restores the
  previous registry/framework/prepared/lifecycle/LSP/monitors on each.
- `replace_agent_components` unloads previous, wires candidate; on candidate
  failure it unloads the partial candidate and re-wires the previous registry.
- A failed lifecycle `activate` during `register_lifecycle` cleans up
  (unregister runs shutdown) so the plugin can be re-registered.
- `PluginLifecycleManager::unregister` removes the map entry before invoking
  deactivate/shutdown, so a failing cleanup cannot leave a stale registration.
- The three targeted tests pass.

## Result

- Exit code: 0
- Summary: All rollback paths confirmed by code + tests.

  **Checkpoint 1 — lifecycle deactivation failure** (`plugin_runtime.rs:575`):
  `state.lifecycle.deactivate_all()` runs before any swap. On error, it
  re-activates the previous set (`activate_enabled(previous_plugins)`),
  shuts down the replacement LSP, and returns Err. No state mutated.

  **Checkpoint 2 — monitor replacement failure** (`plugin_runtime.rs:591`):
  `replace_plugin_monitors` itself rolls back (removes added, restores
  removed) on partial failure; `apply_candidate` then shuts down replacement
  LSP and re-activates previous lifecycle.

  **Checkpoint 3 — agent-component wiring failure**
  (`plugin_runtime.rs:612`, `replace_agent_components:804`):
  `replace_agent_components` runs inside an agent write lock: it calls
  `unload_agent_components(previous)`, then `wire_all(candidate)`. If
  `wire_all.errors` is non-empty OR `register_plugin_agents` fails, it
  unloads the partial candidate (`unload_agent_components(wiring.components_by_plugin,
  candidate_prepared)`) and re-wires `previous_registry` via a second
  `wire_all` + `register_plugin_agents(previous_prepared.agents)`. The
  returned `FailedAgentComponents` carries the restored registry/framework/prepared.
  `apply_candidate` then rolls back monitors and LSP and re-activates previous
  lifecycle (`plugin_runtime.rs:624-647`).

  **Checkpoint 4 — lifecycle activation failure** (`plugin_runtime.rs:655`):
  After the agent swap + LSP swap succeed, `activate_enabled(candidate_plugins)`
  runs. On error: `deactivate_all()`, then a full `replace_agent_components`
  rollback swapping candidate→previous (unloads candidate, re-wires previous),
  restores previous LSP (shuts down candidate LSP), restores previous monitors,
  and `activate_enabled(previous_plugins)`.

  **Lifecycle unregister safety** (`lifecycle.rs:153`): `unregister` does
  `self.plugins.remove(plugin_id)` FIRST, capturing the `ManagedLifecycle`
  into a local, then runs deactivate/shutdown on the local. A failing cleanup
  returns `Err(errors)` but the entry is already gone — re-registration via
  `register` succeeds. Test
  `failed_unregister_still_removes_stale_registration` (lifecycle.rs:365) and
  `failed_native_lifecycle_registration_shuts_down_and_can_retry`
  (plugin_runtime.rs:1700) confirm.

## Deviations

None. One observation: `init` is one-shot (`lifecycle.rs:103`, `initialized`
flag), so on rollback re-activation of previous plugins calls `activate` but
NOT `init` again — this is by design (init is one-time setup). The test
`native_lifecycle_brackets_reload_configure_and_unregisters_on_uninstall`
confirms init=1 across three reloads.

## Conclusion

Activation/reload failure rollback is comprehensive and tested. All four
failure checkpoints (deactivation, monitors, agent wiring, activation) restore
the previous live state. The lifecycle manager's remove-before-cleanup
ordering guarantees a failed cleanup cannot leak a stale registration that
would block re-registration. This closes the "without leaked registrations"
half of the task question for the failure case. No P0/P1 finding in this
area.
