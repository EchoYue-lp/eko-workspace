## Claim

Plugin manifests are parsed from a single YAML schema; component paths are
validated against `./` prefix and `..` traversal; dependencies are resolved via
Kahn's topological sort with semver `VersionReq` constraint enforcement, and
cycles are detected. There is exactly one definition site for each type (no
duplicate framework).

## Expected Result

- One definition site for `PluginManifest`, `PluginRegistry`,
  `PluginLifecycle`, `PluginCapability`.
- `validate()` rejects empty/non-kebab names, bad semver, paths not starting
  with `./`, and paths containing `..`.
- `resolve_dependencies` returns topological order; cycles return Err; missing
  deps return Err; version constraints enforced via `semver::VersionReq`.
- No parallel plugin manifest/registry implementation exists.

## Result

- Exit code: not-applicable (static inspection + grep)
- Summary: All expectations confirmed. Single definition sites located:
  - `manifest.rs:39` — `PluginManifest`
  - `registry.rs:68` — `PluginRegistry`
  - `lifecycle.rs:18` — `PluginLifecycle`
  - `capability.rs:27` — `PluginCapability`
  - `scope.rs:14` — `PluginScope`
- Manifest parsing: `PluginManifest::from_yaml`
  (`manifest.rs:314`) deserializes via `serde_yaml_ng`. Defaults: version
  `"0.0.0"` (`default_version`), `default_enabled = true` (`default_true`).
- Validation (`manifest.rs:332`): name non-empty + kebab-case
  (`is_kebab_case`, `manifest.rs:658`); version skips `"0.0.0"` sentinel then
  requires valid semver (`manifest.rs:352`); `validate_paths`
  (`manifest.rs:541`) checks `./` prefix AND rejects `..` for all 8 component
  fields; config entries validated for type/multiple/min/max/default
  consistency; dependency names checked for kebab-case.
- Dependency resolution (`registry.rs:807` `resolve_dependencies_matching`):
  builds adjacency graph + in-degree map for included plugins; for each dep,
  looks up `self.plugins.get(dep_name)` (Err if missing), checks `include`
  filter (Err if dependency disabled), then enforces version via
  `dep.satisfies(&dep_entry.manifest.version)` (Err on mismatch or malformed
  constraint). Kahn's algorithm with sorted queue (`registry.rs:862-883`);
  `sorted.len() != in_degree.len()` → `"Circular dependency detected"`.
- `PluginDependency::satisfies` (`manifest.rs:282`): `Simple` → `Ok(true)`;
  `Versioned` → `semver::VersionReq::parse(constraint)` then
  `semver::Version::parse(installed_version)` then `req.matches(&ver)`. Both
  sides must parse; malformed → `Err(String)`.
- Duplicate search: one hit each for `PluginRegistry`, `PluginManifest`,
  `PluginLifecycle`, `PluginCapability`, all in `echo-core/src/plugin/`.
  `NativePlugin` trait found only in `echo-agent/src/plugin.rs:460` (facade,
  no implementations — see F-PLG-01-P3-01).
- Scope resolution (`scope.rs:38`): User → `<plugin_base>/plugins/`
  (app-overridable); Project → `<root>/.echo-agent/plugins/`; Local →
  `<root>/.echo-agent/plugins.local/`. The configurable base dir is a single
  `OnceLock` in `mod.rs:83` (`PLUGIN_DATA_BASE_DIR`), set once at startup by
  `set_plugin_data_base_dir` / `set_plugin_data_base_dir_name`.
