## Claim

The desktop app cleans up all resources it allocated (PTY sessions, child
shells, background tasks) when the user closes the window. Specifically: a
window-close hook exists, `TerminalManager.close_all()` is reachable from the
shutdown path, and no `PtySession` outlives the app process.

## Method

Static reachability inspection of the GUI shutdown path. Working directory:
`/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`.

```text
1. Enumerate every window-event / close handler:
   grep -rn "on_window_event\|CloseRequested\|RunEvent\|prevent_close\|destroy" \
       echo-agent-cli/src echo-agent-cli/src-tauri

2. Find the GUI shutdown sequence (post-.run() block):
   read echo-agent-cli/src/tauri/desktop.rs:255-272

3. Find every caller of TerminalManager::close_all and every .kill() site:
   grep -rn "close_all\|\.kill()" echo-agent-cli/src echo-agent-cli/src-tauri

4. Confirm where terminal_manager is owned (reachable from desktop.rs?):
   read echo-agent-cli/src/tauri/state.rs (TauriState fields)
   grep -rn "terminal_manager" echo-agent-cli/src

5. Confirm the A-BOOT-01 GUI shutdown sequence is unchanged and inspect what
   it does/does not cover:
   read echo-agent-cli/src/tauri/desktop.rs:256-271
```

## Expected Result

- At least one window-close handler (`.on_window_event(...)` registering
  `CloseRequested`, or a post-`.run()` cleanup that reaches the terminal
  manager).
- `close_all` has at least one caller on the shutdown path.
- `terminal_manager` is reachable from the shutdown code.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary: claim **falsified**. There is no window-event handler.
  `close_all()` has zero callers. `terminal_manager` is not reachable from
  `desktop.rs`. PTY shells are orphaned on window close. Drives P2-01.

  Step 1 — `grep -rn "on_window_event\|CloseRequested\|RunEvent\|prevent_close"`
  across `src/` and `src-tauri/` returns **zero hits**. `build_tauri_app`
  (`mod.rs:29-773`) does not call `.on_window_event(...)`. `tauri.conf.json`
  has no close/prevention config (only a `"label": "main"` window at line 21).
  `capabilities/default.json` defines no close handling.

  Step 2 — the GUI shutdown sequence is the post-`.run()` block at
  `desktop.rs:256-268`:

  ```text
  let tauri_result = build_tauri_app(state.clone(), runtime.browser_runtime.clone())
      .run(tauri::generate_context!());          // :257-258 — blocks until window closed
  cancel_token.cancel();                          // :261
  if let Some(store) = state.tasks.runtime.as_ref()
      && let Err(error) = store.shutdown_hook_events().await { … }  // :262-266
  runtime.browser_runtime.shutdown().await;       // :267
  tauri_result.map_err(…)?;                       // :268
  ```

  This matches A-BOOT-01's documented sequence. **No terminal cleanup.**

  Step 3 — `grep -rn "close_all"`:

  | Location | Usage |
  |---|---|
  | `terminal.rs:256` | `pub fn close_all(&self)` — definition |
  | (no other hits) | — |

  `close_all` has **zero callers**. The only `kill()` site reachable from the
  command layer is `PtySession::kill` called by `close_terminal`
  (`terminal.rs:410`, per-session, only when the frontend explicitly sends it)
  and internally by `close_all` (which is itself uncalled).

  Step 4 — `terminal_manager` ownership:

  - `state.rs:12` — `pub terminal_manager: Arc<TerminalManager>` (field on
    `TauriState`).
  - `state.rs:20` — `terminal_manager: Arc::new(TerminalManager::new())`
    (constructed inside `TauriState::new`).
  - `mod.rs:39` — `.manage(TauriState::new(app_state, browser_runtime))`
    (handed to Tauri's state manager).

  `desktop.rs` holds `state: Arc<AppState>`, **not** `TauriState`. The
  `terminal_manager` lives inside the Tauri-managed `TauriState`, reachable
  only via `app.state::<TauriState>()` from inside a Tauri handler — which the
  post-`.run()` block in `desktop.rs` is not. So even if `desktop.rs` wanted
  to call `close_all`, it could not reach `terminal_manager` without an
  `on_window_event` hook (which runs inside the Tauri app context).

  Step 5 — A-BOOT-01 sequence confirmed unchanged. It covers:
  `CancellationToken` cancel, task hook dispatcher flush, browser runtime
  shutdown. It does **not** cover: `TerminalManager`, `SchedulerRunner` (per

  watcher shares `cancel_token`, so it is cancelled). This task adds the
  terminal gap to A-BOOT-01's list.

## Deviations

The claim is cleanly falsified — no window handler, no `close_all` caller, no
reachability. This is itself the finding (P2-01), not an environmental
deviation.

One uncertainty worth recording: whether the OS / Tauri sends SIGHUP to the
PTY child processes when the app process exits. If it does, the shells die on
their own and the user-visible severity of P2-01 is lower ("no leak in
practice"). If it does not (macOS reparents children to launchd), the shells
persist. This static inspection cannot determine that; the regression
validation (open terminal, `sleep 1000`, close window, `pgrep`) is required to
confirm. The finding stands regardless because the deterministic cleanup
(`close_all` + `kill()`) is the correct design and it is never invoked.

## Conclusion

Supports the A-SRF-02 window/terminal cleanup finding. The desktop app has no
window-close handler; `TerminalManager::close_all` is defined but unreachable;
`terminal_manager` is structurally isolated inside `TauriState`, inaccessible
to the only cleanup code (`desktop.rs` post-`.run()`). On every GUI window
close, live PTY shells are orphaned. This is the sole evidence for P2-01 and
extends A-BOOT-01's GUI-shutdown-sequence finding (which already noted the
absence of `SchedulerRunner` stop) with the terminal-cleanup gap.

## Follow-Up

P2-01 is opened against the missing cleanup. The recommended fix is to
register `.on_window_event` in `build_tauri_app` for `CloseRequested` (or
`Destroy`) and call `app.state::<TauriState>().terminal_manager.close_all()`
there. After landing, re-run as V04-02: `grep "on_window_event" src/tauri`
must return the registration, and `grep "close_all" src/tauri` must return at
least one caller. A manual regression scenario (open terminal → start
long-running shell → close window → confirm `pgrep` finds no orphaned shell)
confirms the runtime behavior.
