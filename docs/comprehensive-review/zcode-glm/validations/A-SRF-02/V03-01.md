## Claim

The GUI emits events to the frontend over a consistent, typed contract: every
channel's payload is a serde struct/enum, every channel has a documented
terminal guarantee, and routing metadata is separated from event data.

## Method

Static enumeration of every `app.emit(` site and its payload shape. Working
directory: `/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`.

```text
1. Enumerate every emit channel:
   grep -rn "\.emit(" echo-agent-cli/src/tauri | grep -oP 'emit\("[^"]+"'

2. For each channel, classify the payload as TYPED (serde struct/enum) or
   UNTYPED (hand-built serde_json::Map / serde_json::Value). Read:
   - chat.rs:27-208 (ChatEvent enum, emit_chat_event, emit_execution_event,
     emit_tool_execution_summary)
   - mod.rs:47-66 (browser bridge), mod.rs:700-760 (subagent bridge payload)
   - terminal.rs:25-170 (OutputEvent, ExitEvent)

3. Confirm the chat-event terminal guarantee (RunStatus + Done on non-running
   TurnStatus):
   read chat.rs:1341-1415 (TauriChatSink::on_event)

4. Confirm the terminal-exit guarantee (one exit per session):
   read terminal.rs:136-170 (reader_loop)

5. Inspect routing-metadata injection:
   read chat.rs:114-143 (emit_chat_event merges message_key/conversation_id)
```

## Expected Result

- Every channel's payload is a serde struct/enum (compile-time field check).
- Every streaming channel has a documented terminal marker.
- Routing metadata is separated from event data.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary: claim **partially falsified** — the contract is split: two channels
  are strongly typed, two are typed-via-struct, and the highest-cardinality
  channel (`execution://event`) is hand-built JSON. Drives P3-02.

  Step 1 — four emit channels:

  | Channel | Emit site |
  |---|---|
  | `browser://event` | `mod.rs:58` |
  | `chat://event` | `chat.rs:142` (via `emit_chat_event`) |
  | `execution://event` | `chat.rs:182` (via `emit_execution_event`) + `mod.rs:751` (subagent bridge direct emit) |
  | `terminal-output` / `terminal-exit` | `terminal.rs:154` / `:148` |

  Step 2 — payload typing classification:

  | Channel | Payload construction | Typing |
  |---|---|---|
  | `chat://event` | `serde_json::to_value(&ChatEvent)` (`chat.rs:120`) then merge routing | **TYPED** — `ChatEvent` enum, 20 variants, `#[serde(tag = "type")]`, per-variant `#[serde(rename)]` (`chat.rs:30-112`) |
  | `terminal-output` | `OutputEvent { id, data }` struct, base64 data (`terminal.rs:25-29`) | **TYPED** — `#[derive(Clone, Serialize)]` |
  | `terminal-exit` | `ExitEvent { id }` struct (`terminal.rs:31-34`) | **TYPED** |
  | `browser://event` | forwards framework `BrowserEvent` as-is (`mod.rs:58`) | TYPED (framework side) |
  | `execution://event` | `let mut map = serde_json::Map::new(); map.insert("kind", …); …; Value::Object(map)` (`chat.rs:162-182`, `mod.rs:703-752`) | **UNTYPED** — hand-built JSON map, string keys, no shared struct |

  The `execution://event` channel is fed from **three** independent
  constructors, none shared:

  - `emit_execution_event` (`chat.rs:153-183`) — generic helper taking
    `kind: &str`, `event: &str`, `agent: &str`, `subagent_run_id: &str`,
    `payload: serde_json::Value`.
  - The subagent bridge in `mod.rs:703-752` — builds its own
    `serde_json::Map::new()` with conditional `task_id` / `run_id` /
    `conversation_id` / `message_id` insertion (it does NOT go through
    `emit_execution_event`; it calls `app_handle.emit` directly at `:751`).
  - `emit_tool_execution_summary` (`chat.rs:185-208`) — wraps
    `emit_execution_event` with `kind="tool"`, forwarding the serialized
    `ToolExecutionSummary` as the field bag.

  No `ExecutionEvent` enum / struct exists. Field names (`"kind"`,
  `"subagent_run_id"`, `"run_id"`, `"event"`, `"agent"`, `"task_id"`,
  `"conversation_id"`, `"message_id"`, plus per-event inlined fields) are
  string literals typed by hand in three places.

  Step 3 — chat terminal guarantee confirmed. `TauriChatSink::on_event`
  (`chat.rs:1342-1388`) on `ChatDriverEvent::TurnStatus { status }` where
  `status != "running"`: emits `ChatEvent::RunStatus { status }` then (if the
  first emit succeeded) `ChatEvent::Done`. So the frontend receives
  `RunStatus` + `Done` as the terminal pair for every turn. Also calls
  `cancel_active_tools` before emitting (best-effort tool cleanup on turn end).

  Step 4 — terminal-exit guarantee confirmed. `reader_loop`
  (`terminal.rs:137-170`) emits `terminal-exit` exactly once per session on
  each of its three exit branches: `Ok(0)` EOF (`:148`), `Err(Interrupted)`
  continues (no emit), other `Err` (`:165`). So one `terminal-exit` per
  session that terminates. (Note: a session the user never closes and that
  never receives EOF emits no exit — but that is correct; the session is still
  alive.)

  Step 5 — routing metadata is **merged into** the event payload, not
  separated. `emit_chat_event` (`chat.rs:128-140`) takes the serialized
  `ChatEvent` JSON object and `map.insert("message_key", …)` /
  `map.insert("conversation_id", …)` at the top level. The emitted JSON is
  `{ "type": "<variant>", <variant fields>, "message_key": "...",
  "conversation_id": "..." }`. Functional, but the routing fields live
  alongside the event discriminator.

## Deviations

The "consistent typing" half of the claim is falsified by `execution://event`.
The terminal-guarantee half holds (chat `Done`, terminal `terminal-exit`).
The routing-separation half is mildly violated (merged into the same object).
These are the finding (P3-02), not environmental deviations.

## Conclusion

Supports the A-SRF-02 event-emission findings. The contract is workable but
inconsistent: `chat://event` and the terminal channels are typed via serde
structs/enums (good); `execution://event` — the channel carrying subagent /
tool / run / task lifecycles, the highest-cardinality feed — is hand-built
JSON with no shared schema, constructed independently in three places. The
chat and terminal terminal-event guarantees are correct. This validation is
the sole evidence for P3-02 and confirms the emit-side contract that A-SRF-03
(frontend consumption) must build against.
