## Claim

Every `ReactAgentBuilder` field is mapped to a runtime field on the
returned `ReactAgent` (either via `AgentConfig` or via a direct setter on
the agent) at `build()` time; no builder option is silently dropped
(orphaned).

## Method

Read-only static inspection. Enumerated all 50+ fields declared on
`ReactAgentBuilder` (`echo-agent/src/agent/react/builder.rs:26-109`) and
traced each one through the `build()` method (`builder.rs:854-1065`) to its
runtime destination. Categorised destinations as:

- **A** — flows through `AgentConfig::<field>` (the canonical config layer);
- **B** — flows through a `ReactAgent::set_*` setter that mutates an
  already-constructed agent (post-`new_inner`);
- **C** — flows through direct field assignment on the agent (bypasses
  both `AgentConfig` and setter APIs);
- **D** — used to choose between `ReactAgent::new` and
  `ReactAgent::new_with_subagent_registry`.

Source anchors used:

```text
echo-agent/src/agent/react/builder.rs:26-109    (struct decl)
echo-agent/src/agent/react/builder.rs:854-1065  (build() body)
echo-agent/src/agent/react/mod.rs:322-583       (new_inner)
echo-agent/src/agent/config.rs:44-195           (AgentConfig fields)
```

## Expected Result

Every builder field has at least one write site in `build()`. No field is
read in the builder struct but never consumed.

## Deviations

Two observations that do not invalidate the "no orphans" claim but are
worth recording:

1. Five builder options (Category C) bypass `AgentConfig` and write
   directly to `ReactAgent` internal fields. This is inconsistent with the
   majority pattern (Category A) but is not a defect — `new_inner`
   initialises each target field to a safe empty/`None` default
   (`mod.rs:514-581`), so the writes do not clobber pre-existing state.
   See F-RCT-01-P3-03.
2. `intervention_callbacks` is the only Category-C option that performs a
   direct list **replacement** rather than an `Option::Some(...)` assignment
   (`builder.rs:1061`). It is gated by `!is_empty()`, and the agent's
   field is initialised to `Vec::new()` at `mod.rs:515`, so the replacement
   is currently safe; the concern is purely forward-looking
   maintainability.

## Conclusion

The claim is **supported**. Every `ReactAgentBuilder` field has a runtime
destination; there are no orphaned options. The Category-C bypasses feed
finding F-RCT-01-P3-03 (config-layer inconsistency) but do not constitute
orphaning.
