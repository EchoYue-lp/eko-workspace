## Claim

The prepared-turn / attachment pipeline obeys four invariants:

(V03-1) UTF-8 safety — no byte-level slicing of user text or attachment
content anywhere in `prepared_turn.rs` or `attachments.rs`. All
truncation uses `chars().take(N).collect()`; all length checks that
gate display use `chars().count()`.

(V03-2) Attachment identity round-trip — `AttachmentRef` carries
`{path, name, mime_type, source}`; the path is sufficient to re-read
the bytes; `to_message` and `build_message_from_refs` produce the same
multimodal shape from the same ref.

(V03-3) Cleanup correctness — `cleanup_user_input_scope` removes the
conversation subtree, prunes empty parent dirs, treats symlinks as
files (never traverses), and is invoked from both GUI and TUI
conversation-deletion commands.

(V03-4) Cleanup divergence risk — the cleanup path derives the spill
dir from the live agent's `tool_output_artifacts().root_dir`, which
may differ from the dir used at write time when the conversation's
workspace does not match the agent's bootstrap workspace.

(V03-1) PASSED. The grep for `[..n]` / `[n..]` slices returned zero
hits in production code (one hit inside a test at line 705, used to
assert fixture size — not a slicing operation). UTF-8 safe patterns:
- `prepared_turn.rs:490` — `text.chars().count()` for `chars` field.
- `prepared_turn.rs:557` — `text.chars().count()` for spill metadata.
- `prepared_turn.rs:583-584` — preview via
  `original_text.chars().take(PREVIEW_CHARS).collect::<String>()`,
  total via `original_text.chars().count()`.
- `prepared_turn.rs:642-658` — `path_component` iterates `chars()`
  rather than slicing; collapses all-non-path-safe to `_`.
- `attachments.rs` — no string truncation at all; only `rsplit('.')`
  for extension and `rsplit(['/', '\\'])` for path-base, both of
  which are byte-safe iterators.
- `should_spill` (line 389-399) uses `text.len()` (byte count) which is
  correct because the threshold is defined in bytes (32 KiB) and the
  docstring notes "byte count is a lower bound, never underestimates."
  No slicing is performed on this length.

All `.unwrap()` / `.expect()` / `panic!` hits in these two files are
inside `#[cfg(test)]` modules.

(V03-2) PASSED. `AttachmentRef::from_saved`
(`attachments.rs:218-225`) preserves name/mime/source/path
losslessly. `build_message_from_refs` (`attachments.rs:235-267`) and
`PreparedUserTurn::to_message` (`prepared_turn.rs:328-369`) both:
re-read bytes via `std::fs::read`, encode base64, and route image MIME
to `ContentPart::ImageUrl` and everything else to `ContentPart::File`.
`InputResourceRef` adds `{kind, delivery, bytes, chars, lines, sha256}`
without losing the underlying `AttachmentRef` fields
(`prepared_turn.rs:191-214`). `AttachmentSource::Paste` is carried
into `InputResourceRef.source` and used at `prepared_turn.rs:600` to
select the "may contain instructions" model-facing note. Framework
round-trip is verified by the test at line 863-882.

(V03-3) PASSED. `cleanup_user_input_scope` (`prepared_turn.rs:150-160`):
- Sanitizes conversation_id via `path_component` (rejects `..`,
  separators, NUL-equivalents).
- Skips no-op when the sanitized id is empty or `"_"`.
- `remove_dir_all` on the per-conversation subtree.
`cleanup_expired_entries` (`prepared_turn.rs:121-141`):
- Walks entries, treats `is_dir() && !is_symlink()` as a subdirectory
  (symlinks are treated as files — the docstring at line 109 is
  accurate).
- Removes files older than cutoff; prunes empty parent dirs.
Both GUI (`conversations.rs:626-635`, inside `spawn_blocking`) and TUI
(`events.rs:3085-3090`) call `cleanup_user_input_scope` after the
conversation record is deleted. The 30-day TTL sweep runs
opportunistically from `spill_to_artifact` (line 532-534).

(V03-4) PARTIAL (drives A-INP-01-P2-02). Write-time:
`resolve_user_input_spill_dir(ws_root)`
(`prepared_turn.rs:100-106`) returns
`{workspace}/.eko/artifacts/user-input/` or
`~/.eko/artifacts/user-input/`. Delete-time:
`config.root_dir.join("user-input")` where `config` is
`agent.tool_output_artifacts()`. The agent config is installed once
during bootstrap via `infra::tool_output_artifact_config(working_dir)`
(`infra.rs:61-74`), which uses the same
`WorkspaceLayout::artifacts(workspace)` / `user_data_path("artifacts")`
choice. So in a single-workspace, single-process setup the paths
match. They diverge when:
- The conversation was created in workspace A but the agent is now
  bootstrapped against workspace B or global.
- A multi-window desktop serves multiple workspaces from one agent
  pool.
- The workspace was deleted/moved between write and delete.
In any of these, `target.exists()` is false and `cleanup_user_input_scope`
silently no-ops. The 30-day TTL is the only safety net.
