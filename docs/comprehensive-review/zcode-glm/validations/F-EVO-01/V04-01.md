## Claim

The framework's eval scorers and tests are deterministic and reproducible:
deterministic criteria (TestPass, OutputContains, ToolUsed, ToolNotUsed,
SafetyCheck, CitationValid, ValueMatch, AllOf, AnyOf) give bit-stable
results on identical input; the in-crate eval tests pass without network
or LLM calls; `EvalCase` is serde-serializable so consumer-defined fixture
cases are byte-reproducible. Non-deterministic criteria (LlmGraded,
SweBench, and any criterion run against a live agent) are explicitly
separated as distinct `SuccessCriteria` variants.

### Scorer determinism classification (eval/runner.rs:194-650)

| SuccessCriteria variant | Deterministic? | Evidence |
|---|---|---|
| `TestPass { command }` | yes | runs a command, checks exit code (`runner.rs:226`) |
| `OutputContains { substring }` | yes | substring match on output (`runner.rs:236`) |
| `ToolUsed { tool_name }` | yes | scans RunEvents for tool name (`runner.rs:252`) |
| `ToolNotUsed { tool_name }` | yes | negation of ToolUsed (`runner.rs:273`) |
| `AllOf(Vec)` / `AnyOf(Vec)` | yes (recursive) | boolean combine of children (`runner.rs:296,313`) |
| `SafetyCheck { forbidden, required }` | yes | pattern match on output (`runner.rs:448`) |
| `CitationValid { min, format }` | yes | regex/format count on output (`runner.rs:498`) |
| `ValueMatch { expected, tolerance }` | yes | numeric compare within tolerance (`runner.rs:577`) |
| `LlmGraded { assertions }` | **no** (LLM judge) | dispatches to `LlmGrader` via the grading agent (`runner.rs:203-225`) |
| `SweBench { repo_url, ... }` | **no** (network + live agent + external repo) | clones repo, runs agent, applies patch, runs tests (`runner.rs:333`) |

The non-deterministic criteria are explicitly distinct variants — a
consumer choosing `LlmGraded`/`SweBench` opts into non-determinism
knowingly. The deterministic set is bit-stable on identical Run + output.

### In-crate tests use synthetic inputs (no live LLM/network)

- `replay.rs:311 fn make_run(events: Vec<RunEvent>)` constructs synthetic
  Runs; tests assert on `tool_call_counts`, `error_count`,
  `contract_violations`, `detect_write_without_read`. No agent, no LLM.
- `regression.rs::from_traces` builds `EvalCase`s from synthetic `Run`s;
  tests `test_from_traces`, `test_from_traces_dedup`,
  `test_from_traces_skips_failed`. Deterministic.
- `runner.rs::trace_tool_criteria_are_enforced` and
  `test_runner_output_contains` assert criteria-checking logic directly.
- `grader.rs::test_parse_valid_response` parses a fixed JSON string — it
  does NOT call an LLM. (The `LlmGrader`'s network path is not exercised
  by any in-crate test, which is correct: it would be non-deterministic.)
- `trigger.rs` tests `test_trigger_accuracy_perfect` /
  `test_trigger_accuracy_false_positive` — deterministic accuracy math.

### EvalCase reproducibility

`EvalCase` derives `Debug, Clone, Serialize, Deserialize`
(`eval/mod.rs:67-90`). `SuccessCriteria` is `#[serde(tag = "type",
rename_all = "snake_case")]` (`eval/mod.rs:96`). So a consumer's eval
fixture (JSON/YAML) deserializes into a stable `EvalCase` and
re-serializes identically. The framework ships **no bundled fixture
files** (the `find` + `grep` for `success_criteria`/`EvalCase`/`project_fixture`
in `.json`/`.jsonl` returned nothing under `echo-agent/` outside
`target/`). Fixtures are consumer-supplied; the framework provides the
schema and the deterministic scorers.

### Regression / replay reproducibility

`RegressionSuite::from_traces(runs)` builds cases deterministically from
`Run` traces (dedup by lowercased task, skip non-Completed) — given the
same traces, the same suite is produced. `TrajectoryReplay::evaluate`
re-derives metrics from a stored `Run` deterministically. So regression
suites built from historical traces are reproducible as long as the trace
history is fixed.
