## Claim

`McpToolAdapter` adapts MCP `tools/list` schemas to the framework
`Tool` trait without semantic loss on the parameter schema or the
call-result discriminator; structured outputs, error semantics, and
risk mapping all flow through. Some metadata fields (`output_schema`,
`icons`, `title`, `meta`, `execution`) are intentionally not surfaced
and are recorded as a low-priority finding.

## Method

Static inspection of `tool_adapter.rs` + cross-check against
`echo-core::tools::Tool` / `ToolResult` definitions and
`echo-integration/src/mcp/types.rs::McpTool`.

```text
1. Read echo-integration/src/mcp/tool_adapter.rs (full file, 258 lines)
```

## Expected Result

- `parameters()` returns the MCP server's JSON Schema verbatim.
- `execute()` correctly maps `is_error`/`structuredContent` to framework
  `ToolResultKind` variants.
- Risk mapping honors `annotations.destructive_hint`/`read_only_hint`.

## Result

- Exit code: not-applicable (static review)
- Duration: n/a
- Summary: All three expectations hold.

  **`parameters()` is lossless.** `tool_adapter.rs:130-133` returns
  `self.tool.input_schema.clone()` verbatim — no normalization, no field
  stripping. The MCP server's JSON Schema is the framework Tool's parameter
  schema byte-for-byte.

  **`execute()` (`tool_adapter.rs:148-209`) maps MCP results onto
  `ToolResult` cleanly:**
  - `Ok(Err(react_error))` → `ToolResult::error(...)` with
    `ToolFailure::from_error(&error, may_have_side_effects)`; side-effect
    flag derived from `risk_level() != ReadOnly` (line 159). Metadata tag
    `result_type = "protocol_error"`.
  - `Ok(Ok(result))` with `result.is_error == true` →
    `ToolFailureCategory::Permanent` failure; if `structured_content` is
    present, also sets `data` and `kind =
    ToolResultKind::StructuredError { error_code: "mcp_is_error" }`.
  - `Ok(Ok(result))` success: if `structured_content` is present →
    `ToolResult::success_json(structured)` (kind=`Json`, `data` set) with
    `output = content_to_text(content)` retained as the LLM-facing view;
    else → `ToolResult::success(text)`.
  - **Extension preservation:** `result.extra` (the catch-all `flatten`'d
    non-standard fields from `McpToolCallResult.extra` at
    `types.rs:347-350`) is appended to `tr.output` as a JSON pretty-print
    block under `"\n\n附加字段:\n"` (lines 197-202). This is the explicit
    fix for "MCP server extra data silently dropped".

  **Risk mapping** (`tool_adapter.rs:135-145`):
  - `annotations.destructive_hint == Some(true)` → `Dangerous`.
  - else `annotations.read_only_hint == Some(true)` → `ReadOnly`.
  - else → `Standard`.
  Matches the framework's `ToolRiskLevel` taxonomy used by the permission
  system; no permission gating is added at this layer (consistent with
  AGENTS.md: MCP is user-configured, don't over-gate).

  **Tool-name sanitization** (`tool_adapter.rs:108-120`):
  `mcp__{sanitized_server}__{sanitized_tool}` — non-alphanumeric/`_`/`-`
  chars collapse to `_`, empty -> `unnamed`. Stable and unique per
  `(server, tool)` pair, so `disconnect_mcp` can later remove exactly the
  same tools (`capabilities.rs:1315-1332`).

  **Intentionally dropped (recorded as P3):** `McpTool.output_schema`,
  `title`, `icons`, `meta`, `execution` are not surfaced by the adapter.
  This is acceptable for the LLM-calling path (model only needs
  `parameters()` + `description()`), but `output_schema` validation
  against `structured_content` is not enforced.

  **In-file test coverage** (`tool_adapter.rs:213-258`): three unit tests
  cover (a) `result_type` preferring structured content over image/audio,
  (b) `result_type` for `Resource` content, (c) name sanitization
  including empty-string fallback. All three pass the parse check.

loss" claim in the task report, with the narrow exception of optional
metadata fields (P3 finding F-INT-01-P3-01).
