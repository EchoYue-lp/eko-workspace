## Claim

The MCP client transport lifecycle (connect → initialize → list tools →
call tool → disconnect) is implemented once, in `echo-integration/src/mcp/`,
and reached through a single application seam (`AgentCapabilities`), with no
duplicate MCP-client/transport implementation elsewhere in either repository.

## Method

Static inspection + grep across both repositories.

```text
1. Read echo-agent/echo-integration/src/mcp/mod.rs (McpManager)
2. Read echo-agent/echo-integration/src/mcp/client.rs (McpClient lifecycle)
3. grep -rn "McpManager|McpClient|McpToolAdapter" echo-agent (defn + uses)
4. grep -rn "McpManager|McpClient|McpToolAdapter|McpConfigFile" \
       echo-agent-cli (defn + uses)
5. Trace one live call chain:
   tauri/commands/mcp.rs::connect_mcp_server
     -> agent.connect_mcp_from_config (capabilities.rs:1149)
        -> McpManager::connect (mod.rs:73)
           -> McpClient::new (client.rs:46)
              -> transport (Stdio/Http/Sse)::new
              -> JsonRpcRequest "initialize"
              -> notification "notifications/initialized"
              -> fetch_tools ("tools/list", paginated)
```

## Expected Result

A single MCP client implementation in `echo-integration`; application reaches
it via framework `AgentCapabilities::connect_mcp_from_config`; no duplicate
client/transport code in `echo-agent-cli`.

## Result

- Exit code: not-applicable (static review)
- Duration: n/a
- Summary: Confirmed.

  Lifecycle in `client.rs:46-180`:
  1. **Connect/transport selection** (`client.rs:48-57`): `TransportConfig`
     match → `StdioTransport::new` / `HttpTransport::new` /
     `SseTransport::new`.
  2. **Initialize handshake** (`client.rs:65-93`): builds `InitializeParams`
     with `MCP_PROTOCOL_VERSION = "2025-11-25"` (`types.rs:5`), sends
     `JsonRpcRequest::new("initialize", …)`, surfaces a structured
     `McpError::InitializationFailed` on JSON-RPC error or empty result.
  3. **`initialized` notification** (`client.rs:108-111`): fire-and-forget
     `notifications/initialized` via `transport.notify`.
  4. **Capability-gated discovery** (`client.rs:117-145`): `tools`,
     `resources`, `prompts` are only fetched when the corresponding
     `server_capabilities` arm is `Some`. `fetch_tools` (`client.rs:155-201`)
     paginates with `next_cursor` and a hard `MAX_PAGINATION = 100` /
     `Duration::from_secs(30)` timeout per page.
  5. **Tool call** (`client.rs:218-237`): `tools/call` JSON-RPC; maps a
     server-side JSON-RPC error into `McpError::ToolCallFailed { code,
     message }`.
  6. **Disconnect** (`client.rs:443-446` / `mod.rs:140-153`): `close()` →
     `transport.close()`. For stdio this `kill()`s the child and `wait()`s
     (`stdio.rs:339-353`). `McpManager::disconnect` also removes the entry
     from the `clients` map.

  Single-source verification:
  - `McpClient`/`McpManager`/`McpToolAdapter` are defined only under
    `echo-agent/echo-integration/src/mcp/`.
  - Framework exposure: `echo-agent/src/agent/react/capabilities.rs:1149`
    `connect_mcp_from_config`, `:1286 mcp_client`, `:1299 list_mcp_servers`,
    `:1315 disconnect_mcp` — all delegate to `self.tools.mcp_manager`.
  - Application consumers (`echo-agent-cli`): only `state.rs`,
    `browser/{mod,sidecar}.rs`, `tauri/commands/mcp.rs` reference
    `echo_agent::mcp::*`; none redefine client/transport types.
  - `McpConfigFile` is parsed via `serde_json::from_value` at
    `tauri/commands/mcp.rs:481` and stored in
    `state.rs:357 PluginState::mcp_config`.

- Log/artifact: none.
