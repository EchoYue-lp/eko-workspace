## Claim

(1) A meaningful number of `#[allow(dead_code)]` annotations exist in
production source, concentrated in framework modules — these are
struct fields populated but not read, or functions reserved for future use.
(2) Several source files exceed 2000 lines, with two exceeding 5000 lines.
(3) Both `Cargo.lock` files contain duplicate crate versions (38 in
echo-agent, 76 in echo-agent-cli), driven primarily by transitive
dependency majors diverging.

## Method

**Dead code search:**

```text
grep -rn '#\[allow(dead_code)\]\|#\[allow(unused' \
    echo-agent/echo-*/src/ echo-agent/src/ --include='*.rs' \
    | grep -v target | grep -v worktrees
grep -rn '#\[allow(dead_code)\]\|#\[allow(unused' \
    echo-agent-cli/src/ echo-agent-cli/echo-agent-app-core/src/ \
    --include='*.rs' | grep -v target | grep -v worktrees
```

**Oversized modules:**

```text
find echo-agent echo-agent-cli -name '*.rs' -not -path '*/target/*' \
    -not -path '*/.worktrees/*' -exec wc -l {} \; | sort -rn | awk '$1>=1000'
```

**Duplicate dependencies:**

```text
python3 -c "<parse Cargo.lock name+version pairs, report names with >1 version>"
```

## Expected Result

Per AGENTS.md "代码清理:无需兼容,过时代码可直接删": dead code should be
deleted, not annotated with `#[allow(dead_code)]`. Per the framework-layer
deletion rule (AGENTS.md "删除框架代码的判定"): framework `pub` API
options may be retained even without current callers, but internal dead code
should be removed. Oversized modules and duplicate dependencies are
maintainability concerns (P2/P3).

## Deviations

The dead-code count is based on `#[allow(...)]` annotations only. Actual
dead code without an annotation (detected only by `cargo`'s dead-code lint)
is not inventoried here — that would require a full compile with
`-D warnings` and parsing the output, which is out of scope for this
static pass. The duplicate-dependency analysis is lockfile-based and does
not attribute which direct dependency pulls each version (that is Q-DEP-01's
job).

## Conclusion

Supports findings:

- **Q-STA-01-P2-01**: ~50 production `#[allow(dead_code)]` in the framework,
  violating AGENTS.md's cleanup policy. Most are struct-field-reserved
  patterns; a targeted cleanup pass should either use the fields, expose
  them via a method, or delete them.
- **Q-STA-01-P2-02**: 25 files over 1000 lines, 2 over 5000 lines — a
  maintainability and review-difficulty concern. No hard line limit is
  codified in AGENTS.md, but files of this size impede navigation and
  increase merge-conflict surface.
- **Q-STA-01-P2-03**: 38/76 duplicate crate versions. The high-impact ones
  (hashbrown x5, rand x3, thiserror/syn x2, reqwest x2) add compile-time
  and binary-size cost. Detailed attribution and remediation deferred to
  `Q-DEP-01`.

## Follow-Up

- `Q-DEP-01` should attribute duplicate versions to their pulling direct
  dependencies and assess which can be converged by updating the direct
  dep's version.
- A future cleanup task (outside this catalog) could split the two 5000+
  line files (`task_runtime/executor.rs`, `tui/events.rs`) along
  responsibility boundaries.
- The dead-code cleanup should be done incrementally per AGENTS.md
  "随手清理是强制要求" — touch a module, clean its dead code in the same
  change.
