## Claim

The application ships exactly the identity types enumerated in the
task spec (`conversation_id`, `turn_id`, `run_id`, `execution_id`,
`task_id`, `subagent_id`, `artifact_id`), plus two correlation
identities (`message_key` for Tauri chat, `message_id` for the
frontend UI projection). Each identity has a deterministic
generation source, a persistence location, and a defined stability
across restart. No identity is duplicated across parallel
authorities.

## Expected Result

- Each identity has exactly one canonical generation site (or, for
  `conversation_id`, one per surface that all converge on the same
  persisted shape).
- All identities are deterministic where downstream consumers rely on
  stability (e.g. `execution_id` derivation).
- No parallel identity authority (no second `TaskClaim` constructor,
  no second `subagent_run_id` derivation).
- The frontend identity key is a faithful echo of a backend identity,
  not a parallel authority.
- `add_artifact` has at least one production caller.

### Restart-stability verification

- `conversation_id` survives restart: confirmed via
  `latestRunForConversation(conversationId)` at
  `taskRuntimeStore.ts:230` which calls
  `file_store::latest_run_for_conversation` at `file_store.rs:84-92`.
  The query scans on-disk `run-state.json` files and filters by
  `r.conversation_id == conversation_id`. The link is structural, not
  cached.
- `task_id` survives restart: confirmed via
  `file_store::get_plan` at `file_store.rs:125-132` which reads
  `plan.json` (rebuilt from `events.jsonl` on `rewrite_plan`).
- `execution_id` survives restart: confirmed via
  `recoverable_subagent_result` at `store.rs:2039-2078` which folds
  events keyed on `(task_id, execution_id)`. A-TSK-04 V01 documents
  the test `boot_recovery_reuses_completed_subagent_without_redispatch`.
- `turn_id` / `run_id` do NOT survive restart — by design. Each
  Task-mode turn is a fresh run. This matches the "trajectory + new
  turn" recovery model F-RCT-05 V01 established.

## Deviations

One: `add_artifact` has zero production callers, contradicting the
expectation that "each persisted type has at least one producer".
This is filed as P3-01 and does not affect the identity-continuity
conclusion (the rest of the matrix is sound).

## Conclusion

Supports: the identity-continuity headline. Seven of the eight
enumerated identity types have deterministic generation, defined
persistence, and stability appropriate to their role. The
conversation→run link is rebuilt at query time so restart preserves
the relationship.

Supports: the "no parallel authority" invariant — every identity
has exactly one canonical generation site and one persistence
location. The frontend's `subagentRunStoreKey` is a faithful echo
of `execution_id`, not a second identity.

Does NOT support: the implicit assumption that `Artifact` is a
live persisted type. It is dead code (P3-01).

Findings using this validation: P3-01 (dead artifact surface).
