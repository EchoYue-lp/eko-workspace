## Claim

Every persisted file type in the persistence stack has a defined
corruption-handling policy. The policies converge on a single
discipline: either (a) surface corruption as a typed `Err` so the
caller can recover, alert, or fail loud; or (b) gracefully truncate
a partial tail (the append-only journal case). No file type silently
swallows corruption, and no file type bricks the run without a
recovery path.

## Expected Result

- All `read_*` functions return `Err` on corrupt JSON (fail loud) OR
  gracefully truncate a partial tail (append-only journal case).
- The policies converge — no two file types in the same persistence
  stack use incompatible corruption-handling disciplines.
- The TaskRuntime events.jsonl either errors out uniformly OR
  truncates uniformly; it does not leave the run in an unusable
  intermediate state.

### Inconsistency evidence

The two `events.jsonl` readers in the SAME application diverge:

```text
file_shadow::read_events (TaskRuntime authority):
  for (i, line) in text.lines().enumerate() {
      let line = line.trim();
      if line.is_empty() { continue; }
      let ev: RuntimeTaskEvent = serde_json::from_str(line)
          .map_err(|e| ShadowError::Decode(format!("line {}: {}", i + 1, e)))?;   ← errors out
      out.push(ev);
  }

tool_execution::read_journal_repairing_last_line (sister authority):
  loop {
      let bytes = reader.read_line(&mut line)?;
      if bytes == 0 { break; }
      if line.trim().is_empty() { last_good_offset = offset; continue; }
      match serde_json::from_str::<JournalRecord>(&line) {
          Ok(record) => { records.push(record); last_good_offset = offset; }
          Err(error) => {
              if reader.fill_buf()?.is_empty() {                 ← last line?
                  tracing::warn!("discarding malformed final tool journal line");
                  truncate_to = Some(last_good_offset);           ← truncate
                  break;
              }
              return Err(error.into());                          ← mid-file: error
          }
      }
  }
  if let Some(length) = truncate_to {
      OpenOptions::new().write(true).open(path)?.set_len(length)?;  ← apply truncation
  }
```

The tool-execution reader implements the "gate 2" the TaskRuntime
docstring (file_shadow.rs:113-117) defers as future work:

```text
file_shadow.rs:113-117 docstring:
  "Atomicity: the append is serialized by the store mutex (single writer),
   and the line is written with a trailing newline. A crash mid-append can
   at worst lose the last partial line — `read_events` skips empty lines
   and a future hardening pass (gate 2) will truncate a partial tail."
```

The deferral is acknowledged but not implemented, even though the
application has the helper available locally.

### Why this matters

The TaskRuntime events.jsonl is the **most load-bearing** append-
only file in the persistence stack: it carries plan revisions, task
status transitions, subagent lifecycle, tool boundaries, recovery
blockers, and review outcomes. Bricking it on a partial tail is
strictly worse than bricking the tool-execution journal (which is
already recovered).

Concretely: a partial tail in events.jsonl causes:
1. `read_events` returns `Err` → `recover_incomplete` cannot list
   todos or boundaries for this run.
2. `next_seq` returns `Err` → `append_event_line` fails → the run
   cannot accept new events.
3. `rewrite_plan` returns `Err` → plan.json/run-state.json cannot be
   refreshed.
4. `list_run_ids` still enumerates the run directory, but every read
   on it fails.
5. The GUI's `loadByConversation` returns an error to the frontend;
   the right-rail panel shows the error state with no recovery.
6. The only recovery is manually editing
   `~/.eko/tasks/<run_id>/events.jsonl` to remove the partial line.

## Deviations

One: the policy does NOT converge. The two `events.jsonl` readers in
the same application use different disciplines. Filed as P2-01.

## Conclusion

Supports: the "fail loud" half of the claim — every `read_*` function
returns `Err` on corrupt JSON. None silently swallows (with the
F-RCT-05-P2-02 prior exception of the resume consumer swallowing the
`Err` end-to-end).

Does NOT support: the "policies converge" half. The TaskRuntime
events.jsonl has no partial-tail recovery, while the tool-execution
journal does. The TaskRuntime docstring explicitly defers this as
"gate 2".

Does NOT support: the "no file bricks the run without recovery"
half. A partial tail in events.jsonl bricks the run for a non-
developer user (manual JSONL edit required).

Findings using this validation: P2-01 (TaskRuntime events.jsonl
partial-tail recovery gap).
