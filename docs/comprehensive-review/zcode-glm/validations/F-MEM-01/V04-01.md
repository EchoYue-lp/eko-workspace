## Claim

The transcript projection (`project_message` / `restore_message`) round-trips
losslessly for the four canonical roles and multimodal content, and the
`SnapshotManager` preserves message-history identity across capture/rollback.

## Method

Static inspection of the projection helpers and the snapshot manager, plus
review of their in-tree tests.

```text
read echo-agent/echo-state/src/memory/conversation.rs (1-220, project_message,
  restore_message, restore_projection_meta, MessageProjectionMeta)
read echo-agent/echo-state/src/memory/snapshot.rs (1-306, StateSnapshot,
  SnapshotManager)
review tests:
  - conversation.rs:206 (projection_round_trips_empty_content_and_message_identity)
  - file_conversation.rs:654 (round_trip_messages_via_project_and_restore)
  - snapshot.rs:186-304 (capture/list/rollback/eviction/clear/metadata)
```

## Expected Result

- Round-trip preserves role, text, structured parts (image urls), tool calls,
  tool results, reasoning content, name, and tool_call_id.
- `SnapshotManager` returns the exact captured `Vec<Message>` on rollback
  (value semantics, no transform).

## Result

- Exit code: not-applicable (static inspection + test review)
- Duration: <1s
- Summary: **Both pass.**
  - **Projection round-trip.** `project_message` (conversation.rs:35-88)
    serializes the runtime `Message` into a `StoredMessage` plus an optional
    versioned `MessageProjectionMeta` envelope (`_echo_message_version=1`,
    conversation.rs:13-24) stored in `attachments_json`.
    `restore_message` (107-167) is the faithful inverse: role-specific
    reconstruction (system/user/assistant/tool), tool-call JSON parsed back
    into `Vec<ToolCall>`, tool-result JSON parsed back into
    `{tool_call_id, name}`, and the meta envelope applied last so structured
    `content`, `reasoning_content`, `name`, and `tool_call_id` win over the
    text projection. Unknown roles are an error, not a silent demotion
    (conversation.rs:151-156). Version mismatch is an error, not a silent
    drop (183-189). The test at file_conversation.rs:654 exercises a
    multimodal user message (text + image data URL), an assistant tool-call
    message, and a tool result message end-to-end through
    `project_messages` → `FileConversationStore.save_messages` →
    `FileConversationStore.get_messages` → `restore_messages`, asserting
    role, content shape, reasoning trace, and tool-call identity.
  - **SnapshotManager.** Capture/rollback is pure value semantics:
    `capture` (snapshot.rs:90-118) clones `messages.to_vec()` into a
    `StateSnapshot`; `rollback` (124-132) and `rollback_to` (135-140) return
    a clone of the captured snapshot and truncate the ring buffer. No
    serialization occurs in this module, so identity is preserved by
    construction. The ring-buffer eviction (112-115) drops the oldest
    entries when `max_snapshots` is exceeded; verified by
    `test_max_snapshots_eviction` (200-210). `SnapshotManager` is purely
    in-memory and is NOT persisted by this module — runtime checkpoints for
    cross-process resume live elsewhere (`echo_agent::state::RuntimeStateStore`
    per the module doc at mod.rs:11-13).

## Deviations

None for the round-trip claim. One observation (not a failure of this
claim): `SnapshotManager` is documented at snapshot.rs:1-2 as capturing
snapshots "after each ReAct iteration for rollback to a known-good state",
which is a run-scoped (in-memory) capability; it is correctly NOT persisted
to disk. Callers needing cross-restart recovery must use `ConversationStore`
instead.
