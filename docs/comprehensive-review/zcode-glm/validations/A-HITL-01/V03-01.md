## Claim

EKO keeps the agent-automation permission path and the direct-user
interaction path cleanly separate: agent tool calls go through
`PermissionStage` (stage 6 of `ToolExecutionPipeline`), which calls
the agent's installed `HumanLoopProvider`; direct-user interactions
(terminal, file picker, MCP server connection, TUI shell escape) do
**not** enter `PermissionStage` and are not gated by `permission_mode`.
If any direct-user command calls `IpcAuth::require_full_auto` or
`require_not_strict`, or if any direct-user command reads
`permission_mode` to decide whether to run, that falsifies the
"separate paths" half of the A-HITL-01 question and becomes a finding.

## Method

Static reachability trace of (a) the agent-tool permission path and
(b) every direct-user IPC / TUI command. Working directory:
`/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`.

```text

   execute_tool_with_policy, which is reached only from the tool

   grep -rn "execute_tool_with_policy\|PermissionStage" \
       echo-agent/src/agent --include="*.rs" | grep -v test

3. For each direct-user command, identify the actual gate:
   grep -rn "permission_mode\|IpcAuth::\|require_full_auto\|require_not_strict" \
       echo-agent-cli/src/tauri/terminal.rs \

5. TUI direct-user shell escape + external editor:

       echo-agent-cli/src/tui --include="*.rs" | grep -v "//\|test"
```

## Expected Result

- One agent-tool permission entry (`PermissionStage` in
  `pipeline.rs`), reached only via `execute_tool_with_policy`.
- Every Tauri direct-user command uses input validation (path
  validator / executable allowlist / URL scheme / per-session
  consent / size cap), **not** `permission_mode`.
- Zero call sites for `IpcAuth::require_full_auto` /
  `require_not_strict` outside `error.rs`.
- TUI `!<shell>` and `$EDITOR` invocations do not enter
  `PermissionStage`.

## Conclusion

Supports A-HITL-01's direct-user-vs-agent-action separation (task
report Current Path "Direct-user interaction path" and Handoff items
1 and 2). The two paths are cleanly separate:

- **Agent automation** → `execute_tool_with_policy` →
  `ToolExecutionPipeline` → `PermissionStage` →
  `PermissionService::check_with_permissions_in_mode` →
  `HumanLoopProvider::request` (whichever provider is installed).
- **Direct-user** → Tauri IPC command or TUI key handler → input
  validation (path validator / executable allowlist / URL scheme /
  per-session consent / size cap / audit log) only.

No direct-user command calls `IpcAuth::require_full_auto` /
`require_not_strict`. The gates are dead code; the actual policy
(input validation only for direct-user actions) is correct under
AGENTS.md's local-assistant positioning. The defect is the dead
code + misleading doc-comment, captured as A-HITL-01-P2-02.
