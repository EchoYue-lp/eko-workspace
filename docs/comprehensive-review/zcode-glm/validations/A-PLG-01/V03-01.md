## Claim

When an application component fails during activation (a malformed agent/theme
/LSP/monitor/output-style in ANY plugin, or a Subagent registration failure
mid-batch), previously-registered components from the prior state are
restored. Partial candidate registrations — including a half-registered
Subagent batch where agents 1..N-1 are live before agent N fails — are fully
unwound before the previous state is re-wired. The
`PluginLifecycleManager` remove-before-cleanup ordering guarantees a failed
cleanup cannot block re-registration.

## Expected Result

- `prepare_application_components` failure (any component in any plugin)
  aborts the reload BEFORE any swap; the previous live state is untouched.
- `register_plugin_agents` partial registration (agents 1..N-1 live, N fails)
  is cleaned by `unload_agent_components`, which iterates the FULL prepared
  list; `unregister_subagent` is a safe no-op on never-registered names.
- After rollback, `replace_agent_components` re-wires the previous registry
  and re-registers previous Subagents.
- The two targeted tests pass.

## Result

- Exit code: 0
- Summary: All rollback paths confirmed by code + tests.

  **Prepare-phase failure (abort before swap).**
  `prepare_application_components` (`plugin_components.rs:96`) accumulates
  every parse/dedup error across all plugins into one `Vec<String>` and
  returns `Err(errors)` if non-empty (`:217-221`). `apply_candidate`
  (`plugin_runtime.rs:570-571`) maps this to `Err` and returns immediately —
  BEFORE `deactivate_all`, BEFORE any `mem::replace`/swap. The previous
  `registry`/`framework_components`/`prepared`/`lifecycle`/LSP/monitors are
  untouched. (This is also the source of finding A-PLG-01-P2-01: the
  granularity is the entire enabled-plugin set.)

  **Subagent partial-registration safety.**
  `register_plugin_agents` (`plugin_components.rs:444-475`) loops over
  `prepared`; for each it builds an instance (`build_plugin_agent(...)?` at
  `:459`, early-returns `Err` on failure), then registers
  `register_subagent_with_definition` + `register_subagent_factory`. If agent
  N fails to build, agents 1..N-1 are already in the registry. The caller
  `replace_agent_components` (`plugin_runtime.rs:844-867`) catches the `Err`,
  calls `unload_agent_components(agent, &wiring.components_by_plugin,
  &candidate_prepared)` — which iterates the FULL `candidate_prepared.agents`
  list (including the never-registered N..end) and calls
  `unregister_subagent(name)` per agent. `unregister_subagent`
  (`capabilities.rs:406-424`) returns `false` for absent names (no panic, no
  error), so the exhaustive cleanup correctly removes 1..N-1 and no-ops the
  rest. Then `wire_all(previous_registry)` + `register_plugin_agents(
  previous_prepared.agents)` re-wire the prior state.

  **Activation-failure full rollback.**
  If `activate_enabled(candidate_plugins)` fails after the agent swap
  succeeded (`plugin_runtime.rs:655-718`), `apply_candidate` runs a full
  reverse `replace_agent_components(candidate → previous)`, restores previous
  LSP (shuts down candidate LSP), restores previous monitors, and
  `activate_enabled(previous_plugins)`. The test
  `activation_failure_restores_previous_components_and_lifecycle` injects a
  failing lifecycle `activate` mid-reload and asserts the prior theme accent
  (`#5b8def`) is restored, init=1/activate=3/deactivate=1 counts hold, and
  the LSP server is still running.

  **Lifecycle remove-before-cleanup.** `PluginLifecycleManager::unregister`
  (`lifecycle.rs:153-179`) does `self.plugins.remove(plugin_id)` FIRST,
  capturing the `ManagedLifecycle` into a local, THEN runs
  deactivate/shutdown on the local. A failing cleanup returns `Err` but the
  entry is already gone — re-registration via `register` succeeds. Framework
  test `failed_unregister_still_removes_stale_registration`
  (`lifecycle.rs:365`) and app test
  `failed_native_lifecycle_registration_shuts_down_and_can_retry`
  (`plugin_runtime.rs:1700`) confirm.

  **Test output:**
  ```text
  test plugin_runtime::tests::failed_real_reload_restores_previous_live_components ... ok
  test plugin_runtime::tests::activation_failure_restores_previous_components_and_lifecycle ... ok
  ```
  The malformed-hook reload test writes invalid `hooks.yaml` content, expects
  the reload to fail with "hooks YAML parse", and asserts the prior subagent,
  theme, output style, monitor, and LSP are all still live.

## Deviations

None. One observation (not a deviation): `init` is one-shot
(`lifecycle.rs:103`, `initialized` flag), so on rollback the re-activation of
previous plugins calls `activate` but NOT `init` again — by design (init is
one-time setup). The test
`native_lifecycle_brackets_reload_configure_and_unregisters_on_uninstall`
confirms init=1 across multiple reloads.

## Conclusion

Application-component activation failures are comprehensively rolled back.
Prepare-phase failures abort before any swap; Subagent partial registrations
are safely unwound via exhaustive cleanup (relying on `unregister_subagent`
being a no-op on absent names); post-swap activation failures trigger a full
reverse swap. No partial candidate state leaks into the live runtime, and the
lifecycle remove-before-cleanup ordering guarantees failed cleanup cannot
block re-registration. This closes the "roll back cleanly" half of the task
question for the failure case.
