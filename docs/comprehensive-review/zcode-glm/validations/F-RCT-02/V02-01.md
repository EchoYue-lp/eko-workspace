## Claim

Terminal ownership is unambiguous: every terminal path the loop can
reach funnels through exactly one of four named finalize helpers
(`finalize_completed_run`, `emit_final_text`, `finalize_no_response`,
`finalize_max_iterations`) or a graceful `Abandoned`/`Cancelled`/
`Blocked` short-circuit. No two terminal arms race or double-emit a
`FinalAnswer`.

## Method

Read-only static enumeration of every `return` site inside
`run_core_loop` (`stream_channel.rs:494-756`) and the four
`phases::finalize::*` helpers (`finalize.rs:23-271`). For each arm I
recorded: (a) which outcome variant triggers it, (b) whether it yields
a `FinalAnswer` / `Error` event on the channel, (c) whether it calls
`finalize_run` (trace store mutation), (d) whether it fires
`SessionEnd`, and (e) whether it updates the TaskNode.

```text
echo-agent/src/agent/react/run/stream_channel.rs:509-516, 589-756
echo-agent/src/agent/react/run/phases/finalize.rs:23-271
echo-agent/src/agent/react/run/phases/think.rs:42-79 (Cancelled/Blocked)
echo-agent/src/agent/react/run/phases/prepare.rs:66-89 (BlockedAndDone)
```

## Expected Result

Each terminal arm has a single owner and a single `FinalAnswer` /
`Error` emission. The four `finalize_*` helpers partition the terminal
space without overlap.

Mutual exclusion: within one iteration, the branch at
`stream_channel.rs:654-702` selects exactly one of `run_tools` /
`verify_final_text` / `NoResponse` based on the ThinkOutput buffers, so
T1/T2/T3 cannot fire in the same iteration. T4 fires only when the
`for` loop exits naturally, which requires every prior iteration to
have hit `IterOutcome::Continue` (the only non-terminal iteration
outcome). T5–T10 are short-circuits that `return Ok(())` before the
iteration `match`, so they pre-empt T1–T4.

The only "non-terminal then terminal" sequence is the Stop-hook
continuation in `emit_final_text`: it returns
`ControlFlow::Continue(())` (`finalize.rs:200`) after emitting
`FinalAnswer`, which lets the loop drive another iteration. The
one-shot `state.stop_hook_continued = true` (`:199`) guarantees a
second Stop hook cannot continue again, bounding the continuation to
at most one extra loop traversal.

## Deviations

The trace-finalization column reveals an asymmetry: T1
(`finalize_completed_run` — the `final_answer`-tool success path, i.e.
the normal happy path for a tool-using agent) does **not** call
`snap.finalize_run`, while T2/T3/T4 do. This means a successful
tool-based turn leaves the trace run in `Running` status indefinitely.
This is a real defect, not a transition-correctness violation — see
finding **F-RCT-02-P2-03**. Terminal ownership itself (the claim under
test) is unaffected: each arm still has a single owner.

## Conclusion

The claim is **supported**. Terminal ownership is unambiguous; no two
arms race or double-emit `FinalAnswer`. The four `finalize_*` helpers
partition the terminal space cleanly and the short-circuit arms
(T5–T10) pre-empt them via early `return Ok(())`. The trace-finalization
asymmetry noted under Deviations is tracked separately as
F-RCT-02-P2-03 because it concerns observability state, not transition
correctness.
