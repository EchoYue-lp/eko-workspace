## Claim

Both EKO protocol projections (`eko:instruction-context` and
`eko:hot-memory-context`) survive context compression: they are recognised
as protected by the framework, excluded from compressor input, and
re-inserted at their original positions after every compression pass. They
are immune to the summary-accumulation defect F-CMP-01-P2-01 because
`replace_projection` removes the previous message before inserting the new
one.

## Method

Static read of the framework projection/protection machinery and the EKO
refresh helpers that wrap it. Cross-checked against F-CMP-01's compression
call graph.

```text
read echo-agent/echo-state/src/compression/mod.rs:30-62   (envelope + helpers)
read echo-agent/echo-state/src/compression/mod.rs:540-645 (apply_projections, replace_projection, remove_projection, has_projection)
read echo-agent/echo-state/src/compression/mod.rs:678-793 (is_protected, split_protected, merge_protected)
read echo-agent-cli/echo-agent-app-core/src/unified_memory.rs:137-186 (refresh helpers)
read echo-agent-cli/echo-agent-app-core/src/unified_memory.rs:217-267 (projection tests)
```

## Expected Result

A single choke point that (a) recognises the projection envelope, (b)
removes the previous message with the same marker, (c) re-inserts the new
message at the system/history boundary, and (d) tags it as protected so
`split_protected` excludes it from compressor input.

## Result

- Exit code: not-applicable (static inspection)
- Summary: Confirmed on all four points.

  **Envelope + recognition** (`mod.rs:30-62`): every projection message is
  prefixed with `<echo-agent-context-projection-v1>\nmarker=<json>\n`.
  `is_context_projection_message` (`:36-38`) returns true iff a message
  starts with that prefix; `projection_marker_prefix` (`:55-62`) builds the
  expected prefix for a given marker.

  **Replace semantics** (`mod.rs:546-611`): `apply_projections` skips
  no-op replacements (`projection_matches`, `:552-554`), then calls
  `remove_projection(marker)` (`:556`) before inserting the new wrapped
  message. `remove_projection` (`:635-645`) does `messages.retain`,
  dropping every envelope with that marker. So a marker is present at most
  once after any refresh — there is no append path that could let
  projections accumulate.

  **Insertion location** (`mod.rs:567-573`): replacements are spliced at
  `boundary`, the index of the first non-`System` message. So projection
  messages stay in the system prefix regardless of when the refresh fires.

  **Compression survival** (`mod.rs:678-791`):
  - `is_protected` (`:679-691`) returns `true` immediately when
    `is_context_projection_message(message)` is true — independent of any
    `protected_markers` registration. So both EKO projections are protected
    by default the moment they are written.
  - `split_protected` (`:747-773`) partitions messages into compressible
    and protected before the compressor runs; protected messages carry
    position metadata (`compressible_after` / `protected_after`).
  - `merge_protected` (`:781-793`) re-inserts each protected message near
    its original relative position from the tail. The compressor never
    sees projection messages, so it cannot summarise, drop, or duplicate
    them.

  **EKO wiring** (`unified_memory.rs:138-186`): all three refresh helpers
  acquire `agent.context().lock()`, build `Message::system(body)`, and call
  `context.replace_projection(MARKER, Some(message))` (or `None` when the
  body is empty, leaving a tombstone). `replace_projection`
  (`unified_memory.rs:150, 166, 184-185`) delegates to
  `apply_projections(&[ContextProjection { marker, message }])`. The
  round-trip is therefore the framework's, and inherits its guarantees.

  **Immunity to F-CMP-01-P2-01**: that defect arises because
  `SummaryCompressor::compress` partitions by `Role::System` and appends a
  new `[对话历史摘要]` system message without removing the previous one
  (`summary.rs:346-348`). Projections cannot hit that path: `split_protected`
  removes them from the compressible input before the Summary compressor
  runs. The existing test `instruction_projection_replaces_previous_workspace`
  (`unified_memory.rs:217-246`) confirms a second `refresh_instruction_projection`
  call produces exactly one envelope (`assert_eq!(projected.matches(...).count(),
  1)`).

## Deviations

None. The F-CMP-01 V02-01 conclusion (protected content survives) is
re-verified specifically for the two EKO projections.

## Conclusion

Both EKO protocol projections survive every compression pass and cannot
accumulate. The protection is structural (envelope recognition in
`is_protected`), not opt-in (no `add_protected_marker` registration is
needed for the two EKO markers). Supports the Current Path "Projection into
the agent" and the Handoff conclusion that downstream tasks may treat the
protocol suffix as stable across compression. Does not address whether the
projection *content* is current — that is the refresh-wiring question V03
covers (and where P1-01 lives).
