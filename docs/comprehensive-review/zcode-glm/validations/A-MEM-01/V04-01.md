## Claim

There are no duplicate memory stores: the hot layer (`MEMORY.md`) and the
warm layer (`store.json`) are two physically distinct files with distinct
purposes by design, and EKO's `create_memory_store_*` factories are thin
wrappers over the framework's `FileStore`. On workspace switch, both the
primary and pooled agents are rebound to the new workspace's store,
layer manager, and projections consistently. The instruction/memory file
protocol has no file watcher (external edits wait until switch/restart);
this is consistent with A-CFG-01's config-watcher-stale-after-switch and
config-not-reloaded-on-switch conclusions, and is the only residual gap.

## Expected Result

Exactly two store files per workspace (hot `MEMORY.md`, warm `store.json`),
one `FileStore` instance per agent, switch rebinds primary + pool to the
new pair, and the gap vs A-CFG-01 is confined to "no watcher for
instruction/memory files" rather than a duplicate-store or split-brain
defect.

## Result

- Exit code: 0
- Summary: Confirmed.

  **Two files, two purposes — not duplication.** Per workspace root `R`:

  | Layer | Path | Format | Owner writer | Owner reader |
  |---|---|---|---|---|
  | Hot | `<R>/.eko/MEMORY.md` | markdown body + YAML frontmatter | `MemoryLayerManager::write_memory_file` (`layer.rs:964-983`) | `InstructionProvider::load_hot_memory` (`instruction_provider.rs:251-259`) |
  | Warm | `<R>/.eko/memory/store.json` | typed KV JSON | `FileStore` via `create_memory_store_for_workspace` (`infra.rs:1354-1359`) | `TypedMemoryStore` / recall / search |

  Both files use the same `echo_agent_dir = <R>/.eko`
  (`WorkspaceLayout::state_dir`, `layout.rs:33-35`), so the layer manager
  (writes `MEMORY.md` at `layer.rs:307`) and the instruction loader (reads
  `MEMORY.md` at `instruction_provider.rs:252`) agree on the hot path.
  Verified for bootstrap (`runtime.rs:229-247` resolves
  `review_echo_agent_dir` from the same `resolve_memory_store_paths` call
  that produced the store) and for switch (`state.rs:946-947` derives
  `echo_agent_dir` from the same `mem_root` as the store).

  **Factories are thin.** `create_memory_store_at` (`infra.rs:1319-1349`)
  is `FileStore::new(path)` + dir creation + logging. The workspace
  (`create_memory_store_for_workspace`, `:1354-1359`) and global
  (`create_global_memory_store`, `:1364-1367`) variants just resolve the
  path and delegate. No second `Store` trait, no parallel KV — F-MEM-01
  V01-01 already established the framework has a single `Store` authority.

  **Switch rebinds both agents consistently.** `switch_workspace`
  (`state.rs:844-1032`):
  1. sets process CWD (`:854`);
  2. primary agent: `set_working_dir` + `refresh_dynamic_context` (both
     projections) (`:877-886`);
  3. pool: `apply_working_dir` (propagates `set_working_dir` +
     `refresh_dynamic_context` to every pooled agent) (`:889-891`);
  4. conversation store + runtime state store rebound (`:894-939`);
  5. `ReviewIntegration::rebind(new_echo_agent_dir, new_store)` (`:948-950`)
     — *before* any `create_layer_manager` call;
  6. primary agent: `install_memory_store` + `install_memory_layer_manager`
     (fresh manager from rebound RI) (`:965-973`);
  7. pool: `apply_memory_store(&mem_root)` (`:1012-1013`) — swaps store +
     layer manager on every pooled agent and records
     `memory_store_override` for future pool agents
     (`agent_pool.rs:632-684`, consumed at `:906-911`).
  `exit_workspace` (`state.rs:1052-1200`) is symmetric: restores global
  paths, `apply_memory_store_global` on the pool (`:1160`), and
  `refresh_dynamic_context(agent, None)` on the primary (`:1072`).

  **`memory_store_override` prevents stale-store pool agents.** A pool
  agent created post-switch reads `memory_store_override` first
  (`agent_pool.rs:906-911`), so it binds to the new workspace's store even
  though `shared.store` still holds the bootstrap instance.

  **Residual gap (P3-01) — no instruction/memory file watcher.** The
  config watcher (per A-CFG-01) observes only `echo-agent.yaml` and
  `hooks.yaml`. No watcher observes `user.md`, `project.md`, `local.md`,
  `learned-rules.md`, or `MEMORY.md`. `InstructionProvider` is a static
  loader (`instruction_provider.rs:14-23`); refresh fires only on the
  explicit triggers enumerated in V03. After a workspace switch, this is
  consistent with A-CFG-01-P1-01 (watcher targets not refreshed) and
  A-CFG-01-P2-04 (config not reloaded on switch): the new workspace's
  instruction/memory files are honored at the switch instant (the switch
  calls `refresh_dynamic_context`), but never hot-reloaded thereafter
  until the next switch or restart.

  **Layout asymmetry (P3-02).** Global warm store is `~/.eko/store.json`
  (`global_memory_paths`, `infra.rs:1274-1278`); workspace warm store is
  `<R>/.eko/memory/store.json` (`WorkspaceLayout::memory_store`,
  `layout.rs:59-61`). Each path is internally consistent and the
  resolution functions return matching pairs, so this is a cleanliness
  observation, not a correctness defect.

## Deviations

- `AgentPool::create_agent` (`agent_pool.rs:850-913`) first builds a pool
  agent via `infra::create_agent`, which itself constructs a `FileStore` at
  the resolved path (`infra.rs:354-357`). That store is immediately
  replaced by `install_store(effective_store)` (`agent_pool.rs:912-913`),
  where `effective_store = memory_store_override.or(shared.store)`. The
  transient bootstrap store is never read or written between build and
  replace (the agent is not running yet), so two `FileStore` instances
  never race on the same path. This is a minor inefficiency (one wasted
  `FileStore::new` per pool agent creation), not a duplicate-store defect;
  not promoted to a finding.

## Conclusion

No duplicate memory-store authority. The hot/warm split is intentional and
the two layers share one `echo_agent_dir`. Workspace switch is the single
fully-consistent rebind path: it refreshes both projections, rebinds the
store, rebuilds the layer manager, and propagates to primary + pool. The
only residual gap is the absence of a file watcher for the instruction/
memory tiers (P3-01), which compounds — but does not duplicate —
A-CFG-01's watcher/config-switch findings. Supports findings A-MEM-01-P3-01
and A-MEM-01-P3-02 and the Handoff conclusion that workspace switch is the
ground-truth refresh path.
