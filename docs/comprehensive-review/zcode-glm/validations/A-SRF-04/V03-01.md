## Claim

Every non-GUI renderer (REPL terminal, channel QQ, channel Feishu)
consumes the shared `ChatDriverEvent` / `OutboundMessage` stream and
projects it onto its surface WITHOUT inventing lifecycle state,
dropping terminal events, or duplicating sends. Specifically:

- REPL: a single `match` over `ChatDriverEvent` prints tokens /
  tool calls / terminal events; no internal state machine.
- Channel: `aggregate_by_sentence` is a pure stream transformer; the
  empty-text placeholder protocol prevents double-sends.
- Feishu: card patching is a renderer optimization on the same chunked
  stream.
- The framework's `dispatch_stream_to_send_tx` +
  `reply_with_empty_guard` enforce the no-double-send invariant for
  every gateway.

## Expected Result

- Each renderer maps every terminal `AgentEvent` (FinalAnswer /
  Cancelled / Error) to a defined output action.
- `aggregate_by_sentence` flushes the buffer on terminal events.
- The framework `dispatch_stream_to_send_tx` returns an empty-text
  placeholder; `reply_with_empty_guard` no-ops on empty text.
- UTF-8 truncation uses `chars()` everywhere (AGENTS.md §1).
- High-frequency execution events are dropped on the channel surface
  by design (`is_attention_event` filter).

## Deviations

One presentation asymmetry surfaced (filed as A-SRF-04-P3-01): the
channel surface wires only `/trace`, `/analysis`, `/papers`,
`/skills`, and `/mode` as slash commands
(`channels.rs:306-412`). Other REPL commands (`/cron`, `/tasks`,
`/diff`, etc.) are not wired to channels; an IM user issuing `/cron
list` would have it routed to `drive_chat` as a normal instruction
rather than dispatched as a structured command. This is a slash-command
surface gap, not an event-rendering defect — the renderer correctly
handles whatever events `drive_chat` emits.

## Conclusion

Supports V03's claim: every non-GUI renderer is a pure projection of
the shared `ChatDriverEvent` / `OutboundMessage` stream. No renderer
invents lifecycle state, drops terminal events, or duplicates sends.
The framework's empty-text placeholder protocol
(`dispatch_stream_to_send_tx` + `reply_with_empty_guard`) is the
single mechanism that makes "one chunk per send" (QQ) and "patch the
same card" (Feishu) both correct.

The chat-lane side of this contract was established by A-CHAT-01 V03
(the one-terminal invariant via `envelope_event_stream`). This
validation confirms the renderers correctly consume what
`drive_chat` emits.
