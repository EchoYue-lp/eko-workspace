## Claim

The four "satellite" capabilities — Resume conversation, Attach file,
Browser control, MCP server management — are reachable from the TUI
event loop via the `Arc<...>` resources that `run_tui` binds at
startup. None is stubbed, deferred, or returns "feature unavailable"
on the default TUI configuration.

## Expected Result

- Each capability's resource is set in `run_tui` before
  `run_event_loop` starts.
- Each capability's slash arm dispatches to a real framework /
  app-core call (not a `return String::from("not implemented")`).
- Each call site is guarded for the `Option<Arc<...>>` case so a
  missing resource yields an informative user message, not a panic.

  Step 2 — Resume conversation (`events.rs:4818-4875`):
  - `store.get_conversation(conversation_id).await?` — returns
    `Option<Conversation>`; `?` short-circuits on storage error.
  - `store.get_messages(conversation_id).await?` — returns
    `Vec<StoredMessage>`.
  - `restore_messages(&stored)` — framework function that converts
    `StoredMessage` → runtime `Message`. Failure is logged with
    `tracing::warn!` and falls back to empty history (no panic).
  - `agent.write(|v| v.set_conversation_id(...))` and
    `agent.read_async(|v| v.load_messages(runtime_messages))` —
    framework `AgentHandle` async methods.
  - `app.conversation_id = Some(...)`, `app.messages = stored.iter().map(...)`,
    push "Resumed conversation: ..." system message,
    `app.task_runtime_view = None`, `app.subagent_runs.clear()`,
    `rebuild_message_groups()`.
  - The `SlashCommand::Resume` arm (`:3021-3036`) guards against
    `app.is_processing` (refuses to resume mid-turn) and empty args
    (usage message).

  Step 3 — Attach file (`events.rs:3261-3300`):
  - `/attach <path>` reads the file, persists under the global uploads
    dir via `stage_attachment` (`:2529-2562`), pushes an
    `AttachmentRef` onto `app.pending_attachments`. The next Enter
    drains the buffer via
    `std::mem::take(&mut app.pending_attachments)` in `handle_enter`
    (`:1328`) and passes it into `dispatch_turn`.
  - `dispatch_turn` builds `turn.attachments` →
    `PreparedUserTurn::build(attachments: &turn.attachments)`
    (`:1371-1401`); `prepared.inline_attachment_refs()` is threaded
    into `ChatResources.attachments` (`:1422`).
  - The `drive_chat` call (`send_to_agent`, `:2212-2230`) receives the
    multimodal message; the framework's `agent.execute_stream_message`
    forwards the staged refs to the LLM as image / document content.
  - Failure modes are guarded: empty path → usage message;
    `stage_attachment` error → user-facing error message. No panic.

  Step 4 — Browser control (`events.rs:4551-4615`):
  - `/browser` (no args or `status`) → `runtime.extension_status().await`
    returns `BrowserExtensionStatus { connected, package,
    token_configured, startup_error }`. Rendered as a multi-line system
    message.
  - `/browser managed` or `/browser chrome` →
    `runtime.execute_main(conv_id, BrowserAction::Backend, params,
    None).await` where `params = { "backend": "managed" | "chrome" }`.
    Returns `Result<(), Error>`; rendered as success or failure
    message.
  - The arm guards `app.browser_runtime.clone()` with `let Some(runtime)

    always populated in `run_tui` (`:1964`), so the unreachable branch

  - Direct browser tool invocations (e.g. `browser_navigate`,
    `browser_click`) are rendered as foreground-tool messages when the

  Step 5 — MCP management (`events.rs:3425-3477`):

  - `/mcp load <path>` →
    `agent.write_async(|v| Box::pin(async move { v.load_mcp_from_file(path).await }))`
    returns `Result<Vec<McpClientHandle>, Error>`; rendered as

  - `/mcp disconnect <name>` →

None. All four capabilities are reachable and call framework / app-core

## Conclusion

Supports the A-SRF-01 reachability claim. Resume / Attach / Browser /
MCP are all wired through the shared `run_tui` resources, dispatched
from the corresponding slash command, and call the correct framework
methods (`agent.load_messages`, `agent.set_conversation_id`,
`PreparedUserTurn::build`, `BrowserRuntime::execute_main`,
`agent.list_mcp_servers` / `load_mcp_from_file` / `disconnect_mcp`).
Failure modes are guarded with user-visible messages, not panics. The
`AgentHandle` async read/write API and the
`BrowserRuntime` / `ConversationStore` traits provide clean adapter
seams — no business logic leaked into the TUI command bodies. Combined
with V01-01's enumeration of all 57 SlashCommands and V02-01's tool /
HITL render traces, this confirms the TUI exposes the full Agent
feature surface required for parity.
