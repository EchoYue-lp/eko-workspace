## Claim

The notebook module (`echo-agent/src/notebook/`) is a coherent, reachable
framework API: it is (a) exported through the facade, (b) constructed or
owned by the agent runtime, (c) registered as a tool / reachable from tool
execution, and (d) the `enable_notebook` knob on `AgentConfig` actually
drives the tracker. If any of these is false, the notebook is an isolated or
aspirational path rather than a live framework capability.

## Method

Static inspection at commit `9b0e0fa`. Enumerated the module's public
surface, traced every reference to notebook symbols across both repos, and
checked whether the agent runtime reads the `enable_notebook` flag or
constructs a `NotebookTracker`.

```text

2. grep -rn "notebook|Notebook" across echo-agent and echo-agent-cli

3. grep -rn "enable_notebook" across both repos to distinguish writes

4. Read echo-agent/src/lib.rs:50 (pub mod notebook) and lib.rs:137-278
   (prelude) and lib.rs:279-331 (advanced) to confirm whether notebook is

5. Read echo-agent/src/agent/config.rs:171-174,263,807-818 for the

6. Cross-checked the echo-agent-cli hits to determine whether they wrap the
   framework notebook or are an unrelated same-name concept.
```

## Expected Result

A live framework capability would show at least one construction site
(`NotebookTracker::new()` or `Default::default()`) owned by the agent
runtime, at least one call to `record_cell` / `cells()` / `export_*` from
the runtime or a tool, and at least one read of `enable_notebook` by the
agent. The module would be re-exported through the prelude or advanced
facade alongside peer modules.

## Deviations

- The validation could not be run as an executable check because there is
  no live path to exercise. A `cargo check` would not flag the dead code
  (the items are `pub`, so they are not dead-code-eliminated). The
  "aspirational" conclusion rests on the absence-of-callsite grep, which is
  deterministic over the two repos.
- `enable_notebook` is `pub(crate)` on the field but exposed via a `pub`
  builder on a `pub` struct (`AgentConfig`) that is itself re-exported in
  the prelude (`src/lib.rs:140`). So the dead setter is part of the public
  API surface even though the field is crate-private.

## Conclusion

The notebook capability fails every reachability criterion in the claim. It
is a self-contained module with a clean in-process API but **no construction
site, no call site, and no consumer of its `enable_notebook` switch**. It is
an isolated, aspirational path, not a coherent live framework API. The
public `pub fn enable_notebook()` builder compounds the problem by advertising
the capability to consumers who use the prelude. Supports task findings
F-NBK-01-P1-01 (unreachable stub) and F-NBK-01-P2-01 (no-op public setter).

## Follow-Up

The natural follow-up is a decision: either wire the tracker into the agent
runtime (construct it when `enable_notebook` is true, call `record_cell`
after each tool execution, expose `export_*` through a callback / API) or
delete the module and the `enable_notebook` setter. Per AGENTS.md
"framework-vs-application" and "no parallel implementations" rules, the
decision belongs to a product-level task, not this review. No executable
re-run is required; the conclusion is a structural fact at commit `9b0e0fa`.
