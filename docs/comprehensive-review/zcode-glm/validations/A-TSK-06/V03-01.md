## Claim

Task-runtime durable artifacts — `events.jsonl`, `plan.json`,
`run-state.json`, the ledger's `progress.md`, and the archived
`artifacts/traces/{task_id}.txt` — are preserved after task and run
completion, with a documented retention policy and a reachable
cleanup path.

Per AGENTS.md "本地个人助理" threat model and the conversation-deletion
cascade audited in A-STATE-01, the expectation is:

- Artifacts are retained for as long as the run is interesting to the
  user (i.e. across restarts — this is the whole point of
  durability).
- The conversation-deletion cascade (Tauri `delete_conversation`,
  TUI `/delete-session`) reaches into the task-runtime artifact tree
  and removes per-conversation/per-run state, so deleted conversations
  do not leave orphaned task artifacts.
- There is no unbounded growth without a cleanup path.

## Expected Result

  `~/.eko/tasks/{run_id}/` (the file-shadow authority) and
  `{workspace}/.eko/runtime/{run_id}/` (the ledger progress/trace

## Result

- Exit code: 0 (static inspection; no compile step).
- Summary: **claim FAILED.** The artifacts are durable and survive
  restarts (positive), but there is **no reachable cleanup path for
  the task-runtime tree**, and the artifact metadata's `retention`
  field is a write-only string with no reader.

**Artifact tree layout (verified):**

| Tree | Path | Authority | Written by |
|---|---|---|---|
| File-shadow authority | `~/.eko/tasks/{run_id}/events.jsonl` | append-only | `append_event_line` (file_shadow.rs:118) |
| File-shadow projection | `~/.eko/tasks/{run_id}/plan.json` | deterministic rebuild | `rewrite_plan` (file_shadow.rs:208) |
| File-shadow projection | `~/.eko/tasks/{run_id}/run-state.json` | deterministic rebuild | `rewrite_plan` (file_shadow.rs:208) |
| Ledger progress export | `{base}/.eko/runtime/{run_id}/progress.md` | derived (best-effort) | `write_progress` (ledger.rs:164) |
| Ledger trace archive | `{base}/.eko/runtime/{run_id}/artifacts/traces/{task_id}.txt` | raw subagent output | `archive_trace` (ledger.rs:138) |

**Cleanup-path enumeration:**

```text
grep -rn "delete_run\|purge_run\|remove_run\|cleanup_runtime\|
         cleanup_task_runtime\|task_runtime.*delete\|remove.*tasks/"
  echo-agent-cli/echo-agent-app-core/src
  echo-agent-cli/src/tauri
  echo-agent-cli/src/tui
→ ZERO matches (excluding test fixtures and unrelated uses).
```

There is no `TaskRuntimeStore::delete_run`, no
`FileTaskShadow::purge_run`, no `cleanup_runtime_scope`, and no Tauri
or TUI command that removes anything under `~/.eko/tasks/`. The
`delete_conversation` cascade (audited in A-STATE-01) reaches:

- the framework `ConversationStore::delete_conversation` (removes
  `<safe_id>.json` under `~/.eko/conversations/`);
- `ToolExecutionRepository::remove_conversation` (moves the
  per-conversation tool-execution subtree to `.trash/` and tombstones
  the in-memory index — tool_execution.rs:464-506);
- `echo_agent::tools::artifact::cleanup_tool_output_scope` (removes
  the framework tool-output subtree under
  `<artifact_root>/<conversation_id>/`);
- `prepared_turn::cleanup_user_input_scope` (removes the user-input
  spill directory under `<user_input_spill_dir>/<conversation_id>/`).

None of these touch `~/.eko/tasks/{run_id}/`. The `run_id` is not
derivable from the `conversation_id` in the cleanup path; the
TaskRuntime store has no `delete_runs_for_conversation` API. A run
outlives its owning conversation on disk.

**`retention` metadata field:**

The artifact round-trip test (store.rs:2259) writes:

```rust
metadata: serde_json::json!({
    "sha256": "abcdef",
    "retention": "conversation_or_30d",
}),
```

A whole-repo grep for `conversation_or_30d` returns exactly one match
— the test. There is no reader, no TTL enforcer, no scheduler that
consumes the `retention` field. It is a stringly-typed wish with no
implementation. The `ArtifactKind::Trace` variant produced by
`archive_trace` is not registered via `add_artifact` at all — it is
written directly by `std::fs::write` (ledger.rs:151) and never
appears in `list_artifacts` (which only folds `ArtifactProduced`
events).

**Growth characteristics:**

- `events.jsonl` grows monotonically per run (one line per state
  mutation). For a long complex run this can be tens of MB; for
  thousands of accumulated runs across months, the
  `~/.eko/tasks/` tree grows without bound.
- `artifacts/traces/{task_id}.txt` archives the **full subagent
  output** (the same `full_output` that was persisted in
  `SubagentReleased.full_output`). The trace is therefore a
  duplicate store of `full_output`, written at executor.rs:2317
  (`super::ledger::archive_trace(&run_id, &task_id, &full_output,
  None)`) immediately before `put_summary`. For a writer task with a
  multi-MB output, both `events.jsonl` (via `SubagentReleased` payload)
  and the trace file store the same content.
- The trace archive's `base` is `None` in the production call site
  (executor.rs:2317), so it falls back to CWD (ledger.rs:140-141).
  In Tauri the CWD is not reliable (A-STATE-01 made the same
  observation about `write_progress`'s `base` parameter). The trace
  archive may land in an unpredictable location for GUI runs.

## Deviations

The "no cleanup path" finding is the failure. The artifact tree is
otherwise durable, atomic, and survives restart — those properties
hold. The gap is the missing end-of-life.

## Conclusion

Supports: artifacts are preserved across restarts (the durability
invariant). `events.jsonl` is append-only under the per-run write
lock (A-TSK-04 V03), `plan.json`/`run-state.json` are deterministic
projections (A-TSK-04 V03), and `recover_incomplete` +
`recoverable_subagent_result` reconstruct everything from the event
stream at boot.

**Does NOT support** the retention/cleanup invariant:

1. No `delete_run` / `purge_run` / cleanup command exists for the
   task-runtime tree.
2. The conversation-deletion cascade (audited in A-STATE-01) does
   not reach `~/.eko/tasks/`. A deleted conversation leaves orphaned
   run/plan/event/trace artifacts indefinitely.
3. The artifact `metadata.retention` field is write-only — no code
   reads it. The "conversation_or_30d" policy is aspirational.
4. The ledger's `archive_trace` writes the full subagent output a
   second time (the first copy is in `SubagentReleased.full_output`
   on `events.jsonl`), doubling disk use for writer tasks. The
   trace archive's `base = None` in production means its location is
   CWD-dependent and unpredictable for Tauri.

This is filed as A-TSK-06-P2-01 (no cleanup cascade) and
A-TSK-06-P3-01 (duplicate trace archive).
