## Claim

Subagent results are preserved in **two distinct durable projections**,
each with a clearly bounded purpose. There is no second authority and
no parallel persistence path.

1. **Full-result projection** — `SubagentReleased` events on
   `events.jsonl` carry the complete `SubagentTaskResult` (status,
   summary ≤ 2 000 chars, artifacts, verification, remaining_work,
   touched_files) **plus** an optional `full_output` text blob (the
   post-thinking output stream). The fold in
   `recoverable_subagent_result` keys the result on the exact
   `execution_id` and serves it back to the resume path without
   re-dispatch.
2. **Summary projection** — `Note{kind: summary_persisted}` events
   carry a `TaskExecutionSummary` (result + decisions +
   next_implications + suggested_tasks + created_at) keyed on
   `(run_id, task_id)`. The fold in `FileTaskStore::get_summary` is a
   `rfind` (last-wins) so a re-execution cleanly replaces the prior
   summary. The compact-context capsule and `collect_dependency_summaries`
   both consume this structured form, falling back to the truncated
   todo summary when the structured form is absent (older tasks).
3. **The two projections are produced together**, both inside
   `execute_task`'s success/failure branches: `put_summary` lands
   first, then `record_subagent_released`. They are intentionally
   distinct — the summary carries the cross-task context fields
   (decisions, next_implications, suggested_tasks) the Subagent
   contract does not have, while the SubagentReleased record carries
   the `full_output` the summary lacks.
4. **Thinking protocol is excluded by construction.** The streaming
   loop maintains an `in_thinking` flag; only non-thinking tokens are
   appended to `output` (which becomes `full_output`). Thinking deltas
   are routed to the realtime trace sink only.

## Conclusion

Supports: the "two-projection result preservation" invariant. The full
result (status, summary, artifacts, verification, remaining_work,
touched_files, full_output) lives on `SubagentReleased`; the structured
summary (adds decisions / next_implications / suggested_tasks) lives
on `Note{kind=summary_persisted}`. The two are written together but
serve different consumers (resume-reuse vs. cross-task context).

Supports: the "thinking protocol does not leak" invariant. The
streaming loop's `in_thinking` flag guarantees only non-thinking
tokens reach `output` → `full_output`. Thinking is delivered only via
the realtime trace channel.

Supports: the "no parallel persistence authority" invariant — every
read/write of results/summaries/artifacts/reviews goes through exactly
one store API.

Does NOT support (and is not asked to support): retention/cleanup
policy for the durable artifacts. That is V03.

Findings using this validation: none directly (this is the
foundational result-preservation invariant). The findings A-TSK-06-P3-01
and A-TSK-06-P3-02 are about retention and ledger-output fidelity, not
about result-preservation correctness.
