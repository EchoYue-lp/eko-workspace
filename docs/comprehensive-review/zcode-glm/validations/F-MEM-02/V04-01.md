- Summary: **Tests green; edge-case / schema inspection fails the claim on four
  points.**
  - **Tests: all 15 passed, 0 failed.** Concretely:
    `test_put_and_get`, `test_get_nonexistent`, `test_upsert`, `test_delete`,
    `test_fts5_search`, `test_fts5_search_multiple_keywords`,
    `test_fts5_like_fallback_supports_cjk_spaced_keywords`,
    `test_fts5_persists_across_store_instances`, `test_list_namespaces`,
    `test_namespace_isolation`,
    `test_semantic_search_without_embedder_is_unsupported`,
    `test_with_embedder` (uses `MockEmbedder` dim=4), `test_vec_serialization`,
    `test_cosine_similarity` (1.0 / 0.0 cases), `test_extract_searchable_text`.
    None of these exercises NaN, blob truncation, dimension mismatch, or
    `prune_expired`.
  - **NaN propagation** (finding F-MEM-02-P3-01): `cosine_similarity`
    (`sqlite_store.rs:239-251`) guards `a.len() != b.len() || a.is_empty()`
    (returns 0.0) and `norm_a == 0.0 || norm_b == 0.0` (returns 0.0), but the
    `==` checks are `false` for NaN. For a NaN element, `dot`/`norm_a`/`norm_b`
    all become NaN and the function returns `NaN / NaN = NaN`. The downstream
    sort at 451 (`b.0.partial_cmp(&a.0).unwrap_or(std::cmp::Ordering::Equal)`)
    is NaN-safe, so **no panic**, but `StoreItem.score = Some(NaN)` is returned
    to callers. No embedder-output validation exists to prevent NaN entering.
  - **Blob truncation** (same finding): `bytes_to_vec` (`sqlite_store.rs:231-
    236`) uses `chunks_exact(4)`, which silently discards a trailing 1-3 byte
    remainder. A 5- or 7-byte corrupted blob becomes a 1-element vector, which
    then scores 0.0 via the dimension-mismatch branch. No detection, no log.
  - **Empty vector / dimension mismatch: handled.** `semantic_search_impl`
    filters `vec.is_empty()` (444-446); `cosine_similarity` returns 0.0 on
    length mismatch. Defensible (0.0) but the mismatch is silent (no warning).
  - **`prune_expired` orphans FTS + vector rows** (finding F-MEM-02-P2-01):
    `prune_expired` (`sqlite_store.rs:909-928`) issues a single `DELETE FROM
    store_items` and returns. It does **not** touch `store_fts` or
    `store_vectors`, and it is not wrapped in a transaction. By contrast
    `delete` (710-745) removes from all three tables atomically. So expired
    items leave orphaned FTS/vector rows that bloat the indexes and get
    silently dropped by `fetch_items` at query time (FTS MATCH returns their
    keys, but the `key IN (...)` lookup against `store_items` finds nothing).
    Results stay correct; the three-table lockstep invariant `delete` upholds
    is violated.
  - **Schema migration swallows non-duplicate errors; migrated columns
    unread** (finding F-MEM-02-P3-03): the migration loop (`sqlite_store.rs:
    147-159`) catches every ALTER error and only `warn!`s if the message lacks
    "duplicate column", then continues. A disk-full / read-only failure would
    leave columns missing and later `put`s (which reference `importance`,
    `expires_at`) failing at write time. Additionally the three migrated
    columns are written by `put` (518-526) but never read back — `get`/`list`/
    `fetch_items` hard-code `importance: 5.0` then call `apply_json_metadata`
    (935-945) which re-reads from the JSON `value` column; `prune_expired`
    likewise reads `json_extract(value, '$.expires_at')`, not the SQL column.
    The sibling `SqliteRuntimeStateStore` (`state/sqlite.rs:73-84`) returns
    `Err` for non-duplicate migration failures — the correct pattern.
  - **Empty-query divergence** (finding F-MEM-02-P3-04): `SqliteStore::search`
    returns `Ok(vec![])` for an empty query (`sqlite_store.rs:624-626`), while
    `FileStore`/`InMemoryStore` return up to `limit` items scored 1.0
    (`store.rs:528-531`, see F-MEM-01-P3-02). The `Store` trait does not fix
    empty-query semantics, so the three impls disagree.
- Log/artifact: none.

## Deviations

The four edge-case/schema gaps are not covered by any in-tree test — they were
found by code reading. The NaN and blob-truncation paths are not reachable
from the existing `MockEmbedder` (which normalises and never produces NaN or
odd-length blobs), so the green test run does not contradict them. The
`prune_expired` orphan gap is reachable but has no test asserting three-table
consistency after prune.

## Conclusion

The sqlite test suite is healthy (15/15) and the core CRUD / FTS5 / vector
happy paths are verified, including cross-instance persistence and the
embedder-backed semantic path. But the numerical-edge-case and schema-
consistency claim fails: NaN propagates through `cosine_similarity` into
`StoreItem.score` (P3-01), truncated blobs are silently reshaped (P3-01),
`prune_expired` orphans FTS/vector index entries (P2-01), the migration
swallows real errors while maintaining unread columns (P3-03), and empty-
query semantics diverge from the file backends (P3-04). The P2-01 orphan gap
is the most material — it is the only one that can produce an observable
index divergence under normal operation (any item that expires). Supports
findings F-MEM-02-P2-01, F-MEM-02-P3-01, F-MEM-02-P3-03, F-MEM-02-P3-04.

The validation does NOT add new executable tests for the gaps (out of scope
for a read-only review); the recommended regression tests are listed in each
finding's "Direction"/"Regression validation" fields.
