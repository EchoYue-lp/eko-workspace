## Claim

The loop exposes three classes of safe interruption points with
distinct on-interrupt behavior: (a) **think-phase intervention** —
synchronous callback cancel/block at think-start plus a cancel-aware
LLM stream; (b) **tool-phase cancellation** — `CancellationToken`
polled at serial pre-iteration and inside the concurrent
`tokio::select!`, with a 5-second grace that drains in-flight tools
before checkpointing and abandoning; (c) **compact-phase** — no
explicit cancel check inside `run_compact`, but the pre-compaction
checkpoint is saved before `ContextManager::prepare` runs, so a kill
during compaction resumes from the pre-compaction (full-context)
checkpoint. Same-turn **steer** is a cooperative input-injection
mechanism (not a preemption): it is drained only at iteration-top and
post-think, gated on `steerable=true`, and scoped to the active turn by
the `ActiveTurnLease` RAII guard.

## Expected Result

1. Think-phase interrupt (intervention cancel OR token cancel during
   stream) forwards an `Err` to the channel, marks the TaskNode
   Failed/Blocked, and the driver returns `Ok(())` without
   `finalize_run` (the F-RCT-02-P3-01 trace gap).
2. Tool-phase cancel observes the token, enters a 5 s grace, drains
   completed results, then saves a checkpoint, emits `ToolBatchEnd`,
   and returns `Abandoned`. Tool-phase batch-timeout does NOT save a
   checkpoint or emit `ToolBatchEnd` (F-RCT-04-P2-01).
3. Compact-phase has no internal cancel check; the checkpoint saved at
   `compact.rs:35` precedes the mutating `ContextManager::prepare`, so
   a crash during compaction leaves the on-disk checkpoint at the
   full-context pre-compaction state.
4. Steer (`steer`) is rejected unless `steerable=true`; it is queued,
   not preemptive, and drained only at the two iteration boundaries.
   The mailbox is cleared when the `ActiveTurnLease` drops
   (`steer.rs:143-147`).

## Result

- Exit code: not-applicable (static inspection) + cargo confirmation.
- Summary: the claim is **supported**.

**(1) Think-phase interrupt.**
Two sub-paths:
- **Synchronous intervention at think-start** (`think.rs:39-79`): each
  `InterventionCallback::on_think_start` returns `{ cancel, block,
  injected_context }`. On `cancel` → TaskNode `Failed`
  (`:43-46`), `tx.try_send(Err(...))` (`:47-49`), return
  `ThinkOutcome::Cancelled`. On `block` → TaskNode `Blocked{reason}`
  (`:56-64`), `tx.try_send(Err(...))` (`:65-68`), return
  `ThinkOutcome::Blocked`. The driver (`stream_channel.rs:605-609`)
  matches `Abandoned|Cancelled|Blocked` and `return Ok(())` — no
  `finalize_run` (the F-RCT-02-P3-01 trace-finalization gap applies).
- **Token cancel during the LLM stream** (`think.rs:321`): the
  `cancel_token` is passed into `ChatRequest` and routed through the
  `LlmClient`. The stream aborts; `create_llm_stream` returns `Err`,
  which `try_send_or!` (`think.rs:99-103`) forwards to `tx` and
  returns `ThinkOutcome::Abandoned`. Same driver arm, same trace gap.

**(2) Tool-phase cancel.**
The concurrent select! (`tools.rs:130-300`) has four relevant arms:
- `cancellation_grace` (observed) → save_runtime_checkpoint("Tool batch
  cancelled") (`:203`), `ToolBatchEnd` (`:204`), return `Abandoned`
  (`:206`).
- `futs.next()` ready → push result; on `final_answer` verifier
  handoff; loop continues.
- `cancel` (if !observed) → set `cancellation_observed=true`, reset
  grace timer to 5 s (`:285-289`). Does NOT immediately exit — lets
  in-flight tools drain.
- `timeout` (if !observed) → forward `Err(Timeout)`, return `Abandoned`
  (`:284-292`) — **no checkpoint, no ToolBatchEnd** (F-RCT-04-P2-01).

Post-loop (`:278-300`): if `cancellation_observed`, the same
checkpoint + ToolBatchEnd + Abandoned sequence runs. The serial path
checks `cancel_token.is_cancelled()` at pre-iteration (`:305-310`) and
inside its own select! (`:348-355`), with the same checkpoint +
ToolBatchEnd + Abandoned on cancel.

So tool-phase cancellation is graceful (5 s drain + checkpoint +
bracket event). Tool-phase timeout is not (immediate abandon, no
checkpoint).

**(3) Compact-phase (no internal cancel check).**
`run_compact` (`compact.rs:21-116`) executes linearly:
PreCompact hook → `pre_compaction_flush` → `save_runtime_checkpoint`
(`:35`) → build projections → `ContextManager.prepare` (`:60`) →
PostCompact hook. There is no `cancel_token.is_cancelled()` check
inside this function. The protection is positional: the checkpoint at
`:35` captures the full pre-compaction context BEFORE `prepare` mutates
it. If the process is killed:
- Before `:35` → no new checkpoint written; resume uses the prior
  iteration's checkpoint (clean, full context).
- Between `:35` and `:60` end → checkpoint is the pre-compaction full
  context; the partially-compressed in-memory state is discarded on
  next Execute-mode resume (`set_messages` overwrites it).
- After `:60` → compaction complete; checkpoint from `:35` is slightly
  stale (pre-compaction) but the in-memory post-compaction state is
  lost on crash. Next Execute-mode resume loads the pre-compaction
  checkpoint — the user loses the compaction but not the conversation.

So compact-phase is crash-safe by checkpoint ordering, not by cancel
cooperation. It does not respond to a cancel token mid-compaction (the
LLM is not called during compact, so the window is small — bounded by
hook execution + ContextManager compression latency).

**(4) Same-turn steer.**
`TurnSteerMailbox` (`steer.rs:43-147`):
- `begin(turn_id)` (`:49-61`) creates an `ActiveTurn { id, steerable:
  false, pending: VecDeque }` and returns an `ActiveTurnLease`.
- `set_steerable(turn_id, bool)` (`:63-70`) — called by the loop at
  safe points (the loop enables steer when the LLM is awaiting input
  and disables it during tool execution).
- `steer(expected_turn_id, message)` (`:72-108`): validates
  non-empty content (`:77-87`), checks `turn_id` match
  (`:93-100` → `TurnMismatch`), checks `steerable` (`:101-105` →
  `NotSteerable`), then `pending.push_back(message)` (`:106`).
- `drain(turn_id)` (`:110-121`) — called by the loop's
  `drain_steer_into_context` at `stream_channel.rs:538` (iteration top)
  and `:663` (after think, before verify). Returns and clears the
  queued messages.
- `finish(turn_id)` (`:123-129`) — called by `ActiveTurnLease::drop`
  (`:143-147`), which runs when the spawned loop task ends.

So steer is a cooperative, RAII-scoped, FIFO input queue — never a
preemption. A steer submitted while `steerable=false` is rejected (the
caller gets `NotSteerable`); it is not buffered for later. The mailbox
is single-turn: a steer enqueued for turn N is lost if the turn ends
before `drain` runs.

## Deviations

1. The think-phase and abandoned/error terminal arms do not call
  `finalize_run` (F-RCT-02-P3-01). This is a trace-status gap, not a
  safety gap — the turn exits cleanly, the user sees the error, but
  the trace run stays `Running`. Out of scope for this validation;
  tracked under F-RCT-02.
2. The batch-timeout arm (`tools.rs:284-292`) is the one interrupt
   point that skips checkpoint + `ToolBatchEnd`. This is F-RCT-04-P2-01
   (filed, not fixed). For F-RCT-05's purpose, the consequence is: an
   interrupt that arrives as a batch-timeout (rather than a cancel
   token) leaves no checkpoint for the partial batch. On resume, the
   user gets the last clean checkpoint (pre-batch), losing the
   in-flight tools' partial work.

## Conclusion

The claim is **supported**. Three interrupt classes are handled with
positioned checkpoints: think-phase forwards the error and exits;
tool-phase cancel drains with grace then checkpoints (timeout does
not, per F-RCT-04-P2-01); compact-phase has no internal cancel but is
crash-safe by checkpoint-before-mutate ordering. Steer is a
cooperative, turn-scoped input queue, not a preemption — it cannot
interrupt mid-phase, only inject at the two drain points. The framework
does not provide a preemptive mid-LLM cancel beyond what the
`cancel_token`-aware LLM stream already offers. This characterization
is the basis for the V03 portion of the F-RCT-05 task report and feeds
the resume-edge-case note in V02 (Deviation 1).
