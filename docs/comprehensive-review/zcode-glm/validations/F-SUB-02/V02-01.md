## Claim

Parent-run cancellation propagates to Sync, Fork, and Teammate subagents
via `CancellationToken::child_token()` and is honoured by each mode's
`tokio::select!` cancel arm; **Team mode does not propagate parent
cancellation at all** (the token is never read, no child token is derived,
and team subagents run via `Agent::execute` which accepts no cancel
parameter).

## Conclusion

Supports finding **F-SUB-02-P1-01**: Team mode is the only execution mode
that does not propagate parent cancellation. Sync/Fork/Teammate each
derive a child token from `req.cancel` and race it in a `select!` arm;
Team mode's `dispatch_team` ignores `req.cancel` entirely, the team module
has no `CancellationToken` plumbing, and the orchestrator invokes the
agent through a trait method that cannot carry a token.

Supports finding **F-SUB-02-P2-02** (partial): team subagents run through
`Agent::execute`, not `execute_stream_with_invocation_context`, so the
cancellation-aware streaming path that the other three modes use is
structurally unreachable for team members.

Does not prove: whether the parent run's token actually fires under
realistic ReactAgent conditions (that is the ReactAgent run-loop's
responsibility, validated by `test_run_stream_cancelled_mid_llm_call` and
`cancellation_drains_running_tool_before_abandoning_turn` which also
passed).
