## Claim

Each of the four execution modes (Sync, Fork, Teammate, Team) plus
Background and manager-fan-out has a single, identifiable spawn path and a
single, identifiable termination path, and no mode creates a parallel
dispatch/identity authority alongside `SubagentExecutor::dispatch`.

## Method

Read-only static inspection of the dispatch routing in
`echo-agent/src/agent/subagent/executor.rs` and whole-repository duplicate
search for parallel dispatch/lifecycle authorities.

```text
1. Read SubagentExecutor::dispatch (executor.rs:407-781) — the single
   routing loop. Confirm it branches on ExecutionMode into exactly four
   internal methods + one background entry.
2. For each mode, trace the spawn primitive (inline / tokio::spawn) and the
   termination primitive (return / join / select arm / timeout).
3. Grep both echo-agent and echo-agent-cli for alternative dispatch entry
   points, parallel executor types, or detached-spawn paths outside
   SubagentExecutor.
4. Grep for Worker terminology (must be absent per AGENTS.md).
5. Confirm the existing test inventory covers each mode's routing.
```

Feature flag: `--features subagent`. Working directory:
`/Users/ls/MyWork/code/ylp_agent_learn/lp-agent/echo-agent`.

## Expected Result

- One routing entry (`dispatch`) selects among four mode methods.

- No second executor/dispatcher type exists in either repo.
- No `Worker`/`worker_` naming in the subagent tree.
- Each mode has a traceable spawn → terminate edge.

## Deviations

The matrix reveals that Team mode is structurally different from the other
three: it does not derive a child cancel token and does not pass an
`AgentInvocationContext` to its subagents (the orchestrator calls
`agent.execute(&task)`, not `execute_stream_with_invocation_context`). This
is recorded as findings F-SUB-02-P1-01 and F-SUB-02-P2-02, not as a
deviation from the validation method.

## Conclusion

Supports: the "single registry, single dispatch tool, single routing entry"
invariant from F-SUB-01 holds for execution modes. Sync, Fork, Teammate,
and Background all route through `SubagentExecutor::dispatch` and share the
`DispatchRequest.cancel` → child-token propagation pattern.

Does NOT support (and actively refutes) the "without detached execution"
half of the task question for Team mode: Team subagents are spawned via
`tokio::spawn` with no cancel token, and on team-level timeout those
JoinHandles are dropped without `abort()` (detached). See F-SUB-02-P1-01
and F-SUB-02-P1-02.

F-SUB-02-P2-02, F-SUB-02-P3-01, F-SUB-02-P3-02.
