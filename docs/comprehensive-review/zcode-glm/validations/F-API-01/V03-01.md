## Method

Read-only conceptual compile check (no `cargo build` executed — this is
a static read-only review task). For each example, every `use` import

(`ReactAgentBuilder`, `HumanLoopManager`) were checked against
`src/agent/react/builder.rs` and `echo-orchestration/src/human_loop/`.

`echo-macros/src/lib.rs` and `src/macros.rs`.

## Deviations

- **demo03_approval.rs** is feature-conditional. Its `use
  echo_agent::human_loop::{…}` only resolves when the `human-loop`
  feature is enabled. The example file itself does not declare this;
  it relies on the caller passing `--features human-loop` (or running
  via the conditional-acceptance harness described in
  `examples/README.md`). This is consistent with the README's
  conditional-acceptance classification (demo03 is listed there at
  lines 30-50) but is a hidden coupling: a user copying the example
  into a fresh crate with default features gets a compile error on
  line 13.
- **demo03_approval.rs:18** imports directly from `echo_core::tools::permission`,
  bypassing the `echo_agent` facade entirely. The facade does not
  re-export `PermissionRule`/`RuleMatcher`/`RuleSource`; it only
  re-exports `DefaultPermissionPolicy`, `PermissionDecision`,
  `PermissionPolicy`, `ToolPermission` (via `crate::tools::permission`,
  prelude line 164-166). This forces every consumer who wants the
  rule/matcher types to take a direct `echo_core` Cargo dependency,
  which contradicts the facade's stated purpose ("one integration
  surface"). Cosmetic for compilation (the example does compile), but
  it is a coherence leak.
- The conceptual check does not execute the code path. Behavioural
  correctness of the agents at runtime is out of scope; only the
  compile-time symbol resolution is checked.
