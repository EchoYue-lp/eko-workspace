## Claim

The root facade (`echo_agent`) exposes a coherent public surface through
three named re-export modules — `prelude`, `advanced`, and `workspace` —
and every re-exported item resolves to a single canonical source crate
(`echo_core`, `echo_macros`, `echo_execution`, `echo_integration`,
`echo_tools`, `echo_state`, `echo_orchestration`, or a real implementation
owned by the root crate itself).

## Method

Read-only static inspection of `echo-agent/src/lib.rs` (prelude,
advanced, workspace blocks) plus the thin-re-export modules
(`src/memory.rs`, `src/audit.rs`, `src/compression.rs`, `src/error.rs`,
`src/retry.rs`, `src/tokenizer.rs`, `src/sandbox.rs`, `src/scheduler.rs`,
`src/lsp.rs`, `src/mcp.rs`, `src/human_loop.rs`, `src/tasks.rs`,
`src/channels.rs`, `src/llm.rs`, `src/event_bus.rs`). Each `pub use`
statement was expanded by a Python script that joined multi-line
statements, stripped `#[cfg_attr(docsrs, …)]`, recorded the active
`#[cfg(feature = "…")]` context, and counted the individual item names
imported from each source path.

## Deviations

- The prelude mixes `crate::*`-relative imports (192) with absolute
  `echo_core::*` imports (8). The 8 absolute imports bypass the root's
  thin-re-export modules and couple the prelude directly to `echo_core`.
  This is intentional (the inline comment at `src/lib.rs:204-208` says
  these metadata types live in `echo_core::memory` and are surfaced via
  the facade so consumers don't need a direct `echo_core` dependency),
  but it means the prelude's "go through the root" invariant is violated
  for those 8 items.
- The `workspace` module documents itself as a migration scaffold
  (`src/lib.rs:119-123`, "Direct access to split workspace crates
  **during migration**"). It is not the curated facade surface; the
  prelude and `advanced` are.
- The prelude count (200) and advanced count (69) count individual
  re-exported item names. A handful of items appear in both prelude and
  advanced — see V02-01 for the duplicate-path analysis.

## Conclusion

The facade is structurally coherent: 200 curated prelude items + 69
advanced items + 5 crate aliases + 8 procedural macros + 1 conditional
module cover the public surface, and every `pub use` resolves to a
canonical source crate that exists in the workspace. The static
inventory supports the F-API-01 finding that the facade is usable as a
single import surface. It does NOT prove that each item has exactly one
canonical path — that is V02's claim, which fails (see V02-01). It also
does NOT prove that the surface compiles end-to-end — that is V03's
claim.

Findings using this report: F-API-01-P2-01 (coherence of the curated
surface), F-API-01-P3-01 (workspace module omits echo_tools/macros,
inherited from B-ARCH-01-P3-07), F-API-01-P3-02 (prelude's 8 absolute
imports break the "go through the root" pattern).
