`global_emitter` API has been removed.

- Webhook emissions are clustered in `WebhookTurnObserver` (chat turns)
  and the scheduler FireFn (cron). Background task-runtime events have

## Conclusion

Supports the V01 claim. Diagnostics are wired to the live framework
`RunStore` (which is itself attached to every agent — primary and
pooled). Webhook emissions are wired to live lifecycle facts via
`WebhookTurnObserver` (inside `drive_chat_inner`, so identical for every
chat surface) and the scheduler's FireFn. No globals remain.

Two observations tracked as findings rather than deviations:

- A-OBS-01-P2-01: F-OPS-01's "RunStore is not wired in the CLI by
  default" handoff is stale; the wiring is in `infra.rs:374-385` and is
  reached by every entry point. F-OPS-01-P1-03 (trace secret leakage)
  and F-OPS-01-P2-01 (unbounded growth) are LIVE defects today.
- A-OBS-01-P2-02: the wiring is correct for foreground chat turns and
  cron success, but cron failure and background TaskRun lifecycle emit
  no webhook events — a misleading-success gap.
