## Claim

The application-layer observability and webhook surfaces do NOT apply
the framework's `redact_secrets` helper. Three plaintext leak paths
exist on the application layer today, complementing the framework-layer
trace-store leak that F-OPS-01-P1-03 documented:

1. The GUI's `ToolExecutionRepository` persists raw tool args and tool
   output to `~/.echo-agent/tool-executions/...` in plaintext.
2. `WebhookTurnObserver` serializes raw tool args (240 chars) and raw
   tool-error messages into outbound HTTP POST bodies, which leave the
   machine to whatever URL the user configured.
3. The CLI `/run show` and `/runs` slash commands print `run.input` and
   `RunSummary.input_preview` to the terminal (same machine, same user
   — but circumvents the framework's redaction even for tool args).

The framework's `redact_secrets` helper is sound and could be applied
at any of these boundaries; it is simply not invoked.

## Conclusion

Supports A-OBS-01-P1-01 (ToolExecutionRepository plaintext leak),
A-OBS-01-P1-02 (webhook plaintext leak), and the application-side
corollary of A-OBS-01-P2-01 (the framework RunStore leak that F-OPS-01
treated as latent is now compounded by an application-side leak of the
same data).

The cleanest remediation is the same shape as F-OPS-01-P1-03's
recommendation: apply `redact_secrets` at the persistence / emission
boundary, not field-by-field at every construction site. Three small,
focused fixes:

1. `tool_execution.rs::start/append_output/finish`: redact the args and
   output strings before writing the manifest or appending JSONL.
2. `chat_driver.rs::WebhookTurnObserver::observe`: redact `args_summary`
   and the two `error`/`message` clones before constructing each
   `WebhookEvent`.
3. `cmd_impls/observability.rs::cmd_run_show` and `cmd_runs`: redact
   printed `input`/`input_preview`.

The framework `redact_secrets` is already `pub` and UTF-8-safe; no new
helper is needed.

Does not prove that secrets are actually flowing through these surfaces
in production today — that depends on user behavior (pasting a key into
a prompt, calling a tool with secrets in args). The leak paths are
deterministic; whether they fire is usage-dependent.
