## Claim

The data and statistics tools (`data.rs`, `data_quality.rs`, `statistics.rs`)
honor the AGENTS.md "no panic / safe arithmetic" rule: they use checked or
saturating arithmetic, guard every numeric division against zero/empty
inputs, and never index slices with unbounded user-derived integers. In
particular, the IQR outlier path must not panic on any input that passes its
own documented minimum (`values.len() >= 4`).

## Method

Static inspection of every arithmetic site flagged by grep (`as f64`, `as
usize`, `/`, `.min`, direct `sorted[...]` indexing) plus one targeted
executable confirmation of the suspected boundary panic. The executable
reproduces the exact indexing expression from `data_quality.rs:253-254` in a
standalone `rustc` program (no polars dependency needed — the bug is in the
index arithmetic, not the dataframe layer).

```text
1. Read echo-agent/echo-tools/src/statistics.rs (full file).
2. Read echo-agent/echo-tools/src/data_quality.rs (full file).
3. grep data.rs for: ` as (f64|usize|i64|u64)`, ` / `, `unwrap`, `expect`,
   direct index `[`.
4. Inspect DataProfileTool numeric-stats block (data.rs:660-704), DataBinTool
   (data.rs:1722-1802), DataContributionTool total guard (data.rs:1543-1559).
5. Reproduce the IQR n=4 indexing panic with a minimal rustc program:

cat > /tmp/iqr_repro.rs <<'EOF'
fn main() {
    let n: usize = 4;                       // passes `values.len() < 4` guard
    let sorted: Vec<f64> = vec![1.0,2.0,3.0,4.0]; // valid indices 0..=3
    let q1_idx = n / 4.min(n - 1);
    let q3_idx = 3 * n / 4.min(n - 1);
    println!("n={} q1_idx={} q3_idx={} (len={})", n, q1_idx, q3_idx, sorted.len());
    let _q1 = sorted[q1_idx];
    let _q3 = sorted[q3_idx];               // expected: index-out-of-bounds
    println!("unreachable");
}
EOF
rustc -O /tmp/iqr_repro.rs -o /tmp/iqr_repro
/tmp/iqr_repro; echo "exit=$?"
```

## Expected Result

- All `as f64` / `as usize` casts are on already-range-checked values
  (post-clamp or post-len-guard).
- Every `/` divisor is provably non-zero at the call site.
- Every slice index is either a `get(...)` or a `[idx]` where `idx < len` is
  locally provable.
- The executable repro panics with exit code 101 if the precedence analysis is
  correct, confirming the IQR path is unsafe at `n == 4`.

## Result

- Exit code: 101 (from `/tmp/iqr_repro`) — **panic confirmed**
- Duration: <1s compile + run
- Summary of arithmetic-site inspection:

  - `statistics.rs` is well-behaved:
    - `exploratory_statistics` filters non-finite values
      (`statistics.rs:80`), returns `None` for sample std when `len() < 2`
      (`statistics.rs:156`), returns `None` for moments when `len() < 3`
      (`statistics.rs:167`), uses `values.len().saturating_sub(1)`
      (`statistics.rs:163`) and `partial_cmp(...).unwrap_or(Ordering::Equal)`
      (`statistics.rs:82`). Quantile uses `.get(idx)?` and `clamp(0.0,1.0)`
      (`statistics.rs:199-206`). No panic, no unguarded division.
  - `data_quality.rs` **fails the claim** at `data_quality.rs:253-254` (see
    finding F-EXT-03-P1-01). Other paths are safe:
    - `missing_value_analysis` guards `total > 0` and
      `row_count * df.width() > 0` (`data_quality.rs:65, 80`).
    - `detect_zscore_outliers` guards `n >= 4` upstream and `std_dev == 0.0`
      (`data_quality.rs:281-283`).
  - `data.rs` has one silent-wrong-result defect (F-EXT-03-P3-01) and
    otherwise sound guards:
    - `DataContributionTool` early-returns when `total == 0.0`
      (`data.rs:1552-1559`).
    - `DataBinTool` clamps `num_bins` to `2..=50` (`data.rs:1689`), guards
      `values.is_empty()` (`data.rs:1722`), and handles `width == 0.0`
      (`data.rs:1763`).
    - `DataRatioTool` division is a Polars `Expr` (`data.rs:2253`); divide-by-
      zero is delegated to Polars (produces null/inf, no panic).

## Deviations

- The repro program is not a `cargo test` against the real
  `detect_iqr_outliers` (that would require compiling echo-tools with the
  `data` feature and the polars dependency, ~minutes). The repro instead
  isolates the *exact* indexing expression; because the panic is in the index
  arithmetic and not in any polars/ChunkedArray code, the standalone program
  is a faithful witness. The real function would panic on the same `sorted[4]`
  access with the same input.

## Conclusion

The claim is **refuted**: `data_quality.rs::detect_iqr_outliers` panics on any
numeric column with exactly four finite values when the default `iqr` method
is used (and the guard at `data_quality.rs:232` rejects `len() < 4`, so `n ==
4` is the first accepted length). This is a direct violation of the AGENTS.md
"no panic" hard constraint and becomes task finding **F-EXT-03-P1-01**. A
second, lesser defect — `DataProfileTool` dividing sample variance by `n - 1`
when `n == 1` (`data.rs:673`) — does not panic but silently emits `null`
stddev/variance via `serde_json`'s inf handling; that is finding
**F-EXT-03-P3-01**. The `statistics` module itself is clean.

## Follow-Up

A second attempt (V02-02) is not required; the finding is structural and the
fix is to clamp the index, not to re-run. The fix direction is recorded in
F-EXT-03-P1-01.
