## Claim

The research, media, and web tools attach honest provenance to every result,
implement cursor pagination where they return collections, classify network
failures as retryable `ToolFailure`, and route every outbound request through
the SSRF-safe connect path. Audit finding 1.7 (image-fetch SSRF) is fixed on
the live execution path.

## Method

Static inspection of `web/{fetch,search,extract}.rs`,
`media/{image_fetch,web_fetch_enhanced}.rs`, and the research modules
`research/{arxiv,pubmed,semantic_scholar,clients,clinical_trials,pdf_fetch}.rs`.
For each tool: (1) check whether the response includes source URL / IDs /
author / venue, (2) check whether the parameters / description advertise
pagination and whether the code implements it, (3) trace the HTTP send call to
see whether it goes through `security::ssrf_safe_*` or a raw `reqwest::Client`,
(4) inspect the failure branch for `ToolFailure` classification.

```text
1. Read echo-agent/echo-tools/src/web/fetch.rs (full).
2. Read echo-agent/echo-tools/src/web/search.rs (full).
3. Read echo-agent/echo-tools/src/media/image_fetch.rs (full).
4. Read echo-agent/echo-tools/src/research/arxiv.rs (full).
5. Read echo-agent/echo-tools/src/research/clients.rs (head, lines 1-120).
6. Read echo-agent/echo-tools/src/security.rs:520-650 (SSRF validators).
7. grep research/*.rs for `ToolFailure`, `Transient`, `.retryable`,
   `ssrf_safe_`, `start=`, `cursor`, `PageRequest`.
```

## Expected Result

- `web_fetch`, `web_search`: provenance present; pagination present; failures
  classified Transient/retryable; SSRF-safe connect.
- `image_fetch`: size cap enforced; SSRF-safe GET (audit 1.7 closed).
- `arxiv/pubmed/semantic_scholar/clinical_trials`: source IDs (doi/pmid/
  arxiv_id/pdf_url) returned; network failures classified Transient.
- Any collection-returning research tool that documents a `limit` should
  either offer cursor pagination or state in its description that pagination
  is unavailable.

- Summary:

  - **`web_fetch` (`web/fetch.rs`)** — exemplar.
    - Provenance: output prefix `URL: {}\nStatus: {}\nContent-Type: {}\n\n{}`
      (`fetch.rs:275-278`) plus `metadata["url"]` (`fetch.rs:309,323`).
    - Pagination: N/A (single URL fetch).
    - Network failure: HTTP non-2xx → `ToolResult::error` with status
      (`fetch.rs:211-216`); body-stream read error → `ToolResult::error`
      (`fetch.rs:243-248`).
    - SSRF: `crate::security::ssrf_safe_get(url, timeout, 5)` at `fetch.rs:201`
      — pinned-IP connect, closing the DNS-rebinding TOCTOU window.
    - Body cap: `MAX_BODY_BYTES = 10 MB`, enforced both via Content-Length
      (`fetch.rs:226-235`) and per-chunk while streaming
      (`fetch.rs:250-258`). `saturating_add` avoids overflow in the cap
      check.
    - UTF-8: `chars().take(max_len)` truncation (`fetch.rs:123`); artifact
      spill for oversized content (`fetch.rs:281-318`).

  - **`web_search` (`web/search.rs`)** — exemplar.
    - Provenance: each `SearchResult` carries `{title, url, snippet}`
      (`search.rs:208-217`); result envelope includes `provider` name
      (`search.rs:158-161`).
    - Pagination: cursor-based via `PageRequest::from_parameters` +
      `paginate(results, &query_identity)` (`search.rs:141-167`); description
      documents cursor usage (`search.rs:100-102`).
    - Network failure: provider error wrapped in
      `ToolFailure::new(ToolFailureCategory::Transient).retryable().with_retry_after(1_000)`
      (`search.rs:181-185`) — correctly hands retry policy to the central
      runtime. Two tests at `search.rs:291-323` verify this classification.
    - `limit` clamped to `[1, MAX_ALLOWED_RESULTS=10]` (`search.rs:80,115`).

  - **`image_fetch` (`media/image_fetch.rs`)** — live path is safe; dead

    - SSRF (live `execute` path): HEAD via `security::ssrf_safe_request`
      (`image_fetch.rs:198-203`), GET via `security::ssrf_safe_get`
      (`image_fetch.rs:226-227`). Audit finding 1.7 (image-fetch SSRF) is
      **fixed**.
    - Provenance: output includes URL, Content-Type, byte size
      (`image_fetch.rs:287-294`).
    - Dead helper `is_image_url` (`image_fetch.rs:47-67`, tagged
      `#[allow(dead_code)]`) issues `self.client.head(url).send()` directly,
      bypassing `ssrf_safe_*`. It is not called from `execute`; recorded as
      F-EXT-03-P3-03.

  - **`arxiv_search` (`research/arxiv.rs`)** — provenance strong; pagination
    missing; failure classification weaker than `web_search`.
    - Provenance: every entry returns `arxiv_id, title, authors, abstract,
      published, pdf_url, categories` (`arxiv.rs:247-255`).
    - Pagination: **absent**. URL hardcodes `start=0`
      (`arxiv.rs:112-113`); the tool always returns the first page of
      `max_results` results, with no `cursor` parameter. Description
      (`arxiv.rs:39`) honestly says "Max 100 results per query" without
      promising a next page, but this diverges from `web_search`/`sql_query`
      which do paginate. Recorded as F-EXT-03-P2-01.
    - Network failure: `reqwest` send error mapped to plain
      `ToolError::ExecutionFailed` (`arxiv.rs:123-126`), not wrapped in a
      retryable `ToolFailure`. Recorded as F-EXT-03-P3-02.
    - Query injection: `cat:` and `query` are `urlencoding::encode`d
      (`arxiv.rs:97-102`). Host is a hardcoded constant
      (`ARXIV_API_URL`, `arxiv.rs:13`), so the user cannot redirect the
      request to an arbitrary host; redirect policy is SSRF-safe
      (`arxiv.rs:21`).

  - **`pubmed` / `semantic_scholar` / `clinical_trials`** (grep + head

  - **SSRF validator (`security.rs:529-650`)**: `validate_url_with_addrs`

    link-local `fe80::/10`, plus IPv4-mapped IPv6 via `to_ipv4_mapped`).
    Callers receive the validated public IPs and pin the connection to them,
    which is the documented defense against DNS rebinding.

## Deviations

- `web_fetch` returns `ToolResult::error(...)` (not a `ToolFailure`-tagged
  result) for non-2xx HTTP and body-read failures. This is intentional: a
  404 or a malformed response is `Permanent`, not `Transient`, so it should
  not be auto-retried. `web_search`, by contrast, classifies provider-side
  transport failures as `Transient`. The two tools' failure models are
  consistent once you distinguish "remote said no" (Permanent) from
  "transport glitch" (Transient).
- The research clients are *not* inconsistent in provenance — every work
  carries a stable provider ID and at least one of doi/pmid/arxiv_id/url. The
  gap is purely pagination + failure classification, not provenance honesty.

## Conclusion

The claim **passes for provenance and SSRF** and **passes for the live
image-fetch SSRF fix (audit 1.7)**, but **fails for pagination parity and
failure classification** on the research tools. Three findings result:

- F-EXT-03-P2-01: `arxiv_search` / `pubmed` / `semantic_scholar` /
  `clinical_trials` return collections but expose no cursor pagination,
  unlike `web_search` and `sql_query`.
- F-EXT-03-P3-02: those same research tools return raw
  `ToolError::ExecutionFailed` on transient HTTP failures, not the
  `ToolFailure::new(Transient).retryable()` pattern that `web_search` uses.
- F-EXT-03-P3-03: `ImageFetchTool::is_image_url` (dead code) bypasses SSRF;
  the live `execute` path is SSRF-safe.
