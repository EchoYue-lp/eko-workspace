## Claim

No direct-user interactive tool (terminal, file picker, MCP
configuration, browser, TUI shell escape) is gated by
`require_full_auto`, `IpcAuth`, `IpcPermission`, or any
`permission_mode` read. The literal `require_full_auto` gate is gone
(matching the AGENTS.md historical lesson). The over-gating that does
exist is confined to the MCP IPC validators (`validate_ipc_mcp_stdio`
executable allowlist + `validate_ipc_mcp_url` private-range/loopback
block — inherited from A-INT-01-P1-01), and the excluded web-service
XSS/SSRF threat model has been re-invoked as the justifying narrative
in 5+ comments across the Tauri IPC layer (X-AUT-01-P2-01).

## Method

Repository-wide grep across both repos at the pinned commits,
narrowing from the broad "permission gate" pattern down to the
specific over-gating signatures.

```text

   IpcPermission (the historical gate + its orphaned definition):
   grep -rn "require_full_auto\|require_not_strict\|IpcAuth\|IpcPermission" \
       echo-agent echo-agent-cli --include="*.rs" | grep -v "test\|//"

   only, never a gate on a direct-user action):
   grep -rn "permission_mode" echo-agent-cli/src/tauri --include="*.rs" \
       | grep -v "test\|//\|/\*"

3. App-layer calls to the agent-tool entry (must be zero):
   grep -rn "execute_tool_with_policy" echo-agent-cli \
       --include="*.rs"

   (the MCP IPC over-gating):
   grep -rn "allowlist\|ALLOWED_.*BASES\|is_satisfied_by\|private.*range\|loopback\|169\.254\|192\.168\|172\.16" \
       echo-agent-cli/src/tauri --include="*.rs" | grep -v "test\|//"

5. Excluded-threat-model narrative in comments (XSS / SSRF / page JS):
   grep -rn "XSS\|SSRF\|xss\|ssrf\|cross-site\|cross site" \
```
