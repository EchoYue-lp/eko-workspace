## Claim

The local data-loss and secret protections EKO actually has are the ones
AGENTS.md explicitly endorses — they each map to one of the three
valid categories (data-loss prevention / framework-bug prevention /
local-universal secret safety) and none is a web-service-style gate
(XSS sanitiser, CSRF token, multi-tenant isolation). The protections
are wired into the live runtime, not dead code.

- Summary: claim confirmed. Ten protections verified live; all map to
  an AGENTS.md-valid category. One comment mis-justifies its gate via
  the excluded XSS model (finding X-AUT-01-P3-01).

  Step 1 — agent-path secret redaction (four live sites):

  | Site | What it redacts | Output destination |
  |---|---|---|
  | `echo-agent/src/tools/builtin/spawn_task.rs:171, 175` | `redact_secrets` on spawn_task stdout+stderr | tool result → trace |
  | `echo-agent/src/trace/mod.rs:434` | `redact_secrets` on every trace string | trace sink |
  | `echo-agent/src/agent/snapshot.rs:885-889` | `contains_secrets` → `redact_secrets` on tool output | snapshot |
  | `echo-agent/src/agent/react/run/execution.rs:229-230` | `contains_secrets` → `redact_secrets` on tool output | LLM input |

  All four call `echo_agent::security::redact_secrets` / `contains_secrets`
  (`security.rs:82-140`, 19 secret patterns). These are the live
  surfaces F-SEC-01 V02-01 audited; they are confirmed live here.

  Step 2 — direct-user MCP-config redaction (`mcp.rs:383-474`):
  `get_mcp_config` calls `redact_mcp_config_secrets(&mut value)` at
  `:388` before returning. The redactor (`:402-474`) strips:
  - `env` map values → `"<redacted>"` (entire value)
  - `headers` map values → `"<scheme> <redacted>"` (keeps auth scheme)
  - `url` credentials → URL with credentials stripped via
    `redact_url_secrets`

  This prevents the MCP panel from displaying configured secrets (API
  keys, env tokens) in the frontend. AGENTS.md category (3) — "不把密钥
  打进日志".

  Step 3 — IPC path validator secret-denylist
  (`path_validator.rs:15-60, 83-115`):
  - `DENIED_HOME_SUBPATHS` (`:18-28`): `.ssh`, `.aws`, `.config/gh`,
    `.docker`, `.gnupg`, `.kube`, `.netrc`, `.npmrc`, `.pypirc`.
  - `DENIED_FILENAME_CONTAINS` (`:31`): `history`, `cookies`, `cookie`.
  - Applied at `:107-112` inside `validate_ipc_path`, which gates
    `native_read_file` (`ipc.rs:29`), `native_write_file` (`ipc.rs:58`),
    and `native_open_path` (`ipc.rs:128`).

  This prevents the GUI file picker from reading credential files into
  the agent context. AGENTS.md category (3). The gate is appropriate;
  the module doc-comment at `:7-9` invokes the excluded XSS threat
  model ("XSS exfiltrating credentials via `native_read_file`"),
  driving finding X-AUT-01-P3-01.

  Step 4 — protected paths (`service.rs:512-528`, `protected.rs:24-59`):
  verified in V02-01. STEP 0 denies `.git/.ssh/.env/.aws/...` before
  the BypassPermissions short-circuit at STEP 1. AGENTS.md category
  (1) data-loss + (3) secret safety. Cross-checked with F-HITL-01 V01
  / V04.

  Step 5 — direct-user file/terminal guards:

## Conclusion

Supports X-AUT-01 Current Path §3 ("Local data-loss / secret
protections"). The ten protections are present, live, and each maps
to an AGENTS.md-valid category. None is a web-service-style gate
applied under the excluded threat model — the gates themselves are
local-valid; the *justifications* in four comments invoke the excluded
model, which is the documentation defect X-AUT-01-P2-01 / P3-01
tracks.

The protections confirm the "data-loss prevention / framework-bug
prevention / local-universal secret safety" half of AGENTS.md's
security-boundary rule is honoured in code. The protected-paths-
override-Bypass invariant (cross-checked with V02 and F-HITL-01 V04)
is the most load-bearing: it is what makes `full-auto` safe enough to
be a user-facing mode.
