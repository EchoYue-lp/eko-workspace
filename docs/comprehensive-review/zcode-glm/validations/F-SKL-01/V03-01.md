## Claim

When two tools with the same name are registered, the framework
resolves the collision deterministically: `ToolManager::register` is a
`DashMap::insert` keyed by tool name (silent last-wins overwrite), and
`ReactAgent::replace_tool` is `unregister(name) + register(tool)` so
the framework's progressive-disclosure tool instances always displace
any user-supplied tool of the same name on each discovery pass.

## Expected Result

`ToolManager` stores tools by name in a `DashMap<String, Box<dyn Tool>>`.
Two registrations of the same name: the second silently replaces the
first; the displaced tool is dropped. No panic, no error, no warning.
`replace_tool` produces the same end state (unregister + register) and
returns the displaced tool. The three progressive-disclosure tool names
are stable string literals: `"activate_skill"`, `"read_skill_resource"`,
`"run_skill_script"`.

- Summary:
  - `ToolManager::register` (tools.rs:529):
    `self.tools.insert(tool.name().to_string(), tool); self.invalidate_cache();`
    Insert into a `DashMap<String, Box<dyn Tool>>` keyed by tool name.
    The displaced tool (if any) is dropped silently — `DashMap::insert`
    returns the previous value, which `register` ignores.
  - `ToolManager::unregister` (tools.rs:541): removes by key and
    returns the displaced tool as `Option<Box<dyn Tool>>`; invalidates
    the definitions cache.
  - `ReactAgent::replace_tool` (capabilities.rs:72):
    `let old = self.tools.tool_manager.unregister(&name); self.tools.tool_manager.register(tool); old`
    Explicit unregister + register; the previous tool is returned to
    the caller (which discards it in the discover path).
  - Post-discovery refresh (capabilities.rs:785-795): on every
    `discover_skills_inner`, three new tool instances are built from
    the latest `available_names` and registry handle, then handed to
    `replace_tool`. The previous instance (framework's own, from the
    prior pass, or a user-supplied tool with the same name) is
    displaced.

## Deviations

- A user-registered tool whose name collides with one of the three
  progressive-disclosure tool names is silently replaced on the next
  `discover_skills()` call. Recorded as task finding F-SKL-01-P3-02,
  not a validation failure: the displacement is the intended behavior
  (the progressive-disclosure tools MUST be the framework's instances
  so their `available_names` snapshot stays correct), but the
  displacement is not logged or surfaced to the user.

## Conclusion

Tool-name collision resolution is deterministic last-wins via
`DashMap::insert`. The progressive-disclosure tools are refreshed on
every discovery pass via `replace_tool`, so they always reflect the
latest registry state. The contract is stable and matches the
implementation; the only gap is observability of user-tool
displacement (F-SKL-01-P3-02). Supports the task report's "Current
Path" item 9 and Finding F-SKL-01-P3-02.
