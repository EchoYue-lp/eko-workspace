## Claim

The compiled subagent prompt is **bounded** (each compiler-owned section
appears exactly once, with a token-budget cap on role prompts and
deduplication guards against compiler-owned sections bleeding into role
`.md`), **language-consistent** (one explicit language policy that anchors
on the user's request language, not the role prompt's language), and
**UTF-8 safe** (the `.md` parser and the prompt assembler never perform
byte-level slicing that could panic on multi-byte characters).

## Expected Result

(1) `EkoSubagentPromptCompiler::compile_system` produces a system prompt
    where each compiler-owned section appears exactly once.
(2) The compiled prompt ends with `render_result_contract()` (the
    framework's terminal `## Result` envelope).
(3) Role `.md` files are bounded (≤ 700 tokens by audit) and do NOT
    duplicate compiler-owned sections.
(4) The language policy is singular, explicit, and anchors on the user's
    request language.
(5) No byte-level slicing (`&s[..n]`, `&s[n..]`, `s[range]`) on
    potentially multi-byte content. All truncation / find operations are
    char-boundary-safe.

### (5) UTF-8 safety — verified

`subagent_loader.rs` (the `.md` parser):

- Line 514: `content.strip_prefix('\u{feff}').unwrap_or(content)` — strips
  a UTF-8 BOM if present. `str::strip_prefix(char)` is UTF-8 safe.
- Line 516: `content.strip_prefix("---")` — ASCII pattern, returns
  `Option<&str>`; safe.
- Line 521-523: `after_open.strip_prefix(['\r', '\n'])` — char-array
  pattern; safe.
- Line 526-528: `after_open.find("\n---")` — returns a byte index, but
  the pattern is ASCII (`\n---`). For a `&str`, `find` returns an index
  where the pattern starts, and ASCII patterns only match at UTF-8 char
  boundaries. The byte index is therefore guaranteed char-aligned.
- Line 530: `&after_open[..close_idx]` — byte slice at a char boundary
  (per above). Safe.
- Line 533: `&after_open[close_idx + "\n---".len()..]` — ASCII pattern
  length is 4 bytes; the resulting index is also char-aligned. Safe.
- Line 539: `rest.trim_start_matches(['\r', '\n'])` — char-array pattern;
  safe.
- Line 425: `body.trim().to_string()` — stdlib, safe.
- Line 419-420: `fm.name.map(|n| n.trim().to_string()).filter(|n| !n.is_empty())`
  — stdlib, safe.

`subagent_prompt.rs` (the compiler):

- All string construction uses `format!`, `push_str`, `\n\n`.join, `trim`.
  No byte slicing.
- The diagnostics counting uses `matches().count()` (UTF-8 safe).
- `chrono::Local::now().format("%Y-%m-%d")` returns ASCII date — safe.

`prompt_contract.rs` uses `HeuristicTokenizer::count_tokens` and

## Deviations

Three observations that do not invalidate the claim:

1. **The 700-token role-prompt budget is enforced only by a unit test**,
   not by a runtime check. A user-authored project `.md` could exceed 700
   tokens and the loader would accept it (`parse_subagent_md` has no
   token-budget gate). The audit runs only against builtins in the test.
   This is acceptable — project `.md` files are user-authored and the
   token budget is a style guideline, not a hard limit — but worth noting.

2. **Plugin role `.md` files bypass the cardinality contract.**
   `register_plugin_agents` (`plugin_components.rs:471-472`) uses the
   parsed `definition.system_prompt` verbatim via `framework_definition`'s
   `system_prompt: Some(definition.system_prompt.clone())` (line 494). It
   does NOT call `EkoSubagentPromptCompiler::compile_system`. The agent is
   then built via `build_plugin_agent` (`plugin_components.rs:511-551`)
   which sets `builder.system_prompt(&definition.system_prompt)` (line
   520) — the raw markdown body. This means a plugin's role prompt does
   not get the compiler-owned sections (no `## Subagent Protocol`, no `##
   Response Language`, no `## Result Quality`, no `render_result_contract()`
   appended). Plugin authors must include those sections themselves if
   they want the same envelope. The framework's `parse_subagent_outcome`
   parser (per F-SUB-01) looks for the `## Result` heading — a plugin
   whose raw prompt omits it would produce un-parseable dispatch results.
   This is a real asymmetry between builtin and plugin subagents.

3. **`compile_system` is invoked per subagent, not cached.** Every call
   to `register_default_subagents` recompiles the system prompt for each
   of the 8+ definitions, and pool agents re-invoke the whole
   `register_default_subagents` path. This is a small CPU cost, not a
   correctness issue.

## Conclusion

The claim is **supported**. The compiled prompt has exactly-once section
cardinality (verified by passing tests), terminates in the framework
result contract, role `.md` files are bounded and free of compiler-owned
sections, the language policy is singular and well-anchored, and the
loader/compiler/assembler are UTF-8 safe (verified by code review and the
CJK parsing test). The plugin-path bypass of `compile_system` (deviation
2) is the most material asymmetry and is noted; it is not a UTF-8 or
cardinality violation of the claim as stated.

Findings that use this validation: this validation primarily supports the
"prompt compilation is sound" conclusion in the task report's Current Path.
The plugin-prompt asymmetry noted in deviation 2 is not filed as a
separate finding because it is a consequence of the plugin registration
path already covered by A-SUB-01-P2-01 / A-SUB-01-P2-03; a future task
that fixes those should also wire `compile_system` for plugin agents.
