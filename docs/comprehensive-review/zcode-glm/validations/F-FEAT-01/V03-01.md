## Claim

Every optional dependency in `echo-agent` is activated exclusively through
its owning feature using the `dep:` prefix, with no leakage (i.e., no
feature implicitly pulls in a dep that should require an explicit
opt-in, and no optional dep is enabled by `default`).

## Method

Read-only inspection of all `[dependencies]`, `[dev-dependencies]`, and
`[features]` tables in the 8 `echo-agent` Cargo.toml files. Working
directory: `/Users/ls/MyWork/code/ylp_agent_learn/lp-agent/echo-agent`.

```text
1. For each Cargo.toml, list every dependency marked optional = true.
2. For each optional dep, find the feature that activates it (search for
   dep:<name> and bare <name> in [features]).
3. Verify each activation uses the dep: prefix (Cargo strong form).
4. Verify default = [] (no optional dep auto-enabled).
5. Verify sub-crates forwarded by feature use default-features = false where
   appropriate (echo_tools, echo_core, etc.).
```

## Expected Result

- `default = []` at the root.
- Every feature → dependency mapping uses `dep:` prefix.
- Sub-crate dependencies use `default-features = false` to avoid pulling
  unintended feature sets.

## Result

- Exit code: 0
- Summary: No leakage detected. All feature-enabled dependencies use the
  `dep:` prefix correctly. `default-features = false` is properly applied
  on internal sub-crate dependencies (`echo_tools`, `echo_core`, etc.) so
  that enabling a feature in the root does not silently enable a sub-crate's
  default features.
