## Claim

The twelve parity gaps from V03 can be prioritized into a defensible
action list ordered by (a) user-visible impact (does the gap make a
capability unreachable?), (b) blast radius (how many users / scenarios
affected), (c) cost-to-fix (localized vs cross-cutting), and (d)
risk-of-regression (does the fix touch chat / data-flow / critical
paths?).

The prioritization must:

- Put the single P1 gap (GUI MCP over-validation) first because it
  makes a user-configured capability unreachable in the default GUI.
- Cluster the P2 gaps by theme (cancel / recovery / observability /
  cleanup).
- Defer the P3 cleanup items until after the P1/P2 clusters.
- Identify the smallest set of fixes that close the most parity gaps
  (the "leverage" view).

## Method

Static prioritization exercise at
`/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`. For each of the
twelve V03 gaps, score on four axes and rank.

```text
For each gap:
  1. user_visible_impact: high (capability unreachable) | medium
     (degraded UX) | low (cosmetic)
  2. blast_radius: high (every session) | medium (specific scenarios)
     | low (rare paths)
  3. cost_to_fix: small (localized, <100 LOC) | medium (one module)
     | large (cross-cutting, multiple modules)
  4. risk_of_regression: low (new surface wiring, no core change)
     | medium (touches sink or service starter) | high (touches chat
     lifecycle / data flow)

Then rank by: user_visible_impact desc, blast_radius desc, cost asc,
risk asc. Identify clusters that share a root cause or a fix locus.
```

## Expected Result

A prioritized table plus a "leverage" view identifying which fixes
close multiple gaps.

### Thematic clusters

The twelve gaps group into five fix themes. Acting on a theme closes
multiple gaps with related work.

#### Cluster A: Input-validation over-gating (1 gap)

- **Gap 1**: GUI MCP IPC validators apply an online-service threat
  model that AGENTS.md excludes for EKO.
- **Why cluster**: this is the only P1 and the only gap that
  *contradicts* AGENTS.md's product-positioning section. It is the
  same class of regression as the historical `require_full_auto` gate.
- **Fix locus**: `tauri/commands/mcp.rs:110-208` (the validators) +
  `:565-613` (the tests that lock in the over-gating).
- **Pairs with**: nothing — this is fully isolated.

#### Cluster B: Missing service wiring + recovery on unattended triggers (2 gaps)

- **Gap 3**: channels-only skips `start_headless_services`.
- **Gap 4**: cron runs not in the `resume_pending` filter.
- **Why cluster**: both are missing-wiring gaps on unattended triggers
  where the wiring primitive already exists (`start_headless_services`,
  `resume_pending`). Both have the same root cause: a feature was
  added (channels-only entry, cron trigger) without extending the
  shared service path.
- **Fix locus**: `main.rs:357-403` (channels branch) +
  `tasks/service.rs:474-563` (resume filter).
- **Pairs with**: A-BOOT-01-P2-02 (the boot-side finding that
  A-SRF-04-P2-03 sharpens).

#### Cluster C: Cancel + cleanup lifecycle (2 gaps)

- **Gap 2**: REPL + channels Chat/Auto turns have no externally
  reachable cancel handle.
- **Gap 7**: GUI window close does not call `TerminalManager.close_all`.
- **Why cluster**: both are lifecycle-end gaps where the primitive
  (`CancellationToken` registry, `close_all`) exists but is not
  invoked at the right moment.
- **Fix locus**: `repl.rs:485-545` + `channels.rs:195-265` (cancel) +
  `tauri/mod.rs` + `tauri/desktop.rs` (close_all hook).
- **Pairs with**: nothing.

#### Cluster D: Observability + interactive management (3 gaps)

- **Gap 5**: TUI subagent detail collapses 11/16 variants.
- **Gap 6**: No LSP restart surface on any mode.
- **Gap 10**: Tool-execution persistence is GUI-only.
- **Why cluster**: all three are observability / management gaps
  where the framework emits the events or exposes the primitive, but
  no surface consumes them. The unifying fix is "wire the framework
  primitive to a surface".
- **Fix locus**: `tui/events.rs:5343-5434` (subagent reducer) +
  new TUI `/lsp` + new Tauri `lsp.rs` + a `ToolExecutionObserver` in
  `ChatResources`.
- **Pairs with**: A-CHAT-01-P2-01 + A-SRF-02-P2-03 (the proposed
  unified recorder).

#### Cluster E: Surface command parity (3 gaps)

- **Gap 8**: channels reduced slash set.
- **Gap 11**: REPL `/mcp` stub.
- **Gap 12**: permission-mode alias drift.
- **Why cluster**: all three are command-surface parity gaps where
  one surface accepts a different command vocabulary than another.
- **Fix locus**: `channels.rs` (new dispatcher) + `cmd_impls/skills.rs`
  (wire MCP arms) + new app-core `PermissionMode::from_alias`.
- **Pairs with**: A-SRF-02-P2-02 (the alias unification owner).

### Recommended sequencing

1. **P1 first** (Gap 1) — the only capability-unreachable gap.
2. **One-line cluster** (Gaps 3, 4, 7, 12) — all small, all localized,
   all close a parity gap with near-zero regression risk. Bundle into
   a single "parity hygiene" PR.
3. **Cancel surface** (Gap 2) — medium effort but high operational
   impact for CLI/channels users.
4. **LSP restart surface** (Gap 6) — medium effort, low risk, gives
   every mode LSP recovery.
5. **Unified `ToolExecutionObserver`** (Gaps 5, 10) — the largest
   single leverage; coordinates with A-CHAT-01-P2-01 / A-SRF-02-P2-03.
6. **Channel slash surface + REPL MCP stub** (Gaps 8, 11) — closes
   the channels parity gaps.
7. **TUI subagent reducer extension** (Gap 5 short-term) — can be
   done independently of the unified recorder for immediate TUI
   observability improvement.
8. **TUI interactive terminal pane** (Gap 9) — a larger UI feature;
   defer until the wiring gaps are closed.

### What this report does NOT recommend

- **No architectural changes.** The two-lane architecture is sound;
  every gap is a wiring gap. No new lane, no parallel implementation,
  no framework rewrite.
- **No new permission gates.** AGENTS.md is explicit: do not over-gate
  the local personal assistant. The P1 fix *removes* a gate; none of
  the other fixes add one.
- **No new framework concepts.** Every fix uses an existing framework
  primitive (`register_run_cancellation`, `restart_server`,
  `close_all`, `ToolExecutionRepository`, `connect_mcp_from_config`,
  `validate_stdio_command`).
