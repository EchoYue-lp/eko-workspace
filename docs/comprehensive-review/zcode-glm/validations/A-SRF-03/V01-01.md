## Claim

The React chat surface has exactly one chat transport that registers
exactly one listener per channel, dispatches events through a single
canonical handler, and writes to dedicated stores. Specifically:
(a) `chat://event` is received with the typed `ChatEvent` discriminated
union; (b) `execution://event` is received as `Record<string, unknown>`
and branched on `kind`; (c) no parallel chat transport or sink exists.

## Method

Static enumeration and trace. Working directory:
`/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`.

```text
1. Enumerate every Tauri listen() registration in the frontend:
   grep -rn "listen<\|listen(" echo-agent-cli/web-frontend/src \
       --include="*.ts" --include="*.tsx"

2. Confirm useTauriChat is mounted exactly once:
   grep -rn "useTauriChat\|useChatTransport" echo-agent-cli/web-frontend/src \

3. Confirm no parallel chat transport exists (WebSocket removal):
```

## Expected Result

- Exactly two `listen` calls for chat-related channels in
  `useTauriChat.ts`, plus one in `useBrowserEvents.ts` and two in
  `Terminal.tsx`. No other chat listener exists.
- `useTauriChat` is called only from `ChatPanel.useChatTransport`.
- No `useWebSocket` or `new WebSocket` references remain.
- The `ChatEvent` TypeScript union matches the Rust `ChatEvent` enum
  variant-for-variant with the same `rename` tags.
- `execution://event` is received untyped and dispatched on `kind`.
