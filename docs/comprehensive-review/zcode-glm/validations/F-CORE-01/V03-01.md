## Claim

`stable_event_id` produces a collision-resistant, monotonic identity per
envelope stream, and the `EventIdentity::from_invocation` fallback chain
always yields a non-degenerate `turn_id`.

## Expected Result

`event_id` is a deterministic SHA-256 over (schema_version,
conversation_id, run_id, turn_id, execution_id, sequence). Sequence is
`saturating_add(1)` per payload starting at `last_persisted + 1`. The
fallback chain never returns empty `turn_id` in production.

## Result

- Exit code: not-applicable (static inspection)
- Duration: n/a
- Summary:
  - **`stable_event_id` inputs** (`event_envelope.rs:64-84`): schema_version,
    conversation_id, run_id, turn_id, execution_id, sequence. The hash
    distinguishes `None` (sentinel byte 0) from `Some("")` (sentinel 1 +
    length 0 + empty bytes), so empty strings are not confused with absent
    fields. `parent_event_id` is **not** part of the hash — by design, so
    that re-emitting a payload with a different parent does not change id.
  - **Determinism** is verified by `resumes_after_persisted_sequence_with_stable_ids`
    (`event_envelope.rs:399-427`): two `EventEnvelope::new` calls with the
    same `(identity, sequence, payload)` produce the same `event_id`, which
    is the contract for idempotent replay after persistence.
  - **Sequence monotonicity** (`event_envelope.rs:128-194`): the wrapper
    holds `last_persisted_sequence` as `u64`, calls
    `sequence.saturating_add(1)` before emitting each envelope, and appends
    exactly one synthesized terminal `Error` envelope when the underlying
    stream ends without a terminal payload (`event_envelope.rs:180-191`).
    Monotonic within one wrapped stream.
  - **`turn_id` fallback** (`event_envelope.rs:91-96`):
    `turn_id || execution_id || run_id || fresh uuid`. The uuid fallback
    guarantees non-empty turn_id for any invocation.
  - **Caller identities**:
    - chat_driver (`chat_driver.rs:211-216, 483-489`) sets `turn_id =
      root_message_id` (or fresh uuid on empty), so every chat turn is
      unique.
    - subagent executor (`subagent/executor.rs:802-825`) calls
      `ensure_background_execution_id` which assigns `execution_id =
      agent_tool-{uuid}` when missing, then `from_invocation` picks that
      execution_id as turn_id (because `turn_id` is None for subagent
      dispatches). So concurrent subagent forks get distinct event_id spaces.
    - a2a server (`a2a/server.rs:211-217`) sets `turn_id = task_id`,
      `run_id = Some(task_id)`, `execution_id = Some(task_id)` — three
      fields collapse to one value, but `task_id` is unique per A2A task,
      so collisions across tasks do not occur.
  - **Trajectory validator** (`event_envelope.rs:197-295`) detects duplicate
    event_ids **inside one trajectory** but not across two parallel
    trajectories sharing the same identity prefix.
- Log/artifact: none

## Deviations

Three edge cases are reachable in principle and are not guarded against:

1. **`EventIdentity::default()` produces empty `turn_id`.** `Default` is
   derived (`event_envelope.rs:13`), so `turn_id` becomes `""`. If two
   production callers constructed envelopes from `EventIdentity::default()`,
   their sequence-1 envelopes would collide. (Today only test code does
   this — `channels.rs:747-749`, `chat_driver.rs:1131-1132` — but the
   possibility is undocumented.)
2. **No cross-stream collision guard.** Concurrent streams that share
   `(conversation_id, run_id, turn_id, execution_id)` will emit colliding
   `event_id`s for the same sequence number. The current callers avoid this
   only because each sets a unique `turn_id`/`execution_id`; the framework
   does not enforce the invariant.
3. **`execution_id` as fallback for `turn_id`** means two callers that both
   leave `turn_id = None` but share the same `execution_id` (e.g. a
   parent's execution_id propagated without forking) collapse to the same
   identity space.

None of these is currently triggered by the audited callers, but they are
silent-failure modes that violate the "stable identity for independent
consumers" invariant the task asks about.

## Conclusion

`stable_event_id` is correct and the fallback chain guarantees non-empty
`turn_id` for **well-behaved** callers; sequence is monotonic per stream;
replay idempotence holds. The contract breaks down only for **misbehaving**
callers that share identity fields across concurrent streams. Used by
finding F-CORE-01-P2-02 (undocumented cross-stream collision invariant) and
F-CORE-01-P3-03 (`EventIdentity::default()` exposes empty turn_id).
