### (1) Envelope predicate is marker-agnostic

```rust
// echo-state/src/compression/mod.rs:30
const PROJECTION_ENVELOPE_PREFIX: &str = "<echo-agent-context-projection-v1>";

// :36-38
pub fn is_context_projection_message(message: &Message) -> bool {
    projection_envelope_text(message).is_some()
}

// :40-53
fn projection_envelope_text(message: &Message) -> Option<&str> {
    match &message.content {
        MessageContent::Text(content) => content
            .starts_with(PROJECTION_ENVELOPE_PREFIX)
            .then_some(content.as_str()),
        MessageContent::Parts(parts) => parts.first().and_then(|part| match part {
            ContentPart::Text { text } if text.starts_with(PROJECTION_ENVELOPE_PREFIX) => Some(text.as_str()),
            _ => None,
        }),
        MessageContent::Empty => None,
    }
}
```

The predicate matches on the envelope prefix only. The marker
(`eko:instruction-context`, `eko:hot-memory-context`, etc.) is encoded inside
the envelope (`marker="..."` line) but is not consulted by the protection
predicate. So both EKO markers are treated identically by the protection
machinery.

### (4) Immunity to summary accumulation

F-CMP-01-P2-01 established that `SummaryCompressor` and
`IncrementalSummaryCompressor` append a new `[对话历史摘要]` system message on
each pass without removing the previous one, causing unbounded system-region
growth. Those summary messages are NOT projection messages (they do not carry
the `<echo-agent-context-projection-v1>` envelope), so they remain in the
`compressible` set and are subject to the accumulation.

EKO's two projections (`eko:instruction-context`, `eko:hot-memory-context`)
ARE projection messages, so they are in the `protected` set, never enter the
compressor, and are re-inserted exactly once by `merge_protected`. There is no
mechanism by which a projection could accumulate across cycles: `merge_protected`
inserts from the `protected` vector, whose cardinality is fixed by the most
recent `split_protected` call, which in turn is bounded by the number of
projection messages currently in `self.messages` (one per marker, because
`replace_projection` removes the previous message with the same marker before
inserting the new one — `apply_projections:556`).
