## Claim

The defaults and trait impls that govern EKO's evolution boundary
enforce "explicit user action required for any semantic mutation".
Specifically: `ReviewConfig::default()` and `BackgroundReviewConfig::
default()` are conservative; `MemoryTriggerSink` returns `Captured`;
`SkillLoadPolicy` blocks drafts and foreign skills; `EvidenceStore::
accept` is the only inbox-to-durable-memory bridge.

### ReviewConfig::default() (framework `review.rs:527-537`)

```rust
impl Default for ReviewConfig {
    fn default() -> Self {
        Self {
            review_on_session_end: false,
            max_conflicts_per_review: 10,
            max_conflict_members: 16,
            detect_skill_candidates: true,
            auto_generate_drafts: false,
        }
    }
}
```

EKO consumes it verbatim: `runtime.rs:236` constructs
`ReviewConfig::default()`; no field override anywhere in the
application crate (`grep -rn "review_on_session_end\s*:" echo-agent-
cli/` returns only the framework's own definition site and one test).

### BackgroundReviewConfig (framework `background_review.rs`)

Per F-EVO-01 V03 (re-verified): `auto_persist_user_preferences = false`
by default; project facts, debugging lessons, and skills are always
proposal-only regardless of config. The CLI `/review` command
(`evolution.rs:36-157`) calls `BackgroundReviewer::review` and pipes
the outcome through `capture_review_outcome` into the Evidence Inbox —
no durable write.

### MemoryTriggerSink disposition (`review_integration.rs:277-321`)

The impl converts the framework `TriggerMatch` into an
`EvidenceCandidateDraft`, upserts it into the workspace `EvidenceStore`,
and returns `Ok(MemoryTriggerDisposition::Captured)` unconditionally.
The comment at `:314-317` states: "EKO treats inferred memory as
review-only. Do not let an inbox storage failure fall through to the
framework's direct durable write path and silently bypass that review
gate." A storage failure logs a warning but the disposition remains
`Captured`, so the framework's auto-write is suppressed even on inbox
failure (fail-closed for write-bypass, fail-open for candidate drop).

### SkillLoadPolicy (`review_integration.rs:324-348`)

Three gates, all read-only:
1. Reject any descriptor whose path contains a `_drafts` ancestor.
2. Reject any descriptor whose `skills/` root does not match the
   current workspace's `.eko/skills`.
3. Reject any skill whose curator-recorded lifecycle is not `Active`
   or `Stale` (so `Candidate`, `Draft`, `Deprecated`, `Archived` are
   blocked from the loader).

No promotion side effect; pure filter.

### EvidenceStore::accept (`evidence.rs:478-636`)

The only inbox→mutation path. Requires `candidate_id: &str`. Two
branches:
- `SaveMemory`: calls `layer_manager.write_memory(&key, &candidate.
  content, meta)`; on success records `Applied` + `EvidenceTarget::
  Memory`; on persistence-record failure, deletes the memory
  (`delete_memory`) and returns an error (rollback).
- `MergeMemories { proposal }`: calls `layer_manager.apply_merge_
  proposal(&proposal)`; on success records `Applied` +
  `EvidenceTarget::MemoryMerge { before, primary_key, superseded_keys
  }`; on persistence-record failure, calls `restore_merge_snapshots`
  (rollback).

`undo` (`evidence.rs:638-770`) is the symmetric revert. No other
callers of `write_memory` / `apply_merge_proposal` exist in
`evidence.rs`.

### AUTO_MEMORY_ENABLED default (`all.rs:462-463`)

```rust
pub static AUTO_MEMORY_ENABLED: std::sync::atomic::AtomicBool =
    std::sync::atomic::AtomicBool::new(true);
```

The default is `true`. Its only effect, however, is to run
`run_auto_memory_on_exit` at session end (`repl.rs:265-330`), which
calls `queue_observations` — pure inbox candidate insertion, no durable
write. The flag does not gate any direct memory mutation.

## Deviations

None. The `AUTO_MEMORY_ENABLED = true` default is mildly surprising
against the conservative defaults elsewhere, but its only consumer
writes to the Review Inbox, not to durable memory.

## Conclusion

Supports the V02 claim. Every semantic mutation requires an explicit
user action; the defaults and trait impls enforce this. The Review
Inbox is the single bridge from proposal to durable state, and the
bridge is one function (`EvidenceStore::accept`) with rollback
semantics.
