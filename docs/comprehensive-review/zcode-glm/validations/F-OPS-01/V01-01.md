## Claim

The cron scheduler trigger lifecycle is inspectable end-to-end from
composition root to background task; specifically: how cron tasks are
triggered, whether they are cancellable, whether there is graceful shutdown
cleanup, and whether the persistence bridge is runtime-portable. This
validation confirms the static facts that underlie F-OPS-01-P1-01,
F-OPS-01-P2-03, F-OPS-01-P2-04, and F-OPS-01-P3-01/02/03.

## Expected Result

- A documented path from composition root to the run_loop background task.
- Evidence that the scheduler observes a CancellationToken.
- Evidence (or absence) of graceful shutdown: cancellation fired by the
  application on shutdown, and a way to await task termination.
- A statement on `block_in_place` portability.

## Result

- Exit code: not-applicable (static inspection)
- Duration: n/a
- Summary:
  - Trigger: 30 s tick in `run_loop`, window-based selection in `tick`,
    `fire_task` calls the EKO `FireFn` which dispatches to
    `launch_cron_run`. Confirmed.
  - Cancellation: the loop observes `self.cancel.cancelled()`, so it is
    cancellable in principle.
  - Shutdown: **no application caller ever fires
    `AppState.scheduler.cancel_token`**. The framework `spawn` drops the
    `JoinHandle`. There is no graceful drain of in-flight `fire_task`
    invocations. (Supports F-OPS-01-P1-01.)
  - Serial fire + no per-task timeout: confirmed via `runner.rs:99-101` and
    `105-118`. (Supports F-OPS-01-P2-03.)
  - `block_in_place` is used in `load_all`/`save_all`; will panic on a
    current_thread runtime. EKO itself uses multi-thread, so this is a
    framework-portability issue, not an EKO production outage.
    (Supports F-OPS-01-P2-04.)
  - `last_fired` is inserted-into but never evicted (deleted task IDs
    linger). (Supports F-OPS-01-P3-03.)
  - `remove`/`set_status`/`update_last_run`/`get` use ID prefix match;
    `remove_exact` is the only tested exact-match path. (Supports
    F-OPS-01-P3-02.)
  - `next_run` and `validate_cron` duplicate the 5->7 field padding.
    (Supports F-OPS-01-P3-01.)
- Log/artifact: none created.

## Deviations

None. The inspection covered every line of `scheduler/{mod,cron_task,runner}.rs`

## Conclusion

Supports F-OPS-01-P1-01 (no graceful shutdown), F-OPS-01-P2-03 (serial fire +
no timeout), F-OPS-01-P2-04 (`block_in_place` panic on current_thread),
F-OPS-01-P3-01 (padding duplication), F-OPS-01-P3-02 (inconsistent ID match),
and F-OPS-01-P3-03 (`last_fired` never evicted). Does not by itself prove
runtime behaviour — a dynamic shutdown test is the regression validation
specified in the task report's Direction for each finding.
