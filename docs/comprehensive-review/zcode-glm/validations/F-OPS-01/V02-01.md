## Claim

The headless runner `run_headless` is **not** event-equivalent to the
interactive/streaming execution path. Specifically, it does not produce or
consume an `AgentEvent` stream, does not register a `RunStore`, does not
plumb a `CancellationToken`, and does not emit tool/permission/metrics
events. This validation confirms the static facts that underlie
F-OPS-01-P1-02.

## Method

Read-only static inspection of `echo-agent/src/headless.rs` plus the Agent
trait surface that headless calls into, and a repository-wide live-caller
inventory. No commands were executed.

```text
1. Open echo-agent/src/headless.rs:
   - read HeadlessConfig (31-43), HeadlessResult (57-91),
     run_headless body (106-159).
   - confirm at line 145 the call is `agent.execute(&config.prompt).await`
     returning Result<String>.
   - confirm the only options applied to the builder are max_iterations
     (lines 124-128); no .with_run_store(...), no .with_callback(...),
     no event sink.

2. Open echo-agent/src/agent/react/mod.rs:
   - read the Agent trait impl `fn execute` (2767-2778): delegates to

     This is what the streaming path uses.

     matches.
```

## Expected Result

- A documented call path showing `run_headless` invokes `agent.execute`,
  which returns a single `String`, not an event stream.
- Confirmation that no `RunStore`, `CancellationToken`, or `AgentCallback`
  is attached.
- A live-caller inventory showing only a demo example exercises it.
- A comparison with the streaming path (`execute_stream`,
  `chat_stream_message`) demonstrating what is missing.

## Result

- Exit code: not-applicable (static inspection)

- Summary:
  - `run_headless` calls `agent.execute(&config.prompt)` at `headless.rs:145`,

## Conclusion

Supports F-OPS-01-P1-02: headless mode is a minimal one-shot helper that is
**not** functionally equivalent to interactive mode (no events, no trace
store, no cancellation, no metrics). Any downstream claim of "all modes
equivalent" (X-SRF-01 surface-parity matrix) must explicitly exclude
`run_headless` until it is rebuilt on top of the streaming API. The
product's own CLI avoids `run_headless` precisely because of these gaps —
strong independent evidence that the gap is real and recognised.

Does not prove the streaming path itself is correct — that is owned by
F-RCT-03 / A-CHAT-01.
