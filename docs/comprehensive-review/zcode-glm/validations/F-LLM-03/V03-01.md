## Claim

strategy; `convert_request` faithfully maps the plan to
`cache_control: {type:"ephemeral"}` placements respecting Anthropic's
4-breakpoint limit and runtime-context exclusion; the Anthropic
`cache_creation_input_tokens` / `cache_read_input_tokens` fields are
correctly extracted into the neutral `Usage` on both paths and feed
the F-LLM-01 normalization authority without adapter-side duplication.
The streaming path's omission of the `anthropic-beta` header is the
one deviation.

## Deviations

- The streaming send block (`anthropic.rs:440-448`) omits the
  `anthropic-beta: prompt-caching-2024-07-31` header that the
  non-streaming send block includes (`:387`). The request body emits
  `cache_control` markers identically on both paths, but the streaming
  path's markers may be ignored or rejected depending on Anthropic API
  version and account tier. See finding F-LLM-03-P2-03.
- The adapter reads `cache_creation_input_tokens` /
  `cache_read_input_tokens` only from `message_start.usage` on the
  streaming path. If Anthropic ever sends these fields in
  `message_delta.usage` (newer API versions or certain account tiers),
  the streaming cache accounting would miss them. The non-streaming
  path reads from the merged `AnthropicUsage` and is unaffected. This
  is a theoretical gap; current Anthropic documentation places these
  fields only in `message_start`.
- The `cache_hints.segments` field (computed by the agent layer via
  `PromptCacheLayout::segment_ranges`) is NOT consumed by the adapter
  — `convert_request` re-derives the layout from `request.messages +
  tools` and uses the layout's breakpoints, not the segments. This is
  a minor inefficiency (recomputation) but not a correctness issue;
  the layout derivation is deterministic.

Anthropic's hard limit and runtime-context exclusion. `convert_request`

paths feeds the F-LLM-01 normalization authority without adapter-side
duplication; the Anthropic-exclusive cache semantics is handled
centrally. The one material deviation is the streaming path's missing
`anthropic-beta` header, which makes cache behavior inconsistent
