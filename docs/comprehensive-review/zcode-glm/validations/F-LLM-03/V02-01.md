## Claim

The Anthropic adapter's thinking-block translation is consistent with the
framework `ThinkingProtocol` resolver, the streaming event loop
assembles tool calls correctly under all block orderings, and the
response-side thinking content is preserved end-to-end. Deviations are
the documented F-LLM-01 gaps plus a streaming tool-index desync that
drops tool calls whenever text precedes `tool_use`.

## Method

Static inspection of `build_anthropic_thinking`, the streaming
`chat_stream` event loop, the `ContentBlock` / `ContentDelta` /
`AnthropicStreamEvent` wire types, and the `convert_response`
non-streaming path. Cross-checked against the `ThinkingProtocol`
resolver in `capabilities.rs` and the streaming-event specification.

## Expected Result

`build_anthropic_thinking` emits the correct thinking block per protocol;
the streaming event loop preserves every tool_use block regardless of
surrounding text/thinking blocks; the response mappers surface thinking

## Deviations

- The streaming tool-call index/key desync (F-LLM-03-P1-01) drops tool
  calls whenever text or any non-tool-use block appears before
  `tool_use`. This is the dominant case in agentic Claude flows. The
  streaming path is live via `think.rs:329`.
- Anthropic thinking blocks are not surfaced on either path
  (F-LLM-03-P2-01 / F-LLM-03-P2-02). Streaming silently drops thinking
  deltas; non-streaming hard-fails the response deserialization.
- Signed thinking blocks cannot round-trip on the request side
  (F-LLM-03-P3-02): the adapter `ContentBlock` enum has no `Thinking`
  variant, so even after the response-side gap is closed there is no
  way to attach a prior thinking block to an outgoing assistant
  message.
- The `claude-sonnet-4-6` (dash-form) model name resolves to the wrong
  thinking protocol (Budget instead of Effort). This is a resolver
  fragility, not an adapter bug; flagged here because it affects the
  adapter's runtime behavior. The dot-form `claude-sonnet-4.6`
  resolves correctly.

## Conclusion

The Anthropic thinking translator (`build_anthropic_thinking`) is a
clean single-purpose resolver that faithfully emits the right wire
shape per protocol and correctly drops fields that would 400. The
streaming event loop's TOOL-CALL ASSEMBLY HAS A P1 INDEX/KEY DESYNC
that silently drops tool calls whenever the response contains
non-tool-use blocks before or between tool_use blocks — the dominant
case in production Claude agentic flows. The response-side thinking
content is not surfaced on either path (streaming drops silently,
non-streaming crashes the parse). Supports V01, V03, V04. Used by
findings F-LLM-03-P1-01, F-LLM-03-P2-01, F-LLM-03-P2-02,
F-LLM-03-P3-02.

## Follow-Up

The streaming tool-index desync (F-LLM-03-P1-01) should be the first
fix; it is a one-line change (`_index` → `index`, insert at `index`)
plus a streaming fixture test that does not exist today. The
thinking-block gap (F-LLM-03-P2-01 / P2-02) requires adding a
`Thinking` variant to the adapter `ContentBlock` enum and a
`#[serde(other)]` fallback for forward compatibility; coordinate with
the F-LLM-01-P2-02 contract change for signed-block round-trip.
