## Claim

There is no parallel task/plan/todo model, store, validator, or CRUD tool in
`echo-agent-app-core`: EKO defines one projection set (`TaskPlan`, `PlanTask`,
`EkoTaskSpec`, `EkoTaskExecution`, `TodoItem`), one `RevisionedTaskStore` /
`TaskToolPolicy` adapter pair, and delegates DAG validation to the framework
`PlanValidator`. The legacy global `todo_write` and any
`plan_create`/`plan_patch`/`plan_execute` parallel CRUD are absent.

## Expected Result

- Exactly one definition each of `TaskPlan`, `PlanTask`, `EkoTaskSpec`,
  `EkoTaskExecution`, `TodoItem`.
- Exactly one `impl RevisionedTaskStore` and one `impl TaskToolPolicy`.
- Zero `PlanValidator`/`task_dependency_cycles`/`task_topological_order`
  definitions in the application (framework delegation only).
- Zero `todo_write` / `plan_create` / `plan_patch` / `plan_execute` tools.
- `TodoItem` is a UI projection with no independent store/state-machine.

## Conclusion

EKO defines exactly one task/plan/todo projection set and one
`RevisionedTaskStore`/`TaskToolPolicy` adapter pair; it does not introduce a
parallel model, store, validator, or CRUD tool. `TodoItem` is a derived UI
projection with no independent store. This satisfies AGENTS.md rule 6 and the
F-TSK-01 handoff ("A-TSK-* may layer EKO product policy on top of this
framework model, not beside it"). Supports the task report's positive
layering conclusion. No finding raised from this validation.
