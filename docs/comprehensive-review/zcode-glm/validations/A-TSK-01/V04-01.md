## Claim

State can be reconstructed from partial or corrupt files: a corrupted
`events.jsonl` does not brick projection-only reads, a partial append tail
is tolerated, and `rebuild_plan_from_events` recovers a consistent snapshot
from an incomplete event stream.

## Method

Read of the event-read, rebuild, rewrite, and read-merge paths.

```text
Read echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime/event_rebuild.rs (full)
Read echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime/file_shadow.rs (362-436) [read_events/atomic_write/append_line]
Read echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime/file_store.rs (37-160) [load/get_run/get_plan merge path]
```

## Expected Result

- `read_events` skips malformed/partial lines so a crash mid-append never
  bricks the run.
- Projection-only reads (`get_run`, `get_plan`) succeed when
  `events.jsonl` is corrupt but `plan.json`/`run-state.json` are intact.
- `rebuild_plan_from_events` produces a usable snapshot from a partial
  stream and errors only on the structurally fatal case (no `RunCreated`).

## Result

- Exit code: not-applicable (static inspection)
- Duration: n/a
- Summary:
  - **`read_events` does NOT skip malformed lines (FAILURE).**
    `file_shadow.rs:362-379`: the loop trims each line and `continue`s only
    on empty/whitespace lines (lines 370-373); a non-empty malformed line is
    fed to `serde_json::from_str` and on failure returns
    `ShadowError::Decode("line {i}: {e}")` (line 374-375). The whole run's
    event stream becomes unreadable from a single bad line.
  - **Projection-only reads are NOT insulated from a corrupt event stream
    (FAILURE).** `FileTaskStore::load` (`file_store.rs:37-55`) eagerly reads
    all three files — `read_plan?`, `read_run_state?`, `read_events?` — and
    propagates any error. Therefore `get_run` (which only needs
    `state.run`) and `get_plan` (which only needs `plan` + `state.tasks`)
    BOTH fail when `events.jsonl` has one malformed line, even though
    `plan.json` and `run-state.json` are intact and independently
    sufficient to answer those queries. This contradicts the V01-01
    authority model in which projections are "deterministic read
    projections" — a projection-derived answer should not depend on the
    event file being parseable.
  - **Partial-append tail not truncated (documented as future).** The
    `append_event_line` doc (`file_shadow.rs:113-117`) states "A crash
    mid-append can at worst lose the last partial line — `read_events` skips
    empty lines and a future hardening pass (gate 2) will truncate a partial
    tail." A partial last line is neither empty nor valid JSON, so under the
    current code it surfaces as a `Decode` error, not a skipped line. The
    "gate 2" truncation is not implemented.
  - **`rebuild_plan_from_events` is best-effort on partial payloads
    (positive).** `event_rebuild.rs:59-260`: missing optional payload fields
    fall back to `unwrap_or_default()` (e.g. `workspace_id`, `goal`,
    `attachments`, `attended_mode` at lines 72-113). The only hard error is
    `RebuildError::NoRunCreated` (line 257) when no `RunCreated` event
    exists. A stream with RunCreated + partial later events rebuilds a
    coherent snapshot with defaults filled in.
  - **`rewrite_plan` handles the orphan/no-RunCreated case gracefully
    (positive).** `file_shadow.rs:245-263`: when
    `rebuild_plan_from_events` returns `NoRunCreated` (orphan write before
    `create_run`, or corrupted stream), it logs a `tracing::warn!` and
    returns `Ok(())` without rewriting the projection. The appended events
    remain durable on disk. This matches the SQL-era tolerance noted in the
    doc (`file_shadow.rs:204-207`).
  - **Execution state survives plan revisions (positive).**
    `event_rebuild.rs:138-206`: on `PlanRevisionCommitted`, the rebuild
    carries forward `previous_execution` for tasks whose ids persist across
    the revision (lines 147-162) and applies `skipped_task_ids` /
    `reset_task_ids` effects (lines 163-193). So editing a plan does not
    wipe in-flight execution state.
  - **Durability primitives.** `atomic_write` (`file_shadow.rs:405-422`)
    uses a per-call unique tmp name (pid + nanos + counter) + `sync_all` +
    `rename`; this avoids the shared-tmp rename race documented in the
    comment. `append_line` (`file_shadow.rs:427-436`) uses `O_APPEND` +
    `sync_all`. Neither performs parent-directory `fsync` after rename
    (consistent with the recurring F-MEM-01 prior; not re-raised here).
- Log/artifact: none

## Deviations

Two defects against the claim. (1) A single malformed line in `events.jsonl`
fails `read_events` and, because `FileTaskStore::load` eagerly reads all
three files, bricks `get_run`/`get_plan`/`list_todos` even when the
projections are intact. (2) The partial-tail truncation described in the
`append_event_line` doc as "future hardening pass (gate 2)" is absent, so a
crash mid-append yields a malformed line that triggers defect (1).

## Conclusion

Reconstruction from incomplete event *payloads* is robust (best-effort
defaults, graceful orphan handling, execution preservation across plan
revisions). Reconstruction from a *corrupt* `events.jsonl` is brittle: one
malformed line makes the entire run unreadable via every read API, including
projection-only reads that do not logically depend on the event file. This
undercuts the "projections are deterministic read projections" authority
model. Supports finding A-TSK-01-P2-01 (corrupt events brick projection
reads) and A-TSK-01-P3-02 (partial-tail truncation not implemented).
