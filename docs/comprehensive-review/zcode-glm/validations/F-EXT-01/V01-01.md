## Claim

The generic Tool contract in `echo-core/src/tools/mod.rs` is typed,
cancel-aware, and carries a complete structured `ToolResult` / `ToolFailure`
vocabulary with no duplicate public contract for the same semantics at this
layer. The trait surface (`Tool`, `ToolRegistrar`, `ToolRunner<P>`) is
sufficiently expressive for any `echo-agent` consumer.

## Method

Read the three primary files in the tools module and enumerated every public
trait, struct, and enum. Cross-checked for parallel definitions of the same
concept.

```text
Read echo-agent/echo-core/src/tools/mod.rs (Tool* traits and result types)
Read echo-agent/echo-core/src/tools/artifact.rs (artifact spill types)
Read echo-agent/echo-core/src/tools/pagination.rs (cursor pagination)
```

## Expected Result

Concrete public inventory of the Tool contract surface; trait methods carry
typed parameters and return `BoxFuture<Result<ToolResult>>`; cancellation is
observable; no duplicate Tool trait at this layer.

## Result

- Exit code: not-applicable (static inspection)
- Duration: n/a
- Summary:
  - `Tool` trait (`mod.rs:739`): `Send + Sync`, requires `name()`, `description()`,
    `parameters() -> serde_json::Value` (JSON Schema), and two executors:
    `execute<'a>(parameters: ToolParameters) -> BoxFuture<'a, Result<ToolResult>>`
    and `execute_with_context<'a>(params, ctx: &'a ToolContext) -> BoxFuture<'a, Result<ToolResult>>`.
    The context variant supports optional sandbox injection / session-aware
    `working_dir` + `resolve_path`.
  - `ToolRegistrar` (`mod.rs:723`): registration surface for adding named tools.
  - `ToolRunner<P = ToolParameters>` (`mod.rs:733`): `Tool + Sized` extension
    carrying a parameter type `P` for typed runners.
  - `ToolResult` (`mod.rs:288`): rich result — `kind: ToolResultKind`
    (`Text`/`Data`/`Bytes`/`Error`/`Stream`), `success: bool`, `output: String`,
    `error: Option<String>`, `failure: Option<ToolFailure>`, `bytes:
    Option<Vec<u8>>`, `data: Option<serde_json::Value>`, `truncated: bool`,
    `mime_type: Option<String>`, `metadata: HashMap<String, String>`.
  - `ToolFailure` (`mod.rs:78`): structured recovery facts — `category`,
    `recovery`, `side_effect`, `retry_after_ms`, `idempotency_key`,
    `postcondition`.
  - `ToolExecutionConfig` (`mod.rs:525`): timeout, concurrency, retry settings.
  - `ToolRiskLevel` (`mod.rs:710`): risk classification.
  - Cancellation: typed via `CancellationToken` threaded through the execution
    path; tool execution is `BoxFuture`-based so dropping/cancelling the
    future is observable by the runtime.
  - Pagination: `PageRequest` (`pagination.rs:14`), `PageInfo`
    (`pagination.rs:21`), `PageError` (`pagination.rs:32`) — cursor-based.
  - Artifacts: `ToolOutputArtifactConfig` (`artifact.rs:29`),
    `ToolOutputArtifactIdentity` (`artifact.rs:70`),
    `ToolOutputArtifactRef` (`artifact.rs:92`),
    `ToolOutputArtifactWriter` (`artifact.rs:145`).
- Log/artifact: none

## Deviations

- `ToolResult` exposes both `output: String` and `data: Option<Value>` plus
  `bytes: Option<Vec<u8>>` and a `kind` discriminator. The contract does not
  document which field is authoritative for a given `kind`; consumers must
  infer. Recorded as task finding F-EXT-01-P3-01, not a validation failure.
- `Tool::execute` and `Tool::execute_with_context` are both required (no
  default delegation between them). Implementors must define both or delegate
  manually; trait does not auto-bridge.

## Conclusion

The Tool contract is comprehensive and uniquely defined at this layer. No
duplicate public concept for tool execution/result/failure exists inside
`echo-core/src/tools`. The surface is typed, cancellable (future-based +
`CancellationToken`), and structured. Supports V02, V03, V04; used by task
finding F-EXT-01-P3-01 (output/data field ambiguity).
