## Expected Result

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary: the claim is partially supported and fails on three counts.
  - **(Pass) Review export: single authority, two thin adapters.**
    Both the agent path (`research_tool.rs:164-181` →
    `research::export_review` / `export_all_review_formats`) and the GUI
    path (`tauri/commands/research.rs:240-255` → same application-core
    functions) call the same code. Artifacts are identical by
    construction; there is no per-surface branching in `export_review`
    (`research.rs:1123-1169`). The TypeScript shape
    (`endpoints.ts:1266-1272`) mirrors the Rust struct.
  - **(Fail) `ReviewExportArtifact` lacks `sha256`.**
    `research.rs:517-524` carries `review_id`, `format`, `path`, `bytes`,
    `citation_audit` — no content hash. The framework
    `ToolOutputArtifactRef` (`echo-core/src/tools/artifact.rs:91-98`)
    carries `sha256` (+ `artifact_bytes`, `payload_bytes`, `retention`).
    The application `AnalysisOutputArtifact` (`analysis.rs:160-167`)
    carries `sha256` (computed by `hash_file` at `analysis.rs:877-894`).
    `ReviewExportArtifact` is the outlier; the `hash_bytes` helper is
    available at `research.rs:2001-2003` but is not called by
    `export_review`.
  - **(Fail) Conversation export is GUI-only.**
    `export_conversation` (`tauri/commands/conversations.rs:643-677`) is
    the only conversation exporter. Grep across `echo-agent-cli/src/tui/`
    returns zero export slash commands (the `SlashCommand` enum at
    `tui/events.rs:2627-3612` has no `Export` variant). Grep across
    `echo-agent-cli/echo-agent-app-core/src/{research_tool,runtime}.rs`
    and `echo-agent/echo-tools/src/` returns no agent-side
    conversation-export tool. So the agent cannot export a conversation,
    and the TUI user cannot either — a multi-mode parity gap per AGENTS.md
    "TUI 与 GUI 是功能完全一样的 Agent 完全体".
  - **(Fail) Analysis workbench artifacts are GUI-only.**
    `AnalysisOutputArtifact` is produced by `run_analysis_with_agent`
    (`analysis.rs`) and surfaced only via the Tauri commands
    `list_analyses` / `get_analysis` / `run_analysis`
    (`src/tauri/commands/analysis.rs:39-126`). The agent reaches analysis
    scripts through `run_code` but has no typed `analysis_library` tool to
    list runs or fetch the `AnalysisOutputArtifact` lineage. The TUI has
    no analysis surface. Coverage gap, not a duplicate-authority gap.
  - **(Fail) `research::atomic_write` omits parent-dir fsync.**
    `research.rs:1988-1999` does `File::create` → `write_all` →
    `sync_all` (temp fsync) → `fs::rename`, but does **not** fsync the
    parent directory after the rename, and does not clean up the temp file
    on error (the `?` operators early-return, leaving `temp_path` behind).
    Contrast with the framework `FileConversationStore::atomic_write`
    (`echo-state/src/memory/file_conversation.rs:494-528`, per A-STATE-01
    Current Path) which calls `sync_parent_directory` after the rename and
    removes the temp on any I/O error. This is the fourth instance of the
    recurring atomic-write defect (A-STATE-01 V02-01, F-MEM-01 P2-01/P2-02
    are the priors).
  - **(Observation) Spilled tool artifacts vs review/analysis files.**
    Framework-spilled artifacts (`ToolOutputArtifactRef`) live under the
    spill root configured in `ctx.output_artifacts` and are readable via
    `read_artifact` (`echo-tools/src/files/artifact.rs:90`). Review and
    analysis export files live under `<workspace>/.eko/{research,analyses}/`,
    outside the spill root, so `read_artifact` cannot page through them;
    the agent must use `read_file`. Not a defect — review/analysis files
    are user-facing documents, not tool logs — but it means the agent has
    two different read paths depending on artifact kind.

## Deviations

The inspection is static; no runtime test compared two artifacts produced
by the agent vs the GUI. The identity conclusion holds because
`export_review` is deterministic in its inputs (workspace, review_id,
format) and is called verbatim from both adapters — there is no per-caller
branch. A live cross-surface fixture run would strengthen the conclusion
and is recommended as a follow-up.

The `read_artifact` reachability check is a coverage observation, not a
failure: the framework makes no promise that `read_artifact` reads files
outside the spill root, and the research/analysis documents have their
own well-formed filesystem layout.

## Conclusion

Cross-surface delivery is correct where it exists: the agent and GUI
review-export paths route through one application-core authority and
produce identical artifacts. But the broader artifact-identity claim
fails on four counts: `ReviewExportArtifact` lacks a content hash
(P3-02); the conversation Markdown export is lossy of tool calls / results
/ attachments / reasoning (P2-03, also a V01 failure); the
`research::atomic_write` recipe omits parent-dir fsync and temp cleanup
(P3-04); and two export surfaces (conversation export, analysis
workbench) are GUI-only, leaving the agent and TUI without a way to
trigger them. The framework `ToolOutputArtifactRef` remains the lineage
reference that the application's two document-artifact structs should
match. Supports findings A-OUT-01-P2-03, A-OUT-01-P3-02, A-OUT-01-P3-04,
plus the cross-surface parity gaps handed off to A-SRF-01 / X-SRF-01.
