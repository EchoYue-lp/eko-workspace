## Claim

For V01 (connect / disconnect / reconnect): the application exposes a
correct connect / disconnect / reconnect path for MCP (IPC + TUI + file),
a single-retry path for browser MCP sidecar calls, and a start-only path
for LSP at bootstrap. The framework's `connect_mcp_from_config`
disconnects-then-reconnects when a same-named server already exists.
LSP has a framework `restart_server` primitive but zero application
callers. `disconnect_mcp_server` IPC always returns success regardless of
whether anything was disconnected.

## Expected Result

- MCP connect path validates input then delegates to framework
  `connect_mcp_from_config`. Framework disconnects same-named client
  first.
- MCP disconnect IPC returns success unconditionally; framework returns
  bool that the IPC layer discards.
- Browser MCP call has exactly one retry on connection failure when the
  action is retry-safe; non-retry-safe failures propagate immediately.
- LSP has start / stop / restart / shutdown_all primitives in the
  framework but the application only calls `start_server` (at bootstrap)
  and `shutdown_all` (only on plugin reload rollback, never on app exit).
- Zero application callers of `LspManager::restart_server`.

## Result

- Exit code: not-applicable (static inspection)

- Summary: confirmed.

  **MCP connect / reconnect (`tauri/commands/mcp.rs:211-258` +
  `capabilities.rs:1149-1181`):** `connect_mcp_server` validates input
  (`validate_ipc_mcp_stdio` / `validate_ipc_mcp_url`), constructs
  `McpServerConfig`, calls `agent.connect_mcp_from_config(config)`.
  Framework: if a same-named client exists, `disconnect_mcp(&name).await`
  is called first (`capabilities.rs:1157-1159`), then
  `mcp_manager.connect(config)` spawns the new client, fetches tools,
  wraps each in `McpToolAdapter`, and `add_tools` registers them. Returns
  `Ok(json!({"success": true, "name": ...}))` on success or
  `Ok(json!({"success": false, "error": ...}))` on connect failure
  (never propagates as `Err`).

  **MCP disconnect (`mcp.rs:261-286`):** calls
  `agent.disconnect_mcp(&name).await` inside `write_async`. Framework
  (`capabilities.rs:1315-1332`) computes the adapter-exposed tool names,
  calls `remove_tool` for each, then `mcp_manager.disconnect(name).await`
  which removes the map entry and `client.close().await` →
  `transport.close().await`. **Returns `bool` (true iff a client was
  removed) but the IPC layer discards it** and unconditionally returns
  `Ok(json!({"success": true, "message": "Disconnected from MCP server
  '{name}'"}))`. → A-INT-01-P3-01.

  **MCP `update_mcp_config` (`mcp.rs:477-559`):** persists config sync,
  spawns background task holding write lock, disconnects every existing
  server by name, then reconnects each enabled entry with 15 s per-server
  timeout (`mcp.rs:503, 534`). Failures are logged-and-skipped
  (`mcp.rs:538-548`). This is the bulk reconnect path used by the GUI
  save button.

  **Browser MCP retry (`browser/mod.rs:867-938`):** `call_mcp` calls
  `ensure_client(backend)` (double-checked locking at `:232-271`), then
  `first.call_tool(tool, arguments)`. On `Err`:
  - if `!browser_mcp_retry_safe(tool, &arguments)` → invalidate + close
    + propagate (`:890-900`);
  - else → invalidate + close + `ensure_client` (spawns new sidecar) +
    one retry (`:901-935`). Second failure propagates.
  A `Some(cancel)` token in `ToolContext.cancel` short-circuits via
  `tokio::select!` to `BrowserError::Cancelled` (`:876-884, :912-920`).
  → exactly one retry; matches claim.

  **LSP start (`runtime.rs:499-592`):** discover + merge global + merge
  nearest project `.lsp.yaml`; for each configured language,
  `lsp_manager.start_server(&language).await` wrapped in 15 s timeout at
  `manager.rs:76-82`. Failures log-and-skip (`runtime.rs:568-571`).
  Framework `start_server` (`manager.rs:64-89`) constructs
  `StdioLspClient`, calls `client.initialize(root_uri)` (which calls
  `spawn_process` at `client.rs:275`), stores `Arc<RwLock<...>>` in the
  per-language map.

  **LSP restart / shutdown primitives (framework, no app caller):**
  `LspManager::restart_server` (`manager.rs:105-108`) = stop + start.
  `LspManager::shutdown_all` exists (called by
  `plugin_runtime.rs:583, 596, 639, 691, 707, 721` on plugin-reload

  **TUI `/mcp` (`tui/events.rs:3425-3477`):** `list` / `load <path>` /

## Deviations

The "passed (with gaps)" classification reflects that the connect /
disconnect / reconnect paths are wired and functionally correct for the
common case, but three observations rose to findings:

- A-INT-01-P3-01: disconnect IPC discards the bool and always returns
  success.
- A-INT-01-P2-02: framework LSP restart primitive has zero application
  callers.
- A-INT-01-P3-02: browser `interrupt()` does not propagate cancellation
  to in-flight tool calls (recorded under V01 because the in-flight
  behavior is part of the connect/disconnect lifecycle).

These are listed as findings in the task report; this validation confirms
the *factual* call-graph state, not that the behavior is desirable.

## Conclusion

Supports V01: the connect / disconnect / reconnect call graph is wired
and faithful to the framework seam contracts for MCP (IPC + TUI + file)
and browser (single retry on retry-safe failures). The LSP wiring is
asymmetric — start-only at bootstrap, no restart surface, shutdown only
on plugin-reload rollback. Used by A-INT-01-P2-02 (LSP restart
unreachable), A-INT-01-P3-01 (disconnect bool discarded), and
A-INT-01-P3-02 (browser interrupt rebuild behavior).
