## Claim

For V03 (invalid config handling): EKO handles invalid MCP and LSP
configuration gracefully — bad JSON / YAML produces a structured error,
missing or non-spawning binaries are logged and skipped, and the
application continues startup with the surviving integrations.

## Expected Result

- Invalid JSON in mcp.json → `McpConfigFile::parse` returns
  `Err(ReactError::Mcp(ProtocolError("mcp.json 格式解析失败: ...")))`,
  surfaced as a startup warning; no panic.
- A server entry missing both `command` and `url` →
  `McpServerEntry::to_server_config` returns
  `Err(ReactError::Mcp(ConnectionFailed("...配置无效...")))`.
- A stdio command with shell metacharacters / dangerous prefix /
  path traversal → rejected by `validate_stdio_command` with a
  structured `ProtocolError`.
- A disabled server → skipped silently (enabled_count excludes it).
- A valid-configured server that fails to spawn → logged and skipped at
  `load_mcp_config` (`capabilities.rs:1259-1269`); startup continues.
- IPC `update_mcp_config` with malformed JSON →
  `serde_json::from_value` → `IpcError::Validation`.
- IPC `update_mcp_config` background reconnect of an invalid server →
  `entry.to_server_config(name)` returns `Ok(...)` or `Err`; the `Err`
  arm logs and skips (`mcp.rs:526-531`).
- Invalid `.lsp.yaml` → `LspConfig::from_yaml` returns
  `Err(String)`; `register_lsp_tools` logs warning, continues
  (`runtime.rs:524-527, 553-556`).
- Missing / non-spawning LSP binary → `LspManager::start_server` returns
  `Err(String)`; `register_lsp_tools` logs warning, continues
  (`runtime.rs:568-571`).
- `get_mcp_config` never panics on a config missing `mcpServers` or
  with non-object entries — `redact_mcp_config_secrets` short-circuits
  on `value.get_mut("mcpServers").and_then(|v| v.as_object_mut())`
  returning `None` (`mcp.rs:403-405`).

## Result

- Exit code: not-applicable (static inspection)

- Summary: confirmed — V03 passes.

  **MCP `mcp.json` parsing**
  (`echo-integration/src/mcp/config_loader.rs:160-204`):
  - `McpConfigFile::parse` (`:162-169`) wraps `serde_json::from_str` in
    a `Result` returning `ReactError::Mcp(ProtocolError("mcp.json 格式
    解析失败: {e}"))`. No panic.
  - `McpConfigFile::from_file` (`:181-191`) wraps `std::fs::read_to_string`
    in a `Result` returning `ConnectionFailed("读取配置文件失败 ...:
    {e}")` on IO error. No panic.
  - `to_server_configs` (`:194-204`) iterates entries; `disabled` ones
    skipped with `tracing::debug!`.
  - `McpServerEntry::to_server_config` (`:107-157`):
    - `disabled=true` → `Err(ConnectionFailed("...已禁用..."))`.
    - `command` set → `validate_stdio_command(command)?` then constructs
      `TransportConfig::Stdio`.
    - `url` set (no command) → constructs `TransportConfig::Sse` (if
      `transport == "sse"`) or `TransportConfig::Http` (default).
    - neither → `Err(ConnectionFailed("...stdio 模式需提供 'command',
      HTTP 模式需提供 'url'..."))`.

  **On-disk `validate_stdio_command`** (`config_loader.rs:229-261`):
  rejects shell metacharacters (`|;&$\`><()\n\r`), dangerous command
  prefixes (`sudo`/`su`/`dd`/`chmod`/`chown`/`reboot`/`shutdown`/`halt`),
  and path traversal (`..`). Returns structured `ProtocolError`. No
  panic, no allowlist (correctly lightweight per AGENTS.md).

  **Startup loader** (`infra.rs:1069-1108` `load_mcp_config`):
  resolves path; `agent.load_mcp_from_file(&path).await` — on `Err(e)`
  logs `tracing::warn!("MCP 配置加载失败: {}", e)` and returns. Startup
  proceeds without MCP. No propagation, no panic.

  **Framework `load_mcp_config`** (`capabilities.rs:1251-1272`):
  iterates `to_server_configs()`; per-server failure logs
  `tracing::warn!("MCP server connection failed, skipping")` and
  continues. Returns the successfully-connected clients.

  **IPC `update_mcp_config`** (`mcp.rs:477-559`):
  - `serde_json::from_value(config)` → `Err` mapped to
    `IpcError::Validation(e.to_string())` (`mcp.rs:482`). No panic.
  - Background reconnect: each server `entry.to_server_config(name)` —
    on `Err` logs `"MCP server config invalid; skipped during reconnect"`
    and `continue`s (`mcp.rs:526-532`).
  - Per-server connect wrapped in `tokio::time::timeout(15s, ...)`;
    timeout logs `"MCP server connect timed out; skipped"` (`mcp.rs:
    541-547`).

  **LSP `.lsp.yaml` parsing** (`echo-integration/src/lsp/config.rs`):
  - `LspConfig::from_file` (`:67-71`) wraps `std::fs::read_to_string`
    + `from_yaml`; returns `Result<Self, String>`.
  - `LspConfig::from_yaml` (`:74-80`) wraps `serde_yaml_ng::from_str`
    in `Result<Self, String>` with `"Failed to parse LSP config YAML:
    {e}"`. No panic.
  - `register_lsp_tools` (`runtime.rs:521-557`): global config error →
    `tracing::warn!("Failed to load global LSP config")` and continue;
    project config error → `tracing::warn!("Failed to load project LSP
    config")` and continue. Startup proceeds.

  **LSP server start failure** (`runtime.rs:567-571`):
  ```rust
  for language in languages {
      if let Err(error) = lsp_manager.start_server(&language).await {
          tracing::warn!(%language, %error, "LSP server unavailable");
      }
  }
  ```
  Framework `start_server` (`manager.rs:64-89`) wraps `client.initialize`
  in a 15 s timeout. `spawn_process` (`client.rs:67-122`) returns
  `LspError::SpawnError` if `Command::new(command).spawn()` fails. All
  errors become `String` and bubble to the warning log above.

  **`get_mcp_config` redaction** (`mcp.rs:402-474`):
  `redact_mcp_config_secrets` early-returns if `mcpServers` is missing
  or not an object (`:403-405`). Per-entry processing skips non-object
  entries (`:407-409`). No panic on partial / malformed config.

## Conclusion

Supports V03: invalid MCP and LSP configuration is handled gracefully —
structured errors, warning logs, skip-and-continue at startup, no panics,
no crashes. The on-disk validators (`validate_stdio_command`,

IPC validators are stricter (locked in by `mcp.rs:565-613`) — that
strictness is filed separately as A-INT-01-P1-01; this validation only
confirms the *error handling shape* (graceful `IpcError::Validation`)
is correct, not that the gate's policy is appropriate.
