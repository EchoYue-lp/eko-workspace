## Claim

For V02 (session cleanup on shutdown): `BrowserRuntime` has an explicit
graceful `shutdown()` that is called on every exit path; MCP and LSP do
not — they rely on best-effort framework `Drop` impls that may not run
if the tokio runtime is already shutting down.

## Expected Result

- Every exit path (TUI / CLI / GUI / channels) calls
  `runtime.browser_runtime.shutdown().await` after the surface returns.
- No exit path calls a corresponding `mcp_shutdown` or `lsp_shutdown`.
- `AgentRuntime` has no `impl Drop` and no `shutdown` method that
  cascades to MCP / LSP.
- Framework `StdioTransport::Drop` uses `tokio::spawn(child.kill())` —
  best-effort.
- Framework `StdioLspClient` relies on `kill_on_drop(true)` set at
  spawn — no graceful LSP `shutdown` request on drop.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary: confirmed — V02 fails.

  **Browser shutdown is explicit and universal** (4/4 exit paths):
  - TUI: `main.rs:334 runtime.browser_runtime.shutdown().await;`
  - channels: `main.rs:399 runtime.browser_runtime.shutdown().await;`
  - CLI: `main.rs:443 runtime.browser_runtime.shutdown().await;`
  - GUI: `desktop.rs:267 runtime.browser_runtime.shutdown().await;`

  `BrowserRuntime::shutdown` (`browser/mod.rs:194-204`) cancels the
  runtime token, `sessions.close_all().await` (marks every session
  `Closed`, persists, emits `SessionClosed`), then for each backend
  (Managed + Chrome) takes the client slot and calls `client.close
  ().await`. This is a correct graceful shutdown.

  **MCP shutdown is absent at the application layer:**
  `grep -rn "browser_runtime.shutdown\|mcp.*shutdown\|shutdown_all\|lsp.*shutdown"
  echo-agent-cli/src/` returns:
  - 4 hits for `browser_runtime.shutdown` (listed above)
  - 0 hits for any MCP-level shutdown
  - 0 hits for any LSP-level shutdown on the exit path
  - The only `shutdown_all` references in the application are in
    `plugin_runtime.rs` (`:583, 596, 639, 691, 707, 721`) and all are
    rollback paths for failed plugin reload — never the app-exit path.

  **Framework MCP cleanup is best-effort:**
  `echo-integration/src/mcp/transport/stdio.rs:270-282`:
  ```rust
  impl Drop for StdioTransport {
      fn drop(&mut self) {
          let child = self._child.clone();
          tokio::spawn(async move {
              let mut child = child.lock().await;
              if let Err(e) = child.kill().await { ... }
              let _ = child.wait().await;
          });
      }
  }
  ```
  If the tokio runtime has already shut down (which is the typical
  ordering when `main` returns and drops `runtime`), `tokio::spawn`
  silently fails to enqueue and the child is leaked until process exit.
  This is the framework-level F-INT-01-P3-02 defect inherited by the
  application.

  **Framework LSP cleanup is best-effort:**
  `echo-integration/src/lsp/client.rs:79` sets `.kill_on_drop(true)` on
  the spawned child. On `StdioLspClient` drop, the OS reaps the child
  (SIGKILL on Unix) — no graceful LSP `shutdown` request is sent
  (framework `LspManager::shutdown_all` exists at `manager.rs` but is
  not called by any exit path). Reader / writer tasks are not aborted.

  **AgentRuntime has no Drop / shutdown that cascades:**
  `grep -n "impl Drop\|fn shutdown\|pub fn shutdown" runtime.rs` returns
  zero hits. `AgentRuntime` (`runtime.rs:31-52`) holds
  `plugin_runtime: Arc<PluginRuntimeService>`; dropping `runtime`
  decrements the refcount. `PluginRuntimeService` itself has no Drop.
  The `Arc<RwLock<LspManager>>` inside `PluginLspRuntime` similarly has
  no Drop that calls `shutdown_all`.

## Deviations

The validation confirms the claim exactly — no unexpected behavior
discovered. The failure classification reflects that the expected
invariant (graceful shutdown at the application layer) is not met for
two of the three integrations.

## Conclusion

Supports finding A-INT-01-P2-01: browser has explicit graceful shutdown
on every exit path; MCP and LSP do not, and rely on framework Drop impls
that are best-effort. The asymmetry is observable in source and is not
mitigated by any `AgentRuntime::shutdown` method or Drop impl. The
inherited framework-level Drop defects are F-INT-01-P3-02 (MCP stdio)
and F-INT-02-P3-02 (LSP reader/writer tasks not cancellable); this
validation only confirms that the application does not compensate for
them.
