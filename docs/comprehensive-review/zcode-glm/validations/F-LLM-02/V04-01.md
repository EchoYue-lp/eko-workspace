## Claim

The OpenAI adapter and shared transport correctly extract usage on both paths
(streaming final chunk + non-streaming raw body), correctly preserve it
through the OpenAI-inclusive cache-normalization inherited from F-LLM-01, and
correctly map every provider failure mode onto the typed `LlmError` hierarchy
with retry applied only to network errors, 429, and 5xx.

## Method

Static inspection of usage extraction on both paths, the retry policy, the
HTTP error mapping, and the SSE error paths. Ran the integration test suite
to confirm compile + green tests.

## Expected Result

Usage is preserved on both paths and round-trips through the F-LLM-01
normalization helpers; HTTP failures map to `LlmError::ApiError`; network
failures map to `LlmError::NetworkError`; body parse failures map to
`LlmError::InvalidResponse`; empty choices map to `LlmError::EmptyResponse`;
retry fires only for `NetworkError` and `ApiError` with status 429 or >=500.

## Result

- Exit code: 0 (both commands)
- Duration: tests 0.04s (62 passed); clippy 11.45s
- Summary:
  - **Usage extraction — non-streaming** (`openai.rs:302-316`): the
    `ChatResponse` carries the full `raw: ChatCompletionResponse`, and
    `raw.usage: Option<Usage>` (`types.rs:633-634`) is the authoritative
    usage source. The OpenAI adapter does no usage transformation at this
    layer — it lets the F-LLM-01 normalization helpers
    (`Usage::effective_prompt_tokens`, `cached_prompt_tokens`,
    `cache_hit_rate` at `types.rs:686-771`) do the math. The React engine
    reads `response.raw.usage.clone()` at `react_loop.rs:100` and feeds it to
    those helpers. Correct separation: adapter preserves raw fields, contract
    normalizes.
  - **Usage extraction — streaming** (`openai.rs:366-375`): each `ChatChunk`
    carries `usage: chunk.usage.clone()`. The final chunk (sent because
    `stream_options: {"include_usage": true}` is set at `openai.rs:346`)
    carries the full `Usage` object even though its `choices` array is empty.
    The empty-choices case is handled by `choice.map(...).unwrap_or_default()`
    for `delta`, while `usage: chunk.usage.clone()` preserves usage
    independently. Verified by code path; the `ChunkChoice.delta`
    null-deserializer (`types.rs:822`) ensures the terminal chunk parses.
  - **OpenAI-inclusive cache normalization** (`types.rs:686-771`): per the
    F-LLM-01 V03-01 authority conclusion, OpenAI's `prompt_tokens` already
    includes cached tokens; `cached_prompt_tokens()` reads
    `prompt_tokens_details.cached_tokens` first (`:724-728`), and
    `effective_prompt_tokens()` returns `prompt_tokens` unchanged when no
    Anthropic cache field is present (`:693-702`). The OpenAI adapter does
    not need to know this — it just feeds the raw `Usage` and the helpers do
    the math. Confirmed consistent with F-LLM-01 V03-01.
  - **HTTP error mapping** (`client.rs:109-172` for `post`,
    `:182-354` for `stream_post`):
    - Send failure → `LlmError::NetworkError(e.to_string())` (`:135, 218`).
    - Non-success status → `LlmError::ApiError { status, message }` where
      `message` is the response body (`:137-147, 220-230`). Status captured
      before consuming the body. Correct.
    - Body text extraction failure → falls back to `"Unknown error"` string
      (`:142, 225`).
    - Body JSON parse failure → `LlmError::InvalidResponse(e.to_string())`
      (`:156-164`). Correct.
    - Stream byte-stream error → `LlmError::NetworkError(e.to_string())`
      (`:308`).
  - **`LlmError` hierarchy** (`error.rs:87-108`): 5 typed variants —
    `NetworkError(String)`, `ApiError{status,message}`,
    `InvalidResponse(String)`, `EmptyResponse`, `SerializationError(String)`.
    No `Other(String)` at this level (per F-CORE-01 conclusion). All variants
    used by the OpenAI path except `SerializationError` (which is reserved
    for serde failures on outbound serialization — not currently triggered).
  - **Empty choices** (`openai.rs:310`, `adapter_client.rs:113`):
    `raw.choices.first().ok_or(LlmError::EmptyResponse)`. Correct.
  - **Retry policy** (`client.rs:13-19`): `is_retryable` returns true for
    `NetworkError` (always) and `ApiError` only when `status == 429 || status
    >= 500`. `InvalidResponse`, `EmptyResponse`, `SerializationError`, and
    4xx `ApiError` are NOT retried. Applied via `with_retry_if` (`:122-154,
    203-237`). `RetryPolicy::default` provides backoff. Correct.
  - **Stream timeouts** (`client.rs:240-302`): three independent timeouts
    (first-chunk 30s default, idle 60s default, overall off by default), all
    env-tunable via `ECHO_AGENT_STREAM_FIRST_CHUNK_TIMEOUT_MS`,
    `ECHO_AGENT_STREAM_IDLE_TIMEOUT_MS`, `ECHO_AGENT_STREAM_OVERALL_TIMEOUT_MS`.
    Timeouts surface as `LlmError::NetworkError("LLM stream ... timeout")`
    (`:29-34`) — retryable. Verified: the `tokio::select!` arms produce the
    timeout error correctly.
  - **`[DONE]` terminator** (`client.rs:81-85, 329, 347`): the `[DONE]`
    marker is converted to `Err(LlmError::NetworkError(SENTINEL))` inside
    `parse_sse_chunk`, then caught in the stream loop by
    `err.to_string().contains(STREAM_DONE_SENTINEL)` and treated as clean
    termination (the loop returns, the stream ends). The sentinel never
    reaches the caller. See finding F-LLM-02-P3-01 for the design smell.
  - **Cancellation** (`client.rs:252-256`): `cancel_token.is_cancelled()`
    checked between SSE chunks; on cancel, the loop returns and the stream
    ends cleanly. No error is emitted — the stream just terminates. This
    matches F-LLM-01 V02-01's contract-trace conclusion.

## Deviations

- Non-streaming `ChatResponse` exposes usage only via `raw.usage`. The
  streaming `ChatChunk` exposes it via a top-level `usage` field. Asymmetric.
  See finding F-LLM-02-P2-04.
- The `[DONE]` marker masquerades as a `NetworkError` with a sentinel
  message. See finding F-LLM-02-P3-01.
- Malformed SSE chunks (serde failure) are dropped silently at the transport
  layer — they do not surface as `LlmError::InvalidResponse`. See finding
  F-LLM-02-P2-03.

## Conclusion

Usage extraction is correct and consistent with the F-LLM-01 authority
contract on both paths; OpenAI-inclusive cache normalization is inherited
without duplication. Error mapping covers every failure mode with the correct
typed `LlmError` variant, and retry is gated on the right conditions. The
three deviations are design-smell or ergonomic findings (P2/P3), not
correctness defects on the live path. Supports V01, V02. Used by findings
F-LLM-02-P2-03, F-LLM-02-P2-04, F-LLM-02-P3-01.
