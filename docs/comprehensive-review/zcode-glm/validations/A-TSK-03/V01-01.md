## Claim

EKO owns product policy only and delegates scheduling to the framework's
`RuntimeDagExecutor`. Concretely:

1. `RuntimeDagExecutor` is constructed exactly once in `echo-agent-cli`
   (executor.rs:1645) and `RuntimeDagController` is implemented exactly once
   (`EkoRuntimeDagController`, executor.rs:1147-1620).
2. `execute_run` (executor.rs:321) is the sole production entry; all callers
   (TUI, GUI, CLI tool) funnel through it; none of them touches the kernel
   directly.
3. The outer drain loop in `execute_run` (line 367-434) is a quiescence /
   appended-tasks wrapper, not a scheduling loop: it never computes the
   ready frontier, never spawns a wave, and never claims a task.
4. `task_execute_tool.rs` adds no scheduling primitive — it serializes per
   `run_id` and delegates to `execute_run`.

## Method

Read-only static inspection of the call graph plus a whole-repository
duplicate search for parallel scheduling authorities.

```text
1. Read executor.rs:321-585 (execute_run drain loop) and 1147-1683

4. Confirm the drain loop never calls DagExecutionState, ready_task_ids,

```

## Deviations

deviation from this validation's claim:

- The drain loop's quiescent branch (executor.rs:385-398) does not re-check
  `parent_cancel.is_cancelled()` nor the run's terminal status. See
  A-TSK-03-P3-01 for the (narrow) race this leaves.

## Conclusion

Supports: the "EKO injects product policy only" invariant. `execute_run`'s
drain loop is a wrapper around the kernel, not a duplicate of it. The
single `RuntimeDagExecutor` construction and single
`EkoRuntimeDagController` implementation confirm there is no second
ready-frontier, wave dispatcher, claim authority, or scheduling loop in
EKO. The framework owns all of those (consistent with F-TSK-03's
kernel-authority conclusion and AGENTS.md rule 6 / the "adapter must stay
thin" rule).

Does NOT support (and is not asked to support): that the framework
kernel's stall/abort behavior is itself complete — that is F-TSK-03-P2-01
and F-TSK-03-P2-02. This validation only establishes that EKO does not
re-implement them.

Findings using this validation: A-TSK-03-P3-01.
