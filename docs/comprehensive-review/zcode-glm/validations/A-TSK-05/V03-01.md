## Claim

EKO reuses logical-task worktrees across retries, repairs pruned
worktrees by re-materialising them from the surviving branch, and
cleans up completed worktrees conservatively (never deleting a dirty
checkout or a branch with unique commits). Specifically:

1. `RunWorktree::acquire_fork` (worktree.rs:381-425) is the reuse
   authority: it finds an existing worktree for the logical-task
   label, re-locks it if unlocked, and re-uses its directory and
   branch.
2. Pruned worktrees (directory gone, branch still exists) are
   materialised via `git worktree add <path> <branch>` (no `-b`,
   because the branch already exists).
3. `cleanup_managed_worktree` (worktree.rs:1001-1017) removes the
   directory only if `git worktree remove` succeeds, and removes the
   branch only if `branch_ahead_of_head(repo, branch) == 0`.
4. The framework `EkoWorktreeFactory::finalize` closure (worktree.rs:1324-1352)
   keeps a changed worktree (does not delete it) and only unlocks it,
   so the review/integration stage can find it later.
5. `cleanup_unattended_worktrees` (worktree.rs:1238-1276) skips
   active runs, releases stale locks, and refuses to remove worktrees
   with uncommitted changes or unique commits.

## Expected Result

- A retained, unlocked worktree for the same label is re-locked and
  reused; the previous attempt's uncommitted files survive.
- A pruned worktree (dir gone, branch exists) is materialised at the
  canonical path and re-locked.
- `cleanup_managed_worktree` refuses to delete a worktree that became
  dirty after the cleanup decision was made (late-arriving content).
- `cleanup_managed_worktree` refuses to `git branch -D` a branch with
  commits ahead of HEAD; the directory is removed but the branch is
  retained with a warning.
- `finalize` on a dirty worktree retains the directory and unlocks it
  (for review); `finalize` on a clean worktree removes both directory
  and branch.
- Active runs are never cleaned up by `cleanup_unattended_worktrees`.
- All 11 reuse/cleanup tests pass.

- Summary: Claim confirmed. The reuse / cleanup state machine is:

```
acquire_fork(label, repo_root):
  branch = fork_branch_name(label)
  validate_branch_name(branch)
  existing = find_worktree_info(branch)?
  if Some(existing):
    if existing.locked:        → Err ("already active at <path>")
    if existing.path.exists:    → re-lock, reuse path+branch+merge-base
    else:                       → git worktree prune (fall through)
  if branch_exists(branch):
    path = default_worktree_path(branch)
    validate_worktree_target(path)
    git worktree add <path> <branch>   # no -b; branch exists
    lock_worktree(path)
    → Ok (materialised from orphan branch)
  else:
    create_fork(label, repo_root):
      path = default_worktree_path(branch)
      validate_worktree_target(path)
      git worktree add -b <branch> <path> <base>
      lock_worktree(path)
      → Ok (brand new)

EkoWorktreeFactory::finalize(wt):
  if !wt.has_changes():        → cleanup_managed_worktree (remove both)
  else:                         → wt.diff_summary() + wt.unlock()
                                  (directory + branch RETAINED for review)

cleanup_managed_worktree(repo, path, branch):
  unlock_worktree(path)        # best-effort, ignore "not locked"
  git worktree remove <path>   # NON-force; fails if dirty
  if branch_ahead_of_head(branch) > 0:
                                → Err ("branch retained, <n> unique commits")
  git branch -D <branch>       # only reachable if ahead == 0
  git worktree prune

cleanup_unattended_worktrees(repo, store):
  for wt in list_unattended_worktrees:
    if wt.active:              → kept (skip)
    if wt.locked:              → unlock_worktree (release stale lock)
    if wt.has_changes:         → kept (dirty or unique commits)
    else:                       → remove_unattended_worktree (force-remove)
```

  the function re-locks the worktree and returns a `RunWorktree` with
  the *same* path and branch. The uncommitted files in the worktree
  are not touched. Test
  `fork_acquire_reuses_unlocked_dirty_worktree` (1557-1577): writes
  `retry.txt` in the first attempt, unlocks, acquires again, asserts

  PASS.
- `acquire_fork` repair path (worktree.rs:403-422): when the worktree
  path does not exist but the branch does, the function runs
  `git worktree prune` (to clean up the stale worktree metadata) and
  falls through to the `branch_exists` branch, which does
  `git worktree add <path> <branch>` (no `-b`). Test
  `automatic_cleanup_retains_new_unique_commit` (1651-1697): creates
  a worktree, unlocks, commits a unique commit, removes the worktree
  directory, then calls `integrate_fork_worktree` which materialises
  the orphan branch and merges it. PASS — the orphan-branch
  materialisation works end-to-end.
- `cleanup_managed_worktree` conservatism (worktree.rs:1001-1017):
  - `unlock_worktree` is best-effort (line 1005: `let _ = ...`).
  - `git worktree remove <path>` is NON-force (line 1006); git itself
    refuses to remove a dirty worktree, returning non-zero. This is
    the first safety net.
  - `branch_ahead_of_head` (worktree.rs:1077-1087) runs
    `git rev-list --count HEAD..<branch>`; the result is parsed as
    `u32`. If non-zero, the function returns `Err` *before* reaching
    `git branch -D`. The branch is retained with a descriptive error.
  - Only if both checks pass does `git branch -D <branch>` run (line
    1013). `-D` is force-delete (the branch has no unique commits, so
    no work is lost).

## Deviations

One nuance filed as a finding (P3-03) rather than a deviation from
this validation's claim:

- `acquire_fork`'s reuse path (worktree.rs:385-401) trusts the path
  returned by `git worktree list --porcelain` without re-running
  `validate_worktree_target`. This is defense-in-depth, not a
  correctness defect — the branch was created by EKO's own validated
  `create_fork` path, so its worktree location is transitively
  trusted. The threat model does not include an attacker with prior
  write access to the user's git repo. See A-TSK-05-P3-03.

## Conclusion

Supports: the "reuse / repair / cleanup is sound and conservative"
invariant. `acquire_fork` reuses unlocked worktrees without
disturbing uncommitted retry work. Pruned worktrees are materialised
from their surviving branches. `cleanup_managed_worktree` refuses to
delete dirty directories (via non-force `git worktree remove`) and
refuses to delete branches with unique commits (via
`branch_ahead_of_head`). `finalize` keeps changed worktrees for the
review/integration stage. The legacy `cleanup_unattended_worktrees`
preserves active runs and dirty worktrees, releases stale locks, and
removes only provably-clean checkouts.

Does NOT support (and is not asked to support): that the *framework's*
worktree tools have analogous conservatism — F-EXT-02-P2-03 found that
the framework's `exit_worktree` synthesises a fake `ManagedWorktree`
with `managed: true` and force-deletes a namesake branch. EKO does not
route through that surface (V01).

Findings using this validation: A-TSK-05-P3-03 (defense-in-depth on
the reuse path).
