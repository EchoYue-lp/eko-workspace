## Claim

The framework and application contain multiple unbounded in-memory
allocations (Vec/HashMap/DashMap registries, append-only maps keyed by
run_id), and at least one unbounded loop path; these grow without eviction
on the live path and can block or bloat long sessions.

## Method

Static grep + read trace across both repositories for the canonical
"unbounded growth" patterns: `HashMap`/`DashMap` fields that are inserted
into but never `remove`/`retain`/`prune`/`evict`-ed on a live (non-test)
path; `Vec` accumulators with no cap; unbounded channel constructors;
`loop {}` / iteration ceilings; and "full-rewrite-on-append" persistence.

```text
# Unbounded registries: insert vs prune call-site balance
grep -rn "prune_completed" echo-agent echo-agent-cli   # 0 live callers
grep -n  "\.remove\|prune\|evict\|retain\|clear()" \
  echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime/file_shadow.rs

# Unbounded channels
grep -rln "unbounded_channel\|mpsc::unbounded\|\.unbounded()" \
  echo-agent/src echo-agent/echo-*

# Iteration ceiling (0 == unlimited)
grep -n  "max_iterations == 0\|usize::MAX\|0..max_iterations" \
  echo-agent/src/agent/react/run/stream_channel.rs

# Full-rewrite persistence per save
sed -n  '211,235p' echo-agent-cli/.../persistence.rs      # save_session -> write_json
sed -n  '350,376p' echo-agent/echo-state/.../file_conversation.rs  # save_messages -> write_record
```

Working directory: `/Users/ls/MyWork/code/ylp_agent_learn/lp-agent`.

## Expected Result

At least one of: (a) a registry inserted-into on the live path with no live
eviction; (b) an append-only map keyed by run_id/session_id with no
removal; (c) a `0 == unlimited` iteration ceiling; (d) a full-file rewrite
per append.

## Result

- Exit code: not-applicable (static trace)
- Summary: all four expected patterns are present and live-reachable.

  1. **`TaskSpawner.tasks` DashMap never pruned live** —
     `echo-orchestration/src/tasks/background_task.rs:381`
     (`tasks: Arc<DashMap<String, Arc<dyn AnyBackgroundTask>>>`), inserted
     at `:560`. `prune_completed` exists at `:606-609` but a repo-wide
     `grep -rn "prune_completed"` finds **zero** live callers (definition +
     tests only). Every spawned background/subagent task stays tracked
     forever. The module's own test at `:769` documents the contract
     (`"still tracked until pruned"`) but nothing on the live path prunes.

  2. **`FileTaskShadow` two run-keyed maps never evicted** —
     `echo-agent-cli/echo-agent-app-core/src/tasks/task_runtime/file_shadow.rs:26`
     (`seq_cache`) and `:32-34` (`run_write_locks`), both
     `Arc<Mutex<HashMap<String, …>>>` keyed by run_id. A grep for
     `\.remove|prune|evict|retain|clear()` inside `file_shadow.rs` returns
     **no matches** — entries accumulate with every task run for the life
     of the process.

  3. **`max_iterations == 0` == `usize::MAX`** (unbounded loop) —
     `echo-agent/src/agent/react/run/stream_channel.rs:521-528`. Default is
     `100` (`config.rs:212`), so this is a config footgun rather than a
     default defect: any consumer (third-party or a future EKO profile)
     that sets `max_iterations(0)` gets an unbounded ReAct loop.

  4. **Full-rewrite persistence per save** —
     `save_session` (`persistence.rs:211-235`) → `write_json`
     (`persistence.rs:350`) rewrites the whole session; framework
     `FileConversationStore::save_messages` (`file_conversation.rs:350-376`)
     → `write_record` (`:168-175`) rewrites the whole conversation record
     (atomic_write). Each save is O(M) in message count; over a long chat
     this is O(M²) cumulative write.

- Additional (bounded, for contrast): `chatStore` (`MAX_MESSAGES=500`,
  `web-frontend/src/stores/chatStore.ts:104,111`) and `taskRuntimeStore`
  (`MAX_EVENTS=500`, `taskRuntimeStore.ts:14,185`) **are** capped; the
  agent pool (`agent_pool.rs:51,744-765`) **is** idle-evicted. So the
  frontend and the pool are not in this finding's scope.
