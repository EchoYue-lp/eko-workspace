## Claim

Multiple on-disk artifacts grow without bound under EKO's default
configuration: the JSONL trace store (per-run, O(E²) and never retained),
the per-run task `events.jsonl` directories (never deleted), the append-only
`app.log` (no rotation, by the code's own admission), and several
append-only journal/evidence files. The in-memory trace cache is likewise
unbounded.

## Method

Static enumeration of every file-writing path on the EKO live path, plus a
retention/rotation search (rotation primitives, `remove_dir`, `truncate`,
`retain`) against each.

```text
# Trace store (live wiring + write path + cache)
grep -rn "JsonlRunStore::new" echo-agent-cli/.../infra.rs            # :377, live
sed -n '677,802p' echo-agent/src/trace/mod.rs                       # cache + save + append_event
grep -n "truncat\|retain\|remove\|rotate\|evict" echo-agent/src/trace/mod.rs

# Task run dirs (created, never deleted)
grep -rn "remove_dir\|prune\|retain\|evict" \
  echo-agent-cli/.../tasks/task_runtime/file_shadow.rs              # none
sed -n '1,8p' echo-agent-cli/.../tasks/task_runtime/file_shadow.rs  # layout {root}/{run_id}/

# App log (append-only, no rotation, self-documented)
sed -n '1655,1668p' echo-agent-cli/.../infra.rs                     # app_log_file -> append(true)
sed -n '1578,1612p' echo-agent-cli/.../infra.rs                     # dual-sink writer wiring
grep -rn  "rolling\|RollingFileAppender\|tracing_appender\|rotation" \
  echo-agent-cli/src-tauri echo-agent-cli/echo-agent-app-core       # none

# Other append-only journals
grep -rn "append(true)" echo-agent-cli/echo-agent-app-core/src
```

## Expected Result

At least one live on-disk artifact grows without bound and has no retention
or rotation on the default path.

## Result

- Exit code: not-applicable (static trace)
- Summary: four independent unbounded on-disk growth sites, all live.

  1. **JSONL trace store — per-run O(E²), no retention (live).**
     `infra.rs:377` wires `JsonlRunStore::new(user_data_path("runs"))`
     into every agent. `save` (`trace/mod.rs:733-749`) opens the per-run
     `.jsonl` in `append(true)` and writes a **full Run snapshot** (incl.
     the ever-growing `events: Vec`, `:76`) each call; `append_event`
     (`:793-801`) does `load → push_event → save`, so each event appends a
     fresh full snapshot → **O(E²) bytes per run** (see V02). A grep for
     `truncat|retain|remove|rotate|evict` inside `trace/mod.rs` finds only
     the in-memory `list_*` result truncation (`:662,788`); **no run-file
     retention** exists. The in-memory `cache: RwLock<HashMap<String,Run>>`
     (`:680`) gains one entry per run_id with no eviction, and `load`
     reads the **entire** file via `read_to_string` to get the last line
     (`:716-721,724-728`).

  2. **Task run directories — never deleted (live).** File layout is
     `{root}/{run_id}/events.jsonl` + `plan.json` (`file_shadow.rs:6`),
     root `~/.eko/tasks/`. A repo-wide search for run-dir deletion
     (`remove_dir_all`/`prune`/`retain` on the store) returns only a
     **temp-dir** cleanup (`ledger.rs:289`) and **test-only** `remove_file`
     calls (`worktree.rs:1575,1626,1646` — all under `#[cfg(test)]`
     context). No live path deletes a completed run's directory; each
     complex-task run leaves `{run_id}/` on disk forever. (The
     `"retention": "conversation_or_30d"` string at `store.rs:2259` is
     test-fixture metadata, not an implemented policy.)

  3. **`app.log` — append-only, no rotation (live, self-documented).**
     `app_log_file` (`infra.rs:1658-1668`) opens
     `~/.eko/logs/app.log` with `create(true).append(true)`. It is wired
     as a `tracing_subscriber` file layer in the `Stderr` (default GUI)
     branch (`:1600-1605`). The preceding comment states verbatim:
     *"Append mode keeps history across restarts; rotate/truncate manually
     if it grows too large"* — i.e. the code acknowledges there is no
     automatic rotation. A grep for `rolling|RollingFileAppender|
     tracing_appender|rotation` across `src-tauri` + `app-core` returns
     **no matches**. (Contrast: the `TuiFile` branch uses `File::create`,
     `:1580`, which truncates each start — so only the GUI/Stderr log is
     unbounded.)

  4. **Other append-only journals (live).** `append_json_line`
     (`tool_execution.rs:641-647`) appends to per-scope
     `events.jsonl`/`details/*.jsonl` tool-execution journals on every
     tool call (`:237,276,318,345,379`); the checkpoint reflection writer
     appends to a `PROJECT.md` memory file (`runtime.rs:481-486`); the
     evolution evidence store appends to its log
     (`evolution/evidence.rs:920-926`). None rotate or truncate.

- For contrast: the EKO **conversation** files (`FileConversationStore`)
  are full-rewritten per save (atomic_write, not append) — they do not
  grow in *line count*, but incur the O(M²) write cost covered in V02/P2-03.

## Deviations

No disk-usage measurement was taken on a real `~/.eko` tree (no long-lived
EKO instance in this environment). The "unbounded" conclusion follows from
the absence of any deletion/rotation code on the write paths, which is a
deterministic static property. A real measurement would give current
magnitude, not the growth law.

## Conclusion

Supports Q-PERF-01-P1-01 (trace store — the on-disk half of the O(E²)
finding, plus the unbounded cache), Q-PERF-01-P2-01 (task run dirs +
shadow maps — disk half), Q-PERF-01-P2-02 (`app.log` no rotation), and the
append-only-journal observations folded into P2-02. The trace store is the
highest-impact disk site because it is both O(E²) per run *and* hit on
every event of every run on the default chat path.

## Follow-Up

A retention policy (cap runs/tasks by age or count, rotate `app.log`) is the
direction noted in the task findings; implementation belongs to a later
milestone, not this read-only review. Q-FLT-01/Q-E2E-01 should exercise a
long session to capture an actual `~/.eko` footprint sample.
