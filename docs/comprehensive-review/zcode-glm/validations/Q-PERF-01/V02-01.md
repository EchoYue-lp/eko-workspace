## Claim

At representative sizes (≈1000 messages, ≈100 task runs, ≈50 subagents,
large tool output), the unbounded-growth sites identified in V01 degrade
super-linearly or block a critical path; specifically: the JSONL trace
store is O(E²) per run, conversation persistence is O(M²) per session, the
session search index holds ~2× total content in memory, and the subagent
spawner registry grows linearly with no prune.

## Method

Static cost analysis grounded in the verified code paths from V01 (no live
LLM/network fixture was run; the growth functions are derivable directly
from the write loops). All line anchors verified at HEAD.

```text

sed -n '733,801p' echo-agent/src/trace/mod.rs        # save() + append_event()
```

## Expected Result

For each growth site, the asymptotic cost at large N should be worse than
linear (super-linear) or unbounded in memory.

- Exit code: not-applicable (analytical)

## Deviations

No live fixture was executed (no model credentials in this static review
environment). The growth functions are read directly from the write loops,
so the asymptotic conclusions do not depend on a runtime measurement. A
real end-to-end timing pass would refine the constant factors but is not
required to establish super-linearity.

## Conclusion

Supports Q-PERF-01-P1-01 (JsonlRunStore O(E²) on the live chat path — the
highest-impact finding, since it fires on every event of every run),
Q-PERF-01-P2-03 (conversation persistence O(M²)), and Q-PERF-01-P2-04
(search index 2×-content memory + linear scan). The subagent registry and
shadow maps grow linearly-not-super-linearly, so they sit at P2 (memory,
not blocking) rather than P1. Tool output is bounded by design.
