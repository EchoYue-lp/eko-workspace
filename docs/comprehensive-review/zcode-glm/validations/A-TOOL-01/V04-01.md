## Claim

Tool outputs are bounded at two independent layers (model-facing spill+truncate
and GUI-facing paginated JSONL), with no unbounded spill into model or frontend
context. Cancellation is recorded as a projection by the
`ToolExecutionRepository` while the framework `CancellationToken` (threaded via
`ExternalRunContext.cancel`) remains the single execution-cancellation
authority. `ToolFailure` (category + recovery) is persisted and surfaced.

## Expected Result

- Model-facing path: outputs exceeding token or byte budget spill to a sha256
  artifact; spill failure falls back to head+tail truncation. No unbounded
  inline output.
- GUI-facing path: output stored as bounded JSONL chunks; read_output paginates
  with a page-byte cap.
- `cancel()` only mutates projection state; framework token is the authority.
- `ToolFailure` persisted in manifest and surfaced on read.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary: all four claims confirmed.

  Model-facing bounding (`snapshot.rs:926-1065`): `process_tool_output_for_call`
  computes `estimated_tokens`; spills when `inline_bytes >= threshold_bytes` OR
  `exceeds_token_budget` (`:936-947`). Spill writes a sha256-tagged artifact
  via `persist_tool_output` (`:957`) and returns a short preview +
  `[Tool output preview only... Use read_artifact with this exact path and
  expected_sha256...]` pointer (`:967-984`). If spill fails (`spill_error`,
  `:958-964`), falls back to token-bounded head+tail truncation using
  `TOOL_OUTPUT_SPILL_FAILURE_FALLBACK_TOKENS = 8_000` (`snapshot.rs:21`,
  `:991-995`), with a `[Output truncated...]` notice (`:1025-1040`). Truncation
  uses `output.chars().take(head_chars).collect()` and reversed-tail
  (`:1033-1035`) — UTF-8 safe. `output_handling` metadata distinguishes
  `inline` / `spilled` / `truncated` / `spill_failed_truncated` (`:999, :1014,
  :1043-1049`). EKO budgets: `DEFAULT_MAX_TOOL_OUTPUT_TOKENS = 4_000`
  (`infra.rs:30-31`), `TOOL_OUTPUT_ARTIFACT_THRESHOLD_BYTES = 32 * 1024`,
  max age 30 days (`infra.rs:32-33`).

  GUI-facing bounding (`tool_execution.rs`): output stored via `append_output`
  (`:260-290`) which splits text into `STORED_OUTPUT_CHUNK_BYTES = 8 * 1024`
  UTF-8 chunks (`:29`, `:275`) and appends each as a JSONL line. `read_output`
  (`:413-450`) clamps the page to `DEFAULT_DETAIL_PAGE_BYTES = 64 * 1024`
  (`:421`) and reads via `read_jsonl_output_page` (`:427`) or, for artifact
  spills, `read_artifact_page` (`:437-443`, helper at `:723`). Each page
  returns `{ chunks, next_cursor, complete }`. No method returns the full
  output in one shot. Manifest writes are atomic (`write_json_atomic`,
  `:232`).

  Cancellation (`tool_execution.rs:360-392`): `cancel()` sets
  `status = Cancelled`, writes the manifest, appends a `Cancelled` journal
  record, removes the active entry. It does NOT cancel any future, thread, or
  framework token — it is projection-only. The execution-level authority is the
  framework `CancellationToken` threaded through `ExternalRunContext.cancel`:
  `chat_driver.rs:480-490` builds the context with
  `cancel: Some(Arc::new(cancel.clone()))`; `executor.rs:3094-3104` and
  `:3700-3710` do the same. The observer `cancel_active_tools`
  (`chat.rs:1116-1180`) fires on run-level `Completed`/`Failed`/`Cancelled`/
  `TimedOut` (`:1106-1111`) and calls the repository `cancel` for each
  still-active tool — i.e. the projection catches up after the framework
  already stopped the run.

  Error persistence: the observer decodes `failure` from the completion payload
  (`chat.rs:1075-1078`) via `serde_json::from_value::<ToolFailure>`; `finish`
  (`tool_execution.rs:293-358`) stores it in `manifest.failure` (`:341-343`);
  `detail_manifest` (`:394-411`) returns it in `ToolExecutionDetailManifest`.
  Failure therefore round-trips from framework `ToolFailure` → JSON event →
  repository manifest → frontend/GUI read.
