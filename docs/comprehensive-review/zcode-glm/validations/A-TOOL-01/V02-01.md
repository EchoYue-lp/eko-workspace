## Claim

The agent `run_code` sandbox is selected via `SandboxManager::local_sandbox()`
with `allow_fallback: false` and an OS-sandbox policy; when the local OS sandbox
probe (`has_local_os_sandbox`) fails, `configure_run_code_capability` removes
`run_code` from the agent, so there is no bare-unsandboxed fallback. Separately,
the GUI-exposed `SandboxConfigData.security_level` (Low/Medium/High) is never
consulted by the agent's sandbox construction — it is dead for `run_code`.

## Expected Result

- `SandboxManager::local_sandbox()` built once at `infra.rs:265`; uses
  `local_os`/`local_process` policy; `allow_fallback: false`.
- `has_local_os_sandbox` probe gates `run_code_available`.
- When unavailable, `run_code` is removed; no bare fallback.
- Writer subagents get the same gate; readonly subagents do not register
  `run_code` at all.
- `security_level` has zero read sites that affect the agent sandbox.
