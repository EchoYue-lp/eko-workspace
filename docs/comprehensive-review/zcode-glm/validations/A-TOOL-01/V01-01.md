## Claim

EKO uses a single framework tool registry per agent and applies per-mode policy
only through invocation-scoped `visible_tools` + `disabled_tools` filters that
compose correctly (a tool reaches the model iff registered AND not disabled AND
visible). Subagent role diff (readonly vs writer) is enforced at registration
time, not via the visibility filter. This validation enumerates the registry
construction, the per-mode exposure sets, the filter composition, and the
subagent registration gate.

## Expected Result

- Exactly one tool registry per agent; no per-mode re-registration.
- `groups_for_mode` returns a distinct visible set per `InteractionMode`.
- Framework `tools_for_llm` filters by `disabled_tools` AND `visibility`.
- Readonly subagent path takes `.readonly_tools()` → `register_readonly_tools`;
  writer path omits it → `register_all_tools`.

  Registry construction (single, mode-agnostic): `infra.rs:280` `.enable_tools()`,
  `infra.rs:288` `.register_agent_dispatch_tool()` (Phase-0 `agent_tool`, later

  - Chat: `chat_driver.rs:465-472` — user-selected `interaction_mode`.
  - TaskRun primary: `executor.rs:3084-3109` — forced `InteractionMode::Task`.
  - Auto/scope subagent: `executor.rs:3686-3710` — forced `InteractionMode::Auto`
    + `unattended_direct_disabled_tools`.

  Framework composition (`snapshot.rs:185-266`): `disabled_tools` accumulates
  agent-level + profile-excluded + invocation-disabled (`:192-204`);
  `visibility` = `available` (registered minus disabled, minus write tools in
  plan mode) ∩ `eligible` (skill-allowed) ∩ `initial` (invocation visible)
  (`:224-254`); `tool_search` force-inserted into initial (`:250`).
  `tools_for_llm` (`:269-279`) filters by both disabled and visibility — i.e. a
  tool reaches the model iff registered AND not disabled AND visible. Filters
  compose correctly.

  Per-mode matrix (`tool_exposure.rs:76-113`), locked by snapshot tests
  (`:206-274`): Chat=16 tools, Task=17 tools, Auto=18 tools (counted from
  sorted snapshots). Auto omits `run_code`; Task omits `list_dir` (see task
  report for the per-mode table and the A-TOOL-01-P3-01 note on Auto/run_code).

  Legacy/parallel tools hard-hidden by `disabled_tools_for_mode` (`:137-169`):
  background-task tools (`spawn_background_task`, `check_task_status`,
  `list_background_tasks`) disabled in all modes; `agent_tool` disabled in
  Task and Auto (hidden via visibility-only in Chat). The authoritative
  `task_create/update/list/execute` API stays visible and not-disabled in all
  modes (asserted by `modes_keep_the_authoritative_task_graph_tools_visible`
  at `:350-365`).

  Subagent registration diff: `build_readonly_subagent_agent` (`infra.rs:968`)
  calls `.readonly_tools()` (`:990`) → framework routes to
  `register_readonly_tools` (`react/mod.rs:743`). `build_writer_subagent_agent`

  additionally takes `sandbox_manager` + calls `configure_run_code_capability`
  (`infra.rs:950`). The framework test `unavailable_os_sandbox_removes_run_code`
  (`infra.rs:2106`) confirms `configure_run_code_capability(agent, false)`

  available. Readonly subagents neither take a sandbox manager nor call the
  capability helper, so they physically cannot expose `run_code`.
