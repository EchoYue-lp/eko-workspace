## Claim

The interactive terminal is a user-action developer tool, fully separate from
the agent `run_code` execution channel: it uses its own PTY (`portable_pty`),
`create_terminal` carries no agent `full-auto`/`permission_mode` gate, and
`write_terminal` is guarded only by a per-session user consent flag plus size
cap and audit log (an XSS-shell-injection guard, not an agent-permission gate).
The AGENTS.md historical lesson ("`require_full_auto` gates on
`create_terminal` were removed") is current.

## Result

- Exit code: not-applicable (static inspection)
- Duration: not-applicable
- Summary: all expected results confirmed.

  `grep -rn "SandboxManager\|run_code\|sandbox" echo-agent-cli/src/tauri/terminal.rs`
  → zero hits. The PTY module has no reference to the agent sandbox or
  `run_code`. The two execution channels share no code path.

  `create_terminal` (`terminal.rs:278-297`): no permission argument, no
  permission-mode check. Comment at `terminal.rs:286-289`:
  "The terminal is an interactive developer tool (compile / test / git etc.),
  not an agent-auto path. EKO is a local personal assistant — there's no
  multi-user / online threat model that warrants a permission gate here. The
  per-session `write_terminal` consent + audit log still guard writes."
  Exactly matches AGENTS.md.

  `write_terminal` (`terminal.rs:300-359`): gate is
  (1) `session.is_consented()` check (`:316-321`) — refuses with a distinct
  error until the user confirms via `confirm_terminal_consent`;
  (2) `MAX_WRITE_BYTES = 64 * 1024` payload cap (`:330, :336-342`);
  (3) audit log of session id + byte count + 80-char lossy preview (`:344-355`).
  The preview uses `chars().take(80)` (UTF-8 safe). No `permission_mode` /
  `full-auto` check exists.

  `confirm_terminal_consent` (`terminal.rs:366-381`) flips an `AtomicBool` on
  the `PtySession` (`consented` field at `terminal.rs:50`); it is the only
  mutator of that flag besides construction (`:121` initializes false).

  `grep -rn "require_full_auto\|permission_mode\|PermissionMode" \
   echo-agent-cli/src/tauri/terminal.rs echo-agent-cli/src/tauri/commands/`
  → zero hits in `terminal.rs`; the term surfaces in `commands/` only in
  unrelated agent-auto paths (chat run launching, HITL), not in the terminal
  commands. The AGENTS.md historical lesson is current: the gates were removed
  and have not returned.

  TUI parity: `grep -rln "portable_pty\|create_terminal\|PtySession"
  echo-agent-cli/src/tui/` → zero hits. The TUI exposes no interactive
  terminal pane (its `terminal` references in `tui/mod.rs` are ratatui/
  crossterm UI plumbing). This is the parity gap re-referenced as
  A-TOOL-01-P3-02.

  Channel separation: `terminal.rs:108-114` spawns the user shell directly via
  `CommandBuilder::new($SHELL)` on the PTY slave; `infra.rs:265` builds the
  agent sandbox via `SandboxManager::local_sandbox()`, used by `run_code`. No
  shared state, no call path between them.
