## Claim

`AppState::switch_workspace` swaps workspace-local state (CWD, agent working
dir, persistence, conversation store, runtime-state store, memory store +
layer manager, review-integration bind, workspace-curated skills) but does
**not** reload `app_config` / `mcp_config` / provider config, and it leaves the
config watcher pointed at the **old** cwd's `.eko/hooks.yaml` — so hooks defined
in the new workspace are never live-reloaded.

## Method

Static read of the switch path plus the workspace state shape, and a grep for
any competing switch entry points.

```text
read echo-agent-cli/echo-agent-app-core/src/state.rs:834-1010 (current_workspace, switch_workspace)
read echo-agent-cli/echo-agent-app-core/src/state.rs:411 (WorkspaceState struct)
grep -rn "switch_workspace\|set_current_dir\|current_workspace" echo-agent-cli/
grep -rn "spawn_config_watcher" echo-agent-cli/ (V02 already confirmed single spawn at bootstrap)
```

## Expected Result

A complete list of what is and is not replaced on switch, plus identification of
any second config reload triggered by the switch.

## Result

- Exit code: not-applicable
- Summary: `switch_workspace` (`state.rs:844`) performs, in order:
  1. `workspace.current` ← new workspace (`:846-849`).
  2. `std::env::set_current_dir(&workspace.root)` — global process CWD mutation
     (`:853-870`).
  3. Primary agent: `set_working_dir`, `set_tool_output_artifacts`,
     `refresh_dynamic_context` (`:875-886`).
  4. Pool: `pool.apply_working_dir(new_wd)` (`:889-891`).
  5. `Persistence::with_base_dir(workspace sessions dir)` swapped into
     `storage.persistence` (`:894-900`).
  6. `FileConversationStore::new(workspace conversations dir)` swapped into
     `storage.conversation_store` and pushed to agent (`:903-919`); on success
     also swaps `RuntimeStateStore` to the workspace sessions dir
     (`:921-934`).
  7. Memory store rebuilt for `{workspace.root}/.eko/`, hot + warm layers
     re-bound, `install_memory_store` + `install_memory_layer_manager` on agent,
     `ReviewIntegration::rebind`, skill curator reset, workspace-curated skills
     reloaded from `{root}/.eko/skills` (`:941-1004`).

  **Not touched** by switch_workspace (verified by reading the full body to its
  return and by the absence of any write lock acquisition on these fields):
  - `app_config: RwLock<AppConfig>` (`state.rs:339`)
  - `web_config`, `sandbox_config`, `permission_mode`, `permission_rules`
    (`state.rs:340-343`)
  - `mcp_config: RwLock<McpConfigFile>`, `mcp_health` (`state.rs:357-358`)
  - provider auth / base_url baked into the agent's `LlmConfig` at bootstrap
  - the config watcher's target list

  Grep confirms `switch_workspace` has exactly one definition and is called from
  IPC/tauri command handlers (workspace management surface); no second call site
  re-runs `load_config` or restarts the watcher after a switch.

  Stale-watcher consequence: `spawn_config_watcher` was started once at bootstrap
  (`main.rs:231`, `desktop.rs:165`) with `config_watch_targets` containing
  `<cwd-at-bootstrap>/.eko/hooks.yaml` (`config_watcher.rs:205-207`). After
  `set_current_dir` to the new workspace root, the process CWD changes but the
  watcher's target list is fixed for the lifetime of the task — the new
  workspace's `.eko/hooks.yaml` is **not** watched, so edits to it do not
  hot-reload. The old-cwd hooks file remains watched (and may no longer exist or
  be irrelevant).

## Deviations

None beyond the two structural gaps above. The state replacement that *does*
happen (persistence, conversation store, runtime store, memory) is consistent
and atomic per-field under each `RwLock`.

## Conclusion

Workspace switching is internally consistent for storage/memory/skills but
**silently inconsistent for config + hooks**: switching CWD changes what
`config_search_paths()` would resolve on the next load, yet no reload occurs;
and the file watcher keeps pointing at the pre-switch hooks file. Supports
findings A-CFG-01-P1-01 (watcher targets not refreshed on workspace switch) and
A-CFG-01-P2-04 (no config reload on workspace switch — may be intentional but is
undocumented and surprises users who put `echo-agent.yaml` in the workspace).
