## Claim

`echo_agent::config::load_config` resolves a single config file by
first-existing-wins search (no merging), and the effective precedence is
`--config` arg → `$ECHO_AGENT_CONFIG` → `./echo-agent.yaml` → `~/.eko/config.yaml`
→ built-in `AppConfig::default()`. CLI `--model` overrides only the model
**name**, not provider / auth / base_url. Provider API-key resolution is
`model_providers[p].auth_token` → `model.auth_token` → well-known env var.

## Method

Static read of the loader, search-path enumeration, CLI arg struct, and the
runtime model resolver.

```text
read echo-agent/src/config.rs:663-757   (config_search_paths, load_config_file, load_config)
read echo-agent/src/config.rs:687-722   (save_config, documents the same search order)
read echo-agent-cli/src/cli/args.rs:1-68 (Args: --config, --model, --mcp_config)
read echo-agent-cli/src/main.rs:95-106   (load_config + apply_env_overrides)
read echo-agent-cli/echo-agent-app-core/src/model_config.rs:237-318 (resolve_runtime_model)
read echo-agent-cli/echo-agent-app-core/src/infra.rs:194-207 (params.model overrides name only)
```

## Expected Result

A single, documented precedence chain with merging semantics clearly separating
file discovery, env overrides, and CLI flags.

## Result

- Exit code: not-applicable
- Summary: Search is **first-existing-wins, no merging** (`config.rs:741-753`
  returns on the first file that both exists and parses). Concrete precedence:

  | Rank | Source | Path / origin |
  |---|---|---|
  | 1 | CLI `--config <path>` | `load_config` short-circuits before search (`config.rs:726`) |
  | 2 | `$ECHO_AGENT_CONFIG` env | first entry of `config_search_paths()` (`config.rs:668-672`) |
  | 3 | `./echo-agent.yaml` (CWD-relative) | `config.rs:673` |
  | 4 | `~/.eko/config.yaml` | `paths::user_data_path("config.yaml")` (`config.rs:674`) |
  | 5 | `AppConfig::default()` | when no file is found / all fail to parse |

  Env overlay (`apply_env_overrides`, `config.rs:763-784`) is **narrow**: it only
  sets `channels.qq.*`, `channels.feishu.*`, and `mcp.config_path`. It does
  **not** touch `model.*`, `model_providers.*`, or any provider API key.

  CLI `--model` flows into `AgentCreateParams.model` (`main.rs:154`,
  `desktop.rs:143`) and in `create_agent_with_diagnostics` is applied as
  `params.model.as_deref().unwrap_or(&runtime_model.model)` (`infra.rs:205`) —
  i.e. only the model **name string**. Provider, auth_token, base_url,
  temperature, max_tokens all remain whatever `resolve_runtime_model` returned
  from the YAML. So `--model <name>` against a config whose default points at a
  different provider keeps the original provider's auth/base_url.

  Provider auth resolution (`model_config.rs:278-293`):
  `config.model_providers[provider].auth_token` → (only when `provider ==
  config.model.provider`) `config.model.auth_token` → `find_env_api_key(provider)`
  (first non-empty of `provider_env_var_names(provider)`) → `(None, "none")`.

## Deviations

- `config_search_paths()` looks for `config.yaml` under `~/.eko/`
  (`config.rs:674`), but `config_discovery.rs:221` advertises the global agent
  file as `~/.eko/echo-agent.yaml`. The two modules disagree on the global
  filename. Discovery is a UI-facing inventory; the loader is the authority, so
  a user who creates `~/.eko/echo-agent.yaml` (the name the UI shows) will have
  it silently ignored at load time. Tracked as finding A-CFG-01-P2-02.
- `config_discovery.rs:231-240` also lists `<project-root>/echo-agent.yaml` as a
  Project-scope agent config, but `config_search_paths()` does **not** include
  the project root — only CWD-relative `./echo-agent.yaml`. So project-root
  discovery is informational only, never loaded (unless cwd == project root).

## Conclusion

The precedence chain is real and deterministic but it is **substitution-based,
not merge-based**: the first parseable file wholly replaces defaults, with no
layered global→project merge. CLI `--model` is a name-only override. Env
overrides cover only channels + MCP path. The filename mismatch between the
loader and the discovery inventory is a concrete defect. Supports findings
A-CFG-01-P2-01 (no merge) and A-CFG-01-P2-02 (filename mismatch). Used by
V02/V03/V04 which reason about what is and is not reloaded.
